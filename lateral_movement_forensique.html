🔀 Lateral Movement — Définition et contexte MITRE ATT&CK
Le mouvement latéral (TA0008 dans MITRE ATT&CK) désigne l'ensemble des techniques permettant à un attaquant de se déplacer d'un système compromis vers d'autres systèmes du réseau. Il intervient après la compromission initiale et la phase de découverte, et précède généralement l'exfiltration ou l'impact (ransomware). Chaque technique laisse des artefacts forensiques distincts sur la machine source (initiateur) et sur la machine cible (victime). Le technicien DFIR doit analyser les deux côtés simultanément.

🔑 Logon Types — Mémo rapide

  • Type 2 — Interactif (clavier local)
  • Type 3 — Réseau (SMB, net use, PsExec)
  • Type 4 — Batch (tâche planifiée)
  • Type 5 — Service (service Windows)
  • Type 7 — Unlock (déverrouillage écran)
  • Type 10 — RemoteInteractive (RDP)
  • Type 11 — CachedInteractive (offline)

📍 Analyse source vs cible

  • Machine source : 4648 (credentials explicites), artefacts prefetch, shimcache, amcache, MRU réseau
  • Machine cible : 4624 type 3/10, 7045 (service), artefacts prefetch de psexesvc.exe, ADMIN$ share access
  • Toujours analyser les deux machines — la cible seule est insuffisante
⚙️ PsExec — L'outil d'admin devenu arme d'attaquant
PsExec (Sysinternals, maintenant Microsoft) est un outil légitime d'administration permettant d'exécuter des processus sur des machines distantes via SMB. Il est massivement détourné par les attaquants car il est souvent autorisé par les politiques de sécurité et laisse des traces distinctives bien documentées. Les frameworks d'attaque (Metasploit, Impacket, CobaltStrike) incluent tous une implémentation PsExec-like. MITRE T1570 (Transfer Tool) + T1021.002 (SMB/Windows Admin Shares).

Variantes modernes — Impacket, CobaltStrike, Metasploit
⚠️ Les variantes Impacket (psexec.py, smbexec.py, wmiexec.py) utilisent des noms de service et fichiers aléatoires pour contourner les signatures basées sur "PSEXESVC". L'artefact Event 7045 reste présent mais avec un nom différent. Chercher : service avec nom aléatoire (8 caractères hex), binaire dans C:\Windows\ ou %TEMP\, durée de vie très courte (secondes).
# Chercher services éphémères suspects dans les logs
Get-WinEvent -LogName System | Where {$_.Id -eq 7045} |
  Select TimeCreated, @{N='Service';E={$_.Properties[0].Value}},
    @{N='Path';E={$_.Properties[3].Value}} |
  Where {$_.Path -match "Temp|Windows\\[a-f0-9]{8}"}

# Chercher dans le registre les services créés (même supprimés via shimcache)
reg query HKLM\SYSTEM\CurrentControlSet\Services /s | findstr "ImagePath"
Un analyste trouve Event ID 7045 sur la machine SERVEUR-01 avec ServiceName = "a1b2c3d4" et ImagePath = "C:\Windows\a1b2c3d4.exe". Le fichier n'existe plus. Comment reconstituer ce qui s'est passé ?PsExec · Niveau : moyen
1. Timestamp Event 7045 → heure exacte de l'installation du service.
2. Shimcache / AppCompatCache (HKLM\SYSTEM\CurrentControlSet\Control\Session Manager\AppCompatCache) → confirme que a1b2c3d4.exe a été exécuté, avec le timestamp de dernière modification du binaire.
3. Amcache.hve (C:\Windows\AppCompat\Programs\Amcache.hve) → hash SHA1 du binaire exécuté — même si le fichier est supprimé. Soumettre à VirusTotal.
4. $UsnJrnl → entrées de création et suppression de a1b2c3d4.exe avec timestamps précis.
5. Event 4624 Type 3 juste avant 7045 → identifie la machine source et le compte utilisé.
6. Prefetch (C:\Windows\Prefetch\a1b2c3d4.EXE-*.pf) → confirme l'exécution, liste les fichiers ouverts par le binaire.
Conclusion : variante Impacket psexec.py ou smbexec.py — noms aléatoires = signature caractéristique.
🔮 WMI — Windows Management Instrumentation
WMI est l'infrastructure de gestion Windows permettant d'exécuter des commandes, de créer des processus et de gérer des systèmes à distance. C'est la technique de lateral movement la plus furtive : elle n'installe pas de service, ne crée pas de fichier exécutable sur la cible, et utilise des ports légitimes (DCOM/RPC 135 + ports dynamiques). Elle est utilisée massivement par les APT avancés. MITRE T1047.
⚙️ Exécution WMI distante
Mécanisme : appel Win32_Process.Create() via DCOM
Port initial : 135 (DCOM endpoint mapper)
Ports dynamiques : 49152-65535 (RPC)
Auth : NTLM ou Kerberos
Avantage attaquant : pas de fichier déposé, processus lancé comme enfant de WmiPrvSE.exe
Outils : wmic.exe, Invoke-WmiMethod, impacket wmiexec.py
🕵️ Persistance WMI (Event Subscription)
Mécanisme : Event Filter + Event Consumer + Binding
Déclencheurs : démarrage système, heure, événement Windows
Stockage : WMI repository (C:\Windows\System32\wbem\Repository\)
Furtivité : aucune clé de registre RUN, aucun fichier .plist
MITRE : T1546.003

DCOM — Distributed COM Objects
🎯 DCOM (T1021.003) permet d'instancier des objets COM sur une machine distante et d'appeler leurs méthodes. Technique popularisée par Matt Nelson (@enigma0x3). Objets COM couramment abusés : ShellBrowserWindow, MMC20.Application, ShellWindows. Laisse des traces similaires à WMI : Event 4624 Type 3, processus enfant de svchost.exe ou mmc.exe distants, Event 4688 avec parent inhabituel.
# Détecter persistance WMI sur système live
Get-WMIObject -Namespace root\subscription -Class __EventFilter
Get-WMIObject -Namespace root\subscription -Class __EventConsumer
Get-WMIObject -Namespace root\subscription -Class __FilterToConsumerBinding

# Parser le repository WMI hors-ligne (python-cim)
python3 python-cim/samples/dump_root_namespace.py win7 ./Repository/

# Chercher WmiEventConsumer dans les logs Sysmon
Get-WinEvent -LogName "Microsoft-Windows-Sysmon/Operational" |
  Where {$_.Id -in @(19,20,21)} | Select TimeCreated, Message

🔍 Signature WMI Lateral Movement

  • Event 4624 Type 3 depuis IP source externe → machine cible
  • Event 4688 avec ParentProcess = WmiPrvSE.exe
  • Processus inhabituel (cmd.exe, powershell.exe, cscript.exe) enfant de WmiPrvSE
  • Connexion réseau port 135 suivie de ports dynamiques >49152
  • Event WMI-Activity 5861 = subscription malveillante créée

⚠️ WMI vs PsExec — Différences clés

  • PsExec : dépose un fichier + crée un service → Event 7045
  • WMI : aucun fichier, aucun service → plus furtif
  • PsExec : processus enfant de services.exe
  • WMI : processus enfant de WmiPrvSE.exe
  • Les deux laissent Event 4624 Type 3 sur la cible
🔑 Techniques de vol et réutilisation de credentials
Le lateral movement repose quasi-systématiquement sur des credentials volés. Les attaquants récupèrent des hashes NTLM ou des tickets Kerberos depuis la mémoire (Mimikatz, LSASS dump) et les réutilisent sans connaître le mot de passe en clair. Comprendre ces techniques est indispensable pour tracer la propagation dans le réseau et identifier le premier compte compromis.
T1550.002
Pass-the-Hash (PtH)
Réutilisation du hash NTLM sans connaître le mot de passe.
T1550.003
Pass-the-Ticket (PtT)
Réutilisation d'un ticket Kerberos TGT ou TGS volé.
T1550.003
Overpass-the-Hash
Hash NTLM → ticket Kerberos. Kerberos sur réseau Kerberos.
T1558.003
Kerberoasting
Demande de TGS pour comptes de service → crack offline.
T1003.001
LSASS Dump / Mimikatz
Extraction credentials depuis la mémoire du processus LSASS.
T1003.006
DCSync
Simulation d'un DC pour extraire tous les hashes du domaine.
RDP — Remote Desktop Protocol (T1021.001)
📋 Artefacts sur la machine SOURCE (client)
  • Registre NTUSER.DAT\Software\Microsoft\Terminal Server Client\Servers\ — liste des serveurs RDP contactés
  • Fichiers .rdp dans Documents, Desktop, Recent
  • Bitmap cache : C:\Users\[user]\AppData\Local\Microsoft\Terminal Server Client\Cache\ — captures d'écran fragmentées de la session RDP distante
  • Event 4648 : credentials utilisés pour la connexion
  • Prefetch : MSTSC.EXE-*.pf
📋 Artefacts sur la machine CIBLE (serveur RDP)
  • Event 4624 Type 10 (RemoteInteractive) + 4778/4779 (reconnexion/déconnexion session)
  • Event TerminalServices-LocalSessionManager 21/23/24/25 — ouverture, déconnexion, reconnexion session
  • Shimcache / Amcache : exécutables lancés pendant la session
  • Registre HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\ProfileList — profil utilisateur créé si premier login
  • Dossier C:\Users\[user]\ créé si nouveau compte
🎯 Bitmap Cache RDP — Technique de reconstruction visuelle
Le Bitmap Cache RDP (bcache22.bmc, cache0000.bin) est un cache de tuiles graphiques utilisé pour optimiser la session RDP. Il contient des fragments d'écran de la session distante — des fenêtres, icônes, textes partiels. L'outil BMC-Tools (NCC Group) reconstitue ces tuiles en images PNG exploitables forensiquement. Même après fermeture de la session, ces fragments persistent et peuvent révéler ce que l'attaquant a vu ou fait sur la machine distante.
Un analyste trouve Event 4768 avec ResulCode 0x0 suivi de multiples Event 4769 avec ServiceName se terminant par "$" depuis un compte de service svc_backup. Quelle technique est en cours et quels artefacts confirmer ?Kerberoasting · Niveau : difficile
Technique identifiée : Kerberoasting (T1558.003)

Explication : Event 4769 = demande de ticket TGS (Service Ticket). Quand un compte demande de nombreux TGS pour des comptes avec SPN (Service Principal Names), c'est le signe d'un Kerberoasting — l'attaquant demande des tickets pour les compter offline. ResulCode 0x0 = succès. Les ServiceName se terminant par "$" indiquent des comptes machine.

Artefacts de confirmation :
· Event 4769 en masse depuis une seule IP source = anormal (légitime = rare, quelques tickets/jour)
· Ticket Encryption Type = 0x17 (RC4-HMAC) dans 4769 = RC4 au lieu d'AES → signature Kerberoasting (RC4 cracké plus facilement)
· Si Sysmon déployé : Event 1 (process create) avec Rubeus.exe ou GetUserSPNs.py
· Réseau : capture des paquets KRB_TGS_REQ/REP → extraire les hashes avec tshark + hashcat

Correction : forcer AES256 pour tous les comptes de service (désactive RC4 downgrade).
🔍 Détection forensique — Approche systématique
La détection du lateral movement repose sur la corrélation multi-sources : les Event Logs seuls ne suffisent pas. Il faut croiser les artefacts Windows (Prefetch, Shimcache, Amcache, $UsnJrnl), les logs réseau, les logs Active Directory et les artefacts de chaque machine impliquée. L'outil de choix pour cette corrélation est Velociraptor + KAPE pour la collecte, et Elastic / Splunk pour la corrélation.
Checklist de triage — Lateral Movement
1. Connexions réseau suspectes (machine cible)
# Event 4624 Type 3 ou 10 depuis IPs internes inhabituelles
Get-WinEvent -LogName Security | Where {$_.Id -eq 4624} |
  Where {$_.Message -match "Logon Type:\s+3|10"} | Select TimeCreated, Message

# Event 5140 : accès partages ADMIN$, C$
Get-WinEvent -LogName Security | Where {$_.Id -eq 5140} |
  Where {$_.Message -match "ADMIN\$|C\$"}
2. Services éphémères (PsExec / variantes)
# Event 7045 : installation service — chercher noms suspects
Get-WinEvent -LogName System | Where {$_.Id -eq 7045} |
  Select TimeCreated, @{N='Svc';E={$_.Properties[0].Value}},
    @{N='Path';E={$_.Properties[3].Value}}

# Shimcache : exécutables qui ont tourné (Eric Zimmerman AppCompatCacheParser)
AppCompatCacheParser.exe -f SYSTEM --csv . --csvf shimcache.csv
3. Processus avec parents anormaux (WMI / DCOM)
# Sysmon Event 1 : cmd/powershell enfant de WmiPrvSE ou mmc
Get-WinEvent -LogName "Microsoft-Windows-Sysmon/Operational" |
  Where {$_.Id -eq 1 -and $_.Message -match "WmiPrvSE|mmc.exe"}

# Event 4688 avec CommandLine (si audit activé)
Get-WinEvent -LogName Security | Where {$_.Id -eq 4688} |
  Where {$_.Message -match "WmiPrvSE"}
4. RDP — Sessions distantes
# Event 4624 Type 10 + TerminalServices logs
Get-WinEvent -LogName "Microsoft-Windows-TerminalServices-LocalSessionManager/Operational" |
  Where {$_.Id -in @(21,23,24,25)} | Select TimeCreated, Message

# Bitmap cache source (client RDP)
ls "$env:LOCALAPPDATA\Microsoft\Terminal Server Client\Cache\"
5. Kerberos / Credentials
# Event 4769 en masse = Kerberoasting
Get-WinEvent -LogName Security -ComputerName DC01 |
  Where {$_.Id -eq 4769} | Group-Object {$_.TimeCreated.Hour} | Sort Count -Desc

# Event 4776 NTLM + 4768/4769 depuis même IP = PtH ou PtT
# Chercher aussi Event 4625 avec sous-status 0xC000006E (compte désactivé utilisé)

🎓 Exam Tip — Lateral Movement Forensique

PsExec → Event 7045 (service PSEXESVC) + 4624 Type 3 + 5140 (ADMIN$) sur la cible

WMI → 4688 avec ParentProcess = WmiPrvSE.exe · plus furtif que PsExec (pas de service)

RDP → 4624 Type 10 + TerminalServices Event 21 sur la cible · Bitmap Cache sur la source

Pass-the-Hash → 4624 Type 3 avec compte + Event 4648 côté source · NTLM auth sans Kerberos

Kerberoasting → multiples Event 4769 depuis même IP · Ticket Encryption Type 0x17 (RC4) = red flag

Règle d'or : analyser toujours source ET cible — les artefacts sont complémentaires
