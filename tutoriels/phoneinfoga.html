📞 PhoneInfoga — OSINT téléphone

À la fin de ce tutoriel, tu sauras utiliser PhoneInfoga pour valider un numéro de téléphone (format E.164, pays, opérateur, type de ligne), lancer ses scanners (local libphonenumber, NumVerify, OVH, Google dorks), exploiter l'API REST et GUI web, intégrer dans un workflow OSINT téléphone complet (PhoneInfoga + GHunt phone + Yandex + HIBP), et orchestrer le quatuor OSINT Sherlock + Maigret + Holehe + GHunt + PhoneInfoga sur les 4 IoCs fondamentaux.
🎯 Niveau intermédiaire ⏱ ~45 min 📞 OSINT téléphone 🐧 Linux / Docker 🌐 GUI web + API REST ⚠️ Sensibilité légale max
⚠️ OSINT téléphone parmi les plus sensibles légalement
Le numéro de téléphone est un identifiant fortement personnel. PhoneInfoga ne révèle pas magiquement le propriétaire (réservé aux autorités via opérateurs avec mandat) mais aide à trouver les traces publiques du numéro. Cadre légal strict : nLPD (Suisse), RGPD, art. 179 CP (atteinte sphère privée), art. 179 quater CP (harcèlement obsessionnel). Mandat ou autorisation explicite obligatoire. Stalking et doxxing = sanctions pénales. Pendant phone de GHunt (v130).

01 Présentation générale

PhoneInfoga est un outil Go (anciennement Python) qui automatise l'OSINT sur les numéros de téléphone.

Ce qu'il fait

  1. Valide le numéro (format E.164 international)
  2. Identifie : pays, opérateur, type de ligne (mobile, fixe, VoIP)
  3. Lance des scanners :
  • Google dorks : cherche le numéro dans Google avec requêtes ciblées
  • NumVerify : API de validation (gratuite avec inscription)
  • OVH : retourne carrier info
  • Custom scanners : extensibles
  1. Vérifie la présence sur réseaux : WhatsApp, Telegram, etc.

Spécificités

  • Open source GPLv3
  • Go binary : multi-plateforme, pas de dépendances
  • GUI web ET CLI
  • REST API : intégrable dans pipelines
  • Maintenu activement par sundowndev

Limites importantes

❌ Aucun outil n'identifie directement le propriétaire d'un numéro (réservé aux autorités via opérateurs avec mandat). PhoneInfoga aide à trouver des traces publiques du numéro, pas à l'identifier de force.

❌ Les fonctions WhatsApp / Telegram check ont été retirées récemment pour cause de violation TOS — vérifier la version actuelle.

02 Cadre légal — OSINT téléphone très sensible

L'OSINT téléphone est parmi les plus sensibles des OSINT :

  • Le numéro est un identifiant fortement personnel
  • En Suisse / EU : numéros = données personnelles directes (nLPD, RGPD)
  • L'usage non autorisé peut constituer stalking ou harcèlement

Ce qui est autorisé

  • Mandat MP (art. 197 CPP en Suisse) — autorité judiciaire
  • Audit interne sur numéros de son organisation
  • Vérification de cohérence d'un partenaire commercial (anti-fraude, due diligence)
  • Investigation cyberharcèlement : retrouver le harceleur si son numéro a été divulgué publiquement
  • Recherche personnelle sur son propre numéro

Ce qui est interdit / réglementé

  • Identification d'une personne par son numéro sans cadre légal : violation grave de la sphère privée
  • Stalking via numéro : art. 179 quater CP (Suisse), art. 222-33-2-2 CP (France)
  • Vente / partage : strictement interdit
  • Phishing préparé : utilisation du numéro pour phishing/smishing = aggravation pénale

Sanctions

  • Suisse : art. 179 CP (atteinte à la sphère privée), nLPD
  • France : art. 226-1 CP, RGPD
  • USA : TCPA, état-spécifique stalking laws
🚨 Critique
à n'utiliser que sur son propre numéro ou avec consentement explicite écrit de la personne. Sinon : exposition légale réelle.

04 Architecture et scanners

Architecture

shell
┌─────────────────────────────────┐
│         CLI / Web GUI           │
├─────────────────────────────────┤
│         Validation libphonenumber│
│  (Google's E.164 parser)        │
├─────────────────────────────────┤
│         Scanners pipeline       │
│  - LocalScanner                 │
│  - NumVerifyScanner             │
│  - OVHScanner                   │
│  - GoogleSearchScanner          │
│  - (autres custom)              │
└─────────────────────────────────┘

LocalScanner

Validation offline via libphonenumber (Google) :

  • Format E.164 valide ?
  • Pays
  • Type de ligne (mobile, fixe, VoIP, premium, gratuit)
  • Opérateur connu

C'est l'étape toujours disponible, sans clé API ni Internet.

NumVerifyScanner

API externe numverify.com :

  • Inscription gratuite : 100 requêtes/mois
  • Retourne : valid, country, location, carrier, line_type

Clé API à configurer.

OVHScanner

API publique OVH (limitée mais sans clé) :

  • Carrier info pour numéros français + quelques autres pays

GoogleSearchScanner

Génère et lance des Google dorks sur le numéro :

shell
"+41 79 123 45 67"
"+41 79 123 45 67" site:linkedin.com
"+41 79 123 45 67" site:facebook.com
"+41 79 123 45 67" filetype:pdf
"0041 79 123 45 67"
"079 123 45 67"

Et plusieurs variantes de formats.

Limitation : Google rate-limit rapidement → captcha. À enchaîner manuellement plutôt qu'automatiquement.

05 Cas d'usage typiques

  • Anti-fraude : valider un numéro avant transaction (cohérence pays/opérateur)
  • Due diligence : vérifier la présence en ligne d'un numéro pro
  • Investigation cyberharcèlement : si harceleur a divulgué son numéro publiquement
  • Threat intelligence : tracer un opérateur de groupe cybercriminel via numéro leaké
  • Journalisme : vérifier une source qui se présente avec un numéro
  • Sécurité personnelle : audit de son propre numéro pour voir où il apparaît publiquement
  • Investigation pénale : assister une enquête formelle (mandat)
  • Trace Labs : OSINT pour personnes disparues (cadre éthique CTF)

11 Comprendre les scanners

Lister les scanners disponibles

bash
phoneinfoga scanners

Affiche : local, numverify, googlesearch, OVH, etc.

Exécuter des scanners spécifiques

bash
# Uniquement local et numverify
phoneinfoga scan -n "+41791234567" --scanner local --scanner numverify

Désactiver des scanners

bash
# Tout sauf googlesearch
phoneinfoga scan -n "+41791234567" --disable-scanner googlesearch

Personnaliser via plugins

PhoneInfoga supporte des plugins custom (Go).

bash
phoneinfoga scan -n "+41791234567" --plugin /path/to/myplugin.so

Permet d'ajouter ses propres scanners (par exemple : interrogation de bases internes).

12 Interface web (REST API + GUI)

PhoneInfoga propose une GUI web + API REST.

Lancer le serveur

bash

Par défaut : http://localhost:5000/

GUI

Ouvrir <http://localhost:5000/> dans le navigateur. Interface simple :

  1. Entrer le numéro
  2. Choisir les scanners
  3. Lancer
  4. Voir les résultats structurés

API REST

bash
# Lister scanners
curl http://localhost:5000/api/scanners

# Scan
curl -X GET "http://localhost:5000/api/numbers/+41791234567/scan"

Réponse JSON exploitable.

Sécurité du serveur

⚠️ Ne pas exposer le serveur sur Internet sans authentification. Par défaut, pas d'auth → quiconque atteignant ton IP peut faire des scans à ton nom (et utiliser ta clé API NumVerify).

Bonne pratique : binder sur localhost uniquement :

bash
phoneinfoga serve --listen 127.0.0.1:5000

Ou derrière un reverse proxy avec auth.

13 Export JSON et exploitation

Sortie JSON

bash
phoneinfoga scan -n "+41791234567" --output json > results.json

Ou en CLI parsable :

bash
phoneinfoga scan -n "+41791234567" --output json | jq

Exploitation Python

python
#!/usr/bin/env python3
"""Wrapper PhoneInfoga"""

import json
import subprocess
import sys

def scan(number):
    result = subprocess.run(
        ['phoneinfoga', 'scan', '-n', number, '--output', 'json'],
        capture_output=True, text=True
    )
    return json.loads(result.stdout)

if __name__ == '__main__':
    number = sys.argv[1]
    data = scan(number)

    # Extraction
    local = data.get('results', {}).get('local', {})
    print(f"Pays : {local.get('country')}")
    print(f"Carrier : {local.get('carrier')}")
    print(f"Type : {local.get('line_type')}")

    # Dorks à ouvrir
    google = data.get('results', {}).get('googlesearch', {})
    for dork in google.get('dorks', []):
        print(f"  - {dork['url']}")

Batch processing

bash
#!/bin/bash
# scan_batch.sh : scan une liste de numéros

while IFS= read -r number; do
    safe=$(echo "$number" | tr -d '+ ')
    echo "Scanning $number..."
    phoneinfoga scan -n "$number" --output json > "results_${safe}.json"
    sleep 10   # rate limit
done < numbers.txt

# Manifest
sha256sum results_*.json > MANIFEST.txt

14 APIs externes (numverify, Google)

NumVerify (recommandé)

<https://numverify.com/>

  1. Créer un compte gratuit
  2. Récupérer la clé API
  3. Configurer dans PhoneInfoga :
bash
export NUMVERIFY_API_KEY="your_api_key_here"
phoneinfoga scan -n "+41791234567"

Quota gratuit : 100 requêtes/mois. Payant au-delà.

Google Custom Search (optionnel)

Pour automatiser les dorks (avec quota) :

  1. Créer un Custom Search Engine sur <https://programmablesearchengine.google.com/>
  2. Récupérer la clé API + CSE ID
  3. Configurer :
bash
export GOOGLECSE_CX="your_cse_id"
export GOOGLECSE_API_KEY="your_api_key"

Quota gratuit : 100 requêtes/jour. Faible mais utile pour batchs raisonnables.

💡 Astuce
Pour éviter les quotas : utiliser la sortie de PhoneInfoga (liste de dorks URLs) et ouvrir manuellement dans navigateur OSINT (avec VPN).

15 Limites et faux positifs

❌ PhoneInfoga ne révèle pas le propriétaire : sauf si trouvé dans une page indexée par Google.

❌ Carrier info pas toujours à jour : portabilité des numéros (changement d'opérateur) pas toujours reflétée.

❌ NumVerify gratuit limité : 100 requêtes/mois. À gérer avec parcimonie.

❌ Google rate-limit : si tu fais trop de dorks, captcha → arrêt.

❌ Faux positifs Google : un numéro peut apparaître sur une page sans rapport avec son propriétaire (forum, scam list, etc.).

❌ VoIP indistinguable : PhoneInfoga ne sait pas toujours différencier mobile et VoIP (Google Voice, Skype, etc.).

❌ Numéros virtuels : SimSimi, TextNow, Hushed → carrier info inutile, jamais retrouvable de cette manière.

❌ Numéros pro masqués : si un numéro pro est avec masquage (PABX), PhoneInfoga voit le numéro public, pas l'utilisateur.

❌ Pas de DB téléphones globale : aucun service ne couvre tous les pays. Bonne couverture US/UE, faible pour Asie/Afrique.

❌ WhatsApp / Telegram retirés : versions récentes ont retiré ces scanners pour conformité TOS.

bash

Étape 5 — HIBP (Have I Been Pwned) — fuites

HIBP support partiel des numéros (Facebook leak 2021 notamment) :

  • Recherche manuelle sur <https://haveibeenpwned.com/>

Étape 6 — Truecaller (manuel)

Visite manuelle de <https://www.truecaller.com/> avec recherche du numéro. Données crowdsourced — à prendre avec recul.

Étape 7 — WhatsApp web (manuel, prudent)

Ouvrir WhatsApp Web, créer un contact temporaire avec ce numéro → si associé à un compte, photo de profil et statut visibles.

⚠️ WhatsApp peut notifier la personne si elle a configuré sa privacy ainsi (rare). Mais cette action est tracée côté WhatsApp. À utiliser avec discernement.

Étape 8 — Telegram (manuel)

Idem WhatsApp : créer un contact temporaire dans Telegram avec le numéro → username, photo de profil si publique.

Étape 9 — Recherche réseaux sociaux

Recherche directe sur Facebook, Instagram, LinkedIn, X/Twitter avec le numéro entre guillemets (souvent moins efficace que la recherche par nom).

17 Sécurité opérationnelle

Environnement isolé

🛡️ VM OSINT dédiée (Tails / Whonix / VM custom)

🛡️ VPN OSINT dédié : Mullvad, ProtonVPN, etc.

🛡️ Navigateur OSINT distinct du perso

🛡️ Comptes burner Google / WhatsApp / Telegram pour les vérifications manuelles

Rate limit

  • Maximum 10-20 numéros par jour par instance pour éviter détection Google
  • Rotation IP via VPN si besoin
  • Espacement minimum 10 secondes entre scans

Anonymat

  • Ne pas utiliser ton propre WhatsApp pour vérifier un numéro suspect (apparition dans son journal)
  • Compte burner avec numéro temporaire (e-SIM, MVNO sans identification)

Données collectées

🛡️ Stockage chiffré : VeraCrypt, LUKS, BitLocker pour les rapports

🛡️ Durée limitée : effacer post-enquête selon délai légal

🛡️ Pas de partage non autorisé

19 Forces, faiblesses et limites

Forces

✅ Multi-scanners : approche complète (carrier + APIs + dorks).

✅ Open source GPLv3 : auditable, modifiable.

✅ CLI + GUI web + API REST : flexibilité d'usage.

✅ Go binary : déploiement simple, pas de dépendances.

✅ Multi-plateforme : Linux / Windows / macOS / Docker.

✅ Plugins extensibles : ajouter des scanners custom.

✅ Validation libphonenumber : précis sur format E.164.

✅ Sortie JSON : intégrable dans workflows automatisés.

✅ Maintenu activement par sundowndev.

✅ Couverture mondiale (avec quelques limites par région).

Faiblesses

❌ Ne révèle pas le propriétaire : sauf si trouvé sur page indexée Google.

❌ Google rate-limit : dorks à ouvrir manuellement.

❌ NumVerify gratuit limité : 100/mois.

❌ WhatsApp/Telegram retirés : versions récentes.

❌ Numéros VoIP/virtuels : difficile à exploiter.

❌ Portabilité : carrier info parfois obsolète.

❌ Pas de DB universelle : couverture variable par pays.

❌ Faux positifs : numéro sur scam list != propriétaire identifié.

❌ Sensibilité légale max : OSINT téléphone est parmi les plus réglementés.

❌ Pas d'identification automatique : tout le travail d'interprétation reste manuel.

25 Conclusion

PhoneInfoga complète l'arsenal OSINT par l'angle téléphone, là où GHunt couvre le Google et Sherlock/Maigret/Holehe les services en ligne. Son approche multi-scanners (carrier + APIs + dorks Google) donne une vue 360° d'un numéro en quelques secondes.

Mais PhoneInfoga n'identifie pas magiquement le propriétaire d'un numéro — c'est techniquement impossible sans accès aux registres des opérateurs (réservé aux autorités avec mandat). PhoneInfoga aide à trouver les traces publiques que le numéro a laissées : sites où il apparaît, fuites, services associés.

L'OSINT téléphone est parmi les plus sensibles légalement. Discipline impérative :

  • Cadre légal documenté (mandat)
  • VM + VPN OSINT dédiés
  • Comptes burner pour vérifications
  • Multi-sources et corroboration
  • Stockage chiffré, durée limitée
  • Pas de stalking, pas de doxxing

Combiné avec Sherlock + Maigret + Holehe + GHunt, tu disposes désormais d'un arsenal OSINT personnes professionnel complet sur les quatre IoCs fondamentaux : username, email, téléphone, compte Google.

Recommandations finales :

  1. Configurer ta VM OSINT avec tous les outils OSINT en parallèle.
  2. Obtenir une clé NumVerify gratuite (100/mois) pour les enquêtes ciblées.
  3. Construire ton script orchestrateur OSINT téléphone (cf. §16).
  4. Pratiquer sur Trace Labs CTFs pour rester dans un cadre éthique.
  5. Lire Bazzell intégralement.
  6. Mettre à jour PhoneInfoga trimestriellement.
  7. Documenter chaque enquête : pour audit interne et défense en cas de contestation.

L'OSINT téléphone est puissant et sensible. À manier avec conscience, rigueur et cadre légal. 📞
