🔍 Sherlock — OSINT pseudonymes

À la fin de ce tutoriel, tu sauras installer Sherlock via pip ou Docker, lancer une recherche sur 400+ sites en 30 secondes, exporter en JSON / CSV / TXT, parser avec jq, utiliser Tor / proxy pour masquer ton IP, cibler des sites spécifiques, comprendre les faux positifs et combiner Sherlock avec Maigret, Holehe et d'autres outils OSINT.
🎯 Niveau intermédiaire ⏱ ~40 min 🐧 Linux / macOS 🪟 Windows 🔍 400+ sites ⚖️ Cadre légal OSINT
⚠️ OSINT : encadrement légal et éthique
Sherlock recherche un pseudonyme sur 400+ sites en quelques secondes. Outil dual-use : il sert l'investigation légitime mais peut aussi servir le stalking, le doxxing, le harcèlement. En Suisse, art. 173-179 CP et 179 quater (harcèlement obsessionnel) s'appliquent. Toujours documenter autorité, mandat, finalité avant chaque investigation. Préférer Tor ou VPN OSINT dédié.

📦 github.com/sherlock-project/sherlock · Licence MIT

01 Présentation générale

Sherlock est un script Python qui :

  1. Prend un username en argument
  2. Teste l'existence d'une page de profil sur 400+ sites
  3. Liste tous les sites où le username retourne une page valide

Le principe est simple : pour chaque site, Sherlock connaît le format d'URL de profil (https://twitter.com/{username}, https://github.com/{username}, etc.) et comment détecter qu'un profil existe (code HTTP, présence de certains éléments dans la page).

Particularités :

  • 400+ sites supportés (liste extensible via data.json)
  • Communautaire et actif : 50k+ stars GitHub
  • Open source MIT
  • Rapide : ~30 secondes pour parcourir 400 sites
  • Multi-plateforme : Linux, macOS, Windows

02 Cadre légal et éthique

L'OSINT touche à des données publiques mais sensibles :

Ce qui est autorisé

  • Investigation par un titulaire de mandat (police, MP, défense, audit autorisé).
  • Investigation interne sur des comptes de son organisation (SOC, RH).
  • Recherche personnelle sur son propre pseudonyme (audit de surface d'attaque personnelle).
  • Activité journalistique d'intérêt public (vérification d'identité d'un escroc, scammer).
  • Activité académique / pédagogique sur des cas anonymisés.

Ce qui est interdit ou réglementé

  • Stalking ou harcèlement : sanction pénale (art. 179 quater CP Suisse, harcèlement obsessionnel).
  • Doxxing : exposition d'informations privées d'autrui = atteinte grave à la sphère privée.
  • Surveillance d'employés sans information préalable : violation LPD (Suisse) et RGPD.
  • Investigation à l'étranger sans cadre légal : peut violer le droit du pays cible.

Règle d'or DFIR

🚨 Critique
Sherlock se justifie par un cadre légal explicite (mandat, audit interne autorisé) ou un usage personnel sur soi-même. Toute autre utilisation pose des questions éthiques fortes.

Sanctions :

  • Suisse : art. 173-179 CP (atteinte à l'honneur et sphère privée), art. 179 quater (harcèlement obsessionnel).
  • France : art. 226-1 CP (atteinte vie privée), GDPR.
  • États-Unis : Stalking statutes, CFAA dans certains cas.

03 Sherlock vs Maigret vs WhatsMyName

OutilSites couvertsParticularités

Maigret~3000Fork avancé de Sherlock, plus de sites, extraction de métadonnées
WhatsMyName~600Maintenu par OSINT Combine, format JSON portable
Holehe~120Spécialisé email → comptes utilisant cet email
Spiderfoot200+ modulesPlateforme OSINT complète (sites, IP, emails, hashs)
Recon-ngModulaireFramework type Metasploit pour OSINT

Règle :

  • Sherlock pour une vérification rapide et standard
  • Maigret quand tu veux plus de couverture (3000 sites vs 400) — cf. tutoriel dédié
  • WhatsMyName + scripts custom pour une intégration plus poussée
  • Holehe quand tu pars d'un email
  • Spiderfoot / Recon-ng pour une enquête longue multi-axes

04 Cas d'usage typiques

  • Enquête sur un suspect : retrouver toutes ses présences en ligne sous son pseudo connu.
  • Vérification d'identité : croiser un pseudo avec d'autres sources (LinkedIn, médias).
  • Surface d'attaque personnelle : « où mon pseudo apparaît-il ? » avant d'auditer ces comptes.
  • Investigation cyberharcèlement : retrouver les autres comptes d'un harceleur si lien de pseudo.
  • Threat intelligence : tracer les comptes d'un membre d'un groupe APT/cybercriminel.
  • Due diligence : vérifier la cohérence d'un partenaire commercial sur Internet.
  • Recrutement (avec accord candidat) : vérifier la présence en ligne déclarée.
  • Journalisme d'investigation : tracer un compte anonyme suspect.

06 Installation via pip

Méthode recommandée : environnement virtuel

bash
# Créer un dossier dédié
mkdir -p ~/osint && cd ~/osint

# Environnement virtuel Python
python3 -m venv venv
source venv/bin/activate

# Installer sherlock
pip install sherlock-project

Sur Windows :

powershell
mkdir $env:USERPROFILE\osint
cd $env:USERPROFILE\osint
python -m venv venv
.\venv\Scripts\Activate.ps1
pip install sherlock-project

Vérification

bash
sherlock --version
sherlock --help
💡 Astuce
toujours utiliser un virtualenv pour les outils OSINT. Évite les conflits avec ton Python système et facilite la désinstallation.

Installation depuis Git (dernière version dev)

bash
git clone https://github.com/sherlock-project/sherlock.git
cd sherlock
pip install -r requirements.txt
python sherlock --version

Utile si tu veux la version master avec les derniers ajouts de sites.

07 Installation via Docker

Pour un usage ponctuel sans installer Python ou pour s'isoler.

bash
# Image officielle
docker pull sherlock/sherlock

# Lancer une recherche
docker run --rm -t sherlock/sherlock test_username

# Récupérer les résultats sur l'hôte
docker run --rm -t -v $(pwd)/output:/opt/sherlock/results sherlock/sherlock --folderoutput /opt/sherlock/results test_username
💡 Astuce
un container Sherlock isolé sur un VPS dédié OSINT empêche d'exposer ton IP personnelle dans les logs des sites cibles.

08 Premier lancement

Syntaxe basique

bash
sherlock pseudo_a_chercher

Exemple :

bash
sherlock johndoe

Sortie typique :

shell
[*] Checking username johndoe on:

[+] GitHub: https://github.com/johndoe
[+] Twitter: https://twitter.com/johndoe
[-] Reddit: not found
[+] HackerNews: https://news.ycombinator.com/user?id=johndoe
[-] Instagram: not found
[-] Pinterest: not found
[+] Pastebin: https://pastebin.com/u/johndoe
...
  • [+] : pseudo trouvé sur ce site
  • [-] : pseudo NON trouvé (ou erreur)
  • [*] : info

Par défaut, Sherlock écrit aussi dans .txt dans le dossier courant.

Durée typique

  • 400 sites en parallèle : 15 à 60 secondes sur une connexion correcte
  • Plus lent si tu utilises un proxy ou Tor

09 Options essentielles

bash
# Verbose
sherlock --verbose johndoe

# Print uniquement les comptes trouvés (filtre les "not found")
sherlock --print-found johndoe

# Print uniquement les "not found" (rare)
sherlock --print-all johndoe

# Limiter le timeout par site
sherlock --timeout 10 johndoe

# Output dans un dossier spécifique
sherlock --folderoutput results/ johndoe

# Output JSON
sherlock --json results.json johndoe

# Pas d'output couleur (utile pour scripts)
sherlock --no-color johndoe

# Open dans le navigateur les résultats trouvés
sherlock --browse johndoe

Combinaison utile

bash
sherlock --print-found --timeout 15 --folderoutput results/ johndoe

Recherche silencieuse (juste les trouvés), timeout étendu, résultats dans results/.

10 Recherche multi-username

Sherlock accepte plusieurs usernames à la fois.

bash
sherlock johndoe jdoe john.doe j_doe john_doe

Très utile pour tester des variations d'un pseudo : avec ou sans points, underscores, majuscules.

Depuis un fichier

bash
# fichier usernames.txt :
# johndoe
# jdoe
# john.doe
# ...

# Bash : itérer
while read username; do
    sherlock --print-found --no-color "$username" --folderoutput results/
done < usernames.txt

Avec GNU parallel

bash
cat usernames.txt | parallel -j 4 sherlock --print-found --no-color {} --folderoutput results/

11 Exporter les résultats

Format texte (par défaut)

bash
sherlock johndoe
# Crée johndoe.txt avec la liste des URLs trouvées

Format JSON

bash
sherlock --json johndoe.json johndoe

Plus facile à traiter ensuite avec jq :

bash
sherlock --json results.json johndoe

# Lister uniquement les sites trouvés
jq '. | to_entries | map(select(.value.status.status == 1)) | map(.key)' results.json

Format CSV

bash
sherlock --csv johndoe
# Crée johndoe.csv

Intégration dans un rapport

bash
# Bash : générer un rapport markdown
{
    echo "# Profils trouvés pour $USERNAME"
    echo ""
    echo "Date : $(date -Iseconds)"
    echo ""
    echo "## Profils trouvés"
    echo ""
    grep -h "^\[+\]" sherlock_output.txt | sed 's/^\[+\] /- /'
} > rapport_$USERNAME.md

12 Cibler des sites spécifiques

Pour gagner du temps, tu peux limiter la recherche à certains sites.

bash
# Uniquement GitHub et Twitter
sherlock --site GitHub --site Twitter johndoe

# Liste des sites supportés
sherlock --site-list

La liste complète est dans data.json (au format JSON Sherlock).

Ajouter un site custom

data.json (dans le dossier d'installation Sherlock) :

json
{
  "MonSiteCustom": {
    "errorMsg": "User not found",
    "url": "https://monsite.example.com/u/{}",
    "urlMain": "https://monsite.example.com/",
    "username_claimed": "blue"
  }
}

Tester avec un compte connu (username_claimed) avant d'ajouter le site définitivement.

13 Comprendre les faux positifs

Sherlock détecte la présence d'une page, pas nécessairement l'identité réelle de la personne.

Sources de faux positifs

CauseExemple
Pseudo génériqueadmin, test, root → trouvé partout sans signification
SquattingQuelqu'un a réservé le pseudo sans l'utiliser
Page "username reserved"Le site retourne une page même si le compte est désactivé
Profil similaire mais homonymejohndoe chez plusieurs personnes
API changéeSite qui a modifié son URL ou ses retours → Sherlock obsolète

Bonne pratique

Ne jamais conclure de la présence d'un pseudo sur 10 sites qu'il s'agit de la même personne. Tu dois corroborer :

  • Photo de profil identique sur plusieurs sites
  • Bio, intérêts, dates cohérents
  • Activité chronologique cohérente
  • Liens entre profils (mention X dans bio Y)

C'est l'investigation, pas Sherlock, qui prouve l'identité.

Filtrer les "vrais" résultats

bash
sherlock --json results.json johndoe

# Garder uniquement les sites où la photo de profil est non-default
# (nécessite scripts custom : Sherlock seul ne vérifie pas)
🚨 Critique
un résultat Sherlock est une piste, jamais une preuve.

14 Utiliser un proxy ou Tor

Sur des comptes ciblés (ex. : enquête sur compte suspect), tu peux masquer ton IP pour ne pas alerter la cible.

Via HTTPS proxy

bash
sherlock --proxy http://proxy.example.com:8080 johndoe

Via Tor (SOCKS5)

Démarrer le service Tor :

bash
sudo systemctl start tor   # Linux
# Le SOCKS écoute sur 127.0.0.1:9050 par défaut

Configurer Sherlock pour passer par Tor :

bash
sherlock --tor johndoe
# ou explicitement :
sherlock --proxy socks5h://127.0.0.1:9050 johndoe
⚠️ Attention
️ Performance : via Tor, la recherche est 5-10x plus lente. Augmenter --timeout. Ne pas abuser, certains sites bloquent les sorties Tor connues (résultats faussés).

IP rotation pour requêtes massives

Si tu cherches 100 pseudos en boucle, certains sites te limiteront (rate limit) ou te banniront temporairement. Solutions :

  • Sleep entre les requêtes : sleep 10 dans la boucle bash
  • IPs rotatives : VPN avec rotation, ou pool de proxies

15 Croiser avec d'autres outils OSINT

Sherlock seul ne suffit pas. Workflow OSINT typique :

shell
Username → Sherlock      ──┐
       └→ Maigret           │
                            ├──→ Liste de profils → Investigation manuelle
Email   → Holehe         ──┘
       └→ Hunter.io / Have I Been Pwned

IP / Domaine → Shodan, Censys, AbuseIPDB, AlienVault OTX
Photo        → Reverse image search (TinEye, Yandex, Google)
Réseau perso → Maltego, Recon-ng

Exemple de pipeline complet

bash
USERNAME="suspect_handle"
mkdir -p "osint_$USERNAME"
cd "osint_$USERNAME"

# 1. Sherlock
sherlock --print-found --json sherlock.json "$USERNAME"

# 2. Maigret (3000 sites)
maigret --json json --folder . "$USERNAME"

# 3. Extraire les URLs trouvées
jq -r '. | to_entries | map(select(.value.status.status == 1)) | map(.key)[]' sherlock.json > sites_found.txt

# 4. Pour chaque site trouvé, archiver la page Wayback Machine
while read site; do
    url=$(jq -r ".[\"$site\"].url_user" sherlock.json)
    curl -s "https://web.archive.org/save/$url"
    sleep 2
done < sites_found.txt

echo "Investigation complète pour $USERNAME"

16 Limites de Sherlock

❌ Sites qui changent souvent : Twitter/X qui change ses URLs ou ses retours casse régulièrement la détection.

❌ Sites avec rate limit agressif : Instagram, Facebook → souvent en faux négatifs.

❌ Sites derrière captcha ou Cloudflare : Sherlock ne les contourne pas.

❌ Sites avec JavaScript obligatoire : Sherlock fait du HTTP, pas du rendering. Certains sites ne sont jamais détectés.

❌ Pas de vérification d'identité : présence ≠ identité.

❌ Sites russes/chinois : couverture moindre.

❌ Sites privés : Sherlock voit seulement la page publique. Profils restreints sont invisibles.

❌ Détection par sites : un site peut détecter Sherlock (User-Agent par défaut, comportement scripté) et bannir ton IP.

17 Forces et faiblesses

Forces

✅ Gratuit et open source (MIT).

✅ 400+ sites couverts, communauté très active (PRs régulières).

✅ Simple à utiliser : sherlock username et c'est parti.

✅ Multi-plateforme : Linux, macOS, Windows.

✅ Format de sortie multiple : text, JSON, CSV.

✅ Combinable avec parallel, jq, autres outils OSINT.

✅ Documentation correcte sur GitHub.

✅ Mise à jour fréquente des sites supportés.

✅ Performance correcte : 30s pour 400 sites en parallèle.

Faiblesses

❌ Faux positifs non négligeables (cf. §13).

❌ Faux négatifs sur sites avec captcha / JS.

❌ Pas d'extraction de métadonnées (photo, bio) — Maigret le fait.

❌ Sites majeurs (Instagram, Facebook) souvent en échec.

❌ Dépendant des changements : un site qui modifie son API casse Sherlock.

❌ Détection : Sherlock par défaut envoie un User-Agent "Sherlock", certains sites bloquent.

❌ Pas de TOR par défaut : ton IP apparaît dans les logs des sites cibles.

❌ Configuration limitée : peu de paramètres avancés vs Maigret.

18 Bonnes pratiques OSINT

🔹 Documenter chaque investigation : autorité, finalité, date, durée, résultats. Comme pour Hashcat.

🔹 Préférer Tor ou un VPN OSINT dédié pour les recherches sensibles.

🔹 Ne jamais conclure d'un seul outil : croiser Sherlock + Maigret + recherches manuelles.

🔹 Archiver les résultats dès leur découverte (Wayback Machine, capture screenshot horodatée) — les profils peuvent être supprimés rapidement.

🔹 Respecter la sphère privée : juste parce que c'est public ne signifie pas que ça doit être publié dans ton rapport sans réflexion.

🔹 Différencier piste et preuve : Sherlock fournit des pistes. La corroboration en fait des preuves.

🔹 Pas d'investigation sur du droit étranger sans appui juridique : ton pseudo cible peut être protégé par une loi que tu ne connais pas.

🔹 Mettre à jour régulièrement : pip install --upgrade sherlock-project.

🔹 Tenir une base d'IoCs OSINT : pseudos déjà recherchés et conclusions, pour ne pas refaire le travail.

🔹 Ne pas exposer ton IP : utiliser un VPN OSINT dédié, jamais ton IP perso ou pro.

🔹 Considérer l'éthique avant chaque recherche : « ai-je le droit ? le devoir ? l'intérêt légitime ? »

🔹 Combiner avec Maigret pour la couverture, Holehe pour les emails, et WhatsMyName pour le format JSON portable.

20 Conclusion

Sherlock est l'outil OSINT de référence pour la recherche de pseudonymes. Sa simplicité d'usage cache une discipline d'analyste : un résultat brut n'est jamais une conclusion. C'est un pivot : il te donne des pistes que tu corrobores.

Pour aller plus loin, le combo Sherlock + Maigret couvre quasi tout l'écosystème (400 + 3000 sites). Avec un VPN OSINT dédié et un workflow d'archivage rigoureux, tu disposes d'une chaîne OSINT professionnelle.

Recommandations finales :

  1. Configurer un environnement OSINT isolé : VM dédiée + VPN OSINT + pas de comptes perso.
  2. Apprendre Maigret en parallèle (tutoriel dédié dans CAS-IN).
  3. Maîtriser l'archivage : Wayback Machine, screenshots horodatés.
  4. Documenter chaque investigation : c'est ton dossier juridique.
  5. Considérer chaque résultat comme une piste : la corroboration en fait une preuve.
  6. Lire Bazzell — Open Source Intelligence Techniques (référence académique).
  7. Faire des CTFs OSINT (Trace Labs Global OSINT Search Party) pour pratiquer.

Bonne investigation responsable ! 🔍
