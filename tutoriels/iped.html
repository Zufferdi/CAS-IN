⚡ IPED — Indexador e Processador de Evidências Digitais

À la fin de ce tutoriel, tu sauras installer IPED, le configurer correctement, traiter une image disque en ligne de commande, et utiliser l'interface d'analyse pour rechercher des évidences. Tu connaîtras aussi les profils, le carving et l'OCR.
🎯 Niveau intermédiaire ⏱ ~35 min 🪟 Windows / Linux ☕ Java 11 + JavaFX 💾 SSD recommandé
ℹ️ À propos d'IPED
IPED est un logiciel open source de forensique numérique développé depuis 2012 par la Police Fédérale Brésilienne, rendu public en 2019. Il traite des preuves numériques saisies sur scène de crime ou collectées en investigation privée.
📦 Dépôt : github.com/sepinf-inc/IPED
📜 Licence : open source (voir LICENSE.txt)

01 Présentation générale

IPED est multiplateforme (Windows, Linux), écrit principalement en Java. Sa philosophie repose sur trois piliers :

  • Performance : jusqu'à 400 Go/h sur matériel moderne, cas avec 135+ millions d'items.
  • Stabilité : décodage des FS et parsing hors processus principal — un fichier corrompu ne plante pas tout.
  • Portabilité : cas autonomes, ouvrables depuis un disque amovible sans installation.

Formats d'image disque supportés (via Sleuthkit) :

RAW/DD · E01 · EX01 · AFF · ISO9660 · VHD/VHDX · VMDK · UDF · AD1 (AccessData) · UFDR (Cellebrite).

02 Cas d'usage typiques

  • Analyse d'un disque dur saisi (image E01 ou DD).
  • Extraction et indexation des conversations WhatsApp, Telegram, Skype, etc.
  • Recherche de cartes bancaires, emails, URL, wallets crypto par regex.
  • Recherche d'images similaires ou de reconnaissance faciale.
  • Récupération de fichiers supprimés via data carving.
  • Géolocalisation d'évidences via métadonnées GPS.
  • Transcription audio automatique de conversations vocales.
  • Analyse de timelines corrélées multi-suspects.

04 Installation sous Windows

Méthode rapide : binaires précompilés

  1. Va sur la page des releases.
  2. Télécharge la dernière version stable (ex : iped-X.X.X.zip).
  3. Décompresse l'archive dans un dossier de ton choix, ex : C:\Forensic\IPED\.
  4. Aucune installation requise : IPED est portable.
  5. Vérifie la présence du fichier iped.exe à la racine du dossier.

Test de fonctionnement

Ouvre une invite de commande dans le dossier IPED et tape :

batch 
iped.exe --help
✓ Ce que tu dois voir
Une liste de toutes les options en ligne de commande (~30 lignes), commençant par :
Usage: iped [options] Options: -d, --datasource <file> Source de données (image disque, dossier, etc.) -o, --output <dir> Dossier de sortie -profile <name> Profil de traitement ...
Si oui : IPED est opérationnel. Passe à la section suivante.
🚨 Si tu vois « commande introuvable »
C'est que tu n'es pas dans le bon dossier. Tape cd C:\Forensic\IPED (ou ton chemin) avant de relancer. Vérifie aussi que java -version renvoie bien 11.x avec mention Full ou JavaFX.

05 Installation sous Linux

L'installation Linux demande plus de manipulations : Sleuthkit doit être compilé localement.

Étape 1 — Installer Java 11 avec JavaFX

bash 
# Exemple avec Liberica OpenJDK Full
wget https://download.bell-sw.com/java/11.0.x+x/bellsoft-jdk11.0.x+x-linux-amd64-full.tar.gz
tar -xzf bellsoft-jdk11*.tar.gz
sudo mv jdk-11* /opt/
export JAVA_HOME=/opt/jdk-11.x.x-full
export PATH=$JAVA_HOME/bin:$PATH

Vérifie l'installation :

bash 
java -version
✓ Ce que tu dois voir
openjdk version "11.0.x" ... OpenJDK Runtime Environment (build 11.0.x+x-LTS) OpenJDK 64-Bit Server VM (build 11.0.x+x-LTS, mixed mode)
La mention « Full » ou « JavaFX » doit apparaître pour qu'IPED fonctionne avec son interface graphique.

Étape 2 — Installer les dépendances système

Sous Ubuntu/Debian :

bash 
sudo apt update
sudo apt install -y git maven build-essential autoconf libtool \
  libafflib-dev libewf-dev libssl-dev libsqlite3-dev zlib1g-dev \
  libbz2-dev libvhdi-dev libvmdk-dev

Étape 3 — Compiler Sleuthkit

Procédure détaillée sur le wiki Linux d'IPED. En résumé :

bash 
git clone https://github.com/sleuthkit/sleuthkit.git
cd sleuthkit
./bootstrap
./configure
make
sudo make install
sudo ldconfig

Étape 4 — Exécuter IPED

Sous Linux, on utilise iped.jar au lieu de iped.exe :

bash 
java -jar iped.jar --help
✓ Ce que tu dois voir
La même sortie « Usage: iped [options]... » que sous Windows. Si oui, IPED est prêt.

06 Compilation depuis les sources

Pour compiler la dernière version (ou contribuer) :

bash 
git clone https://github.com/sepinf-inc/IPED.git
cd IPED
mvn clean install

Le binaire compilé apparaîtra dans target/release.

⚠️ Branche par défaut = instable
La branche master est la branche de développement. Pour une version stable, fais un checkout d'un tag de release après le clone :
bash 
git checkout tags/4.3.0

07 Configuration initiale

Avant le premier lancement, configure le fichier LocalConfig.txt à la racine d'IPED.

Paramètre clé : indexTemp

ini 
indexTemp = default

Ce dossier reçoit les données temporaires durant le traitement.

🚨 Recommandations critiques pour indexTemp
  • Place ce dossier sur un volume différent de l'OS.
  • Idéalement un SSD rapide ; dans ce cas active : indexTempOnSSD = true
  • Exclus-le de l'antivirus, de l'indexation Windows et des snapshots (Shadow Copy, Time Machine). Ces services tuent la performance.
  • Sous Windows, double les antislashs : indexTemp = D:\\IPED_TEMP

Autres fichiers de configuration

  • IPEDConfig.txt — options de traitement (hash, OCR, carving, regex...).
  • Profils prédéfinis : forensic, pedo (CSAM), triage, fastmode, blind.

08 Premier cas pratique : traiter une image disque

Commande de base

batch 
iped.exe -d image.dd -o output
  • -d image.dd : chemin vers l'image disque à traiter.
  • -o output : dossier de sortie (doit être vide ou inexistant).

Spécifier un fuseau horaire (cas FAT)

Pour les systèmes de fichiers FAT (qui ne stockent pas le fuseau) :

batch 
iped.exe -d image.dd -tz GMT-3 -o output

Par défaut, IPED utilise le fuseau horaire local.

Ajouter un alias à l'image

batch 
iped.exe -d image.dd -dname "PC_Suspect_01" -o output

Traiter plusieurs images dans le même cas

batch 
iped.exe -d image1.dd -d image2.dd -o output

Ajouter une image à un cas existant

batch 
iped.exe -d image3.dd -o output --append

Reprendre / redémarrer un traitement

batch 
# Reprendre où ça s'est arrêté
iped.exe -d image.dd -o output --continue

# Tout recommencer
iped.exe -d image.dd -o output --restart
💡 Astuce — Lister toutes les options
Tape simplement iped.exe --help pour voir l'intégralité des paramètres disponibles (~50 options). Indispensable pour découvrir --portable, --asap, --nohash, etc.
✓ Ce que tu dois voir au lancement
Une console qui défile rapidement avec des lignes du type :
[INFO] IPED 4.3.0 starting... [INFO] Loading config from LocalConfig.txt [INFO] Processing data source: image.dd [INFO] Sleuthkit version: 4.12.x [INFO] Indexing items: 1234 / 56789 (2.2%) ... [INFO] Carving allocated space ...
Le traitement peut durer plusieurs heures selon la taille. À la fin, ton dossier output contiendra IPEDSearchApp.exe (Windows) ou iped/lib/iped-search-app.jar (Linux) qu'il faudra lancer pour analyser.

09 Interface d'analyse : prise en main

Une fois le traitement terminé :

  • Windows : double-clique sur IPEDSearchApp.exe dans le dossier de sortie.
  • Linux :
bash 
java -jar [output]/iped/lib/iped-search-app.jar

Vue d'ensemble de l'interface

  1. Arborescence des évidences (gauche) : navigation hiérarchique fichiers / conteneurs.
  2. Onglets de catégorisation : par type, métadonnées, regex trouvées, etc.
  3. Tableau de résultats : items correspondant à la recherche/filtrage en cours.
  4. Visionneuses intégrées (bas / droite) : hex, texte Unicode, métadonnées, vue native.
  5. Galerie d'images / vidéos : aperçus rapides.
  6. Barre de recherche : indexation full-text Lucene/Solr — très rapide.

Recherches utiles dès le départ

  • Recherche full-text simple : tape un mot-clé dans la barre.
  • Recherche par regex : onglet dédié.
  • Filtre par métadonnée : ex. dc:creator:"Jean Dupont".
  • Bookmark : clic droit → Bookmark sur les items intéressants.

10 Fonctionnalités avancées

Hashing et déduplication

Algorithmes : MD5, SHA-1, SHA-256, SHA-512, eDonkey. PhotoDNA est disponible uniquement pour les forces de l'ordre (contact : iped at pf dot gov dot br).

Bases compatibles : NIST NSRL, NIST CAID, ProjectVIC, Interpol ICSE, ou CSV standard.

Data carving

Moteur qui scanne bien au-delà de l'espace non alloué, supporte 40+ formats (dont vidéos), occupe ~10 % du temps de traitement. Extensible par scripts.

OCR (Tesseract 5)

Reconnaissance optique de caractères — précieuse pour scans, captures, photos de documents.

NER — Détection d'entités nommées

Nécessite les modèles Stanford CoreNLP. Extrait automatiquement personnes, lieux, organisations.

Reconnaissance faciale

Optimisée sans GPU, seuil de similarité configurable. Recherche d'images similaires depuis une image source.

Transcription audio

Implémentations locales ou distantes (Azure, Google Cloud) — pratique pour les notes vocales WhatsApp.

Regex prédéfinies

Détection automatique de cartes bancaires, emails, URL, IP, MAC, montants monétaires, wallets Bitcoin/Ethereum/Monero/Ripple, validables par script.

Géolocalisation, graphe communications, timeline, API Web, scripting

  • Affichage géolocalisé sur Google Maps, Bing Maps, OpenStreetMap.
  • Visualisation des liens entre appels, emails, messages.
  • Timeline unifiée filtrée par type d'événement.
  • API Web pour intégration externe (HTTP).
  • Extensible en JavaScript et Python (CPython inclus).

11 Profils de traitement

IPED fournit des profils prêts à l'emploi, sélectionnables au lancement :

ProfilDescription
forensicProfil par défaut. Traitement exhaustif pour expertise complète.
pedo (CSAM)Enquêtes sur contenu pédopornographique : hash, détection nudité, ProjectVIC.
triageTriage rapide pour identifier les disques prioritaires.
fastmodeAperçu rapide. Désactive carving et OCR.
blindExtraction automatique sans interface (pipelines).

Activation : ligne de commande (-profile triage) ou édition de IPEDConfig.txt.

12 Forces d'IPED

  • ✅ Gratuit et open source — alternative crédible à EnCase, FTK, X-Ways (plusieurs k€/licence).
  • ✅ Performance : jusqu'à 400 Go/h, 135M items par cas, parallélisation multithread.
  • ✅ Stabilité : décodage hors processus — un fichier corrompu ne tue pas tout.
  • ✅ Cas portables : sortie autonome, exécutable depuis clé USB sans installation.
  • ✅ Reprise / redémarrage (--continue / --restart) — précieux sur gros cas.
  • ✅ Très large catalogue de parsers : WhatsApp, Telegram, Skype, eMule, Shareaza, Ares, BitTorrent, ActivitiesCache, historiques navigateurs (IE, Edge, Firefox, Chrome, Safari).
  • ✅ Multiformat : DD, E01, AFF, VMDK, UFDR Cellebrite, etc.
  • ✅ Détection de 70+ langues automatiquement.
  • ✅ Recherche d'images / visages similaires sans GPU.
  • ✅ Extensible par JavaScript et Python.
  • ✅ API Web pour automatisation.
  • ✅ Communauté active : ~1500 ★ GitHub, 38+ contributeurs, releases régulières.
  • ✅ Reconnu par les forces de l'ordre (Police fédérale brésilienne et autres).

13 Faiblesses et limites

  • ❌ Courbe d'apprentissage exigeante — interface dense, beaucoup d'options.
  • ❌ Documentation parfois lacunaire sur fonctionnalités avancées (NER, scripting).
  • ❌ Dépendance Java 11 + JavaFX — pas trivial à mettre en place sous Linux.
  • ❌ Installation Linux laborieuse — compilation Sleuthkit obligatoire.
  • ❌ Pas d'interface graphique pour le traitement — tout en CLI, rebute les non-techs.
  • ❌ Consommation de ressources élevée — RAM, CPU, SSD rapide nécessaires.
  • ❌ Origine brésilienne — quelques éléments encore en portugais.
  • ❌ Pas de support commercial — dépendance à la communauté GitHub.
  • ❌ PhotoDNA réservé aux forces de l'ordre (limitation légale).
  • ❌ Pas de support natif d'images chiffrées (BitLocker, FileVault, LUKS) sans clé.
  • ❌ Mises à jour parfois cassantes entre versions majeures.
  • ❌ Reconnaissance faciale / NER en deçà des solutions commerciales GPU.

14 Bonnes pratiques

  • 🔹 Travailler sur une copie de l'image, jamais sur l'original (chaîne de preuve).
  • 🔹 Hash de l'image originale avant et après traitement pour prouver l'intégrité.
  • 🔹 Documenter chaque cas : alias, fuseau horaire, profil, version d'IPED.
  • 🔹 indexTemp sur SSD dédié, hors antivirus et snapshots.
  • 🔹 Bon profil dès le départ — relancer un long traitement coûte cher.
  • 🔹 Multicase pour les dossiers avec plusieurs supports.
  • 🔹 Bookmarks pour structurer l'analyse et préparer le rapport (HTML/CSV).
  • 🔹 Tester sur petit échantillon avant un cas de plusieurs To.
  • 🔹 Sauvegarder bookmarks + tags régulièrement.
  • 🔹 Bases de hash à jour (NSRL, ProjectVIC).
  • 🔹 Apprendre la syntaxe Lucene pour exploiter la recherche.
