🗝️ RegRipper — Analyse Registry Windows par plugins

À la fin de ce tutoriel, tu sauras analyser les hives Registry Windows avec RegRipper (créé par Harlan Carvey). Tu comprendras les hives (SYSTEM, SOFTWARE, NTUSER, SAM, AmCache), maîtriseras les 100+ plugins Perl (UserAssist, ShimCache, AmCache, ShellBags, USBSTOR, BAM, etc.), reconstitueras l'activité utilisateur (programmes lancés, USB branchées, dossiers visités), et orchestreras un workflow KAPE + EZ Tools + RegRipper complet.

01 Présentation générale

RegRipper est un outil CLI Perl qui automatise l'extraction d'artefacts forensiques depuis les fichiers de Registry Windows (hives).

Pourquoi c'est important

Le Registry Windows contient une quantité énorme d'informations forensiques : programmes installés et lancés, périphériques USB branchés, sites web visités, dossiers ouverts, recherches effectuées, mots de passe Wi-Fi, comptes utilisateurs, services système, configurations réseau, etc.

Sans outil dédié : parser manuellement avec regedit = impossible (millions de clés). Avec RegRipper : commande unique → rapport texte structuré.

Le principe

  • 100+ plugins Perl, un par artefact connu
  • Chaque plugin sait extraire une clé Registry précise et la formater
  • Plugins maintenus par la communauté DFIR (Harlan Carvey + contributeurs)
  • Sortie texte → facile à grepper, archiver, intégrer

Open source mais utilisé en pro

RegRipper est gratuit, mais c'est le standard de facto dans :

  • Police (Suisse, France, US)
  • Cabinets d'audit cybersécurité
  • SOC / IR teams
  • Formations SANS FOR500

02 Pourquoi le Registry est un trésor DFIR

Le Registry Windows est une base de données hiérarchique où Windows et les applications stockent leurs configurations. Mais il enregistre aussi énormément de traces d'activité :

03 Les hives Registry expliqués

Le Registry est éclaté en plusieurs fichiers appelés "hives" :

Hives système

Hive (chemin Windows)Fichier sur disqueContenu
HKLM\SYSTEMC:\Windows\System32\config\SYSTEMConfig système, services, drivers, USB, ControlSets
HKLM\SOFTWAREC:\Windows\System32\config\SOFTWARELogiciels installés, options OS, AmCache
HKLM\SAMC:\Windows\System32\config\SAMComptes utilisateurs locaux, hashs NTLM
HKLM\SECURITYC:\Windows\System32\config\SECURITYPolicies de sécurité

Hives utilisateur

HiveFichierContenu
HKCU (par user)C:\Users\\NTUSER.DATPréférences user, UserAssist, ShellBags, RecentDocs, TypedURLs
HKCU\Software\ClassesC:\Users\\AppData\Local\Microsoft\Windows\UsrClass.datShellBags étendus, MUICache

Acquisition des hives

Pour utiliser RegRipper, il faut d'abord récupérer ces fichiers :

  • Image disque : monter avec Autopsy/IPED/X-Ways, extraire les hives
  • Triage live : KAPE (cf. v125) collecte tous les hives automatiquement
  • EZ Tools : Reg.exe export ou RegistryExplorer
  • FTK Imager : extraction logique des fichiers
  • Volume Shadow Copy : peut révéler des hives anciens
💡 Astuce
Les hives sont verrouillés sur un système Windows en cours d'exécution. Tu ne peux pas simplement les copier en vif. Il faut une copie via VSS, RawCopy (KAPE/EZ Tools), ou depuis une image disque.

Quand utiliser RegRipper

  • Triage rapide : un hive → un rapport complet en quelques secondes
  • Automatisation : pipeline DFIR sur N machines
  • Couverture exhaustive : 100+ plugins = très peu d'artefacts ratés
  • Audit reproductible : ligne de commande exacte documentable

Quand préférer un autre outil

  • Exploration manuelle : Registry Explorer (EZ Tools) plus ergonomique

  • Tout-en-un : Autopsy intègre déjà Recent Activity

10 Anatomie d'un plugin RegRipper

Chaque plugin est un fichier Perl .pl dans plugins/. Exemple compname.pl (nom du PC) :

perl
package compname;
use strict;

my %config = (
    hive          => "System",
    hasShortDescr => 1,
    hasDescr      => 0,
    hasRefs       => 0,
    osmask        => 22,
    version       => 20200526
);

sub getConfig {return %config}
sub getShortDescr {
    return "Gets ComputerName and Hostname values from System hive";
}

sub pluginmain {
    my $class = shift;
    my $hive = shift;

    ::rptMsg("compname v.".$VERSION);
    ::rptMsg("Hive: ".$hive."\n");

    my $reg = Parse::Win32Registry->new($hive);
    my $root_key = $reg->get_root_key;

    my $key_path = "ControlSet001\\Control\\ComputerName\\ActiveComputerName";
    my $key = $root_key->get_subkey($key_path);

    if (defined($key)) {
        my $name = $key->get_value("ComputerName")->get_data();
        ::rptMsg("ComputerName: $name");
    }
}

1;

Ce qu'on apprend

  • Chaque plugin déclare le hive cible (System, Software, NTUSER, etc.)
  • Description courte affichée dans -l
  • Plugin parse une clé précise et formate la sortie
  • Sortie via ::rptMsg() → texte brut
💡 Astuce
chaque plugin est ~50-200 lignes Perl. Tu peux comprendre exactement ce qu'il fait.

12 Première extraction sur un hive SYSTEM

Tu as une copie du fichier SYSTEM (extrait via KAPE ou Autopsy).

Plugin unique

bash

Sortie :

shell

Hive: /path/to/SYSTEM

ControlSet001\Control\ComputerName\ActiveComputerName
LastWrite: 2025-12-15 14:32:11Z

Plusieurs plugins en série

TypedURLs

15 AmCache, ShimCache, AppCompatCache

Trois artefacts qui se recoupent partiellement mais sont complémentaires.

ShimCache (AppCompatCache)

Dans SYSTEM :

bash
perl rip.pl -r /path/to/SYSTEM -p shimcache > shimcache.txt

Liste des binaires exécutés, avec date de modification du fichier (pas d'exécution). Conservé sur reboot. Précieux pour détecter des malwares effacés.

AmCache (Windows 8+)

Fichier séparé : C:\Windows\AppCompat\Programs\Amcache.hve

bash
perl rip.pl -r /path/to/Amcache.hve -p amcache > amcache.txt

Liste des binaires exécutés avec :

  • SHA-1 du fichier
  • Taille
  • Date de première exécution
  • Chemin complet
  • Éditeur

C'est l'artefact ultime pour Windows moderne. Combiner avec VirusTotal sur les SHA-1 pour détecter du malware.

BAM (Background Activity Moderator)

Dans SYSTEM :

bash
perl rip.pl -r /path/to/SYSTEM -p bam > bam.txt

Liste des exécutions récentes avec timestamp précis. Très utile sur Windows 10/11.

Tableau comparatif

ArtefactCapturePrécision dateHash
UserAssistLancements GUI utilisateurDernière exécution + countnon
ShimCacheBinaires apparus dans la VMDate modif fichiernon
AmCacheBinaires exécutésPremière exécutionSHA-1
BAMExécutions récentesTimestamp précisnon
Prefetch (hors Registry)Programmes lancés8 dernières datesnon

Workflow DFIR : croiser ces 4-5 sources pour avoir une vue complète des exécutions.

16 USB et clés branchées

L'un des cas DFIR les plus fréquents : prouver qu'une clé USB a été branchée à tel moment.

USBSTOR

Dans SYSTEM :

bash
perl rip.pl -r /path/to/SYSTEM -p usbstor > usbstor.txt

Sortie typique :

shell
usbstor v.20200526

ControlSet001\Enum\USBSTOR
LastWrite: 2025-12-19 16:42:18Z

  Disk&Ven_SanDisk&Prod_Ultra_USB_3.0&Rev_1.00 [LastWrite: 2025-12-19 16:42:18Z]
    S/N: 4C530001120329122210&0
    FriendlyName: SanDisk Ultra USB 3.0 USB Device

  Disk&Ven_Kingston&Prod_DT_USB_3.0&Rev_PMAP [LastWrite: 2025-12-18 14:03:22Z]
    S/N: 002618E0AF92F23150F61C5C

Tu vois :

  • Marque et modèle de chaque clé branchée
  • Numéro de série (unique, prouvable)
  • Date de dernière connexion

Croiser avec MountedDevices

bash
perl rip.pl -r /path/to/SYSTEM -p mountdev > mountdev.txt

Permet d'identifier la lettre de lecteur assignée (E:, F:, etc.).

Croiser avec ShellBags

ShellBags (NTUSER.DAT, UsrClass.dat) révèle quels dossiers sur ces clés ont été visités.

Workflow USB enquête

bash
# 1. Liste USB
rip -r SYSTEM -p usbstor > usbstor.txt

# 2. Lettres assignées
rip -r SYSTEM -p mountdev > mountdev.txt

# 3. ShellBags pour activité
rip -r NTUSER.DAT -p shellbags > shellbags_user1.txt
rip -r UsrClass.dat -p shellbags > shellbags_class_user1.txt

# 4. EventLog : DeviceSetupManager EID 112 (cf. Hayabusa, à venir)

Tu reconstitues qui a branché quoi, quand, et a accédé à quels dossiers.

17 Profils RegRipper (rip.pl all)

Au lieu de lancer plugin par plugin, RegRipper a des profils pré-définis.

Profils standards

ProfilHive cible
-a (all auto)Auto-détection du hive et tous les plugins
-f systemTous les plugins SYSTEM
-f softwareTous les plugins SOFTWARE
-f ntuserTous les plugins NTUSER.DAT
-f samTous les plugins SAM
-f amcacheTous les plugins AmCache
-f usrclassTous les plugins UsrClass

Exemple complet

bash
mkdir reports

perl rip.pl -r SYSTEM -a > reports/SYSTEM.txt
perl rip.pl -r SOFTWARE -a > reports/SOFTWARE.txt
perl rip.pl -r SAM -a > reports/SAM.txt
perl rip.pl -r SECURITY -a > reports/SECURITY.txt
perl rip.pl -r users/user1/NTUSER.DAT -a > reports/user1_NTUSER.txt
perl rip.pl -r users/user1/UsrClass.dat -a > reports/user1_UsrClass.txt
perl rip.pl -r Amcache.hve -a > reports/Amcache.txt

En quelques minutes : rapport complet de tous les artefacts Registry.

Profil custom

Créer un fichier monprofil.prof :

shell
compname
timezone
userassist
shimcache
amcache
usbstor
shellbags
recentdocs

Lancer :

bash
perl rip.pl -r SYSTEM -f monprofil

Permet de cibler les plugins pertinents pour ton type d'enquête.

18 Intégration KAPE + EZ Tools + RegRipper

Workflow DFIR typique combinant les trois outils.

Étape 1 — Collecte avec KAPE

cmd
KAPE.exe --tsource C: --tdest C:\triage --tflush --target !SANS_Triage

KAPE copie tous les hives Registry dans C:\triage\Registry\.

Étape 2 — Exploration avec Registry Explorer (EZ Tools)

GUI pour navigation manuelle, exploration ciblée d'une clé suspecte.

Étape 3 — Triage rapide avec RegRipper

bash
cd /triage_processed/
mkdir -p reports

for hive in System Software Sam Security; do
    perl /opt/RegRipper/rip.pl -r ../triage/Registry/$hive -a > reports/${hive}.txt
done

for user_dir in ../triage/Users/*/; do
    user=$(basename "$user_dir")
    if [ -f "$user_dir/NTUSER.DAT" ]; then
        perl /opt/RegRipper/rip.pl -r "$user_dir/NTUSER.DAT" -a > reports/${user}_NTUSER.txt
    fi
    if [ -f "$user_dir/AppData/Local/Microsoft/Windows/UsrClass.dat" ]; then
        perl /opt/RegRipper/rip.pl -r "$user_dir/AppData/Local/Microsoft/Windows/UsrClass.dat" -a \
            > reports/${user}_UsrClass.txt
    fi
done

# AmCache
if [ -f ../triage/Windows/AppCompat/Programs/Amcache.hve ]; then
    perl /opt/RegRipper/rip.pl -r ../triage/Windows/AppCompat/Programs/Amcache.hve -a \
        > reports/Amcache.txt
fi

echo "Rapports générés dans reports/"
ls -la reports/

Étape 4 — Analyse

Grep ciblé :

bash
# Toutes les USB
grep -A 2 "S/N:" reports/*SYSTEM.txt

# Exécutions de cmd.exe ou powershell
grep -i "powershell\|cmd.exe" reports/*NTUSER.txt

# Hashes AmCache à vérifier sur VirusTotal
grep -E "^SHA1:" reports/Amcache.txt | awk '{print $2}' | sort -u > hashes_to_check.txt

Étape 5 — Croiser avec autres sources

  • EVTX (cf. Hayabusa, à venir) : confirmer les exécutions avec EID 4688
  • Prefetch (cf. EZ Tools v126) : précision sur les premières exécutions
  • Browser history (Autopsy/IPED) : croiser TypedURLs avec history complète
💡 Astuce
Registry + EventLog + Prefetch + Browser = vision 360° de l'activité Windows.

19 Forces, faiblesses et limites

Forces

✅ Référence DFIR depuis 2008, maintenu par Harlan Carvey.

✅ 100+ plugins couvrent quasi tous les artefacts Registry connus.

✅ Open source, auditable, modifiable.

✅ Sortie texte structurée : facile à grepper, archiver, intégrer en pipeline.

✅ CLI scriptable : automation parfaite.

✅ Multi-plateforme : Windows / Linux / macOS (Perl partout).

✅ Léger : pas d'install lourde, fichiers Perl simples.

✅ Communauté DFIR active : nouveaux plugins régulièrement.

✅ Format reproductible : commande exacte documentable.

✅ Complément naturel de KAPE, EZ Tools, Autopsy.

Faiblesses

❌ CLI uniquement : pas de GUI native (utiliser Registry Explorer en complément).

❌ Sortie texte brute : pas de format JSON/CSV natif (workarounds existent).

❌ Dépend de la maintenance des plugins : nouvelles clés Windows = plugins à écrire/mettre à jour.

❌ Pas de support transaction logs : pour les hives "dirty" avec logs non commit, utiliser yarp ou Registry Explorer (EZ Tools).

❌ Pas de timeline native : pour timeline, exporter et intégrer dans Plaso ou super-timeline.

❌ Documentation parfois sèche : Harlan Carvey est expert, suppose connaissance Registry préalable.

❌ Perl : langage moins populaire que Python, courbe d'apprentissage pour écrire des plugins custom.

❌ Pas d'analyse comportementale : juste extraction. L'interprétation reste manuelle.

21 Conclusion

RegRipper est l'outil de référence pour l'analyse forensique du Registry Windows. 100+ plugins Perl exhaustifs, CLI scriptable, open source, maintenu depuis 2008 par Harlan Carvey lui-même.

Sa place dans un workflow DFIR Windows complet :

shell
KAPE (collecte)
  ↓
RegRipper (triage Registry rapide, texte)  +  EZ Tools (exploration manuelle GUI)
  ↓
Croisement avec EVTX (Hayabusa, à venir), Prefetch, Browser
  ↓
Reconstitution chronologique → rapport

RegRipper ne remplace ni Autopsy ni X-Ways — il est complémentaire. Sa force : extraction ciblée et exhaustive du Registry, là où d'autres outils sont généralistes.

Recommandations finales :

  1. Installer RegRipper sur ta machine DFIR (Linux ou Windows).
  2. Maîtriser les ~20 plugins essentiels (compname, timezone, userassist, shimcache, amcache, usbstor, shellbags, recentdocs, typedurls, services, run, networklist, samparse, bam).
  3. Construire ton workflow KAPE → RegRipper → grep ciblé.
  4. Croiser systématiquement Registry + EVTX + Prefetch + Browser.
  5. Lire Harlan Carvey : Windows Forensic Analysis Toolkit est incontournable.
  6. Suivre les blogs DFIR pour nouveaux artefacts Registry découverts.
  7. Contribuer un plugin si tu identifies un artefact non couvert.
  8. Tester sur CTFs (CyberDefenders, DFIR Madness) pour pratiquer.

Le Registry Windows ne ment pas. RegRipper te le révèle. 🗝️
