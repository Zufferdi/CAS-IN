🦈 Wireshark — Analyse réseau et PCAP

À la fin de ce tutoriel, tu sauras installer Wireshark, capturer du trafic avec dumpcap, filtrer par adresse, port et protocole, suivre un flux TCP/HTTP, extraire des fichiers transmis (HTTP/SMB), décrypter du TLS avec une clé de session, et automatiser des analyses avec tshark en ligne de commande.
🎯 Niveau intermédiaire ⏱ ~50 min 🪟 Windows / Linux / macOS 📡 Network forensics 📦 PCAP / PCAPNG
ℹ️ À propos de Wireshark
Wireshark est l'outil de référence pour la capture et l'analyse de trafic réseau. Open source, multi-plateforme, développé depuis 1998 (initialement Ethereal). 3000+ dissecteurs de protocoles. Standard de facto pour la network forensics, le débogage réseau et l'investigation d'incidents.

📦 www.wireshark.org · Licence GPL v2

01 Présentation générale

Wireshark capture et dissèque les paquets réseau circulant sur une interface (Ethernet, Wi-Fi, USB, loopback, Bluetooth). Il transforme des octets bruts en information lisible : protocoles décodés, champs nommés, conversations reconstruites.

L'outil repose sur quatre composants :

  • dumpcap : démon de capture bas niveau (le seul à avoir les privilèges réseau)
  • tshark : moteur d'analyse en ligne de commande
  • wireshark : interface graphique Qt
  • 3000+ dissecteurs : un par protocole connu (HTTP, DNS, TLS, SMB, Kerberos, mDNS, etc.)

Formats supportés :

pcap (libpcap classique), pcapng (format moderne, métadonnées riches), cap (Windows), snoop, etl (ETW Windows), et 40+ autres via lecture seule.

02 Cas d'usage typiques en DFIR

  • Analyse post-mortem d'un PCAP capturé par un IDS, SOC ou firewall lors d'un incident.
  • Identification de communications C2 : beaconing périodique, DGA, exfiltration via DNS.
  • Reconstruction de transferts de fichiers sur HTTP, SMB, FTP, ou tunnelés.
  • Investigation de phishing : extraire l'URL exacte cliquée, le payload téléchargé.
  • Analyse d'attaques réseau : ARP poisoning, Kerberos roasting, port scanning, SMB relay.
  • Décryptage TLS quand on dispose de la clé privée ou des SSLKEYLOGFILE.
  • Triage initial d'un environnement compromis : identifier les hôtes parlant à des IP suspectes.
  • Confirmation d'IoC réseau fournis par un threat intelligence feed.

03 Wireshark vs tshark vs dumpcap

OutilRôleUsage typique
dumpcapCapture bas niveau, écrit dans un fichierCapture longue durée sans charge
tsharkCLI : capture + dissection + filtrageScripts, pipelines, post-traitement automatisé
wiresharkGUI : analyse interactive, statistiques visuellesInvestigation humaine, suivi de flux, IO graphs

Règle d'or DFIR : capturer avec dumpcap ou tshark, analyser avec wireshark. La GUI consomme énormément de mémoire sur de longues captures et peut perdre des paquets.

05 Installation sous Windows

Méthode standard : installateur officiel

  1. Va sur <https://www.wireshark.org/download.html>
  2. Télécharge Wireshark-x.y.z-x64.exe.
  3. Lance l'installateur en tant qu'administrateur.
  4. Accepte l'installation de Npcap quand demandée — c'est le driver de capture.
  5. Coche « Install Npcap in WinPcap API-compatible Mode » si tu utilises d'anciens outils.
  6. Termine l'installation.

Vérification

Ouvre une invite de commande :

bat
wireshark -v

Tu dois voir : Wireshark 4.x.x (v4.x.x-x) suivi des composants et de la version de Npcap.

💡 Astuce
sur Windows, ajoute l'utilisateur au groupe Network Capture Users créé par Npcap pour lancer Wireshark sans droits admin.

06 Installation sous Linux

Ubuntu / Debian

bash
sudo apt update
sudo apt install -y wireshark tshark

L'installateur te demande « Should non-superusers be able to capture packets? » — réponds Yes (cela installe dumpcap avec les capabilities adéquates).

Puis ajoute ton utilisateur au groupe :

bash
sudo usermod -aG wireshark $USER
newgrp wireshark

Vérifie :

bash
wireshark -v
tshark -v

Fedora / RHEL / Rocky

bash
sudo dnf install -y wireshark wireshark-cli
sudo usermod -aG wireshark $USER

Arch

bash
sudo pacman -S wireshark-qt wireshark-cli
sudo usermod -aG wireshark $USER
⚠️ Attention
️ Si Wireshark refuse de lister les interfaces sans sudo, c'est que les capabilities ne sont pas posées sur dumpcap. Corriger : sudo setcap cap_net_raw,cap_net_admin=eip $(which dumpcap).

07 Installation sous macOS

Via Homebrew (recommandé)

bash
brew install --cask wireshark
brew install wireshark

Le cask installe l'application graphique. Le formula CLI installe tshark et les outils en ligne de commande.

Vérification

bash
wireshark -v
tshark -v
⚠️ Attention
️ Au premier lancement, macOS demande d'installer ChmodBPF pour donner accès aux devices réseau. Accepte, sinon les interfaces n'apparaîtront pas.

08 Capturer du trafic en direct

Avec Wireshark (GUI)

  1. Lance Wireshark.
  2. Sélectionne l'interface qui t'intéresse (eth0, wlan0, en0…).
  3. Optionnel : applique un filtre de capture (cf. section 10).
  4. Clique sur le bouton bleu d'aileron de requin pour démarrer.
  5. Clique sur le carré rouge pour arrêter.
  6. Fichier → Enregistrer sous pour conserver la capture.

Avec dumpcap (recommandé en DFIR)

bash
# Lister les interfaces
dumpcap -D

# Capturer sur eth0, rotation toutes les 1h ou 500 Mo, jusqu'à 24 fichiers
sudo dumpcap -i eth0 -b duration:3600 -b filesize:500000 -b files:24 -w /case/capture.pcapng

Cette commande crée un anneau circulaire : 24 fichiers max, rotation chaque heure ou chaque 500 Mo, le plus ancien remplacé.

Avec tshark

bash
sudo tshark -i eth0 -w /case/capture.pcapng -F pcapng -P

-P affiche les paquets à l'écran en plus de les enregistrer.

🚨 Critique
capture toujours dans un fichier pcapng (format moderne avec timestamps précis et métadonnées), jamais dans le buffer mémoire de la GUI seule. Hash le fichier (sha256sum capture.pcapng) dès qu'il est clos.

09 Ouvrir et naviguer dans un PCAP

Ouvrir

Fichier → Ouvrir → capture.pcapng. Wireshark charge tout en mémoire — sur un PCAP > 500 Mo, prévois plusieurs Go de RAM.

Vue principale

L'interface est divisée en trois zones :

  1. Liste des paquets (haut) : un paquet par ligne, colonnes No / Time / Source / Destination / Protocol / Length / Info.
  2. Détail du paquet (milieu) : arborescence des couches (Ethernet → IP → TCP → HTTP, par exemple).
  3. Octets bruts (bas) : hex + ASCII du paquet sélectionné.

Navigation utile

  • Touches Ctrl+G : aller à un numéro de paquet précis.
  • Touches Ctrl+F : rechercher dans les paquets (texte, hex, regex).
  • Clic droit sur un champ → Apply as Filter → Selected : génère un filtre display sur ce champ.
  • Clic droit sur un paquet → Follow → TCP Stream : reconstitue la conversation TCP.
💡 Astuce
crée un profil dédié dans Edit → Configuration Profiles → New, ajuste les colonnes (ajoute tcp.stream, http.host, dns.qry.name). Sauvegarde et réutilise sur chaque cas.

10 Les filtres : capture vs display

Wireshark a deux langages de filtres bien distincts.

Filtre de capture (BPF, à la capture)

Plus restrictif, syntaxe BSD Packet Filter. Réduit ce qui est écrit sur disque, à appliquer avant de capturer.

shell
host 192.168.1.5
port 443
tcp port 80 or tcp port 443
not arp and not stp
host 10.0.0.1 and port 53

Filtre d'affichage (display, après capture)

Beaucoup plus expressif. N'affecte que l'affichage, le PCAP reste complet. Syntaxe propre à Wireshark.

shell
ip.addr == 192.168.1.5
tcp.port == 443
http.request.method == "POST"
dns.qry.name contains "evil.com"
tcp.flags.syn == 1 and tcp.flags.ack == 0
http.host == "phishing-domain.example"
tcp.analysis.retransmission
frame.time >= "2026-01-15 14:00:00"
💡 Astuce
Wireshark colorie en vert un filtre display valide, en rose un filtre invalide. Et il y a l'auto-complétion sur chaque champ. Profite-en pour explorer.

Filtres DFIR essentiels

shell
# Trafic vers une IP suspecte
ip.addr == 185.142.236.123

# Requêtes DNS pour des domaines longs (potentiel DGA)
dns.qry.name.len > 30

# Requêtes HTTP vers User-Agent suspects
http.user_agent contains "powershell"

# Authentification Kerberos avec ASREP roasting potentiel
kerberos.req_type == 0xa and kerberos.padata == 0

# Transferts SMB volumineux
smb2.cmd == 9 and frame.len > 50000

11 Suivre un flux TCP / UDP / HTTP

L'une des fonctions les plus puissantes : reconstituer la conversation complète.

Suivre un flux TCP

  1. Clic droit sur n'importe quel paquet TCP de la conversation.
  2. Follow → TCP Stream.
  3. Une fenêtre s'ouvre avec client en rouge et serveur en bleu, dans l'ordre chronologique.

Format possible : ASCII, Hex Dump, C Arrays, YAML, Raw. Pour un transfert binaire, choisis Raw et Save As pour récupérer le fichier transmis.

Suivre un flux HTTP

Idem mais clic droit → Follow → HTTP Stream. Les en-têtes et le corps de chaque requête/réponse apparaissent enchaînés.

Suivre une conversation UDP

Clic droit → Follow → UDP Stream. Utile pour DNS, DHCP, VoIP.

En tshark

bash
tshark -r capture.pcapng -z follow,tcp,ascii,4

Le 4 est l'index du flux. Pour lister tous les flux : tshark -r capture.pcapng -q -z conv,tcp.

12 Statistiques essentielles

Conversations

Statistics → Conversations : tableau de toutes les paires source/destination avec volumes en paquets et octets. Tri par octets décroissants pour identifier les gros transferts suspects.

Endpoints

Statistics → Endpoints : volume par hôte unique. Cocher « Limit to display filter » pour filtrer.

Protocol Hierarchy

Statistics → Protocol Hierarchy : répartition par protocole. Si tu vois 80 % de TLS sur un port non standard ou du DNS sur le port 80, c'est suspect.

I/O Graph

Statistics → I/O Graph : volumes au cours du temps. Permet de repérer visuellement un beaconing C2 (pics réguliers) ou une exfiltration en bloc.

DNS analysis

Statistics → DNS : toutes les requêtes DNS, leur fréquence, leurs réponses. Repérer les NXDOMAIN en série (typique DGA).

💡 Astuce
sur un PCAP d'incident, commence systématiquement par Conversations (sort par octets), puis Protocol Hierarchy, puis DNS analysis. En 5 minutes tu as souvent l'angle d'attaque.

13 Extraire des fichiers transmis (HTTP, SMB, FTP)

HTTP

Fichier → Exporter les objets → HTTP. Wireshark liste tous les objets HTTP avec leur taille, hostname, content-type. Sélectionne et Save ou Save All pour tout extraire dans un dossier.

SMB

Fichier → Exporter les objets → SMB. Idem pour les fichiers partagés via SMB1/2/3 (lecture, écriture, copie).

DICOM, TFTP, IMF (email)

Mêmes principes via le menu Export Objects.

Avec tshark

bash
tshark -r capture.pcapng --export-objects http,./extracted_http

Crée un dossier extracted_http/ avec tous les fichiers HTTP transmis.

🚨 Critique
les fichiers extraits peuvent contenir du malware. Analyse-les dans un environnement isolé (sandbox, VM), jamais directement sur ton poste d'analyse.

14 Décrypter du TLS avec une clé de session

Le trafic TLS est chiffré, mais Wireshark peut le déchiffrer dans deux cas :

Cas 1 — Tu as les clés de session (SSLKEYLOGFILE)

Si l'application cliente (navigateur, curl, malware analysé) a écrit ses clés de session dans un fichier (variable d'environnement SSLKEYLOGFILE), Wireshark peut décrypter :

  1. Edit → Preferences → Protocols → TLS.
  2. (Pre)-Master-Secret log filename : pointer vers le fichier sslkeys.log.
  3. Le trafic TLS sera décrypté automatiquement.

Pour générer ce fichier pendant l'exécution d'un malware en sandbox :

bash
export SSLKEYLOGFILE=/tmp/sslkeys.log
# Le navigateur ou curl écrira les clés ici

Cas 2 — Tu as la clé privée RSA du serveur

Seulement si le serveur utilise un échange de clés RSA (rare aujourd'hui, la plupart utilisent ECDHE qui offre la forward secrecy).

  1. Edit → Preferences → Protocols → TLS.
  2. RSA keys list → Edit → New : ajouter IP, port, protocole, chemin vers la clé.
💡 Astuce
pour analyser un malware qui parle en TLS, lance-le dans une VM isolée avec SSLKEYLOGFILE défini, capture le trafic, puis charge la clé dans Wireshark pour voir le contenu en clair des communications C2.

15 tshark : Wireshark en ligne de commande

Lire un PCAP en CLI

bash
tshark -r capture.pcapng

Filtrer en CLI (display filter)

bash
tshark -r capture.pcapng -Y "http.request.method == GET"

Extraire des champs en CSV

bash
tshark -r capture.pcapng -T fields \
  -e frame.time \
  -e ip.src \
  -e ip.dst \
  -e http.host \
  -e http.request.uri \
  -E header=y -E separator=, > requests.csv

Très puissant pour pipeliner vers awk, jq, ou Splunk.

Compter les requêtes DNS uniques

bash
tshark -r capture.pcapng -Y "dns" -T fields -e dns.qry.name | sort -u | wc -l

Top 10 des hôtes contactés

bash
tshark -r capture.pcapng -q -z hosts | head -20

Décoder un protocole non standard

bash
tshark -r capture.pcapng -d tcp.port==8443,ssl -Y "ssl.handshake.type == 1"

Force le décodage du port 8443 en TLS et filtre les Client Hello.

💡 Astuce
tshark + jq est imbattable pour automatiser. Exemple : extraire tous les User-Agent uniques d'une capture HTTP : ``bash tshark -r capture.pcapng -Y "http.user_agent" -T fields -e http.user_agent | sort -u ``

16 Bonnes pratiques DFIR

🔹 Capturer dans un fichier dès le départ (jamais en buffer GUI). Privilégier pcapng avec timestamps haute résolution.

🔹 Hash immédiatement le fichier PCAP après clôture (sha256sum) et documenter dans la chaîne de preuve.

🔹 Capture rotative sur les longues durées (dumpcap -b ...) pour éviter un fichier de 50 Go ingérable.

🔹 Ne jamais ouvrir un PCAP suspect directement dans Wireshark sans précautions : certains exploits ciblent les dissecteurs eux-mêmes (CVE historiques). Utiliser tshark en CLI ou Wireshark dans une VM isolée.

🔹 Préférer un filtre de capture quand on sait ce qu'on cherche (réduit la taille du fichier et la surface d'attaque).

🔹 Conserver le PCAP original intact, travailler sur des copies filtrées (tshark -r orig.pcapng -w filtered.pcapng -Y "ip.addr == 10.1.1.5").

🔹 Documenter les filtres utilisés dans le rapport, pour qu'un autre analyste puisse reproduire ton analyse.

🔹 Croiser avec les logs (firewall, proxy, EDR) pour valider les hypothèses tirées du PCAP.

🔹 Apprendre la syntaxe BPF et display progressivement — un cheat sheet imprimé près du clavier accélère énormément.

🔹 Désactiver la résolution DNS automatique (View → Name Resolution → décoche Resolve Network Addresses) lors de l'analyse de PCAP suspect : éviter que ton poste ne contacte des serveurs DNS douteux.

🔹 Profils par cas : un profil Wireshark par investigation, avec ses colonnes, filtres et règles de coloration.

18 Conclusion

Wireshark est un outil incontournable du DFIR : aucune analyse d'incident impliquant le réseau ne se passe vraiment sans lui. Sa courbe d'apprentissage est exigeante mais payante — investir une dizaine d'heures dans la maîtrise des filtres et des statistiques transforme un analyste.

Pour aller plus loin :

  1. Pratiquer sur les exercices PCAP de malware-traffic-analysis.net (un par semaine pendant trois mois).
  2. Lire Practical Packet Analysis de Chris Sanders.
  3. Construire son propre profil DFIR avec colonnes, filtres et règles de coloration personnalisés.
  4. Automatiser les analyses récurrentes en tshark + scripts shell.

Bonnes captures ! 🦈
