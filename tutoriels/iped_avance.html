⚗️ IPED avancé — Profils custom, tasks Java, intégration

À la fin de ce tutoriel, tu sauras créer des profils custom par type de cas (fraude doc, malware, etc.), tuner le pipeline de tasks, intégrer NSRL + ProjectVic + IoCs CTI, optimiser l'OCR multi-langues, exploiter la détection de doublons et clustering, écrire des tasks Java custom, exporter l'index Lucene pour exploitation Python externe, et orchestrer un workflow IPED + Autopsy + Plaso.
🎯 Niveau expert ⏱ ~75 min ⚗️ Profils custom ☕ Tasks Java 🔍 OCR multi-langues 🔬 Workflow complet
ℹ️ Prérequis : IPED débutant (v130) + IPED standard (v124)
Niveau expert : tu maîtrises IPED de base. Place aux techniques d'architecte DFIR : profils sur mesure, pipeline de tasks tuné, intégration de hash sets, tasks Java custom, exploitation de l'index Lucene en Python externe, workflow orchestré IPED + Autopsy + Plaso.

Cluster IPED désormais en 3 niveaux (débutant v130 → standard v124 → avancé v130).

01 Prérequis et positionnement

Prérequis :

  • Tutoriel IPED débutant (v130) : tu sais créer un cas, lancer l'indexation, naviguer.
  • Tutoriel IPED standard (v124) : tu connais les modules et les recherches Lucene.
  • Bases CLI (v127) et idéalement CLI intermédiaire (v128) pour scripting.
  • Notions Java (pour les tasks custom).

Ce que tu sauras à la fin :

  • Créer des profils custom adaptés à chaque type de cas
  • Tuner parsers, OCR, threads pour 5-10× plus de perf
  • Intégrer NSRL, ProjectVic, IoCs CTI
  • Écrire des tasks Java custom
  • Exporter et exploiter l'index Lucene en CLI et en Python externe
  • Orchestrer un workflow complet IPED + Autopsy + Plaso

02 Architecture IPED en profondeur

shell
┌──────────────────────────────────────────┐
│         Interface Swing (Java)           │
├──────────────────────────────────────────┤
│         Pipeline de tasks                │
│  (chaîne de modules Java configurables)  │
├──────────────────────────────────────────┤
│   Index Lucene + base SQLite             │
│   (text, metadata, thumbnails)           │
├──────────────────────────────────────────┤
│      Parsers Apache Tika                 │
│   (1500+ formats : DOCX, PDF, EML, etc.) │
├──────────────────────────────────────────┤
│   Sleuth Kit (TSK) en backend            │
│  (lecture FS, identique à Autopsy)       │
├──────────────────────────────────────────┤
│     Tesseract OCR + JBIG2 + autres       │
└──────────────────────────────────────────┘

Composants clés

  • Pipeline de tasks : chaîne ordonnée de traitements (Hash, Sig, OCR, Carving, Indexing...)
  • Lucene : index full-text mais aussi base de métadonnées (taille, dates, hashs)
  • SQLite : stockage relationnel des métadonnées et liens
  • Apache Tika : parsing universel (1500+ formats)
  • Tesseract : OCR multi-langues
  • TSK (Sleuth Kit) : même backend qu'Autopsy

Différence essentielle avec Autopsy

  • Autopsy : "Ingest modules" parallèles indépendants. Plugins en Jython 2.7.
  • IPED : "Tasks" en pipeline séquentiel. Plugins en Java natif.

IPED est plus monolithique mais souvent plus performant sur l'indexation.

03 Comprendre IPEDConfig.txt et profils

Toute la configuration d'IPED est dans des fichiers texte. Cœur du système :

conf/IPEDConfig.txt :

shell
# Performance
numThreads = auto                 # auto = CPU cores
ramSize = 16G                     # RAM allouée à la JVM
indexTempOnSSD = true             # SSD pour temp

# Modules
enableHashTask = true
enableOCR = true
enableCarving = true
enableHTMLReport = true
enableImageThumbs = true

# OCR
ocrLanguage = eng+por+spa         # langues OCR
ocrSkipKnownFiles = true          # skip NSRL

# Carving
enableCarving = true
carvingFolder = $HOME/.iped/carving

# Network
enableYaraScan = false            # règles YARA

Profils prédéfinis

Dossier profiles/ :

shell
profiles/
├── default/
│   ├── conf/
│   │   └── IPEDConfig.txt
│   └── ...
├── forensic/
├── triage/
├── photo_dna/
└── blind/

Chaque profil = surcharge de la config par défaut.

04 Créer un profil custom

Cas concret : tu veux un profil "fraude documentaire" : OCR maximal multi-langues, hashing strict, carving désactivé (pas d'images supprimées attendues).

Étape 1 : copier un profil de base

bash
cd /opt/iped-X.Y.Z/profiles
cp -r default fraude_doc

Étape 2 : adapter fraude_doc/conf/IPEDConfig.txt

shell
# fraude_doc — profil sur mesure
numThreads = auto
ramSize = 24G                     # cas exigeant en RAM

# Modules pertinents
enableHashTask = true
enableOCR = true
enableCarving = false             # désactivé : pas de carving
enableHTMLReport = true
enableImageThumbs = true

# OCR maximal
ocrLanguage = eng+fra+deu+ita+spa+por
ocrMinPageWidth = 200             # OCR sur tout sauf miniatures
ocrSkipKnownFiles = true          # gain temps via NSRL

# Hashs
enableHashTask = true
hashTask.computeMD5 = true
hashTask.computeSHA1 = true
hashTask.computeSHA256 = true
hashTask.computeEdonkey = false   # pas nécessaire

# Catégorisation enrichie
categoriesFile = $PROFILE/conf/CategoriesByTypeConfig.txt

Étape 3 : enrichir les catégories

fraude_doc/conf/CategoriesByTypeConfig.txt peut définir des catégories sur mesure (par exemple "Factures", "Contrats", "Photocopies") basées sur des patterns dans les métadonnées ou le contenu.

Étape 4 : utiliser le profil

Au lancement du cas, sélectionner fraude_doc dans le wizard.

Ou en CLI :

bash
iped.sh -profile fraude_doc -d /path/to/image.E01 -o /path/to/case
💡 Astuce
à mesure que tu enchaînes les cas, tu construis ta bibliothèque de profils (fraude, harcèlement, malware, intrusion, mobile). Versionner dans Git interne.

05 Tasks d'IPED — comprendre le pipeline

Le pipeline IPED est une chaîne ordonnée. Chaque task a un nom, une config, peut être activée/désactivée.

Tasks principales

TaskRôle
SignatureTaskDétecte le vrai type MIME (vs extension)
CarverTaskCarving récursif
HashTaskCalcule MD5/SHA-1/SHA-256/Edonkey
HashDBLookupTaskCompare aux bases (NSRL, IoCs)
OCRTaskTesseract sur images
ParsingTaskApache Tika sur tout fichier
ImageThumbTaskGénère vignettes
VideoThumbsTaskVignettes vidéos
IndexTaskConstruit l'index Lucene
DuplicateTaskDétecte les doublons
PhotoDNATaskDétection contenu illégal (licence)
NamedEntityTaskEntités nommées (NER)
HTMLReportTaskGénère rapport

Activer / désactiver

Dans conf/IPEDConfig.txt :

shell
enableHashTask = true
enableOCRTask = false      # désactivé
enableCarverTask = true

Configurer une task

Chaque task a son propre fichier de config dans conf/ :

  • OCRConfig.txt
  • HashTaskConfig.txt
  • CategoriesByTypeConfig.txt
  • RegexConfig.txt
  • etc.
💡 Astuce
avant de tuner les paramètres, lire le commentaire en début de chaque fichier de config — la doc est inline.

06 Configurer NSRL et ProjectVic

NSRL (filtrer le bénin)

Comme dans Autopsy avancé (v129).

conf/HashTaskConfig.txt :

shell
hashesDB = $HOME/hashes/nsrl.db
hashesDB.format = nsrl
hashesDB.action = ignore        # ignorer les fichiers NSRL (gain temps massif)

Variants :

  • ignore : skip l'indexation
  • ignoreContent : indexer métadonnées mais pas contenu
  • flag : flag mais traiter

Hash IoCs custom (CTI interne)

Fichier iocs_2026.csv :

shell
sha256,description
abc123...,"Malware Emotet variant"
def456...,"Cobalt Strike beacon"

Importer comme Known Bad :

shell
hashesDB.bad = /path/to/iocs_2026.csv
hashesDB.bad.action = flag

Les fichiers correspondants apparaîtront dans la catégorie Hash hits avec flag rouge.

ProjectVic

Pour les services autorisés (police pédopornographie). Configuration similaire mais avec hashesDB.format = projectvic.

07 Carving avancé avec IPED

IPED utilise un carving signature-based avec ses propres parsers + intégration optionnelle de photorec.

Configuration

conf/CarverConfig.txt :

shell
# Tailles min/max
minFileSize = 1024
maxFileSize = 100M

# Signatures actives
enable.jpg = true
enable.pdf = true
enable.docx = true
enable.zip = true
enable.exe = false               # ignore exe (souvent fragmentés)
enable.png = true

# Source
carveOnlyUnallocated = false     # carving aussi dans allocated
                                  # (utile pour trouver fichiers dans archives intactes)

Cas DFIR : récupérer des PDF supprimés

shell
enable.pdf = true
enable.jpg = true
enable.png = true
enable.docx = true
# Désactiver le reste pour ne pas être noyé
enable.zip = false
enable.exe = false

Cibler les formats = 5-10× plus rapide qu'un carving exhaustif.

08 OCR multi-langues et optimisation

Langues

conf/OCRConfig.txt :

shell
# Langues OCR (codes ISO Tesseract)
ocrLanguage = eng+fra+deu+ita+spa+por+rus+ara+chi_sim+chi_tra

# Engine Tesseract
tesseractCmd = tesseract
tesseractDataPath = /opt/iped/jre/share/tessdata

# Optimisations
ocrMinPageWidth = 300           # skip miniatures
ocrSkipKnownFiles = true        # NSRL skip
ocrMaxImageWidth = 5000         # downscale géants
ocrTimeout = 600                # 10 min max par image

Compromis vitesse / précision

  • Plus de langues = OCR plus précis (détecte le bon scripted) mais plus lent
  • Tesseract 5 : 2-3× plus rapide que Tesseract 4 pour résultats équivalents

Vérification

Après indexation, tester :

  1. Catégorie Documents → Images contenant texte
  2. Recherche Lucene sur un mot connu dans une image OCR'd
  3. Si pas trouvé : problème de langue ou de config

09 Détection des doublons et clustering

IPED a une task DuplicateTask qui détecte les fichiers identiques par hash.

Configuration

shell
enableDuplicateTask = true
duplicateTask.checkMD5 = true
duplicateTask.checkSHA256 = true
duplicateTask.linkDuplicates = true     # crée des liens entre doublons dans l'UI

Cas DFIR

  • Filtrage : ne traiter qu'un exemplaire de chaque fichier identique
  • Réseaux d'échange : repérer le même fichier illégal sur plusieurs supports
  • Fuites de données : croiser hash d'un document interne avec ce qu'on trouve sur disque suspect

Clustering par similitude

Au-delà du hash exact, IPED peut faire du clustering (fichiers proches mais pas identiques) avec des hashs perceptuels (pHash).

shell
enableSimilarImagesTask = true
similarImageTask.threshold = 0.85

Utile pour : "trouve-moi toutes les images similaires à celle-ci" (recadrages, compressions différentes du même original).

10 Communicating accounts et liens entre artefacts

IPED extrait automatiquement les comptes de communication (emails, téléphones) trouvés dans les fichiers.

Comme Autopsy CommAccounts

Vue dans l'UI : Communications → graphe des comptes et échanges.

Configuration

shell
enableCommAccountsExtraction = true
commAccounts.emailPattern = .*@.*\..*
commAccounts.phonePattern = \+?[0-9]{8,15}

Cas DFIR

Enquête fraude : retrouver qui a communiqué avec qui, fréquence, période. Visualisation parlante pour magistrat.

Combiner avec Maigret (v128) sur les emails trouvés pour enrichir.

11 Intégration Plaso (super-timeline)

IPED n'a pas Plaso intégré comme Autopsy, mais on peut produire une super-timeline externe et l'analyser en parallèle.

Workflow

bash
# Étape 1 — IPED sur l'image
iped.sh -d image.E01 -o /cases/INC2026/iped/

# Étape 2 — Plaso sur la même image (cf. tuto Plaso v124)
log2timeline.py /cases/INC2026/timeline.plaso image.E01
psort.py -o l2tcsv -w /cases/INC2026/timeline.csv /cases/INC2026/timeline.plaso

# Étape 3 — Importer le CSV dans IPED comme source additionnelle
# (Add Folder dans le wizard, pointer sur le CSV)

L'index Lucene IPED indexe alors la timeline texte — tu peux faire des recherches Lucene sur la timeline (HOST(\"PC-SUSPECT\") AND TYPE(\"USB\")).

Vue temporelle

IPED n'a pas de vue temporelle native équivalente à Autopsy Timeline View. Alternative : exporter la liste filtrée IPED en CSV → ouvrir dans Timesketch ou Excel pour visualisation.

12 Sortie et exports — exploiter en Python externe

L'index IPED est dans /indexador/. C'est un index Lucene standard.

Exporter la liste des artefacts

Dans l'UI : File → Export → CSV (ou directement filtrer puis exporter).

Exploiter en Python

python
#!/usr/bin/env python3
"""Lecture index Lucene IPED en Python via pylucene OU via export CSV"""

import csv
from collections import Counter

with open('export_iped.csv', 'r', encoding='utf-8') as f:
    reader = csv.DictReader(f)
    rows = list(reader)

# Top 10 extensions
ext_counter = Counter()
for r in rows:
    name = r.get('Name', '')
    if '.' in name:
        ext = name.rsplit('.', 1)[-1].lower()
        ext_counter[ext] += 1

print("Top 10 extensions :")
for ext, count in ext_counter.most_common(10):
    print(f"  .{ext:10s} {count}")

Croiser avec d'autres outils

python
# Croiser hashs IPED avec hashs VirusTotal
import hashlib
import requests
import os

VT_KEY = os.environ['VT_API_KEY']

for r in rows:
    sha = r.get('SHA-256', '').strip()
    if not sha:
        continue
    resp = requests.get(
        f'https://www.virustotal.com/api/v3/files/{sha}',
        headers={'x-apikey': VT_KEY}
    )
    if resp.status_code == 200:
        data = resp.json()['data']['attributes']
        malicious = data['last_analysis_stats']['malicious']
        if malicious > 0:
            print(f"⚠️  {r['Name']} flagué malicieux ({malicious} engines)")
💡 Astuce
IPED indexe et catégorise. Python externe enrichit (VirusTotal, AbuseIPDB) et produit des analyses sur mesure. Combo puissant.

13 Lucene query syntax avancée

Recherche par champ

L'index IPED expose de nombreux champs :

shell
name:facture                   # nom de fichier
contains:"contrat important"   # contenu
path:Documents                 # chemin
size:[1000 TO 10000]           # taille (octets)
modified:[2026-01-01 TO 2026-01-31]
hash.sha256:abc123
type:application/pdf
category:Documents

Combinaisons

shell
contains:fraude AND modified:[2025-01-01 TO 2025-12-31]
name:*.docx AND NOT path:Temp
contains:bitcoin OR contains:crypto

Wildcards et fuzzy

shell
trans*                         # transaction, transfer, etc.
contrat~                       # fuzzy : contrant, ontrat, contrt

Regex

shell
/[0-9]{2}-[0-9]{2}-[0-9]{4}/

Boost

shell
contrat^3 OR facture           # contrat 3× plus important dans le scoring

14 Écrire une task Java custom

IPED supporte des tasks Java (pas Python) custom.

Squelette

src/main/java/iped/MyCustomTask.java :

java
package iped;

import iped.engine.task.AbstractTask;
import iped.data.IItem;
import iped.configuration.Configurable;
import java.util.List;
import java.util.Collections;

public class MyCustomTask extends AbstractTask {

    @Override
    public void init(ConfigurationManager configManager) throws Exception {
        // Initialisation : charger config, ouvrir ressources
    }

    @Override
    public void finish() throws Exception {
        // Nettoyage
    }

    @Override
    public List<Configurable<?>> getConfigurables() {
        return Collections.emptyList();
    }

    @Override
    public boolean isEnabled() {
        return true;
    }

    @Override
    protected void process(IItem item) throws Exception {
        String name = item.getName();
        if (name.endsWith(".donottouch")) {
            item.setCategory("Donottouch");
            item.setExtraAttribute("flagged", true);
        }
    }
}

Compiler et déployer

bash
javac -cp /opt/iped/lib/iped-engine.jar MyCustomTask.java
jar cf my-task.jar MyCustomTask.class
cp my-task.jar /opt/iped/lib/plugins/

Activer dans conf/TaskInstallerConfig.txt :

shell
iped.MyCustomTask
💡 Astuce
IPED Java = plus performant mais plus complexe à coder. Autopsy Jython = plus simple mais limité.

15 Configuration multi-threading et RAM

CPU

shell
numThreads = auto                # par défaut auto = CPU cores
numThreads = 16                  # forcer 16 threads

Sur multi-socket : numThreads = 32 peut être contre-productif (saturation L3 cache). Tester : commencer à cores * 1 puis ajuster.

RAM

shell
ramSize = 32G                    # JVM heap (Xmx)
indexTempOnSSD = true            # SSD pour les fichiers temporaires

Règles empiriques :

  • Cas < 100 Go : 8 Go suffisent
  • Cas 100-500 Go : 16 Go minimum
  • Cas > 500 Go : 32 Go recommandés
  • Cas > 2 To : 64 Go + SSD NVMe dédié

Cache de l'OS

Éviter de saturer la RAM par d'autres applications pendant l'indexation. Idéalement : machine dédiée IPED.

SSD temp

shell
tempDir = /mnt/ssd/iped_tmp

Sur cas géants, prévoir 500 Go de scratch sur SSD séparé.

16 IPED en CLI et scripting

IPED peut tourner headless (sans GUI) pour automatisation.

Indexation CLI

bash
iped.sh -d /path/to/image.E01 -o /path/to/case -profile forensic --portable
FlagEffet
-dData source (image, dossier)
-oOutput (case)
-profileProfil à utiliser
--portableCas portable (chemins relatifs)
--no-guiPas d'interface
--continueReprendre indexation interrompue

Recherche CLI

Pas de mode "search CLI" natif. Workaround : utiliser PyLucene ou parser l'export CSV.

Automation multi-cas

bash
#!/bin/bash
# Indexer 10 images en série, profil "fraude_doc"

for img in /cases/2026/*.E01; do
    name=$(basename "$img" .E01)
    iped.sh -d "$img" -o "/cases/2026_iped/$name" \
        -profile fraude_doc --portable --no-gui
done

Pour parallélisation : utiliser GNU parallel (cf. tuto CLI expert v128).

17 Workflow d'enquête complet IPED + Autopsy + Plaso

Cas : intrusion serveur Linux + poste compromis

shell
INC-2026-005
├── Source 1 : disque dur serveur web (linux ext4, 500 Go)
├── Source 2 : disque dur poste analyste (Windows, 1 To)
├── Source 3 : dump RAM poste (16 Go)
└── Source 4 : PCAP 24h

Pipeline

bash
# 1. Acquisition + hash
sha256sum src1.E01 src2.E01 src3.mem src4.pcap > MANIFEST.txt

# 2. IPED sur les disques (indexation et catégorisation)
iped.sh -d src1.E01 -d src2.E01 -o /cases/INC2026005/iped/ \
    -profile forensic --no-gui

# 3. En parallèle : Plaso sur les disques (cf. tuto v124)
log2timeline.py /cases/INC2026005/timeline.plaso src1.E01 src2.E01
psort.py -o l2tcsv -w /cases/INC2026005/timeline.csv \
    /cases/INC2026005/timeline.plaso

# 4. Volatility sur la RAM (cf. tuto v124)
vol -f src3.mem windows.pslist > /cases/INC2026005/pslist.txt
vol -f src3.mem windows.netstat > /cases/INC2026005/netstat.txt

# 5. tshark sur le PCAP (cf. tuto CLI expert v128)
tshark -r src4.pcap -q -z conv,ip > /cases/INC2026005/conversations.txt

# 6. Autopsy aussi sur src2.E01 pour bénéficier de la timeline view
# (lancement GUI)

# 7. Exploitation IPED : recherche Lucene croisée
# - contains:cobalt strike OR contains:beacon
# - category:Encrypted AND modified:[2026-01-15 TO 2026-01-25]
# - regex:/[0-9]+\.[0-9]+\.[0-9]+\.[0-9]+/ AND path:logs

# 8. Croisement Plaso (timeline) avec recherches IPED
# - identifier le pic d'activité dans timeline.csv
# - chercher dans IPED les fichiers modifiés à cette heure

# 9. Rapport final
# - IPED HTML report avec bookmarks
# - Autopsy HTML report
# - Synthèse rédigée
💡 Astuce
chaque outil voit ce que les autres ratent. IPED + Autopsy + Plaso + Volatility + tshark = vue complète.

18 Forces, faiblesses et limites

Forces

✅ Indexation rapide sur gros volumes (Lucene très optimisé).

✅ OCR intégré multi-langues : avantage majeur.

✅ Galerie d'images très ergonomique.

✅ Détection de doublons + clustering native.

✅ Tasks pipeline : architecture claire et extensible.

✅ CLI complet : automation et scripting possibles.

✅ Profils : facile de capitaliser sur les types de cas récurrents.

✅ TSK en backend : tous les filesystems supportés.

✅ Apache Tika : 1500+ formats parsés.

✅ Open source EPL 2.0 : auditable.

Faiblesses

❌ Communauté plus restreinte qu'Autopsy.

❌ Documentation parfois clairsemée (et beaucoup en portugais).

❌ Pas de multi-user intégré (contrairement à Autopsy).

❌ Plugins Java uniquement (plus complexe que Jython).

❌ Pas de mode CLI search intégré : il faut PyLucene ou export.

❌ RAM gourmand : minimum 16 Go pour cas sérieux.

❌ Plaso non intégré : workflow externe nécessaire.

❌ Pas de communauté française active (forum, tutoriels).

❌ Mobile limité vs Cellebrite/AXIOM payants.

19 Bonnes pratiques expert

🔹 Bibliothèque de profils : un profil custom par type de cas (fraude doc, malware, mobile, intrusion réseau). Versionner dans Git interne.

🔹 NSRL à jour : trimestriellement. Configurer ignore pour gain temps massif.

🔹 OCR ciblé : ne pas activer toutes les langues — seulement les pertinentes (Suisse FR/DE/IT/EN suffisent).

🔹 SSD NVMe pour les cas sérieux. Disque mécanique = supplice.

🔹 RAM 16 Go minimum, 32 Go pour cas > 500 Go.

🔹 Séparer image source et cas : disques différents pour performance.

🔹 Hash systématique avant et après indexation.

🔹 Tester sur image de test avant production : valider config OCR, profil custom, exclusions.

🔹 Croiser avec Autopsy : ils trouvent des choses différentes. Un seul outil ne suffit jamais.

🔹 Plaso en parallèle : pour la timeline forensique qui manque dans IPED.

🔹 Logs IPED : log.txt du cas pour audit/debug.

🔹 Exporter en CSV + Python pour analyses sur mesure non prévues par l'UI.

🔹 Tasks Java custom pour les patterns récurrents de ton organisation.

🔹 Suivre les releases : IPED s'améliore régulièrement (perf, formats).

🔹 Contribuer à la communauté : pull requests si tu améliores quelque chose.

🔹 Documenter chaque cas : profil utilisé, version IPED, paramètres clés.

21 Conclusion

Tu disposes maintenant des techniques d'un expert IPED. Profils custom, tuning de pipeline, intégration NSRL/CTI, OCR multi-langues optimisé, tasks Java custom, CLI scripting : tu peux orchestrer un workflow d'indexation industriel.

IPED brille particulièrement sur :

  • Gros volumes (indexation rapide)
  • Cas riches en documents/images (OCR)
  • Recherches Lucene complexes
  • Détection de doublons et clustering

Mais ne suffit pas seul. Le multi-outil (IPED + Autopsy + Plaso + Volatility + outils CLI) reste la règle pour les enquêtes sérieuses.

Recommandations finales :

  1. Construire ta bibliothèque de profils custom par type de cas.
  2. Maintenir NSRL à jour trimestriellement.
  3. Comparer systématiquement IPED + Autopsy sur les mêmes cas — chacun trouve des choses différentes.
  4. Apprendre Apache Tika et Lucene en profondeur — c'est le moteur derrière IPED.
  5. Écrire des tasks Java custom pour capitaliser sur les enquêtes récurrentes.
  6. Suivre le projet sur GitHub pour les évolutions.
  7. Croiser avec Plaso et Volatility sur chaque cas — IPED ne fait pas tout.
  8. Contribuer au moins une pull request à la communauté.

L'expertise multi-outil sépare l'analyste DFIR de l'architecte. Tu es prêt pour ce niveau. 🔬
