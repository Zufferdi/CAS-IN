🦖 Velociraptor — DFIR endpoint à distance

À la fin de ce tutoriel, tu sauras installer Velociraptor en standalone, déployer des agents Windows via MSI, écrire et lancer un hunt sur des centaines d'endpoints en VQL, intégrer KAPE via l'artefact dédié, générer un collecteur offline autonome, et chasser des menaces avec Sigma + YARA à l'échelle.
🎯 Niveau expert ⏱ ~70 min 🐧 Serveur Linux 🪟 Windows / Linux / macOS agents 🌐 Endpoint à l'échelle 🛠️ VQL (SQL-like)
ℹ️ À propos de Velociraptor
Velociraptor est la plateforme open source de collecte forensique distante et de chasse aux menaces à l'échelle. Développée par Mike Cohen (ex-Google, auteur de GRR) depuis 2018, soutenue par Rapid7. Permet d'agir sur des milliers d'endpoints depuis un point central, en open source autohébergeable.

📦 github.com/Velocidex/velociraptor · Licence Apache 2.0

01 Présentation générale

Velociraptor est un agent endpoint + serveur central + langage de requête (VQL) qui permet, depuis un point central, de :

  • Interroger des milliers d'endpoints Windows / Linux / macOS simultanément
  • Collecter des artefacts forensiques distants en quelques minutes
  • Chasser des menaces avec Sigma, YARA, ou des règles VQL custom
  • Quarantainer un endpoint compromis (isolation réseau)
  • Triage offline pour générer un binaire autonome à exécuter sur un poste isolé

Le tout en open source, autohébergeable, sans agent commercial à payer.

C'est l'outil utilisé par les CERT modernes, les MSSP et plusieurs services nationaux (CISA, NCSC-FI, ANSSI dans certains incidents).

02 Cas d'usage typiques

  • Réponse à incident à l'échelle : un ransomware touche 200 postes, tu veux les identifier et collecter en parallèle.
  • Chasse menaces (threat hunting) : balayer 5000 endpoints à la recherche d'un IoC spécifique.
  • Forensique distant : collecter Prefetch + Amcache + EVTX sur un poste à 800 km sans VPN.
  • Triage offline : générer un binaire autonome (Windows .exe) que l'utilisateur lance, qui collecte et envoie vers un partage S3.
  • Quarantaine d'un endpoint : isolation réseau immédiate d'un poste compromis.
  • Monitoring continu : agent persistant qui remonte des événements en quasi temps réel.
  • Préservation d'urgence : capturer la mémoire d'un poste suspect avant que l'utilisateur ne s'en rende compte.
  • Audit de conformité : vérifier que tous les postes ont un AV à jour, BitLocker activé, etc.

| (agents)       |  pinned cert        | Velociraptor     |
| Windows/Linux/ |                     | (Frontend +      |
| macOS          |                     |  Datastore +     |
+----------------+                     |  GUI)            |
                                       +-----------------+
                                                ^
                                                |
                                       +-----------------+
                                       | Analyste DFIR    |
                                       | (HTTPS GUI ou   |
                                       |  velociraptor   |
                                       |  CLI)           |
                                       +-----------------+
  • Endpoint : exécute l'agent velociraptor.exe (Windows) ou binaire (Linux/macOS). L'agent est piloté par le serveur via gRPC avec authentification mTLS (certificats épinglés).
  • Serveur : héberge le datastore (fichiers), la GUI web, et le frontend gRPC. Peut tourner sur un VPS / serveur on-prem.
  • Analyste : se connecte via la GUI HTTPS ou la CLI pour lancer des hunts, collecter des artefacts, consulter les notebooks.

Modèle de déploiement

  • Standalone : un seul binaire velociraptor, fait serveur + GUI. Idéal pour les petits déploiements (< 1000 endpoints).
  • Multi-frontend : plusieurs frontends derrière un load balancer pour les déploiements massifs (> 10 000 endpoints).
  • Triage offline : aucun serveur, un binaire autonome avec configuration embarquée qui exporte vers S3 ou partage SMB.

04 VQL : le langage de Velociraptor

VQL (Velociraptor Query Language) est un langage proche de SQL spécialisé pour la forensique. Toute interaction avec Velociraptor — collecte, chasse, monitoring — se fait via VQL.

Exemple basique

Lister les processus avec une commande PowerShell :

sql
SELECT Pid, Name, CommandLine
FROM pslist()
WHERE CommandLine =~ "powershell"

Concepts clés

  • Plugins : fonctions qui retournent des données (pslist(), glob(), parse_evtx(), parse_pe())
  • Fonctions : transformations sur des valeurs (hash(), regex_replace(), parse_string_with_regex())
  • Sources : un artefact peut avoir plusieurs sources (collecte côté client + post-traitement côté serveur)
  • Parameters : un artefact prend des paramètres réglables au lancement

Lecture d'un artefact

Les artefacts (collectes prédéfinies) sont des fichiers YAML qui contiennent du VQL. Exemple simplifié :

yaml
name: Windows.System.Pslist
description: List Windows processes
parameters:
  - name: ProcessRegex
    default: .
sources:
  - query: |
      SELECT Pid, Ppid, Name, Exe, CommandLine
      FROM pslist()
      WHERE Name =~ ProcessRegex

Cet artefact est invocable depuis la GUI avec un paramètre ProcessRegex configurable.

06 Installation du serveur (Linux)

Étape 1 : télécharger le binaire

bash
# Sur Debian/Ubuntu
mkdir -p /opt/velociraptor && cd /opt/velociraptor
wget https://github.com/Velocidex/velociraptor/releases/latest/download/velociraptor-v0.x.x-linux-amd64
mv velociraptor-v0.x.x-linux-amd64 velociraptor
chmod +x velociraptor

Remplace v0.x.x par la dernière version (au moment de l'écriture, branche 0.7.x).

Étape 2 : générer une configuration

bash
./velociraptor config generate -i

Mode interactif. Réponds aux questions :

  • OS du serveur : Linux
  • Path datastore : /opt/velociraptor/datastore
  • Logs : /opt/velociraptor/logs
  • DNS / nom public : vr.example.com (ou IP)
  • Frontend port : 8000 (TCP, exposé aux agents)
  • GUI port : 8889 (HTTPS, exposé aux analystes)
  • Utiliser Let's Encrypt ? Oui pour production, Non pour PoC (certificat auto-signé)
  • Créer un compte admin : oui

Deux fichiers générés :

  • server.config.yaml (pour démarrer le serveur)
  • client.config.yaml (à embarquer dans les agents)

Étape 3 : initialiser le datastore et créer l'admin

bash
./velociraptor --config server.config.yaml user add admin --role administrator

Tu seras invité à saisir un mot de passe.

Étape 4 : lancer le serveur

bash
./velociraptor --config server.config.yaml frontend -v

Le serveur écoute sur les ports configurés. La GUI est accessible à https://localhost:8889/.

💡 Astuce
crée un service systemd. Velociraptor fournit une commande pour générer le fichier service : ``bash ./velociraptor --config server.config.yaml service install ``

Vérification

bash
curl -k https://localhost:8889/

Devrait répondre la page de login.

07 Génération et déploiement des agents Windows

Étape 1 : créer un installeur MSI Windows

Depuis le serveur :

bash
./velociraptor --config client.config.yaml package install msi --msi_name velociraptor-client.msi

Cela génère velociraptor-client.msi contenant l'agent + la configuration client (URL du serveur, certificat épinglé).

Étape 2 : déployer sur les endpoints

Plusieurs voies :

  • Manuel : copier le MSI et l'installer (msiexec /i velociraptor-client.msi /qn)
  • GPO : Software Installation policy avec le MSI
  • Intune / SCCM / Tanium : déployer comme tout autre logiciel
  • Ansible / Chef / Puppet : installation via gestionnaire de config
  • Script PowerShell sur poste isolé

Une fois installé, l'agent enregistre un service Velociraptor qui se lance au démarrage.

Étape 3 : vérifier dans la GUI

Connecte-toi à <https://vr.example.com:8889/> avec ton compte admin. Onglet Search clients → l'agent doit apparaître après quelques secondes.

Étape 4 : labels et organisation

Pour ranger les clients par criticité ou par site, applique des labels :

sql
SELECT label(client_id="C.123abc", labels="critical,site-geneva", op="set")
FROM scope()

Tu peux ensuite filtrer les hunts par label.

08 Premier hunt : lister les processus

Un hunt est une collecte lancée sur plusieurs clients à la fois. C'est le concept central de Velociraptor.

Via la GUI

  1. Hunt Manager → New Hunt
  2. Description : « Liste des processus PowerShell suspects »
  3. Expiry : 24 hours
  4. Condition : OS == "windows" (ou un label)
  5. Artifact Selection : choisir Windows.System.Pslist
  6. Parameters : ProcessRegex = powershell|cmd|wmic
  7. Resources : limite par défaut (10 minutes CPU, 100 Mo RAM)
  8. Review and launch

Le hunt démarre. Au fur et à mesure que les agents se connectent, ils exécutent la collecte et remontent les résultats.

Consulter les résultats

Hunt Manager → Selectionne le hunt → Results. Tu vois un tableau agrégé de tous les clients, avec la commande PowerShell détectée.

Avec l'API CLI

bash
./velociraptor --config server.config.yaml \
  hunts create \
  --description "Pslist hunt" \
  --artifact Windows.System.Pslist \
  --condition 'OS == "windows"'
💡 Astuce
nomme tes hunts avec un identifiant de ticket (INC-2026-0123 — Pslist) pour pouvoir les retrouver après le post-mortem.

10 Collecter avec KAPE via Velociraptor

Velociraptor intègre KAPE via l'artefact Windows.KapeFiles.Targets.

Configuration

  1. Hunt → New Hunt
  2. Artifact : Windows.KapeFiles.Targets
  3. Parameters :
  • Device: C:
  • KapeTargets : !SANS_Triage (ou autre composite)
  • UseAutoAccessor : Y (NTFS raw access pour fichiers verrouillés)
  • Output : vfs (stocke dans le datastore Velociraptor)

Lance le hunt. Les agents exécutent la collecte KAPE-style directement et remontent les fichiers via le canal gRPC chiffré.

Avantages

  • Pas besoin de copier KAPE sur la cible (Velociraptor implémente nativement les Targets)
  • Les fichiers transitent chiffrés (TLS + mTLS) vers le serveur central
  • Centralisation immédiate (pas de partage SMB / clé USB à gérer)
  • Hash + provenance documentés automatiquement

Récupérer la collecte

Dans la vue du client → Collected → ton hunt apparaît → Download zip te donne l'archive complète.

11 Mode triage offline (collector standalone)

Cas typique : tu dois faire le triage d'un poste isolé (sans accès au serveur Velociraptor) ou d'un poste où tu ne veux pas installer d'agent permanent.

Générer un collecteur autonome

Dans la GUI :

  1. Server Artifacts → Server.Utils.CreateCollector
  2. Parameters :
  • OS : Windows
  • target : ZIP
  • target_args : nom du fichier de sortie
  • Artifacts : sélectionner les artefacts à collecter (Pslist, Prefetch, EvtxECmd, etc.)
  1. Launch

Velociraptor compile un exécutable autonome (Collector_velociraptor.exe, ~50 Mo) qui contient tous les artefacts demandés.

Utiliser le collecteur

Copie le binaire sur la machine cible (clé USB, partage). Lance-le en admin :

bat
Collector_velociraptor.exe

Il collecte tout, crée un ZIP local, et c'est fini. Tu récupères le ZIP et tu l'importes ensuite sur le serveur Velociraptor pour analyse.

Variantes d'output

  • ZIP : local
  • S3 : upload direct S3
  • Azure : upload Azure Blob
  • SFTP : envoi SFTP
  • GCS : Google Cloud Storage
💡 Astuce
prépare en amont des collecteurs offline pré-configurés par scénario (triage_workstation.exe, triage_server.exe, memory_capture.exe) sur ta clé USB d'intervention.

12 Chasse Sigma et YARA à l'échelle

Sigma : chasse dans les EVTX

L'artefact Generic.Detection.SigmaRules permet d'évaluer des règles Sigma (le standard ouvert de détection) sur les journaux EVTX de tous les endpoints.

  1. Hunt → Generic.Detection.SigmaRules
  2. Paramètres :
  • SigmaRulePath : URL ou contenu YAML des règles
  • EVTXGlob : C:\Windows\System32\winevt\Logs\*.evtx

Velociraptor évalue les règles côté client (économise la bande passante) et remonte uniquement les hits.

Tu peux pointer vers le dépôt officiel SigmaHQ (~3000 règles maintenues par la communauté) ou tes propres règles.

YARA : chasse sur les fichiers et la mémoire

L'artefact Generic.Forensic.Yara.Glob scanne des fichiers selon un pattern avec des règles YARA.

  1. Hunt → Generic.Forensic.Yara.Glob
  2. Paramètres :
  • Glob : ex. C:\Users\**\AppData\Local\Temp\*.exe
  • YaraRule : contenu YARA ou URL d'un fichier .yar

Pour scanner la mémoire d'un processus (détection Cobalt Strike, Meterpreter), utiliser Windows.Detection.Yara.Process.

💡 Astuce
utiliser des packs YARA de référence (florian-roth/signature-base, Volexity, Mandiant) pour la chasse APT à l'échelle.

13 Notebooks et investigation interactive

Velociraptor inclut des notebooks type Jupyter pour l'analyse interactive en VQL.

Créer un notebook

  1. Notebooks → New Notebook
  2. Ajouter une cellule VQL :
sql
SELECT Name, Pid, CommandLine
FROM pslist()
WHERE CommandLine =~ "powershell"
  1. Exécute. Résultats en tableau.

Cellules Markdown

Intercaler des cellules Markdown pour documenter ton raisonnement, comme dans Jupyter.

Cellules Python / shell

Velociraptor 0.7+ supporte des cellules Python pour traitement avancé (pandas, etc.). Utile pour les graphiques complexes ou l'intégration avec d'autres APIs.

Cas d'usage

  • Post-incident : reconstituer l'attaque en interrogeant successivement les hunts
  • Brouillon de nouvel artefact : développer du VQL en mode REPL avant de le coder en YAML
  • Rapport interactif : produire un notebook commenté à remettre au client

14 Forces de Velociraptor

✅ Open source Apache 2.0 — auditable, modifiable, sans verrouillage.

✅ Multi-plateforme : Windows, Linux, macOS sur le même agent.

✅ Échelle massive : éprouvé sur 100 000+ endpoints chez certains opérateurs.

✅ VQL puissant : SQL-like, accessible aux analystes qui connaissent SQL ; extensible avec plugins custom.

✅ 300+ artefacts intégrés maintenus par la communauté et l'équipe Rapid7.

✅ Triage offline : collecteur standalone autonome (idéal pour les sites isolés).

✅ Notebooks : analyse interactive intégrée, documenter en même temps qu'on enquête.

✅ Intégration KAPE native : profite de tous les Targets KAPE depuis l'interface centralisée.

✅ Chasse Sigma / YARA à l'échelle : pas besoin d'un SIEM en plus.

✅ Quarantaine : isolation réseau d'un endpoint en un clic (Windows Firewall ou Sysmon).

✅ Communauté active : Discord, forum, vidéos de l'équipe (Mike Cohen, Kevin Stokes), formations Rapid7.

✅ Documentation excellente : <https://docs.velociraptor.app/> couvre tout.

✅ Pas de licence par endpoint : déploiement gratuit à volonté.

15 Faiblesses et limites

❌ Courbe d'apprentissage VQL : familier pour qui connaît SQL, hostile pour les autres. Compter 2-4 semaines de pratique avant d'être autonome.

❌ Pas d'EDR temps réel : Velociraptor est un outil de collecte sur demande, pas un EDR continu (pas de blocking de processus, pas d'alertes temps réel sans monitoring artifact actif).

❌ Pas d'isolation totale : la quarantaine via firewall peut être contournée par un attaquant privilégié.

❌ Stockage côté serveur peut exploser : collectes massives = datastore gros. Prévoir 100 Go à 1 To selon le volume d'endpoints.

❌ Pas d'interface mobile : la GUI web n'est pas optimisée mobile (pas grave pour les analystes en SOC, gênant en déplacement).

❌ Pas d'auto-update des agents par défaut : il faut redéployer manuellement (ou via outil de déploiement) pour mettre à jour.

❌ EDR commerciaux peuvent l'alerter : sur certains EDR, Velociraptor est considéré suspect (collecte massive). Whitelister.

❌ Pas de SIEM intégré : pour corréler les collectes avec d'autres sources (firewall, AD), il faut exporter vers Splunk / Elastic.

❌ Configuration TLS épinglée : si tu perds les certificats du serveur, tu dois redéployer tous les agents (à protéger).

❌ Performance des hunts longs : un hunt complexe peut surcharger un agent (CPU 100 % pendant 10 min sur un poste user).

16 Bonnes pratiques DFIR

🔹 Toujours déployer avec mTLS et certificat épinglé — ne jamais accepter une connexion d'un agent non autorisé.

🔹 Limiter les ressources des hunts : CpuLimit, MaxBytes, Timeout configurables. Sur un poste utilisateur, jamais > 30 % CPU.

🔹 Hash et conserver chaque collecte : Velociraptor le fait automatiquement, mais documenter dans le rapport DFIR.

🔹 Préparer des hunts standards par scénario (ransomware, exfiltration, lateral movement) avant l'incident — pas pendant.

🔹 Tester chaque artefact en VM avant de le lancer en production. Certains artefacts peuvent crasher des services (rare, mais possible).

🔹 Backup régulier du datastore : c'est ton coffre-fort de preuves. RPO < 24 h.

🔹 Audit des comptes admin Velociraptor — chaque action d'un analyste est tracée mais il faut surveiller.

🔹 Combiner avec une acquisition mémoire (Surge Collect, WinPmem, MAGNET RAM Capture) — Velociraptor a Windows.Memory.Acquisition mais limité.

🔹 Whitelister Velociraptor dans l'AV et l'EDR en amont du déploiement.

🔹 Documenter chaque hunt avec un identifiant de ticket et une description claire.

🔹 Apprendre VQL progressivement : commence par lire les artefacts intégrés, modifie-les, puis crée tes propres artefacts custom.

🔹 Ne pas remplacer l'EDR temps réel : Velociraptor est complémentaire d'un EDR commercial, pas un remplacement.

🔹 Tester la quarantaine sur une VM avant utilisation en production.

🔹 Programmer des hunts récurrents légers (par exemple Pslist + Persistence Run keys toutes les 6h) pour détection passive.

18 Conclusion

Velociraptor est devenu le standard open source du DFIR moderne. Il transforme un analyste isolé en force de frappe capable d'agir simultanément sur des milliers d'endpoints. Sa philosophie open source autohébergeable en fait l'alternative crédible aux EDR commerciaux pour les organisations qui ne veulent pas dépendre d'un fournisseur unique.

La courbe d'apprentissage VQL est l'unique obstacle réel. Une fois passé, l'outil débloque des capacités qui prenaient autrefois des jours d'effort manuel.

Recommandations finales :

  1. Monter un lab maison : VM Debian pour le serveur, 2-3 VM Windows comme endpoints.
  2. Faire passer les exercices de <https://github.com/Velocidex/velociraptor-docs>.
  3. Lire les artefacts intégrés un par un pour apprendre VQL en contexte.
  4. Construire ses propres artefacts custom pour les besoins spécifiques de son organisation.
  5. Intégrer dans le runbook IR : Velociraptor devient une étape standard des interventions, pas un outil exceptionnel.

Bonnes chasses ! 🦖
