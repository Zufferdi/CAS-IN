🧰 Eric Zimmerman Tools — Suite Windows

À la fin de ce tutoriel, tu sauras utiliser les 15 outils standalone d'Eric Zimmerman : PECmd (Prefetch), RECmd + Registry Explorer (registre), MFTECmd (MFT + USN Journal), EvtxECmd + maps (journaux EVTX), JLECmd/LECmd (Jumplists/LNK), SBECmd (Shellbags), RBCmd (Corbeille), SrumECmd, WxTCmd, et exploiter Timeline Explorer pour visualiser les CSV.
🎯 Niveau intermédiaire ⏱ ~60 min 🪟 Windows uniquement 🧰 15 outils standalone ⚡ CSV + GUI Timeline Explorer
ℹ️ À propos des EZ Tools
Eric Zimmerman Tools (souvent abrégés EZ Tools) est la suite forensique de référence pour Windows. 15 outils CLI + GUI, développés depuis 2012 par Eric Zimmerman (SANS instructor, ex-FBI). Intégrés dans KAPE comme parsers principaux, mais aussi utilisables en standalone pour analyse fine et debug. Sorties CSV exploitables via Timeline Explorer.

📦 ericzimmerman.github.io · Gratuit

01 Présentation générale

EZ Tools couvre tous les artefacts Windows classiques avec un principe : un outil = un artefact, sortie CSV exploitable. Ils sont rapides (10x à 100x plus rapides que les anciens outils Perl), bien documentés et maintenus activement.

Composition de la suite

CatégorieOutils principaux
ExécutionPECmd (Prefetch), AmcacheParser, AppCompatCacheParser
RegistreRECmd, Registry Explorer, RegistryExplorer.exe (GUI)
Système de fichiersMFTECmd (MFT, $LogFile, $J, $Boot)
LogsEvtxECmd (.evtx), EvtxEditor (GUI)
Activité utilisateurJLECmd (Jumplists), LECmd (.lnk), SBECmd (Shellbags)
Stockage récentRBCmd (Corbeille)
Usage systèmeSrumECmd (SRUM), WxTCmd (Windows 10 Timeline)
VisualisationTimeline Explorer (GUI)

Tous exportent en CSV (sauf GUI). Tous acceptent un dossier d'entrée (-d) et un dossier de sortie (--csv).

02 Pourquoi standalone et pas seulement via KAPE

KAPE chaîne EZ Tools via les Modules (!EZParser). Mais l'usage en standalone présente des avantages :

Cas d'usagePourquoi standalone
Analyse cibléeTu veux juste parser le Prefetch, pas faire tout EZParser (3 min vs 30 min)
Re-parser sur cas ancienTu reviens sur un cas, tu veux re-parser avec une version plus récente de l'outil
Comprendre l'artefactLire la documentation de l'outil = apprendre l'artefact (PECmd documente Prefetch)
Options avancéesCertains paramètres (--at, --bn, --debug) ne sont pas exposés par KAPE
Debug d'erreurSi KAPE plante sur un fichier, lancer l'outil seul donne une erreur exploitable
Image montée hors KAPETu as monté une image E01, tu veux parser directement sans recopier

Règle pédagogique : on apprend Windows DFIR en utilisant EZ Tools en CLI directement, puis on industrialise via KAPE.

04 Get-ZimmermanTools : récupérer la suite complète

Le script PowerShell Get-ZimmermanTools.ps1 télécharge tous les outils en une commande.

Procédure

  1. Télécharge le script : <https://download.mikestammer.com/Get-ZimmermanTools.zip>
  2. Décompresse dans C:\Tools\EZ\.
  3. Ouvre PowerShell admin dans ce dossier.
  4. Lance :
powershell
.\Get-ZimmermanTools.ps1 -Dest C:\Tools\EZ -NetVersion 6

Le script télécharge tous les outils EZ dans C:\Tools\EZ\net6\.

Mise à jour

Relance la même commande : seuls les outils mis à jour sont retéléchargés.

💡 Astuce
programmer en tâche planifiée hebdomadaire pour rester à jour. Eric Zimmerman publie des correctifs régulièrement.

05 PECmd — Prefetch (exécutions passées)

Le Prefetch Windows enregistre les premiers 1 Mo de chaque exécutable lancé, pour accélérer ses prochains démarrages. Pour le DFIR, c'est une preuve d'exécution : nom du programme, chemin, date de première exécution, fréquence, fichiers chargés.

Lancer PECmd

bat
PECmd.exe -d C:\Triage\C\Windows\Prefetch --csv C:\Output\Prefetch
  • -d : dossier contenant les fichiers .pf.
  • --csv : dossier de sortie.

Sortie

Un fichier CSV listant un par ligne chaque Prefetch :

shell
SourceFilename, SourceCreated, SourceModified, SourceAccessed, ExecutableName, Hash, Size, Version, RunCount, LastRun, PreviousRun0, ..., Volumes, FilesLoaded

Cas DFIR concrets

  • Repérer un exécutable malveillant dans \AppData\Local\Temp\ ou \Users\Public\.
  • Voir la première exécution (souvent l'arrivée du malware).
  • Voir la fréquence : malware ré-exécuté plusieurs fois = persistance probablement active.
  • Lister les fichiers chargés par le programme (DLL injection, fichiers de config).
💡 Astuce
trier le CSV par LastRun décroissant pour voir l'activité récente.

06 RECmd — Registre Windows

RECmd parse les ruches du registre (SAM, SYSTEM, SOFTWARE, SECURITY, NTUSER.DAT, UsrClass.dat) selon des fichiers de batch YAML.

Lancer RECmd avec un batch

bat
RECmd.exe -d C:\Triage\C\Windows\System32\config --bn BatchExamples\Kroll_Batch.reb --csv C:\Output\Registry
  • -d : dossier contenant les ruches.
  • --bn : batch file (collection de plugins YAML).
  • --csv : dossier de sortie.

Batches utiles

BatchUtilité
Kroll_Batch.rebPack complet : services, autoruns, programmes installés, USB devices, ShellBags, etc.
DFIRBatch.rebBatch dédié forensique standard
SANS_Triage.rebPack SANS pédagogique

Sortie

Un CSV par plugin. Exemples :

  • Services.csv : services Windows avec ImagePath, StartType
  • RunMRU.csv : commandes tapées via Win+R
  • USB_devices.csv : périphériques USB connectés
  • Persistence_RunKey.csv : entrées Run / RunOnce (persistance malware)
  • UserAssist.csv : programmes lancés depuis l'Explorer (preuve d'exécution utilisateur)

Cas DFIR concrets

  • Persistance malware : entrée dans HKLM\Software\Microsoft\Windows\CurrentVersion\Run pointant vers un binaire suspect.
  • Historique USB : tous les périphériques USB jamais connectés (preuve d'exfiltration).
  • Programmes désinstallés : entrées Uninstall encore présentes même après désinstallation.
  • MountedDevices : disques montés avec leur sériel.

07 MFTECmd — MFT, USN Journal, LogFile

La Master File Table (MFT) est l'index NTFS de tous les fichiers d'un volume — même supprimés (encore référencés tant que les entrées ne sont pas réécrites).

Parser le MFT

bat
MFTECmd.exe -f C:\Triage\$MFT --csv C:\Output\MFT
  • -f : fichier $MFT brut.
  • --csv : dossier de sortie.

Sortie : *_MFT_Output.csv avec une ligne par entrée MFT (fichier, dossier, supprimé ou actif).

Parser le USN Journal

bat
MFTECmd.exe -f C:\Triage\$Extend\$UsnJrnl_$J --csv C:\Output\MFT

Sortie : *_UsnJrnl_$J_Output.csv listant toutes les modifications récentes du système de fichiers (création, suppression, renommage, écriture).

Parser le $LogFile (journal NTFS)

bat
MFTECmd.exe -f C:\Triage\$LogFile --csv C:\Output\MFT

Le $LogFile contient les transactions NTFS récentes (très court historique, 64 Mo par défaut).

Cas DFIR concrets

  • Fichier supprimé : entrée MFT marquée 0 mais nom et taille encore lisibles.
  • Création récente : voir tous les fichiers créés dans les 24h.
  • Wiping détecté : entrées MFT effacées en masse = activité anti-forensique.
  • Timeline filesystem : croisé avec Plaso, le USN donne un grain fin.
💡 Astuce
le USN Journal couvre 1-7 jours typiquement. Si l'attaque est plus ancienne, le $MFT reste la source.

08 EvtxECmd — Journaux EVTX

EvtxECmd parse les fichiers .evtx (journaux d'événements Windows) avec une force : il applique des maps qui enrichissent les événements avec une sémantique DFIR.

Lancer

bat
EvtxECmd.exe -d C:\Triage\C\Windows\System32\winevt\Logs --csv C:\Output\EVTX --maps Maps
  • -d : dossier contenant les .evtx.
  • --csv : dossier de sortie.
  • --maps : dossier des maps YAML (téléchargé via Get-ZimmermanTools).

Maps EvtxECmd

Une map est un fichier YAML qui transforme un événement brut en ligne enrichie. Exemples :

  • Security 4624 (logon) : extrait le compte, le type de logon, l'IP source, le processus parent.
  • Sysmon 1 (process create) : ProcessName, CommandLine, ParentImage, User, IntegrityLevel.
  • PowerShell 4104 (script block) : contenu de la commande, sa hash, sa taille.

Sortie

Un CSV unique consolidé : *_EvtxECmd_Output.csv.

Cas DFIR concrets

  • Connexion RDP entrante (Security 4624, type 10) avec IP source malveillante.
  • Script PowerShell obfusqué (4104) lancé par Office (chaîne d'exécution phishing).
  • Process Sysmon (1) avec parent Outlook + ligne de commande PowerShell encodée.
  • Effacement du journal Security (1102) = activité d'attaquant cherchant à couvrir ses traces.
💡 Astuce
combiner EvtxECmd avec Hayabusa (chasse Sigma) pour transformer le CSV en alertes priorisées.

09 JLECmd et LECmd — Jumplists et raccourcis LNK

Les Jumplists (Windows 7+) enregistrent les fichiers récents par application. Les fichiers .lnk sont les raccourcis Windows qui contiennent des métadonnées étendues (volume sériel, NetBIOS du PC source, etc.).

JLECmd — Jumplists

bat
JLECmd.exe -d "C:\Triage\C\Users\suspect\AppData\Roaming\Microsoft\Windows\Recent\AutomaticDestinations" --csv C:\Output\Jumplists

Sortie : liste des fichiers récents par application (Office, Notepad, etc.) avec timestamps.

LECmd — Fichiers .lnk

bat
LECmd.exe -d "C:\Triage\C\Users\suspect\AppData\Roaming\Microsoft\Windows\Recent" --csv C:\Output\Lnk

Sortie : chaque .lnk détaillé. Extrait notamment :

  • Volume Serial Number : sérial du disque où le fichier ciblé a été créé.
  • MAC address : adresse MAC de la machine source si volume réseau.
  • NetBIOS name : nom NetBIOS de la machine source.

Cas DFIR concrets

  • Exfiltration USB : .lnk pointant vers E:\confidentiel.docx avec serial USB = preuve.
  • Accès partage réseau : .lnk pointant vers \\SERVER\Share\ avec MAC source.
  • Fichiers ouverts juste avant l'incident : timeline d'activité utilisateur.

10 SBECmd — Shellbags

Les Shellbags (registre UsrClass.dat) enregistrent chaque dossier visité dans l'Explorateur Windows, même si le dossier n'existe plus. C'est une mine d'or pour la navigation utilisateur.

Lancer

bat
SBECmd.exe -d C:\Triage\Users --csv C:\Output\Shellbags

-d : pointe vers Users\ ou un sous-dossier utilisateur.

Sortie

*_UserClass_Output.csv avec colonnes : utilisateur, chemin, type (Local / Network / USB), première et dernière interaction.

Cas DFIR concrets

  • Reconstitution du parcours : tous les dossiers ouverts dans l'Explorateur (même supprimés).
  • Accès USB / cloud : Shellbag E:\ ou OneDrive\ daté.
  • Anti-forensique : si Shellbags ont été effacés = activité de wiping.

11 RBCmd — Corbeille Windows

La Corbeille Windows ($Recycle.Bin par disque) garde les fichiers supprimés avec leurs métadonnées originales (chemin avant suppression, taille, date de suppression).

Lancer

bat
RBCmd.exe -d "C:\Triage\C\$Recycle.Bin" --csv C:\Output\Recycle

Sortie

Pour chaque fichier supprimé :

  • Nom original
  • Chemin original complet
  • Taille
  • Date de suppression
  • Utilisateur SID qui a supprimé

Cas DFIR concrets

  • Suppression de preuves : fichiers déplacés en Corbeille avant wiping.
  • Activité utilisateur : timeline de suppressions volontaires.
  • Récupération : on peut ensuite extraire le fichier physique depuis $Recycle.Bin\\$Rxxxxx.

12 AppCompatCacheParser et AmcacheParser

Deux artefacts critiques pour la preuve d'exécution au-delà du Prefetch.

AppCompatCacheParser (ShimCache)

bat
AppCompatCacheParser.exe -f C:\Triage\System --csv C:\Output\ShimCache

ShimCache (dans SYSTEM hive) enregistre tous les exécutables vus par Windows (pas seulement exécutés sur certaines versions). Liste limitée (~1024 entrées récentes), pas de date d'exécution mais date du fichier exécutable.

AmcacheParser

bat
AmcacheParser.exe -f C:\Triage\C\Windows\AppCompat\Programs\Amcache.hve --csv C:\Output\Amcache

Amcache.hve enregistre chaque programme installé ou lancé avec son hash SHA-1, son chemin, sa signature numérique. Riche en métadonnées.

Cas DFIR concrets

  • Hash de malware : Amcache contient le SHA-1, comparable à VirusTotal.
  • Programme désinstallé : entrée Amcache persiste après désinstallation.
  • Signature : Amcache indique si le binaire était signé par un éditeur connu.
  • ShimCache + Prefetch + Amcache : triple corroboration de l'exécution d'un programme.

13 SrumECmd et WxTCmd — SRUM et Timeline Windows 10

SrumECmd — System Resource Usage Monitor

Le SRUM (Win 8+) enregistre l'usage CPU, RAM, réseau, disque par application par heure.

bat
SrumECmd.exe -d "C:\Triage\C\Windows\System32\sru" --csv C:\Output\SRUM

Sortie : volumes de données envoyées et reçues par chaque application, par heure, sur 30-60 jours.

Cas DFIR :

  • Exfiltration : application avec gros volume sortant à 3h du matin = signal fort.
  • Beaconing C2 : connexions périodiques détectables dans SRUM.
  • Programme malveillant actif : usage CPU/RAM anormal sur période précise.

WxTCmd — Windows 10 Timeline

ActivitiesCache.db (Win 10+) contient la Timeline (vue Win+Tab) : applications utilisées, documents ouverts, sites visités, durée par activité.

bat
WxTCmd.exe -f "C:\Triage\C\Users\suspect\AppData\Local\ConnectedDevicesPlatform\<id>\ActivitiesCache.db" --csv C:\Output\Timeline

Cas DFIR :

  • Activité utilisateur précise : « à 14h32 le 12/01, suspect a ouvert WhatsApp Web puis Word avec doc.docx ».
  • Devices synchronisés : Timeline est partagée entre PC d'un même compte Microsoft.

14 Timeline Explorer — visualisation des CSV

Timeline Explorer est l'interface graphique pour visualiser les CSV produits par les outils ci-dessus. C'est l'équivalent Excel pour le DFIR, en plus rapide et avec des filtres adaptés.

Procédure

  1. Lance TimelineExplorer.exe.
  2. File → Open → ton CSV (PECmd, EvtxECmd, MFTECmd, etc.).
  3. Le CSV s'ouvre en tableau filtrable.

Fonctionnalités clés

  • Filtres par colonne : clic sur l'en-tête, choisir valeur.
  • Recherche full-text : Ctrl+F sur tout le tableau.
  • Tri multi-colonnes : Shift+clic sur les en-têtes.
  • Tagging : marquer des lignes (couleur).
  • Bookmarking : sauvegarder des lignes pour le rapport.
  • Export : sélection → CSV / Excel.

Cas DFIR concret

Ouvrir EvtxECmd output → filtrer EventID == 4624 → filtrer LogonType == 10 → exporter les RDP entrants → corréler avec firewall.

💡 Astuce
Timeline Explorer est 10x plus rapide qu'Excel sur des fichiers > 100 000 lignes.

15 Registry Explorer — exploration interactive du registre

Registry Explorer est le pendant graphique de RECmd : exploration interactive des ruches du registre.

Procédure

  1. Lance RegistryExplorer.exe.
  2. File → Load hive → sélectionner SOFTWARE, SYSTEM, NTUSER.DAT, etc.
  3. L'arborescence du registre s'affiche, navigable comme regedit mais en lecture seule et avec des plugins enrichis.

Plugins Registry Explorer

Comme RECmd, Registry Explorer charge des plugins YAML qui transforment des clés brutes en données lisibles :

  • UserAssist : décode les ROT13 de la clé UserAssist
  • TypedPaths : adresses tapées dans l'Explorer
  • MountedDevices : disques montés
  • NetworkList : tous les Wi-Fi connus
  • InstalledPrograms : programmes installés

Cas d'usage

  • Exploration interactive quand tu n'as pas encore le batch RECmd adapté.
  • Vérification rapide d'une clé spécifique.
  • Compréhension de la structure du registre pour écrire un nouveau plugin.

16 Forces et faiblesses

Forces

✅ Suite la plus complète pour le DFIR Windows. Aucun autre projet open source ne couvre autant d'artefacts.

✅ Performance : 10x à 100x plus rapide que les anciens outils Perl (RegRipper).

✅ Sorties CSV standardisées : compatibles avec Timeline Explorer, Excel, Splunk, Elastic.

✅ Documentation excellente : chaque outil a son manuel, blog Eric Zimmerman très actif.

✅ Communauté : Discord, plugins contributés, formations SANS (FOR500, FOR508, FOR509).

✅ Maintenance active : releases fréquentes, suivi des évolutions Windows.

✅ Intégration KAPE : tous les outils sont des Modules KAPE.

✅ Gratuit sans restriction d'usage forensique légitime.

✅ Multi-format de sortie : CSV pour automatisation, GUI pour exploration.

✅ Maps EvtxECmd : enrichissement sémantique des événements Windows (unique en son genre).

Faiblesses

❌ Windows uniquement : tous les outils sont .NET, pas de version Linux/macOS native (mais utilisables sous Wine/Mono).

❌ Pas open source : code propriétaire Eric Zimmerman, audit limité.

❌ Apprentissage progressif : 15 outils à maîtriser, prévoir 1-2 semaines de pratique.

❌ Pas d'orchestrateur natif : si tu veux chaîner les outils, c'est via KAPE ou scripts batch maison.

❌ Pas de timeline unifiée : chaque outil produit un CSV séparé. Pour une super-timeline, il faut Plaso en complément.

❌ Sensibilité à la version Windows source : un Amcache de Win10 1809 ne se parse pas exactement comme Win11 23H2 (mais Eric Zimmerman suit).

❌ EULA gratuite mais propriétaire : pas de fork possible si le développement s'arrêtait.

17 Bonnes pratiques DFIR

🔹 Mettre à jour régulièrement via Get-ZimmermanTools.ps1 (tâche planifiée hebdomadaire).

🔹 Garder les versions utilisées en archive par cas (cohérence pour reproductibilité juridique).

🔹 Toujours travailler sur copie des artefacts (.pf, .evtx, ruches) jamais sur l'original.

🔹 Versionner les batches RECmd custom pour reproductibilité.

🔹 Combiner EZ Tools + KAPE + Plaso :

  • KAPE pour la collecte initiale et le parsing standard
  • EZ Tools standalone pour creuser un artefact spécifique
  • Plaso pour la super-timeline unifiée

🔹 Utiliser Timeline Explorer systématiquement pour les CSV — Excel sature au-delà de 100k lignes.

🔹 Croiser au moins 2 sources pour confirmer une exécution : PECmd + Amcache, ou PECmd + ShimCache.

🔹 Documenter les commandes exactes utilisées dans le rapport pour reproductibilité.

🔹 Tester sur images publiques (Digital Corpora) avant les cas réels pour apprendre.

🔹 Apprendre la sémantique des artefacts : un outil n'extrait pas un sens, l'analyste l'extrait. Lire le blog d'Eric Zimmerman, suivre les présentations DFIR Summit.

🔹 Faire des cheat sheets par artefact avec les chemins typiques et les commandes essentielles.

🔹 Apprendre Hayabusa et Chainsaw en complément d'EvtxECmd pour la chasse Sigma.

19 Conclusion

Eric Zimmerman Tools est la suite forensique de référence pour Windows. Maîtriser ces outils signifie maîtriser les artefacts Windows fondamentaux : Prefetch, MFT, Registry, EVTX, Shellbags, Jumplists, ShimCache, Amcache, SRUM, Timeline. C'est la culture générale obligatoire de tout analyste DFIR Windows.

Le toolkit s'intègre parfaitement dans un workflow moderne :

  1. Acquisition avec FTK Imager (RAM + disque)
  2. Triage Windows avec KAPE (qui utilise EZ Tools en interne)
  3. Analyse approfondie avec EZ Tools standalone sur les CSV produits
  4. Super-timeline avec Plaso
  5. Mémoire avec Volatility 3
  6. Visualisation avec Timeline Explorer

Recommandations finales :

  1. Get-ZimmermanTools.ps1 : installer tout en une commande, mettre à jour régulièrement.
  2. Pratiquer un outil à la fois sur des images publiques (Digital Corpora).
  3. Lire le blog d'Eric Zimmerman pour comprendre les artefacts en profondeur.
  4. S'inscrire au DFIR Summit annuel : Eric présente régulièrement les évolutions.

Bons parsings ! 🧰
