🔓 Hashcat — Cassage de hash

À la fin de ce tutoriel, tu sauras installer Hashcat avec accélération GPU, identifier le bon mode -m pour un hash, lancer une attaque par dictionnaire + règles (best64, OneRule), maîtriser les attaques par masque, casser des hashs NTLM Windows, des fichiers protégés (KeePass, Office, ZIP, BitLocker, VeraCrypt), et gérer des sessions longues avec reprise.
🎯 Niveau expert ⏱ ~65 min 🪟 Windows 🐧 Linux 🎮 GPU recommandé ⚖️ Cadre légal strict
⚠️ Hashcat est un outil dual-use
Casser un hash est une opération réglementée. En Suisse : nécessite un mandat MP (art. 197 CPP) ou un cadre d'audit autorisé. Sanctions sérieuses en cas d'usage abusif (art. 143bis CP, jusqu'à 3 ans). Ce tutoriel suppose un cadre légal explicite — documenter l'autorité, le mandat et la finalité avant chaque session.

01 Présentation générale

Hashcat exploite la puissance des GPU modernes pour tester des milliards de candidats par seconde. Là où un CPU teste 50 millions de hash MD5/seconde, une RTX 4090 dépasse 150 milliards (×3000).

Capacités principales :

  • 300+ algorithmes supportés : MD5, SHA-1, SHA-256, SHA-512, NTLM, NetNTLMv2, Kerberos AS-REP, bcrypt, scrypt, Argon2, WPA-PBKDF2, BitLocker, VeraCrypt, LUKS, KeePass, 1Password, fichiers Office, PDF, archives, etc.
  • 5 modes d'attaque : dictionnaire, combinaison, masque, hybrides.
  • Règles : transformations massives appliquées à un dictionnaire.
  • Reprises : sauvegarde automatique de session.
  • Distribution : peut tourner sur plusieurs GPU et machines simultanément.

02 Cadre légal et éthique

Casser un hash est une opération réglementée. En Suisse :

  • Avec mandat MP (art. 197 CPP) : autorisé pour les besoins de l'enquête.
  • Sans mandat : uniquement sur des hashs dont tu es légitimement propriétaire (audit de ton propre AD, récupération de ton propre mot de passe).
  • Jamais : casser le hash d'un tiers sans autorisation, même par curiosité.

En entreprise :

  • Audit de mot de passe : autorisé si prévu dans la politique signée par les employés et coordonné avec le DPO et le service juridique.
  • Récupération d'urgence : autorisé si propriétaire des données (poste d'entreprise, conteneur appartenant à la société).

Sanctions :

  • Suisse : art. 143bis CP (accès illicite à un système informatique) — jusqu'à 3 ans.
  • France : art. 323-1 CP, RGPD.
  • États-Unis : Computer Fraud and Abuse Act (CFAA).
🚨 Critique
avant chaque session Hashcat, documenter dans le rapport : autorité demandeuse, mandat, hash source, finalité, durée. Hashcat n'est pas un outil de curiosité.

04 Cas d'usage DFIR typiques

  • Cassage de SAM Windows : dump des hashs NTLM d'un poste compromis, identifier les comptes faibles.
  • Cracking BitLocker : récupérer une clé sur un disque chiffré (parfois plus rapide que TPM bypass).
  • Conteneur VeraCrypt / LUKS : si on suspecte un dictionnaire personnalisé du suspect.
  • Fichier KeePass : récupérer le master password pour ouvrir la base.
  • Office protégé : Word/Excel/PPT avec mot de passe.
  • Archive ZIP/RAR/7z : preuves potentiellement chiffrées par le suspect.
  • Audit Active Directory : DCSync, identifier les comptes avec mots de passe faibles.
  • WPA / WPA2 : analyse réseau Wi-Fi compromis (avec mandat).
  • Hash leaké : confirmer si un hash dans une fuite correspond à un mot de passe utilisateur connu.

06 Installation sous Windows

Étape 1 : drivers GPU

Avant Hashcat, installer les drivers GPU à jour :

  • NVIDIA : <https://www.nvidia.com/Download/index.aspx>
  • AMD : <https://www.amd.com/en/support>
  • Intel : <https://www.intel.com/content/www/us/en/download-center/home.html>

Redémarrer après installation.

Étape 2 : télécharger Hashcat

  1. Va sur <https://hashcat.net/hashcat/>
  2. Télécharge hashcat-x.y.z.7z (la dernière version).
  3. Décompresse dans C:\Tools\hashcat\.

Étape 3 : vérifier

Ouvre PowerShell ou cmd dans C:\Tools\hashcat\ :

powershell
.\hashcat.exe --version
.\hashcat.exe -I

--version affiche la version. -I (i majuscule) liste les devices détectés (GPU + CPU).

⚠️ Attention
️ Si l'antivirus alerte : Hashcat est légitime mais souvent flaggé. Autoriser dans Windows Defender (l'usage DFIR est légal). Documenter cette autorisation.

10 Attaque par dictionnaire (mode -a 0)

L'attaque la plus simple et la plus efficace en pratique : tester chaque ligne d'un dictionnaire contre le hash.

Syntaxe de base

bash
hashcat -a 0 -m 1000 hash.txt rockyou.txt
  • -a 0 : mode attaque par dictionnaire.
  • -m 1000 : type de hash (NTLM ici).
  • hash.txt : fichier contenant le ou les hashs à casser (un par ligne).
  • rockyou.txt : le dictionnaire.

Dictionnaires de référence

DictionnaireTailleSource
rockyou.txt14 M lignesLeak RockYou 2009, standard pédagogique
rockyou2021.txt8.4 G lignesMéga-leak 2021, à manier avec précaution
HaveIBeenPwned850 M de hashs SHA-1HIBP, format hash:count
weakpass_39 G lignesweakpass.com, très qualifié
CrackStation Human-Only65 M lignescrackstation.net
xato-net-10-million-passwords10 M lignesxato.net

Stocker les hashs trouvés

Hashcat écrit dans hashcat.potfile (dans son dossier) les couples hash:password déjà cassés. Cette base est réutilisée automatiquement entre sessions.

Pour voir les résultats :

bash
hashcat -m 1000 hash.txt --show

11 Attaque par règles (rule-based)

Les règles sont la fonction la plus puissante de Hashcat. Une règle est une transformation (capitalisation, ajout de chiffres, leetspeak) appliquée à chaque mot du dictionnaire.

Syntaxe

bash
hashcat -a 0 -m 1000 hash.txt rockyou.txt -r rules/best64.rule

-r rules/best64.rule : applique le pack de règles best64.rule (64 règles classiques).

Règles fournies avec Hashcat

FichierNombre de règlesUsage

leetspeak.rule~10Conversions a→4, e→3
toggles1.rule à toggles5.ruleVariants de casseTest toutes capitalisations

Exemples de transformations

Mot de base : password

Combinaisons typiques

bash
# Standard DFIR : rockyou + best64
hashcat -a 0 -m 1000 hash.txt rockyou.txt -r rules/best64.rule

# Cible utilisateur professionnel : OneRule
hashcat -a 0 -m 1000 hash.txt company_wordlist.txt -r rules/OneRuleToRuleThemAll.rule

OneRuleToRuleThemAll.rule (~52k règles) est le pack de référence sur GitHub : <https://github.com/NotSoSecure/password_cracking_rules>

💡 Astuce
commencer par best64.rule (rapide, 90% des résultats). Si rien, passer à OneRuleToRuleThemAll.rule (lent, exhaustif).

12 Attaque par combinaison (mode -a 1)

Combine deux dictionnaires : pour chaque mot de A, concatène chaque mot de B.

bash
hashcat -a 1 -m 1000 hash.txt names.txt dates.txt

Teste alice2020, alice2021, ..., bob2020, ... Très utile si l'organisation a un schéma de password prévisible (prénom + année).

13 Attaque par masque (mode -a 3)

L'attaque par masque énumère méthodiquement un espace de candidats défini.

Syntaxe

bash
hashcat -a 3 -m 1000 hash.txt ?u?l?l?l?d?d?d?d
  • ?l : lettre minuscule (a-z)
  • ?u : lettre majuscule (A-Z)
  • ?d : chiffre (0-9)
  • ?s : symbole (espace inclus)
  • ?a : tout caractère imprimable (l+u+d+s)
  • ?b : tout octet 0x00-0xff

Le masque ?u?l?l?l?d?d?d?d teste : Abcd1234, Xyzw9999, etc.

Charsets personnalisés

bash
hashcat -a 3 -m 1000 hash.txt -1 ?d?u ?1?1?1?1?1?1

-1 ?d?u définit le charset 1 comme chiffres+majuscules. Le masque ?1?1?1?1?1?1 teste 6 caractères dans ce charset.

Cas d'usage

  • Mots de passe Wi-Fi prédictibles : ?l?l?l?l?l?l?l?l (8 lettres minuscules)
  • PIN : ?d?d?d?d?d?d (6 chiffres)
  • Patterns institutionnels : ?u?l?l?l?l?d?d?d?d
💡 Astuce
un masque de 10 caractères en ?a = 95^10 = 6 × 10^19 combinaisons. Hors d'atteinte. Ne jamais brute-force aveugle au-delà de 8-9 caractères, sauf algorithme rapide (MD5, NTLM).

14 Attaque hybride (modes -a 6 et -a 7)

Hybrides entre dictionnaire et masque.

-a 6 : dictionnaire + masque (suffix)

bash
hashcat -a 6 -m 1000 hash.txt rockyou.txt ?d?d?d?d

Pour chaque mot du dictionnaire, ajoute 4 chiffres en suffix. Teste : password0000, password0001, ...

-a 7 : masque + dictionnaire (prefix)

bash
hashcat -a 7 -m 1000 hash.txt ?d?d?d?d rockyou.txt

Préfixe 4 chiffres devant chaque mot. Teste : 0000password, 0001password, ...

💡 Astuce
un employé qui change son mot de passe tous les 90 jours en ajoutant le mois → dictionnary.txt + ?d?d (mois numérique) en suffixe attrape souvent le pattern.

15 Casser un hash NTLM Windows

Le scénario classique : tu as un dump SAM ou des hashs AD.

Extraire les hashs depuis SAM (poste compromis)

Si tu as les fichiers SAM et SYSTEM (acquis avec KAPE ou FTK Imager) :

bash
# Avec impacket-secretsdump (Linux)
impacket-secretsdump LOCAL -sam SAM -system SYSTEM

Sortie typique :

shell
Administrator:500:aad3b435b51404eeaad3b435b51404ee:31d6cfe0d16ae931b73c59d7e0c089c0:::
JohnDoe:1001:aad3b435b51404eeaad3b435b51404ee:8846f7eaee8fb117ad06bdd830b7586c:::

Format : user:RID:LM:NT::: — c'est la 4e colonne (NT) qui nous intéresse.

Préparer pour Hashcat

Crée hashes.txt avec uniquement les hashs NT :

shell
31d6cfe0d16ae931b73c59d7e0c089c0
8846f7eaee8fb117ad06bdd830b7586c

Cracking

bash
hashcat -a 0 -m 1000 hashes.txt rockyou.txt -r rules/best64.rule

Le hash 31d6cfe0d16ae931b73c59d7e0c089c0 est le NTLM du mot de passe vide (à connaître par cœur, il revient souvent).

8846f7eaee8fb117ad06bdd830b7586c est le NTLM de password.

Résultats

bash
hashcat -m 1000 hashes.txt --show

Affiche les paires hash:password trouvées.

16 Casser un fichier protégé (ZIP, Office, KeePass)

Hashcat ne casse pas directement un fichier — il casse son hash extrait par un outil dédié.

KeePass

bash
# Extraction avec keepass2john (de John the Ripper)
keepass2john MyDatabase.kdbx > kp_hash.txt

# Cracking
hashcat -a 0 -m 13400 kp_hash.txt rockyou.txt -r rules/best64.rule

Office (Word/Excel/PPT)

bash
office2john document.docx > office_hash.txt
# Identifier la version dans le hash (Office 2007 → mode 9400, etc.)
hashcat -a 0 -m 9600 office_hash.txt rockyou.txt

ZIP / RAR / 7z

bash
zip2john archive.zip > zip_hash.txt
hashcat -a 0 -m 17220 zip_hash.txt rockyou.txt

PDF

bash
pdf2john.py protected.pdf > pdf_hash.txt
hashcat -a 0 -m 10500 pdf_hash.txt rockyou.txt

BitLocker

bash
# Avec bitlocker2hashcat (séparé)
bitlocker2hashcat -i disk_image.raw -o bl_hash.txt
hashcat -a 0 -m 22100 bl_hash.txt rockyou.txt

VeraCrypt

Hashcat peut attaquer directement le conteneur :

bash
hashcat -a 0 -m 13722 container.tc rockyou.txt

Le mode dépend de l'algorithme (13721 pour AES, 13722 pour Serpent, etc.).

💡 Astuce
*2john scripts de John the Ripper ont une version Hashcat compatible. La documentation hashcat.net pour chaque mode donne la commande d'extraction exacte.

17 Gérer les sessions longues

Un cracking sérieux dure des heures, parfois des jours. Hashcat sauvegarde automatiquement.

Lancer une session nommée

bash
hashcat --session enquete2026 -a 0 -m 1000 hashes.txt rockyou.txt -r rules/best64.rule

Reprendre après interruption

bash
hashcat --session enquete2026 --restore

Hashcat reprend exactement où il s'était arrêté (Ctrl+C, panne, redémarrage).

Suivre le statut

Pendant le cracking, appuie sur s pour voir le status : vitesse, ETA, % progression.

Appuie sur b pour bypass (passer au suivant si plusieurs attaques en queue).

Appuie sur c pour faire un checkpoint propre puis q pour quitter.

Distribution sur plusieurs GPU

Hashcat utilise tous les GPU détectés automatiquement. Pour forcer un sous-ensemble :

bash
hashcat -d 1,2 -a 0 -m 1000 hashes.txt rockyou.txt

-d 1,2 : utiliser uniquement devices 1 et 2.

Distribution sur plusieurs machines

Hashcat supporte le mode brain server (cracking distribué) :

bash
# Sur le serveur
hashcat --brain-server

# Sur les clients
hashcat --brain-client --brain-host=server.ip

18 Forces et faiblesses

Forces

✅ Le plus rapide au monde sur GPU — pas de débat.

✅ 300+ algorithmes supportés — couvre tous les besoins DFIR courants.

✅ Règles très puissantes — transformations massives, leetspeak, capitalisation, suffixes.

✅ Multi-plateforme : Windows, Linux, macOS.

✅ Multi-GPU et multi-machine : scalabilité horizontale.

✅ Reprise automatique : sessions persistantes.

✅ Potfile : base de mots de passe déjà cassés réutilisable.

✅ Documentation excellente : wiki, exemples, FAQ.

✅ Communauté très active : Discord, forum, GitHub issues.

✅ Open source MIT : auditable, sans dépendance fournisseur.

Faiblesses

❌ Courbe d'apprentissage : 5 modes d'attaque, 300+ types, syntaxe dense — prévoir 1-2 semaines.

❌ Pas de GUI officielle : tout en CLI (existences de wrappers GUI tiers mais non officiels).

❌ Antivirus alertes : faux positifs fréquents (outil flagué comme hacktool par défaut sur Windows Defender).

❌ Dépendance drivers GPU : configuration matérielle complexe, mises à jour drivers à gérer.

❌ Pas d'extraction de hash : il faut des outils externes (*2john, impacket, bitlocker2hashcat).

❌ Pas d'attaques en ligne : Hashcat est purement offline (par design, c'est une force aussi).

❌ Pas d'optimisation Apple Silicon : sur Mac M1/M2/M3, performances réduites (pas de Metal optimisé).

❌ Aspect éthique : outil dual-use, à manipuler avec discernement.

❌ Énergie : sessions longues sur multi-GPU = facture électrique sérieuse.

19 Bonnes pratiques DFIR

🔹 Toujours documenter : autorité, mandat, hash source, finalité, durée — Hashcat se trace.

🔹 Travailler sur copie des hashs originaux. Conserver l'original avec hash de fichier.

🔹 Préférer dictionnaire + règles au brute force aveugle. Plus rapide, plus éthique (cible des humains, pas force brute).

🔹 Commencer par les classiques : rockyou + best64, puis seulement si rien → règles plus larges.

🔹 Cibler le contexte : dictionnaire personnalisé du suspect (CV LinkedIn, intérêts, ville, dates) souvent plus efficace que rockyou.

🔹 Vérifier le mode -m avec --example-hashes avant lancement (un mauvais mode → cracking impossible).

🔹 Mesurer le coût avant : un masque à 95^9 = 630 ans sur RTX 4090. Calculer avec hashcat -b -m XX pour estimer.

🔹 Pas de cracking sur poste analyste : station dédiée, isolée du réseau si possible, climatisation pour les longues sessions.

🔹 Conserver le potfile entre cas : effet cumulatif (chaque hash cassé enrichit la base).

🔹 Hash trouvés = données sensibles : stocker chiffré, ne jamais committer dans Git, ne pas partager hors équipe.

🔹 Croiser avec HaveIBeenPwned : si le hash est dans une fuite publique connue, c'est instantané (avant Hashcat).

🔹 Apprendre les règles : 80 % du gain perf vient des règles, pas du dictionnaire.

🔹 Surveiller la température GPU : nvidia-smi -l 5 pour monitoring. Throttling thermique = perte de perf.

🔹 Mettre à jour régulièrement : Hashcat ajoute des modes (par exemple Argon2id récemment).

🔹 Ne JAMAIS lancer Hashcat sur des hashs non autorisés — sanctions pénales sérieuses.

21 Conclusion

Hashcat est l'outil de référence pour casser un hash en DFIR. Sa puissance brute (GPU), sa flexibilité (5 modes d'attaque, 300+ types, règles) et sa robustesse (sessions, potfile) en font l'incontournable de toute investigation impliquant un mot de passe à récupérer.

Sa manipulation exige rigueur éthique et juridique : un mauvais usage = sanctions pénales sérieuses. C'est un outil dual-use qui n'a sa place qu'en cadre légal explicite.

Recommandations finales :

  1. Configurer ta station GPU une fois pour toutes (drivers, OS, ventilation).
  2. Construire ta wordlist : rockyou + weakpass_3 + tes dictionnaires custom.
  3. Maîtriser les règles : OneRuleToRuleThemAll pour les cas costauds, best64 pour le quotidien.
  4. Tenir un journal de cracking : modes utilisés, durées, succès/échecs — pour reproductibilité juridique.
  5. Documenter chaque session : mandat associé, hashs traités, résultats, hashs détruits ensuite.

Bons cassages dans le cadre légal ! 🔓
