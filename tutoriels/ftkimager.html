💾 FTK Imager — Acquisition forensique

À la fin de ce tutoriel, tu sauras acquérir une image disque write-blocked au format E01 avec hash MD5+SHA-1 vérifiés, capturer la RAM d'un poste en cours de fonctionnement, monter une image E01 en lecture seule pour exploration, et documenter une chaîne de preuve conforme à l'art. 192 CPP.
🎯 Niveau débutant ⏱ ~40 min 🪟 Windows uniquement 💾 Acquisition E01 🔒 Write-blocker conseillé
ℹ️ À propos de FTK Imager
FTK Imager est l'outil gratuit de référence pour l'acquisition forensique : production d'images disque write-blocked, capture mémoire RAM, vérification d'intégrité par hash, montage lecture seule. Développé par AccessData (devenu Exterro) depuis 2003. Standard de facto en perquisition.

📦 exterro.com/ftk-imager · Gratuit (propriétaire)

01 Présentation générale

FTK Imager est l'outil universel d'acquisition : il fait l'image d'un support, vérifie son intégrité par hash, et permet de naviguer dans l'image obtenue sans installer un logiciel d'analyse complet. C'est ce qu'utilise un enquêteur de terrain pour saisir un disque sans contaminer la preuve.

Sa philosophie : produire une copie bit-à-bit fidèle, signée par hash, qu'on pourra ensuite analyser à froid avec Autopsy, IPED, X-Ways, EnCase ou tout autre outil compatible avec les formats E01, AD1 ou DD.

Capacités principales :

  • Acquisition de disques physiques (HDD, SSD, NVMe, clés USB, cartes SD)
  • Acquisition de partitions logiques (NTFS, FAT, ext, HFS+, APFS en lecture)
  • Acquisition de dossiers spécifiques (image partielle ciblée)
  • Acquisition de la mémoire vive Windows (RAM)
  • Vérification d'intégrité par MD5, SHA-1, SHA-256
  • Montage d'images en lecture seule pour exploration
  • Export de fichiers individuels depuis une image existante

02 Pourquoi acquérir avant d'analyser

Toute analyse forensique repose sur un principe : ne jamais toucher l'original. Cela vient du droit (chaîne de preuve, art. 192 CPP) et de la science (un disque modifié = preuve invalide).

L'acquisition produit :

  1. Une image bit-à-bit : copie exacte de chaque secteur, y compris l'espace non alloué.
  2. Un hash de l'image (MD5 et SHA-256) prouvant qu'aucun bit n'a changé.
  3. Un rapport d'acquisition documentant date, outil, opérateur, support source.
⚠️ Attention
️ Sans acquisition propre, toute analyse ultérieure est juridiquement attaquable. Un avocat peut faire écarter une preuve si l'acquisition n'est pas documentée ou si le hash n'est pas vérifié.

05 Installation sous Windows

Méthode standard

  1. Lance AccessData FTK Imager.exe (l'installeur).
  2. Accepte l'EULA.
  3. Choisis le dossier d'installation (par défaut C:\Program Files\AccessData\FTK Imager).
  4. Termine.
  5. Lance FTK Imager.exe depuis le menu Démarrer.

Vérification

L'interface s'ouvre. Tu vois :

  • Barre de menu : File, View, Mode, Help.
  • Volet Evidence Tree (gauche) : sources actuellement chargées.
  • Volet File List (haut) : fichiers du dossier sélectionné.
  • Volet Properties / Hex / Custom Content : détails du fichier sélectionné.
🚨 Critique
exécute toujours FTK Imager en administrateur sur Windows, sinon l'accès aux disques physiques échoue.

06 Version portable et FTK Imager Lite

Une version portable de FTK Imager existe : un dossier zippable à copier sur clé USB, sans installation.

Cas d'usage

  • Intervention sur un système qu'on ne veut pas modifier (installation = modification).
  • Triage rapide sur poste suspect avant décision d'acquisition complète.
  • Acquisition sur poste sans connexion internet.

Procédure

  1. Sur ton poste, installe FTK Imager normalement.
  2. Copie le dossier C:\Program Files\AccessData\FTK Imager vers une clé USB.
  3. Sur le poste cible, lance FTK Imager.exe directement depuis la clé.
⚠️ Attention
️ Attention : même portable, FTK Imager écrit dans le registre Windows et utilise le filesystem. Une vraie acquisition write-safe se fait avec un write-blocker matériel entre le disque source et l'analyste.

FTK Imager Lite

Une variante Lite (très allégée) existait historiquement mais Exterro l'a abandonnée. Privilégier la version standard.

07 Acquérir un disque physique

C'est le cas le plus courant : tu as un disque saisi, branché sur write-blocker, tu veux faire une image complète.

Étape 1 : démarrer l'acquisition

File → Create Disk Image…

Étape 2 : choisir la source

Sélectionne Physical Drive (pas Logical, qui ne capture que la partition active).

Une liste apparaît : \\.\PHYSICALDRIVE0, \\.\PHYSICALDRIVE1, etc.

Repère bien le disque cible par sa taille et son numéro de série :

  • \\.\PHYSICALDRIVE0 = disque système (à ne PAS imager)
  • \\.\PHYSICALDRIVE1 = disque saisi via write-blocker (à imager)

Clique Finish.

Étape 3 : ajouter la destination

Clique Add…. Choisis le format : E01 (recommandé).

Remplis les métadonnées :

  • Case Number : référence de réquisition (ex. MP-VD-2026-001).
  • Evidence Number : numéro de la pièce (ex. 01-A-DD500).
  • Unique Description : description (ex. Samsung 870 EVO 500GB - Suspect PC).
  • Examiner : ton nom et fonction.
  • Notes : observations (ex. « Disque externe trouvé dans tiroir bureau »).

Clique Next.

Étape 4 : destination de fichier

  • Image Destination Folder : disque externe analyste (jamais le disque source !).
  • Image Filename : MP-VD-2026-001_01-A-DD500 (sans extension).
  • Image Fragment Size (MB) : 2000 (2 Go par segment, standard).
  • Compression : 6 (équilibre vitesse/taille).
  • Use AD Encryption : décoché sauf cas spécifique.

Clique Finish.

Étape 5 : lancer

Sur la fenêtre récapitulative :

  • Coche Verify images after they are created (calcul automatique du hash).
  • Coche Precalculate Progress Statistics.
  • Coche Create directory listings of all files in the image (génère un fichier .csv des chemins).

Clique Start.

L'acquisition démarre. Pour un disque de 500 Go :

  • Sur USB 3.0 + SSD source + SSD destination : 45-90 minutes
  • Sur USB 2.0 + HDD source : 5-8 heures
💡 Astuce
pendant l'acquisition, NE PAS débrancher ni utiliser ton poste analyste. Toute interruption casse l'image (à recommencer du début).

Résultat

Tu obtiens dans ton dossier de destination :

shell
MP-VD-2026-001_01-A-DD500.E01
MP-VD-2026-001_01-A-DD500.E02
...
MP-VD-2026-001_01-A-DD500.E07
MP-VD-2026-001_01-A-DD500.E01.txt   ← rapport d'acquisition

Le .txt contient toutes les métadonnées et les hashs MD5 + SHA-1 calculés sur source et image. Ces hashs doivent être identiques : si oui, l'image est intègre.

08 Acquérir une partition logique

Cas plus rare mais utile : tu veux acquérir uniquement la partition D: d'un disque, pas tout le disque.

Procédure

File → Create Disk Image… → Logical Drive

Sélectionne la lettre (D:, F:, etc.) et procède comme pour un disque physique.

Limitations

  • L'espace non alloué du disque (entre partitions, après la partition) n'est pas capturé.
  • Les partitions cachées (recovery, EFI) ne sont pas dans l'image.
  • Si l'attaquant a effacé des fichiers présents dans l'espace non alloué, tu les perds.
🚨 Critique
préférer toujours l'image physique complète. L'image logique est utile uniquement quand tu cibles explicitement une partition (ex. partition chiffrée déjà déchiffrée, partage réseau).

09 Acquérir une image dans une image (sous-imagerie)

Tu reçois une image E01 contenant un VHD chiffré BitLocker. Tu as la clé, tu veux acquérir le contenu déchiffré du VHD pour analyse.

Procédure

  1. File → Add Evidence Item → Image File : pointe vers le .E01.
  2. L'image apparaît dans l'Evidence Tree.
  3. Déchiffre le VHD via outil tiers (manage-bde, Passware, etc.).
  4. Une fois monté, File → Create Disk Image sur le VHD déchiffré.
  5. Tu obtiens une nouvelle image E01 du contenu déchiffré.

Cette technique permet de traiter en cascade des conteneurs chiffrés sans casser la preuve d'origine.

10 Capturer la mémoire vive (RAM)

Capture de RAM = première étape en intervention sur un poste en cours de fonctionnement. Si tu coupes l'alimentation, la RAM s'efface — perte de :

  • Processus actifs
  • Connexions réseau
  • Clés de chiffrement déchiffrées
  • Mots de passe en clair
  • Commandes PowerShell en cours
  • Malware fileless

Procédure

  1. File → Capture Memory…
  2. Destination path : disque externe (USB 3.0 minimum).
  3. Filename : RAM_HOSTNAME_AAAAMMJJ.mem.
  4. Coche Include pagefile si tu veux aussi pagefile.sys (très volumineux mais utile pour reconstruction d'artefacts).
  5. Coche Create AD1 file si tu veux un format AccessData (sinon .mem brut).
  6. Clique Capture Memory.

Durée typique : 1-3 minutes pour 16 Go de RAM.

Résultat exploitable par Volatility 3

Le fichier .mem est directement analysable par Volatility 3 :

bash
vol -f RAM_HOSTNAME_20260115.mem windows.pslist
vol -f RAM_HOSTNAME_20260115.mem windows.netscan
vol -f RAM_HOSTNAME_20260115.mem windows.malfind
💡 Astuce
(1) RAM avec FTK Imager, (2) triage Windows avec KAPE, (3) image disque finale. Dans cet ordre, pour préserver la RAM (volatile) en premier.

11 Vérifier l'intégrité d'une image (hash)

Une image E01 sans vérification de hash est inutile juridiquement.

Au moment de l'acquisition

L'option Verify images after they are created lance le calcul à la fin et écrit dans le .txt :

shell
[Computed Hashes]
MD5 checksum:    a3f5b4c7d8e9f0a1b2c3d4e5f6a7b8c9
SHA1 checksum:   1234567890abcdef1234567890abcdef12345678

[Image Information]
Acquired using:  ADI 4.7.1.x
Case number:     MP-VD-2026-001
Examiner:        Analyste DFIR

Les hashs doivent être identiques entre source et image (MD5 et SHA-1 listés). Si différence : image corrompue, à refaire.

A posteriori

File → Verify Drive/Image sur n'importe quelle image E01. FTK Imager recalcule et compare aux hashs stockés dans le fichier. Si OK, l'image est intacte depuis l'acquisition.

🚨 Critique
refaire un Verify : - Après chaque copie de l'image - Avant de la transmettre à un autre service - Avant de l'analyser dans Autopsy / IPED - À chaque nouvelle expertise sur un cas ancien

12 Monter une image en lecture seule

FTK Imager peut monter un E01 ou un AD1 comme un disque virtuel Windows, accessible depuis l'Explorateur ou en CLI, sans extraire les fichiers.

Procédure

File → Image Mounting…

  • Image File : ton .E01.
  • Mount Type : Physical & Logical.
  • Drive Letter : choisis une lettre libre (ex. Z:).
  • Write Cache Folder : laisse vide (lecture seule).

Clique Mount.

Z: apparaît dans l'Explorateur Windows. En lecture seule : tu peux parcourir, ouvrir, copier des fichiers vers ton poste analyste. Toute écriture est bloquée.

Cas d'usage

  • Exploration rapide avant lancement d'Autopsy / IPED (gros traitement).
  • Recherche par mot-clé dans tout le disque via Windows Search.
  • Récupération sélective d'un fichier sans monter Autopsy.
  • Test d'outils tiers sur le contenu de l'image.
💡 Astuce
combiner avec un antivirus en lecture seule pour pré-scanner les malwares sans risque (l'image est read-only, l'AV ne peut pas modifier les fichiers).

13 Exporter des fichiers d'une image existante

Tu veux extraire un fichier précis d'un E01 sans monter l'image.

Procédure

  1. File → Add Evidence Item → Image File : ton .E01.
  2. Dans l'Evidence Tree, navigue vers le fichier voulu ([root]/Users/.../Documents/...).
  3. Clic droit sur le fichier → Export Files….
  4. Choisis le dossier de destination.

Le fichier est extrait avec ses métadonnées préservées (timestamps MAC).

Export en lot

Clic droit sur un dossier → Export Files… export tout son contenu récursivement.

Export avec liste

Clic droit → Export File Hash List… génère un CSV de tous les fichiers du dossier avec leur hash MD5 / SHA-1.

💡 Astuce
extraire la base de données SQLite d'un navigateur (History, Cookies) sans monter toute l'image, et l'analyser avec SQLite Browser.

15 Faiblesses et limites

❌ Windows uniquement : pas de version Linux ou macOS native.

❌ Pas open source : code propriétaire Exterro, audit impossible.

❌ Pas de write-blocker logiciel : il faut un write-blocker matériel (Tableau, FastBloc) pour acquisition forensique stricte.

❌ Lent sur HDD : sur disque source mécanique, l'acquisition est limitée par la lecture séquentielle.

❌ Pas d'acquisition de disques chiffrés : BitLocker, FileVault, LUKS doivent être déchiffrés en amont (sinon image chiffrée non analysable).

❌ Pas de support natif de RAID complexe : il faut reconstruire le RAID en amont ou utiliser X-Ways.

❌ Pas d'image distante : pas de capture sur un endpoint à distance (utiliser Velociraptor ou KAPE pour cela).

❌ Pas d'acquisition mobile : iPhone, Android nécessitent UFED (Cellebrite), GrayKey ou MVT.

❌ Pas de mode CLI scriptable : tout est en GUI, pas adapté pour automatisation.

❌ Vérification de hash lente : sur un E01 de 1 To, le Verify peut prendre 1-2 heures.

❌ Erreurs cryptiques : les messages d'erreur sont peu explicites, parfois il faut deviner.

❌ Dépendance à Exterro (anciennement AccessData) : si la société disparaît, plus de support.

16 Bonnes pratiques DFIR

🔹 Toujours utiliser un write-blocker matériel entre le disque source et l'ordinateur analyste. C'est non négociable en perquisition.

🔹 Vérifier le hash systématiquement après acquisition. Si différence MD5/SHA-1 source vs image, l'image est invalide.

🔹 Documenter chaque acquisition : opérateur, date, support source (numéro de série, fabricant, taille), outil, version, write-blocker utilisé.

🔹 Préférer le format E01 par défaut. Utiliser .001 (raw) uniquement si l'outil cible n'accepte que ce format.

🔹 Acquérir en physique, pas en logique, sauf cas particulier (partition chiffrée déjà ouverte).

🔹 Sur poste live, capturer la RAM EN PREMIER (avec FTK Imager) avant tout autre action.

🔹 Stocker l'image originale en lecture seule (CD-R, BD-R) ou sur RAID redondant. Toujours analyser des copies.

🔹 Calculer hash SHA-256 en plus du MD5/SHA-1 : MD5 et SHA-1 sont cryptographiquement faibles, SHA-256 est le standard moderne (peut être ajouté dans les préférences FTK Imager).

🔹 Tester l'image après acquisition : la monter via FTK Imager, naviguer dans le système de fichiers. Si l'image est invalide, FTK Imager refusera de monter.

🔹 Conserver le rapport .txt d'acquisition avec l'image. Sans rapport, l'image est inutilisable juridiquement.

🔹 Limiter le nombre de personnes en contact avec l'image originale : chain of custody documentée à chaque transfert.

🔹 Faire un backup de l'image avant analyse : la copie de travail peut être corrompue par accident.

🔹 Acquérir aussi le pagefile.sys et hiberfil.sys lors de la capture mémoire (option dans FTK Imager) : artefacts précieux complémentaires à la RAM.

18 Conclusion

FTK Imager est l'outil-pivot de toute investigation forensique : sans acquisition propre, aucune analyse n'a de valeur juridique. Sa maîtrise est la première compétence que doit acquérir un analyste DFIR.

Sa simplicité d'usage cache l'importance de la rigueur :

  1. Toujours write-blocker matériel sur le disque source.
  2. Toujours hash vérifié après acquisition.
  3. Toujours rapport documenté et conservé.
  4. Toujours travailler sur copie, jamais sur original.

Une acquisition mal faite = preuve perdue, parfois irrécupérable. Une acquisition bien faite = base solide pour des semaines d'analyse.

Recommandations finales :

  1. S'entraîner sur clé USB ou disque externe sacrificiel avant d'acquérir une preuve réelle.
  2. Acquérir + analyser dans Autopsy sur un cas pédagogique (Digital Corpora propose des images publiques pour s'exercer).
  3. Documenter ton workflow d'acquisition sous forme de checklist imprimée à apporter sur le terrain.
  4. Maîtriser la triple capture (RAM → KAPE → image disque) avant d'intervenir en réel.

Bonnes acquisitions ! 💾
