🔑 John the Ripper — Cassage de hash multi-format

À la fin de ce tutoriel, tu sauras installer John the Ripper (jumbo), identifier le bon --format pour un hash, exploiter le mode single crack unique à John (basé sur le login/GECOS), utiliser les modes wordlist + rules et incremental, et surtout maîtriser les scripts *2john (zip2john, office2john, keepass2john, pdf2john, bitlocker2john) qui sont incontournables même quand on crack avec Hashcat. Workflow combiné John + Hashcat.
🎯 Niveau expert ⏱ ~60 min 🐧 Linux 🪟 Windows 🔧 CPU optimisé ⚖️ Cadre légal strict
⚠️ Cadre légal identique à Hashcat
John the Ripper est un outil de cassage de hash dual-use réglementé. En Suisse : mandat MP (art. 197 CPP) ou audit autorisé. Sanctions : art. 143bis CP (jusqu'à 3 ans), RGPD, CFAA. Toujours documenter autorité, mandat, finalité, durée. Ce tutoriel suppose le tutoriel Hashcat (v127) en prérequis — les concepts de hash et de modes d'attaque y sont introduits.

01 Présentation générale

John the Ripper est le patriarche du cassage de hash. Sa philosophie diffère de Hashcat :

AspectHashcatJohn the Ripper
OptimisationGPU avant toutCPU avant tout (jumbo a un support GPU partiel)
ForceBrute computationPolyvalence + intelligence (mode "single")
Communauté50k+ starsPlus modeste, mais experts pointus
ConfigurabilitéTrès bonneExcellente (fichier john.conf riche)
ScriptingPlugins limitésMode external (langage C-like intégré)

Particularités :

  • 400+ formats supportés
  • Mode "single crack" unique : exploite les infos contextuelles (login, GECOS) pour deviner les passwords
  • **Scripts *2john : standard de facto pour extraire un hash depuis Office, KeePass, ZIP, RAR, BitLocker, etc. — utilisés y compris par Hashcat**
  • Règles compatibles avec Hashcat (mais syntaxe étendue)
  • Pot file : base de mots cassés réutilisable entre sessions
  • Multi-plateforme : Linux, macOS, Windows, BSD, Solaris

02 Cadre légal et éthique

Identique à Hashcat (v127) — relire la section §2 de ce tutoriel.

Rappel rapide :

  • En Suisse : casser un hash nécessite un mandat MP (art. 197 CPP) ou un cadre d'audit autorisé.
  • Sanctions : art. 143bis CP (jusqu'à 3 ans), RGPD, CFAA.
  • Toujours documenter : autorité, mandat, finalité, durée.
🚨 Critique
John est un outil dual-use réglementé. Comme Hashcat, il n'a sa place qu'en cadre légal explicite.

03 John vs Hashcat — complémentarité

Ne pas opposer John et Hashcat : les utiliser ensemble.

Quand préférer John

  • Cracking CPU uniquement (serveur sans GPU)
  • Mode "single crack" : pour AD avec colonne GECOS riche (nom, mail, fonction)
  • Formats exotiques (PDF, ZIP, Office, KeePass, BitLocker, Mozilla, DMG, ...) — l'extraction *2john est ici incontournable
  • Cas où la vitesse pure n'est pas critique (~50-100M h/s CPU vs 100G+ h/s GPU pour MD5)
  • Cracking sur SSH d'un serveur distant sans capacité GPU

Quand préférer Hashcat

  • Volume massif de hashs simples (NTLM en masse)
  • Algorithmes rapides où le GPU explose le CPU (MD5, NTLM, SHA1)
  • Brute force aveugle (uniquement si justifié)

Workflow combiné typique

  1. Identifier le hash : hashid ou --example-hashes (Hashcat)
  2. Extraire le hash : scripts *2john (John, même si on utilisera Hashcat)
  3. Cracker : Hashcat sur GPU si format pris en charge ; sinon John
bash
# Exemple complet : KeePass avec John, puis avec Hashcat
keepass2john MyDB.kdbx > kp_hash.txt

# Option A — John CPU
john --wordlist=rockyou.txt --rules kp_hash.txt
john --show kp_hash.txt

# Option B — Hashcat GPU
hashcat -a 0 -m 13400 kp_hash.txt rockyou.txt -r rules/best64.rule

Les scripts *2john de John sont toujours nécessaires pour préparer le hash. C'est pour cette raison qu'on installe les deux outils en parallèle.

05 Cas d'usage DFIR typiques

  • Cracking NTLM sur serveur sans GPU (cf. workflow Hashcat §15, transposable)
  • Audit d'AD par mode "single crack" : exploite les noms réels des comptes
  • KeePass : récupérer le master password d'une base saisie
  • Office : déverrouiller un document Word/Excel/PPT protégé
  • PDF : déverrouiller un PDF avec mot de passe utilisateur
  • ZIP, RAR, 7z : archives chiffrées suspectes
  • BitLocker : récupération de clé de volume chiffré
  • KeyChain macOS : déverrouiller un trousseau Apple
  • iTunes Backup : sauvegarde iOS protégée
  • DMG : image disque macOS chiffrée
  • Mozilla Master Password : récupérer les mots de passe Firefox

07 Installation sous Linux

Option A : depuis le paquet de la distribution (rapide mais souvent ancien)

bash
# Debian/Ubuntu
sudo apt update
sudo apt install -y john

# Fedora
sudo dnf install -y john

# Arch
sudo pacman -S john

Vérifier que c'est la version jumbo :

bash
john --list=formats | wc -l

Si moins de 200, c'est la version core — passer à l'option B pour avoir jumbo.

Option B : compiler depuis les sources (recommandé pour DFIR)

bash
# Dépendances
sudo apt install -y build-essential libssl-dev zlib1g-dev yasm pkg-config \
                    libgmp-dev libpcap-dev libbz2-dev libsqlite3-dev

# Récupérer
cd /opt
sudo git clone https://github.com/openwall/john.git
cd john/src

# Configurer et compiler
sudo ./configure
sudo make -s clean && sudo make -sj4

# Le binaire est dans ../run/
cd ../run
./john --version
./john --list=formats | wc -l   # doit afficher 400+

Tester

bash
cd /opt/john/run

# Liste des formats
./john --list=formats | head -n 30

# Hash NTLM exemple
echo 'admin:31d6cfe0d16ae931b73c59d7e0c089c0' > test.txt
./john --format=NT test.txt

Ajouter au PATH

bash
echo 'export PATH="/opt/john/run:$PATH"' >> ~/.bashrc
source ~/.bashrc

08 Installation sous Windows

Étape 1 : télécharger Jumbo

  1. Aller sur <https://www.openwall.com/john/>
  2. Télécharger john-1.9.0-jumbo-1-win64.7z (ou la dernière version Windows binaire)
  3. Décompresser dans C:\Tools\john\

Étape 2 : tester

Ouvre PowerShell ou cmd dans C:\Tools\john\run\ :

powershell
.\john.exe --version
.\john.exe --list=formats | Measure-Object -Line

Étape 3 : antivirus

Comme Hashcat, John est souvent flagué par Defender. Autoriser dans Windows Defender en documentant la décision.

09 Format de hash et identification

Identifier un hash inconnu

bash
# Avec hashid (Python)
pip install hashid
echo "5f4dcc3b5aa765d61d8327deb882cf99" | hashid
# Réponse : MD5

Avec John, on précise le format avec --format=. La liste est dans :

bash
john --list=formats

Formats DFIR essentiels

--format=Raw-SHA1SHA-1

Auto-détection

Si tu omets --format=, John essaie de détecter automatiquement. Mais en cas d'ambiguïté (deux formats compatibles), il faut spécifier explicitement.

10 Le mode "single crack"

Le mode signature de John. Il combine :

  • Le login de chaque compte
  • Les champs GECOS (nom complet, bureau, téléphone) si disponibles
  • Une mutation par règles (variations classiques : 1, !, casse, etc.)

C'est très efficace sur des dumps de /etc/shadow ou d'AD où on a le login en clair.

Syntaxe

bash
john --single hash.txt

Exemple

Fichier shadow_dump.txt (format Unix shadow) :

shell
john_doe:$6$xyz...
admin:$6$abc...

John génère et teste automatiquement : johndoe, JohnDoe, john_doe1, john_doe!, J0hndoe, doe1234, etc.

bash
john --single shadow_dump.txt
💡 Astuce
sur un dump avec logins en clair. Souvent, 30-50 % des comptes tombent en quelques secondes — sans même charger de dictionnaire.

11 Mode dictionnaire (wordlist)

Identique conceptuellement à Hashcat -a 0.

Syntaxe

bash
john --wordlist=rockyou.txt hash.txt
john --wordlist=rockyou.txt --rules hash.txt

--rules applique les transformations standards (capitalize, append digit, leet speak basique). Le pack par défaut est riche.

Personnaliser les règles

bash
john --wordlist=rockyou.txt --rules=Single hash.txt
john --wordlist=rockyou.txt --rules=Wordlist hash.txt
john --wordlist=rockyou.txt --rules=Jumbo hash.txt

Les packs sont définis dans john.conf (section [List.Rules:Xxx]).

Format des wordlists

John lit les wordlists ligne par ligne, comme Hashcat. Tous tes dictionnaires Hashcat sont réutilisables.

bash
# Récupérer un dictionnaire référence
wget https://github.com/danielmiessler/SecLists/raw/master/Passwords/Common-Credentials/10-million-password-list-top-1000000.txt

john --wordlist=10-million-password-list-top-1000000.txt --rules hash.txt

12 Mode incremental (brute force)

Brute force "intelligent" basé sur des modèles statistiques (qui sont plus efficaces qu'un brute force naïf).

Syntaxe

bash
john --incremental hash.txt
john --incremental=ASCII hash.txt
john --incremental=Alpha hash.txt
john --incremental=Digits hash.txt

Les modes définissent l'alphabet : Alpha = lettres, Digits = chiffres, Alnum = alphanumérique, etc.

Limiter

bash
john --incremental --max-length=8 hash.txt
john --incremental --min-length=6 --max-length=8 hash.txt

Sans limite, John bouclera potentiellement très longtemps. En pratique, incremental est rarement utilisé seul — préférer dictionnaire + règles.

13 Mode external et règles

Mode external

John permet d'écrire des modes de génération en langage C-like dans john.conf. Section [List.External:NomMode].

Exemple : générer des mots commençant par majuscule + 4 chiffres :

shell
[List.External:MyMode]
void filter() {
    word[0] = word[0] - 32;   // majuscule sur 1re lettre
}

void generate() {
    // ... logique custom ...
}

C'est avancé — la plupart des analystes utilisent les règles standards.

Règles personnalisées

Dans john.conf, section [List.Rules:MyCustom] :

shell
# Capitalize
c
# Append digit 0-9
$[0-9]
# Append year 2020-2026
$2$0$2$[0-6]

Puis :

bash
john --wordlist=base.txt --rules=MyCustom hash.txt
💡 Astuce
les règles John sont fortement inspirées du même langage. Beaucoup de règles Hashcat fonctionnent dans John (et inversement). Conversion souvent triviale.

Exemple : casser un PDF protégé

bash
# Extraction du hash
pdf2john.pl document_protege.pdf > pdf_hash.txt

# Inspection
cat pdf_hash.txt
# document.pdf:$pdf$2*3*128*-1028*1*16*...

# Cracking avec John
john --wordlist=rockyou.txt pdf_hash.txt

# Ou avec Hashcat
hashcat -a 0 -m 10500 pdf_hash.txt rockyou.txt -r rules/best64.rule
💡 Astuce
les scripts *2john sont incontournables pour préparer le hash.

15 Casser un hash NTLM, ZIP, Office, KeePass, PDF

NTLM (Windows)

bash
# Hash NTLM dans hashes.txt (1 par ligne)
echo "31d6cfe0d16ae931b73c59d7e0c089c0" > hashes.txt
echo "8846f7eaee8fb117ad06bdd830b7586c" >> hashes.txt

john --format=NT --wordlist=rockyou.txt --rules hashes.txt
john --show --format=NT hashes.txt

ZIP

bash
zip2john archive_protege.zip > zip_hash.txt
john --wordlist=rockyou.txt --rules zip_hash.txt
john --show zip_hash.txt

Office (Word, Excel)

bash
office2john.py document.docx > office_hash.txt
john --wordlist=rockyou.txt office_hash.txt
john --show office_hash.txt

KeePass

bash
keepass2john MyDB.kdbx > kp_hash.txt
john --wordlist=rockyou.txt --rules kp_hash.txt
john --show kp_hash.txt

PDF

bash
pdf2john.pl document.pdf > pdf_hash.txt
john --wordlist=rockyou.txt pdf_hash.txt
john --show pdf_hash.txt

Clé SSH privée protégée

bash
ssh2john.py id_rsa_protegee > ssh_hash.txt
john --wordlist=rockyou.txt ssh_hash.txt
john --show ssh_hash.txt
💡 Astuce
john --show affiche les mots de passe déjà cassés depuis le pot file. Inutile de relancer un cracking.

16 Gestion des sessions et reprise

John supporte la reprise automatique comme Hashcat.

Lancer une session nommée

bash
john --session=enquete2026 --wordlist=rockyou.txt --rules hash.txt

Suivre l'avancement

Pendant le cracking, appuie sur n'importe quelle touche pour voir le statut. Ou depuis un autre terminal :

bash
john --status=enquete2026

Mettre en pause (Ctrl+C) et reprendre

bash
john --restore=enquete2026

Le pot file

john.pot (dans le dossier ~/.john/ ou /opt/john/run/) stocke tous les hashs déjà cassés. Réutilisé automatiquement entre sessions.

Pour voir les résultats :

bash
john --show hash.txt

Astuce DFIR : conserver et archiver le john.pot entre cas — il s'enrichit progressivement.

17 Performances et parallélisation

Voir les perfs

bash
john --test

Benchmark de tous les formats avec vitesse en c/s (candidates per second).

Sur un i9-13900K (24 cœurs) :

  • NTLM : ~1.2 G c/s
  • MD5 : ~600 M c/s
  • bcrypt : ~10 k c/s
  • KeePass : ~200 c/s

Multi-cœur (OpenMP)

John jumbo est compilé avec OpenMP. Pour exploiter tous les cœurs :

bash
john --fork=16 --wordlist=rockyou.txt hash.txt

--fork=16 lance 16 processus parallèles.

Distribution sur plusieurs machines

bash
# Sur la machine 1 (de 4)
john --node=1/4 --fork=8 --wordlist=rockyou.txt hash.txt

# Sur la machine 2
john --node=2/4 --fork=8 --wordlist=rockyou.txt hash.txt

# Etc.

Chaque nœud traite 1/4 de l'espace de recherche. Combiné avec --fork pour le multi-cœur local, et tu as une distribution simple sans MPI.

Support GPU (limité)

Avec John jumbo compilé avec OpenCL :

bash
john --list=opencl-devices
john --format=NT-opencl --wordlist=rockyou.txt hash.txt
💡 Astuce
. John en GPU est correct mais Hashcat est mieux optimisé.

18 Forces et faiblesses

Forces

✅ Le standard historique : 30 ans de maturité.

✅ Polyvalence inégalée : 400+ formats supportés (jumbo).

✅ Mode "single crack" : intelligence basée sur le contexte (login, GECOS).

✅ **Scripts *2john : incontournables**, même quand on crack avec Hashcat.

✅ Modes external : langage C-like pour règles très avancées.

✅ Open source GPLv2 : auditable, modifiable, sans dépendance commerciale.

✅ Multi-plateforme : Linux, macOS, Windows, BSD, Solaris.

✅ Pot file persistant : réutilisation entre sessions et cas.

✅ Communauté experts : moins de bruit que Hashcat, mais analystes pointus.

✅ Distribution simple : --node=X/N --fork=K sans MPI.

Faiblesses

❌ Plus lent que Hashcat sur GPU : par design (CPU first).

❌ Documentation parfois sèche : doc historique, certaines options peu commentées.

❌ Compilation parfois nécessaire : la jumbo des distros est souvent en retard.

❌ Syntaxe légèrement différente de Hashcat — courbe d'apprentissage si on vient de l'autre.

❌ Moins d'aide automatique : --example-hashes n'existe pas en équivalent direct.

❌ Communauté plus restreinte : moins de tutoriels modernes que Hashcat.

❌ Aspect dual-use : à manipuler avec discernement (cadre légal).

19 Bonnes pratiques DFIR

🔹 Toujours installer John ET Hashcat : les deux sont complémentaires, jamais concurrents.

🔹 Démarrer par --single sur tout dump avec logins en clair. 30-50 % de comptes tombent en quelques secondes.

🔹 Construire ta wordlist : rockyou + weakpass + dictionnaire métier custom (CV, intérêts, dates) du suspect.

🔹 Tester --show avant relancer : le pot file peut déjà contenir la réponse.

🔹 Documenter chaque session : --session=nom_explicite qui rappelle le cas.

🔹 Conserver le pot file entre cas (effet cumulatif, base de mots cassés qui s'enrichit).

🔹 Préférer dictionnaire + règles au brute force aveugle.

🔹 Mesurer avant lancer : john --test --format=XX pour estimer la faisabilité.

🔹 Pour formats exotiques (BitLocker, KeePass, Office, PDF) : *2john puis John ou Hashcat selon ce qui va vite.

🔹 Cracking sur machine dédiée : pas sur le poste analyste, jamais sur preuve directe.

🔹 Mises à jour régulières : git pull && make ajoute des formats fréquemment.

🔹 Audit légal préalable : mandat, cadre, finalité documentés avant chaque session.

🔹 Effacer les hashs une fois l'enquête close (sauf si pièce de procédure formalisée).

🔹 Apprendre john.conf : pour personnaliser règles et modes external.

🔹 Comprendre le --node : pour distribuer sur plusieurs machines sans complexité.

21 Conclusion

John the Ripper reste un incontournable du DFIR, malgré la montée en puissance de Hashcat. Son mode "single crack", ses **scripts *2john et sa polyvalence inégalée** sur les formats exotiques en font le complément naturel — pas le concurrent — de Hashcat.

Recommandations finales :

  1. Installer la version jumbo systématiquement (paquet distro souvent insuffisant).
  2. Maîtriser --single : c'est le différenciateur de John face à Hashcat.
  3. **Connaître les scripts *2john** : tu les utiliseras pour Hashcat aussi.
  4. Construire un workflow hybride : John pour l'extraction et les formats exotiques, Hashcat pour la puissance brute GPU.
  5. Conserver les pot files entre enquêtes — effet cumulatif considérable.
  6. Documenter chaque session — discipline juridique identique à Hashcat.

John est l'outil qui a inventé une discipline. Le respecter, c'est respecter l'histoire du DFIR. 🔑
