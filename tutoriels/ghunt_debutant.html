🪪 GHunt débutant — OSINT Google Account

À la fin de ce tutoriel, tu sauras installer GHunt, créer un compte burner Google dédié OSINT, t'authentifier via cookies de session, lancer une recherche par email Google (nom complet, photo, Gaia ID, organisations, reviews Maps, YouTube channel, calendriers publics), faire une recherche par Gaia ID, exporter en JSON et exploiter dans un workflow combiné avec Holehe, Sherlock, Maigret.
🎯 Niveau débutant ⏱ ~45 min 🐧 Linux / macOS 🪟 Windows 🪪 OSINT Google Account ⚠️ Compte burner OBLIGATOIRE
⚠️ Compte Google burner OBLIGATOIRE — sensibilité légale renforcée
GHunt utilise les API privées Google et nécessite une authentification via cookies de session. Ne JAMAIS utiliser ton compte Google personnel ni un compte pro : risque de suspension, violation TOS, exposition. Créer un compte burner dédié OSINT (ProtonMail / Tutanota + Google sans téléphone perso). Données collectées (nom, photo, organisations) = données personnelles directes : nLPD, RGPD, art. 173-179 CP. Mandat ou autorisation explicite obligatoire.

  • Tu prépares une certification OSINT

02 Qu'est-ce que GHunt

GHunt est un outil Python qui exploite les API internes de Google pour extraire des informations publiques associées à un compte.

Ce que GHunt récupère

À partir d'un email Google :

InformationDescription
Nom completSi le compte est public
Photo de profilURL et téléchargement
Gaia IDIdentifiant unique Google interne
Custom URLsLiens vers le profil sur Google services
LocalisationSi renseignée publiquement
Reviews Google MapsAvis publics laissés
Photos Google MapsPhotos publiques de lieux
YouTube channelSi associé au compte
Last activityDate approximative dernière activité
OrganisationsGoogle Workspace si applicable
Calendriers publicsSi rendus publics

Spécificités

  • Légal mais sensible : récupère des données publiquement disponibles mais via les API privées Google (zone grise)
  • Évolue avec Google : Google ferme régulièrement des endpoints → GHunt doit suivre
  • Authentification requise : GHunt utilise des cookies de session Google légitime
  • Pas de bypass : récupère uniquement ce qui est rendu public par l'utilisateur

03 Cadre légal et éthique — particulièrement sensible

GHunt est plus sensible que Sherlock/Maigret/Holehe parce que :

  1. Il utilise des API privées Google (zone grise vis-à-vis des Terms of Service Google)
  2. Il extrait des données personnelles au sens RGPD/nLPD
  3. Il identifie explicitement une personne réelle (nom, photo)

Ce qui est autorisé

  • Mandat MP (art. 197 CPP en Suisse) avec finalité documentée
  • Audit interne autorisé sur emails de son organisation
  • Recherche sur son propre compte (audit personnel)
  • Journalisme d'investigation d'intérêt public, avec encadrement éditorial
  • Trace Labs (CTF OSINT pour personnes disparues, cadre éthique)

Ce qui est interdit / réglementé

  • Stalking : sanction pénale (art. 179 quater CP Suisse, harcèlement obsessionnel)
  • Doxxing : exposition d'informations privées → atteinte grave sphère privée
  • Recherche sans cadre légitime : violation nLPD/RGPD (traitement de données sans base légale)
  • Vente de données collectées : strictement interdit

Risques spécifiques GHunt

⚠️ Google peut détecter les usages anormaux :

  • Compte Google utilisé pour GHunt peut être suspendu s'il fait trop de requêtes
  • Bannissement IP possible
  • Violation TOS Google : zone grise juridique

Sanctions

  • Suisse : art. 173-179 CP, nLPD
  • France : art. 226-1 CP, RGPD
  • USA : Stalking statutes
  • Toute juridiction : violation TOS Google peut entraîner des actions civiles
🚨 Critique
GHunt n'est pas un outil de curiosité. Mandat ou autorisation explicite avant chaque utilisation.

05 Cas d'usage typiques

  • Enquête pénale : email Google d'un suspect → identité, organisations, dernière activité
  • Anti-fraude : valider la cohérence d'un partenaire commercial (compte Google = profil pro probablement vrai)
  • Investigation cyberharcèlement : retrouver l'identité d'un harceleur Gmail
  • Threat intelligence : tracer un opérateur de groupe APT via email Gmail leaké
  • Due diligence : vérifier la présence Google d'un cible (avant fusion, recrutement, etc.)
  • Journalisme d'investigation : tracer un compte Gmail anonyme qui publie de fausses informations
  • Trace Labs OSINT CTF : retrouver une personne disparue via traces Google

09 Authentification — étape clé

C'est le point qui rend GHunt différent : il faut t'authentifier avec un compte Google.

Pourquoi ?

GHunt utilise les mêmes API internes que Google Maps, Drive, etc. — ces API exigent une session Google valide. Sans authentification, GHunt ne peut rien faire.

Compte burner OBLIGATOIRE

⚠️ Ne JAMAIS utiliser ton compte Google personnel ni un compte pro.

Raisons :

  • Google peut détecter l'usage anormal → suspension du compte
  • Tu exposes ton identité dans les logs Google
  • Tu violes potentiellement les TOS Google

Bonne pratique : créer un compte Google dédié OSINT (alias burner) :

  1. Email aléatoire chez un autre fournisseur (Proton Mail, Tutanota)
  2. Inscription Google avec téléphone temporaire (ou jamais)
  3. Compte utilisé uniquement pour OSINT
  4. Pas de données personnelles, pas de Drive, pas de Photos

Procédure d'authentification

bash
ghunt login

GHunt te demande de te connecter à Google dans un navigateur, puis de copier-coller des cookies :

  1. Va sur <https://accounts.google.com/> avec ton compte burner
  2. Connecte-toi
  3. Va sur <https://drive.google.com/>
  4. Ouvre les DevTools (F12)
  5. Onglet Application (Chrome) ou Storage (Firefox)
  6. Copier les valeurs des cookies : SID, HSID, SSID, APISID, SAPISID
  7. Coller dans le terminal GHunt

GHunt sauvegarde ces cookies dans un fichier de config (~/.ghunt/).

Renouvellement

Les cookies Google expirent. Si une recherche échoue avec erreur d'auth → refaire ghunt login.

💡 Astuce
sur ta VM OSINT dédiée, Chrome connecté au compte burner reste ouvert en permanence. Les cookies restent valides plus longtemps.

Syntaxe basique

bash

11 Comprendre les résultats GHunt

Account ID (Gaia ID)

Identifiant unique permanent Google. Précieux car même si l'email change, le Gaia ID reste.

Last edit / Last active

  • Last edit : dernière modification du profil Google (changement de photo, nom)
  • Last active : dernière activité estimée (basée sur indicateurs publics, pas exact)

Profile picture

Photo de profil téléchargeable via l'URL. Très utile pour reverse image search (TinEye, Yandex, Google Images) → trouve d'autres comptes avec la même photo.

Reviews et photos Maps

Si la cible a laissé des avis ou photos publics sur Google Maps :

  • Géolocalisation indirecte : lieux qu'elle fréquente
  • Habitudes : restaurants, hôtels, etc.
  • Photos : peut révéler beaucoup (intérieur de maison, plaque immatriculation, etc.)

YouTube channel

Si associé : preuves audiovisuelles potentielles.

Workspace / Organization

Si compte professionnel : nom de l'organisation. Pivot vers LinkedIn, Hunter.io pour confirmer.

Calendriers publics

Rare mais précieux : agenda d'événements de la cible.

12 Recherche par Gaia ID

Si tu connais le Gaia ID (depuis une fuite, une recherche précédente, ou un partage Drive) :

bash
ghunt gaia 1234567890123456789

Avantage : même si la cible change d'email, le Gaia ID reste. Recherche plus stable.

13 Export JSON et exploitation

bash
ghunt email john@gmail.com --json results.json

Sortie JSON structurée. Exploitable en Python :

python
import json

with open('results.json') as f:
    data = json.load(f)

print(f"Nom : {data.get('name')}")
print(f"Gaia ID : {data.get('gaia_id')}")
print(f"Photo : {data.get('profile_picture_url')}")

for review in data.get('maps', {}).get('reviews', []):
    print(f"Avis sur {review['place']} le {review['date']}")

Intégration workflow

Combiner avec Sherlock/Maigret :

bash
# 1. GHunt → récupérer nom
NAME=$(ghunt email john@gmail.com --json - | jq -r '.name')
echo "Nom : $NAME"

# 2. Dériver usernames probables
# Si "John Doe" → johndoe, j.doe, jdoe, john_doe, doejohn
for user in johndoe j.doe jdoe john_doe doejohn; do
    sherlock --print-found "$user"
done

# 3. Maigret sur l'email + variants
maigret john@gmail.com --html

14 Limites de GHunt

❌ Authentification Google requise : compte burner obligatoire.

❌ Cookies expirent : nécessite refresh régulier.

❌ Google ferme des endpoints : GHunt doit suivre → version obsolète peut ne plus fonctionner.

❌ Détection possible : Google peut suspendre le compte qui fait trop de requêtes.

❌ Que des comptes Google : limité à l'écosystème Google (Gmail, Workspace, Maps, YouTube).

❌ Pas de bypass de privacy : si la cible a tout en privé, GHunt récupère peu de chose (nom, peut-être Gaia ID).

❌ Pas de Drive privé : GHunt voit les partages publics, pas les fichiers privés.

❌ Geolocation imprécise : "last active" est une estimation, pas exact.

❌ Aspect zone grise TOS : usage discutable même à des fins légitimes.

❌ Recherche par téléphone limitée : la fonction ghunt phone existe mais moins fiable.

15 Sécurité opérationnelle

GHunt demande plus de précautions que les autres outils OSINT.

Environnement isolé

🛡️ VM dédiée OSINT (ex : Tails, Whonix, ou VM custom avec navigateur burner).

🛡️ VPN OSINT dédié (Mullvad, ProtonVPN multi-hop, ou Tor).

🛡️ Compte Google burner : créé spécifiquement pour OSINT, jamais utilisé personnellement.

Rotation et précautions

  • Limiter les requêtes : pas plus de 10-20 par heure sur le compte burner.
  • Rotation : avoir 2-3 comptes burner en réserve.
  • Si suspension : utiliser le suivant.
  • Pas de données personnelles sur le compte burner.

Pas de pivotement personnel

🛡️ Le compte burner ne doit pas pouvoir te remonter :

  • Pas de téléphone réel à la création
  • Pas d'email perso de récupération
  • Pas de navigation perso avec ce compte
  • Pas de Drive/Photos partagés perso

Documentation rigoureuse

Comme tous les outils OSINT — autorité, finalité, période, outils, version, IP utilisée, compte burner utilisé. Pour audit interne ou défense en cas de contestation.

16 Workflow OSINT Google complet

Mise en pratique : enquête à partir d'un email Gmail.

bash
EMAIL="suspect@gmail.com"
mkdir -p "case_${EMAIL//@/_at_}"
cd "case_${EMAIL//@/_at_}"

source ~/osint/venv/bin/activate

Étape 1 — GHunt

bash
ghunt email "$EMAIL" --json ghunt_results.json
cat ghunt_results.json | jq

Récupération :

  • Nom : John Doe
  • Gaia ID : 1234567890
  • Photo de profil
  • 12 reviews Maps
  • YouTube channel

Étape 2 — Reverse image search sur la photo

Télécharger la photo (URL dans le JSON), faire reverse image search :

  • TinEye : <https://tineye.com/>
  • Yandex Images : <https://yandex.com/images/>
  • Google Images : upload manuel

Souvent retrouve la photo sur LinkedIn, Twitter, etc. — confirmation identité.

Étape 3 — Maps reviews analyse

bash
jq -r '.maps.reviews[]' ghunt_results.json

Liste des avis publics avec lieux. Permet de géolocaliser approximativement (lieux fréquentés).

Étape 4 — Holehe sur l'email

bash
holehe "$EMAIL" --only-used --no-color

→ Liste des autres services associés.

Étape 5 — Have I Been Pwned

bash
curl -H "hibp-api-key: $HIBP_KEY" \
    "https://haveibeenpwned.com/api/v3/breachedaccount/$EMAIL"

→ Fuites de données associées.

Étape 6 — Dérivation usernames probables depuis "John Doe"

bash
USERS="johndoe j.doe jdoe john_doe doejohn jdoe123"
for user in $USERS; do
    sherlock --print-found --no-color "$user" --folderoutput sherlock_results/
done

maigret "$EMAIL" --html --folderoutput maigret_email/

Étape 7 — Corroboration

Croiser :

  • Nom GHunt avec noms trouvés sur Sherlock/Maigret
  • Photo GHunt avec photos sur autres profils (reverse image)
  • Lieux Maps avec localisations déclarées sur autres réseaux
  • Email avec fuites HIBP

Si 3+ sources cohérentes → forte probabilité même personne.

Étape 8 — Archivage et rapport

bash
# Wayback Machine sur chaque profil trouvé
# Screenshots horodatés
# Hash de tous les rapports
sha256sum *.json *.html > MANIFEST.txt

# Synthèse
cat > rapport_synthese.md <<EOF
# Investigation OSINT — $EMAIL

**Date :** $(date -Iseconds)
**Autorité :** [mandat]
**Analyste :** [nom]

17 Identité présumée

  • Nom : John Doe
  • Gaia ID : 1234567890
  • Photo : (corroborée sur Sherlock + Maigret)

18 Sources Google

  • 12 avis Maps publics
  • YouTube channel "John Doe Travels"

19 Sources externes (Sherlock + Maigret + Holehe)

  • ...

20 Manifest

$(cat MANIFEST.txt) EOF

17 Erreurs fréquentes du débutant

🪤 Utiliser son compte Google perso : suspension probable + risque légal. Compte burner obligatoire.

🪤 Faire 100 requêtes en boucle : détection Google → ban. Limiter à 10-20/heure.

🪤 Conclure de la seule réponse GHunt : le nom n'est pas une preuve. Toujours corroborer (photo + reviews + reverse image + autres outils).

🪤 Pas de VPN OSINT : ton IP perso dans les logs Google.

🪤 Ne pas archiver immédiatement : la cible peut tout passer en privé après avoir reçu une notification d'activité suspecte.

🪤 Confondre GHunt et Sherlock : GHunt = Google uniquement, Sherlock = tous sites publics. Complémentaires, pas substituables.

🪤 Ignorer le cadre légal : pas de mandat = pas d'enquête. Curiosité = sanction.

🪤 Ne pas tester sur soi-même : lancer GHunt sur ton propre email Google pour voir ce que tu exposes — bonne pratique préliminaire.

🪤 Oublier de renouveler les cookies : ghunt login régulier.

🪤 Ne pas mettre à jour GHunt : Google change les APIs régulièrement. pip install --upgrade ghunt fréquemment.

🪤 Stocker les résultats non-chiffrés : noms et photos de personnes = données personnelles. Chiffrer au repos (VeraCrypt, LUKS).

19 Forces et faiblesses

Forces

✅ Identification rapide : nom, photo, organisation Google en 10 secondes.

✅ Spécialiste Google : seul outil qui exploite vraiment l'écosystème Google.

✅ Reviews Maps : géolocalisation indirecte précieuse.

✅ Photo de profil : pivot vers reverse image search.

✅ Open source : auditable.

✅ JSON export : intégrable dans workflow scripté.

✅ Maintenu activement : mxrch suit les changements Google.

✅ Complémentaire de Sherlock + Maigret + Holehe.

Faiblesses

❌ Authentification Google obligatoire : compte burner requis.

❌ Google ferme des endpoints : version peut devenir obsolète sans préavis.

❌ Cookies expirent : refresh régulier.

❌ Détection possible : usage massif → ban compte.

❌ Zone grise TOS Google : risque légal théorique.

❌ Limité à Google : pas d'autres écosystèmes.

❌ Pas de bypass de privacy : si cible verrouille tout, peu de résultats.

❌ Setup plus complexe que Sherlock/Maigret/Holehe.

❌ Données très personnelles : sensibilité légale et éthique forte.

❌ Dépendance fournisseur : Google peut tout casser un matin.

25 Conclusion

GHunt complète puissamment l'arsenal OSINT par l'angle Google — un écosystème omniprésent dans la vie numérique moderne. Là où Sherlock/Maigret/Holehe couvrent l'aspect "présence en ligne", GHunt apporte l'identification réelle quand le compte est associé à Google.
