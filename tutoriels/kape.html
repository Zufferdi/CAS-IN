🥋 KAPE — Triage Windows en intervention

À la fin de ce tutoriel, tu sauras installer KAPE et le mettre à jour avec Get-KAPEUpdate.ps1, lancer un triage Windows complet en 5 minutes avec !SANS_Triage, parser les artefacts avec EZ Tools (Prefetch, Amcache, Registry, EVTX, MFT), encapsuler en VHDX, et chasser avec Hayabusa via les Modules KAPE.
🎯 Niveau intermédiaire ⏱ ~45 min 🪟 Windows uniquement ⚡ ~5 min de triage 🧰 EZ Tools intégrés
ℹ️ À propos de KAPE
KAPE (Kroll Artifact Parser and Extractor) est l'outil de référence pour le triage forensique Windows. Développé par Eric Zimmerman pour Kroll Cyber. Standard de fait dans les CERT et MSSP. Collecte et parse en 3-7 minutes ce qu'une collecte manuelle prendrait des heures.

📦 Page officielle Kroll · Gratuit (EULA non commerciale)

01 Présentation générale

KAPE est un moteur d'exécution qui automatise deux tâches répétitives en intervention sur incident Windows :

  1. Collecter des fichiers depuis un système live ou une image montée (les Targets).
  2. Parser ces fichiers pour produire des artefacts exploitables (les Modules).

Là où une collecte manuelle prend une heure, KAPE le fait en 2 à 5 minutes sur une machine en production, sans redémarrage. C'est devenu l'outil de triage Windows dans les CERT et chez les MSSP.

Particularités :

  • 100 % portable : un dossier KAPE\ que tu copies sur une clé USB ou un partage.
  • Pas d'installation, pas de modifications du système cible (sauf la cible où KAPE écrit).
  • Lit les fichiers verrouillés Windows (ruches du registre, NTUSER.DAT actif) grâce à RawCopy et Volume Shadow Copy intégrés.
  • Communauté très active : 200+ Targets et 250+ Modules contribués sur GitHub.

02 Cas d'usage typiques

  • Triage d'urgence sur un poste compromis en production, sans le redémarrer.
  • Collecte forensique légère à utiliser à distance (RDP, PSExec, Velociraptor) sans saisir le poste.
  • Triage de masse sur un parc compromis (ransomware) : 50 postes en parallèle.
  • Préparation d'une analyse longue : KAPE livre déjà 80 % des artefacts à analyser avant que tu reçoives l'image disque complète.
  • Préservation orientée sur un système où l'image complète n'est pas possible (serveur 24/7, RAID complexe).
  • Audit de conformité : vérifier rapidement des indicateurs sur un échantillon de postes.

03 Architecture : Targets et Modules

KAPE repose sur deux types de fichiers de configuration YAML.

Targets (.tkape)

Un Target décrit quels fichiers collecter depuis le système :

  • Chemin (avec wildcards)
  • Filtres (par nom, taille, date)
  • Récursivité
  • Description et catégorie

Exemple simplifié : un Target « EvidenceOfExecution » collecte Prefetch, Amcache, RecentFileCache, ShimCache, BAM, UserAssist, etc.

Modules (.mkape)

Un Module décrit comment parser les fichiers collectés :

  • Quel binaire externe exécuter (parser EZ Tools, regripper, etc.)
  • Quels paramètres lui passer
  • Quel format de sortie

Exemple : le Module PECmd parse les fichiers .pf (Prefetch) avec l'outil PECmd.exe d'Eric Zimmerman et produit un CSV.

Targets composites

Un Target peut référencer d'autres Targets pour créer des collectes composées. Le Target !BasicCollection par exemple agrège ~20 Targets élémentaires : registre, EVTX, MFT, Prefetch, navigateurs, etc.

04 Prérequis et téléchargement

OS supportés

  • Windows 7 / Server 2008 R2 et supérieur (KAPE lui-même est .NET)
  • Cible : tout Windows depuis XP (mais l'efficacité dépend des artefacts présents)

Prérequis machine analyste

  • .NET Framework 4.6.2+ (présent par défaut sur Win10+)
  • ~100 Mo libres pour KAPE + binaires EZ Tools
  • Privilèges administrateur sur la machine cible pour lire les fichiers verrouillés

Téléchargement

KAPE n'est pas sur GitHub directement. Procédure :

  1. Va sur la page de Kroll : <https://www.kroll.com/en/services/cyber-risk/incident-response-litigation-support/kroll-artifact-parser-extractor-kape>
  2. Remplis le formulaire (nom, email, organisation).
  3. Tu reçois un lien de téléchargement par mail.
  4. Télécharge kape.zip.

05 Installation

Étape 1 : décompresser

Décompresse kape.zip dans un dossier de ton choix, par exemple :

bat
C:\Tools\KAPE\

Étape 2 : exécuter Get-KAPEUpdate.ps1

C'est l'étape critique souvent oubliée. Ouvre PowerShell en administrateur dans le dossier KAPE :

powershell
cd C:\Tools\KAPE
.\Get-KAPEUpdate.ps1

Ce script télécharge :

  • La dernière version du moteur KAPE
  • Tous les Targets et Modules du dépôt GitHub <https://github.com/EricZimmerman/KapeFiles>
  • Tous les binaires EZ Tools nécessaires (PECmd, RECmd, MFTECmd, EvtxECmd, etc.)

Sans cette étape, KAPE est inutilisable car les Modules réfèrent à des binaires absents.

Étape 3 : vérifier

bat
.\kape.exe --version

Tu dois voir la version (1.x.x.x). Et :

bat
dir /b Targets\*.tkape | find /c /v ""
dir /b Modules\*.mkape | find /c /v ""

Tu dois avoir 200+ Targets et 250+ Modules disponibles.

💡 Astuce
programme Get-KAPEUpdate.ps1 en tâche planifiée hebdomadaire pour rester à jour des nouveaux Targets/Modules contribués.

06 Premier triage avec gkape (GUI)

gkape.exe est l'interface graphique. Elle aide à découvrir les options et génère la commande CLI équivalente.

Étapes typiques

  1. Lance gkape.exe (clic droit → exécuter en tant qu'admin).
  2. Use Target options : coche.
  3. Target source : C:\ (ou la lettre du disque à triager).
  4. Target destination : D:\KAPE_Output\HOSTNAME\ (vers un disque externe ou partage).
  5. Dans la liste des Targets, coche !BasicCollection (le pack standard de triage).
  6. Use Module options : coche.
  7. Module source : le même que Target destination (parse ce qu'on vient de collecter).
  8. Module destination : D:\KAPE_Modules\HOSTNAME\.
  9. Dans la liste des Modules, coche !EZParser (parse tout ce qui a été collecté).
  10. Options : coche Process VSCs si tu veux inclure les Volume Shadow Copies.
  11. Container : choisis VHDX pour packager le résultat.
  12. Clique Execute!.

En bas, la command line générée s'affiche. Sauvegarde-la dans tes notes — c'est ce qu'il faut taper en CLI la prochaine fois.

07 Triage en ligne de commande

La même chose en CLI, plus rapide et scriptable :

bat
kape.exe --tsource C: --tdest D:\KAPE_Output\HOSTNAME --target !BasicCollection ^
  --msource D:\KAPE_Output\HOSTNAME --mdest D:\KAPE_Modules\HOSTNAME --module !EZParser ^
  --vhdx HOSTNAME

Explication :

  • --tsource : où collecter (généralement C:)
  • --tdest : où écrire les fichiers collectés
  • --target : nom du Target (ou Target composite)
  • --msource : où trouver les fichiers à parser (ici, identique à --tdest)
  • --mdest : où écrire les résultats parsés
  • --module : nom du Module (ou Module composite)
  • --vhdx HOSTNAME : encapsule la collecte dans un fichier VHDX nommé HOSTNAME.vhdx

Options utiles supplémentaires

bat
--vss             # Inclut les Volume Shadow Copies (versions antérieures de fichiers)
--vhdx NAME       # Package en VHDX (montable comme un disque)
--zip NAME        # Package en zip
--gui             # Lance gkape
--mlogq           # Log silencieux des Modules (pas de fenêtre par binaire)
--debug           # Verbeux pour debug
--mc              # Génère le manifeste de collecte

10 Workflow complet : collecte + parsing en un coup

Le scénario typique en intervention sur incident : tu arrives sur un poste compromis, tu veux la collecte standardisée en 5 minutes, parsée et zippée.

bat
kape.exe ^
  --tsource C: ^
  --tdest D:\Triage\WORKSTATION01 ^
  --target !SANS_Triage ^
  --vss ^
  --msource D:\Triage\WORKSTATION01 ^
  --mdest D:\Triage\WORKSTATION01\Parsed ^
  --module !EZParser,Hayabusa,Loki ^
  --vhdx WORKSTATION01_2026-01-15 ^
  --mlogq

Cette commande :

  1. Collecte tous les artefacts SANS Triage depuis C: (avec Volume Shadow Copies pour les versions historiques)
  2. Parse immédiatement avec EZ Tools + Hayabusa (chasse Sigma) + Loki (YARA)
  3. Encapsule la collecte brute dans WORKSTATION01_2026-01-15.vhdx
  4. Place les parses dans D:\Triage\WORKSTATION01\Parsed\

Tu obtiens en sortie :

  • WORKSTATION01_2026-01-15.vhdx : montable, contient toute la collecte brute
  • Parsed\ : CSV exploitables dans Excel / Timeline Explorer / Splunk
  • Logs KAPE détaillés
💡 Astuce
sur un disque externe NVMe, ce workflow prend 3 à 7 minutes pour un poste utilisateur standard. Préparer une clé USB pré-configurée avec ce .bat est un réflexe DFIR.

11 Triage à distance

KAPE peut être exécuté à distance via plusieurs moyens.

PSExec / Sysinternals

bat
psexec \\TARGET-PC -c -s -h kape.exe --tsource C: --tdest \\NAS\Triage\TARGET-PC --target !SANS_Triage --vss --zip TARGET-PC

Copie KAPE vers la cible, l'exécute en SYSTEM, et écrit le résultat vers un partage.

Velociraptor

KAPE est intégré dans Velociraptor via l'artefact Windows.KapeFiles.Targets. Voir le tutoriel Velociraptor pour les détails.

GPO + tâche planifiée

Pour un triage de masse, déployer KAPE via GPO et déclencher via tâche planifiée distante (schtasks /create /s TARGET /tn ...).

🚨 Critique
un triage à distance écrit potentiellement sur la cible (ou un partage). Documenter précisément où vont les fichiers et hasher la collecte dès qu'elle est close.

12 Personnaliser un Target ou Module

Créer un Target custom

Crée un fichier Targets\Custom\MonCas.tkape :

yaml
Description: Collecte spécifique pour le cas Affaire 2026-001
Author: Analyste DFIR
Version: 1.0
Id: 12345678-abcd-ef00-1234-567890abcdef
RecreateDirectories: true
Targets:
    -
        Name: Fichiers suspects identifiés
        Category: Custom
        Path: 'C:\Users\*\AppData\Local\Temp\suspicious_*.exe'
    -
        Name: Logs application X
        Category: Custom
        Path: 'C:\ProgramData\AppX\Logs\*.log'
        Recursive: true

Au lancement suivant, KAPE détecte le nouveau Target et tu peux le sélectionner.

Créer un Module custom

Modules\Custom\MonParser.mkape :

yaml
Description: Mon parser custom
Category: Custom
Author: Analyste DFIR
Version: 1.0
Id: 87654321-abcd-ef00-1234-567890abcdef
BinaryUrl: https://example.com/myparser
ExportFormat: csv
Processors:
    -
        Executable: myparser.exe
        CommandLine: -input %sourceDirectory% -output %destinationDirectory%\output.csv
        ExportFormat: csv

Contribuer au projet

Si ton Target ou Module est généralisable, propose une PR au dépôt <https://github.com/EricZimmerman/KapeFiles>. La communauté est très réactive et la qualité de revue est élevée.

13 Forces de KAPE

✅ Gratuit (sous EULA non commerciale stricte).

✅ Rapidité : 3-10 minutes pour un triage complet, sans redémarrage.

✅ Portable : un dossier, une clé USB, aucune installation.

✅ Lit les fichiers verrouillés Windows (registre actif, NTUSER.DAT, EVTX en cours d'écriture) via RawCopy et VSS.

✅ Communauté très active : ~250 Modules, ~200 Targets contribués, mises à jour fréquentes.

✅ Intégration EZ Tools : tous les parsers de référence d'Eric Zimmerman directement disponibles.

✅ Encapsulation VHDX : collecte montable comme un disque virtuel, idéale pour analyse ultérieure.

✅ VSS : récupère les versions antérieures de fichiers via Volume Shadow Copies (parfois la seule trace d'un malware effacé).

✅ Documentation foisonnante : tutoriels SANS, Magnet Forensics, Kroll, blog Eric Zimmerman.

✅ Standard de fait : reconnu par les CERT, les MSSP, les forces de l'ordre.

✅ Scriptable : intégrable dans tout workflow PowerShell, batch, ou orchestrateur (Velociraptor, MS Sentinel, Splunk SOAR).

14 Faiblesses et limites

❌ Windows seulement : pas de support Linux ou macOS (sauf collecter une image montée).

❌ EULA restrictive : interdit la facturation comme livrable client direct. Ambigu en consulting — relire avant chaque mission commerciale.

❌ Pas open source : le code de KAPE lui-même est propriétaire Kroll. Seuls les Targets/Modules sont open source.

❌ Pas de signature numérique sur tous les binaires EZ Tools, ce qui peut alerter l'EDR ou l'antivirus de la cible.

❌ Antivirus / EDR sensibles : certains EDR considèrent KAPE comme suspect (lecture massive du système). Prévoir une exclusion ou désactivation temporaire avec validation hiérarchique.

❌ Dépendance internet pour les updates : Get-KAPEUpdate.ps1 nécessite un accès à GitHub. Sur une mission air-gappée, prévoir un pack pré-téléchargé.

❌ Configuration verbeuse : créer un Target ou Module custom demande de comprendre la syntaxe YAML et la sémantique KAPE (chemins, wildcards, recursion).

❌ Pas de moteur de chasse intégré : KAPE collecte et parse, mais c'est à toi de chercher dans les CSV (ou d'utiliser Hayabusa/Chainsaw en Module).

❌ VHDX limité à 2 To : sur un serveur volumineux, fractionner.

❌ Pas de mode hors-ligne natif sur image montée : il faut utiliser --tsource F:\Windows après avoir monté l'image, en faisant attention aux chemins.

15 Bonnes pratiques DFIR

🔹 Préparer une clé USB KAPE dédiée, avec kape.exe à jour et un fichier .bat standard pour la collecte triage.

🔹 Toujours écrire la collecte sur un disque externe, jamais sur le disque cible (sauf si impossible — alors documenter).

🔹 Inclure les VSS (--vss) par défaut : c'est souvent là que tu trouves les traces effacées par l'attaquant.

🔹 Hasher la collecte (Get-FileHash *.vhdx -Algorithm SHA256) dès qu'elle est terminée, et consigner.

🔹 Documenter le contexte : utilisateur connecté à l'instant t, processus actifs, dernière mise à jour Windows, etc. (KAPE inclut un manifeste mais le complémenter).

🔹 Combiner KAPE avec une acquisition mémoire (Surge, MAGNET RAM Capture, DumpIt, winpmem) — KAPE ne fait pas de mémoire vive.

🔹 Whitelister KAPE dans l'EDR avant l'intervention si possible, ou prévoir le risque d'alerte.

🔹 Triage en local d'abord, parsing ensuite : sur une mission, exécute --target rapidement, puis lance --module en parallèle dans un second terminal pendant que tu prépares la suite.

🔹 Conserver la collecte brute (VHDX) intacte, et travailler sur copies des CSV de parsing.

🔹 Apprendre EZ Tools en parallèle : KAPE est génial, mais comprendre PECmd, RECmd, EvtxECmd directement permet de creuser un cas spécifique sans passer par KAPE.

🔹 Tester sur une VM avant d'utiliser en mission réelle — créer un scénario de compromission (Cobalt Strike beacon, persistence registry, exécution Mimikatz) et faire le triage.

🔹 Croiser avec MITRE ATT&CK : chaque artefact KAPE correspond à une ou plusieurs techniques (T1059 PowerShell → PowerShellHistory, T1547 Persistence → Registry Run keys, etc.).

17 Conclusion

KAPE est devenu l'outil pivot du triage Windows en intervention sur incident. Sa capacité à collecter et parser en quelques minutes ce qui prenait des heures manuellement transforme le métier de l'analyste DFIR : on peut désormais traiter dix postes là où on n'en traitait qu'un.

La courbe d'apprentissage est rapide (1-2 jours pour être opérationnel) mais la maîtrise approfondie (Targets custom, Modules custom, intégration Velociraptor/Sentinel) demande quelques semaines de pratique.

Recommandations finales :

  1. Préparer ta clé USB KAPE avec Get-KAPEUpdate.ps1 exécuté avant chaque mission.
  2. Maîtriser les Targets composites !SANS_Triage et !BasicCollection avant de créer du custom.
  3. Apprendre les EZ Tools en parallèle pour creuser un cas hors workflow KAPE.
  4. Tester sur VM compromise avant déploiement réel.

Bons triages ! 🥋
