🔭 GHunt moyen — Phone OSINT, Drive enumeration, scripting

À la fin de ce tutoriel, tu sauras exploiter les fonctions avancées de GHunt : Phone OSINT (avec ses limites Google), énumération Drive partages publics, YouTube channel deep-dive, Maps reviews pour géolocalisation indirecte, download automatisé photo, reverse image search (Yandex), scripting Python sur l'API GHunt, orchestration multi-outils et rotation de comptes burner avec gestion du rate limit.
🎯 Niveau intermédiaire ⏱ ~60 min 🔭 Phone OSINT + Drive 🐍 Scripting Python 🔄 Rotation burners ⚠️ Sensibilité légale max
⚠️ Prérequis : GHunt débutant (v130) — discipline opérationnelle renforcée
Niveau intermédiaire : tu maîtrises GHunt de base. Place aux techniques avancées sur des données très personnelles (Phone OSINT, Drive partages, Maps géolocalisation). Discipline obligatoire : VM OSINT isolée, VPN dédié, 3+ comptes burner en rotation, limite 10-20 requêtes/jour/burner, stockage chiffré, archivage Wayback Machine immédiat, hashs systématiques. Cadre légal documenté avant chaque enquête.

02 Architecture interne GHunt

Comprendre l'architecture aide à scripter et déboguer.

shell
┌────────────────────────────────────┐
│         CLI ghunt                  │
├────────────────────────────────────┤
│   Modules : email, gaia, phone,    │
│   drive, youtube                   │
├────────────────────────────────────┤
│   API GHunt (asyncio + httpx)      │
├────────────────────────────────────┤
│   Cookies session Google           │
│  (SID, HSID, SSID, APISID, ...)    │
├────────────────────────────────────┤
│   Endpoints internes Google :       │
│   - PeopleAPI (profil, identité)   │
│   - Maps API (reviews, photos)     │
│   - Drive API (partages publics)   │
│   - YouTube Data API               │
│   - Calendar API                   │
└────────────────────────────────────┘

Points clés

  • Asyncio : GHunt est asynchrone → rapide (plusieurs requêtes parallèles)
  • httpx : remplace requests, gère HTTP/2 et reuse de connexions
  • Cookies session : sauvegardés dans ~/.ghunt/
  • Pas d'API officielle : Google peut casser à tout moment

03 Recherche par numéro de téléphone

GHunt peut chercher par numéro de téléphone, mais avec limites majeures.

Comment ça marche

Google associe parfois un numéro à un compte (notamment via le composant "Google Account Recovery" ou "Phone-based login"). GHunt cherche cette association.

Syntaxe

bash
ghunt phone "+41 79 123 45 67"

Format international avec + obligatoire.

Ce que GHunt peut retourner (si disponible)

  • Nom partiel : "Jn D" (Google masque)
  • Photo de profil (parfois)
  • Confirmation : compte Google existe avec ce numéro

Ce que GHunt ne peut pas retourner

  • Email complet
  • Nom complet
  • Localisation
  • Activité

Google masque délibérément ces informations dans les retours phone, pour limiter le stalking.

⚠️ Attention
️ Cadre légal renforcé : utiliser GHunt phone pour identifier une personne par son numéro = traitement de données très sensible. Mandat indispensable.

04 Limites Phone OSINT

❌ Beaucoup de numéros ne sont pas associés à un compte Google trouvable.

❌ Information très limitée : nom masqué.

❌ Google peut bloquer la fonction sans préavis.

❌ Sensibilité légale max : associer un numéro à une identité = traitement très réglementé.

Alternative : PhoneInfoga

PhoneInfoga (cf. tutoriel PhoneInfoga v130) est complémentaire :

  • Vérifie le format du numéro (carrier, country)
  • Cherche dans les fuites de données publiques
  • Cherche sur réseaux sociaux (Telegram, WhatsApp)
  • Plus efficace que GHunt phone pour la plupart des cas

Workflow :

  1. PhoneInfoga : info de base (carrier, region, présence WhatsApp/Telegram)
  2. GHunt phone : si compte Google associé (rare)
  3. HIBP : si le numéro apparaît dans des fuites

05 Drive enumeration — partages publics

GHunt peut énumérer les partages Google Drive publics d'un compte.

Comportement

Quand quelqu'un partage un fichier ou dossier Google Drive en mode "Anyone with the link can view", ce partage devient accessible via une URL publique. GHunt cherche ces partages associés au compte.

Syntaxe

Selon version GHunt :

bash
ghunt drive --email john@gmail.com

ou intégré dans la commande email :

bash
ghunt email john@gmail.com --drive

Ce qui peut être trouvé

  • Documents partagés : Word, Sheets, Slides en partage public
  • Photos partagées : albums Google Photos publics
  • Vidéos : si stockées Drive et partagées

Cas DFIR concret

Cible : suspect lance un projet personnel. Souvent, il partage par mégarde des documents Drive en public :

  • Liste de mots de passe (terriblement fréquent)
  • Brouillons de communications
  • Notes personnelles
  • Photos privées

GHunt révèle ces fuites accidentelles.

Précautions

⚠️ Si tu trouves des documents Drive privés exposés par erreur : ne pas télécharger sans cadre légal. Documenter la trouvaille, signaler à l'autorité compétente, archiver l'URL pour preuve.

06 YouTube channel deep-dive

Si la cible a une chaîne YouTube associée à son compte Google :

Information disponible

  • Nom de la chaîne
  • Nombre d'abonnés
  • Date de création
  • Liens vidéos publiques
  • Description et liens externes (souvent vers Twitter, Twitch, etc.)

Analyse vidéo

Une fois la chaîne identifiée :

bash
# yt-dlp pour télécharger métadonnées (légal)
yt-dlp --skip-download --write-info-json --write-thumbnail \
    "https://www.youtube.com/channel/UCxxx"

Tu obtiens un JSON par vidéo avec : titre, description, date, tags, vues, commentaires.

Pivots

  • Vidéo de vacances → géolocalisation indirecte
  • Voix dans les vidéos → identification audio
  • Personnes apparaissant → relations sociales
  • Liens dans descriptions → réseaux liés

07 Maps reviews — géolocalisation indirecte

Les reviews Google Maps publiques sont une mine d'or DFIR.

Extraction enrichie

bash
ghunt email john@gmail.com --json - | jq '.maps.reviews[]'

Pour chaque review : lieu, date, note, texte du commentaire.

Analyse géographique

Concentration des reviews → zone de vie probable de la cible.

Workflow Python :

python
import json
import folium
from collections import Counter

with open('ghunt_results.json') as f:
    data = json.load(f)

reviews = data.get('maps', {}).get('reviews', [])

# Lieux et fréquences
places = Counter()
for r in reviews:
    places[r['place']] += 1

# Si géo dispo (lat/lng) — carte Folium
m = folium.Map(location=[46.0, 6.0], zoom_start=10)
for review in reviews:
    if 'lat' in review and 'lng' in review:
        folium.Marker(
            location=[review['lat'], review['lng']],
            popup=review['place']
        ).add_to(m)
m.save('cible_carte.html')

Tu obtiens une carte interactive des lieux fréquentés.

Photo en review

Si la cible a posté des photos dans ses reviews :

  • Métadonnées EXIF parfois préservées (date, GPS exact)
  • Visages → reconnaissance (à éviter sans cadre légal)
  • Plaques d'immatriculation, intérieurs → données très personnelles

⚠️ Analyse photo = traitement de données sensibles. Cadre légal strict.

08 Download automatisé photo et avatar

Pour archiver les photos de profil :

bash
# Récupérer l'URL de la photo via GHunt JSON
PHOTO_URL=$(ghunt email john@gmail.com --json - | jq -r '.profile_picture_url')

# Télécharger avec curl
curl -s "$PHOTO_URL" -o "john_profile.jpg"

# Hash pour preuve
sha256sum john_profile.jpg >> manifest.txt

Batch sur plusieurs emails

bash
#!/bin/bash
# Pour une liste d'emails

while read email; do
    safe_name="${email//@/_at_}"
    ghunt email "$email" --json "results/${safe_name}.json"

    photo_url=$(jq -r '.profile_picture_url // empty' "results/${safe_name}.json")
    if [ -n "$photo_url" ]; then
        curl -s "$photo_url" -o "photos/${safe_name}.jpg"
    fi

    sleep 10   # Rate limit
done < emails.txt

# Manifest
sha256sum photos/*.jpg > photos/MANIFEST.txt

⚠️ Stocker les photos téléchargées chiffrées (VeraCrypt, LUKS) — données personnelles.

09 Reverse image search depuis photo GHunt

Une fois la photo de profil obtenue : reverse image search trouve d'autres comptes avec la même photo.

Sites de reverse image search

  • TinEye : <https://tineye.com/> (gratuit, scientifique)
  • Yandex Images : <https://yandex.com/images/> (le plus puissant, surtout sur visages)
  • Google Images : <https://images.google.com/> (upload bouton appareil photo)
  • Bing Visual Search : <https://www.bing.com/visualsearch>
  • PimEyes : <https://pimeyes.com/> (commercial, reconnaissance faciale — sensibilité élevée)

Workflow

  1. Télécharger la photo GHunt
  2. Aller sur Yandex (souvent le meilleur)
  3. Upload
  4. Yandex retourne des sites où la photo apparaît
  5. Beaucoup de découvertes : LinkedIn, Twitter, blogs, articles

Discipline

⚠️ Reverse image search est puissant et intrusif. À utiliser dans cadre légal strict. Yandex peut révéler des sites où la cible apparaît dans des contextes très privés.

10 Scripting Python avec l'API GHunt

GHunt expose une API Python utilisable directement.

Exemple : recherche scriptée

python
#!/usr/bin/env python3
"""Recherche GHunt scriptée"""

import asyncio
import json
from ghunt.modules.email import hunt_email
from ghunt.helpers.auth import load_authentication

async def main(email):
    creds = load_authentication()
    if not creds:
        print("Erreur : non authentifié. Lance 'ghunt login' d'abord.")
        return

    result = await hunt_email(email)

    return result

if __name__ == '__main__':
    import sys
    if len(sys.argv) != 2:
        print(f"Usage: {sys.argv[0]} email@gmail.com")
        sys.exit(1)

    result = asyncio.run(main(sys.argv[1]))
    print(json.dumps(result, indent=2, default=str))
⚠️ Attention
️ L'API GHunt évolue avec les versions. Vérifier la doc avant scripting massif. Adapter les imports selon ta version.

Batch processing

python
#!/usr/bin/env python3
"""Batch GHunt sur fichier d'emails"""

import asyncio
import json
import sys
import time

from ghunt.modules.email import hunt_email

async def process_email(email, delay=10):
    """Une recherche avec délai pour éviter ban"""
    try:
        result = await hunt_email(email)
        return {'email': email, 'success': True, 'data': result}
    except Exception as e:
        return {'email': email, 'success': False, 'error': str(e)}
    finally:
        await asyncio.sleep(delay)

async def main(emails_file):
    with open(emails_file) as f:
        emails = [line.strip() for line in f if line.strip()]

    results = []
    for email in emails:
        print(f"[*] Processing {email}...")
        result = await process_email(email)
        results.append(result)

    with open('batch_results.json', 'w') as f:
        json.dump(results, f, indent=2, default=str)

    found = sum(1 for r in results if r['success'])
    print(f"\n[+] {found}/{len(results)} successful")

if __name__ == '__main__':
    asyncio.run(main(sys.argv[1]))
⚠️ Attention
️ Limiter le batch à 10-20 emails par session pour éviter détection. Rotation des comptes burner.

11 Workflow orchestré multi-outils

Script Bash combinant GHunt + Sherlock + Maigret + Holehe + HIBP :

bash
#!/bin/bash
# osint_email.sh — workflow OSINT complet à partir d'un email

set -euo pipefail

if [ $# -lt 1 ]; then
    echo "Usage: $0 <email>"
    exit 1
fi

EMAIL="$1"
SAFE="${EMAIL//@/_at_}"
DIR="case_${SAFE}_$(date +%Y%m%d_%H%M%S)"
mkdir -p "$DIR/photos"
cd "$DIR"

log() { echo "[$(date +%H:%M:%S)] $*"; }

log "=== Investigation OSINT pour $EMAIL ==="

# 1. GHunt
log "[1/5] GHunt..."
ghunt email "$EMAIL" --json ghunt.json 2>ghunt.log || true
NAME=$(jq -r '.name // empty' ghunt.json 2>/dev/null)
PHOTO=$(jq -r '.profile_picture_url // empty' ghunt.json 2>/dev/null)

if [ -n "$NAME" ]; then
    log "  → Nom identifié : $NAME"
fi
if [ -n "$PHOTO" ]; then
    log "  → Téléchargement photo de profil..."
    curl -s "$PHOTO" -o "photos/${SAFE}.jpg"
fi

# 2. Holehe
log "[2/5] Holehe..."
holehe --only-used --no-color "$EMAIL" > holehe.txt 2>&1 || true

# 3. Have I Been Pwned (si clé API)
if [ -n "${HIBP_API_KEY:-}" ]; then
    log "[3/5] Have I Been Pwned..."
    curl -s -H "hibp-api-key: $HIBP_API_KEY" \
        -H "user-agent: OSINT-Investigation" \
        "https://haveibeenpwned.com/api/v3/breachedaccount/$EMAIL" \
        > hibp.json 2>&1 || true
else
    log "[3/5] HIBP skipped (no API key)"
fi

# 4. Dérivation usernames si nom récupéré
if [ -n "$NAME" ]; then
    log "[4/5] Sherlock sur usernames dérivés..."
    LOCAL="${EMAIL%@*}"
    USERS=("$LOCAL" "${NAME// /}" "${NAME// /.}" "${NAME// /_}")

    for u in "${USERS[@]}"; do
        u_lower=$(echo "$u" | tr '[:upper:]' '[:lower:]')
        sherlock --print-found --no-color "$u_lower" \
            --folderoutput "sherlock_${u_lower}/" 2>/dev/null || true
        sleep 5
    done
fi

# 5. Maigret sur email
log "[5/5] Maigret..."
maigret "$EMAIL" --html --folderoutput maigret/ 2>maigret.log || true

# Manifest
log "Calcul des hashs..."
find . -type f \( -name "*.json" -o -name "*.html" -o -name "*.txt" -o -name "*.jpg" \) \
    -exec sha256sum {} \; > MANIFEST_SHA256.txt

# Synthèse
log "Génération synthèse..."
cat > rapport_synthese.md <<EOF
# Investigation OSINT — $EMAIL

**Date :** $(date -Iseconds)
**Autorité :** [À compléter — mandat / autorisation]
**Analyste :** [À compléter]

12 Pivoter avec Gaia ID entre comptes

Le Gaia ID est l'identifiant Google permanent. Permet de pivoter même si l'email change.

Cas : retrouver un compte après changement d'email

Si tu as un vieil email d'un suspect et que tu connais son Gaia ID :

bash
# Avec l'email connu (peut être obsolète)
ghunt email vieux_email@gmail.com --json - | jq '.gaia_id'
# 1234567890123456789

# Avec ce Gaia ID, retrouver le compte actuel
ghunt gaia 1234567890123456789

Si le suspect a changé d'email mais gardé son compte → tu retrouves le nouveau profil via Gaia ID.

Linkage Gaia ID entre services

Le même Gaia ID est utilisé par tous les services Google (Drive, YouTube, Maps, Photos, Workspace). Indispensable pour corroborer : un même Gaia ID dans plusieurs sources = même personne.

13 Détection et contournement des limites

Google détecte les usages anormaux de ses API internes. Symptômes :

  • Erreur 403 Forbidden sur les requêtes
  • Compte burner suspendu
  • Message "Unusual activity detected"

Mitigations

bash
# Max 10 requêtes par heure par compte
sleep 360   # 6 minutes entre chaque requête

Utiliser plusieurs IPs sortantes via VPN avec rotation :

bash
# Avant chaque requête : reconnect VPN
mullvad disconnect && sleep 5 && mullvad connect
# ou
nordvpn disconnect && sleep 3 && nordvpn connect
ghunt email "$EMAIL"

Si tu fais 50+ recherches dans la journée :

  • Compte A pour matin
  • Compte B pour après-midi
  • Compte C en réserve

GHunt rotate déjà les User-Agents. Vérifier dans les logs si toujours valide pour ta version.

  • Tor : très lent et beaucoup d'IPs sont blacklistées par Google
  • Résidentiel proxies : commercial, coûteux
💡 Astuce
ne faire jamais plus de 10-20 recherches GHunt par jour par compte burner. Au-delà : risque ban élevé.

14 Gestion de plusieurs comptes burner

Pour un usage soutenu, plusieurs comptes burner.

Création

  1. Créer 3-5 comptes Google burner différents
  2. Chacun avec :
  • Email burner (ProtonMail, Tutanota)
  • Pas de téléphone (ou téléphone temporaire)
  • Pas de récup email perso
  1. Stocker les credentials chiffrés (KeePass, Bitwarden)

Switch entre comptes

GHunt sauvegarde les cookies dans ~/.ghunt/. Pour switcher :

bash
# Sauvegarder la config actuelle (burner A)
cp -r ~/.ghunt/ ~/.ghunt-burnerA/

# Charger config burner B
rm -rf ~/.ghunt/
cp -r ~/.ghunt-burnerB/ ~/.ghunt/

Ou script wrapper :

bash
#!/bin/bash
# ghunt-with-burner.sh BURNER_NAME COMMAND...

BURNER="$1"
shift

cp -r ~/.ghunt-burner${BURNER}/ ~/.ghunt/
ghunt "$@"

Rotation automatisée

bash
#!/bin/bash
# Round-robin entre 3 burners

BURNERS=("A" "B" "C")
COUNT_FILE="$HOME/.ghunt-counter"

counter=$(cat "$COUNT_FILE" 2>/dev/null || echo 0)
burner=${BURNERS[$((counter % ${#BURNERS[@]}))]}
echo $((counter + 1)) > "$COUNT_FILE"

./ghunt-with-burner.sh "$burner" "$@"

16 Cas pratique : retracer un compte Gmail anonyme

Scénario : journaliste reçoit des emails anonymes depuis whistleblower2026@gmail.com avec des accusations contre une entreprise.

⚠️ Cadre éthique délicat : whistleblower peut être protégé. Cette enquête doit avoir un cadre légal documenté (poursuite pour diffamation, par exemple).

Étape 1 — GHunt sur l'email

bash
ghunt email whistleblower2026@gmail.com --json wb.json

Probablement compte créé récemment, peu d'info publique. Mais on récupère :

  • Gaia ID : 1234567890
  • Date de création approximative
  • Photo de profil (peut-être anonyme/par défaut)

Étape 2 — Reviews Maps

Souvent rien sur compte burner — bonne hygiène opérationnelle.

Étape 3 — Drive partages

Le whistleblower a peut-être partagé des documents Drive — c'est souvent comme ça qu'il fait fuiter des éléments. GHunt peut révéler ces partages.

Étape 4 — YouTube channel

Rare sur un burner mais à vérifier.

Étape 5 — Holehe sur l'email

Tester si l'email est associé à d'autres services. Souvent non sur un vrai burner. Si oui (par erreur) → pivot.

Étape 6 — Have I Been Pwned

Email récent → probablement aucune fuite.

Étape 7 — Recherche manuelle de l'email

  • Twitter / X : recherche d'occurrences
  • GitHub : si l'email apparaît dans un commit
  • Pastebin : recherche directe
  • Recherche Google : "whistleblower2026@gmail.com"

Étape 8 — Analyse des messages reçus

  • Headers email : IP source, MTA, langue (cf. tutos forensique mail)
  • Contenu : style d'écriture, fautes typiques, expressions caractéristiques
  • Pièces jointes : EXIF, métadonnées Office (auteur, organisation)

Étape 9 — Corroboration

Si GHunt + recherches manuelles donnent peu de résultats : c'est un bon burner. Identification quasi impossible sans accès aux logs Google ou demande judiciaire à Google.

⚠️ Demande judiciaire à Google : possible mais réservée aux autorités, avec mandat.

17 Intégration avec Spiderfoot, Recon-ng, Maltego

Spiderfoot

<https://www.spiderfoot.net/>

Plateforme OSINT auto-hébergeable avec 200+ modules. Inclut un module GHunt qui automatise l'enrichissement.

bash
docker run -p 5001:5001 -v $(pwd)/data:/data binarypool/spiderfoot:latest

Puis configurer le module GHunt avec tes cookies.

Recon-ng

Framework type Metasploit pour OSINT. Modules custom possibles intégrant GHunt.

Maltego

Visualisation graphique de liens OSINT. Transforms custom pour GHunt (via API GHunt en script Python).

Workflow :

  1. Maltego avec nœud "Email"
  2. Right-click → Run transform → GHunt
  3. Nouveau nœud "Person" avec attributs (nom, photo, Gaia ID)
  4. Continuer le graphe avec autres OSINT

18 Bonnes pratiques renforcées

🔹 Comptes burner multiples : 3-5 en rotation, jamais le perso.

🔹 VM OSINT isolée : Tails, Whonix, ou VM custom.

🔹 VPN OSINT dédié : Mullvad, ProtonVPN, rotation IP.

🔹 Limite stricte : 10-20 requêtes/jour/burner. Au-delà : ban risqué.

🔹 Rotation automatique entre burners pour les batchs.

🔹 Documenter chaque enquête : autorité, finalité, burner utilisé, IP.

🔹 Hash systématique des rapports.

🔹 Archivage immédiat des éléments (Wayback Machine + screenshots).

🔹 Corroboration : 3+ sources avant conclure.

🔹 Mise à jour fréquente : GHunt évolue rapidement avec Google.

🔹 Backup des cookies : tes burners sont précieux, sauvegarder leurs cookies.

🔹 Stockage chiffré : noms, photos, Gaia IDs = données très personnelles.

🔹 Durée de conservation limitée : effacer selon délai légal.

🔹 Pas de pivotement perso : le compte burner ne doit pas pouvoir te remonter.

🔹 Tester sur soi-même : faire GHunt sur ton propre email Google personnel pour comprendre ce qui est exposé.

🔹 Lire les TOS Google : zone grise, conscience des risques.

🔹 Respecter le cadre légal national : nLPD Suisse, RGPD EU, etc.

19 Forces, faiblesses et limites

Forces

✅ Phone OSINT unique (même avec limites).

✅ Drive enumeration : trouvailles précieuses (fuites accidentelles).

✅ YouTube deep-dive : nombreux pivots possibles.

✅ API scriptable : intégration dans workflows automatisés.

✅ JSON export clean : exploitable en Python.

✅ Maintenu activement par mxrch.

✅ Complémentaire avec Sherlock + Maigret + Holehe + PhoneInfoga.

Faiblesses

❌ Phone OSINT très limité par les masques Google.

❌ Dépendance Google : peut tout casser.

❌ Détection : usage massif → ban.

❌ Setup complexe : burners, VPN, isolation.

❌ Zone grise TOS : risque légal théorique pour usage massif.

❌ Pas de bypass : si cible verrouille tout, peu de résultats.

❌ Faux négatifs : un compte existant peut paraître absent si fortement restreint.

❌ Documentation parfois en retard sur le code (mxrch évolue vite).

❌ Sensibilité légale : un des outils OSINT les plus sensibles.
