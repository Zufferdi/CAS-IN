✉️ Holehe — OSINT email (services associés)

À la fin de ce tutoriel, tu sauras utiliser Holehe pour identifier sur quels 120+ sites un email est enregistré (Twitter, GitHub, Adobe, Spotify, Pinterest, Snapchat, etc.), comprendre le mécanisme (test « mot de passe oublié » automatisé), évaluer le risque de notification cible, exporter en JSON pour intégration, combiner Holehe avec Sherlock + Maigret (v128) et Have I Been Pwned pour un workflow OSINT email complet.
🎯 Niveau intermédiaire ⏱ ~40 min 🐧 Linux / macOS 🪟 Windows ✉️ OSINT par email ⚖️ Notification cible possible
⚠️ Holehe peut notifier la cible
Contrairement à Sherlock/Maigret qui consultent juste les pages publiques, Holehe interagit avec l'API des sites (« mot de passe oublié »). Certains sites envoient un email de notification à la cible lors de cette requête. Avant chaque utilisation sur cible sensible : évaluer ce risque, et préférer Sherlock pour la discrétion absolue. Cadre légal : nLPD (Suisse), RGPD, art. 173-179 CP. Strictement interdit pour préparer du phishing.

01 Présentation générale

Holehe est un script Python très simple en surface, très astucieux en profondeur :

  1. Tu lui donnes une adresse email.
  2. Pour chaque site supporté (~120), Holehe simule l'action « mot de passe oublié » ou « créer un compte ».
  3. Le site répond différemment selon que l'email existe ou non dans sa base.
  4. Holehe parse la réponse et te dit pour chaque site : [+] existe, [-] n'existe pas, [?] indéterminé.

Particularités :

  • 120+ sites supportés : Twitter, Adobe, Amazon, GitHub, GitLab, Imgur, Instagram, LinkedIn, Pinterest, Spotify, Snapchat, etc.
  • Pas de récupération de données : juste un binaire « existe / n'existe pas »
  • Asynchrone (asyncio) : très rapide, ~30 secondes pour 120 sites
  • Open source GPLv3
  • Léger : un fichier Python, dépendances minimes

02 Cadre légal et éthique

Holehe est moins sensible que Sherlock/Maigret car il ne récupère aucune donnée (juste un booléen), mais le cadre légal s'applique.

Ce qui est autorisé

  • Investigation par mandat (police, MP)
  • Audit interne sur emails de son organisation (RH, SOC)
  • Recherche personnelle sur son propre email (audit de surface)
  • Vérification d'identité dans cadre journalistique légitime
  • Anti-fraude pour valider l'existence d'un email avant transaction

Ce qui est interdit ou réglementé

  • Énumération massive d'emails pour préparer du phishing ciblé : STRICTEMENT INTERDIT (CP, RGPD).
  • Stalking d'une personne : violation art. 179 quater CP (harcèlement obsessionnel).
  • Vente de données : énumérer des emails et vendre les comptes associés = atteinte sphère privée.
  • Sans cadre légal explicite pour autrui : éthiquement problématique même si techniquement faisable.

Particularité Holehe : le risque de notification

⚠️ Certains sites notifient l'utilisateur quand on lance un « mot de passe oublié ». Lors de tests Holehe, la cible peut recevoir un email « Tentative de réinitialisation de votre mot de passe ».

Ce comportement varie selon les sites (et selon les versions de Holehe — voir option --no-clear). À considérer :

  • Si tu veux rester discret : tester d'abord Holehe sur tes propres comptes pour voir quels sites notifient.
  • Pour les enquêtes discrètes, préférer Sherlock (qui consulte juste les pages publiques, sans déclencher d'action).
🚨 Critique
Holehe doit s'utiliser dans un cadre légal documenté. Pas de curiosité, pas de stalking.

03 Comment fonctionne Holehe

Imagine que tu vas sur Twitter, page « mot de passe oublié », et tu tapes un email. Twitter répond différemment selon que l'email existe :

  • Email existe : « Un email a été envoyé »
  • Email inconnu : « Cet email n'est pas associé à un compte »

Holehe automatise cette interaction pour 120+ sites simultanément.

Méthode pour chaque site

Le repo de Holehe contient un module Python par site. Chaque module :

  1. Identifie l'URL de l'endpoint (souvent l'API du formulaire « forgot password »).
  2. Envoie une requête POST avec l'email.
  3. Parse la réponse selon les signatures connues de chaque site.
  4. Retourne True (existe), False (n'existe pas) ou None (indéterminé).

C'est un travail communautaire continu : les sites changent leurs APIs → les modules Holehe doivent suivre.

04 Holehe vs Sherlock vs Maigret

Les trois outils sont complémentaires : différents IoCs, différentes informations retournées.

OutilInputOutputCouverture
SherlockusernameURL profil400+ sites
Maigretusername, email, téléphone, nomURL + métadonnées3000+ sites
Holeheemailexiste / n'existe pas120+ sites

Différences clés

  • Sherlock / Maigret : cherchent un username sur la page publique. Non intrusif. Mais limité aux sites avec profils publics.
  • Holehe : interagit avec l'API du site (souvent « forgot password »). Peut notifier la cible. Mais fonctionne sur les sites sans profil public (services privés, paiement, dating).

Combiner

Workflow OSINT email → username typique :

  1. Holehe sur l'email → liste de sites où l'email existe.
  2. Pour chaque site trouvé, Sherlock / Maigret sur les usernames potentiels (souvent dérivés de l'email : john.doe@example.com → johndoe, j.doe, etc.).
  3. Croisement manuel des résultats.

05 Cas d'usage DFIR typiques

  • Enquête pénale : suspect identifié par email → quels services utilisait-il ?
  • Fraude : vérifier la crédibilité d'un email reçu (existe-t-il vraiment ?)
  • Audit interne : surface d'attaque des emails d'une entreprise (audit RH ou cybersécurité)
  • Investigation cyberharcèlement : identifier les comptes du harceleur si email connu
  • Anti-phishing : valider qu'un email expéditeur n'est pas une usurpation (paradoxe : si l'email n'existe nulle part, peut-être suspect)
  • Recrutement vérifié (avec accord) : présence professionnelle du candidat
  • Threat intelligence : tracer un membre d'un groupe APT/cybercriminel par email leaké
  • Due diligence M&A : vérifier la présence en ligne d'un dirigeant cible

10 Options et personnalisation

Filtrer les résultats

bash
# Afficher uniquement les sites où l'email existe
holehe email@example.com --only-used

# Pas de couleurs (utile pour scripts)
holehe email@example.com --no-color

Sites notifiant la cible

bash
# Exclure les sites qui peuvent envoyer une notification à la cible
holehe email@example.com --no-clear

Cette option (selon version) limite Holehe aux modules silencieux (pas de notification de réinitialisation envoyée à la cible).

Timeout

bash
# Timeout par site (en secondes)
holehe email@example.com --timeout 10

Lister les modules

bash
holehe --list-modules

11 Comprendre les résultats

[+] — Existe

L'email est enregistré sur ce site. C'est l'information la plus utile : tu sais que la cible (ou quelqu'un avec cet email) a un compte là.

Précautions :

  • Un faux positif est possible si le module Holehe a un bug ou si le site a changé son API.
  • Tester plusieurs fois pour confirmer si crucial.

[-] — N'existe pas

L'email n'est pas enregistré. Information utile aussi (élimine des hypothèses).

[?] — Indéterminé

Le site a renvoyé une réponse que Holehe ne sait pas interpréter. Causes courantes :

  • Captcha déclenché
  • Rate limit atteint
  • Site bloque Tor (si tu passes par Tor)
  • API du site changée → module Holehe obsolète
💡 Astuce
un [?] n'est pas une non-information. C'est un appel à investigation manuelle sur ce site.

Erreur ou crash

Si un module crash : signaler une issue GitHub à megadose. La communauté est réactive.

12 Format JSON et automatisation

Holehe n'a pas d'option --json directe, mais on peut utiliser la bibliothèque Python pour une sortie structurée.

Script Python wrapper

python
#!/usr/bin/env python3
"""holehe_json.py — wrapper JSON pour Holehe"""

import sys
import json
import asyncio
import httpx
from holehe.modules import * 
from holehe.core import get_functions

async def check_email(email):
    websites = get_functions()
    out = []

    async with httpx.AsyncClient() as client:
        tasks = [w(email, client, out) for w in websites]
        await asyncio.gather(*tasks, return_exceptions=True)

    return out

if __name__ == '__main__':
    if len(sys.argv) != 2:
        print(f"Usage: {sys.argv[0]} email@example.com")
        sys.exit(1)

    results = asyncio.run(check_email(sys.argv[1]))
    print(json.dumps(results, indent=2))

Usage :

bash
python3 holehe_json.py johndoe@gmail.com > results.json
jq '.[] | select(.exists == true) | .name' results.json

Format de sortie

Chaque résultat est un objet :

json
{
  "name": "github",
  "domain": "github.com",
  "method": "register",
  "frequent_rate_limit": false,
  "rateLimit": false,
  "exists": true,
  "emailrecovery": null,
  "phoneNumber": null,
  "others": null
}

exists: true / false / null est la donnée clé.

13 Recherche multi-email

Boucle bash

bash
# emails.txt : un email par ligne
while read email; do
    echo "=== $email ==="
    holehe --only-used --no-color "$email"
    sleep 5
done < emails.txt

Avec GNU parallel (cf. tuto CLI expert v128)

bash
cat emails.txt | parallel -j 4 'holehe --only-used --no-color {}'

⚠️ Attention au rate limit : trop d'emails en parallèle = certains sites bannissent ton IP temporairement. Préférer 2-4 jobs simultanés max.

14 Limitations de Holehe

❌ APIs qui changent : un site qui modifie son API casse le module Holehe. Mise à jour communautaire mais peut prendre des semaines.

❌ Captchas : certains sites (Cloudflare, hCaptcha) bloquent les requêtes scriptées. Résultats [?] fréquents.

❌ Rate limit : tester 100 emails en boucle = bans temporaires.

❌ Pas de récupération de métadonnées : juste « existe / pas ».

❌ Notifications cible : certains sites alertent la cible (cf. §16).

❌ Sites majeurs : Google, Microsoft, Apple ne sont pas dans Holehe — leurs APIs ne révèlent rien.

❌ Sites privés / B2B : pas couverts (LinkedIn limité, Salesforce, ...).

❌ Faux positifs / négatifs : possibles selon les versions et changements d'API.

❌ Dépendant de la maintenance : actif mais pas garanti à long terme.

15 Workflow OSINT complet (Holehe + Sherlock + Maigret)

Mise en pratique : enquête à partir d'un email seul.

Setup

bash
EMAIL="suspect@example.com"
mkdir -p "case_${EMAIL//@/_at_}"
cd "case_${EMAIL//@/_at_}"

source ~/osint/venv/bin/activate

Étape 1 — Holehe sur l'email

bash
holehe --only-used --no-color "$EMAIL" > holehe_results.txt
cat holehe_results.txt

→ Liste de sites où l'email existe. Ex : GitHub, Spotify, Pinterest, Adobe.

Étape 2 — Have I Been Pwned

bash
# Manuel : https://haveibeenpwned.com/account/EMAIL
# Ou API (clé requise) :
curl -H "hibp-api-key: $HIBP_KEY" \
    "https://haveibeenpwned.com/api/v3/breachedaccount/$EMAIL"

→ Fuites de données où l'email est apparu.

Étape 3 — Dériver les usernames probables

À partir de john.doe@example.com :

bash
USERS="johndoe john.doe j.doe j_doe jdoe doejohn"
echo $USERS

Étape 4 — Sherlock sur les usernames

bash
for user in $USERS; do
    sherlock --print-found --no-color "$user" --folderoutput sherlock_results/
done

Étape 5 — Maigret sur l'email + usernames trouvés

bash
maigret "$EMAIL" --html --folderoutput maigret_email/
for user in $USERS; do
    maigret "$user" --html --folderoutput "maigret_$user/"
done

Étape 6 — Croiser et corroborer

Pour chaque site identifié par 2+ outils (Holehe et Sherlock/Maigret) : forte probabilité que ce soit la même personne.

Vérification manuelle :

  • Photo de profil cohérente sur 2+ sites
  • Bio, intérêts, dates cohérents
  • Liens entre profils

Étape 7 — Archivage

bash
# Wayback Machine pour chaque profil trouvé
while read url; do
    curl -s "https://web.archive.org/save/$url" > /dev/null
    sleep 3
done < urls_trouves.txt

Étape 8 — Rapport synthèse

bash
sha256sum *.txt *.html > MANIFEST_SHA256.txt

cat > rapport_synthese.md <<EOF

**Autorité :** [mandat / autorisation]
**Analyste :** [nom]

16 Risques de détection et discrétion

Les sites qui notifient

Quand Holehe lance une requête « mot de passe oublié », certains sites envoient un email à la cible :

ℹ️ Note
« Tentative de réinitialisation de votre mot de passe. Si vous n'êtes pas à l'origine de cette demande, ignorez ce message. »

La cible peut alors être alertée qu'elle fait l'objet d'une enquête.

Lister les modules non-notifiants

L'option --no-clear (selon version) limite à des modules non intrusifs. Vérifier la doc à jour.

Alternative : test sur toi d'abord

Avant d'utiliser Holehe sur une cible sensible :

  1. Créer un email témoin chez toi.
  2. Le « inscrire » sur quelques sites.
  3. Lancer Holehe dessus.
  4. Vérifier quels sites t'envoient une notification.

Tu sais ainsi lesquels exclure pour rester discret.

Tor / VPN

Comme Sherlock/Maigret, utiliser Tor ou VPN OSINT dédié :

  • Évite que ton IP apparaisse dans les logs des sites cibles
  • Mais n'empêche pas les notifications email à la cible — c'est l'email qui déclenche la notification, pas l'IP

Préférer Sherlock pour la discrétion absolue

Sherlock ne fait que consulter les pages publiques — pas d'interaction, pas de notification. C'est moins intrusif que Holehe.

Workflow discret :

  1. Sherlock + Maigret d'abord (silencieux)
  2. Holehe uniquement si nécessaire (et après évaluation du risque de notification)

17 Forces et faiblesses

Forces

✅ Approche unique : OSINT par email, là où Sherlock/Maigret font par username.

✅ 120+ sites couverts : large surface.

✅ Rapide : ~30 secondes pour 120 sites en asyncio.

✅ Léger : un script Python, peu de dépendances.

✅ Open source GPLv3 : auditable.

✅ Bibliothèque Python utilisable : intégration dans des workflows custom.

✅ Communauté active : megadose maintient activement.

✅ Complémentaire de Sherlock + Maigret.

Faiblesses

❌ Risque de notification cible : certains sites alertent.

❌ Captchas / Cloudflare : faux négatifs ou [?].

❌ APIs qui changent : modules obsolètes possibles.

❌ Pas de récupération de données : juste « existe ».

❌ Pas Google / Microsoft / Apple : leurs APIs ne révèlent rien.

❌ Rate limit sur recherches massives.

❌ Pas d'export structuré natif : il faut wrapper en Python pour JSON.

❌ Dépendance Python 3 et virtualenv : peut être pénible pour utilisateur non-tech.

❌ Aspect dual-use : peut servir au phishing si mauvaise intention.

18 Bonnes pratiques OSINT email

🔹 Toujours utiliser un VPN OSINT ou Tor pour les enquêtes sensibles.

🔹 Environnement isolé : VM dédiée OSINT, pas tes comptes perso.

🔹 Documenter chaque enquête : autorité, finalité, période, outils, versions.

🔹 Hasher les rapports dès production (chaîne de preuve).

🔹 Évaluer le risque de notification avant chaque utilisation sur cible sensible.

🔹 Combiner avec Sherlock + Maigret : Holehe par email, Sherlock/Maigret par username.

🔹 Croiser avec Have I Been Pwned : si l'email est dans une fuite, l'info de Holehe est confirmée.

🔹 Dériver les usernames probables depuis l'email pour relancer Sherlock/Maigret.

🔹 Mettre à jour Holehe régulièrement : pip install --upgrade holehe.

🔹 Stocker les rapports chiffrés : VeraCrypt, BitLocker, LUKS.

🔹 Durée de conservation limitée : effacer enquêtes closes après délai légal.

🔹 Respecter la sphère privée : info publique ≠ exploitable sans cadre.

🔹 Ne pas faire de phishing : trouver qu'un email existe sur Spotify ≠ envoyer un faux email Spotify à la cible.

🔹 Tester sur soi-même d'abord pour identifier les modules notifiants.

🔹 Vérifier le statut [?] manuellement avant de conclure.

🔹 Suivre megadose sur GitHub pour les évolutions.

19 Outils complémentaires (Hunter, HIBP, Holehe Web)

Hunter.io

<https://hunter.io/>

API commerciale : trouve les emails d'une organisation, vérifie la délivrabilité.

bash
curl "https://api.hunter.io/v2/email-verifier?email=$EMAIL&api_key=$HUNTER_KEY" | jq

Plan gratuit : 25 vérifications/mois.

Have I Been Pwned (HIBP)

<https://haveibeenpwned.com/>

Service de référence pour les fuites de données. Indique si un email apparaît dans des fuites connues.

Gratuit pour consultation manuelle, payant pour API (3.50 $/mois).

bash
curl -H "hibp-api-key: $HIBP_KEY" \
    "https://haveibeenpwned.com/api/v3/breachedaccount/$EMAIL"

EmailHippo, EmailListVerify

Services de validation d'email (existe + valide DNS + boîte active). Pas exactement OSINT mais utiles en complément.

GHunt

<https://github.com/mxrch/GHunt>

OSINT spécifique Google Account : si tu as un email Google, GHunt peut extraire photo de profil, nom, organisations Google, calendriers publics. Plus puissant que Holehe pour Google.

Holehe Tracker (web)

<https://holehe.altsweb.app/> ou similaires.

Service web qui propose Holehe sans installation. Méfiance : tu transmets l'email recherché à un tiers.

Préférer l'auto-hébergement (pip install) pour la confidentialité.

25 Conclusion

Holehe complète l'arsenal OSINT par l'angle email, là où Sherlock et Maigret travaillent l'angle username. Son usage demande discipline éthique renforcée car certains sites notifient la cible — Holehe est moins discret que Sherlock.

Le trio Holehe + Sherlock + Maigret couvre quasi tout l'écosystème OSINT moderne sur les personnes. Avec un VPN OSINT dédié, un workflow d'archivage rigoureux et une documentation soignée, tu disposes d'une chaîne OSINT professionnelle complète.

Recommandations finales :

  1. Configurer ton environnement OSINT : VM dédiée + VPN + virtualenv Python avec Sherlock + Maigret + Holehe + GHunt.
  2. Évaluer le risque de notification avant chaque utilisation Holehe sur cible sensible.
  3. Croiser systématiquement Holehe + Have I Been Pwned + Sherlock + Maigret.
  4. Dériver les usernames depuis l'email pour relancer Sherlock/Maigret.
