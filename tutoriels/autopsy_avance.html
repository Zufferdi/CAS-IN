🧪 Autopsy avancé — Plugins, scripting, super-timeline

À la fin de ce tutoriel, tu sauras maîtriser le carving avancé PhotoRec, intégrer la super-timeline Plaso dans Autopsy, configurer des hash sets personnalisés (NSRL, IoCs custom, ProjectVic), créer des keyword lists avec regex, exploiter Communicating Accounts, configurer le mode multi-utilisateur (PostgreSQL + Solr), écrire des ingest modules Python (Jython 2.7), utiliser Sleuth Kit en CLI (mmls, fls, icat, mactime), et orchestrer un workflow d'enquête complet avec Volatility, Plaso, KAPE, Cellebrite.
🎯 Niveau expert ⏱ ~85 min 🧪 Plugins Python 🗄️ Multi-user PostgreSQL ⌨️ Sleuth Kit CLI 🔬 Workflow complet
ℹ️ Prérequis : Autopsy débutant + Autopsy standard
Niveau expert : tu maîtrises déjà Autopsy (cas, ingest, tags, rapports). Place aux techniques qui distinguent un utilisateur d'un architecte DFIR : carving fin, super-timeline intégrée, hash sets custom (NSRL, ProjectVic), modules Python custom, Sleuth Kit en CLI, mode multi-user en équipe.

01 Prérequis et positionnement

Prérequis :

  • Tutoriel Autopsy débutant (v129) : tu sais créer un cas, ajouter une source, lancer ingest, tagger, générer un rapport.
  • Tutoriel Autopsy standard (v124) : tu connais tous les modules d'ingest et la logique générale.
  • Tutoriel Bases CLI (v127) et idéalement CLI intermédiaire (v128) — pour le travail avec TSK et les scripts custom.
  • Notions Python (pour les modules custom).

Ce que tu sauras à la fin :

  • Maîtriser le carving récursif avec configuration fine de PhotoRec.
  • Générer une super-timeline Plaso intégrée et l'exploiter dans Autopsy.
  • Importer NSRL et ProjectVic pour le filtrage des fichiers connus.
  • Écrire un ingest module Python personnalisé pour un cas spécifique.
  • Configurer Autopsy en mode multi-utilisateur (PostgreSQL + Solr).
  • Utiliser le Sleuth Kit en CLI pour les opérations chirurgicales.
  • Orchestrer un workflow complet avec Cyber Triage et autres outils.

02 Architecture Autopsy en profondeur

Comprendre l'architecture aide à dépanner et étendre.

Stack technique

shell
┌─────────────────────────────────────┐
│         Interface NetBeans          │
│       (Java + RCP framework)        │
├─────────────────────────────────────┤
│         Ingest pipeline             │
│  (modules Java + plugins Python)    │
├─────────────────────────────────────┤
│   Case DB (SQLite ou PostgreSQL)    │
│   Keyword index (Solr / Lucene)     │
├─────────────────────────────────────┤
│      The Sleuth Kit (TSK) — C       │
│   (lecture FS, carving, timeline)   │
├─────────────────────────────────────┤
│       libraires natives (libewf,    │
│       libtsk, libafflib, etc.)      │
└─────────────────────────────────────┘
  • Sleuth Kit : moteur C qui lit les filesystems (NTFS, FAT, ext, HFS+, APFS).
  • Autopsy : interface Java + base de données + indexation.
  • Plugins : Java natifs ou Python (Jython 2.7 — pas Python 3).

Fichiers d'un cas

shell
<case_dir>/
├── <case_name>.aut          # Fichier de cas (XML)
├── autopsy.db               # SQLite (mode single-user)
├── ModuleOutput/            # Sortie de chaque module
├── Reports/                 # Rapports générés
├── Logs/                    # Logs Autopsy
├── Temp/                    # Fichiers temporaires (peut être gros)
└── timeline.db              # Base timeline (si module Timeline activé)

Où sont les configs

  • Linux : ~/.autopsy/ ou ~/Library/autopsy/
  • Windows : %APPDATA%\autopsy\
  • macOS : ~/Library/Application Support/Autopsy/

Les logs sont précieux : Logs/autopsy.log pour débuter en cas d'erreur d'ingest.

03 Carving avancé avec PhotoRec intégré

Le module PhotoRec Carver d'Autopsy embarque le célèbre PhotoRec (de Christophe Grenier, CGSecurity). Indispensable pour récupérer des fichiers partiellement supprimés ou fragmentés.

Activer le module

Ingest Modules → PhotoRec Carver (lors de l'ajout de la source ou via Tools → Run Ingest Modules).

Configuration

Cliquer Settings :

OptionEffet
Limit max file sizeIgnorer les fichiers > X Mo (gain de temps)
Carve unallocated space onlyCarving uniquement dans le $Unalloc (logique mais peut rater du contenu en allocated)
Process this many sectors at a timeTaille de bloc de traitement

Cibler des types spécifiques

PhotoRec supporte 480+ formats. Pour cibler :

PhotoRec Carver Settings → Configure PhotoRec → File Family Settings

Décocher les formats inutiles accélère drastiquement le carving. Par exemple, sur une enquête fraude documentaire : ne garder que PDF, DOCX, JPG, PNG, EML.

Où trouver les résultats

Data Sources → → $CarvedFiles (ou similaire selon version).

💡 Astuce
sur disque SSD avec TRIM, le carving peut donner peu de résultats (TRIM efface définitivement les blocs supprimés). Sur HDD, c'est très productif.

Carving manuel avec scalpel ou foremost

Pour aller plus loin que PhotoRec, en CLI :

bash
# foremost (carving guidé par config)
sudo apt install foremost
foremost -t jpg,pdf,docx -i image.dd -o /output/carved/

# bulk_extractor (carving + extraction d'IoCs)
sudo apt install bulk-extractor
bulk_extractor -o /output/bulk image.E01

Ces outils peuvent compléter Autopsy quand le carving intégré est insuffisant.

04 Super-timeline Plaso intégrée

Le module Plaso (super-timeline) d'Autopsy intègre log2timeline + psort directement.

Comportement

Le module Plaso lit tous les artefacts temporels : fichiers, registres Windows, EVTX, Prefetch, navigateurs, $LogFile NTFS, ... et produit une super-timeline unifiée intégrée à Autopsy.

Activer

Ingest Modules → Plaso (cocher lors de l'ajout de source).

Configuration

Settings → Plaso Module Settings :

  • Parser selection : tous (long) ou sélection (cibler EVTX, Web, Registry)
  • Date range : restreindre la timeline à une période

Visualisation

Une fois Plaso terminé : menu Tools → Timeline.

Autopsy ouvre la vue Timeline dédiée :

  • Histogramme global de l'activité
  • Filtrage par type d'événement (file activity, web, registry, EVTX)
  • Zoom temporel
  • Liens vers les fichiers source dans l'arbre

Combiner avec le tutoriel Plaso (v124)

Pour un usage encore plus puissant, générer la timeline avec Plaso en CLI directement (cf. tutoriel Plaso v124) et l'importer dans Autopsy via le module Body File.

bash
# Générer un body file Plaso
log2timeline.py --output bodyfile case.plaso image.E01
psort.py -o l2tcsv -w timeline.csv case.plaso

# Importer dans Autopsy : Tools → Import Body File

Avantage : la timeline CLI est plus customisable et reproductible. L'intégration Autopsy est plus visuelle.

05 Hash sets personnalisés (NSRL, ProjectVic, IoCs custom)

Le module Hash Lookup compare chaque fichier à une base de hashs. Permet de :

  • Filtrer les fichiers connus comme bénins (NSRL) → gain de temps massif
  • Détecter des fichiers connus comme malveillants (CIRCL, malwarebazaar) → flag
  • Détecter des fichiers connus comme illégaux (ProjectVic, NCMEC) → flag

Installer NSRL (Reference Data Set)

NSRL (NIST National Software Reference Library) contient millions de hashs de logiciels légitimes (Windows, Office, navigateurs, jeux).

  1. Télécharger depuis <https://www.nist.gov/itl/ssd/software-quality-group/national-software-reference-library-nsrl> (très lourd, plusieurs Go)
  2. Format : .txt (CSV avec colonnes SHA-1, MD5, etc.) ou plus efficace : .kdb (Hash Database compatible Autopsy)

Configurer dans Autopsy

Tools → Options → Hash Sets → New Database :

  • Database Type : Known Files (NSRL) ou Known Bad Files ou Indexed Files
  • Source File : pointer vers le .kdb ou .txt

Une fois indexé, Autopsy filtrera ou flaguera automatiquement.

Pour les IoCs custom

Si tu as une liste de hashs SHA-1 issus de la CTI (Cyber Threat Intelligence) :

  1. Créer un fichier texte avec un hash par ligne.
  2. New Database → Known Bad Files → Source file = ton fichier txt.
  3. Autopsy l'indexe.

Tout fichier de l'image qui a un de ces hashs apparaîtra dans Results → Hashset Hits.

ProjectVic

Pour les enquêtes pédopornographie : ProjectVic maintient des hashs catégorisés.

Accès strictement réservé aux forces de l'ordre habilitées (Suisse : Office fédéral de la police).

Source malware

  • MalwareBazaar (Abuse.ch) : <https://bazaar.abuse.ch/> — dumps SHA-256
  • MISP : si ton organisation a une instance, exporter les hashs en feed Autopsy

06 Keyword lists avancées et regex

Importer une liste

Tools → Options → Keyword Search → New List :

  • Name : ex. IoC_2026_Q1
  • Type : Exact match, Substring match, ou Regex
  • Add Keyword : un par un, ou Import depuis un fichier texte

Regex utiles

RegexCapture

Lancer sur cas existant

Si tu ajoutes une liste après l'analyse initiale : Tools → Run Ingest Modules → Keyword Search (cocher la nouvelle liste).

Pas besoin de relancer tous les modules.

07 Communicating Accounts (CommAccounts)

Module avancé qui extrait et croise les comptes de communication trouvés dans l'image :

  • Emails dans les .pst, .mbox, signatures
  • Numéros de téléphone dans contacts mobiles, SMS, signatures
  • Identifiants de messagerie (Skype, WhatsApp, Telegram dans les caches)

Activer

Ingest Modules → Communication Accounts (cocher).

Visualiser

Tools → Communications

Autopsy ouvre une vue graphique : nœuds = comptes (emails, téléphones), liens = échanges. Tu peux :

  • Filtrer par date, type de compte, fréquence
  • Identifier les hubs (un compte qui communique avec beaucoup d'autres)
  • Exporter les listes pour rapport
💡 Astuce
enquête fraude → CommAccounts révèle souvent qui communiquait avec qui, à quelle fréquence, sur quelle période. Visualisation très parlante pour magistrat.

08 Mode multi-utilisateur (PostgreSQL + Solr)

Pour les équipes travaillant sur le même cas, ou les très gros cas (> 500 Go).

Prérequis

  • PostgreSQL 9.5+ accessible en réseau
  • Apache Solr 4.x.x (version spécifique Autopsy)
  • ActiveMQ pour la messagerie

Configuration

Tools → Options → Multi-user

ChampExemple
PostgreSQL Serverdb.internal:5432
Username / Passwordcredentials
Solr Serversolr.internal:8983
ActiveMQ Servermq.internal:61616

Tester chaque connexion.

Créer un cas multi-user

Case → New Case → Case Type = Multi-user.

Plusieurs analystes peuvent maintenant ouvrir le même cas depuis leur poste, voir les tags et notes des autres, contribuer à la même base.

💡 Astuce
multi-user demande infrastructure et compétences DB. À envisager seulement pour les équipes ≥ 3 et cas ≥ 500 Go. Pour les autres cas, le single-user reste plus simple.

09 Ingest modules Python custom

Tu peux étendre Autopsy avec tes propres modules en Python (Jython 2.7).

Squelette d'un module

Fichier MyCustomIngestModule.py :

python
import jarray
import inspect

from java.lang import System
from java.util.logging import Level
from org.sleuthkit.autopsy.casemodule import Case
from org.sleuthkit.autopsy.coreutils import Logger
from org.sleuthkit.autopsy.ingest import IngestModule
from org.sleuthkit.autopsy.ingest import IngestModule.IngestModuleException
from org.sleuthkit.autopsy.ingest import DataSourceIngestModule
from org.sleuthkit.autopsy.ingest import IngestModuleFactoryAdapter
from org.sleuthkit.autopsy.ingest import IngestServices
from org.sleuthkit.autopsy.ingest import ModuleDataEvent
from org.sleuthkit.datamodel import SleuthkitCase
from org.sleuthkit.datamodel import BlackboardArtifact
from org.sleuthkit.datamodel import BlackboardAttribute


class MyCustomIngestModuleFactory(IngestModuleFactoryAdapter):

    moduleName = "Detecteur de fichiers .donottouch"

    def getModuleDisplayName(self):
        return self.moduleName

    def getModuleDescription(self):
        return "Flague les fichiers avec extension .donottouch"

    def getModuleVersionNumber(self):
        return "1.0"

    def isDataSourceIngestModuleFactory(self):
        return True

    def createDataSourceIngestModule(self, ingestOptions):
        return MyCustomIngestModule()


class MyCustomIngestModule(DataSourceIngestModule):

    _logger = Logger.getLogger(MyCustomIngestModuleFactory.moduleName)

    def __init__(self):
        self.context = None

    def startUp(self, context):
        self.context = context

    def process(self, dataSource, progressBar):
        progressBar.switchToIndeterminate()

        fileManager = Case.getCurrentCase().getServices().getFileManager()
        files = fileManager.findFiles(dataSource, "%.donottouch")

        self._logger.log(Level.INFO, "Trouvé " + str(len(files)) + " fichiers .donottouch")

        for file in files:
            # Créer un artefact blackboard
            artifact = file.newArtifact(BlackboardArtifact.ARTIFACT_TYPE.TSK_INTERESTING_FILE_HIT)
            attribute = BlackboardAttribute(
                BlackboardAttribute.ATTRIBUTE_TYPE.TSK_SET_NAME,
                MyCustomIngestModuleFactory.moduleName,
                "Fichier .donottouch détecté"
            )
            artifact.addAttribute(attribute)

        return IngestModule.ProcessResult.OK

Installer

  1. Trouver le dossier des modules Python : Tools → Python Plugins
  2. Y déposer le fichier MyCustomIngestModule.py
  3. Redémarrer Autopsy
  4. Le module apparaît dans la liste lors de l'ajout de source

Use case typique

Un client a une liste interne d'IoCs pas dans les bases publiques (noms de fichiers projet leaké, patterns spécifiques). Un module Python custom les détecte en quelques lignes.

💡 Astuce
Autopsy utilise Jython 2.7 (Python 2.7), pas Python 3. Pas de f-strings, pas de bibliothèques Python 3 modernes. Pour des analyses complexes, préférer exporter les artefacts en CSV et traiter en Python 3 externe.

python

        with open(baseReportDir + "/report_custom.html", "w") as f:
            f.write("<html><body><h1>Rapport custom</h1>")
            # ... requêter la base, écrire le contenu ...
            f.write("</body></html>")

        progressBar.complete()

Utile pour générer des rapports au format exact d'un client ou d'une procédure.

11 Le Sleuth Kit en CLI (TSK)

Sous Autopsy, il y a The Sleuth Kit. Tu peux l'utiliser directement en CLI pour les opérations chirurgicales.

Inspecter une image

bash
# Lister les partitions
mmls image.E01

# Lister les fichiers d'une partition
fls -r -p -o 2048 image.E01     # -o 2048 = offset du début de la partition

# Voir les attributs d'un fichier
istat -o 2048 image.E01 12345

# Extraire un fichier par son inode
icat -o 2048 image.E01 12345 > extracted_file.bin

Body file pour timeline

bash
fls -m / -r -o 2048 image.E01 > body.txt
mactime -b body.txt -d > timeline.csv

C'est le format mactime classique — base de toute timeline DFIR.

Recherche par hash

bash
hfind -e hashes.kdb my_db.txt

Avantage CLI

  • Scriptable : tu peux automatiser sur 100 images.
  • Léger : pas besoin de lancer l'interface Autopsy pour 3 fichiers.
  • Reproductible : commande exacte documentable dans un rapport.

12 Body file et mactime pour timeline manuelle

Si la super-timeline Plaso est trop lente ou trop verbose, tu peux générer une timeline minimaliste très rapidement.

bash
# Lister tous les fichiers avec horodatages MFT
fls -m C: -r -o 2048 image.E01 > body.txt

# Voir le format body file
head body.txt
# 0|<path>|<inode>|<mode>|<UID>|<GID>|<size>|<atime>|<mtime>|<ctime>|<crtime>

# Convertir en timeline
mactime -b body.txt -y -d > timeline.csv

# Filtrer sur une période
mactime -b body.txt -y -d 2026-01-01..2026-02-01 > timeline_jan.csv

Bien plus rapide que Plaso. Capture seulement le filesystem (pas EVTX, pas registre), donc à compléter avec d'autres sources si besoin.

13 Intégration avec Cyber Triage

Cyber Triage (Basis Technology, créateurs d'Autopsy) est un outil commercial de triage Windows. Il s'intègre nativement avec Autopsy.

Cas d'usage

  • Triage automatique sur poste compromis en cours d'incident
  • Scoring automatique des artefacts (ce qui est suspect, ce qui ne l'est pas)
  • Comparaison multi-postes dans un même incident

Workflow

  1. Cyber Triage collecte sur le poste (similaire à KAPE, mais avec scoring)
  2. Le résultat est importé dans Autopsy : Add Data Source → Cyber Triage Collection
  3. Tu disposes des deux vues : Cyber Triage (scoring rapide) + Autopsy (exploration approfondie)
💡 Astuce
mais l'intégration native avec Autopsy en fait un outil légitime pour le DFIR pro. Version Lite gratuite pour évaluer.

15 Performance et tuning

Configuration JVM

Autopsy tourne sur la JVM. Augmenter la mémoire allouée :

Fichier etc/autopsy.conf (dans le dossier d'installation) :

shell
default_options="-J-Xms2g -J-Xmx16g"

-Xmx16g = 16 Go max JVM. À adapter selon ta machine.

Solr (keyword search)

Pour les gros cas, Solr peut consommer beaucoup. Tuner solrconfig.xml :

  • ramBufferSizeMB : à 256-512 pour les gros cas
  • mergeFactor : à 25-50 pour réduire les recompactions

Base de données

Mode multi-user → PostgreSQL → tuning postgresql.conf :

  • shared_buffers : 25 % de la RAM
  • effective_cache_size : 75 % de la RAM
  • work_mem : 256 Mo

Stockage

  • Image disque : sur disque externe USB 3.0 ou eSATA — lecture seule.
  • Cas : sur SSD NVMe rapide — accès intensif.
  • Sortie Plaso : encore sur SSD séparé idéalement (très intensif disk).

Modules

Désactiver les modules non pertinents au cas pour gagner du temps :

  • Cas Android → désactiver iOS Analyzer
  • Cas sans email → désactiver Email Parser
  • Cas sans archive → désactiver Embedded File Extractor

16 Mobile : Android et iOS Analyzer

Android Analyzer

Module qui parse les artefacts Android :

  • Contacts
  • SMS / MMS
  • Call logs
  • WhatsApp, Telegram (caches publics)
  • Géolocalisation Google
  • Browser history

Source = image Android acquise (ADB backup, Cellebrite UFD, etc.).

iOS Analyzer

Idem pour iOS :

  • Contacts, SMS, calls
  • iMessage (si extrait full file system)
  • Photos avec EXIF
  • Safari history

Source = backup iTunes / iOS image / extraction Cellebrite.

Limitations

  • Apps chiffrées : sans clé, non accessibles.
  • iOS récents avec Secure Enclave : full file system difficile sans GrayKey ou Cellebrite Premium.
  • Pas de bypass intégré : Autopsy lit ce qu'il a, ne contourne pas la sécurité.
💡 Astuce
extraction avec Cellebrite (cf. tutoriel v126) → lecture dans Cellebrite Reader → export → import dans Autopsy pour croiser avec autres sources (PC, cloud, etc.).

17 Workflow d'enquête complet

Mise en pratique : enquête sur poste Windows compromis.

1. Acquisition

bash
# FTK Imager (cf. tuto v126) sur le poste → image.E01
# Calcul SHA-256
sha256sum image.E01 > MANIFEST.txt

2. Triage rapide

bash
# KAPE pour un triage rapide (cf. tuto v125)
KAPE.exe --tsource image.E01 --tdest /triage --tflush --target !SANS_Triage

3. Création cas Autopsy

shell
Case Name : INC-2026-001-WORKSTATION-John
Examiner : [analyste]
Multi-user : non (sauf si équipe)

4. Ajout source + ingest configuré

Modules à activer :

  • ✅ Recent Activity (essentiel)
  • ✅ Hash Lookup (NSRL + IoCs CTI internes)
  • ✅ File Type Identification
  • ✅ Encryption Detection
  • ✅ Email Parser
  • ✅ Embedded File Extractor
  • ✅ Keyword Search (avec IoC list à jour)
  • ✅ Interesting Files Identifier
  • ✅ Communication Accounts
  • ✅ Plaso (pour super-timeline)
  • ⚠️ PhotoRec : seulement si recherche de fichiers supprimés suspectée

Durée typique : 4-12 heures.

5. Analyse

Pendant que Plaso tourne, on commence à explorer :

  • Recent Activity → USB Device Attached : clé USB inconnue ?
  • Web History → derniers 7 jours : sites suspects ?
  • Hashset Hits : IoCs trouvés ?
  • Encryption Detection : conteneur VeraCrypt ?

6. Timeline analysis

Une fois Plaso fini : Tools → Timeline.

Zoom sur le jour de l'incident. Filtrer par catégorie : Web Activity, File Activity, Registry. Identifier le point d'entrée.

7. Tags

Tagger systématiquement chaque artefact pertinent : Notable, Evidence, Follow-up.

8. Croisement

  • Memory : Volatility 3 sur le memory dump (cf. tuto v124)
  • Network : PCAP via tshark CLI (cf. tuto v128)
  • Endpoint distant : Velociraptor (cf. tuto v125)

Importer les éléments clés dans Autopsy via Logical Files comme source supplémentaire.

9. Rapport final

Tools → Generate Report → HTML Report avec Tagged Files Only.

Compléter avec un rapport rédigé manuellement qui contextualise les éléments tagués.

10. Archivage

  • Cas Autopsy → archivé chiffré
  • Image source → archivée séparément
  • Hash MANIFEST → conservé

18 Forces, faiblesses et limites

Forces

✅ Le standard open source mondial du DFIR disque.

✅ GUI accessible + extensibilité par modules Python.

✅ Sleuth Kit en backend : robuste, mature.

✅ Intégration native Plaso, PhotoRec, Communications Accounts.

✅ Multi-user disponible pour les équipes.

✅ Tous filesystems : NTFS, FAT, ext, HFS+, APFS, exFAT.

✅ Plugins communautaires riches.

✅ Documentation correcte et formation gratuite Basis Tech.

Faiblesses

❌ Java Heavy : RAM et CPU intensif sur gros cas.

❌ Jython 2.7 : limitation pour modules Python modernes.

❌ Mobile : moins puissant que Cellebrite, Magnet AXIOM payants.

❌ Pas de bypass sécurité : ne déchiffre rien sans la clé.

❌ Multi-user complexe : PostgreSQL + Solr + ActiveMQ = infra non triviale.

❌ Lent sur très gros cas (> 1 To) : la BD SQLite ralentit.

❌ Pas de scripting CLI natif : tout passe par la GUI (sauf workarounds TSK direct).

❌ Mises à jour parfois lentes sur nouveaux formats (par rapport aux outils commerciaux).

19 Bonnes pratiques expert

🔹 Architecture du cas : disque externe pour image (lecture seule), SSD NVMe pour le cas (intensif), SSD séparé pour Plaso si possible.

🔹 Tuning JVM systématique : -Xmx16g minimum sur les gros cas.

🔹 Hash sets à jour : NSRL trimestriel, IoCs CTI quotidiens si possible.

🔹 Keyword lists versionnées : Git interne pour partager entre analystes.

🔹 Modules Python custom pour les patterns récurrents : capitaliser sur les enquêtes.

🔹 Documentation continue : tags + notes dans le cas + journal externe.

🔹 Croiser sources : Autopsy seul rate des choses. Volatility (mémoire), Plaso CLI (timeline plus fine), KAPE (triage rapide), Cellebrite (mobile) sont complémentaires.

🔹 Backup régulier du cas : ne pas perdre 40 heures d'analyse pour un crash disque.

🔹 Hash verification systématique avant ET après analyse.

🔹 Tester les modules custom sur image de test AVANT image de production.

🔹 Logs autopsy.log : à conserver pour audit/débogage.

🔹 Versionner les configs Autopsy : etc/autopsy.conf, listes de mots-clés, hash sets.

🔹 Former l'équipe : Basis Tech a des formations gratuites. À suivre par chaque membre.

🔹 Suivre les releases : nouvelles versions Autopsy ~3-4 fois/an avec améliorations notables.

🔹 Contribuer à la communauté : modules custom utiles → soumettre sur GitHub Autopsy.

21 Conclusion

Tu disposes maintenant des techniques d'un expert Autopsy. PhotoRec configuré finement, super-timeline Plaso intégrée, hash sets personnalisés, modules Python custom, Sleuth Kit en CLI, mode multi-user : tu peux orchestrer une analyse de disque industrielle.

L'expertise vient de la pratique sur cas réels. Un débutant lance les modules et regarde. Un expert sait quels modules activer, comment les configurer, où regarder en priorité, quand écrire un module custom plutôt que faire à la main.

Recommandations finales :

  1. Faire 5 CTFs DFIR sur CyberDefenders ou DFIR Madness pour acquérir le réflexe.
  2. Construire ta bibliothèque de modules Python custom pour les patterns récurrents.
  3. Maintenir des hash sets à jour (NSRL trimestriel + feed CTI quotidien).
  4. Versionner tes configs et modules dans un Git d'équipe.
  5. Suivre Basis Tech pour les releases et nouveautés.
  6. Croiser systématiquement avec Volatility, Plaso, KAPE, Cellebrite selon le cas.
  7. Contribuer au moins un module Python custom à la communauté.
  8. Préparer GCFE ou GCFA pour valider ton expertise par une certification reconnue.

Le DFIR de pointe ne consiste pas à utiliser un outil, mais à savoir lequel utiliser, quand, et comment l'étendre. Tu es prêt pour ce niveau. 🔬
