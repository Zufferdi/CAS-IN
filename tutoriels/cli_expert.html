🚀 CLI expert — Automation & orchestration

À la fin de ce tutoriel, tu sauras parser du JSON avec jq, paralléliser massivement avec GNU parallel, construire des tunnels SSH (ProxyJump, ControlMaster), capturer le réseau en CLI avec tcpdump/tshark, tracer des processus avec strace/ltrace/lsof, surveiller en live avec inotifywait, persister des sessions avec tmux, créer des services systemd, automatiser via PowerShell remoting, scripter en Python pour DFIR, et orchestrer des collectes multi-host.
🎯 Niveau expert ⏱ ~80 min 🐧 jq, parallel, ssh, tmux 🪟 PowerShell remoting 🐍 Python DFIR 🌐 Multi-host
ℹ️ Prérequis : CLI intermédiaire (v128)
Niveau expert : tu maîtrises déjà awk, sed, bash scripting. Place aux outils qui distinguent un analyste d'un architecte DFIR : orchestration distribuée, parallélisme massif, tunnels SSH avancés, scripting Python pour APIs OSINT, services systemd persistants.

Prérequis : tutoriels Bases CLI (v127) et CLI intermédiaire (v128). Tu dois maîtriser :

  • Pipelines awk, sed, grep, sort, uniq, wc
  • Conditions, boucles, fonctions bash

Ce que tu sauras à la fin :

  • Parser des sorties JSON d'APIs (VirusTotal, AbuseIPDB) avec jq
  • Paralléliser un cracking ou un parsing sur 100 fichiers avec parallel
  • Construire des tunnels SSH pour accéder à des endpoints isolés
  • Capturer et analyser du réseau en CLI sur un serveur sans GUI
  • Tracer un malware en cours d'exécution avec strace
  • Orchestrer une collecte distribuée sur des dizaines de machines

02 jq — parser et requêter du JSON

jq est à JSON ce qu'awk est aux logs. Indispensable pour exploiter les APIs DFIR (VirusTotal, AbuseIPDB, Have I Been Pwned, Shodan).

Installation

bash
# Debian/Ubuntu
sudo apt install -y jq

# Fedora
sudo dnf install -y jq

# macOS
brew install jq

# Windows : depuis https://jqlang.github.io/jq/

Syntaxe de base

bash
# Afficher un JSON joliment
echo '{"name":"alice","age":30}' | jq

# Extraire une clé
echo '{"name":"alice","age":30}' | jq '.name'
# "alice"

# Sans les guillemets autour
echo '{"name":"alice"}' | jq -r '.name'
# alice

Tableaux

bash
# Premier élément
echo '[1,2,3]' | jq '.[0]'

# Tous les éléments
echo '[{"id":1},{"id":2}]' | jq '.[].id'

# Filtrer
echo '[{"name":"a","ok":true},{"name":"b","ok":false}]' | jq '.[] | select(.ok == true)'

Cas DFIR réels

bash
curl "https://www.virustotal.com/api/v3/files/HASH" -H "x-apikey: $VT_KEY" |
    jq '.data.attributes | {malicious: .last_analysis_stats.malicious,
                             names: .names,
                             type: .type_description}'
bash
cat extraction.json | jq -r '.locations[] | .latitude, .longitude' | paste - -
bash
cat hayabusa_results.json | jq -r '.[].RuleTitle' | sort | uniq -c | sort -rn | head
bash
cat data.json | jq -r '.[] | [.id, .name, .email] | @csv' > data.csv
💡 Astuce
jq + APIs publiques (VirusTotal, AbuseIPDB, AlienVault OTX, Shodan, GreyNoise) transforment l'enrichissement d'IoCs en pipelines automatisables. Indispensable.

03 GNU parallel — paralléliser massivement

Au lieu de traiter 100 fichiers en série (1 heure), GNU parallel en traite 16 simultanément (4 minutes sur 16 cœurs).

Installation

bash
sudo apt install -y parallel

Syntaxe basique

bash
# Hasher 1000 fichiers en parallèle (autant que cœurs disponibles)
ls *.E01 | parallel sha256sum {}

# Limiter à 4 jobs simultanés
ls *.E01 | parallel -j 4 sha256sum {}

# Plusieurs arguments par job
parallel cp {} /backup/ ::: /data/*.log

{} est remplacé par chaque élément, ::: introduit une liste inline.

Cas DFIR

bash
ls Logs/*.evtx | parallel -j 8 EvtxECmd.exe -f {} --csv ./Parsed/
bash
# Plusieurs hashs, plusieurs wordlists
parallel hashcat -m 1000 hashes.txt {} -r rules/best64.rule ::: \
    rockyou.txt weakpass.txt leaked.txt
bash
find /cases/2026/01 -type f | parallel -j 16 sha256sum > MANIFEST_SHA256.txt

Distribuer sur plusieurs machines

bash
# Liste des hosts SSH dans ~/.parallel/sshloginfile
parallel --sshloginfile ~/.parallel/sshloginfile hash_file ::: *.E01

Permet de distribuer une tâche sur plusieurs serveurs comme s'ils étaient un seul cluster.

💡 Astuce
parallel --eta --progress affiche une barre de progression et l'ETA. Très utile sur les longues sessions.

04 SSH avancé : tunnels, ProxyJump, ControlMaster

ProxyJump : rebond automatique

Tu dois accéder à server-interne depuis ton PC, mais il faut passer par bastion :

bash
ssh -J user@bastion user@server-interne

Le -J (Jump host) gère le rebond automatiquement. Bien plus simple que les anciens tunnels manuels.

Avec fichier ~/.ssh/config :

shell
Host bastion
    HostName bastion.example.com
    User analyst

Host server-interne
    HostName 10.0.0.50
    User analyst
    ProxyJump bastion

Désormais : ssh server-interne suffit.

Port forwarding (tunnels)

bash
ssh -L 5901:remote.host:5901 user@bastion

Tunnel : localhost:5901 sur ton poste = remote.host:5901 côté distant. Utile pour accéder à un Velociraptor GUI, un Splunk, etc., qui ne sont accessibles que depuis le bastion.

bash
ssh -R 8080:localhost:8080 user@server

Le port 8080 du serveur distant pointe vers ton localhost:8080. Utile pour partager temporairement un service.

bash
ssh -D 1080 user@bastion

Crée un proxy SOCKS sur ton localhost:1080 qui transite par le bastion. Configure ton navigateur en SOCKS5 → tu navigues comme depuis le bastion.

ControlMaster : connexions persistantes

Dans ~/.ssh/config :

shell
Host *
    ControlMaster auto
    ControlPath ~/.ssh/sockets/%r@%h-%p
    ControlPersist 600

mkdir -p ~/.ssh/sockets une fois pour toutes.

Effet : la première connexion SSH ouvre une session, les suivantes vers le même host réutilisent la connexion (instantanées, pas de re-saisie). Énorme gain de productivité.

Cas DFIR : collecte sur poste isolé via bastion

bash
# Lancer Velociraptor collector via tunnel SOCKS
ssh -D 1080 -fN user@bastion
# Puis depuis le navigateur configuré SOCKS, accéder au Velociraptor distant

05 rsync — synchronisation efficace

rsync ne transfère que les différences : reprend les transferts coupés, économise bande passante, idéal pour copier de gros volumes de preuves.

Syntaxe

bash
# Copie locale
rsync -avh source/ dest/

# Copie distante
rsync -avh source/ user@host:/dest/

# Copie distante avec compression
rsync -avhz source/ user@host:/dest/

# Reprise en cas d'interruption
rsync -avhz --partial --progress source/ user@host:/dest/
OptionSens
-aarchive (récursif, préserve permissions, timestamps)
-vverbeux
-hhuman-readable
-zcompression durant transfert
--partialgarde les fichiers partiels en cas d'interruption
--progressbarre de progression
-n ou --dry-runsimulation, ne fait rien
--deletesupprime côté dest ce qui n'existe plus côté source

Cas DFIR

bash
# Transférer un cas vers le NAS d'archivage avec progress + reprise
rsync -avhz --partial --progress /cases/2026/01/ nas:/archive/2026/01/

# Comparer deux acquisitions du même disque (debug)
rsync -avhc --dry-run image1/ image2/
💡 Astuce
rsync over SSH par défaut. Pas besoin de NFS / FTP.

06 tcpdump et tshark en CLI

Sur un serveur sans GUI, tu n'as pas Wireshark. Mais tu as tcpdump et tshark.

tcpdump : capture rapide

bash
# Capturer 100 paquets sur eth0
sudo tcpdump -i eth0 -c 100

# Capturer dans un fichier
sudo tcpdump -i eth0 -w capture.pcap

# Filtrer (BPF)
sudo tcpdump -i eth0 'host 192.168.1.5 and port 443'
sudo tcpdump -i eth0 'not arp and not stp'
sudo tcpdump -i eth0 'tcp[tcpflags] == tcp-syn'   # SYN scans

tshark : analyse complète

bash
# Lecture d'un PCAP existant
tshark -r capture.pcap

# Filtre display Wireshark
tshark -r capture.pcap -Y "http.request.method == GET"

# Extraire champs en CSV
tshark -r capture.pcap -T fields \
    -e ip.src -e ip.dst -e http.host -e http.request.uri \
    -E header=y -E separator=, > requests.csv

# Top hosts
tshark -r capture.pcap -q -z hosts | head -20

# Suivre un flux TCP
tshark -r capture.pcap -q -z follow,tcp,ascii,5

Cas DFIR : capture + analyse en script

bash
#!/bin/bash
# Capture 5 minutes puis analyse les top conversations

CAPTURE_FILE="/tmp/triage_$(date +%s).pcap"

sudo tcpdump -i eth0 -w "$CAPTURE_FILE" &
TCPDUMP_PID=$!

sleep 300
kill $TCPDUMP_PID
wait $TCPDUMP_PID 2>/dev/null

echo "=== Top 10 conversations ==="
tshark -r "$CAPTURE_FILE" -q -z conv,ip | head -n 15

echo "=== DNS queries ==="
tshark -r "$CAPTURE_FILE" -Y "dns" -T fields -e dns.qry.name | sort -u | head -n 30

07 nc / netcat — couteau suisse réseau

netcat (nc) lit et écrit sur des sockets TCP/UDP. Tester, transférer, écouter.

Tester si un port est ouvert

bash
nc -zv 8.8.8.8 53                  # TCP 53 ouvert ?
nc -zvu 8.8.8.8 53                 # UDP 53

Bannière de service

bash
nc -v webserver.local 80
GET / HTTP/1.0

(deux retours chariot pour valider la requête).

Transférer un fichier sans SSH

Côté récepteur :

bash
nc -l -p 4444 > file.received

Côté émetteur :

bash
nc receiver.host 4444 < file.to.send

Cas DFIR : exfil rapide depuis poste isolé

Si SSH n'est pas dispo mais que le réseau passe :

bash
# Côté analyste (récepteur)
nc -l -p 9999 > collected.tar.gz

# Côté poste source
tar -czf - /cases/ | nc analyst.host 9999

⚠️ Aucun chiffrement : à utiliser dans un réseau de confiance uniquement, ou tunneler dans SSH.

Le mode "écoute" pour debug

Tu testes un script qui envoie des requêtes HTTP ? Lance nc -l -p 8080 côté serveur, observe ce qui arrive. Idéal pour debug d'un webhook ou d'un exfil malware suspect.

08 strace, ltrace — tracer un processus

strace capture chaque appel système d'un processus. ltrace capture les appels de bibliothèques.

Strace en cours d'exécution

bash
# Lancer un binaire avec strace
strace /tmp/suspicious.elf

# Attacher à un processus en cours
strace -p 1234

# Filtrer les appels (-e)
strace -e openat,read,write -p 1234

# Sortie dans un fichier
strace -o trace.log -p 1234

# Tracer aussi les enfants
strace -f -p 1234

Cas DFIR : analyser un malware Linux

bash
strace -f -e trace=network,file -o malware_trace.log ./suspicious_binary

Tu vois :

  • Tous les fichiers ouverts
  • Toutes les connexions réseau (avec adresses IP et ports)
  • Les chargements de bibliothèques

ltrace : appels aux bibliothèques

bash
ltrace ./binary
ltrace -p 1234

Capture malloc, strcpy, printf, etc. Utile pour comprendre la logique d'un binaire sans le reverser.

💡 Astuce
strace + ltrace + tcpdump sur le même processus = mini-sandbox dynamique pour comprendre un malware Linux en 5 minutes.

09 lsof — qui ouvre quoi

lsof (LiSt Open Files) liste tout ce qui est ouvert (fichiers, sockets, devices). Sur Linux, tout est fichier, donc tout passe par lsof.

Lister ce qu'un processus ouvre

bash
sudo lsof -p 1234

Trouver qui utilise un fichier

bash
sudo lsof /var/log/auth.log

Trouver qui utilise un port

bash
sudo lsof -i :443
sudo lsof -i tcp:443
sudo lsof -i udp:53

Listing complet réseau

bash
sudo lsof -i -P -n
  • -i : connexions réseau
  • -P : port numérique (pas de résolution service)
  • -n : pas de résolution DNS

Cas DFIR

bash
# Identifier le processus qui maintient un socket ouvert vers une IP suspecte
sudo lsof -i | grep "185.142.236"

# Voir tous les fichiers ouverts par un service compromis
sudo lsof -p $(pgrep nginx)

10 Inspection système : /proc, /sys, sysfs

Sur Linux, le kernel expose son état via les pseudo-filesystems /proc et /sys. C'est gold pour DFIR live.

/proc/$PID/

Chaque processus a un dossier. Exemples utiles :

bash
PID=1234

cat /proc/$PID/cmdline | tr '\0' ' '       # ligne de commande complète
cat /proc/$PID/status                       # état détaillé
ls -la /proc/$PID/cwd                       # répertoire courant
ls -la /proc/$PID/exe                       # chemin du binaire
ls -la /proc/$PID/fd/                       # tous les descripteurs ouverts
cat /proc/$PID/maps                         # mémoire mappée (libraries, heap, stack)
cat /proc/$PID/environ | tr '\0' '\n'       # variables d'environnement

Cas DFIR : retrouver le binaire d'un processus supprimé

Si le processus est encore en mémoire mais que le binaire sur disque a été supprimé (typique malware) :

bash
# Le lien /proc/$PID/exe pointe vers le binaire originel
sudo cp /proc/1234/exe /tmp/recovered_malware

Tu récupères le binaire malicieux même s'il a été effacé.

/proc système

bash
cat /proc/meminfo                # RAM
cat /proc/cpuinfo                # CPU
cat /proc/loadavg                # load moyenne
cat /proc/uptime                 # uptime
cat /proc/version                # version kernel

/sys

/sys expose les devices et drivers. Moins utilisé en DFIR mais utile pour :

bash
# Lister les disques
ls /sys/class/block/

# Voir le sérial d'un disque
cat /sys/class/block/sda/device/serial

11 inotifywait — surveillance live de fichiers

inotifywait (paquet inotify-tools) attend des événements filesystem : création, modification, suppression, accès.

Installation

bash
sudo apt install -y inotify-tools

Surveiller un dossier

bash
# Bloquant jusqu'au prochain événement
inotifywait -m /var/log/

# En continu, formaté
inotifywait -m -r --format '%T %e %w%f' --timefmt '%F %T' /var/log/

Cas DFIR : honeypot fichier

bash
#!/bin/bash
# Surveille un dossier "appât" et alerte sur toute modification

inotifywait -m -r --format '%T %e %w%f' --timefmt '%F %T' /opt/honeypot/ | \
while read evenement; do
    echo "[ALERT] $evenement" | mail -s "Honeypot triggered" soc@example.com
done

Détecter une exfiltration en temps réel

bash
# Alerter dès qu'un fichier > 50 Mo est créé dans /tmp
inotifywait -m -e create /tmp/ | \
while read dir event file; do
    fullpath="$dir$file"
    sleep 2
    size=$(stat -c%s "$fullpath" 2>/dev/null || echo 0)
    if [ "$size" -gt 52428800 ]; then
        echo "$(date) — Gros fichier créé : $fullpath ($size octets)" >> /var/log/big_files.log
    fi
done

12 tmux / screen pour les sessions longues

Sur SSH, une déconnexion = ton script meurt. Pas acceptable pour un cracking de 12h. Solution : multiplexeur de terminal.

tmux (recommandé)

bash
# Démarrer une session
tmux new -s investigation

# Détacher : Ctrl+B puis D

# Lister les sessions
tmux ls

# Réattacher
tmux attach -t investigation

Raccourcis essentiels (préfixe Ctrl+B)

RaccourciAction
Ctrl+B Ddétacher
Ctrl+B Cnouveau onglet
Ctrl+B N / Ponglet suivant / précédent
Ctrl+B 0-9onglet n° X
Ctrl+B ,renommer onglet
Ctrl+B %split vertical
Ctrl+B "split horizontal
Ctrl+B flèchesnaviguer entre panes
Ctrl+B [mode scroll (q pour sortir)

Cas DFIR

bash
# Lance ton cracking dans tmux
tmux new -s hashcat

# À l'intérieur de tmux :
hashcat -a 0 -m 1000 hashes.txt rockyou.txt -r rules/best64.rule

# Détache (Ctrl+B D)
# Tu peux fermer ta session SSH, le hashcat continue

# Le lendemain :
ssh user@server
tmux attach -t hashcat
# Tu retrouves ton hashcat exactement comme il était

screen (alternative classique)

Mêmes principes. Préfixe par défaut Ctrl+A.

bash
screen -S investigation
# Ctrl+A D pour détacher
screen -ls
screen -r investigation

13 systemd — services, timers, journalctl

Systemd est le système d'init de tous les Linux modernes. Maîtriser ses commandes = maîtriser le serveur.

systemctl : services

bash
# Lister tous les services actifs
systemctl list-units --type=service --state=running

# Statut d'un service
systemctl status nginx

# Démarrer / stopper / redémarrer
sudo systemctl start nginx
sudo systemctl stop nginx
sudo systemctl restart nginx

# Activer au boot
sudo systemctl enable nginx
sudo systemctl disable nginx

Créer un service custom

/etc/systemd/system/triage.service :

ini
[Unit]
Description=DFIR Triage Daemon
After=network.target

[Service]
Type=simple
User=analyst
WorkingDirectory=/opt/triage
ExecStart=/opt/triage/run.sh
Restart=on-failure

[Install]
WantedBy=multi-user.target

Puis :

bash
sudo systemctl daemon-reload
sudo systemctl enable --now triage

systemd timers (alternative à cron)

/etc/systemd/system/daily-hash.timer :

ini
[Unit]
Description=Daily hash check

[Timer]
OnCalendar=daily
Persistent=true

[Install]
WantedBy=timers.target

Et le service associé /etc/systemd/system/daily-hash.service.

bash
sudo systemctl enable --now daily-hash.timer
systemctl list-timers

journalctl : logs unifiés

bash
# Tous les logs
journalctl

# Pour un service
journalctl -u nginx

# Suivre en temps réel
journalctl -fu nginx

# Depuis une date
journalctl --since "2026-01-15 14:00:00"
journalctl --since yesterday
journalctl --since "1 hour ago"

# Niveau d'urgence
journalctl -p err          # erreurs et critiques uniquement

# Format JSON pour parser avec jq
journalctl -u nginx -o json | jq '.MESSAGE'

# Boot précédent (rares cas)
journalctl -b -1

Cas DFIR

bash
# Toutes les tentatives sudo dans les 24h
journalctl --since "24 hours ago" SYSLOG_FACILITY=10 | grep -i sudo

# Pic d'erreurs nginx aujourd'hui
journalctl -u nginx --since today -p err | wc -l

14 PowerShell expert : remoting, jobs, classes

PowerShell Remoting

powershell
# Activer le remoting sur le serveur cible
Enable-PSRemoting -Force

# Sur le client : exécuter une commande à distance
Invoke-Command -ComputerName WS01,WS02,WS03 -ScriptBlock {
    Get-Process | Where-Object { $_.CPU -gt 100 }
}

# Avec credentials
$cred = Get-Credential
Invoke-Command -ComputerName WS01 -Credential $cred -ScriptBlock { hostname }

# Session interactive
Enter-PSSession -ComputerName WS01

Background jobs

powershell
# Lancer une commande en arrière-plan
$job = Start-Job -ScriptBlock { Start-Sleep 60; Get-Process }

# Récupérer le statut
Get-Job

# Récupérer le résultat
Receive-Job $job -Wait

Classes PowerShell

powershell
class Artifact {
    [string]$Path
    [string]$Hash
    [datetime]$Collected

    Artifact([string]$path) {
        $this.Path = $path
        $this.Hash = (Get-FileHash $path).Hash
        $this.Collected = Get-Date
    }
}

$art = [Artifact]::new("C:\Cases\image.E01")
$art.Hash

Cas DFIR : collecte parallèle sur 50 postes

powershell
$computers = Get-Content workstations.txt

$results = $computers | ForEach-Object -Parallel {
    Invoke-Command -ComputerName $_ -ScriptBlock {
        @{
            Host = $env:COMPUTERNAME

$results | Export-Csv triage_parc.csv

15 Scripting Python pour le DFIR

Quand bash atteint ses limites (parsing complexe, structures de données, APIs), passe à Python.

Pourquoi Python en DFIR

  • Bibliothèques pyimpacket, volatility3, dfir_iris_client, mitreattack disponibles
  • Manipulation JSON, CSV, XML, SQLite native
  • Threading et multiprocessing natifs
  • Standard du tooling DFIR moderne (Volatility, Plaso, MVT — tous Python)

Squelette de script DFIR

python
#!/usr/bin/env python3
"""
collecte_etat.py — Snapshot état système pour triage
Usage : python3 collecte_etat.py /chemin/sortie
"""

import sys
import json
import hashlib
import subprocess
from datetime import datetime
from pathlib import Path

def hash_file(path: str, algo='sha256') -> str:
    h = hashlib.new(algo)
    with open(path, 'rb') as f:
        for chunk in iter(lambda: f.read(8192), b''):
            h.update(chunk)
    return h.hexdigest()

def run_cmd(cmd: list) -> str:
    return subprocess.run(cmd, capture_output=True, text=True).stdout

def main(output_dir: str):
    out = Path(output_dir)
    out.mkdir(parents=True, exist_ok=True)

    data = {
        'timestamp': datetime.utcnow().isoformat(),
        'hostname': run_cmd(['hostname']).strip(),
        'uname': run_cmd(['uname', '-a']).strip(),
        'who': run_cmd(['who']).strip(),
        'processes': run_cmd(['ps', '-auxf']),
    }

    output_file = out / 'snapshot.json'
    with open(output_file, 'w') as f:
        json.dump(data, f, indent=2)

    print(f"[+] Snapshot écrit : {output_file}")
    print(f"[+] Hash : {hash_file(output_file)}")

if __name__ == '__main__':
    if len(sys.argv) != 2:
        print(f"Usage: {sys.argv[0]} <output_dir>")
        sys.exit(1)
    main(sys.argv[1])

Cas DFIR : pivoter avec une API

python
#!/usr/bin/env python3
"""Enrichissement IP via AbuseIPDB"""

import os
import sys
import requests

API_KEY = os.environ['ABUSEIPDB_KEY']

def check_ip(ip):
    r = requests.get(
        'https://api.abuseipdb.com/api/v2/check',
        params={'ipAddress': ip, 'maxAgeInDays': 90},
        headers={'Key': API_KEY, 'Accept': 'application/json'}
    )
    return r.json()['data']

if __name__ == '__main__':
    for ip in sys.stdin:
        ip = ip.strip()
        try:
            data = check_ip(ip)
            print(f"{ip}\t{data['abuseConfidenceScore']}\t{data['countryCode']}")
        except Exception as e:
            print(f"{ip}\tERROR\t{e}", file=sys.stderr)

Usage :

bash
cat ips.txt | python3 enrich.py > enriched.tsv

shell

Script de triage distant

scripts/triage_remote.sh (sur ton poste) :

bash
#!/bin/bash
set -euo pipefail

if [ $# -lt 1 ]; then
    echo "Usage: $0 <hosts_file>"
    exit 1
fi

HOSTS_FILE="$1"
CASE_DIR="cases/$(date +%Y%m%d_%H%M%S)"
mkdir -p "$CASE_DIR"

log() {
    echo "[$(date +%H:%M:%S)] $*" | tee -a "$CASE_DIR/orchestration.log"
}

triage_host() {
    local host="$1"
    local out_dir="$CASE_DIR/$host"
    mkdir -p "$out_dir"

    log "Triage $host"

    # Lancer le script de triage à distance
    ssh "$host" 'bash -s' < scripts/triage_local.sh > "$out_dir/triage.log" 2>&1

    # Récupérer le résultat (compressé)
    scp "${host}:/tmp/triage_$(hostname).tar.gz" "$out_dir/"

    # Hasher
    sha256sum "$out_dir"/*.tar.gz >> "$CASE_DIR/MANIFEST.txt"
}

export -f triage_host log
export CASE_DIR

# Parallel sur 5 hosts simultanés
parallel -j 5 triage_host :::: "$HOSTS_FILE"

log "Tous les triages terminés."
log "Synthèse :"
ls -lh "$CASE_DIR"

Script local sur chaque serveur

scripts/triage_local.sh :

bash
#!/bin/bash
set -euo pipefail

OUT="/tmp/triage_$(hostname).tar.gz"
WORK="/tmp/triage_$$"

mkdir -p "$WORK"

hostname > "$WORK/hostname.txt"
uname -a > "$WORK/uname.txt"
ps -auxf > "$WORK/ps.txt"
ss -tunap > "$WORK/connections.txt" 2>/dev/null || netstat -tunap > "$WORK/connections.txt" 2>/dev/null
who > "$WORK/who.txt"
last -n 50 > "$WORK/last.txt"

# Récents
find /tmp /var/tmp -type f -mtime -7 2>/dev/null > "$WORK/recent_tmp.txt"
journalctl --since "24 hours ago" > "$WORK/journal_24h.txt" 2>/dev/null || true

# Hash binaires sensibles
sha256sum /bin/* /sbin/* /usr/bin/* /usr/sbin/* 2>/dev/null > "$WORK/binary_hashes.txt"

# Pack
tar -czf "$OUT" -C "$WORK" .
rm -rf "$WORK"

echo "Triage écrit : $OUT"

Exécution

bash
chmod +x scripts/*.sh
./scripts/triage_remote.sh hosts.txt

Résultat : 15 serveurs triés en parallèle (par batch de 5), chaque collecte hashée et tracée. Reproductible, scriptable, scalable.

17 Performance et profiling de scripts

time

bash
time ./mon_script.sh
# real    1m23.456s
# user    0m45.789s
# sys     0m12.345s
  • real : temps écoulé
  • user : temps CPU utilisé en mode utilisateur
  • sys : temps CPU en kernel

Profiler bash

bash
PS4='+ ${BASH_SOURCE}:${LINENO}: ' bash -x ./script.sh 2> trace.log

Trace toutes les lignes exécutées avec leur emplacement. Tu vois où le temps passe.

Profiler PowerShell

powershell
Measure-Command { .\script.ps1 }

# Profilage détaillé avec Trace-Command
Trace-Command -Name Cmdlet -Expression { Get-Process | Where CPU -gt 100 } -PSHost

18 Sécurité de tes scripts

🔒 Variables sensibles : ne JAMAIS hardcoder un API key. Utiliser variables d'environnement.

bash
# Mauvais
curl "https://api.example.com" -H "Authorization: Bearer abc123secret"

# Bon
curl "https://api.example.com" -H "Authorization: Bearer $API_KEY"

🔒 Permissions des scripts : chmod 700 sensible.sh. Que toi puisses le lire/exécuter.

🔒 Pas de mots de passe en arguments : ils apparaissent dans ps aux. Lire depuis stdin ou fichier protégé.

🔒 Quoter les arguments utilisateur : "$1", jamais $1 nu. Sinon injection possible.

🔒 Pas de eval : eval exécute du texte arbitraire. À bannir.

🔒 Set -u : refuse les variables non définies. Évite les bugs silencieux.

🔒 Logging sans secrets : ne pas logger les clés, hashs sensibles, mots de passe.

🔒 Audit : versionner tes scripts dans Git, signé. Reproductibilité judiciaire.

Exemple : script sécurisé

bash
#!/bin/bash
set -euo pipefail
IFS=$'\n\t'

# Charger les secrets depuis un fichier protégé
[ -f ~/.dfir_secrets ] && source ~/.dfir_secrets

# Vérifier les variables requises
: "${VT_API_KEY:?VT_API_KEY non définie. Charge ~/.dfir_secrets ou exporte-la.}"

# Quoter systématique des inputs
input_file="${1:-}"
[ -z "$input_file" ] && { echo "Usage: $0 <input_file>"; exit 1; }
[ ! -r "$input_file" ] && { echo "Fichier $input_file illisible"; exit 1; }

19 Bonnes pratiques DFIR avancé

🔹 Tout scripter : aucune tâche manuelle répétitive ne devrait survivre 3 mois. Si tu le fais 3 fois, automatise.

🔹 Versionner avec Git : tes scripts sont des outils d'expert. Git local au minimum, GitLab d'équipe idéal.

🔹 Documenter en haut de fichier : usage, arguments, exemples, dépendances, auteur, date.

🔹 Tests sur VM avant production sur preuve réelle. Surtout pour les scripts destructeurs.

🔹 Logging obligatoire : chaque script DFIR doit logger ce qu'il fait, quand, sur quoi.

🔹 Reproductibilité juridique : tout script qui touche une preuve doit produire un manifest hashé.

🔹 Sécurité des secrets : variables d'environnement, jamais hardcodées. Fichier ~/.dfir_secrets chmod 600.

🔹 Apprendre Python en complément : bash + PowerShell + Python = combo gagnant. Python pour la logique métier complexe.

🔹 Lire les scripts d'autres : awesome-dfir, sigma, atomic-red-team. Apprentissage continu.

🔹 Cheat sheets personnels : un dossier cheatsheets/ versionné Git avec les pipelines utiles découverts.

🔹 Surveiller les performances : profiler les scripts qui prennent > 5 min.

🔹 Capitaliser : transformer une suite de commandes one-shot en fonction réutilisable.

🔹 Refactoring régulier : un script qui marche n'est pas un bon script. Bon = lisible, robuste, documenté.
