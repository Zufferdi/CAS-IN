**Conséquence** : ces 11 sagas sont **invisibles** dans l'écran « Dossiers /
Sagas » (`scene-campaigns-v1.js` charge `data/campaigns.json` au boot). Elles
restent accessibles via URL directe `scene.html?scene=<id>` et apparaissent

navigation utilisateur ne mène à elles.

**Cause probable** : les scripts `scripts/apply_saga_*.py` n'ont jamais été
exécutés sur ce ZIP. Les fichiers `scenes/*.json` ont été ajoutés (probablement
via git pull) mais les étapes `inject_campaign` + `bump_sw` + `rebuild_meta`
n'ont pas eu lieu.

## Bug mineur corrigé : `next: 'phase*'` dans acte 7 Data brokers

Convention non-standard `next: 'phase2'/'phase3'/'phase4'/'phase5'` (12
occurrences dans `ch-affaire-data-brokers-7-bilan-doctrine.json`) → corrigée
en `'continue'`.

Comportement avant correction : non bloquant (le moteur `advanceStep()` dans
`js/pages/scene-app.js` fait `G.stepIdx++` pour toute string non-`'end'` et
non numérique) — l'avancement séquentiel fonctionnait, mais c'était une
convention étrangère au reste du catalogue.

## Installation du patch

Depuis la racine du workspace CAS-IN :

```bash
# 1. Extraire le patch par-dessus le workspace existant
tar -xzf cas-in-audit-repair.tar.gz

# 2. Réparer l'état actuel (idempotent, sans risque)
bash repair_all_sagas.sh

# 3. Installer le hook pre-commit local
bash scripts/install_hooks.sh

# 4. (Optionnel) Vérifier que tout est OK
python3 scripts/check_campaigns_parity.py

# 5. Commit + push
git add -A
git commit -m "fix(catalog): repair 11 orphan sagas + add catalog parity validation"
git push
```

La GitHub Action `validate-catalog.yml` s'activera automatiquement au prochain
push touchant `scenes/`, `data/campaigns.json` ou `scripts/apply_saga_*.py`.
