☁️ Cloud Forensics — Quand la preuve est dans un autre pays
Le cloud computing a profondément transformé l'investigation numérique. Avant 2010, les preuves étaient sur le PC de bureau du suspect — saisie locale, image disque, analyse. Aujourd'hui, l'essentiel des données d'entreprise et personnelles est dans le cloud : Microsoft 365 (Office, Outlook, OneDrive, Teams, SharePoint), Google Workspace (Gmail, Drive, Calendar), AWS / Azure / GCP (infrastructure), iCloud (iMessages, photos, backups iOS), Dropbox, Box, Slack, Notion… Pour le forensiste, cela crée quatre défis fondamentaux : (1) Juridiction multiple — où sont stockées les données ? Souvent inconnu, parfois chez plusieurs hébergeurs. (2) Accès limité — l'enquêteur n'a pas accès direct aux serveurs, dépend du provider. (3) Volatilité — les logs disparaissent après leur période de rétention (souvent 90 jours), les snapshots peuvent être effacés à tout moment. (4) Multi-tenancy + chiffrement — les données sont chiffrées au repos et isolées entre clients. Solution : Preservation Request immédiate au provider (gel des données), puis demande légale formelle via MLAT (long : 6-18 mois) ou accord bilatéral. Le US CLOUD Act (2018) permet aux autorités américaines d'accéder aux données stockées par des providers US même à l'étranger — point de friction avec la souveraineté européenne et suisse.

🌐 Défis spécifiques du cloud forensique
⚠️ Problèmes fondamentaux
  • Juridiction multiple : les données peuvent être stockées dans n'importe quel pays
  • Accès limité : l'enquêteur n'a pas accès direct aux serveurs
  • Volatilité : logs supprimés après rétention (souvent 90 jours)
  • Multi-tenancy : isolation des données entre clients
  • Chiffrement : données chiffrées au repos et en transit
  • Réplication géographique : copies sur plusieurs continents
  • Authentification déléguée : SSO, fédération identités
🔑 Leviers légaux disponibles
  • MLAT (Mutual Legal Assistance Treaty) : entraide judiciaire internationale formelle
  • US CLOUD Act (2018) : accès direct aux données US stockées à l'étranger
  • Preservation Request : demander au provider de conserver les logs avant MLAT
  • Emergency Disclosure : pour danger imminent pour la vie (heures)
  • Convention Budapest art. 18 : entraide cybercriminalité
  • EU-US Data Privacy Framework (juillet 2023, remplace Privacy Shield)
  • Content vs Metadata : les métadonnées sont plus facilement accessibles
📊 Sources de logs par provider
🟦 Microsoft 365 / Azure
  • Unified Audit Log — activité utilisateur — 90 j (E3) · 1 an (E5)
  • Azure AD Sign-in logs — authentifications, IP, localisation, MFA
  • Exchange Online — emails, métadonnées, traces de lecture
  • SharePoint / OneDrive — accès fichiers, partages, téléchargements
  • Teams — messages (via Compliance Center)
  • Outils : Microsoft Compliance Center · Graph API · eDiscovery
🔴 Google Workspace
  • Admin Reports — activité admin, connexions
  • Gmail logs — envoi/réception, IP, appareil
  • Drive Activity — accès, partage, suppression fichiers
  • Meet — participation aux réunions
  • Rétention : variable selon licence (180 j–6 mois)
  • Outils : Vault (Google) · GAM (CLI) · Admin SDK API
🟠 Amazon AWS
  • CloudTrail — toutes les actions API (qui a fait quoi, quand)
  • VPC Flow Logs — trafic réseau entre ressources
  • S3 Access Logs — accès aux buckets de stockage
  • GuardDuty — détection d'anomalies (équiv. EDR)
  • Rétention : configurable (par défaut non permanents)
  • Outils : AWS CLI · CloudWatch · Athena pour requêtes
🍎 Apple iCloud
  • Données disponibles via Legal Process Guidelines d'Apple
  • Contenu : contacts, calendriers, email, backups iOS
  • iMessages = chiffrés E2E — Apple ne peut pas déchiffrer
  • Backups non chiffrés si option activée par l'utilisateur
  • Rétention : 25 jours pour les métadonnées de connexion
  • Advanced Data Protection (2022) : E2E sur tout iCloud
📋 Processus de préservation
1
Preservation Request immédiate — Contacter le provider AVANT toute demande formelle pour demander la conservation des données. La plupart répondent en 24–48h pour les cas d'urgence. Sans ça, les logs disparaissent après rétention.
2
Identifier la juridiction — Où sont stockées les données ? (US, EU, etc.). Quel traité d'entraide applicable ? MLAT USA–Suisse (1977), Entraide judiciaire EU–Suisse, Convention Budapest sur la cybercriminalité. Le siège du provider ≠ localisation des données.
3
Demande légale formelle — Via MLAT (lent : 6–18 mois) ou accord bilatéral. En Suisse : passe par l'OFJ (Office fédéral de la justice). Distinguer métadonnées (plus facile) vs contenu (plus restrictif). CLOUD Act US permet aux autorités US d'obtenir données stockées hors US.
4
Analyse des logs reçus — Formater en timeline. Croiser avec les logs locaux (PC, smartphone). Les IP dans les logs cloud + corrélation avec DHCP local = attribution. Vérifier les User-Agents pour identifier l'appareil.
5
Documentation chaîne de custody — Hash SHA-256 de chaque export reçu, traçabilité requête → réponse, conservation des correspondances avec le provider, sceller le numéro d'affaire dans toutes les communications.
🇨🇭 Suisse et cloud : La LPD révisée (2023) impose des obligations aux entreprises suisses utilisant le cloud (art. 8 LPD : sécurité, art. 9 LPD : sous-traitants). Le PFPDT doit être notifié en cas de violation « dans les meilleurs délais » (pas de délai 72h chiffré, contrairement au RGPD). Les données personnelles stockées dans le cloud US bénéficient du EU-US Data Privacy Framework (depuis juillet 2023, remplace Privacy Shield invalidé par CJUE Schrems II) — la Suisse a adopté un cadre équivalent (Swiss-US Data Privacy Framework, en vigueur depuis le 15 septembre 2024).
🧠 Testez-vous
Une entreprise suisse vous appelle : un employé suspect a quitté la société. Vous avez besoin de ses emails M365. Que faire en premier ?Preservation · Niveau : facile
Preservation Request immédiate à Microsoft. Procédure : (1) Activer eDiscovery hold sur le compte de l'employé via l'Compliance Center Microsoft 365 (l'admin de l'entreprise peut le faire) — gel de toutes les données : emails, OneDrive, Teams, SharePoint. Crucial : sans ça, les emails marqués supprimés disparaissent au bout de 30 jours. (2) Si l'admin n'est pas coopératif ou compte personnel : contacter Microsoft Law Enforcement via https://docs.microsoft.com/en-us/microsoft-365/compliance/law-enforcement-requests avec un courrier officiel + numéro affaire CH. Délai : 24-48h pour preservation. (3) Pendant le gel : préparer la demande légale formelle (MLAT via OFJ si données aux US, ou plus rapide si datacenters EU Microsoft confirmés). (4) Backup local : Outlook PST/OST sur le poste de l'employé contient peut-être déjà tout (à saisir avant qu'il les efface). Délai critique : un Unified Audit Log E3 ne conserve que 90 jours — il faut agir vite ou activer la rétention longue durée.
Que pouvez-vous obtenir d'Apple concernant les iMessages d'un suspect ?iCloud · Niveau : moyen
Très peu en pratique : (1) Métadonnées (qui parle à qui, IP, horodatage des connexions iCloud) — Apple les conserve 25 jours. (2) Contenu iMessages = chiffrés E2E — Apple ne peut pas déchiffrer même sur ordre judiciaire. (3) Backups iCloud peuvent contenir les iMessages en clair côté Apple si l'utilisateur n'a PAS activé Advanced Data Protection (introduit fin 2022). Si activé, tout iCloud est E2E (Apple voit rien). (4) Données obtenables via Apple Legal Process Guidelines : Apple ID, email associé, photos iCloud (sauf ADP), contacts, calendrier, Find My (localisation des appareils), achats App Store, Game Center. (5) Solution alternative : saisir le terminal physique du suspect (iPhone/iPad/Mac) — les iMessages sont stockés en clair sur l'appareil dans sms.db. (6) Saisir le terminal du correspondant aussi — les messages sont sur les deux téléphones. Advanced Data Protection est l'enjeu du moment : 90% des utilisateurs ne l'activent pas → Apple peut encore aider via demande légale pour ces utilisateurs.
Qu'est-ce que le US CLOUD Act et pourquoi pose-t-il problème en Europe / Suisse ?Cadre légal · Niveau : difficile
Le CLOUD Act (Clarifying Lawful Overseas Use of Data Act, mars 2018) permet aux autorités américaines d'obliger les providers US (Microsoft, Google, Amazon, Apple, Meta…) à fournir des données même stockées à l'étranger. Avant CLOUD Act, le « Microsoft Ireland case » (2013-2018) avait montré qu'un provider US pouvait refuser de fournir des données stockées en Irlande. Le CLOUD Act a tranché : le provider doit obéir, peu importe où les données sont. Conflit avec l'UE/CH : (1) Le RGPD et la nLPD suisse interdisent le transfert non autorisé de données personnelles vers des pays tiers sans garanties suffisantes. Un provider US qui répond au CLOUD Act peut être en violation du RGPD/LPD. (2) Conflit de lois : (US autorise → UE interdit). (3) Schrems II (CJUE 2020) a invalidé le Privacy Shield justement à cause de cette accessibilité aux services de renseignement US. (4) Le Data Privacy Framework (juillet 2023) tente de combler avec « équivalence reconnue » — mais beaucoup d'experts pensent qu'il sera invalidé à son tour (Schrems III). Conséquence pratique : pour les données réellement sensibles (santé, secret bancaire CH, secret professionnel), beaucoup d'entreprises CH choisissent des providers strictement européens ou suisses (Infomaniak, Exoscale, Swisscom Cloud) pour éviter le CLOUD Act.
