🔑 ATT&CK — la lingua franca de la cybersécurité
MITRE ATT&CK (Adversarial Tactics, Techniques, and Common Knowledge) est une base de connaissances publique maintenue par MITRE Corporation (ONG américaine financée par le gouvernement) qui décrit comment les attaquants opèrent réellement, étape par étape. Lancé en 2013 (publié 2015), ATT&CK est devenu le langage commun de tous les acteurs cyber : SOC, Threat Hunters, Red Teams, éditeurs EDR/SIEM, vendors, gouvernements, chercheurs académiques. Quand un rapport CISA dit « APT29 a utilisé T1059.001 puis T1003.001 », tout le monde comprend exactement ce qui s'est passé. C'est la pierre angulaire du Threat-Informed Defense.

Les trois matrices ATT&CK
🏢 Enterprise (la principale)

14 tactiques · 216 techniques · 475 sub-techniques (v18, oct 2025)

Couvre Windows, macOS, Linux, Cloud (AWS/Azure/GCP/M365), Network, Containers, ESXi.

Inclut les phases pré-compromission depuis v8 (2020) : Reconnaissance + Resource Development (anciennement PRE-ATT&CK).

C'est celle utilisée par 95 % des SOC.

📱 Mobile

12 tactiques (sans Reconnaissance ni Resource Development).

iOS + Android. Techniques spécifiques : abus d'accessibilité, cassage du sandbox app, MFA bypass via SIM swap, etc.

Moins utilisé en SOC traditionnel mais essentiel pour MDR/XDR mobile.

🏭 ICS (Industrial Control Systems)

12 tactiques dont 2 spécifiques : Inhibit Response Function + Impair Process Control.

Cible les SCADA, PLC, HMI, RTU. Référencée par les rapports d'attaques OT (Industroyer, Stuxnet, Triton, Pipedream/Incontroller).

Utile pour le secteur énergie / industrie / eau.

⭐ Pourquoi ATT&CK > IOC : bloquer un hash = inutile (l'attaquant recompile). Bloquer un comportement (T1003.001 = lire lsass.exe) = bloquer Mimikatz, ProcDump, comsvcs.dll, MiniDumpWriteDump, secretsdump.py… tous d'un coup. C'est la promesse de la défense fondée sur ATT&CK : faire mal à l'attaquant, pas juste à un outil.
🎯 Les 14 Tactiques Enterprise — la kill chain ATT&CK
Les tactiques sont des « catégories de pourquoi ». Elles ne sont pas strictement séquentielles — un attaquant peut sauter d'une à l'autre, revenir en arrière, ou en ignorer plusieurs. Mais l'ordre canonique de la matrice (de gauche à droite) reflète l'évolution typique d'une intrusion.

⚙️ Anatomie d'une fiche technique ATT&CK
Chaque technique a sa page dédiée sur attack.mitre.org qui suit une structure normalisée. Cette structure est la même pour toutes les 216 techniques — la connaître permet de naviguer efficacement.
Structure d'une fiche technique
📋 Métadonnées
  • ID (T1003), Sub-techniques (8 sous-techniques pour T1003)
  • Tactic(s) (Credential Access)
  • Platforms (Windows, Linux, macOS…)
  • Permissions Required (Administrator, SYSTEM)
  • Data Sources (Process: Process Access, File: File Access…)
  • Defenses Bypassed (Anti-virus, Application Control)
  • Contributors (chercheurs)
  • Version + last modified
📖 Contenu narratif
  • Description détaillée (1–3 paragraphes)
  • Procedure Examples — outils et groupes connus qui l'utilisent (avec hyperliens)
  • Mitigations (M1xxx) — contrôles de sécurité applicables
  • Detection Strategies (v18+) — stratégies de détection structurées
  • Analytics (v18+) — règles de détection concrètes (auparavant « Data Sources »)
  • References — liens vers les rapports originaux

💡 Pourquoi les sous-techniques importent : en SOC, dire « on a vu du T1003 » est vague. Dire « on a vu du T1003.006 (DCSync) » donne immédiatement le mode opératoire (réplication frauduleuse), la signature (event 4662 sur DC + GUID 1131f6aa pour Replicating Directory Changes) et la mitigation (auditer Domain Replication Permissions). Mapping d'une intrusion sur ATT&CK — méthode CISA
Best Practices for MITRE ATT&CK® Mapping (CISA, mise à jour 2023) recommande deux approches complémentaires :
Approche 1 — Top-down (Data Source)
  1. Identifier la source de données disponible (ex : EVTX 4688)
  2. Lister les techniques observables avec cette source
  3. Filtrer celles qui correspondent au comportement vu
  4. Confirmer le mapping par un second indicateur
Approche 2 — Bottom-up (artefact)
  1. Partir d'un artefact concret (Mimikatz.exe sur le disque)
  2. Chercher le software dans ATT&CK (S0002 Mimikatz)
  3. Lister les techniques associées
  4. Garder celles dont l'usage est confirmé dans cet incident
⚠️ Pièges classiques de mapping :
  1. Sur-mapper — assigner T1059.001 à chaque exécution PowerShell, même légitime. Mapping = comportement adversaire confirmé, pas usage normal.
  2. Sous-mapper — se contenter de la technique parent (T1003) sans préciser la sous-technique (T1003.001) quand on a l'info.
  3. Mapper l'outil au lieu du comportement — « mimikatz.exe a été vu » ≠ technique. C'est ce qu'il a fait (T1003.001) qui se mappe.
  4. Confondre Tactic et Technique — TA0006 est une tactique (Credential Access), T1003 est la technique. ID préfixé TA ou T.
Sigma — règles de détection portables liées à ATT&CK
Sigma (github.com/SigmaHQ/sigma) est le standard ouvert pour écrire des règles de détection en YAML, traduisibles automatiquement vers Splunk, Elastic, Sentinel, Chronicle, QRadar, etc. Chaque règle Sigma est mappée sur une ou plusieurs techniques ATT&CK via les champs tags. 
title: Mimikatz Command Line via PowerShell
status: stable
description: Detects mimikatz invocation via PowerShell
references:
    - https://attack.mitre.org/techniques/T1003/001/
tags:
    - attack.credential-access
    - attack.t1003.001
logsource:
    product: windows
    service: powershell
    definition: 'Requires Script Block Logging EID 4104'
detection:
    selection:
        EventID: 4104
        ScriptBlockText|contains:
            - 'sekurlsa::logonpasswords'
            - 'lsadump::dcsync'
            - 'Invoke-Mimikatz'
            - 'AmsiUtils'
            - 'amsiInitFailed'
    condition: selection
falsepositives:
    - Penetration tests authorized
level: high
🔧 Pourquoi tout enquêteur DFIR doit maîtriser ATT&CK
ATT&CK n'est pas seulement un outil pour SOC — c'est un outil de communication qui structure le rapport forensique, harmonise le vocabulaire devant un magistrat, et permet la comparaison rigoureuse entre incidents. En 2026, un rapport DFIR sérieux doit contenir un mapping ATT&CK des TTPs observés.
Cas d'usage 1 — Rapport forensique judiciaire (CH)
Pratique recommandée pour les expertises CAS-IN : dans le rapport au Ministère public, inclure une section « Cartographie des actions de l'auteur sur la matrice MITRE ATT&CK » avec les techniques observées et les preuves (IOC) qui les supportent. Avantages :
  • Vocabulaire internationalement reconnu par les autorités étrangères (entraide pénale)
  • Pas d'ambiguïté technique pour un magistrat non-IT
  • Permet de comparer le mode opératoire avec d'autres dossiers ouverts
  • Renforce la crédibilité scientifique de l'expertise (méthodologie traçable)

Quelle est la différence entre tactic et technique dans MITRE ATT&CK, et pourquoi cette distinction compte-t-elle pour un rapport DFIR ?
MITRE ATT&CK · Niveau : facile
Une tactic répond à « pourquoi » (objectif tactique de l'adversaire) — il y en a 14 dans Enterprise, identifiées TA0001–TA0043. Une technique répond à « comment » (la méthode utilisée) — il y en a 216 dans Enterprise (v18), identifiées T1xxx. Plusieurs techniques peuvent servir la même tactique. Exemple : pour la tactic Credential Access (TA0006), un attaquant peut utiliser T1003 (OS Credential Dumping), T1110 (Brute Force), T1558 (Steal/Forge Kerberos Tickets), etc.

Pour un rapport DFIR, la distinction compte parce qu'elle permet de structurer la narration : « L'attaquant a cherché à obtenir des credentials [TA0006], en utilisant spécifiquement le dump LSASS [T1003.001] via Mimikatz ». Le magistrat / le RSSI comprend la logique stratégique de l'attaque, pas juste une liste d'outils. C'est aussi la base pour comparer cet incident à d'autres : « Ce mode opératoire est compatible avec FIN12 (G0102) qui combine T1566.001 + T1059.001 + T1003.001 + T1486 ».
Vous êtes en SOC. Une alerte signale powershell.exe -nop -w hidden -enc SQBFAFg…. Mappez cette observation sur ATT&CK le plus précisément possible et expliquez pourquoi vous choisissez ce niveau de précision.
MITRE ATT&CK · Niveau : moyen
Mapping correct (du plus général au plus précis) :
  • Tactic : TA0002 — Execution
  • Technique : T1059 — Command and Scripting Interpreter
  • Sous-technique : T1059.001 — PowerShell
  • Tactic complémentaire : TA0005 — Defense Evasion
  • Technique : T1027 — Obfuscated Files or Information (à cause du -EncodedCommand)
On choisit T1059.001 plutôt que T1059 parce qu'on dispose de l'information précise (PowerShell, pas cmd.exe ni bash). Toujours descendre au niveau de sub-technique quand l'évidence le permet. Cela permet (1) de chercher si des groupes connus (FIN7, APT29, Wizard Spider) utilisent T1059.001 pour prioriser le hunt, (2) de mapper la mitigation correcte (M1042 PowerShell logging, M1038 Execution Prevention via WDAC), (3) d'enrichir une règle Sigma attack.t1059.001. Mapper seulement TA0002 sans technique = sous-mapping et perd toute la valeur du framework.
