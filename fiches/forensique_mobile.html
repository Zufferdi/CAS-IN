🔑 Principe — Le mobile = le coffre-fort numérique d'une vie
Le téléphone mobile est aujourd'hui l'objet le plus dense en preuves numériques : localisation, communications, photos, contacts, applications, traces de navigation, transactions crypto. Sa forensique se distingue radicalement du forensique PC : chiffrement par défaut (iOS depuis 2014, Android depuis 2017), Secure Enclave matériel, cycle de vie court (~3 ans), écosystèmes fermés. Cellebrite, GrayKey et Magnet AXIOM dominent le marché. Le critère discriminant : avoir le bon outil au bon moment pour le bon device, avant qu'un patch ne ferme la faille exploitée.
🗝️ 1. Les 4 niveaux d'extraction

Toute extraction mobile se classe sur une échelle de complétude croissante, qui dépend de l'OS, du modèle, de l'état du device (verrouillé ou non) et des outils disponibles.

Niveau Données obtenues Difficulté
1. Manual examinationCaptures écran, photos du device. Pas d'extraction réelle.🟢 Faible
2. Logical extractionDonnées accessibles via API standard (contacts, SMS, photos, journal d'appels)🟡 Standard
3. File System / Advanced LogicalSystème de fichiers complet, équivalent backup iTunes étendu (incluant SQLite apps tierces)🟠 Moyenne
4. Full File System (FFS) / PhysicalDump complet de la NAND, y compris zones supprimées, keychain, attributs sécurité🔴 Élevée
📚 BFU vs AFU — la distinction critique : BFU (Before First Unlock) = le device a été redémarré et n'a pas encore été déverrouillé une seule fois — la plupart des données sont chiffrées et inaccessibles. AFU (After First Unlock) = le device a été déverrouillé au moins une fois depuis le démarrage — les clés de chiffrement sont en mémoire, permettant beaucoup plus d'accès. En perquisition, NE PAS ÉTEINDRE un device trouvé AFU. Mettre en mode avion + Faraday bag immédiatement.
🍏 2. iOS — l'écosystème fermé

Apple a construit un modèle de sécurité matériel-logiciel extrêmement intégré, qui complique fortement l'extraction.

Composant Rôle
Secure Enclave Processor (SEP)Co-processeur ARM dédié, isolé du SoC principal. Stocke les clés de chiffrement et empreintes biométriques. Inaccessible logiciellement.
File-based encryptionChaque fichier chiffré individuellement (Data Protection API : NSFileProtectionComplete, etc.)
KeychainStockage chiffré des mots de passe et clés. Extraction nécessite full file system.
iCloud syncPhotos, contacts, messages synchronisés cloud. Récupérables via Apple (warrant) ou backup iCloud.
Lockdown Mode (iOS 16+)Mode renforcé activable par l'utilisateur, bloque la plupart des vecteurs d'extraction
USB Restricted ModeDésactive le port Lightning/USB-C pour data après ~1h verrouillé — complique drastiquement Cellebrite/GrayKey

L'exploit checkm8 (publié par axi0mX en septembre 2019) reste l'un des outils fondamentaux pour la forensique iOS : exploite une faille du bootrom (donc inpatchable par mise à jour logicielle). Couvre les SoC A5 à A11, soit iPhone 4s à iPhone X. Permet un Full File System en mode BFU si le passcode est connu. Pour les iPhone récents (A12+ depuis iPhone XS, 2018), seul Cellebrite Premium ou GrayKey offrent des solutions — qui dépendent du firmware actuel et sont en course continue avec Apple.

⚠️ La course aux exploits iOS : Apple patche, Cellebrite/Grayshift trouvent — le cycle se répète à chaque version iOS. Le forensique iOS est une fenêtre temporelle : un device iPhone 15 saisi aujourd'hui sera peut-être extractible la semaine prochaine (nouveau build Cellebrite), ou jamais (faille trop coûteuse à exploiter ou patchée plus vite que découverte). Prioriser les saisies de devices récents.
🤖 3. Android — la fragmentation

Android est un écosystème radicalement plus hétérogène : centaines de constructeurs, des dizaines de versions actives, des sécurités matérielles variables (Samsung Knox, Pixel Titan M, Huawei HiSec, etc.). Le forensique Android est donc moins universel que iOS.

Mécanisme Impact forensique
FBE (File-Based Encryption)Standard depuis Android 7 (2016) — chaque fichier chiffré séparément. Avant : FDE (Full-Disk Encryption).
Verified BootVérifie l'intégrité du firmware au boot. Bootloader verrouillé par défaut.
TEE (Trusted Execution Environment)Zone sécurisée ARM TrustZone, équivalent du SEP iOS — stocke clés et biométrie
Samsung KnoxSurcouche sécurité Samsung, e-fuse au bootloader unlock — détectable post-mortem
Bootloader unlockMode root via fastboot — possible sur certains modèles, détruit les données dans le process
ADB debuggingSi activé par l'utilisateur, facilite extraction logique. Souvent désactivé.

Méthodes d'extraction Android par ordre de complétude :

  • MTP / backup standard — données utilisateur visibles (médias surtout)
  • ADB pull (si debug ON) — accès limité aux espaces non sandbox
  • Cellebrite/MSAB exploit propriétaire — varient par constructeur, parfois full FS
  • Chip-off / ISP — méthode physique destructive, dump direct de la NAND (eMMC/UFS) — devient inopérante avec FBE Android moderne car les données restent chiffrées
  • JTAG — interface debug processeur, devenu rare (devices récents la désactivent)

📚 Limites des outils propriétaires : Cellebrite et GrayKey sont controversés — accès LE, mais cas documentés de revente sur eBay (~100 USD pour des UFED obsolètes 2019-2020). Ils ne sont pas omniscients : un device récent + iOS up-to-date + Lockdown Mode + USB Restricted Mode = souvent inextractible même par Cellebrite Premium. Documenter les limites de l'outil dans le rapport est crucial pour la défense.
📋 5. Workflow forensique mobile — bonnes pratiques
① Saisie — sur les lieux : photo de l'écran si déverrouillé, mode avion immédiat, Faraday bag (sac blindé) pour bloquer signaux. Ne JAMAIS éteindre un device AFU.
② Documentation — IMEI, modèle, OS, état (verrouillé/déverrouillé, BFU/AFU), niveau de batterie, fissures éventuelles (chip-off impossible si chip endommagé).
③ Chaîne de garde — scellement immédiat, scellés numérotés, registre.
④ Préparation labo — Faraday box, chargement via Faraday cable (charge sans signal).
⑤ Choix de la méthode — du moins au plus invasif : logical → advanced logical → FFS → physical/chip-off. Documenter chaque tentative.
⑥ Extraction — calcul hash SHA-256 du dump immédiatement après extraction. Conservation copie sur stockage isolé.
⑦ Analyse — Physical Analyzer / AXIOM / Oxygen pour parsing structuré. Carving manuel pour données effacées (Recoverable + Free space).
⑧ Rapport — horodaté, signé numériquement, exportable en PDF + CSV. Inclure les limites et hypothèses.
🔍 6. Sources de preuve à ne pas oublier
  • Applications de messagerie chiffrée — WhatsApp (SQLite + clés), Signal (SQLCipher), Telegram (chats secrets jamais sauvegardés), Threema, Wire
  • Notes et journaux — Apple Notes (peut être chiffré), Google Keep, OneNote — données souvent oubliées
  • Health / Fitness — Apple Health, Google Fit, Samsung Health — géolocalisation indirecte, pas (timing/positions)
  • Wallet et NFC — Apple Wallet (cartes), Google Pay, Samsung Pay — historique transactions, traces de paiement
  • Crypto wallets — Trust Wallet, MetaMask, Coinbase Wallet — adresses, transactions, seed phrase ?
  • Photos et vidéos — EXIF, géolocalisation, dates, miniatures système (caches Photos.app)
  • Calendrier et contacts — base de données critique de connexions sociales
  • Knowledge_C / biome.sqlite (iOS) — base de données système qui historise l'usage des apps (très riche)
  • Wi-Fi connus — Plist de SSID connectés, localisation indirecte
  • Significant Locations (iOS) — historique des lieux fréquentés
  • Carrier files — IMSI, IMEI, métadonnées télécom

Jurisprudence TFLe mobile peut être perquisitionné mais l'accès au contenu chiffré nécessite mandat spécifique. Refus de fournir le code = silence licite (CEDH).
⚖️ Droit au silence vs déverrouillage : la jurisprudence européenne (CEDH) protège le droit au silence — la personne ne peut être contrainte de fournir son code de déverrouillage. Mais l'utilisation de la biométrie (empreinte digitale, Face ID) sur la personne saisie peut être ordonnée par un magistrat selon la jurisprudence cantonale (sujet à débat juridique constant). Pratique : si le suspect a les empreintes enregistrées sur le device, présenter le doigt rapidement avant déverrouillage forcé impossible.
⚠️ 8. Anti-patterns courants
🎯 Anti-pattern #1 — éteindre le device AFU : si trouvé déverrouillé, ne JAMAIS éteindre. Le passer en mode avion, brancher au chargeur, Faraday bag, transport vers labo en restant alimenté.
🎯 Anti-pattern #2 — connecter au PC perso : iTunes/Finder peut déclencher des changements (synchronisations, mises à jour iOS, dernier accès). Toujours utiliser une station forensique isolée.
🎯 Anti-pattern #3 — confondre déverrouillage et extraction : déverrouiller un device permet une logical extraction, mais pas un FFS. Pour le FFS sur iPhone récent, il faut Cellebrite Premium ou GrayKey en plus du passcode.
🎯 Anti-pattern #4 — ignorer les apps tierces : un dump FFS contient des centaines de SQLite/Realm d'applications. Les outils auto-parsing en couvrent les plus connues (WhatsApp, Telegram, Signal, Instagram, TikTok…). Pour les apps spécifiques (banques, crypto wallets, apps locales CH), parsing manuel ou scripts iLEAPP/ALEAPP nécessaires.
🎯 Anti-pattern #5 — négliger le cloud : le device mobile est souvent synchronisé. Un device verrouillé inextractible peut quand même livrer ses secrets via réquisition Apple iCloud / Google (avec entraide internationale si nécessaire).
