💬 Messagerie chiffrée

Messagerie Instantanée Forensique

Extraction et analyse des artefacts WhatsApp, Signal et Telegram : bases SQLite chiffrées, clés de déchiffrement, Signal Protocol, cadre légal suisse (LSCPT) et limites de l'end-to-end.

🎯 Panorama des trois applications
Chaque messagerie stocke l'historique localement dans une base SQLite — c'est la cible principale d'une extraction forensique.
🟢
WhatsApp
E2EE · Signal Protocol · ~2 Md users
Base : msgstore.db.crypt15
Chiffrement : AES-GCM · clé 32 octets
Clé : /data/data/com.whatsapp/files/key (Android, root requis)
Backups : Google Drive (Android) / iCloud (iOS), chiffrés E2E depuis 2021 (opt-in).
🔵
Signal
E2EE · Signal Protocol · open source
Base : signal.db (SQLCipher, AES-256-CBC)
Clé : dérivée du Signal PIN + Android Keystore / iOS Keychain
Backups : chiffrés localement par phrase de 30 mots (jamais cloud).
Sealed Sender : expéditeur masqué côté serveur.
🔷
Telegram
MTProto · E2EE optionnelle
Chats classiques : pas chiffrés E2E — déchiffrables par Telegram
Secret Chats : E2E, device-to-device, pas de cloud
Base : cache4.db (Android) / db.sqlite (Desktop)
Cloud sync : récupération possible via login depuis nouvel appareil.

🔓 Déchiffrement — ordre opérationnel

🟢 WhatsApp · msgstore.db.crypt15

Méthode classique (Android root) :

  • Extraire /data/data/com.whatsapp/files/key (ou encrypted_backup.key depuis Keystore)
  • Récupérer msgstore.db.crypt15 dans /sdcard/WhatsApp/Databases/
  • Outil : wa-crypt-tools (Python, open source) ou WhatsApp Viewer
  • Si pas de root : extraction ADB backup (bloquée depuis Android 6+), ou chip-off
  • iOS : iTunes backup non chiffré + ChatStorage.sqlite directement

🔵 Signal · SQLCipher

Signal utilise SQLCipher avec une clé dérivée du Signal PIN.

  • Sans le PIN : déchiffrement impossible en pratique (PBKDF2 + Keystore)
  • Si l'appareil est déverrouillé : dump de la RAM avec la clé en mémoire (outil volatility + plugin custom)
  • Desktop : la clé est stockée dans config.json — lisible si l'OS est accessible
  • Sealed Sender complique l'attribution côté serveur — pas de logs récupérables auprès de Signal Foundation

🔷 Telegram · Chats classiques

Chats cloud = non-E2E — récupération via entraide :

  • Cloud non-chiffré côté Telegram (serveurs à Dubai, Londres) — accessible via MLAT, mais Telegram refuse quasi toutes les requêtes sauf terrorisme avéré
  • Base locale cache4.db : non chiffrée, SQLite standard → lecture directe avec DB Browser
  • Réauthentification sur nouveau device : possible sans le téléphone d'origine si SIM récupérée (risque d'altération de preuve)

🔷 Telegram · Secret Chats

Les Secret Chats sont E2E et jamais sur serveur.

  • Uniquement présents sur les deux devices qui ont initié la conversation
  • Si le mode « self-destruct » est activé : message effacé des deux côtés à expiration — récupération en slack space SQLite (pages WAL, freelist)
  • Outil : sqlite-parser / undark pour carving SQLite
🔬 Tables SQLite critiques (WhatsApp / msgstore.db)
Table Contenu forensique Champs clés
messages Tous les messages envoyés/reçus, texte + métadonnées _id, key_remote_jid, timestamp, data, media_url, status
chat_list Liste des conversations et groupes key_remote_jid, subject, creation
group_participants Membres des groupes avec rôles gjid, jid, admin
messages_quotes Messages cités (réponses) — peut contenir des messages supprimés key_id, data
deleted_messages Messages supprimés côté utilisateur — parfois toujours présents _id, original_timestamp
Messages supprimés : même après « Delete for everyone » dans WhatsApp, des traces subsistent : notifications Android (NotificationHistory), messages_quotes (citations), slack SQLite (pages libérées mais non réécrites), pages WAL non-checkpointées. Toujours carver la base avec undark ou sqlite-dissect.
🇨🇭 Cadre légal suisse
⚖️ LSCPT · CPP · ORVN

LSCPT (RS 780.1) : Loi sur la surveillance de la correspondance par poste et télécommunication — régit l'obtention des données de communication auprès des opérateurs et fournisseurs de services dérivés (OSCom).


Art. 269 CPP : surveillance de la correspondance par télécommunication en temps réel — réservée aux infractions graves du catalogue (art. 269 al. 2). Autorisation par le Tmc (Tribunal des mesures de contrainte).


Art. 273 CPP : données rétroactives (qui, quand, avec qui) — durée de conservation obligatoire : 6 mois pour les opérateurs.


Limite E2E : Signal et WhatsApp ne transmettent pas le contenu à l'OSCom. Seules les métadonnées (heure de connexion, IP, numéro inscrit) sont accessibles via LSCPT. Le contenu chiffré n'est récupérable qu'au terminal (saisie du téléphone).


Art. 280 CPP : utilisation d'appareils techniques de surveillance — inclut les IMSI-catchers et l'installation de logiciels de surveillance (Govware) autorisés depuis 2018.

  • Oxygen Forensic Detective — forte couverture Telegram et apps chinoises (WeChat)

🆓 Open source / gratuits

  • WhatsApp Viewer — GUI Windows pour msgstore.db
  • telegram-history-dump — export JSON via API
  • ALEAPP / iLEAPP — Android/iOS Logs, Events, and Protobuf Parser (Python)
  • undark / sqlite-dissect — carving SQLite (messages supprimés)
📋 Mémo — à vérifier sur chaque saisie
  • Mode avion immédiat + Faraday → empêche les commandes « Delete for everyone » à distance
  • Vérifier si le compte est lié à d'autres appareils (WhatsApp Web, Signal Desktop, Telegram multi-device)
  • Capture de la RAM avant extinction : clé SQLCipher parfois présente en clair
  • Backups locaux .crypt14 sur /sdcard/ — souvent plus anciens que msgstore.db actif
  • Sauvegardes cloud (Google Drive / iCloud) : requête LSCPT à l'opérateur + entraide au provider (art. 18 Convention de Budapest)
  • Timeline : corréler avec usage_stats Android et KnowledgeC.db iOS (activité applicative)
  • Toujours hacher les bases extraites avant décryptage — garder une copie brute chiffrée
