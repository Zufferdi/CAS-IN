💬 E2EE — La fin de l'écoute classique
Avec le chiffrement de bout en bout (E2EE), seuls l'expéditeur et le destinataire peuvent lire les messages. Les serveurs de l'opérateur (WhatsApp, Signal) ne voient que des paquets chiffrés. Conséquence majeure pour la procédure pénale suisse : la surveillance LSCPT classique (RT) ne fonctionne plus sur le contenu. L'ordonnance art. 269 CPP, même autorisée par le TMC, ne récupérera que des métadonnées (qui parle à qui, quand, depuis quelle IP) — jamais le contenu lui-même. Conséquence forensique : pour accéder au contenu, il faut saisir le terminal physique (smartphone) du suspect et déchiffrer la base SQLite locale. C'est pourquoi l'extraction mobile (Cellebrite, GrayKey, AXIOM) est devenue le pilier des enquêtes contre criminalité organisée et terrorisme. Le Signal Protocol (utilisé par Signal et WhatsApp) reste à ce jour cryptographiquement intact — seules les failles d'implémentation ou l'accès au terminal permettent l'extraction.

🎯 Panorama des trois applications
Chaque messagerie stocke l'historique localement dans une base SQLite — c'est la cible principale d'une extraction forensique.
🟢 WhatsApp

E2EE · Signal Protocol · ~2 Md users

  • Base : msgstore.db.crypt15
  • Chiffrement : AES-GCM · clé 32 octets
  • Clé : /data/data/com.whatsapp/files/key (Android, root)
  • Backups : Google Drive (Android) / iCloud (iOS), chiffrés E2E depuis 2021 (opt-in)
🔵 Signal

E2EE · Signal Protocol · open source

  • Base : signal.db (SQLCipher AES-256-CBC)
  • Clé : dérivée du Signal PIN + Android Keystore / iOS Keychain
  • Backups : chiffrés localement par phrase de 30 mots (jamais cloud)
  • Sealed Sender : expéditeur masqué côté serveur
🔷 Telegram

MTProto · E2EE optionnelle

  • Chats classiques : NON chiffrés E2E — déchiffrables côté Telegram
  • Secret Chats : E2E, device-to-device, jamais sur cloud
  • Base : cache4.db (Android) / tdata/ (Desktop, format propriétaire)
  • Cloud sync : récupération possible via login depuis nouvel appareil

🔓 Déchiffrement — Ordre opérationnel par app
🟢 WhatsApp · msgstore.db.crypt15

Méthode classique (Android root) :

  • Extraire /data/data/com.whatsapp/files/key (ou encrypted_backup.key depuis Keystore)
  • Récupérer msgstore.db.crypt15 dans /sdcard/WhatsApp/Databases/
  • Outil : wa-crypt-tools (Python, open source) ou WhatsApp Viewer
  • Si pas de root : extraction ADB backup (bloquée depuis Android 6+), ou chip-off
  • iOS : iTunes backup non chiffré + ChatStorage.sqlite directement
🔵 Signal · SQLCipher

Signal utilise SQLCipher avec une clé dérivée du Signal PIN.

  • Sans le PIN : déchiffrement impossible en pratique (PBKDF2 + Keystore)
  • Si appareil déverrouillé : dump RAM avec la clé en mémoire (Volatility + plugin custom)
  • Desktop : la clé est stockée dans config.json — lisible si l'OS est accessible
  • Sealed Sender complique l'attribution côté serveur — pas de logs récupérables auprès de Signal Foundation
🔷 Telegram · Chats classiques

Chats cloud = non-E2E — récupération via entraide :

  • Cloud non-chiffré côté Telegram (serveurs à Dubai, Londres) — accessible via MLAT, mais Telegram refuse quasi toutes les requêtes sauf terrorisme avéré
  • Base locale cache4.db : non chiffrée, SQLite standard → lecture directe avec DB Browser
  • Réauthentification sur nouveau device : possible sans le téléphone d'origine si SIM récupérée (risque d'altération de preuve)
🔷 Telegram · Secret Chats

Les Secret Chats sont E2E et jamais sur serveur.

  • Uniquement présents sur les deux devices qui ont initié la conversation
  • Si le mode « self-destruct » est activé : message effacé des deux côtés à expiration — récupération en slack space SQLite (pages WAL, freelist)
  • Outils : sqlite_dissect / undark pour carving SQLite

🇨🇭 Cadre légal suisse — LSCPT & CPP
⚖️ LSCPT · CPP · Convention de Budapest

LSCPT (RS 780.1) : Loi sur la surveillance de la correspondance par poste et télécommunication — régit l'obtention des données de communication auprès des opérateurs et fournisseurs de services dérivés (OSCom).

Art. 269 CPP : surveillance de la correspondance par télécommunication en temps réel (RT) — réservée aux infractions graves du catalogue (art. 269 al. 2 CPP). Autorisation par le Tmc (Tribunal des mesures de contrainte).

Art. 273 CPP : données rétroactives (RR) — qui, quand, avec qui. Durée de conservation obligatoire pour les opérateurs : 6 mois.

⚠️ Limite E2E : Signal et WhatsApp ne transmettent pas le contenu à l'OSCom. Seules les métadonnées (heure de connexion, IP, numéro inscrit) sont accessibles via LSCPT. Le contenu chiffré n'est récupérable qu'au terminal (saisie du téléphone).

Art. 280 CPP : utilisation d'appareils techniques de surveillance — inclut les IMSI-catchers et l'installation de logiciels de surveillance (Govware) autorisés depuis 2018.

Convention de Budapest art. 18 : entraide internationale pour obtenir des données de service auprès de prestataires étrangers (Apple iCloud, Google Drive, Microsoft, Meta).

📋 Mémo — Procédure type lors d'une saisie de smartphone
  • Mode avion immédiat + Faraday — empêche les commandes « Delete for everyone » à distance et le wipe Find My iPhone/Android
  • Vérifier si le compte est lié à d'autres appareils : WhatsApp Web (icône ordinateur), Signal Desktop, Telegram multi-device — ces appareils peuvent recevoir les messages aussi
  • Capture de la RAM avant extinction : la clé SQLCipher (Signal) est parfois présente en clair en RAM pendant que l'app tourne
  • Backups locaux .crypt14 sur /sdcard/ — souvent plus anciens que msgstore.db actif (peut révéler messages supprimés depuis)
  • Sauvegardes cloud (Google Drive / iCloud) : requête LSCPT à l'opérateur + entraide au provider (art. 18 Convention de Budapest)
  • Timeline : corréler avec usage_stats Android et knowledgeC.db iOS (activité applicative) — preuve qu'un message a été lu/écrit même sans contenu
  • Toujours hacher SHA-256 les bases extraites avant décryptage — garder une copie brute chiffrée (preuve d'intégrité)
  • ⚠️ Ne JAMAIS allumer le téléphone sans Faraday : message « Delete for everyone » peut arriver et tout supprimer
🧠 Testez-vous
Une ordonnance art. 269 CPP est délivrée pour surveiller un suspect qui utilise WhatsApp. Le service SCPT vous transmet les données. Que pouvez-vous lire ?LSCPT · Niveau : facile
Vous lisez les métadonnées, PAS le contenu. WhatsApp utilise le Signal Protocol (E2EE) — Meta/WhatsApp ne possède pas les clés et ne peut pas déchiffrer. Le service SCPT ne peut transmettre que ce que l'opérateur capture sur le réseau : (1) Heures de connexion à WhatsApp, (2) IP du suspect, (3) Volumes de données (qui révèlent des conversations actives mais pas leur contenu). Pour le contenu, deux options : (a) Saisir physiquement le téléphone et extraire msgstore.db, (b) Govware art. 280 CPP (logiciel de surveillance installé sur l'appareil — autorisation TMC très stricte). C'est la grande révolution forensique de la dernière décennie : la surveillance classique ne suffit plus, il faut accéder au terminal.
Vous saisissez un téléphone Android. WhatsApp est ouvert. Que faire dans l'ordre ?Procédure terrain · Niveau : moyen
Ordre opérationnel : (1) Faraday immédiat — sac/cage de Faraday pour bloquer toutes les communications (4G/5G/Wi-Fi/Bluetooth). Empêche un complice d'envoyer « Delete for everyone » qui effacerait les messages des deux côtés. (2) NE PAS éteindre / verrouiller — sinon iOS/Android passera en état « After First Unlock » → certains chiffrements deviennent inactifs et plus difficiles à casser plus tard. (3) Photographier l'écran allumé tel quel (preuve de contexte). (4) Mode avion via les paramètres (sans déverrouiller si possible — accessible depuis l'écran de verrouillage Android). (5) Capturer la RAM via UFED/AXIOM si possible — clés SQLCipher peuvent y être en clair. (6) Branchement chargeur — éviter coupure batterie. (7) Transport en Faraday vers labo. (8) Au labo : extraction logique d'abord (avec ADB/iTunes), puis physique si nécessaire (Cellebrite, GrayKey).
Vous trouvez la base msgstore.db WhatsApp. Le suspect a utilisé « Delete for everyone » sur 50 messages. Sont-ils définitivement perdus ?Récupération · Niveau : moyen
Probablement pas ! Plusieurs angles d'attaque : (1) Pages libres SQLite — quand un message est supprimé, sa page est marquée libre dans la freelist mais le contenu reste jusqu'à VACUUM. undark msgstore.db ou sqlite_dissect peut récupérer ces enregistrements. (2) WAL non-checkpointé — msgstore.db-wal contient peut-être des écritures récentes qui incluent ces messages. (3) Table messages_quotes — si quelqu'un a cité le message dans une réponse, le contenu original est dupliqué dans cette table (souvent oublié par les attaquants). (4) Notifications Android dans NotificationHistory ou com.android.systemui/databases/ — peuvent contenir le texte du message qui s'est affiché en notif. (5) Backup local .crypt14 sur /sdcard/WhatsApp/Databases/ daté d'avant la suppression. (6) Backup cloud Google Drive via entraide. (7) Le téléphone du destinataire peut encore avoir une copie si « Delete for everyone » n'a pas réussi (réception après expiration de la fenêtre).
Différence entre Telegram chats classiques et Secret Chats ?Telegram · Niveau : facile
Chats classiques (cloud) : stockés sur les serveurs Telegram à Dubaï/Londres, chiffrés côté serveur avec une clé que Telegram possède (chiffrement client-to-server, pas E2EE). Theoriquement déchiffrables par Telegram sur ordre judiciaire. En pratique, Telegram refuse quasi toutes les requêtes sauf cas avérés de terrorisme. Synchronisés sur tous les appareils. Secret Chats : E2EE véritable (Diffie-Hellman 2048 bits + AES-256), device-to-device, jamais sur le cloud, uniquement sur les deux téléphones qui ont initié le chat. Pas synchronisés multi-device. Self-destruct possible. Conséquence forensique : (1) chats classiques = récupérables via cloud sync sur nouveau device avec SIM/numéro, (2) Secret Chats = uniquement extraction terminal des deux interlocuteurs. Important : par défaut, Telegram n'utilise PAS Secret Chats — il faut explicitement les activer (icône cadenas). 99% des conversations Telegram sont des chats classiques.
🎓 Exam Tip — Messagerie Instantanée Forensique

Signal Protocol (Open Whisper Systems) = E2EE de référence · X3DH + Double Ratchet

Utilisé par : Signal, WhatsApp, Messenger (opt-in), Skype, Google Messages (RCS)

WhatsApp : E2EE par défaut · base msgstore.db.crypt15 · clé dans /data/data/com.whatsapp/files/key

Signal : E2EE + SQLCipher · clé dérivée du PIN + Keystore · Sealed Sender (anonymise expéditeur)

Telegram : chats classiques NON E2EE · seuls les Secret Chats le sont

Trois points d'attaque forensique :

  1. Terminal (saisie + extraction Cellebrite/AXIOM/GrayKey)

  2. LSCPT métadonnées (qui parle à qui, quand) — pas le contenu E2EE

  3. RAM / Govware (clés en clair pendant session active)

Cadre légal CH : LSCPT (RS 780.1) · art. 269 CPP (RT) · art. 273 CPP (RR · 6 mois) · art. 280 CPP (Govware)

Saisie type : Faraday immédiat → ne pas verrouiller → photographier → mode avion → RAM dump → transport

Backups : Google Drive (Android), iCloud (iOS) — depuis 2021 : E2E opt-in WhatsApp

Outils : Cellebrite UFED, Magnet AXIOM, Oxygen Detective, MSAB XRY, GrayKey, ALEAPP/iLEAPP, wa-crypt-tools

Carving messages supprimés : undark, sqlite_dissect, table messages_quotes, NotificationHistory, backups .crypt14
