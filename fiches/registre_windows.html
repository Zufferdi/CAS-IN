🗝 Le Registre Windows — Base de données centrale de l'OS
Le Registre Windows est une base de données hiérarchique qui stocke la totalité de la configuration du système d'exploitation : paramètres machine, paramètres utilisateurs, paramètres applications, autoruns, services, périphériques connectés, historique de navigation, et bien plus. Introduit avec Windows 95 pour remplacer les anciens fichiers .ini, il est aujourd'hui le cœur névralgique de Windows. Pour le forensiste, c'est une mine d'or : pratiquement toute activité utilisateur ou système laisse une trace dans le registre. Le registre n'est pas un fichier unique — il est composé de plusieurs ruches (hives) physiquement séparées sur le disque dans C:\Windows\System32\config\ (ruches machine) et C:\Users\<user>\ (ruches utilisateur). Lorsque Windows tourne, ces ruches sont chargées en mémoire et présentées via les points d'entrée logiques HKLM (HKEY_LOCAL_MACHINE), HKCU (HKEY_CURRENT_USER), HKU, etc. — mais en forensique offline, on travaille directement sur les fichiers ruches avec des outils comme RegRipper, Registry Explorer (Eric Zimmerman), ou impacket-secretsdump. Les 7 ruches essentielles à connaître : SAM (comptes locaux + hashes NTLM), SYSTEM (config matérielle, USB connectés), SOFTWARE (applis, autoruns), SECURITY (LSA secrets), NTUSER.DAT (profil utilisateur), USRCLASS.DAT (ShellBags), DEFAULT (profil par défaut). Chaque ruche a aussi des fichiers de transaction .LOG1/.LOG2 qui permettent de récupérer les modifications récentes en cas de corruption — précieux pour la forensique car ils peuvent contenir des versions antérieures de clés modifiées récemment par un malware ou anti-forensique.

RegRipper

Extracteur de plugins Perl — analyse automatique des ruches. Plus de 200 plugins spécialisés (usbstor, userassist, shellbags, autoruns, etc.).

rip.pl -r NTUSER.DAT -f ntuser

GUI Windows pour l'analyse de ruches hors ligne. Supporte les ruches de transactions (.LOG), la reconstruction de ruches corrompues, la recherche full-text.

🎓 Exam Tip — Registre Windows

USBSTOR : USB (modele + S/N + dates) — ruche SYSTEM

UserAssist : programmes GUI — encode ROT13 — decoder avant lecture

ShellBags : dossiers navigues meme supprimes — USRCLASS.DAT

Run/RunOnce : persistance malware — HKLM + HKCU

SAM + SYSTEM : hashes NTLM — impacket-secretsdump — hashcat -m 1000

AmCache : hash SHA-1 des executables + date execution

ShimCache : preuve de presence (pas forcement d'execution)

Pourquoi UserAssist est-il encode en ROT13 et ou le trouver ?Registre Windows
ROT13 masque les chemins de programmes depuis Windows XP. Ruche : NTUSER.DAT a la cle Software\Microsoft\Windows\CurrentVersion\Explorer\UserAssist. Decoder avec CyberChef ROT13, RegRipper ou Registry Explorer (automatique).
Difference forensique entre ShimCache et AmCache ?Registre Windows
ShimCache : presence sur le systeme (pas forcement execute). Mis a jour au demarrage.
AmCache : execution prouvee + hash SHA-1 + chemin + date. Fichier : C:\Windows\AppCompat\Programs\Amcache.hve
Vous saisissez un PC suspect en mode allumé. Vous voulez extraire les hashes NTLM de la SAM. Quelle est la procédure correcte ?Extraction · Niveau : difficile
La ruche SAM est verrouillée par le système en cours d'exécution — impossible de la copier directement. Procédure correcte : (1) Acquisition RAM d'abord (ISO/IEC 27037, mesure de contrainte art. 248 CPP) — peut contenir des credentials en clair via Mimikatz si déployé. (2) Volume Shadow Copy pour copier SAM verrouillé : vssadmin create shadow /for=C: puis copy \\?\GLOBALROOT\Device\HarddiskVolumeShadowCopy1\Windows\System32\config\SAM . Idem pour SYSTEM. (3) Extraction offline des hashes avec impacket-secretsdump : impacket-secretsdump -sam SAM -system SYSTEM LOCAL. Sortie : user:RID:LM_hash:NT_hash:::. Important : la ruche SYSTEM est obligatoire car elle contient la SysKey qui déchiffre les hashes dans SAM. Sans SYSTEM, les hashes restent illisibles. (4) Crackage offline avec hashcat : hashcat -m 1000 hashes.txt rockyou.txt (mode 1000 = NTLM). Vitesse moderne : 100+ milliards de tentatives/sec sur GPU récent. (5) Documentation forensique : hash SHA-256 des ruches avant/après chaque manipulation, journalisation complète, chaîne de possession. NB : si le système utilise Windows Hello/Credential Guard, certaines protections additionnelles peuvent compliquer l'extraction. Pour les comptes de domaine, ce n'est pas SAM qu'il faut extraire mais NTDS.dit sur le DC (cf. fiche Active Directory).
