Virtualisation & VM Forensique

VMware VMDK · Hyper-V VHD/VHDX · Snapshots · Forensique sans démarrage

"Virtual machines are forensic gold mines — they carry snapshots frozen in time, disk images trivially mountable, and often contain the attacker's own toolset untouched."
— SANS FOR508 Advanced Incident Response
💡 Réalité IR suisse : La majorité des serveurs d'entreprise suisses fonctionnent sur VMware vSphere ou Hyper-V. Un ransomware ou une intrusion dans un ESXi peut affecter des dizaines de VMs simultanément. Savoir acquérir et analyser des VMs est aujourd'hui incontournable.

📸 Snapshots — Artefact forensique clé

💡
Un snapshot est un arrêt sur image à un instant T. Forensiquement, il peut capturer l'état exact au moment d'une attaque — avant que les logs ne soient effacés, avant le chiffrement d'un ransomware. Ne jamais supprimer un snapshot sans l'analyser.

VMware — Fichiers snapshot

  • .vmdk — disque de snapshot (delta)
  • .vmsn — état mémoire RAM au moment du snapshot
  • .vmsd — métadonnées des snapshots
  • .vmem — fichier mémoire paginée
  • Chaîne de snapshots : s'emboîtent chronologiquement

Hyper-V — Fichiers snapshot

  • .avhd / .avhdx — delta disk du checkpoint
  • .vmrs — état RAM du checkpoint
  • Dossier Snapshots\ — métadonnées XML
  • Commande : Get-VMSnapshot -VMName "nom"

🔍 Acquisition sans démarrage — Méthode standard

1
Copier les fichiers de la VM (offline)
Sur l'hôte hyperviseur, accéder aux fichiers VMDK/VHD directement. Calculer le hash avant et après copie. Ne jamais travailler sur les fichiers originaux.
sha256sum vm-disk.vmdk → copie → sha256sum identique
2
Convertir au format RAW si nécessaire
Certains outils forensiques travaillent mieux avec le format RAW. Conversion sans perte : qemu-img ou VBoxManage.
qemu-img convert -f vmdk -O raw vm.vmdk vm.raw
3
Monter et analyser avec FTK Imager / Autopsy
FTK Imager peut ouvrir directement les VMDK et VHD. Autopsy les supporte via TSK. X-Ways les monte comme des disques physiques.
4
Analyse du fichier mémoire (si snapshot avec RAM)
Les fichiers .vmem (VMware) ou .vmrs (Hyper-V) contiennent la RAM au moment du snapshot — analysables avec Volatility 3.
vol.py -f vm.vmem windows.pslist

⚡ ESXi — Forensique sur hyperviseur compromis

🔴
Ransomware ciblant ESXi : Depuis 2022, les ransomwares ESXiArgs, Royal, et BlackBasta ciblent spécifiquement VMware ESXi pour chiffrer toutes les VMs en une seule opération. Reconnaître cet attaque pattern est crucial.
  • Logs ESXi : /var/log/vmkernel.log, /var/log/hostd.log, /var/log/vpxa.log
  • Fichiers chiffrés : Extension .args, .locked — les VMDK sont chiffrés mais les VMX restent lisibles
  • Authentification : /etc/passwd, /etc/shadow ESXi — comptes créés par l'attaquant
  • ESXCLI : esxcli vm process list — VMs en cours d'exécution
  • Artefact clé : vpxuser — compte de gestion vCenter → première cible des attaquants

🏢 Hyper-V — Investigation Windows Server

ℹ️
Hyper-V étant intégré à Windows Server, les Event Logs Windows de l'hôte contiennent les événements Hyper-V : démarrages/arrêts de VMs, migrations, snapshots créés/supprimés.
  • Event IDs Hyper-V : 18590 (VM started), 18592 (VM stopped), 13000 (snapshot created)
  • Chemin : Microsoft-Windows-Hyper-V-Worker/Operational
  • Dossier VMs : C:\ProgramData\Microsoft\Windows\Hyper-V\
  • PowerShell forensique : Get-VM | Get-VMSnapshot
