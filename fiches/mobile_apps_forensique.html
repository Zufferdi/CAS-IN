iOS Apps Tierces — Catalogue Forensique

Paths critiques par application · Inspiré du poster SANS FOR585 (Mattia Epifani, 2021)

📂 Comment iOS organise les apps : chaque app installée depuis l'App Store reçoit un conteneur Sandbox. Le bundle (binaire signé Apple) est dans /private/var/containers/Bundle/. Les données utilisateur sont dans /private/var/mobile/Containers/Data/Application/<APP_GUID>/. Certaines apps stockent aussi dans un Shared Container à /private/var/mobile/Containers/Shared/AppGroup/<GROUP_GUID>/ — souvent oublié des examinateurs.
🔑 Trouver l'APP_GUID : la base /private/var/mobile/Library/FrontBoard/applicationState.db mappe bundle ID ↔ container path. Indispensable pour passer du nom commercial (« WhatsApp ») à net.whatsapp.WhatsApp puis au GUID local. Outil pratique : iLEAPP (parser open source de Brignoni) qui automatise l'extraction.
Prérequis : 📖 iOS Forensique 📖 SQLite Forensique

🎓 Exam Tip — Méthodologie d'analyse iOS app tierce

1. Identifier l'APP_GUID : applicationState.db → mapping bundle ID ↔ container path.

2. Examiner les 3 sandboxes : Data/ (privé), Shared/AppGroup/ (partage entre apps du même éditeur), iCloud/ (sync).

3. Hiérarchiser les artéfacts : SQLite/Realm en priorité (données structurées), puis Plists (configuration), puis caches (médias). Logs en dernier (volumineux).

4. Dater les actions : timestamps SQLite à convertir selon l'epoch utilisée. iOS = Mac Absolute Time (depuis 2001-01-01) → SELECT datetime(ts+978307200, 'unixepoch').

5. Ne pas oublier les KTX : /SplashBoard/Snapshots/ contient des screenshots auto-générés à chaque mise en arrière-plan de l'app — utile si l'app efface ses données mais pas ses captures.

6. BFU vs AFU : Before First Unlock = beaucoup de données chiffrées inaccessibles. After First Unlock = quasiment tout dispo. Voir iOS Forensique.
