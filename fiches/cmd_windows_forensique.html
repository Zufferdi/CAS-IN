CMD Windows Forensique

💡 Pourquoi connaître cmd.exe en 2026 ? Parce que sur un système compromis ou legacy, PowerShell peut être désactivé par GPO, restreint en Constrained Language Mode, ou journalisé en détail (un attaquant le sait). cmd.exe reste universel : il fonctionne sur Windows XP comme sur Windows Server 2025, et il est moins surveillé que PowerShell — ce qui rend sa connaissance autant utile en defense qu'en offensive.

🔄 Processus & Services

tasklist Liste des processus
tasklist /v /fo csv > tasks.csv
Mode verbose en CSV → import direct dans Excel/Timeline Explorer. Sans /v : juste PID + nom.
tasklist /m DLLs chargées
tasklist /m crypto.dll
Liste tous les processus qui ont chargé crypto.dll. Excellent pour détecter une DLL injectée (par ex. malware persistant via DLL hijacking).
tasklist /svc PID ↔ Service
tasklist /svc | findstr /i svchost
Déplie le mapping svchost.exe ↔ services hébergés. Utile pour identifier quel service tourne dans quel conteneur svchost (Windows 10+ a un svchost par service).
sc query État services
sc query state= all > services.txt
⚠️ Espace après = obligatoire ! Liste tous les services (running + stopped). Compléter avec sc qc <ServiceName> pour la config détaillée (binPath, startMode).
sc qc Config service
sc qc TermService
Inspect la config d'un service spécifique. BINARY_PATH_NAME est la cible critique : un service modifié pour pointer sur cmd.exe /c <malware> = persistance classique.

🛠️ WMIC — Le couteau suisse legacy

wmic est déprécié depuis Windows 11 24H2 (octobre 2024) mais reste présent sur tous les systèmes plus anciens — donc en forensique, on le rencontre encore en 2026 sur la grande majorité du parc en production. Sur les systèmes récents, basculer sur Get-CimInstance (PowerShell).

Grammaire fondamentale

wmic [alias] [where clause] [verb clause]

Trois parties : quoi regarder (alias), filtre (where), action (verb).

Alias utiles
process · service · share · nicconfig startup · useraccount · qfe
qfe = Quick Fix Engineering = patches appliqués (KB). Idéal pour vérifier si un système est patché contre une CVE donnée.
Découvrir les attributs
wmic process get /?
Liste TOUS les attributs disponibles pour un alias. Combiner avec get attr1,attr2 pour ne récupérer que ceux qui intéressent.
Lister callable methods
wmic process call /?
Voir les méthodes invocables (par ex. terminate, create). Permet par ex. de tuer un processus à distance.

Exemples forensiques pratiques

# Tous les processus + parent + commande complète wmic process get name,processid,parentprocessid,commandline /format:csv # Recherche : nc.exe ou variantes wmic process where "name='nc.exe' or name='ncat.exe'" get processid,commandline # Processus enfants de cmd.exe (souvent suspect via webshell ou pivot) wmic process where "name='cmd.exe'" get processid,parentprocessid,commandline # Tous les services configurés en démarrage automatique wmic service where "startmode='Auto'" get name,pathname,startname # Les patches Windows installés (dépister un système vulnérable) wmic qfe list brief

WMIC à distance (pivot ou audit)

wmic /node:<TargetIP> /user:<User> /password:<Pass> \ process list full

⚠️ Ne JAMAIS taper le mot de passe en clair sur la ligne de commande pendant un IR — il finit dans cmd.exe history et events 4688. Utiliser runas /user:DOMAIN\\user "wmic /node:..." ou psexec.

🌐 Réseau en CLI

netstat -nao Connexions + PID
netstat -nao | findstr ESTABLISHED
-n = numérique (pas de DNS) · -a = all · -o = PID. Combiner avec tasklist | findstr <PID> pour identifier le processus.
netstat -anob Bonus EXE
netstat -anob > net.txt
-b ajoute le binaire propriétaire de chaque connexion (nécessite admin). Très utile pour identifier directement le malware C2.
netstat surveillance continue
netstat -nao 5 | findstr 4444
Refresh toutes les 5 sec — utile pour traquer une connexion intermittente vers un port suspect (4444 = port par défaut Metasploit).
netstat statistiques protocole
netstat -s -p tcp
Stats détaillées du protocole. Une explosion de "Connections Reset" peut indiquer un scan agressif ou une attaque DoS.

netsh — config réseau et firewall

# État firewall + règles actives netsh advfirewall show allprofiles netsh advfirewall firewall show rule name=all > fw_rules.txt # Désactiver firewall (⚠️ contexte test uniquement) netsh advfirewall set allprofiles state off # Voir interfaces et IP netsh interface ip show config # Voir la config DNS (détecte hijacking) netsh interface ip show dnsservers # Wifi : profils + clés en clair (admin) netsh wlan show profiles netsh wlan show profile name="MyWifi" key=clear

⚠️ netsh wlan show profile key=clear exfiltre les passwords WiFi en clair — c'est une technique d'attaquant classique post-exploitation. À surveiller en defense (event 4688).

📁 Fichiers — Recherche et énumération

Recherche par nom de fichier

# Cherche tous les .lnk dans Windows + sous-dossiers, format brief dir /b /s C:\Windows\*.lnk # Cherche tous les exécutables modifiés dans les 7 derniers jours forfiles /p C:\Windows\System32 /m *.exe /d -7 /c "cmd /c echo @path @fdate" # Compter les lignes d'output (combien de hits ?) dir /b /s C:\Users\*.docx | find /c /v ""

🔁 Boucles for — automatisation

Boucle compteur for /L

for /L %i in (1,1,254) do @ping -n 1 -w 100 192.168.1.%i | find "Reply"

Ping sweep manuel sur un /24. (start, step, stop) = de 1 à 254 par pas de 1. Lent mais ne nécessite aucun outil tiers.

Boucle sur fichier for /F

for /F "tokens=*" %i in (hashes.txt) do @echo Checking %i & certutil -hashfile %i SHA256

Itère sur chaque ligne d'un fichier de chemins, calcule le SHA256 de chacun. certutil est natif Windows depuis Vista.

🔌 Arrêt & redémarrage

# Arrêt immédiat (pas de notice utilisateur, pas de timer) shutdown /s /t 0 # Redémarrage immédiat shutdown /r /t 0 # Redémarrage forcé même si applications bloquent shutdown /r /f /t 0 # Annuler un shutdown lancé shutdown /a # Arrêt distant (admin requis) shutdown /m \\TARGET /s /t 30 /c "Maintenance security"

⚠️ En live response, n'éteins jamais un système compromis avant d'avoir capturé la RAM (cf. RAM Forensique). L'extinction détruit l'état volatil.

🚨 Intrusion Discovery — détecter une compromission en live

Inspiré du cheat sheet SANS « Windows Intrusion Discovery » (Ed Skoudis). À exécuter périodiquement sur chaque machine sensible. Chaque commande répond à une question précise : « est-ce que cette machine a été compromise ? »

💡 Méthode : connaître le « normal » de la machine (baseline), puis chercher les déviations. Une commande ne dit rien dans l'absolu — elle dit qu'il y a un truc bizarre par rapport à d'habitude.

🌐 Connexions et sessions SMB inhabituelles

# Liste des partages exposés par cette machine (\\127.0.0.1) C:\> net view \\127.0.0.1 # Sessions SMB ENTRANTES (machines connectées à mes partages) C:\> net session # Sessions SMB SORTANTES (j'ai ouvert sur d'autres machines) C:\> net use # NetBIOS sessions actives — utile pour mouvement latéral C:\> nbtstat -S # Connexions TCP/UDP avec PID owner (-o) C:\> netstat -nao # Idem + DLL chargées par chaque connexion (-b nécessite admin) C:\> netstat -naob # Mode continu (rafraîchit toutes les 5 sec) C:\> netstat -nao 5 # Configuration firewall complète C:\> netsh advfirewall firewall show rule name=all

À chercher : ports en LISTENING inattendus (RAT typiquement 4444/5555/8080), connexions ESTABLISHED vers des IPs étrangères, sessions SMB depuis des comptes non-admin, partages c$/admin$ exposés.

🚀 Persistance — clés Run / RunOnce / RunonceEx

Les 3 clés registre exécutées au démarrage utilisateur. À auditer systématiquement :

# Au démarrage de chaque session utilisateur (chargé permanent) C:\> reg query HKLM\Software\Microsoft\Windows\CurrentVersion\Run C:\> reg query HKCU\Software\Microsoft\Windows\CurrentVersion\Run # Au prochain redémarrage seulement (puis effacé) C:\> reg query HKLM\Software\Microsoft\Windows\CurrentVersion\RunOnce C:\> reg query HKCU\Software\Microsoft\Windows\CurrentVersion\RunOnce # Idem mais avec dépendances ordonnées (rare, suspect si présent) C:\> reg query HKLM\Software\Microsoft\Windows\CurrentVersion\RunOnceEx

Cumuler avec : schtasks /query /v /fo LIST (tâches planifiées), wmic startup list full (tous les points de démarrage), Sysmon Event ID 12/13 (Registry mod).

🛠️ Outils Sysinternals indispensables (hors Windows par défaut)

Téléchargeables sur learn.microsoft.com/sysinternals. Signés Microsoft, exécutables sans installation :

  • Process Explorer (procexp.exe) — Task Manager sur stéroïdes : VirusTotal lookup, signature check, parent-child tree, DLLs chargées par processus.
  • Process Monitor (procmon.exe) — Trace temps réel : tous les accès filesystem / registre / réseau de chaque processus. Volume énorme, à filtrer.
  • Sysmon — Service de logging persistant. Loggue process creation (Event ID 1), network connection (3), driver load (6), registry mod (12-14), DNS query (22). Configuration via XML (Sysmon-Modular).
  • Autoruns (autoruns.exe) — Énumère tous les points de démarrage (Run/RunOnce + Services + Tasks + WMI Subscriptions + 50+ autres).
  • PsExec — Exécution distante. Légitime mais aussi utilisé par attaquants (lateral movement). Détecter via Event ID 7045 service "PSEXESVC".
  • Process Hacker (processhacker.sourceforge.io) — Alternative open source à Process Explorer.

⚡ Performances anormales (signaux faibles)

# CPU/RAM/Disque par processus (live) C:\> taskmgr.exe # Espace disque (alarme si chute soudaine = exfiltration ou logs malveillants) C:\> dir C:\ PowerShell> Get-PSDrive C | Select-Object Used,Free # Crashs systeme (si nombreux = instabilité due à malware/exploit) C:\> wevtutil qe System /q:"*[System[Provider[@Name='Microsoft-Windows-WER-SystemErrorReporting']]]" /c:20 /f:text

Sluggish ≠ forcément malware (peut être MAJ/AV/indexation), mais combiné avec nouveau processus + nouvelle connexion sortante = très suspect.

💊 Auto-évaluation

Tu vois une connexion ESTABLISHED vers 185.220.100.42:443 dans netstat -nao avec PID 4632. Quelles sont tes 3 prochaines étapes sans utiliser PowerShell ?Live response · Niveau : moyen
1. Identifier le processus : tasklist /v | findstr 4632
2. Voir la commande exacte : wmic process where "processid=4632" get name,executablepath,commandline
3. Examiner le binaire : certutil -hashfile <path> SHA256 puis chercher le hash sur VirusTotal. Optionnel : tasklist /m /fi "PID eq 4632" pour les DLLs chargées.
Quelle est la différence forensique majeure entre tasklist /svc et sc query ?Services Windows · Niveau : facile
tasklist /svc montre quels services tournent dans quels processus (vue par PID). sc query montre l'état configuré de tous les services (running/stopped, démarrage auto/manuel). Combiner : sc query trouve un service "running" suspect, puis tasklist /svc | findstr ServiceName identifie le PID associé pour analyse mémoire.
Pourquoi un attaquant préfère souvent cmd.exe à PowerShell sur un système moderne (Windows 10+) ?OPSEC · Niveau : moyen
PowerShell 5+ a un logging très détaillé activable par GPO : Module Logging, Script Block Logging (event 4104), Transcription. Sur les environnements durcis, tout script PowerShell est tracé voire bloqué (Constrained Language Mode, AMSI). cmd.exe ne logge que via Process Creation Auditing (event 4688) — pas le contenu des scripts batch ni l'output. Donc en defense : activer Process Command Line Auditing (4688 + GPO "Include command line in process creation events") pour capturer aussi les arguments de cmd.exe.
🎓 Exam Tip — CMD Forensique

WMIC : grammaire alias + where + verb. Déprécié sur W11 24H2 mais toujours présent partout ailleurs. Migrer vers Get-CimInstance sur les systèmes récents.

tasklist : /v verbose · /m DLLs · /svc services par PID · /fi filtre.

netstat -nao : connexions + listening ports + PID. Combine avec tasklist /fi "PID eq X".

reg query : /s recurse · /v valeur précise. Sur poste distant : \\TARGET\HKLM\....

Persistance Run/RunOnce : HKLM\Software\Microsoft\Windows\CurrentVersion\Run et RunOnce, idem dans HKCU.

Logging : Process Command Line Auditing (event 4688) capture les arguments. À activer en GPO.
