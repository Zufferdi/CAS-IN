TRM Labs — Investigation crypto pratique

Guide opérationnel · TRM Forensics + TRM Risk · workflow type · export probant
Prérequis :📖 Forensique crypto
Pratiquer :🎮 Saga 1 (extension crypto)
Voir aussi :🔗 OSINT investigatif🔗 Coordination internationale
🔑 Principe — TRM Labs en 3 mots : Trace, Cluster, Risk
TRM Labs est une plateforme commerciale d'analyse blockchain utilisée par les forces de l'ordre, FIU et VASP régulés. Trois capacités centrales : tracer les flux entre adresses, clusteriser les adresses appartenant à un même propriétaire (exchange, mixer, ransomware actor), et scorer le risque d'une adresse selon des heuristiques propriétaires. Ce tutoriel décrit le workflow standard de 6 étapes, du point de départ (adresse suspecte) au rapport exportable. Note d'accès : TRM n'est pas un outil grand public — l'accès se fait par licence institutionnelle (fedpol, MROS, MPC, OFCS, OFJ, banques régulées CH), ou via partenaire d'enquête international.

Pour un enquêteur cantonal sans accès direct, deux voies : (a) demande de coordination via fedpol, (b) coopération internationale (Europol, FBI) qui fournit le résultat de l'analyse.

① 3. Search — point d'entrée de l'enquête

L'enquête démarre toujours par un identifiant blockchain : adresse (BTC, ETH, USDT), TxID (transaction hash), ou identifiant de wallet (xpub). Sources typiques :

  • Déclaration MROS d'un VASP (le VASP fournit l'adresse impliquée)
  • Hardware wallet saisi en perquisition (extraction firmware Ledger/Trezor)
  • Note de rançon (paiement demandé sur adresse spécifique)
  • Capture réseau (analyse PCAP révélant une adresse C2 crypto)
  • Information de threat intel (Chainalysis, abuse.ch, MISP)
📚 Bonne pratique — préserver l'intégrité : avant toute requête TRM, documenter l'adresse exactement comme reçue (copier-coller, screenshot horodaté de la source). Les adresses crypto sont sensibles à la casse pour Ethereum (checksum EIP-55) et aux caractères pour Bitcoin (Base58). Une typo = mauvaise enquête. Validez via un block explorer avant de traiter dans TRM.

Action TRM : Search → Address/Transaction → Paste → Submit. La plateforme reconnaît automatiquement le type d'asset (BTC/ETH/USDT/etc.) et la chaîne associée. Pour les enquêtes massives (centaines d'adresses), utiliser le batch import via CSV.

② 4. Identify — clustering et entités

Une fois l'adresse soumise, TRM applique son moteur de clustering propriétaire pour répondre à 3 questions :

  • Est-ce une adresse connue ? Si oui, l'entité est labellisée (exchange Binance hot wallet, Tornado Cash router, Lazarus Group, etc.). TRM maintient une base de millions d'entités identifiées.
  • Quel cluster contient cette adresse ? Le clustering applique les heuristiques classiques (common input pour Bitcoin, behavioral pour Ethereum) + des signaux propriétaires.
  • Combien d'adresses dans ce cluster ? Un exchange majeur peut avoir des centaines de milliers d'adresses ; un wallet personnel quelques dizaines.
⚠️ Limite du clustering : un cluster n'est pas une preuve juridique en soi. C'est une inférence probabiliste basée sur des heuristiques. Toujours documenter : « TRM associe cette adresse au cluster X avec confiance Y, basé sur Z transactions co-utilisant des inputs communs ». La conclusion d'attribution finale repose sur la corroboration par les endpoints KYC (réquisition exchange).
③ 5. Risk Score — l'évaluation algorithmique

TRM attribue à chaque adresse un Risk Score de 0 à 100 (0 = bénin, 100 = très haut risque). Le score agrège plusieurs indicateurs :

Indicateur de risque Exemple de signal
Direct exposureReçu/envoyé directement à un mixer, sanction OFAC, ransomware connu
Indirect exposureConnexion via 2-3 hops à une entité à haut risque
Behavioral patternsPeel chain, structuring (sous-seuils), rapidité, montants typiques
Counterparty mix% des fonds reçus d'exchanges KYC vs DeFi vs darknet
Sanctions exposureLien direct/indirect avec adresses SDN OFAC ou listes EU/UN

Interprétation pratique pour un enquêteur :

  • 0-30 = adresse normale, faible probabilité d'origine illicite. Pas d'enquête prioritaire.
  • 30-60 = exposition indirecte modérée. Justifie un suivi, pas nécessairement une réquisition immédiate.
  • 60-85 = adresse à risque. Justifie réquisition LBA, demande KYC à l'exchange d'entrée.
  • 85-100 = adresse hautement risquée. Souvent liée à sanctions, ransomware, darknet markets. Action rapide.
⚖️ Risk Score ≠ preuve pénale : un score TRM élevé est un indicateur d'enquête, pas un élément probant suffisant pour une condamnation. Le score peut être contesté par la défense — bonne pratique : ne jamais s'appuyer uniquement sur le score, toujours documenter les flux concrets (TxIDs, montants, dates, contreparties identifiées) qui justifient l'évaluation.
④ 6. Trace — visualisation des flux

L'écran Trace (équivalent du « Reactor » Chainalysis) affiche le graphe des flux entrants et sortants de l'adresse. Visualisation type :

   [Exchange Binance]  ──┐
                         │ 0.5 BTC, 14.03.2026
                         ▼
                    [Adresse cible]  ── 2.1 BTC ──► [Tornado Cash]
                         ▲
                         │ 1.6 BTC, 15.03.2026
   [Coinbase hot wallet]─┘

Paramètres clés à régler :

  • Hop depth — nombre de sauts en amont/aval (default 3, on monte à 5-6 pour enquêtes profondes)
  • Threshold — montant minimum affiché (filtrer le bruit, ex. ≥ 0.01 BTC)
  • Time window — restreindre la période (ex. 7 jours avant/après l'événement)
  • Asset filter — BTC seul ou multi-chain (utile en chain hopping)
📚 Astuce — analyse en remontant : en cas d'attribution incertaine, remonter vers l'origine des fonds (« upstream ») est souvent plus productif que descendre vers la destination. L'origine donne accès à un exchange KYC qui révèlera l'identité réelle. La destination peut être perdue dans un mixer ou un wallet froid.
⑤ 7. Pivot — extraire les éléments probants

Pour chaque flux pertinent, extraire et documenter :

Élément Pourquoi le documenter
TxID completVérifiable indépendamment sur block explorer = preuve immuable
Adresses source / destinationPoints de pivot pour réquisitions KYC ultérieures
Date + heure UTCChronologie de l'enquête, recoupement avec autres événements
Montant brutQuantification du dommage en CHF (cours à la date)
Entité identifiée (si applicable)Exchange où réquisitionner, mixer à confirmer
Justification du clusteringHeuristique utilisée par TRM (vérifiable par contre-expertise)

Pivot vers KYC = étape décisive. Une fois une adresse d'exchange identifiée :

  • Exchange régulé CH (Bitcoin Suisse, SEBA, Sygnum, Bity) : réquisition LBA art. 9 + CPP art. 263 / 273
  • Exchange UE (Bitstamp, Kraken EU, Coinbase EU) : entraide EIMP via OFJ, ou ordonnance E-Evidence (UE 2023/1543) à partir du 18.8.2026
  • Exchange US (Coinbase, Kraken US, Binance US) : entraide TEJUS (RS 0.351.933.6) ou MLAT
  • Exchange non-coopératif (offshore, juridictions non conventionnées) : impasse partielle — utiliser pression indirecte (sanctions, partenaires)
⑥ 8. Export — produire la preuve

TRM permet plusieurs formats d'export, à choisir selon la destination :

  • Rapport PDF — pour intégration dans le dossier pénal, le rapport contient les graphes de flux, le risk score, les justifications. Signé numériquement.
  • CSV des transactions — pour analyse offline, recoupement avec d'autres sources, expertise judiciaire.
  • JSON / API — pour intégration dans un SIEM ou outil interne d'analyse.
  • Screenshots horodatés — capture d'écran de l'interface TRM, horodatée et signée, pour usage probant en audience.
🎯 Bonne pratique — chain of custody : tous les exports TRM doivent être horodatés et hashés au moment de la production (SHA-256 sur le fichier). Documenter qui a fait l'export, depuis quel compte TRM, à quelle date. Conserver les exports dans le dossier d'enquête, jamais sur poste personnel.
🎓 9. Cas pratique court — workflow type
Scénario : ransomware sur une PME suisse. Note demande 2 BTC à l'adresse bc1qxxxx.... Paiement effectué le 12.03.2026.

① Search : adresse bc1qxxxx... entrée dans TRM Forensics.
② Identify : cluster avec 47 adresses ; pas labellisé directement mais 89% des fonds entrants viennent de victimes US/EU récentes (pattern ransomware connu, possible affiliate LockBit).
③ Risk Score : 92/100 — direct exposure ransomware + indirect exposure Tornado Cash.
④ Trace : flux sortants → cluster Binance hot wallet (1.2 BTC), Tornado Cash (0.8 BTC).
⑤ Pivot : extraction TxID Binance → demande EIMP via OFJ + MLAT US (Binance US). 0.8 BTC dans Tornado = perte de traçabilité.
⑥ Export : rapport PDF horodaté, intégré au dossier MPC.

Résultat probable : récupération partielle (0.5-1.0 BTC via Binance avec coopération), saisie sur compte fiat associé, IOC partagés via MISP communauté ransomware. Le reste (Tornado Cash) reste hors d'atteinte technique.
⚠️ 10. Limites et pièges courants
  • TRM ≠ vérité absolue — les heuristiques de clustering peuvent se tromper. Toujours valider par recoupement (Chainalysis, Elliptic, block explorer manuel).
  • Privacy coins (Monero, Zcash z-addresses) opaques — TRM ne peut pas tracer là où la crypto est conçue pour être opaque.
  • Délai de mise à jour — TRM met à jour ses labels avec un certain délai. Une adresse fraîchement utilisée par un acteur peut ne pas être encore identifiée.
  • Faux positifs sanctions — un score 100/100 « sanctions » peut être dû à une connexion très indirecte. Lire attentivement le détail.
  • Données off-chain absentes — TRM ne voit que la blockchain. Les transactions internes d'exchange (deposits/withdrawals consolidés) sont invisibles. D'où l'importance de la réquisition KYC.
  • Coût — licence TRM = budget significatif (typiquement 50-200 kCHF/an selon volume). Justifie une stratégie de mutualisation (fedpol coordonne pour cantons).

Outil Force relative

EllipticBonne couverture dark web et ransomware, racines UK

Le bon réflexe : croiser au moins 2 outils pour les enquêtes sensibles. Une attribution Chainalysis + TRM concordante est plus solide qu'un seul outil. Pour vérification publique des transactions individuelles, Etherscan/blockchain.info restent incontournables.
