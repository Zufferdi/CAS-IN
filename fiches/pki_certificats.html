Chaîne de certification PKI
🏛
Root CA — Autorité racine — Auto-signée, stockée hors ligne (air-gap). Signe uniquement les CA intermédiaires. Compromission = invalidation de toute la PKI. Ex: DigiCert Global Root CA, SwissSign Gold CA G2.
🏢
Intermediate CA — Opérationnelle (en ligne). Signe les certificats end-entity. Révocation possible sans toucher à la Root CA. Plusieurs niveaux possibles.
📄
End-Entity — Serveur TLS, utilisateur S/MIME, code signing. Durée maximale : 398 jours (depuis 2020). Contient clé publique + identité vérifiée par la CA.

Certificat auto-signé — Red flag forensique
  • Émis par soi-même (Issuer = Subject) — aucune CA de confiance
  • Légitime : développement local, intranet non exposé
  • Suspect : serveur HTTPS public, C2 malware, proxy MITM
  • Fichiers sensibles : .p12/.pfx (cert + clé privée), .pem avec clé non chiffrée, id_rsa, known_hosts
TLS 1.3 — Handshake forensique
1
Client Hello — SNI en clair, cipher suites, random 32 bytes. Forensique : le SNI révèle le domaine contacté même si tout le reste est chiffré.
2
Server Hello + Certificate — chaîne complète transmise. Échange de clé ECDHE.
3
Client Finished — vérification chaîne. Certificate Pinning bloque ici si CA non reconnue.
4
Application Data — chiffré (AES-GCM ou ChaCha20-Poly1305). TLS 1.3 impose ECDHE → PFS obligatoire → la clé privée du serveur ne déchiffre pas les sessions passées.
Déchiffrement TLS forensique
  • SSLKEYLOGFILE — Chrome/Firefox exporte les clés de session → Wireshark déchiffre
  • Clé privée serveur — possible uniquement si RSA + TLS 1.2 (pas de PFS)
  • TLS 1.3 + ECDHE — irrecupérable sans SSLKEYLOGFILE
Certificate Pinning — Impact mobile
  • App accepte uniquement son cert hard-codé
  • Bloque les proxies MITM légaux (Burp, mitmproxy, Charles)
  • Banques, WhatsApp, Signal, apps financières
  • Bypass : Frida (hook SSL_verify), apktool + patch, Magisk TrustUserCerts
Révocation — CRL vs OCSP
CRL — Certificate Revocation List
  • Fichier signé par la CA listant tous les serials révoqués
  • Publié à intervalle régulier (24h–7j)
  • Délai entre révocation et mise à jour = fenêtre de risque
  • openssl crl -in crl.pem -text -noout
OCSP — Online Certificate Status Protocol
  • Requête temps réel → réponse good / revoked / unknown
  • OCSP Stapling : serveur inclut la réponse dans le handshake TLS
  • OCSP Must-Staple : extension forçant le stapling
  • openssl ocsp -issuer inter.pem -cert end.pem -url [URL]
S/MIME — Email chiffré et signé
Les deux opérations S/MIME
  • Signature : expéditeur chiffre le hash avec sa clé privée → prouve identité + intégrité
  • Chiffrement : expéditeur chiffre avec la clé publique du destinataire → seul le destinataire peut lire
Pièges S/MIME à l'examen
  • Signature valide ≠ identité de la personne physique — prouve que la clé a signé (clé volée possible)
  • Confondre "chiffrer avec clé publique" et "signer avec clé privée" = erreur classique
  • Art. 269 CPP → surveillance TLC peut autoriser l'interception légale (avec mandat)

Erreurs classiques
❌ Confusions fréquentes
  • Chiffrer ≠ Signer — Chiffrement = clé publique du destinataire. Signature = propre clé privée.
  • TLS 1.3 + clé privée = déchiffrement — FAUX avec PFS/ECDHE.
  • CRL = OCSP — CRL = liste téléchargée. OCSP = requête unitaire temps réel.
  • Signature = identité personne — Signature = identité de la clé.
✅ Ce qu'on peut prouver
  • SNI en clair → domaine contacté même en TLS
  • Certificate Pinning → raison de l'échec du proxy MITM
  • Durée ≤ 398j → certificat post-2020
  • Certificat auto-signé sur C2 → indicateur de compromission
