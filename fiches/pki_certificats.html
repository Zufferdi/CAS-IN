Chaîne de certification PKI
🏛
Root CA — Auto-signée, stockée hors ligne (air-gap). Signe uniquement les CA intermédiaires. Compromission = invalidation de toute la PKI.
🏢
Intermediate CA — Opérationnelle (en ligne). Signe les end-entity. Révocation possible sans toucher la Root CA.
📄
End-Entity — Serveur TLS, utilisateur S/MIME. Durée max : 398 jours (depuis 2020). Contient clé publique + identité vérifiée par la CA.

Certificat auto-signé — Red flag forensique
  • Issuer = Subject — aucune CA de confiance dans la chaîne
  • Légitime : dev local, intranet non exposé · Suspect : HTTPS public, C2 malware, proxy MITM
  • Chercher : .p12/.pfx/.pem (clé privée), id_rsa, known_hosts
TLS 1.3 — Forensique
Handshake clés
  • Client Hello : SNI en clair → domaine visible même si chiffré
  • TLS 1.3 impose ECDHE → PFS obligatoire
  • Clé privée serveur ne déchiffre PAS les sessions passées
  • SSLKEYLOGFILE → Chrome/Firefox exporte clés de session
Certificate Pinning
  • App accepte uniquement son cert hard-codé
  • Bloque Burp, mitmproxy, Charles
  • Banques, WhatsApp, Signal, apps financières
  • Bypass : Frida (hook SSL_verify) · apktool · Magisk
Révocation & S/MIME
CRL vs OCSP
  • CRL = liste complète téléchargée périodiquement (24h–7j)
  • OCSP = requête unitaire temps réel → good / revoked / unknown
  • OCSP Stapling = serveur inclut la réponse dans le handshake
S/MIME — Pièges examen
  • Signature = chiffrer hash avec sa clé privée
  • Chiffrement = chiffrer avec clé publique du destinataire
  • Signature valide ≠ identité personne physique (clé peut être volée)
🧠 Testez-vous
TLS 1.3 est actif. Vous avez la clé privée du serveur. Pouvez-vous déchiffrer les sessions enregistrées ?
Non. TLS 1.3 impose ECDHE (Perfect Forward Secrecy). Les clés de session sont éphémères — jamais stockées, non dérivables de la clé privée. Seul SSLKEYLOGFILE (variable d'environnement Chrome/Firefox) permet de capturer les clés en temps réel.
Pourquoi l'interception TLS échoue-t-elle sur une application bancaire mobile ?
Certificate Pinning. L'application hard-code le certificat attendu du serveur. Même si le proxy présente un certificat valide, l'app le rejette car il ne correspond pas au cert pinned. Bypass : Frida (hook dynamique de SSL_verify), apktool + patch du binaire, ou Magisk TrustUserCerts (root requis).
