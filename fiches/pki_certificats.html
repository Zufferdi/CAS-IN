🔏 La PKI — distribuer des clés publiques avec confiance
Sans la PKI, comment savoir que la clé publique reçue appartient bien au serveur attendu ? La PKI résout ce problème par une chaîne de signatures : une Autorité de Certification (CA) signe des certificats qui lient une clé publique à une identité vérifiée. C'est le socle de HTTPS, S/MIME, SSH certificates et des signatures électroniques qualifiées (ZertES en Suisse).

« Le Certificate Pinning est la raison pour laquelle votre proxy MITM légal échoue sur l'application bancaire — et un sujet récurrent à expliquer devant un magistrat. »

Chaîne de certification PKI — Hiérarchie de confiance
🏛
Root CA — Auto-signée, stockée hors ligne (air-gap). Signe uniquement les CA intermédiaires. Compromission = invalidation de toute la PKI. Ex : DigiCert Global Root, Swiss Government Root CA IV.
🏢
Intermediate CA — Opérationnelle (en ligne). Signe les end-entity. Révocation possible sans toucher la Root. Permet la compartimentalisation par usage (TLS, S/MIME, code signing).
📄
End-Entity — Serveur TLS, utilisateur S/MIME. Durée max : 398 jours (CA/B Forum, depuis 2020). Contient clé publique + identité vérifiée par la CA.

🚩 Certificat auto-signé — Red flag forensique
  • Issuer = Subject — aucune CA de confiance dans la chaîne
  • Légitime — dev local, intranet non exposé · Suspect — HTTPS public, C2 malware, proxy MITM
  • Chercher dans le système : .p12 / .pfx / .pem (clé privée), id_rsa, known_hosts
TLS 1.3 — Implications forensiques
🔐 Handshake & clés
  • Client Hello : SNI en clair → domaine visible même si chiffré
  • TLS 1.3 impose ECDHE → PFS obligatoire
  • Clé privée serveur ne déchiffre PAS les sessions passées
  • SSLKEYLOGFILE → Chrome/Firefox exporte clés de session
  • ECH (Encrypted Client Hello) — chiffre le SNI (déploiement progressif 2024+)
📌 Certificate Pinning
  • App accepte uniquement son cert hard-codé
  • Bloque Burp, mitmproxy, Charles
  • Banques, WhatsApp, Signal, apps financières
  • Bypass : Frida (hook SSL_verify) · apktool · Magisk TrustUserCerts
Révocation & S/MIME
📋 CRL vs OCSP
  • CRL = liste complète téléchargée périodiquement (24h–7j)
  • OCSP = requête unitaire temps réel → good / revoked / unknown
  • OCSP Stapling = serveur inclut la réponse dans le handshake
  • OCSP Must-Staple — extension qui force le client à vérifier OCSP
📧 S/MIME — Pièges examen
  • Signature = chiffrer hash avec sa clé privée
  • Chiffrement = chiffrer avec clé publique du destinataire
  • Signature valide ≠ identité personne physique (clé peut être volée)
  • Signature qualifiée ZertES = équivalent juridique de la signature manuscrite
🧠 Testez-vous
TLS 1.3 est actif. Vous avez la clé privée du serveur. Pouvez-vous déchiffrer les sessions enregistrées ?TLS · PFS · Niveau : moyen
Non. TLS 1.3 impose ECDHE (Perfect Forward Secrecy). Les clés de session sont éphémères — jamais stockées, non dérivables de la clé privée. La clé privée du serveur sert uniquement à signer (prouver l'identité), pas à chiffrer le master secret. Seul SSLKEYLOGFILE (variable d'environnement Chrome/Firefox) permet de capturer les clés en temps réel.
Pourquoi l'interception TLS échoue-t-elle sur une application bancaire mobile ?Pinning · Niveau : facile
Certificate Pinning. L'application hard-code le certificat attendu du serveur. Même si le proxy présente un certificat valide signé par une CA de confiance, l'app le rejette car il ne correspond pas au cert pinned. Bypass : Frida (hook dynamique de SSL_verify), apktool + patch du binaire, ou Magisk TrustUserCerts (root requis). Note : sur iOS, le bypass nécessite jailbreak ou repackaging via theos.
Un certificat a une durée de validité de 5 ans. Émis en 2024. Que conclure ?Conformité · Niveau : facile
Non conforme aux règles CA/B Forum. Depuis le 1er septembre 2020, la durée maximale d'un certificat TLS public est de 398 jours (~13 mois). Un certificat de 5 ans soit (1) émis avant 2020, (2) un certificat de CA intermédiaire ou root (durées plus longues admises pour les CA), (3) un certificat interne / privé hors écosystème public, ou (4) un certificat invalide / suspect. Vérifier le contexte d'émission et la chaîne complète.
🎓 Exam Tip — PKI & Certificats

Root CA = hors ligne (air-gap) · Durée max certificat TLS = 398 jours (depuis 2020)

TLS 1.3 = ECDHE → PFS → clé privée serveur ne déchiffre pas les sessions passées

SNI = domaine en clair dans le Client Hello (sauf ECH)

Certificate Pinning → bypass via Frida (hook SSL_verify)

OCSP Stapling = réponse dans le handshake (pas de requête séparée)

Signature S/MIME ≠ identité personne physique (clé peut être volée)

Auto-signé en HTTPS public = red flag (C2, MITM, malware)
