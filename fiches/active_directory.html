Active Directory Forensique

ℹ️ Active Directory (AD) est la cible n°1 des attaquants dans les environnements Windows d'entreprise. Sa compromission donne un accès total au réseau. La forensique AD analyse les logs d'authentification, les tickets Kerberos et les modifications d'objets AD.

Attaques AD courantes — Détection forensique
Pass-the-Hash (PtH)
L'attaquant utilise le hash NTLM volé sans connaître le mot de passe en clair. Mouvement latéral via SMB ou WMI.
EID 4624 LogonType=3 + NtLmSsp
EID 4776 (validation NTLM DC)
Indicateur : connexion depuis IP inhabituelle sans TGT préalable
Pass-the-Ticket (PtT)
Vol d'un ticket Kerberos TGT ou TGS en RAM (Mimikatz sekurlsa::tickets) et réutilisation. Contourne l'authentification NTLM.
EID 4768 (TGT demandé depuis IP inattendue)
EID 4769 (TGS demandé pour service inhabituel)
Ticket avec durée anormale (> 10h par défaut)
Golden Ticket
Forge d'un TGT avec le hash du compte krbtgt (compromis). Accès total à n'importe quel service du domaine sans limite de temps.
EID 4769 sans EID 4768 préalable
Ticket avec RenewUntil > 7 jours ou EncType = 0x17 (RC4 suspect)
Domaine dans le ticket ≠ domaine réel
Kerberoasting
Demande de TGS pour des comptes de service (SPN), puis crackage hors-ligne du hash RC4. Cible les comptes de service avec mots de passe faibles.
EID 4769 avec EncType=0x17 (RC4) en masse
Multiples requêtes TGS depuis un même compte en peu de temps
Comptes demandeurs inhabituels pour des services sensibles
DCSync
Simule un contrôleur de domaine pour répliquer NTDS.dit et obtenir tous les hashes. Requiert les droits DS-Replication-Get-Changes.
EID 4662 — accès à objet AD avec droit de réplication
Trafic réseau : DRSUAPI depuis un hôte non-DC
Commande : mimikatz lsadump::dcsync /domain:X /all
Persistance via GPO
Modification d'une GPO pour exécuter un script malveillant sur tous les postes du domaine. Persistence furtive et massive.
EID 5136 — modification d'objet AD (GPO)
Vérifier SYSVOL pour des scripts PowerShell ajoutés
EID 4739 — changement de politique de domaine
NTDS.dit — Extraction forensique
⚠️ Fichier verrouillé par le DC en cours d'exécution

NTDS.dit est verrouillé par le processus LSASS. Méthodes d'extraction légitimes (forensique autorisée) :

# Méthode 1 : Volume Shadow Copy (VSS)
vssadmin create shadow /for=C:
copy \\?\GLOBALROOT\Device\HarddiskVolumeShadowCopy1\Windows\NTDS\NTDS.dit .

# Méthode 2 : ntdsutil (builtin Windows)
ntdsutil "ac i ntds" "ifm" "create full c:\temp\AD" quit quit

# Extraction des hashes (post-acquisition, hors ligne)
python3 secretsdump.py -ntds NTDS.dit -system SYSTEM LOCAL

Outils d'analyse AD
BloodHound

Cartographie graphique des chemins d'attaque AD. Ingère les données via SharpHound. Identifie les paths vers Domain Admin.

Mimikatz

Extraction de credentials depuis LSASS. Fonctions : sekurlsa::logonpasswords, kerberos::list, lsadump::dcsync.

Plaso / log2timeline

Timeline des logs AD. Correlate EID 4624/4625/4768 pour reconstituer les mouvements latéraux.

Impacket

Suite Python : secretsdump (hashes), smbclient, psexec. Standard pour l'analyse post-exploitation AD.
