🏢 Active Directory — Cible n°1 des attaquants en entreprise
Active Directory (AD) est le service d'annuaire centralisé de Microsoft, utilisé par plus de 95% des entreprises dans le monde pour gérer les utilisateurs, ordinateurs, groupes, et politiques de sécurité d'un domaine. Sa compromission donne un accès total au réseau — c'est pourquoi chaque ransomware moderne cherche d'abord à compromettre l'AD avant de chiffrer. Le composant central est le Domain Controller (DC) qui héberge la base NTDS.dit contenant tous les hashes NTLM des utilisateurs du domaine. L'authentification utilise principalement Kerberos (v5, RFC 4120) avec deux types de tickets : TGT (Ticket Granting Ticket, obtenu auprès du KDC) et TGS (Ticket Granting Service, pour accéder à un service spécifique). Les attaques classiques exploitent ce système : Pass-the-Hash (réutilisation de hash NTLM volé), Pass-the-Ticket (vol de ticket Kerberos), Golden Ticket (forge de TGT avec le hash krbtgt = god mode permanent), Kerberoasting (vol de TGS pour cracker hors-ligne), DCSync (réplication frauduleuse de NTDS.dit). Pour le forensiste : tout commence par les Event Logs Security du DC — EID 4624, 4625, 4768, 4769, 4776, 4662 — combinés avec Sysmon et capture mémoire LSASS côté workstations.

⚔️ Attaques AD courantes — Détection forensique
🔴 Pass-the-Hash (PtH)

Attaque : l'attaquant utilise le hash NTLM volé sans connaître le mot de passe en clair. Mouvement latéral via SMB ou WMI.

Détection :

  • EID 4624 LogonType=3 + AuthPackage NtLmSsp
  • EID 4776 (validation NTLM côté DC)
  • Indicateur : connexion depuis IP inhabituelle sans TGT préalable
🟠 Pass-the-Ticket (PtT)

Attaque : vol d'un ticket Kerberos TGT ou TGS en RAM (Mimikatz sekurlsa::tickets) et réutilisation. Contourne l'authentification NTLM.

Détection :

  • EID 4768 TGT depuis IP inattendue
  • EID 4769 TGS pour service inhabituel
  • Ticket avec durée anormale (> 10h défaut)
🟡 Golden Ticket

Attaque : forge d'un TGT avec le hash du compte krbtgt compromis. Accès total à n'importe quel service du domaine, sans limite de temps, et survit aux changements de mot de passe.

Détection :

  • EID 4769 sans EID 4768 préalable
  • Ticket avec RenewUntil > 7 jours · EncType 0x17 (RC4 suspect)
  • Domaine du ticket ≠ domaine réel
🟣 Kerberoasting

Attaque : demande de TGS pour des comptes de service (SPN), puis crackage hors-ligne du hash RC4. Cible les comptes service avec mots de passe faibles.

Détection :

  • EID 4769 EncType=0x17 (RC4) en masse
  • Multiples requêtes TGS depuis un même compte en peu de temps
  • Comptes demandeurs inhabituels pour des services sensibles
🔵 DCSync

Attaque : simule un contrôleur de domaine pour répliquer NTDS.dit et obtenir tous les hashes. Requiert les droits DS-Replication-Get-Changes.

Détection :

  • EID 4662 — accès à objet AD avec droit de réplication
  • Trafic réseau : DRSUAPI depuis un hôte non-DC
  • Cmd : mimikatz lsadump::dcsync /domain:X /all
🔷 Persistance via GPO

Attaque : modification d'une GPO pour exécuter un script malveillant sur tous les postes du domaine. Persistence furtive et massive.

Détection :

  • EID 5136 — modification d'objet AD (GPO)
  • Vérifier SYSVOL : scripts PowerShell ajoutés ?
  • EID 4739 — changement politique de domaine
💎 NTDS.dit — Extraction forensique
⚠️ Fichier verrouillé par le DC en cours d'exécution. NTDS.dit est verrouillé par le processus LSASS. Méthodes d'extraction légitimes (forensique autorisée).
🛠 Méthodes d'extraction
# Méthode 1 : Volume Shadow Copy (VSS)
vssadmin create shadow /for=C:
copy \\?\GLOBALROOT\Device\HarddiskVolumeShadowCopy1\Windows\NTDS\NTDS.dit .

# Méthode 2 : ntdsutil (built-in Windows)
ntdsutil "ac i ntds" "ifm" "create full c:\temp\AD" quit quit

# Extraction des hashes (post-acquisition, hors ligne)
python3 secretsdump.py -ntds NTDS.dit -system SYSTEM LOCAL

# Crackage NTLM hashes (offline)
hashcat -m 1000 hashes.txt rockyou.txt

🛠 Outils d'analyse AD
🔵 BloodHound

Cartographie graphique des chemins d'attaque AD. Ingère les données via SharpHound. Identifie les paths vers Domain Admin en quelques requêtes Cypher.

Open source · GUI Neo4j · standard pentest et défense.

🔴 Mimikatz

Extraction de credentials depuis LSASS. Fonctions : sekurlsa::logonpasswords, kerberos::list, kerberos::golden, lsadump::dcsync.

Outil offensif référence (Benjamin Delpy). Détecté par tous les EDR modernes.

🟢 Plaso / log2timeline

Timeline des logs AD et workstations. Corrèle EID 4624/4625/4768 pour reconstituer mouvements latéraux. Sortie : timeline CSV unifiée multi-source.

🟣 Impacket

Suite Python : secretsdump (hashes), smbclient, psexec, wmiexec, GetUserSPNs (Kerberoasting). Standard pour analyse post-exploitation AD.

🧠 Testez-vous
Vous voyez sur le DC : EID 4769 avec EncType=0x17 (RC4) pour 50 comptes de service en 5 minutes depuis le même utilisateur. Que se passe-t-il ?Attaque · Niveau : moyen
Kerberoasting en cours. Signaux clairs : (1) EncType 0x17 = RC4 — chiffrement faible, crackable hors-ligne avec hashcat (vs AES qui résiste mieux). Les attaquants demandent spécifiquement RC4 pour avoir des hashes faciles à cracker. (2) Volume anormal — un user normal demande des TGS pour 1-2 services par session, pas 50 en 5 minutes. (3) Cibles = comptes service avec SPN — typiquement MSSQLSvc/..., HTTP/..., HOST/.... Procédure forensique : (a) Identifier l'utilisateur source (TargetUserName dans l'événement), (b) Identifier la machine source (IP dans l'événement), (c) RAM dump immédiat de la workstation source — Mimikatz/Rubeus/GetUserSPNs probablement en mémoire, (d) Vérifier les comptes de service ciblés : ont-ils des MDP forts ? Si MDP < 12 chars → considérer comme déjà cassés. (e) Reset password immédiat des comptes service à risque + désactiver RC4 (msDS-SupportedEncryptionTypes), (f) Threat hunting sur les machines compromises : kerberoast peut être suivi de PtT avec ces tickets crackés. Outil détection : règles Sigma win_susp_kerberoasting, win_susp_high_rc4.
Quelle est la différence entre Pass-the-Hash et Pass-the-Ticket ?Concepts · Niveau : facile
Pass-the-Hash (PtH) : utilise le hash NTLM de l'utilisateur volé en RAM (LSASS) ou dans la base SAM/NTDS.dit. L'attaquant prouve son identité via NTLM en réutilisant le hash sans connaître le mot de passe en clair. Utilise le protocole NTLM, pas Kerberos. Détection : EID 4624 LogonType=3 + AuthPackage NtLmSsp · EID 4776. Pass-the-Ticket (PtT) : vole un ticket Kerberos (TGT ou TGS) directement de la mémoire (Mimikatz sekurlsa::tickets /export) puis le réinjecte sur sa propre machine (Mimikatz kerberos::ptt). Utilise le protocole Kerberos. Détection : EID 4768/4769 depuis IP inhabituelle, durée ticket anormale. Différence clé : PtH = NTLM (legacy, plus facile à détecter), PtT = Kerberos (plus moderne, plus furtif). Variantes avancées : Overpass-the-Hash = utiliser le hash NTLM pour demander un TGT Kerberos (mélange des deux). Golden Ticket = forge complète d'un TGT avec hash krbtgt (le ticket n'a jamais existé légitimement). Silver Ticket = forge d'un TGS avec hash du compte de service (cible un service spécifique, plus furtif que Golden). Mitigation : Credential Guard (Win10+), Protected Users group, désactivation NTLM, MFA Kerberos.
Une enquête révèle un Golden Ticket actif depuis 6 mois. Comment éradiquer cette persistance ?Remédiation · Niveau : difficile
Procédure d'éradication critique : un Golden Ticket valide signifie que le hash krbtgt est compromis et que l'attaquant peut forger des TGT pour n'importe quel utilisateur, y compris des comptes inexistants, sans limite de temps. Action immédiate : (1) Reset DEUX FOIS le mot de passe krbtgt avec délai entre les deux (le 2e reset après réplication complète + ~10h pour expirer les TGT en cours). Microsoft fournit le script officiel Reset-KrbTgt-Password.ps1. Pourquoi deux fois ? Active Directory garde les 2 derniers mots de passe krbtgt valides pour éviter les ruptures Kerberos pendant le rollover — un seul reset laisse l'ancien hash valide. (2) Reset MDP de tous les Domain Admins et comptes privilégiés. (3) Audit complet AD : rechercher tous les changements suspects depuis la date estimée de compromission — comptes créés (EID 4720), ajouts de groupe (4728/4732), GPO modifiées (5136), ACL modifiées (5136 sur AdminSDHolder), comptes service avec SPN ajoutés. (4) Inspecter SYSVOL : scripts logon altérés ? GPO malveillantes ? (5) Réinitialiser les comptes service à risque (Silver Tickets possibles). (6) Hunt sur workstations : signes de Mimikatz, dumps LSASS, persistance locale. (7) Reset les comptes machine ($) du domaine si massivement compromis. (8) Considérer un rebuild AD complet (forêt entière) si compromission profonde — la doctrine Microsoft recommande dans les cas extrêmes. Prévention future : Tier Model · Privileged Access Workstations (PAW) · LAPS · Credential Guard · ESAE/Red Forest · MFA · monitoring continu krbtgt password age.

━━ ATTAQUES PRINCIPALES ━━

• Pass-the-Hash (PtH) : réutilisation hash NTLM · NTLM · EID 4624 type 3 + 4776

• Pass-the-Ticket (PtT) : vol ticket Kerberos · sekurlsa::tickets · EID 4768/4769

• Golden Ticket : forge TGT avec hash krbtgt · god mode permanent

• Silver Ticket : forge TGS pour service spécifique · plus furtif

• Kerberoasting : TGS RC4 + crackage offline · EID 4769 EncType=0x17 en masse

• AS-REP Roasting : comptes sans pré-auth · EID 4768 sans préauthentification

• DCSync : réplication frauduleuse NTDS.dit · EID 4662 droit Replication

• Overpass-the-Hash : hash NTLM → TGT Kerberos (mix PtH + PtT)
