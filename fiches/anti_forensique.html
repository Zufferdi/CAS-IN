🕵️ L'art de la dissimulation des preuves
L'anti-forensique regroupe toutes les techniques visant à échapper à l'analyse ou la rendre coûteuse : altération d'horodatages, effacement sécurisé, dissimulation de fichiers, chiffrement, living off the land, rootkits. Pour l'enquêteur, chaque technique a sa contre-mesure — souvent dans des sources résiduelles ($UsnJrnl, $LogFile, Volume Shadow Copies, RAM, prefetch).
Techniques anti-forensiques
Pour chaque technique : son fonctionnement, ses traces résiduelles, et la méthode de détection.
⏱ Timestomping
Modification des timestamps NTFS ($STANDARD_INFORMATION) pour faire apparaître un fichier malveillant comme ancien. Outils : timestomp (Metasploit), SetMace.
Comparer $SI et $FILE_NAME — divergence = manipulation. Vérifier $UsnJrnl et $LogFile pour les vraies dates.
🧹 Wiping sécurisé
Écrasement avec patterns définis (DoD 5220.22-M = 3 passes : zéros, uns, aléatoire ; la version ECE 7 passes est l'extension de 2001 ; Gutmann = 35 passes, obsolète sur supports modernes ; NIST SP 800-88 recommande 1 passe sur HDD moderne, ou ATA Secure Erase / cryptographic erase pour les SSD). Outils : Eraser, SDelete, shred (Linux). Sur SSD, le TRIM rend le wiping classique partiellement inefficace.
Traces dans $UsnJrnl (fichier créé puis modifié intensivement), partitions formatées avec zones non allouées aléatoires.
📁 ADS — Alternate Data Streams
Cacher un exécutable ou des données dans un flux alternatif NTFS. Ex : calc.exe:malware.exe. Invisible dans l'explorateur Windows.
X-Ways → colonne ADS · dir /r (cmd) · Sysinternals streams.exe · tout fichier avec « : » dans le nom.
🔒 Chiffrement / VeraCrypt
Volumes chiffrés indiscernables d'un espace aléatoire. Volume caché (déni plausible) : deux MDP pour deux volumes dans le même fichier.
Entropie ≥ 0.997, taille ronde, absence de magic bytes. Passware + RAM dump pour FVEK. Le déni plausible est légalement reconnu en Suisse.
🖼 Stéganographie
Cacher des données dans une image JPEG, PNG ou audio. Outils : Steghide, OpenStego, DeepSound. Le fichier paraît normal visuellement.
StegDetect pour JPEG · comparer la taille avec images similaires · analyser LSB (Least Significant Bit) · test χ² sur distribution des pixels.
📋 Effacement des logs
Vidage des Event Logs Windows (wevtutil cl Security), modification des logs Linux (/var/log). Rootkits : hooks kernel pour masquer les entrées.
Gap dans les Event IDs (séquence non continue). $LogFile NTFS révèle les opérations même après effacement log. Sysmon écrit dans son propre canal.
🐚 Living off the Land
Utiliser des outils système légitimes (PowerShell, WMI, certutil, mshta) pour exécuter du code malveillant. Aucun binaire malveillant sur disque.
Event 4104 (ScriptBlock logging), Sysmon sur WMI et certutil, comparer les arguments de ligne de commande avec les usages normaux.
👻 Rootkits
Code s'installant dans le noyau OS pour masquer processus, fichiers, connexions réseau. Les UEFI rootkits survivent au formatage.
Volatility : pslist vs psscan (processus cachés). Comparer fichiers sur disque vs en mémoire. Analyse depuis OS live externe.

Volume Shadow Copies (VSS)
Volume Shadow Copies (VSS) — Le contournement de l'effacement
Snapshots Windows automatiques avant les mises à jour et restaurations. Souvent oubliés par les attaquants.
📸 Snapshots Windows — Trésor pour l'enquêteur

Windows crée automatiquement des Shadow Copies avant les mises à jour et restaurations. Elles contiennent des versions antérieures de fichiers — même effacés depuis. X-Ways peut monter un VSS directement.

# Lister les Shadow Copies existantes
vssadmin list shadows

# Monter une VSS spécifique en lecture seule
mklink /D C:\vss\snap1 \\?\GLOBALROOT\Device\HarddiskVolumeShadowCopy1\

# Sur Linux (image montée) — libvshadow
vshadowinfo disk.dd
vshadowmount disk.dd /mnt/vss/
🇨🇭 Déni plausible (VeraCrypt) — droit suisse : Un suspect peut refuser de donner le mot de passe d'un volume caché en invoquant le nemo tenetur (art. 113 CPP). La preuve de l'existence d'un volume caché est forensiquement très difficile à établir by design.
🎓 Exam Tip — Anti-Forensique

Timestomping → divergence $SI ≠ $FN dans la MFT

ADS → fichier avec « : » dans le nom → streams.exe ou X-Ways colonne ADS

Stéganographie → LSB + entropie + taille anormale + outils zsteg/stegdetect

Living off the Land → Event 4104 ScriptBlock PowerShell décodé

Volume Shadow Copies → versions antérieures même après effacement

Rootkit détecté → pslist ≠ psscan (Volatility)

Wiping SSD inefficace → TRIM efface les blocs en arrière-plan

Un fichier backup.zip a un timestamp de création datant de 2018, mais sa MFT entry montre $STANDARD_INFORMATION = 2018 et $FILE_NAME = 2024. Que conclure ?Timestomping · Niveau : moyen
Timestomping confirmé. L'attaquant a modifié $SI (visible dans Explorer) avec un outil type timestomp ou SetMace, mais $FN n'est mis à jour que par le système lui-même au moment de la création/renommage. La divergence trahit la manipulation. Vraie date de création = 2024 ($FN). Croiser avec : (1) $UsnJrnl qui enregistre les opérations FS, (2) $LogFile NTFS, (3) timestamps Prefetch / Amcache si le fichier a été exécuté.
Un suspect a effacé son historique navigateur. Aucun fichier n'est récupérable via carving. Que faire ?VSS · Niveau : facile
Vérifier les Volume Shadow Copies (VSS). Windows crée automatiquement des snapshots avant les mises à jour, restaurations système ou installations majeures. Ces VSS contiennent des copies historiques du profil utilisateur (incluant le navigateur — %LocalAppData%\Google\Chrome\User Data\Default\History). Lister avec vssadmin list shadows ou via X-Ways → menu Mount VSS. Si VSS désactivés ou nettoyés (vssadmin delete shadows /all), tenter Volatility sur dump RAM, ou reconstruire via cookies/cache résiduels en swap/pagefile.
