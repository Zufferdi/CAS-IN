🕵️ L'art de la dissimulation des preuves
L'anti-forensique regroupe toutes les techniques visant à échapper à l'analyse ou la rendre coûteuse : altération d'horodatages, effacement sécurisé, dissimulation de fichiers, chiffrement, living off the land, rootkits. Pour l'enquêteur, chaque technique a sa contre-mesure — souvent dans des sources résiduelles ($UsnJrnl, $LogFile, Volume Shadow Copies, RAM, prefetch).
Techniques anti-forensiques
Pour chaque technique : son fonctionnement, ses traces résiduelles, et la méthode de détection.
⏱ Timestomping
Modification des timestamps NTFS ($STANDARD_INFORMATION) pour faire apparaître un fichier malveillant comme ancien. Outils : timestomp (Metasploit), SetMace.
Comparer $SI et $FILE_NAME — divergence = manipulation. Vérifier $UsnJrnl et $LogFile pour les vraies dates.
🧹 Wiping sécurisé
Écrasement avec patterns aléatoires (DoD 5220.22-M : 7 passes). Outils : Eraser, SDelete, shred (Linux). Sur SSD, le TRIM rend le wiping partiellement inefficace.
Traces dans $UsnJrnl (fichier créé puis modifié intensivement), partitions formatées avec zones non allouées aléatoires.
📁 ADS — Alternate Data Streams
Cacher un exécutable ou des données dans un flux alternatif NTFS. Ex : calc.exe:malware.exe. Invisible dans l'explorateur Windows.
X-Ways → colonne ADS · dir /r (cmd) · Sysinternals streams.exe · tout fichier avec « : » dans le nom.
🔒 Chiffrement / VeraCrypt
Volumes chiffrés indiscernables d'un espace aléatoire. Volume caché (déni plausible) : deux MDP pour deux volumes dans le même fichier.
Entropie ≥ 0.997, taille ronde, absence de magic bytes. Passware + RAM dump pour FVEK. Le déni plausible est légalement reconnu en Suisse.
🖼 Stéganographie
Cacher des données dans une image JPEG, PNG ou audio. Outils : Steghide, OpenStego, DeepSound. Le fichier paraît normal visuellement.
StegDetect pour JPEG · comparer la taille avec images similaires · analyser LSB (Least Significant Bit) · test χ² sur distribution des pixels.
📋 Effacement des logs
Vidage des Event Logs Windows (wevtutil cl Security), modification des logs Linux (/var/log). Rootkits : hooks kernel pour masquer les entrées.
Gap dans les Event IDs (séquence non continue). $LogFile NTFS révèle les opérations même après effacement log. Sysmon écrit dans son propre canal.
🐚 Living off the Land
Utiliser des outils système légitimes (PowerShell, WMI, certutil, mshta) pour exécuter du code malveillant. Aucun binaire malveillant sur disque.
Event 4104 (ScriptBlock logging), Sysmon sur WMI et certutil, comparer les arguments de ligne de commande avec les usages normaux.
👻 Rootkits
Code s'installant dans le noyau OS pour masquer processus, fichiers, connexions réseau. Les UEFI rootkits survivent au formatage.
Volatility : pslist vs psscan (processus cachés). Comparer fichiers sur disque vs en mémoire. Analyse depuis OS live externe.

Volume Shadow Copies (VSS)
Volume Shadow Copies (VSS) — Le contournement de l'effacement
Snapshots Windows automatiques avant les mises à jour et restaurations. Souvent oubliés par les attaquants.
📸 Snapshots Windows — Trésor pour l'enquêteur

Windows crée automatiquement des Shadow Copies avant les mises à jour et restaurations. Elles contiennent des versions antérieures de fichiers — même effacés depuis. X-Ways peut monter un VSS directement.

# Lister les Shadow Copies existantes
vssadmin list shadows

# Monter une VSS spécifique en lecture seule
mklink /D C:\vss\snap1 \\?\GLOBALROOT\Device\HarddiskVolumeShadowCopy1\

# Sur Linux (image montée) — libvshadow
vshadowinfo disk.dd
vshadowmount disk.dd /mnt/vss/
EDR / AV bypass — Techniques modernes (2024-2026)
L'attaquant moderne ne se contente plus de timestomper : il neutralise activement la télémétrie EDR avant d'agir. Connaître ces techniques = savoir où chercher leurs traces.
🪝 EDR Unhooking
Les EDR (CrowdStrike, SentinelOne, Defender) injectent des hooks dans ntdll.dll en userland pour intercepter les syscalls. L'attaquant restaure les bytes originaux depuis une copie fraîche (D:\Windows\System32\ntdll.dll ou téléchargée). Outils : SharpUnhooker, RefleXXion, BananaPhone.
Comparer les premiers bytes de chaque export ntdll!Nt* en mémoire vs disque. Détection : sondes EDR kernel-mode (ELAM), Sysmon Event 8 (CreateRemoteThread), ETW Microsoft-Windows-Threat-Intelligence.
📡 ETW Patching
Event Tracing for Windows alimente la majorité de la télémétrie EDR. Patcher EtwEventWrite avec ret 0x14 (Windows x64) ou NtTraceEvent désactive silencieusement la télémétrie de PowerShell, .NET, AMSI. Outils : EtwTiSwallow, SilenceETW.
Comparer les bytes initiaux de EtwEventWrite en mémoire vs binaire signé. Sysmon log 25 (process tampering). Activer ETW providers kernel-mode (Microsoft-Windows-Kernel-Process) que l'attaquant ne peut pas patcher en userland.
🛡 AMSI Bypass
L'Antimalware Scan Interface scanne les scripts PowerShell/JS/VBA avant exécution. Bypass classique : patcher AmsiScanBuffer avec un saut vers S_OK. Variants 2024-2026 : memory patching via FFI, COM hijacking de l'IAmsiContext, AMSI provider remplacement via registre.
PowerShell Event 4104 capture le ScriptBlock avant le bypass — toujours vérifier ces logs. Defender ASR rule Block Office applications from creating executable content. Sysmon Event 7 (Image Loaded) sur amsi.dll dans des processus inattendus.
🔇 Direct/Indirect Syscalls
Au lieu d'appeler NtAllocateVirtualMemory via kernel32!VirtualAlloc (hooké), l'attaquant fait directement syscall avec le bon Service Number (SSN). Variants : HellsGate, HalosGate, TartarusGate (résolution dynamique du SSN). Indirect syscalls = jmp [ntdll!syscall_addr] pour rester dans la stack ntdll.
Stack call analysis : un syscall normal vient toujours de ntdll.dll. Origine = autre module = direct syscall. Sysmon ne capture pas, mais EDR kernel-mode oui (SspiCli, EDRSandblast). Hardware breakpoints (Intel PT) en R&D.
💉 Process Injection avancé
Au-delà du DLL injection classique : Early Bird APC (avant ResumeThread), Process Doppelgänging (TxF), Process Herpaderping (modify-on-disk), Phantom DLL Hollowing. Beaucoup ne déclenchent aucun écrit disque, donc invisibles à la signature AV classique.
RAM forensics indispensable : Volatility plugins malfind, hollowfind, ldrmodules. Sysmon Event 10 (ProcessAccess) avec GrantedAccess 0x1F1FFF + filtrage parent légitime (explorer.exe qui injecte = anormal).
🎭 BYOVD — Bring Your Own Vulnerable Driver
Charger un driver Windows signé légitimement mais vulnérable (ex. kdmapper + iqvw64.sys, dbutil_2_3.sys) pour obtenir un primitive d'écriture kernel. Désactive ensuite l'EDR via EtwTi kernel patching. Vu en 2023-2024 (BlackByte, AvosLocker).
Microsoft Vulnerable Driver Blocklist (depuis 2023, on by default sur Win11 + HVCI). Sysmon Event 6 (DriverLoaded) avec hash check vs liste connue. Liste publique sur loldrivers.io. Si HVCI/VBS désactivé sur le poste = signal d'alarme.
🌥 LOLBins & Cloud Living-off-the-Land
2024+ : utiliser des services cloud légitimes (Cloudflare Workers, AWS Lambda, GitHub Pages, Azure Front Door) comme C2 et exfiltration. Trafic = TLS sortant vers IP réputées, indétectable par signature.
Analyse comportementale (UEBA) : volume sortant inhabituel vers Workers/Pages, patterns DNS suspects (jitter beaconing). Logs DNS du firewall + Cloudflare Logpush. Ne pas bloquer Cloudflare/AWS sans contexte (faux positifs massifs).
🧊 Hibernation et hibernation file abuse
L'attaquant déclenche une hibernation Windows juste avant ses opérations. hiberfil.sys capture la RAM mais l'attaquant peut l'altérer en post-mortem (montage en lecture-écriture sous WinPE) pour effacer ses propres traces. Vu dans des cas APT 2024.
Comparer le hash du hiberfil.sys à différentes époques (VSS). Capture RAM en live avant redémarrage. Volatility 3 plugin hibernation identifie les manipulations dans la structure du fichier.

💡 Pour l'enquêteur : Quand vous tombez sur un poste où l'EDR semblait actif mais aucun alert n'a remonté, suspectez bypass. Sources résiduelles fiables : logs Sysmon (s'ils sont activés et exfiltrés vers SIEM externe), ETW kernel via logman ou outil SilkETW, artefacts disque classiques (Prefetch, Amcache, $UsnJrnl), RAM dump pour trouver les hooks restaurés ou syscalls inhabituels, logs réseau du proxy/firewall (côté attaquant peut désactiver l'agent local mais pas les flux sortants).
🇨🇭 Déni plausible (VeraCrypt) — droit suisse : Un suspect peut refuser de donner le mot de passe d'un volume caché en invoquant le nemo tenetur (art. 113 CPP). La preuve de l'existence d'un volume caché est forensiquement très difficile à établir by design.

Un fichier backup.zip a un timestamp de création datant de 2018, mais sa MFT entry montre $STANDARD_INFORMATION = 2018 et $FILE_NAME = 2024. Que conclure ?Timestomping · Niveau : moyen
Timestomping confirmé. L'attaquant a modifié $SI (visible dans Explorer) avec un outil type timestomp ou SetMace, mais $FN n'est mis à jour que par le système lui-même au moment de la création/renommage. La divergence trahit la manipulation. Vraie date de création = 2024 ($FN). Croiser avec : (1) $UsnJrnl qui enregistre les opérations FS, (2) $LogFile NTFS, (3) timestamps Prefetch / Amcache si le fichier a été exécuté.
Un suspect a effacé son historique navigateur. Aucun fichier n'est récupérable via carving. Que faire ?VSS · Niveau : facile
Vérifier les Volume Shadow Copies (VSS). Windows crée automatiquement des snapshots avant les mises à jour, restaurations système ou installations majeures. Ces VSS contiennent des copies historiques du profil utilisateur (incluant le navigateur — %LocalAppData%\Google\Chrome\User Data\Default\History). Lister avec vssadmin list shadows ou via X-Ways → menu Mount VSS. Si VSS désactivés ou nettoyés (vssadmin delete shadows /all), tenter Volatility sur dump RAM, ou reconstruire via cookies/cache résiduels en swap/pagefile.
