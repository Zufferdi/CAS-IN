🇨🇭 Pratique suisse : X-Ways Forensics génère MD5 + SHA-1 + SHA-256 simultanément lors de l'acquisition. Le hash MD5 reste requis par certains tribunaux cantonaux pour la compatibilité avec les outils existants.
Rôle du hachage en forensique
✅ Authenticité de l'image

Le hash calculé juste après l'acquisition (hash A) doit être identique au hash recalculé avant analyse (hash B). A = B → l'image est intacte.

🔍 Identification de fichiers connus

Comparaison avec les bases NSRL (National Software Reference Library), HashKeeper, Project VIC. Permet de filtrer les fichiers système et identifier du contenu illicite connu.

🔗 Chaîne de possession

Chaque transfert de preuve doit être accompagné du hash. Si le hash change → altération détectée. Documenté dans le rapport d'acquisition.

⚠️ Limitations MD5 / SHA-1

MD5 : collisions connues depuis 2004 (Wang et al.). SHA-1 : collision pratique démontrée par Google (SHAttered, 2017). Ne pas utiliser seul pour la recevabilité.

SSDEEP — Hachage par similarité (fuzzy hashing)
Principe du fuzzy hashing

Contrairement à MD5/SHA, SSDEEP produit un hash qui varie graduellement avec le contenu. Deux fichiers similaires à 80% auront des hashs SSDEEP similaires — impossible avec les hash classiques.

Cas d'usage
  • Détecter des variantes d'un malware (même code, emballage différent)
  • Retrouver des copies modifiées d'un document
  • Corréler des artefacts similaires sur plusieurs systèmes
  • Outils : ssdeep CLI, X-Ways (fuzzy hash), Autopsy
Score de similarité

Score 0–100 %. 0 = aucune similarité · 100 = identique.

Seuil pratique : ≥ 70 % → probable variante.
Attention aux faux positifs sur les petits fichiers (entropie faible).

Entropie de Shannon — Détecter le chiffrement

L'entropie mesure l'aléatoire du contenu (0 = totalement prévisible, 1 = totalement aléatoire). Utile pour détecter les fichiers chiffrés ou compressés.

Rapport d'acquisition & droit suisse
Éléments requis dans le rapport
  • Date et heure exactes de l'acquisition
  • Outil utilisé (X-Ways, FTK Imager, dd…) + version
  • Hash de l'image avant ET après
  • Hash des pièces à conviction originales
  • Numéro de scellé (art. 248 CPP)
⚖️ Recevabilité (TF + CPP)
  • Hash discordant → preuve potentiellement irrecevable
  • TF 1B_602/2020 : procédure de scellés iPhone, hash exigé
  • ISO/IEC 27037 §8.3 : documentation de l'intégrité obligatoire
  • Art. 192 CPP : authenticité des pièces à conviction
⚖️ Point clé examen : Un hash MD5 ne suffit plus seul (collisions démontrées). SHA-256 est le minimum recommandé. En pratique : calculer MD5 + SHA-256 simultanément pour la rétro-compatibilité et la sécurité.
⚖️ Examen CAS-IN : SHA-256 = minimum requis · MD5 seul = collisions connues (insuffisant) · SSDEEP = fuzzy hashing pour similarité · Entropie ≥ 0.95 = probable chiffrement · Chaîne de custody : hash avant ET après acquisition · Art. 192 CPP : authenticité des pièces à conviction.
