🔑 Principe — Master Boot Record
Le MBR occupe le tout premier secteur du disque (LBA 0, 512 octets). Il contient le bootloader (446 octets), la table de 4 partitions primaires (64 octets, 16 octets chacune) et la signature de boot 55 AA. C'est le point d'entrée absolu de tout disque Windows pré-2012 et de nombreux disques Linux/forensiques.

Types de partitions MBR — Byte 0x04
0x07
NTFS / exFAT
Le plus courant sur les disques Windows. Vérifier l'OEM Name pour distinguer NTFS de exFAT.
0x0C
FAT32 (LBA)
FAT32 avec adressage LBA. Le plus courant sur clés USB et cartes SD < 32 Go.
0x0B
FAT32 (CHS)
FAT32 avec adressage CHS legacy. Identique à 0x0C côté structure interne.
0x83

Partition Linux native. Identifier ext2/3/4 via le magic 0xEF53 dans le superbloc à offset 1080.
0x82
Linux Swap
Zone de pagination RAM Linux. Pas de FS — mais peut contenir des résidus de RAM (mots de passe, clés).
0x05 / 0x0F
Étendue
Contient des partitions logiques (EBPB). 0x05 = CHS, 0x0F = LBA. Chaque logique a son propre EBR.
0xEE
GPT Protective
Indique un disque GPT. Une seule entrée 0xEE qui couvre tout le disque — le vrai schéma est dans le GPT Header à LBA 1.
0x17 / 0x1B
Partitions cachées
Versions "cachées" de NTFS (0x17) et FAT32 (0x1B). L'OS ne les monte pas automatiquement — IOC potentiel.

🔍 Signatures MBR essentielles

  • Signature boot : 55 AA aux offsets 0x1FE–0x1FF
  • Première partition entry : offset 0x1BE (446 en décimal)
  • Bootstrap code vide (zéros) : disque non bootable ou effacé
  • Type 0xEE → disque GPT (Protective MBR)
  • Type 0x00 en entrée → slot de partition vide

⚡ Formules MBR essentielles

  • Offset entrée N = 0x1BE + (N × 16), N ∈ {0,1,2,3}
  • Offset absolu partition = LBA_Start × BytesPerSector
  • Taille partition = LBA_Size × BytesPerSector
  • LBA_Start & LBA_Size : Little Endian 32 bits
  • Ex. LBA Start = 00 08 00 00 → 0x00000800 = 2048 secteurs = offset 1 048 576 o
🔑 Principe — GUID Partition Table
GPT est le successeur du MBR, défini par le standard UEFI. Il supporte jusqu'à 128 partitions, des disques jusqu'à 9,4 Zo, et intègre une redondance primaire/secondaire (header et table dupliqués). Tout disque GPT commence par un Protective MBR (type 0xEE) pour la compatibilité avec les outils hérités.

GPT Header — Champs clés (LBA 1, 92 octets utilisés)
Offset Taille Champ Valeur type / Forensique
0x00 8 o Signature 45 46 49 20 50 41 52 54 = "EFI PART" — présent dans le header primaire ET le backup
0x08 4 o Revision 00 00 01 00 = version 1.0. Inchangé depuis l'introduction de GPT.
0x10 4 o Header CRC32 CRC32 du header (ce champ mis à zéro pour le calcul). Forensique : CRC invalide = header corrompu ou manipulé → utiliser le backup.
0x18 8 o My LBA LBA de ce header. Primaire = 1, Backup = dernier LBA. Forensique : divergence → copie déplacée ou image tronquée.
0x20 8 o Alternate LBA LBA du header miroir. Primaire pointe vers backup, backup pointe vers primaire. Cohérence à vérifier.
0x28 8 o First Usable LBA Début de la zone utilisable (LBA 34 typiquement). Les LBA 1–33 sont réservés aux métadonnées GPT.
0x30 8 o Last Usable LBA Fin de la zone utilisable (n−34). Forensique : espace entre Last Usable LBA et Backup Table = zone non allouée potentiellement exploitable.
0x38 16 o Disk GUID Identifiant unique du disque (128 bits). Forensique : pivot de corrélation entre images, logs Windows, partitions. Modifiable par anti-forensique.
0x48 8 o Partition Entry LBA LBA du début de la table de partitions (LBA 2 dans le header primaire).
0x50 4 o Num Partition Entries Nombre d'entrées de partition (typiquement 128, même si seules quelques-unes sont utilisées).
0x58 4 o Partition Entry CRC32 CRC32 de la totalité de la table de partitions. Forensique : CRC invalide = table modifiée ou corrompue.

🔍 Signatures GPT essentielles

  • GPT Header : 45 46 49 20 50 41 52 54 = "EFI PART" à LBA 1
  • Protective MBR : type 0xEE à l'offset 0x1C2, couvre tout le disque
  • Backup header : dernier LBA du disque — toujours vérifier la cohérence
  • Partition Name : encodé en UTF-16LE (2 octets par caractère)

⚡ MBR vs GPT — différences clés

  • Partitions : 4 primaires (MBR) vs 128 (GPT)
  • Disque max : 2 To (MBR, 32 bits LBA) vs 9,4 Zo (GPT, 64 bits)
  • Redondance : aucune (MBR) vs header + table dupliqués (GPT)
  • Intégrité : aucun CRC (MBR) vs CRC32 header + table (GPT)
  • ID disque : 4 octets @ 0x1B8 (MBR) vs GUID 128 bits (GPT)
🔍 Approche forensique — Table de partitions
La table de partitions est le premier élément à analyser sur tout support. Elle détermine les offsets des FS, révèle les zones cachées, et peut contenir des traces de manipulation (partitions supprimées, chevauchements, entrées altérées). Sur un disque GPT, toujours comparer le header primaire et le backup.
Workflow d'analyse — Premier contact avec un disque
1
Déterminer MBR ou GPT
Lire l'offset 0x1C2 du secteur 0. Si 0xEE → GPT. Sinon → MBR classique. Toujours vérifier la signature 55 AA @ 0x1FE.
2
Lister les partitions et calculer les offsets
Pour chaque entrée non vide : Offset = LBA_Start × 512. Vérifier que les partitions ne se chevauchent pas. Un chevauchement est un IOC fort.
3
Identifier les zones non allouées
Espace entre la fin d'une partition et le début de la suivante = potentielle zone cachée (HPA, zone de données dissimulées). Cartographier tout le disque.
4
Vérifier la cohérence (GPT)
Comparer header primaire (LBA 1) et backup (LBA n). CRC invalide sur le primaire mais backup intact = tentative d'altération détectée. Comparer les Disk GUIDs.
5
Documenter avant toute montage
L'accès à une partition peut modifier des timestamps ou déclencher un TRIM sur SSD. Toujours travailler sur une image bloquée en écriture (--ro ou write-blocker).
IOC — Indicateurs de compromission au niveau partitions
🚨 Partition cachée / type modifié
Type 0x17 (NTFS caché) ou 0x1B (FAT32 caché) à la place de 0x07/0x0C. L'OS ne monte pas ces partitions automatiquement — elles passent souvent inaperçues.
🚨 Chevauchement de partitions
LBA_Start d'une partition qui pointe à l'intérieur d'une autre. Impossible dans un usage normal — indique une manipulation de la table pour dissimuler des données.
🚨 Zone non allouée entre partitions
Espace inhabituellement large entre deux partitions (plusieurs Mo/Go). Peut contenir un FS masqué ou des données exfiltrées. Toujours scanner avec file carving.
🚨 Signature MBR modifiée (Bootkits)
Le code de bootstrap (offsets 0x000–0x1BD) est remplacé par un bootkit (ex: TDL4, Rovnix). Comparer avec le MBR original Windows ou hash connu. Signature 55 AA toujours présente — ne pas se fier à elle seule.
🚨 GPT CRC invalide
CRC32 du header GPT primaire ne correspond pas au contenu. Si le backup est intact → altération ciblée du header primaire (tentative de rendre le disque illisible ou de masquer une partition).
🚨 Disk ID / GUID incohérent
Le Disk ID MBR (4 octets @ 0x1B8) ou le Disk GUID GPT ne correspond pas aux logs Windows (HKLM\SYSTEM\MountedDevices). Indique un remplacement du disque ou une image clonée sans réidentification.

🔑 Disk ID Windows — corrélation

  • MBR Disk ID (4 o @ 0x1B8) référencé dans le registre : HKLM\SYSTEM\MountedDevices
  • GPT Disk GUID visible dans diskpart → list disk → detail disk
  • Logs d'événements : Event ID 98 (Volume Mount) contient le GUID
  • Incohérence Disk ID ↔ registre = disque remplacé, cloné ou virtualisé

🔑 Bootkits — Indicateurs MBR

  • Hash du secteur 0 ≠ hash MBR Windows de référence → compromis
  • Bootstrap modifié mais 55 AA intact → bootkit classique
  • Code après offset 0x1FD mais avant les entries → zone de stockage bootkit
  • Outils : MBRScan, GMER, comparer avec image propre

❓ Questions de révision
Quel offset dans le secteur MBR contient la première partition entry ? Quelle est sa taille ?MBR · Niveau : facile
La première partition entry commence à l'offset 0x1BE (446 en décimal) et fait 16 octets. Les 4 entries occupent les offsets 0x1BE–0x1FD. La signature 55 AA suit aux offsets 0x1FE–0x1FF. Formule pour l'entrée N (0 à 3) : 0x1BE + N × 16.
Comment distinguer un disque MBR d'un disque GPT sans logiciel spécialisé ?MBR vs GPT · Niveau : facile
Lire le type byte de la première partition entry à l'offset 0x1C2 (offset 0x1BE + 4 octets = entrée 1, champ type). Si la valeur est 0xEE → Protective MBR → disque GPT. Tout autre type → MBR classique. Confirmer avec la signature "EFI PART" au LBA 1 (offset 512 du disque).
Une partition entry MBR contient LBA Start = 00 08 00 00 en Little Endian et BPS = 512. Quel est l'offset absolu de début de cette partition ?LBA → Offset · Niveau : moyen
Décodage LE : 00 08 00 00 → 0x00000800 = 2048 secteurs. Offset = 2048 × 512 = 1 048 576 octets = 1 Mo. C'est l'alignement standard Windows (1 Mo = 2048 secteurs de 512) depuis Windows Vista — optimisé pour les SSD et les disques Advanced Format.
Pourquoi le GPT a-t-il deux copies du header et de la table de partitions ? Quelle est l'implication forensique d'une divergence entre les deux ?GPT Redondance · Niveau : moyen
Le GPT stocke un header primaire (LBA 1) et un backup (dernier LBA), ainsi qu'une table primaire (LBA 2–33) et backup (avant le dernier LBA). Implication forensique : une divergence entre primaire et backup indique soit une corruption (panne, arrachage), soit une manipulation ciblée — par exemple effacer une partition du header primaire en laissant la table backup intacte. L'analyste doit toujours comparer les deux et vérifier les CRC32 des deux headers. Le backup permet aussi la récupération si le header primaire est effacé.
Lors de l'analyse d'une image disque, tu constates une zone de 50 Mo entre la fin de la partition 1 et le début de la partition 2. Quelles sont tes hypothèses et actions ?Zone non allouée · Niveau : difficile
Hypothèses : (1) Partition supprimée dont l'entry a été effacée — les données restent intact. (2) Zone de stockage volontairement cachée (disque chiffré, conteneur VeraCrypt). (3) Alignement inhabituel sans raison technique — IOC. (4) HPA partielle visible dans la table mais pas dans le firmware.

Actions :
· mmls pour confirmer l'étendue exacte de la zone
· File carving avec bulk_extractor ou Autopsy sur les secteurs concernés
· Chercher des magic bytes de FS (FAT : EB 58 90, NTFS : EB 52 90, ext4 : 53 EF @ offset +0x438, VeraCrypt : octets aléatoires sans signature)
· Calculer l'entropie : entropie ~8 bits/octet = chiffrement probable
· Documenter l'offset et la taille précise dans le rapport
Qu'est-ce que le Disk ID MBR (offset 0x1B8) et comment l'utiliser en forensique Windows ?Disk ID · Niveau : moyen
Le Disk ID (ou Disk Signature) est un identifiant de 4 octets stocké à l'offset 0x1B8 dans le MBR. Windows l'utilise pour identifier les disques de manière unique, indépendamment du port SATA/USB utilisé.

Valeur forensique :
· Référencé dans HKLM\SYSTEM\MountedDevices — croise les clés \DosDevices\C: et \DosDevices\??\Volume{GUID}
· Si le Disk ID du disque saisi ≠ la valeur dans le registre de la machine → le disque a été remplacé ou cloné
· Permet de retrouver quel disque était branché sur quelle lettre de lecteur, même après déconnexion
· Sur GPT, équivalent = Disk GUID (offset 0x38 du GPT Header)
🎯 Essentiel terrain : MBR = LBA 0, signature 55 AA @ 0x1FE, 4 partitions primaires max · Partition entry = 16 octets depuis 0x1BE · LBA Start @ 0x08 (LE32) · Type 0x07=NTFS/exFAT, 0x0C=FAT32 LBA, 0x83=Linux, 0xEE=GPT Protective · Offset absolu = LBA_Start × 512 · GPT = "EFI PART" @ LBA 1, 128 partitions, CRC32, backup au dernier LBA · Disk ID (0x1B8) corrélable au registre Windows · Zone inter-partitions non allouée = carving systématique.
