🐧🍎 macOS & Linux — La famille Unix au quotidien
Linux et macOS partagent un héritage Unix / POSIX commun (1970), ce qui se reflète dans leur structure (arborescence /, permissions rwx, processes, /etc, /var, /home, etc.). Mais ils divergent radicalement : macOS est fermé, propriétaire, ajoute des couches Apple (Cocoa, Spotlight, Quarantine, FSEvents, LaunchAgents) au-dessus du noyau Darwin (BSD); Linux est open source, fragmenté en distributions (Ubuntu, Debian, Fedora, Arch...), avec des artefacts standardisés (syslog, journald, .bash_history, /etc/passwd). Forensiquement, ces deux OS sont longtemps restés moins documentés que Windows dans la formation forensique classique — pourtant ils représentent ensemble ~30% des desktops et plus de 95% des serveurs Internet (Apache, Nginx, Postfix tournent presque tous sur Linux). Le forensiste moderne doit les maîtriser : un APT cible souvent des serveurs Linux pour exfiltrer des données ; un Mac de cadre supérieur contient potentiellement des secrets industriels critiques. Bonne nouvelle : grâce à POSIX, beaucoup de techniques sont transposables (commandes shell, structure /etc/, /home/), et les artefacts Apple sont aujourd'hui bien documentés (SANS FOR518, Sarah Edwards, mac4n6).

/proc/[pid]/fd/ — Fichiers ouverts en temps réel

Si un fichier est supprimé pendant qu'un processus l'a ouvert, il reste accessible via /proc/[pid]/fd/[numéro] jusqu'à la fermeture du processus.


ls -la /proc/$(pidof apache2)/fd/
→ Liens symboliques vers les fichiers ouverts, même supprimés.


cp /proc/[pid]/fd/4 /tmp/recovered.log
→ Copie d'un log supprimé encore ouvert par le daemon.


Technique critique pour récupérer des fichiers supprimés sur un système live sans redémarrage.

💡 EXT4 vs EXT2 récupération : EXT2 conserve les pointeurs de blocs après suppression → récupération directe. EXT4 efface les pointeurs (block pointer zeroing) → obligatoire de passer par le journal (ext4magic) ou le carving. Voir aussi : debugfs pour inspection interactive.
🧠 Testez-vous
Vous voulez prouver qu'un suspect a téléchargé un PDF sensible sur son Mac le 12 mars. Quel artefact privilégier ?macOS · Niveau : facile
QuarantineEventsV2. Localisation : ~/Library/Application Support/com.apple.LaunchServices/com.apple.LaunchServices.QuarantineEventsV2 = base SQLite. Quand macOS télécharge un fichier (Safari, Mail, Messages, AirDrop...), il marque le fichier comme « quarantine » via un attribut étendu com.apple.quarantine et enregistre dans QuarantineEventsV2 : (1) URL exacte de la source, (2) horodatage précis, (3) application qui a téléchargé, (4) titre de la page source, (5) UUID de l'événement. Avantage forensique majeur : persiste après suppression du fichier téléchargé. Requête SQL : SELECT datetime(LSQuarantineTimeStamp+978307200,'unixepoch'), LSQuarantineDataURLString, LSQuarantineAgentName FROM LSQuarantineEvent ORDER BY LSQuarantineTimeStamp DESC; (epoch Cocoa = +978307200 sec UNIX). Compléments : (a) knowledgeC.db peut prouver que Safari était utilisé à ce moment, (b) Unified Log peut contenir l'événement réseau, (c) ~/Library/Safari/Downloads.plist liste l'historique download Safari spécifiquement.
Sur un serveur Linux compromis, où chercher des persistances installées par l'attaquant ?Linux Persistance · Niveau : moyen
Plusieurs emplacements à inspecter (par ordre de priorité forensique) : (1) Cron jobs — /var/spool/cron/crontabs/* (par user), /etc/crontab (système), /etc/cron.{daily,hourly,weekly,monthly}/ (scripts), /etc/cron.d/ (fichiers cron). Lister tous : for u in $(cut -f1 -d: /etc/passwd); do crontab -l -u $u 2>/dev/null; done. (2) Systemd units — /etc/systemd/system/*.service, /lib/systemd/system/, /usr/lib/systemd/system/, ~/.config/systemd/user/. Lister actifs : systemctl list-unit-files --state=enabled. (3) SSH keys — ~/.ssh/authorized_keys de chaque utilisateur (donne accès distant). (4) Init scripts (legacy) — /etc/init.d/, /etc/rc.local. (5) Profile / shell init — ~/.bashrc, ~/.bash_profile, /etc/profile, /etc/bash.bashrc (commandes au login). (6) sudoers — /etc/sudoers, /etc/sudoers.d/* (privilèges escaladés). (7) PAM modules — /etc/pam.d/ (backdoors auth). (8) LD_PRELOAD — /etc/ld.so.preload (injection libs). (9) Comptes — /etc/passwd + /etc/shadow : nouveaux utilisateurs créés. (10) Kernel modules — lsmod + /etc/modules-load.d/. Outil forensique : UAC (Unix-like Artifacts Collector) automatise toute cette collecte.
Vous saisissez un Mac. Le suspect a effacé son ~/.bash_history. Tout est-il perdu ?macOS Terminal · Niveau : moyen
Pas du tout. Plusieurs sources alternatives : (1) Sur Mac récents (10.15+), le shell par défaut est zsh, pas bash — chercher ~/.zsh_history. Beaucoup ne savent pas et continuent d'effacer .bash_history sans toucher au vrai. (2) Unified Log — log show --predicate 'process == "Terminal"' --last 7d peut contenir des références à des commandes (selon verbosity). (3) Récupération SQLite de Terminal.app — ~/Library/Saved Application State/com.apple.Terminal.savedState/ contient parfois l'état d'anciennes sessions. (4) Spotlight Store-V2 peut avoir indexé le contenu de .bash_history avant suppression. (5) Time Machine backups locaux automatiques sur disque externe ou local snapshots APFS — tmutil listlocalsnapshots /. (6) APFS snapshots automatiques (jusqu'à 24h). (7) FSEvents peut révéler les modifications de .bash_history — heure d'effacement. (8) Fichiers .lesshst, .viminfo, .python_history, .mysql_history, etc. — autres histories spécifiques. (9) Process accounting si activé (/var/log/usrmon). (10) RAM dump si machine encore vive — bash garde l'historique en mémoire jusqu'à fermeture du shell. L'effacement de .bash_history est un IOC en soi — preuve d'intention de dissimulation.
Sur Linux EXT4, vous voulez récupérer un fichier supprimé il y a 1 heure. Comment faire ?EXT4 récupération · Niveau : difficile
EXT4 a une particularité : à la différence de EXT2/EXT3, il efface les pointeurs de blocs dans l'inode lors de la suppression (block pointer zeroing) — donc la récupération directe via inode est impossible. Stratégies : (1) Vérifier si le fichier est encore ouvert par un process : lsof | grep deleted ou ls -la /proc/*/fd/ 2>/dev/null | grep deleted. Si oui, le récupérer via cp /proc/<pid>/fd/<n> /tmp/recovered_file (technique magique POSIX : tant que le file descriptor est ouvert, le fichier reste accessible même après rm). (2) Journal EXT4 — le journal contient parfois encore les anciens pointeurs : utiliser ext4magic qui parse le journal et reconstruit les inodes : ext4magic -r -j /dev/sda1. Fenêtre de récupération typique : quelques heures à quelques jours. (3) extundelete — outil similaire mais moins efficace sur EXT4 récents. (4) debugfs — exploration interactive : debugfs -R 'lsdel' /dev/sda1 liste les inodes supprimés récemment, puis debugfs -R 'dump <inode> /tmp/recovered' /dev/sda1. (5) Carving — dernier recours, par signature avec foremost, scalpel, ou PhotoRec. Récupère le contenu mais perd le nom et la structure. Best practice : démonter immédiatement le filesystem (umount) ou monter en read-only pour éviter que le bloc soit réutilisé. Sur SSD avec TRIM, fenêtre très courte (minutes).
🎓 Exam Tip — macOS & Linux

Héritage Unix/POSIX commun : structure /, permissions rwx, processes, /etc, /var, /home

macOS = Darwin (BSD) + couches Apple · Linux = noyau Linux + GNU + distros

━━ macOS ARTEFACTS CLÉS ━━

• QuarantineEventsV2 = URL source de chaque téléchargement (persistant !)

• FSEvents (/.fseventsd/) = équivalent USN Journal NTFS — modifs FS

• Spotlight Store-V2 = index de recherche très riche

• Unified Log (.tracev3) = remplace syslog depuis 10.12 · log show --last 24h

• knowledgeC.db = timeline d'usage (apps, verrouillages, mouvement)

• LaunchDaemons (root) / LaunchAgents (user) = persistance

• Epochs : HFS+ = 1904 · APFS / plist = 2001 (Cocoa epoch)

━━ LINUX ARTEFACTS CLÉS ━━

• ~/.bash_history · ~/.zsh_history = commandes shell

• /var/log/auth.log · syslog · journalctl (systemd)

• /var/log/wtmp = logins (last -f)

• /etc/crontab · /var/spool/cron/ = persistance scheduler

• /etc/systemd/system/*.service = persistance moderne

• ~/.ssh/authorized_keys = accès SSH

• /proc/<pid>/fd/ = fichiers ouverts (récupération live possible !)

━━ EXT4 PARTICULARITÉ ━━

EXT4 efface les pointeurs de blocs à la suppression (block pointer zeroing)

→ obligation de passer par le journal (ext4magic) ou le carving

━━ OUTILS ━━

macOS : mac_apt · APOLLO · iLEAPP · UFADE

Linux : TSK · Autopsy · LiME (RAM) · Volatility · plaso/log2timeline · ext4magic · UAC
