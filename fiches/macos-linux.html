🐧 Fun fact Unix : rm vient de "remove" mais ne supprime pas vraiment les données — il supprime juste le lien (dentry) entre le nom et l'inode. Si le fichier est ouvert par un process au moment du rm, il reste accessible via /proc/<pid>/fd/ jusqu'à la fermeture du process. Technique de récupération en temps réel.

🐧🍎 macOS & Linux — La famille Unix au quotidien
Linux et macOS partagent un héritage Unix / POSIX commun (1970), ce qui se reflète dans leur structure (arborescence /, permissions rwx, processes, /etc, /var, /home, etc.). Mais ils divergent radicalement : macOS est fermé, propriétaire, ajoute des couches Apple (Cocoa, Spotlight, Quarantine, FSEvents, LaunchAgents) au-dessus du noyau Darwin (BSD); Linux est open source, fragmenté en distributions (Ubuntu, Debian, Fedora, Arch...), avec des artefacts standardisés (syslog, journald, .bash_history, /etc/passwd). Forensiquement, ces deux OS sont longtemps restés moins documentés que Windows dans la formation forensique classique — pourtant ils représentent ensemble ~30% des desktops et plus de 95% des serveurs Internet (Apache, Nginx, Postfix tournent presque tous sur Linux). Le forensiste moderne doit les maîtriser : un APT cible souvent des serveurs Linux pour exfiltrer des données ; un Mac de cadre supérieur contient potentiellement des secrets industriels critiques. Bonne nouvelle : grâce à POSIX, beaucoup de techniques sont transposables (commandes shell, structure /etc/, /home/), et les artefacts Apple sont aujourd'hui bien documentés (SANS FOR518, Sarah Edwards, mac4n6).

🎓 Exam Tip — macOS & Linux (vue comparative)

Héritage Unix/POSIX commun : arborescence /, permissions rwx, /etc, /var, /home, shell, inode

macOS = Darwin (BSD) + couches Apple · Linux = noyau Linux + GNU + distributions

━━ macOS — Points clés ━━

• QuarantineEventsV2 = URL source de chaque téléchargement (persiste après suppression du fichier)

• FSEvents (/.fseventsd/) ≈ $UsnJrnl NTFS · knowledgeC.db = boîte noire utilisateur

• LaunchDaemons (root, avant login) / LaunchAgents (user, au login) = persistance

• Epochs : HFS+ = 1904 · APFS / plist = 2001 · conversion Unix : +978307200

━━ Linux — Points clés ━━

• auth.log = SSH/sudo · audit.log = syscalls kernel · journalctl = systemd logs

• ~/.ssh/authorized_keys = persistance SSH · /proc/[pid]/fd/ = fichiers ouverts live

• EXT4 : block pointer zeroing → journal (ext4magic) ou carving obligatoire pour la récupération
