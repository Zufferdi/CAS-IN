📦 SQLite = Embedded Database Format
Self-contained SQL database engine. No server needed. Used in 90%+ of applications (browsers, apps, OS). Format is well-documented (sqlite.org).
SQLite File Structure (Bytes)
Offset | Content

0x00 | Magic Header: "SQLite format 3\0" (16 bytes)
        Signature = 53 51 4C 69 74 65 20 66 6F 72 6D 61 74 20 33 00

0x10 | Page size (2 bytes, big-endian): usually 4096
0x12 | Database version
0x13 | Format write version

0x100 | Page 1 (B-Tree root)
        Contains table + index definitions

0x4100 | Page 2
        More data pages (linked by B-Tree)

End | Free list
        Deleted records (recoverable!)
🔍 Forensic Keys
  • Page size = 4096 (common) = easier to find boundaries
  • B-Tree structure = linked pages (can recover deleted)
  • Free pages = unallocated space (contains deleted data)
  • No encryption by default (plaintext when SQLCipher not used)

🔷 Chrome = SQLite History Database
Chrome stores browsing history in SQLite. Includes: URLs, visit times, page titles, visit counts. Complete timeline of user web activity.
Chrome History Tables
Table Columns Forensic Value
urls id, url, title, visit_count, last_visit_time 🔴 Main artifact (all visited URLs)
visits id, url_id, visit_time, transition, referrer Timeline (each visit individually)
keyword_search_terms keyword_id, url_id, term Search queries entered
Timestamp Format (Important!)
Chrome uses WebKit timestamp (microseconds since 1601-01-01).
last_visit_time = 13379999880000000 (example)
Convert: divide by 1,000,000 = 13379999880
Then: subtract 11644473600 = 1735526280
Unix time → 2024-12-29 16:31:20 UTC

🦊 Firefox = places.sqlite
Firefox uses SQLite for history + bookmarks. File: places.sqlite. Contains complete browsing timeline + bookmark organization.
Firefox places.sqlite Tables
Table Content
moz_places URLs (id, url, title, visit_count, last_visit_date)
moz_historyvisits Visits (id, place_id, visit_date, visit_type)
moz_bookmarks Bookmarks (id, parent, title, url, dateAdded)
Firefox Timestamp Format
Microseconds since Unix epoch (different from Chrome!)
visit_date = 1703862680000000 (example)
Convert: divide by 1,000,000 = 1703862680
→ 2023-12-29 16:31:20 UTC (Unix timestamp)
Firefox Cookies & Prefs

prefs.js (plaintext JavaScript)
  • User preferences
  • Extension settings

CLI Quick Commands
# Open and query database
$ sqlite3 History
sqlite> SELECT url, last_visit_time FROM urls;

# Dump entire database to text
$ sqlite3 History ".dump" > output.sql

# Export to CSV
$ sqlite3 -header -csv History "SELECT url, title, visit_count FROM urls;" > urls.csv

# List all tables
$ sqlite3 History ".tables"

# Show schema
$ sqlite3 History ".schema visits"

# Search for keyword in all tables
$ sqlite3 History "SELECT * FROM urls WHERE url LIKE '%malware%';"

# Check file integrity
$ sqlite3 History "PRAGMA integrity_check;"

# Extract from unallocated space (deleted records)
$ strings History | grep -i "http://"
✅ Deleted Record Recovery
  1. Identify free pages (via PRAGMA page_count)
  2. Carve SQLite records (look for row patterns)
  3. Validate data (check row format, types)
  4. Reconstruct tables from loose pages
  5. Timeline deleted entries (timestamps still intact)
⚠️ Important: Timestamps Conversion
Different apps use different epoch!
  • Chrome: WebKit (microseconds since 1601)
  • Firefox: Unix epoch × 1,000,000
  • iOS: NSDate (seconds since 2001-01-01)
  • Android: Varies by app (Unix usually)
