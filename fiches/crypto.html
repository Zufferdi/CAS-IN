Création du Couple de Clefs
Toute la sécurité RSA repose sur l'impossibilité de factoriser n en ses facteurs premiers p et q.
((·)) PUBLIÉE
{e, n}
L'exposant public e et le module n = p × q sont distribués librement.

n est le produit de deux grands premiers — sa taille détermine la sécurité (2048, 4096 bits).

Rôle : chiffrer les messages et vérifier les signatures.
🔒 SECRÈTE
d
L'exposant privé d est calculé via l'indicatrice d'Euler :
φ(n) = (p−1)(q−1)

d est l'inverse modulaire de e : d × e ≡ 1 mod φ(n)

Rôle : déchiffrer et signer.
PUBLIC
n
Module
Produit de p × q. Partagé publiquement. Sa taille (bits) = force de la clef.
PUBLIC

Souvent 65537. Utilisé pour chiffrer : C = Mᵉ mod n.

Exposant privé (Inverse)
Secret absolu. Inverse modulaire de e. Déchiffre : M = Cᵈ mod n.

Indicatrice d'Euler
(p−1)(q−1). Permet de calculer d. Ne jamais divulguer.
p, q
Nombres premiers
Très grands et secrets. Retrouver p et q depuis n = casser RSA.
PKI
Infrastructure à clefs
RSA est le fondement des certificats TLS, HTTPS, signatures numériques.

⚠️ POINT CLÉ FORENSIQUE

  • Un fichier chiffré RSA-2048 est mathématiquement inviolable par force brute
  • Chercher d'abord la clef, pas casser le chiffrement
  • La RAM peut contenir des clefs RSA en clair si le système était actif
  • Les certificats PKI permettent d'identifier l'émetteur même sans contenu

📋 À SAVOIR POUR L'EXAMEN

  • RSA repose sur la difficulté de factoriser n = p × q
  • Clef publique = {e, n} — Clef privée = {d, n}
  • C = Mᵉ mod n — M = Cᵈ mod n
  • φ(n) = (p−1)(q−1) sert à calculer d
  • TLS 1.3 utilise ECDHE + RSA ou ECDSA

Analyse d'entropie
X-Ways / Entropy Test
Un fichier chiffré ou compressé a une entropie de Shannon proche de 1.0 (données quasi-aléatoires). Comparer avec des fichiers normaux (entropie 0.3–0.7).

🔑 SOURCES DE CLEFS

  • BitLocker : compte Microsoft, Active Directory, clef USB, fichier .BEK
  • VeraCrypt : dump RAM (FVEK via Volatility), keyfile externe
  • FileVault : compte iCloud, clef institutionnelle MDM
  • EFS : certificat utilisateur dans le profil Windows

📋 MAGIC BYTES ABSENTS

  • Aucune signature de format reconnue = indice fort de chiffrement
  • VeraCrypt : volontairement sans en-tête identifiable
  • BitLocker : header "-FVE-FS-" identifiable dans certains modes
  • Croiser entropie + absence magic bytes + taille ronde

⚡ STRATÉGIE D'ATTAQUE

  • D'abord : dictionnaire (rockyou.txt, SecLists)
  • Ensuite : dictionnaire + règles (best64.rule)
  • Puis : masque ciblé si pattern connu
  • En dernier : masque brute force complet

  • -m 0 : MD5 / -m 1000 : NTLM
  • -m 1800 : SHA-512 (Linux /etc/shadow)
