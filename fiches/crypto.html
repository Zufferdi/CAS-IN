Citation — Kerckhoffs (1883)
"Il faut qu'il n'exige pas le secret, et qu'il puisse sans inconvénient tomber entre les mains de l'ennemi."
— Auguste Kerckhoffs, La cryptographie militaire, Journal des sciences militaires, vol. IX, janvier 1883. Le 2e des 6 principes — la base de toute cryptographie moderne.
🔑 Paradoxe AES-256 : Casser AES-256 par brute force nécessiterait plus d'énergie que ce que le soleil produira dans toute sa vie. Pourtant, en 2023, Cl0p a exfiltré des données de 2000 organisations en exploitant non pas AES, mais une faille SQL dans MOVEit — le serveur de transfert de fichiers. L'algorithme résiste. L'écosystème cède.

Chiffrement symétrique
AES — Standard de référence
  • Blocs de 128 bits. Clés : 128 / 192 / 256 bits
  • Nombre de tours : 10 / 12 / 14 selon la taille de clé
  • Étapes/tour : SubBytes (S-box) → ShiftRows → MixColumns → AddRoundKey
  • AES-256 ne sera pas cassé par force brute (2²⁵⁶ opérations)
  • Ce qui cède : écosystème (mdp faible, clé en RAM, backup non protégé)
Modes opératoires
ECB❌ Motifs visibles. Proscrire absolument.
CBCIV aléatoire. ⚠ Padding oracle si mal implémenté.
CTRFlux. ⚠ Réutilisation nonce = C1⊕C2 = P1⊕P2.
GCM✅ CTR + authentification. Standard actuel.
XTS✅ Pour disques (BitLocker, FileVault).
XOR & piège two-time pad

XOR réversible : si C = M ⊕ K, alors M = C ⊕ K.
Réutilisation de clé/nonce :
C1 ⊕ C2 = (M1 ⊕ K) ⊕ (M2 ⊕ K) = M1 ⊕ M2
La clé est éliminée → relation entre plaintexts visible.

Chiffrement de disques
  • BitLocker : clé en RAM si volume monté. Clé dans l'AD (entreprise). VMK récupérable.
  • LUKS : header en-tête du volume → contient clés chiffrées. Forensiquement exploitable.
  • VeraCrypt : plausible deniability — volume caché indiscernable de l'espace libre.
  • FileVault : recovery key dans iCloud.
Chiffrement asymétrique et RSA
RSA — Formules clés

n = p × q (deux grands premiers) · φ(n) = (p−1)(q−1)
Clé publique : (e, n) avec pgcd(e, φ(n)) = 1
Clé privée : d tel que e × d ≡ 1 (mod φ(n))

Chiffrement : C = Me mod n
Déchiffrement : M = Cd mod n
Signature : S = Md mod n · Vérification : M = Se mod n

Python : pow(c, d, n) — exponentiation modulaire native

Sécurité et attaques RSA
  • RSA-512 : cassé (1999). RSA-1024 : déconseillé. RSA-2048 : minimum actuel.
  • Håstad (Broadcast) : même message pour 3 dest avec e=3 → CRT → M³ extrait
  • Side-channel : timing, power analysis — exploitent l'implémentation
  • Diffie-Hellman : échange clé sur canal non sécurisé → base de PFS (TLS)
PKCS#12 (.p12/.pfx)
  • Conteneur chiffré = certificat X.509 + clé privée
  • Criticité maximale : obtenir le fichier + le mot de passe = usurpation totale d'identité
  • L'attaquant peut déchiffrer les TLS sessions passées enregistrées
  • Cassage : hashcat mode 12600 (PKCS#12)
PKI et certificats
  • Hiérarchie : Root CA → Intermediate CA → Leaf certificate
  • Révocation : CRL (périodique) ou OCSP (temps réel)
  • Certificate Transparency (CT) : tous les certs publics loggés → crt.sh pour OSINT
  • Certificate Pinning : bloque les proxy MITM (Burp, mitmproxy)
  • TLS 1.3 : RSA key exchange supprimé, PFS obligatoire (ECDHE/DHE)
Hachage et intégrité
Fonctions de hachage
MD5128 bits (32 hex). Rapide. Collisions connues. Acceptable en forensique (chain of custody), pas pour signatures.
SHA-1160 bits. Cassé en 2017 (SHAttered). Ne plus utiliser pour signatures numériques.
SHA-256256 bits. Standard forensique actuel pour chain of custody.
bcrypt/Argon2Intentionnellement lent (facteur de coût). Pour les mots de passe uniquement.
Fuzzy hashing (ssdeep)
  • Compare la similarité entre fichiers (≠ hashing cryptographique)
  • Score 85% = 85% de contenu commun
  • Détecte les variantes de malwares légèrement recompilés
  • NSRL (NIST) : base de hash de logiciels connus → éliminer les fichiers système
Cassage de mots de passe
Hashcat — Modes
  • -a 0 : Dictionnaire (rockyou.txt)
  • -a 1 : Combinaison (dict1 × dict2)
  • -a 3 : Masque (?l?u?d?s?a)
  • -a 6 : Hybride dict + masque
  • ?l=minuscule · ?u=majuscule · ?d=chiffre · ?s=symbole
Vitesses typiques (GPU)
  • MD5 : milliards/sec
  • SHA-256 : centaines M/sec
  • bcrypt cost 12 : ~milliers/sec
  • Argon2 : encore plus lent
Attaques forensiques courantes
  • Cold boot : clés AES récupérables en RAM (1–2 min après extinction)
  • Padding oracle (CBC) : déchiffrement sans clé
  • Two-time pad (CTR/nonce réutilisé) : M1⊕M2 visible
  • PKCS#12 : hashcat mode 12600
💡 Principe de Kerckhoffs (1883) : La sécurité doit reposer sur la clé, pas sur le secret de l'algorithme. AES est sûr précisément parce qu'il a été analysé publiquement pendant des années. Un algorithme "secret maison" n'a pas subi ce test.
