Principe de la supertimeline
Concept

Regrouper toutes les sources de temps (FS, logs, registre, navigateur, artefacts) dans un seul fichier CSV ou base de données, trié chronologiquement. Permet de reconstituer un incident minute par minute.

Sources intégrées
  • NTFS : $MFT, $LogFile, $UsnJrnl
  • Registre Windows (SAM, SYSTEM, NTUSER)
  • Event Logs (Security, System, Sysmon)
  • Prefetch, ShimCache, AmCache
  • Historique navigateur (Chrome, Firefox, Edge)
  • Logs applicatifs, LNK files, Jump Lists
log2timeline / Plaso
# 1. Générer le fichier Plaso (.plaso) depuis une image disque
log2timeline.py output.plaso /dev/sdb1

# 2. Filtrer et exporter en CSV (L2T format)
psort.py -o l2tcsv output.plaso -w timeline.csv

# 3. Filtrage par date
psort.py -o l2tcsv output.plaso "date > '2024-01-01 00:00:00' AND date < '2024-01-31 00:00:00'"

# 4. Importer dans Timesketch pour analyse collaborative
timesketch_importer.py -u admin --host http://localhost timeline.csv

Points critiques
⚠️ Timezone — Piège fréquent

Les sources utilisent des timezones différentes (NTFS = UTC · Event Logs = UTC · HFS+ = locale · FAT = locale). Normaliser en UTC avant de construire la timeline. Vérifier SYSTEM\TimeZoneInformation.

Timestomping

Un attaquant peut modifier les timestamps NTFS ($STANDARD_INFORMATION) avec des outils comme timestomp. Comparer $SI et $FILE_NAME — divergence = manipulation.

⚖️ Examen CAS-IN : log2timeline → .plaso → psort → CSV · Sources : $MFT + Event Logs + Registre + Prefetch · Timezone : toujours normaliser en UTC · Timestomping : $SI ≠ $FN · Timesketch : outil collaboratif d'analyse de timeline · Corrélation temporelle = cœur de l'analyse forensique.
