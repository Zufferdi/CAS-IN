⏱ La Supertimeline — Reconstituer minute par minute
Une supertimeline regroupe toutes les sources horodatées d'un système ($MFT, Event Logs, Registre, Prefetch, navigateurs, logs applicatifs…) en un seul fichier trié chronologiquement. C'est l'épine dorsale de toute analyse d'incident : elle révèle l'enchaînement précis des événements (entrée → exécution → persistence → exfiltration). Outils standards : log2timeline.py pour l'extraction, psort.py pour le filtrage/tri, Timesketch pour l'analyse collaborative en équipe.
🔧 Pipeline supertimeline — De l'image disque à l'analyse
3 OUTILS · 4 ÉTAPES · NORMALISATION UTC OBLIGATOIRE
Image disque (input) log2timeline (extraction) .plaso (intermédiaire) psort + CSV Timesketch (analyse) Normalisation timezone
🔧 Pipeline log2timeline / Plaso — Commandes
# 1. Générer le fichier Plaso (.plaso) depuis une image disque
log2timeline.py output.plaso /dev/sdb1

# 2. Filtrer et exporter en CSV (format L2T)
psort.py -o l2tcsv output.plaso -w timeline.csv

# 3. Filtrage par fenêtre temporelle (UTC)
psort.py -o l2tcsv output.plaso "date > '2024-03-15 08:00:00' AND date < '2024-03-15 09:00:00'"

# 4. Importer dans Timesketch
timesketch_importer.py -u admin --host http://localhost timeline.csv

⚠️ Points critiques à surveiller
⏰ Timezone — Piège #1

Les sources utilisent des timezones différentes :

  • NTFS · Event Logs · Sysmon → UTC
  • HFS+ · APFS → locale (TZ système)
  • FAT12/16/32 → locale
  • SQLite (Chrome, Firefox) → mélange

Toujours normaliser en UTC avant la corrélation. Vérifier SYSTEM\CurrentControlSet\Control\TimeZoneInformation.

🕰 Timestomping — Piège #2

Un attaquant peut modifier les timestamps NTFS du $STANDARD_INFORMATION avec des outils comme timestomp ou SetMACE. Mais le $FILE_NAME reste intact car il n'est mis à jour que par le système (création/renommage).

Détection : comparer $SI et $FN via MFTECmd ou analyzeMFT. Divergence = manipulation.

📊 Pivots de corrélation
  • Process tree via Sysmon Event 1 — relier parent/enfant
  • $UsnJrnl + $LogFile = couche basse NTFS, à 0,1 sec près
  • Prefetch = timestamp de première et dernière exécution
  • ShimCache / AmCache = applications listées même supprimées
🔬 Bonnes pratiques Timesketch
  • Importer plusieurs sources dans une même sketch
  • Utiliser les tags (suspicious, persistence, c2)
  • Stories pour raconter l'enchaînement aux magistrats
  • Règles Sigma intégrées pour détection automatique
🧠 Testez-vous
Vous comparez via MFTECmd les timestamps $SI et $FN d'un fichier malware.exe. $SI = 2010-01-01 mais $FN = 2024-03-15. Que conclure ?Timestomping · Niveau : moyen
Timestomping confirmé. Le $STANDARD_INFORMATION ($SI) a été antidaté à 2010 par un outil type timestomp. Le $FILE_NAME ($FN) — uniquement mis à jour lors de la création / renommage / déplacement par le système — montre la véritable création 2024-03-15. Action : (1) consigner les deux timestamps dans le rapport, (2) chercher l'outil de timestomping (souvent dans les recent files de l'attaquant), (3) corréler avec $UsnJrnl pour la création réelle, (4) ne jamais se fier au seul $SI dans une analyse.
log2timeline.py prend 12 heures sur une image de 500 GB. Comment optimiser ?Performance · Niveau : facile
Limiter les parsers. Par défaut, log2timeline lance tous les parsers. Stratégies : (1) --parsers "winreg,evtx,mft,prefetch" pour ne cibler que les sources Windows essentielles, (2) --partitions 1,2 pour exclure des partitions inutiles (recovery), (3) --vss-stores none pour ignorer les Volume Shadow Copies (gain énorme), (4) workflow en deux temps : timeline rapide MFT-only d'abord pour cibler la fenêtre temporelle, puis pleine analyse sur cette fenêtre uniquement avec psort.py "date > X AND date < Y".
Une image NTFS dump à 09:30 (heure suisse, été). Vous voyez une création à 07:30:42 dans Plaso. Quelle est l'heure réelle locale ?Timezone · Niveau : facile
09:30:42 heure locale (CEST). Plaso affiche tout en UTC par défaut. En été suisse (CEST = UTC+2), l'heure locale = UTC + 2h. En hiver (CET = UTC+1), ce serait 08:30:42. Pour éviter les confusions, toujours mentionner l'offset dans le rapport : 2024-03-15 07:30:42 UTC = 09:30:42 CEST (Europe/Zurich). Vérifier la timezone du système source via SYSTEM\CurrentControlSet\Control\TimeZoneInformation dans le registre.
🎓 Exam Tip — Timeline Forensique

Pipeline : log2timeline.py → .plaso → psort.py → CSV / Timesketch

Sources : $MFT · $UsnJrnl · $LogFile · Event Logs (Security/System/PowerShell/Sysmon) · Registre · Prefetch · ShimCache · AmCache · LNK · Jump Lists · navigateurs

Format L2T_CSV : date,time,timezone,MACB,source,sourcetype,type,user,host,short,desc,version,filename,inode,notes,format,extra

Timezone : NTFS = UTC · HFS+/FAT = locale · TOUJOURS normaliser en UTC

Timestomping : $SI ≠ $FN = manipulation · MFTECmd / analyzeMFT pour détecter

Timesketch : analyse collaborative · stories · tags · règles Sigma

Optim : --parsers ciblés · --vss-stores none · timeline rapide MFT-only en premier
