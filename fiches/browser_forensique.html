🌐 Le navigateur — Le journal intime numérique
Un navigateur web stocke tout par défaut : chaque URL visitée, chaque cookie de session, chaque téléchargement, chaque mot de passe enregistré, chaque recherche tapée, chaque onglet ouvert. Pour un enquêteur forensique, c'est la mine d'or — une vue chronologique de l'activité du suspect en ligne. Tous les navigateurs modernes (Chrome, Firefox, Edge, Safari) stockent ces données dans des bases SQLite facilement requêtables avec un client SQL standard. Attention : la « Navigation privée » n'efface pas tout — DNS cache, slack space, swap file conservent souvent des traces. Toujours analyser la machine complète, pas seulement les bases du navigateur.

Profil Chrome — Localisation & Structure
Chemin du profil Windows

C:\Users\[user]\AppData\Local\Google\Chrome\User Data\Default\


Chaque profil Chrome = un sous-dossier de User Data\. Le profil par défaut = Default\. Les profils supplémentaires = Profile 1\, Profile 2\…

Requêtes SQL directes — History
# Ouvrir le fichier History avec sqlite3 (copier d'abord — Chrome le verrouille si ouvert)
cp History /tmp/History_copy
sqlite3 /tmp/History_copy

-- Historique trié par date (epoch Chrome = microsecondes depuis 1601-01-01)
SELECT datetime((last_visit_time/1000000)-11644473600, 'unixepoch') AS date,
url, title, visit_count FROM urls ORDER BY last_visit_time DESC LIMIT 100;

-- Téléchargements
SELECT datetime((start_time/1000000)-11644473600, 'unixepoch') AS date,
target_path, tab_url, received_bytes FROM downloads;

-- Recherches (mots tapés dans la barre)
SELECT term, normalized_term FROM keyword_search_terms ORDER BY id DESC;

-- Cookies (valeur peut être chiffrée)
SELECT host_key, name, value, path, expires_utc FROM cookies WHERE host_key LIKE '%suspect%';
⚠️ Epoch Chrome : Chrome stocke les timestamps en microsecondes depuis le 1er janvier 1601 (Windows FILETIME). Convertir : (valeur / 1000000) - 11644473600 → Unix timestamp.
Mots de passe Chrome — Déchiffrement
⚠️ Chiffrement AES-256-GCM

Depuis Chrome 80, les mots de passe dans Login Data sont chiffrés avec une clé maître stockée dans Local State (JSON), elle-même chiffrée par l'API DPAPI Windows (liée au compte utilisateur).


Pour déchiffrer : il faut être connecté avec le même compte Windows, ou disposer de la clé DPAPI (dans le registre + hash NTLM du compte).

Outils de récupération
  • Hindsight (open source) — analyse complète du profil Chrome
  • Autopsy Browser History module — intégré
  • NirSoft ChromePass — si accès au compte Windows
  • DB Browser for SQLite — inspection manuelle
  • AXIOM / Magnet — extraction + déchiffrement automatique

Chemin du profil

Le nom du dossier contient un hash aléatoire + suffixe. Sur Linux : ~/.mozilla/firefox/[hash].default/. Sur macOS : ~/Library/Application Support/Firefox/Profiles/

Requêtes SQL Firefox
-- Historique Firefox (microsecondes depuis 1970-01-01, puis ÷ 1 000 000)
SELECT datetime(v.visit_date/1000000, 'unixepoch') AS date,
p.url, p.title, p.visit_count
FROM moz_historyvisits v JOIN moz_places p ON v.place_id = p.id
ORDER BY v.visit_date DESC LIMIT 100;

-- Téléchargements (dans moz_annos depuis Firefox 26)
SELECT datetime(a.dateAdded/1000000,'unixepoch') AS date,
p.url, a.content FROM moz_annos a JOIN moz_places p ON a.place_id=p.id
WHERE a.anno_attribute_id = (SELECT id FROM moz_anno_attributes WHERE name='downloads/destinationFileURI');

-- Cookies
SELECT host, name, value, datetime(expiry,'unixepoch') AS expires FROM moz_cookies
WHERE host LIKE '%suspect.ch%';
💡 sessionstore.jsonlz4 : Ce fichier contient les onglets ouverts au moment du crash ou de la fermeture du navigateur. Format propriétaire LZ4 de Mozilla — décompresser avec python-lz4 ou des outils comme sessionstore-parser. Mine d'informations sur les dernières activités.

Navigation privée — Persistance
❌ Ce que la navigation privée SUPPRIME
  • Historique de navigation dans le profil
  • Cookies et sessions après fermeture
  • Données de formulaires
  • Téléchargements dans l'historique du navigateur (pas le fichier lui-même)
✅ Ce qui persiste malgré tout
  • Fichiers téléchargés sur le disque
  • DNS cache Windows (ipconfig /displaydns)
  • Prefetch Windows (si navigateur lancé)
  • Mémoire RAM (pendant la session)
  • Logs du proxy/firewall d'entreprise
  • Logs du routeur domestique (FAI)
  • ShellBags (si dossier téléchargements exploré)
💡 Tip forensique : Même si le navigateur ne conserve pas l'historique, le fichier NTUSER.DAT Windows peut contenir des traces via UserAssist (navigateur lancé) et les LNK files pointant vers les fichiers téléchargés.

Browser History Examiner

GUI Windows supportant Chrome, Firefox, Edge, IE, Opera. Reconstitue la timeline complète. Intégration AXIOM disponible.


Format de sortie : HTML, CSV, PDF pour inclusion directe dans un rapport judiciaire.

Autopsy — Recent Activity

Module intégré qui analyse automatiquement tous les navigateurs présents sur l'image. Résultats dans Web History, Web Downloads, Web Cookies, Web Search.


Idéal pour une première vue d'ensemble sans requêtes SQL manuelles.

DB Browser for SQLite

Outil GUI pour inspecter manuellement les fichiers SQLite du navigateur. Permet les requêtes SQL ad hoc et l'export CSV.


⚠️ Toujours copier le fichier SQLite avant ouverture — Chrome/Firefox le verrouillent si le navigateur est actif.

Points anti-forensique navigateur
Techniques de suppression
  • CCleaner / BleachBit : efface les profils complets
  • Extension "History Eraser" : suppression sélective
  • Modification manuelle des SQLite (timestamps, entrées)
  • Navigation privée + VPN pour éviter les logs côté serveur
Détection de manipulation
  • Gaps dans les timestamps (séquences non continues)
  • Fichier SQLite avec last_modified récent mais peu d'entrées
  • Présence de CCleaner dans Prefetch/AmCache
  • Journal NTFS ($UsnJrnl) révèle les suppressions récentes de fichiers profil
🧠 Testez-vous
Vous trouvez la valeur 13234567890123456 dans la colonne last_visit_time du fichier History de Chrome. C'est quelle date ?Timestamps · Niveau : moyen
Chrome utilise le format WebKit timestamp : microsecondes depuis le 1er janvier 1601 UTC. Conversion : (13234567890123456 / 1000000) − 11644473600 = 1590094290 Unix timestamp = 21 mai 2020, 19:31:30 UTC. Outil pratique : DCode (Digital Detective) ou la commande Python datetime.utcfromtimestamp(13234567890123456 / 1e6 - 11644473600). ⚠️ Ne pas confondre avec le format Firefox (Unix microsecondes) ou Safari (Cocoa, secondes depuis 2001).
Le suspect a utilisé la « Navigation privée » Chrome. Toutes ses traces sont-elles effacées ?Navigation privée · Niveau : facile
Non, loin de là. La navigation privée n'efface que les bases SQLite du navigateur lui-même (History, Cookies). Restent : (1) DNS cache de l'OS (ipconfig /displaydns sur Windows · sudo killall -HUP mDNSResponder sur macOS), (2) Prefetch Windows qui enregistre que chrome.exe a été lancé avec horodatage, (3) swap file / pagefile.sys peut contenir des fragments d'URL en clair, (4) fichiers téléchargés ne sont jamais effacés (juste l'entrée History), (5) RAM contient toute l'activité avant fermeture (raison pour laquelle le RAM dump est priorité 1 RFC 3227), (6) logs FAI / proxy côté réseau. La navigation privée protège contre un autre utilisateur du PC, pas contre une analyse forensique.
Vous voulez extraire les mots de passe enregistrés dans Chrome. Quel défi technique ?Login Data · Niveau : difficile
Chrome chiffre les mots de passe dans Login Data (SQLite) avec DPAPI Windows. La clé de déchiffrement est dérivée du mot de passe Windows de l'utilisateur et est stockée dans Local State JSON (encrypté à son tour). Pour déchiffrer hors-ligne : il faut soit (1) connaître le mot de passe Windows + la SID utilisateur, soit (2) avoir accès à SYSTEM, SECURITY et la NTUSER.DAT du suspect (DPAPI master keys), soit (3) analyser un dump RAM où la clé est en clair pendant que la session est active — d'où l'importance d'un RAM dump avant extinction. Outils : NirSoft ChromePass (sur la machine live), DPAPI tools (mimikatz, dpapick) pour offline. Note : depuis Chrome 80, le chiffrement utilise AES-256-GCM en plus de DPAPI.
🎓 Exam Tip — Browser Forensics

Tous les navigateurs stockent leurs artefacts dans des bases SQLite

Chrome / Edge : %LOCALAPPDATA%\Google\Chrome\User Data\Default\

Firefox : %APPDATA%\Mozilla\Firefox\Profiles\xxxx.default\

Safari : ~/Library/Safari/

Fichiers clés Chrome : History · Cookies · Login Data · Web Data · Bookmarks · Sessions/

Fichiers clés Firefox : places.sqlite · cookies.sqlite · key4.db · logins.json · sessionstore-*

Timestamps : Chrome = WebKit µs depuis 1601 · Firefox = Unix µs · Safari = Cocoa secondes depuis 2001

Conversion Chrome : (value / 1000000) − 11644473600 = Unix timestamp

Mots de passe Chrome : chiffrés DPAPI · clé dans Local State JSON · besoin RAM live ou DPAPI offline

Navigation privée : DNS cache + Prefetch + swap + downloads + RAM = traces persistantes

Outils : Hindsight (Chrome) · DB Browser for SQLite · NirSoft (ChromeHistoryView, MZHistoryView, ChromePass)

🎯 Essentiel terrain : Chrome History = SQLite · Epoch Chrome = microsecondes depuis 1601 (convertir : valeur/1000000 − 11644473600) · Firefox = places.sqlite (moz_historyvisits + moz_places) · Navigation privée : fichiers téléchargés persistent · DNS cache + Prefetch restent même en mode privé · Login Data = chiffré DPAPI (clé liée au compte Windows) · Hindsight = outil de référence Chrome.
