📡 Wireshark — Le microscope réseau de référence
Wireshark (anciennement Ethereal, par Gerald Combs · 1998) est l'analyseur de paquets de référence mondiale — utilisé par les ingénieurs réseau, pentesteurs, équipes SOC, et enquêteurs forensiques. Il décode plus de 3000 protocoles : Ethernet, IP, TCP, UDP, HTTP/HTTPS, DNS, DHCP, SMB, RDP, Kerberos, et bien d'autres. Le format PCAP (Packet Capture, format libpcap) est le standard universel pour stocker des captures réseau — un fichier PCAP contient chaque octet qui a transité sur l'interface, avec timestamps précis. Forensiquement, un PCAP est la preuve réseau ultime : indéniable, complet, rejouable. Wireshark est l'outil graphique ; tshark et tcpdump sont les versions CLI pour scripts et captures à distance. NetworkMiner (Netresec, Suède) extrait automatiquement fichiers, sessions, hosts depuis un PCAP — outil incontournable pour le triage rapide. Limite : avec le HTTPS généralisé (~95% du trafic web aujourd'hui), Wireshark voit les métadonnées (qui parle à qui, quand, combien) mais pas le contenu — sauf si on dispose des clés TLS (SSLKEYLOGFILE) ou d'un MITM autorisé.

Capture avec tcpdump
# Capture basique sur eth0
tcpdump -i eth0 -w /evidence/capture.pcap

# Capturer seulement le trafic vers/depuis une IP
tcpdump -i eth0 host 185.220.1.42 -w suspect.pcap

# Limiter la taille de capture (rotation toutes les 100 Mo)
tcpdump -i eth0 -C 100 -W 10 -w capture_%n.pcap

# Capturer seulement les en-têtes (pas le contenu) pour audit de masse
tcpdump -i eth0 -s 96 -w headers_only.pcap

# Hash de la capture pour chaîne de custody
sha256sum capture.pcap > capture.sha256
Statistiques Wireshark utiles
Statistics → Conversations

Liste toutes les paires IP qui ont communiqué avec volumes de données. Identifier rapidement les connexions volumineuses (exfiltration) ou anormales.


Trier par "Bytes" décroissant → les plus grosses transferts en haut.

Statistics → Protocol Hierarchy

Vue globale des protocoles présents dans la capture et leur proportion. Un PCAP avec 95% de TLS vers une seule IP extérieure = suspect.

Statistics → IO Graph

Graphe du volume de trafic dans le temps. Les pics réguliers et espacés trahissent un beaconing C2.

Statistics → DNS

Toutes les requêtes/réponses DNS. Identifier les domaines résolus (et ceux qui ne le sont pas — DGA). Longueur anormale = DNS tunneling.

File → Export Objects → HTTP (ou SMB, FTP, DICOM…). Wireshark reconstruit les fichiers transférés depuis les flux TCP.


Puis hasher chaque fichier extrait pour l'intégrer dans la chaîne de custody.

Outil GUI spécialisé dans l'extraction passive depuis PCAP. Reconstruit automatiquement les fichiers, les images, les emails, les credentials HTTP.

Détecter le beaconing C2
🎯 Le beaconing est la communication régulière d'un malware avec son serveur de commande et contrôle (C2). La régularité est la signature la plus facilement détectable.
Caractéristiques du beaconing
  • Intervalles réguliers : toutes les 60s, 300s, 3600s
  • Petites tailles de paquets (heartbeat) alternant avec des bursts
  • Destination : IP ou domaine fixe non lié à l'activité légitime
  • Persistance : fonctionne même la nuit (pas de comportement humain)
  • HTTPS : chiffré → contenu non visible mais pattern temporel visible
Méthode de détection
  1. Statistics → IO Graph : chercher des pics réguliers
  2. Statistics → Conversations : trier par durée longue
  3. Filtre : ip.dst == [ip suspecte] → examiner les intervalles
  4. Extraire timestamps : frame.time_delta entre paquets successifs
  5. Calculer l'écart-type des intervalles → faible = beaconing
# Extraire les timestamps des connexions vers une IP suspecte
tshark -r capture.pcap -Y "ip.dst==185.220.1.42 && tcp.flags.syn==1" -T fields -e frame.time

# Calculer les intervalles avec awk
tshark -r capture.pcap -Y "ip.dst==185.220.1.42" -T fields -e frame.time_epoch |
awk 'NR>1{print $1-prev} {prev=$1}' | sort -n | uniq -c

# Détecter le DNS tunneling (requêtes très longues)
tshark -r capture.pcap -Y "dns.qry.name" -T fields -e dns.qry.name | awk 'length($0)>60'
Jitter — Beaconing avec variation
Qu'est-ce que le jitter ?

Les malwares sophistiqués ajoutent une variation aléatoire (±20%) à leur intervalle de beacon pour éviter la détection par des règles d'intervalle fixe.


Cobalt Strike, par exemple, a un paramètre sleep et jitter configurables.

Détection malgré le jitter
  • Analyser la distribution statistique des intervalles
  • Chercher un intervalle médian constant malgré la variation
  • Volume de données : constant malgré les variations de temps
  • Outils : RITA (Real Intelligence Threat Analytics) — détection beaconing automatique
  • Zeek/Bro : analyseur de logs réseau avec détection comportementale

PCAP en investigation judiciaire
Chaîne de custody PCAP
  • Hash SHA-256 immédiatement après capture
  • Documenter : interface, timestamp début/fin, outil + version
  • PCAP = preuve directe du trafic réseau → haute valeur probatoire
  • En entreprise : autorisation préalable obligatoire (surveillance réseau)
⚖️ Légalité de la capture
  • Réseau d'entreprise : autorisation de l'employeur + mention dans le règlement IT
  • Réseau privé tiers : interdit sans mandat judiciaire (art. 269 CPP)
  • LPD : la capture PCAP contient des données personnelles → mesures de protection
  • ATF 136 II 508 : IP = abonné, pas auteur → PCAP doit être corrélé avec d'autres preuves
🧠 Testez-vous
Vous capturez du trafic HTTPS dans Wireshark. Pouvez-vous lire le contenu des pages web ?HTTPS · Niveau : facile
Non par défaut, sauf cas spéciaux. HTTPS = TLS sur HTTP : tout le contenu (URLs précises après le hostname, headers, body, cookies) est chiffré bout-à-bout. Wireshark voit uniquement : (1) IP source/destination, (2) port destination (443), (3) le SNI (Server Name Indication) dans le ClientHello TLS — révèle le hostname (www.example.ch) mais pas le path, (4) volumes de données, (5) timing. Pour déchiffrer, trois options : (a) SSLKEYLOGFILE = variable d'env qui force Chrome/Firefox à logger les clés de session — Wireshark peut alors les utiliser pour déchiffrer (Edit → Preferences → Protocols → TLS → (Pre)-Master-Secret log filename), (b) RSA private key du serveur — fonctionne uniquement pour les vieilles suites RSA (PFS = Perfect Forward Secrecy le rend obsolète), (c) MITM avec proxy (Burp, mitmproxy) avec certificat installé — légal seulement si autorisé. Encrypted SNI (ECH) et DNS over HTTPS (DoH) rendent l'analyse encore plus difficile dans le futur.
Vous voyez 1 paquet toutes les 60 secondes vers 185.234.X.X, sur le port 443, taille très constante (~120 octets). Conclusion ?Beaconing · Niveau : moyen
Beaconing C2 fortement suspect. Signaux : (1) périodicité fixe = 60 sec ± epsilon (un humain ne génère jamais ce pattern), (2) même IP de destination à chaque fois (vrai service web aurait du load balancing), (3) taille constante = check-in vers C2 (« je suis vivant, des ordres ? »), (4) port 443 = se cache dans le trafic légitime, (5) IP 185.234.X.X dans plage VPS (Bulgarie/Roumanie typique). Procédure : (a) lookup IP sur VirusTotal + AbuseIPDB + ThreatFox, (b) extraire le SNI du TLS ClientHello (tls.handshake.extensions_server_name), (c) chercher l'IP dans Censys / Shodan, (d) corréler avec les EDR sur le poste source pour identifier le process. Variantes : jitter = beaconing avec ±20% de variation aléatoire pour échapper à la détection (Cobalt Strike par défaut). Outils auto : RITA (Real Intelligence Threat Analytics) calcule le score de beaconing automatiquement sur des PCAPs / Zeek logs.
Quelle est la différence entre filtre BPF (capture) et filtre Display dans Wireshark ?Filtres · Niveau : moyen
BPF (Berkeley Packet Filter) = filtre de capture, syntaxe libpcap. Appliqué au moment de la capture par le kernel — les paquets non-matching sont ignorés et perdus à jamais. Syntaxe : host 10.0.0.42 and port 443. Utilisation : tcpdump, dumpcap, capture Wireshark sur interface live. Filtre Display = filtre d'affichage, syntaxe Wireshark. Appliqué après la capture sur les paquets déjà chargés en mémoire — change uniquement la vue, ne supprime rien. Syntaxe différente : ip.addr == 10.0.0.42 and tcp.port == 443. Best practice forensique : (1) capturer SANS filtre BPF ou avec un filtre très large (not multicast and not broadcast) pour ne perdre aucune preuve, (2) utiliser des filtres Display pour explorer le PCAP, (3) si le volume est trop gros, découper avec editcap ou tcpdump -r in.pcap -w out.pcap [BPF]. Pièges : la syntaxe BPF utilise port, la syntaxe Display utilise tcp.port. and en BPF, and aussi en Display mais préfixe différent.
Vous saisissez un PCAP comme preuve. Que faire pour préserver son intégrité judiciaire ?Chaîne de custody · Niveau : facile
SHA-256 immédiat et chaîne de custody documentée. Procédure : (1) Hash SHA-256 du fichier PCAP dès l'arrivée au labo : sha256sum capture.pcap > capture.pcap.sha256, (2) Documentation : qui a capturé, où, quand, sur quelle interface, avec quel outil et version, durée de capture, filtre BPF utilisé, (3) Travail sur copie : cp capture.pcap analysis-copy.pcap, jamais sur l'original, (4) Stockage : original sur support write-blocked + copie de travail séparée, (5) Chaîne d'analyse : chaque outil exécuté, chaque export documenté avec horodatage. Pièges : (a) Wireshark peut modifier un PCAP si on clique sur File → Save As avec des modifications (jamais le faire sur l'original), (b) format .pcapng moderne contient des options qui peuvent diverger entre versions de Wireshark — préférer .pcap classique pour stockage long terme (editcap -F libpcap). Article CPP applicable : 192 (administration des preuves) + 379 (recevabilité) + ATF sur l'identité PCAP/preuve.
🎓 Exam Tip — Wireshark & PCAP

Wireshark = analyseur graphique · tshark = CLI · tcpdump = capture Unix légère

Format PCAP = libpcap · .pcap classique · .pcapng moderne (options + nanoseconds)

Filtres BPF (capture) : appliqués au kernel · host X and port Y · paquets non-matching perdus

Filtres Display : appliqués après capture · ip.addr == X and tcp.port == Y · vue uniquement

Filtres Display essentiels :

  • ip.addr == 10.0.0.42

  • tcp.port == 443 · udp.port == 53

  • http.request.method == "POST"

  • dns.qry.name contains "evil"

  • tls.handshake.extensions_server_name (SNI)

HTTPS : voir SNI + IPs + volume · contenu chiffré sauf SSLKEYLOGFILE / RSA key (legacy)

Stats Wireshark : Statistics → Conversations · Endpoints · I/O Graphs · Protocol Hierarchy

Extraction : File → Export Objects → HTTP / SMB / IMF / DICOM

Beaconing C2 : intervalles réguliers (60s · 5min) · taille constante · port 443 (cache)

Jitter : beaconing avec variation ±20% (Cobalt Strike par défaut)

DGA : Domain Generation Algorithm · NXDOMAIN en masse · domaines aléatoires

DNS Tunneling : sous-domaines > 60 car. · entropie élevée · volumes anormaux

Outils complémentaires : NetworkMiner · Brim/Zui · RITA · Zeek

Chaîne de custody : SHA-256 immédiat · doc complète · jamais modifier original

Cadre légal CH : LSCPT pour interception · ATF 136 II 508 (IP ≠ auteur)
