Capture avec tcpdump
# Capture basique sur eth0
tcpdump -i eth0 -w /evidence/capture.pcap

# Capturer seulement le trafic vers/depuis une IP
tcpdump -i eth0 host 185.220.1.42 -w suspect.pcap

# Limiter la taille de capture (rotation toutes les 100 Mo)
tcpdump -i eth0 -C 100 -W 10 -w capture_%n.pcap

# Capturer seulement les en-têtes (pas le contenu) pour audit de masse
tcpdump -i eth0 -s 96 -w headers_only.pcap

# Hash de la capture pour chaîne de custody
sha256sum capture.pcap > capture.sha256
Statistiques Wireshark utiles
Statistics → Conversations

Liste toutes les paires IP qui ont communiqué avec volumes de données. Identifier rapidement les connexions volumineuses (exfiltration) ou anormales.


Trier par "Bytes" décroissant → les plus grosses transferts en haut.

Statistics → Protocol Hierarchy

Vue globale des protocoles présents dans la capture et leur proportion. Un PCAP avec 95% de TLS vers une seule IP extérieure = suspect.

Statistics → IO Graph

Graphe du volume de trafic dans le temps. Les pics réguliers et espacés trahissent un beaconing C2.

Statistics → DNS

Toutes les requêtes/réponses DNS. Identifier les domaines résolus (et ceux qui ne le sont pas — DGA). Longueur anormale = DNS tunneling.

Extraction de fichiers depuis un PCAP
Wireshark — Export Objects

File → Export Objects → HTTP (ou SMB, FTP, DICOM…). Wireshark reconstruit les fichiers transférés depuis les flux TCP.


Puis hasher chaque fichier extrait pour l'intégrer dans la chaîne de custody.

NetworkMiner

Outil GUI spécialisé dans l'extraction passive depuis PCAP. Reconstruit automatiquement les fichiers, les images, les emails, les credentials HTTP.


Classé par hôte → visualiser immédiatement ce que chaque machine a téléchargé/uploadé.

# Extraire tous les fichiers HTTP d'un PCAP avec tshark
tshark -r capture.pcap --export-objects http,/tmp/http_exports/

# Extraire les credentials HTTP Basic Auth
tshark -r capture.pcap -Y "http.authorization" -T fields -e http.authorization

# Reconstruire un flux TCP (File → Follow → TCP Stream dans Wireshark)
tshark -r capture.pcap -q -z follow,tcp,ascii,0

Détecter le beaconing C2
🎯 Le beaconing est la communication régulière d'un malware avec son serveur de commande et contrôle (C2). La régularité est la signature la plus facilement détectable.
Caractéristiques du beaconing
  • Intervalles réguliers : toutes les 60s, 300s, 3600s
  • Petites tailles de paquets (heartbeat) alternant avec des bursts
  • Destination : IP ou domaine fixe non lié à l'activité légitime
  • Persistance : fonctionne même la nuit (pas de comportement humain)
  • HTTPS : chiffré → contenu non visible mais pattern temporel visible
Méthode de détection
  1. Statistics → IO Graph : chercher des pics réguliers
  2. Statistics → Conversations : trier par durée longue
  3. Filtre : ip.dst == [ip suspecte] → examiner les intervalles
  4. Extraire timestamps : frame.time_delta entre paquets successifs
  5. Calculer l'écart-type des intervalles → faible = beaconing
# Extraire les timestamps des connexions vers une IP suspecte
tshark -r capture.pcap -Y "ip.dst==185.220.1.42 && tcp.flags.syn==1" -T fields -e frame.time

# Calculer les intervalles avec awk
tshark -r capture.pcap -Y "ip.dst==185.220.1.42" -T fields -e frame.time_epoch |
awk 'NR>1{print $1-prev} {prev=$1}' | sort -n | uniq -c

# Détecter le DNS tunneling (requêtes très longues)
tshark -r capture.pcap -Y "dns.qry.name" -T fields -e dns.qry.name | awk 'length($0)>60'
Jitter — Beaconing avec variation
Qu'est-ce que le jitter ?

Les malwares sophistiqués ajoutent une variation aléatoire (±20%) à leur intervalle de beacon pour éviter la détection par des règles d'intervalle fixe.


Cobalt Strike, par exemple, a un paramètre sleep et jitter configurables.

Détection malgré le jitter
  • Analyser la distribution statistique des intervalles
  • Chercher un intervalle médian constant malgré la variation
  • Volume de données : constant malgré les variations de temps
  • Outils : RITA (Real Intelligence Threat Analytics) — détection beaconing automatique
  • Zeek/Bro : analyseur de logs réseau avec détection comportementale

PCAP en investigation judiciaire
Chaîne de custody PCAP
  • Hash SHA-256 immédiatement après capture
  • Documenter : interface, timestamp début/fin, outil + version
  • PCAP = preuve directe du trafic réseau → haute valeur probatoire
  • En entreprise : autorisation préalable obligatoire (surveillance réseau)
⚖️ Légalité de la capture
  • Réseau d'entreprise : autorisation de l'employeur + mention dans le règlement IT
  • Réseau privé tiers : interdit sans mandat judiciaire (art. 269 CPP)
  • LPD : la capture PCAP contient des données personnelles → mesures de protection
  • ATF 136 II 508 : IP = abonné, pas auteur → PCAP doit être corrélé avec d'autres preuves
