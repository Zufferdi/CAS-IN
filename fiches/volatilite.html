Pourquoi analyser la RAM ?
⚡ Contenu volatile

Processus actifs, connexions réseau, clés de chiffrement (FVEK BitLocker), mots de passe en clair, fichiers ouverts non sauvegardés — tout disparaît à l'extinction.

🎯 Priorité forensique

ISO/IEC 27037 : la RAM doit être capturée avant tout autre action sur un système actif. Sa volatilité en fait la preuve la plus fragile.

Commandes d'acquisition
# Windows — WinPMem
winpmem_mini_x64.exe image_ram.raw

# Linux — avml
sudo avml /tmp/ram.lime

# VM VMware — copier le .vmem pendant que la VM tourne
cp /var/vmware/machine.vmem /evidence/ram.vmem

# Hash immédiat après acquisition
sha256sum image_ram.raw > image_ram.sha256
⚖️ Art. 248 CPP : La saisie d'un ordinateur allumé nécessite une décision motivée — éteindre = perte définitive de la RAM. L'acquisition RAM est une mesure de contrainte à documenter scrupuleusement.
Plugins Volatility 3 — Windows
windows.pslist
Liste tous les processus actifs (PID, PPID, nom, heure démarrage)
→ Détecter processus suspects ou masqués
windows.pstree
Arbre des processus parents/enfants — visualiser les chaînes d'exécution
→ cmd.exe enfant de Word = macro malveillante
windows.psscan
Scan mémoire pour les structures EPROCESS — trouve les processus cachés (rootkits)
→ Divergence pslist vs psscan = rootkit
windows.netscan
Connexions réseau actives et fermées (IP, port, protocole, PID)
→ Connexions C2, beacon malware
windows.cmdline
Arguments de ligne de commande de chaque processus
→ PowerShell -enc = commande encodée suspecte
windows.dlllist
DLL chargées par chaque processus — détecter DLL injection
→ DLL injectée dans lsass.exe = credential dumping
windows.handles
Handles ouverts (fichiers, clés registre, mutexes) par processus
→ Fichiers ouverts non visibles sur disque
windows.malfind
Détecte les régions mémoire exécutables sans image disque associée
→ Code injecté, shellcode en mémoire
windows.filescan
Scan les objets FILE_OBJECT en mémoire — fichiers ouverts ou récemment fermés
→ Fichiers supprimés encore référencés
windows.registry.hivelist
Liste les ruches de registre chargées en mémoire
→ Ruches volatiles (HKCU non sauvées)
windows.hashdump
Extrait les hashes NTLM depuis la mémoire (SAM en mémoire)
→ Casser avec Hashcat -m 1000
windows.vadinfo
Virtual Address Descriptor — régions mémoire mappées par processus
→ Analyse des segments de mémoire
Commandes types
# Structure générale Volatility 3
python3 vol.py -f image_ram.raw windows.pslist

# Processus masqués (rootkit detection)
python3 vol.py -f ram.raw windows.psscan --
python3 vol.py -f ram.raw windows.pslist
# → Comparer les deux listes

# Connexions réseau
python3 vol.py -f ram.raw windows.netscan | grep ESTABLISHED

# Extraire un processus pour analyse
python3 vol.py -f ram.raw windows.dumpfiles --pid 1234
Détection de malware en mémoire
Indicateurs de compromission RAM
  • Processus avec nom légitime mais PPID anormal (svchost sans services.exe)
  • Processus dupliqués (2 × lsass.exe)
  • Chemin d'exécution hors %SystemRoot% (lsass.exe dans C:\Temp)
  • Connexions réseau vers IP suspectes depuis processus système
  • malfind → régions PAGE_EXECUTE_READWRITE sans fichier
  • DLL injectée dans processus légitime (hollowing)
Processus système légitimes
  • System — PID 4, toujours, PPID 0
  • smss.exe — 1 seul, enfant de System
  • csrss.exe — 1 par session, enfant smss
  • lsass.exe — 1 seul, enfant winlogon/wininit
  • services.exe — 1 seul, enfant wininit
  • svchost.exe — multiple, enfants services.exe uniquement
Process Hollowing & Injection
Process Hollowing

Le malware crée un processus légitime (svchost.exe) suspendu, remplace son code en mémoire par du code malveillant, puis reprend l'exécution. L'apparence est celle d'un processus légitime.


Détection : malfind + comparer le PE header en mémoire avec le fichier sur disque.

DLL Injection

Forcer un processus légitime à charger une DLL malveillante via CreateRemoteThread + LoadLibrary. La DLL tourne dans le contexte du processus cible (et ses privilèges).


Détection : dlllist → DLL avec chemin anormal ou sans signature.

Extraction de clés de chiffrement
BitLocker — FVEK

Si le volume BitLocker était monté lors de la capture RAM, la FVEK (Full Volume Encryption Key) est présente en mémoire.

Passware : Analyze Encrypted Disk → sélectionner le dump RAM → extraction automatique.

Volatility : plugin windows.bitlocker (Volatility 3 avec plugin tiers).

VeraCrypt / TrueCrypt

Les clés AES de VeraCrypt sont en mémoire tant que le volume est monté. Passware Kit Forensic les extrait automatiquement depuis le dump RAM.

Aucune attaque de MDP nécessaire — la clé symétrique déchiffre directement.

Hashes NTLM (hashdump)

Les hashes NTLM des comptes locaux sont en mémoire dans le processus lsass.exe.

windows.hashdump → hashes → Hashcat -m 1000

Mimikatz : sekurlsa::logonpasswords peut récupérer les MDP en clair si WDigest est actif.

Attention légale (Suisse)

L'extraction de clés de chiffrement depuis la RAM est une mesure de contrainte (art. 246–248 CPP). Elle doit être autorisée et documentée. Le résultat (clé ou hash) est une pièce à conviction soumise aux règles de la chaîne de possession.
