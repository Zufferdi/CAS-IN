Alternate Data Streams (ADS) NTFS

Le compartiment fantôme · fichier:stream:$DATA · T1564.004 · Saga Gamaredon 2026
Prérequis :📖 NTFS📖 Windows artefacts
Pratiquer :🎮 Saga 2 — Le compartiment fantôme
Voir aussi :🔗 Malware🔗 RAM🔗 MITRE ATT&CK
🔑 Principe — Le compartiment caché
Tout fichier NTFS a un stream principal sans nom (le « data fork » classique, ce que vous voyez quand vous ouvrez le fichier). Mais NTFS permet de greffer sur n'importe quel fichier des streams supplémentaires nommés, illimités, chacun avec son propre contenu. Ces streams sont invisibles dans Windows Explorer, ignorés par la plupart des antivirus, et copiables seulement vers NTFS (perdus si copie vers FAT32/exFAT). Un cadeau pour les APT.
📜 Origine — Compatibilité Mac HFS

Microsoft introduit les ADS dans NTFS au milieu des années 1990 pour assurer la compatibilité avec le système de fichiers Mac HFS, qui utilisait des « resource forks » (un fichier Mac contenait deux flux : data fork pour le contenu, resource fork pour les métadonnées d'icône, type, association, etc.). Les fonctionnalités Services for Macintosh sur Windows NT Server permettaient à un partage SMB de servir des fichiers à des Macs en préservant leurs resource forks via les ADS.

Services for Macintosh a été supprimé de Windows 2008. Mais les ADS sont restés dans NTFS — c'est une fonctionnalité native du système de fichiers, impossible à désactiver. Documentation Microsoft officielle limitée, parfois contradictoire entre versions Windows.

🔤 Syntaxe — fichier:stream:$DATA

Syntaxe officielle Microsoft : nomfichier:nomstream:$DATA. Le suffixe :$DATA est l'attribut type, généralement omis car implicite pour les streams de données.

Création triviale (CMD ou PowerShell) :
C:\> echo "secret" > visible.txt:hidden.txt

Le fichier visible.txt continue d'afficher son contenu d'origine, mais contient désormais un stream caché hidden.txt.

Lecture du stream :
C:\> more < visible.txt:hidden.txt
secret

PowerShell équivalent :
PS> Set-Content -Path visible.txt -Stream hidden.txt -Value "secret"
PS> Get-Content -Path visible.txt -Stream hidden.txt

Propriétés clés des ADS :

  • Pas d'impact sur la taille apparente du fichier hôte (mais consomme l'espace disque réel)
  • Pas de timestamps propres au stream — seul nom + taille visibles via API
  • Streams illimités par fichier — un seul fichier peut contenir des centaines de streams nommés
  • Les exécutables stockés en ADS peuvent être lancés directement : start visible.txt:hidden.exe (Windows historique ; bloqué partiellement depuis Windows 10 1709 mais contournements existent)
❌ Pourquoi les outils ratent les ADS
Le grand silence : la majorité des outils Windows standards ignorent les ADS par défaut. C'est précisément pourquoi ils restent un vecteur APT efficace en 2026.
Outil Comportement avec ADS
Windows Explorer❌ N'affiche jamais les streams, même en mode « afficher fichiers cachés »
FTK Imager⚠️ Image les ADS dans le bitstream mais ne les expose pas dans l'arbre — l'analyste doit les chercher activement
Antivirus standard⚠️ La plupart (Bitdefender, McAfee, Norton) scannent uniquement le stream principal sans nom
Microsoft Defender (2017+)✅ Scanne aussi les streams nommés depuis 2017, ratio detection variable selon configuration
EnCase⚠️ Expose les ADS dans la vue « entries » mais nécessite que l'analyste sache où regarder
X-Ways Forensics✅ EXCELLENT pour les ADS — colonne « Attr » affiche un suffixe « e? » pour signaler la présence d'un stream extra
🔧 Les bons outils de détection
1. dir /R (Windows builtin depuis Vista)
C:\> dir /R C:\target\
Liste les streams supplémentaires de tous les fichiers. Outil rapide de détection. Output :
4'096 config.dat
47'104 config.dat:hidden.hta:$DATA

2. streams.exe (Sysinternals, gratuit)
C:\> streams.exe -s C:\target\ — liste récursive
C:\> streams.exe -d fichier — supprime tous les streams
C:\> streams.exe -accepteula — contourne le prompt licence (utile en script)

3. PowerShell Get-Item -Stream
PS> Get-Item -Path "C:\target\config.dat" -Stream "*"
Liste les streams associés. Pour lire le contenu :
PS> Get-Content -Path "config.dat" -Stream "hidden.hta"

4. NirSoft AlternateStreamView (GUI gratuite)
Scan disque entier, export CSV, filtrage par taille/nom. Idéal pour audit de masse.

5. Linux (ntfs-3g) — getfattr
$ getfattr -d -m "^user." /mnt/disk/path/fichier
Extrait via attributs étendus xattr. Méthode forensique idéale en lecture seule (pas de modification du fichier hôte).
🎯 ADS et APT — T1564.004 MITRE

MITRE ATT&CK référence cette technique sous T1564.004 — Hide Artifacts: NTFS File Attributes. Groupes documentés utilisant les ADS :

  • Gamaredon (FSB Centre 18, Russie) — saga 2 CAS-IN 2026 (cas anonymisé Solidarité Dnipro). VBScript GammaSteel stocké en ADS sur %PROGRAMDATA%\Microsoft\Crypto\config.dat:hidden.hta. Persistance via Scheduled Task pointant directement vers le path avec « : ».
  • Astaroth — campagne 2019 Brésil, payload bancaire stocké en ADS.
  • LokiBot — variantes 2020-2022, info stealer.
  • Emotet — historique 2018 (avant takedown 2021).

Patterns courants à monitorer :

  • ADS sur fichiers de %APPDATA%, %PROGRAMDATA%, %TEMP%
  • Streams avec extensions exécutables (.hta, .ps1, .vbs, .js, .scr, .exe, .dll)
  • Streams > 10 Ko (rare pour stream légitime Zone.Identifier qui contient typiquement < 100 octets)
  • Scheduled Tasks pointant vers des paths contenant « : » (signal très fort)
🛡 Défense et détection
✅ Détection temps réel — Sysmon Event ID 15

Sysmon (Sysinternals) propose l'événement Event ID 15 — FileCreateStreamHash qui enregistre la création d'un ADS avec hash MD5/SHA1 du stream créé. C'est la détection comportementale en temps réel.

Config recommandée dans sysmon.xml :
<FileCreateStreamHash onmatch="exclude">
<TargetFilename condition="end with">:Zone.Identifier</TargetFilename>
</FileCreateStreamHash>
(exclut les streams Zone.Identifier légitimes, alerte sur tous les autres)

Autres défenses complémentaires :

  • EDR comportementaux (Defender for Endpoint, CrowdStrike, SentinelOne) — détectent l'écriture/exécution depuis ADS
  • Application Whitelisting (AppLocker, WDAC) — bloque l'exécution depuis ADS de manière proactive
  • Monitoring des Scheduled Tasks — alerte sur les tâches pointant vers des paths avec « : »
  • Audit régulier via streams.exe sur les zones sensibles (%APPDATA%, %PROGRAMDATA%)
⚠️ Limite involontaire : les ADS ne survivent pas à une copie vers FAT32/exFAT. Backup sur clé USB FAT32, transfert via certains protocoles cloud, ou restauration depuis backup non-NTFS = perte des ADS. Cela peut être un mécanisme de désinfection involontaire pour le défenseur, mais aussi une perte de preuves forensiques (à éviter pendant collecte).
🔬 Forensique post-mortem

Où chercher en investigation :

  • ADS sur fichiers fréquemment utilisés (config, log, dat) dans %PROGRAMDATA%
  • ADS dans %APPDATA%\Local\Temp (zone d'écriture massive, signal faible mais fréquent chez APT)
  • Streams Zone.Identifier — légitimes (créés par Windows pour fichiers téléchargés depuis Internet, contiennent juste « ZoneId=3 ») — à filtrer mais à conserver pour traçabilité origine
  • Streams suspects — extensions exécutables, taille > 10 Ko, noms ne correspondant pas à Zone.Identifier
Méthode forensique propre — extraction via Linux (ntfs-3g) :

# Monter image en lecture seule
$ sudo mount -t ntfs-3g -o ro,loop image.dd /mnt/forensic

# Localiser et confirmer le stream
$ getfattr -d -m "^user." /mnt/forensic/ProgramData/Microsoft/Crypto/config.dat
# Output: user.hidden.hta="..." (47'104 octets)

# Extraction propre sans modifier le fichier hôte
$ getfattr -n -n "user.hidden.hta" \
/mnt/forensic/ProgramData/Microsoft/Crypto/config.dat \
> /lab/extracted/hidden.hta

# Hash de vérification d'intégrité
$ sha256sum /lab/extracted/hidden.hta
$ sha256sum /mnt/forensic/ProgramData/Microsoft/Crypto/config.dat
# (le hash du fichier hôte ne doit PAS avoir changé)
