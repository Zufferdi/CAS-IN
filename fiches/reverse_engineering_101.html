🏗️ PE = Portable Executable Format (Windows)
Format standard Windows pour .EXE, .DLL, .SYS. Structure : Header + Sections (.text, .data, .rsrc). Contient code machine (x86/x64) + metadata.
Anatomie PE : Structure Disque
Offset | Taille | Section
0x0000 | 2 bytes | MZ signature (0x4D5A = "MZ")
0x0002 | 58 bytes | DOS header (legacy)
0x003C | 4 bytes | PE offset (pointeur vers PE header)
0x0040 | variable | DOS stub + padding

[PE HEADER]
0x00XX | 4 bytes | "PE\0\0" signature
0x00XX | 20 bytes | COFF Header (Machine, # sections, etc.)
0x00XX | variable | Optional Header (Entry point, ImageBase, etc.)

[SECTIONS]
| variable | .text (code machine)
| variable | .data (données globales)
| variable | .rsrc (ressources: icons, strings, dialogs)
| variable | .reloc (relocations)
| variable | .debug (symbols - optionnel)
Clés Forensiques PE
  • Entry Point (EP) : Où le code commence à s'exécuter
  • ImageBase : Adresse mémoire de chargement (malware change souvent)
  • Import Address Table (IAT) : Quelles DLL + fonctions importées
  • Export Table : Fonctions exposées par le DLL (DLLs seulement)
  • Debug Info : Strings, symbols (si débuguer =malware éducationnel souvent)
Indicateurs de Malveillance en PE
Indicateur Normal 🚨 Suspect
Entry Point Dans .text section En .data ou .rsrc (obfuscation)
Sections .text, .data, .rsrc standard Noms bizarres (.utext, .malw, etc.)
Imports Standard APIs (kernel32, user32) WinInet, WinHTTP (network) · LoadLibrary (injection)
Debug Info Absent (release build) Présent avec paths source (éducationnel?)
Timestamps Compilé récemment Compilé années 1990 (faux, obfuscation)
⚙️ x86/x64 Assembly : Langage Machine Lisible
Assembly = représentation textuelle du code machine. x86/x64 = instruction sets processeur Intel/AMD 32-bit / 64-bit.
Instructions x86/x64 Courantes
Instruction Exemple Signification
MOV mov eax, 0x41 Move : eax ← 0x41
PUSH / POP push ebx; pop eax Stack operations (function args)
CALL / RET call 0x401000; ret Function call + return
JMP / Jcc jmp 0x401050; jne skip Unconditional / conditional jumps
CMP / TEST cmp eax, ebx; test al, 0xFF Compare flags (puis Jcc)
XOR / AND / OR xor eax, eax Logic (XOR same=0 = clear register)
⚠️ Shellcode Pattern
push ebp ; sauvegarde base pointer (prologue fonction)
mov ebp, esp ; configure stack frame
sub esp, 0x40 ; allocate local variables
[fonction code]
mov esp, ebp ; restore stack
pop ebp ; restore bp
ret ; retour appelant (epilogue) Pattern standard = absent = shellcode obfuscated
🔓 Disassembly = Convertir Code Machine en Assembly
Processus : Bytes hex → mnémoniques assembly intelligibles. Outils : IDA Pro (commercial), Ghidra (gratuit NSA).
Workflow Disassembly Basique
1. Charge binaire
IDA/Ghidra → File open
Détecte format (PE, ELF, Mach-O)
Fixe ImageBase
2. Analyse statique
Scan bytes
Identifie instructions
Construit graph appels
3. Anotation
Nomme fonctions
Identifie strings
Crée commentaires
4. Décompilation
Ghidra décompile → pseudo-code C
Plus lisible que asm brut
Reste incomplet parfois
Techniques Anti-Disassembly (Malware)
Obfuscation Techniques
  • Code packing : UPX, WinRAR SFX → décompresse en mémoire
  • Junk code : Instructions dead qui ralentissent disassembly
  • Self-modifying : Code change lui-même en runtime
  • Polymorphism : Code change à chaque exécution
  • Control flow flattening : Boucles complexes → confondre analyseur

✅ Checklist Malware Reverse
  1. Dump PE header → ImageBase, Entry Point, sections
  2. Extract strings → grep URLs, IPs, command lines
  3. List imports → API calls = intent
  4. Identify packing → UPX/WinRAR/custom?
  5. Disassemble entry point → prologue + early code
  6. Search for syscalls → WinAPI hooking?
  7. Timeline → compile timestamp plausible?
  8. Sandbox vs Real → behavior analysis if possible
