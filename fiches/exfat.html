exFAT — Extensible File Allocation Table

Lancé en 2006 · SD > 64 Go · Volume 128 Po · Fichier 16 Eo · Timestamps 10 ms · Pas de journalisation
Prérequis :📖 Encodage📖 FAT16/32

"Tout est optimisé pour le flash" — exFAT remplace FAT32 sur les supports > 64 Go. Pas de Root Directory fixe, pas de limite de 4 Go par fichier, timestamps 10× plus précis qu'exFAT. Spécification ouverte depuis 2019 (Microsoft).

$Bitmap

Table d'allocation des clusters. 1 bit = 1 cluster. Bit 1 = utilisé, bit 0 = libre. Cluster 2 par défaut. Pas de Root Directory fixe.

$UpCase

Table 128 Ko de conversion minuscules → majuscules Unicode. Comparaison insensible à la casse des noms. Cluster 3 habituellement.

Root Directory

Répertoire racine dynamique. Commence au cluster spécifié dans RootDirectoryCluster (BPB offset 0x60). Pas de limite fixe d'entrées.

Structure des entrées — Directory Entry Set

Un fichier exFAT occupe 3 à 19 entrées de 32 octets chacune, toujours contiguës. Chaque entrée a un type (EntryType). Cliquez sur un segment.

Bit 7 de l'EntryType — Fichier supprimé
Mécanisme de suppression exFAT

Le bit 7 de l'EntryType (octet 0x00 de chaque entrée) = flag In-use. Mise à 0 pour marquer la suppression :

  • File Entry : 0x85 → 0x05
  • Stream Extension : 0xC0 → 0x40
  • File Name : 0xC1 → 0x41

Le contenu reste intact jusqu'à réallocation → récupération possible via FirstCluster encore présent dans le Stream Extension.

NoFatChain — Fichier contigu vs fragmenté
✅ NoFatChain = 1 (contigu)
  • Clusters contigus — FAT non utilisée pour ce fichier
  • Seuls FirstCluster + DataLength suffisent
  • Bit dans le Stream Extension (GeneralSecondaryFlags)
  • Forensique : carving plus facile, lecture directe depuis FirstCluster
🔗 NoFatChain = 0 (fragmenté)
  • Fichier fragmenté — consulter la FAT
  • Navigation : FirstCluster → entrée FAT → cluster suivant
  • Identique au chaînage FAT32
  • Forensique : suivre la chaîne jusqu'à 0xFFFFFFFF (EOF)
Comment identifier rapidement un fichier supprimé dans un répertoire exFAT ?exFAT suppression · Niveau : moyen
Lire le bit 7 de l'EntryType (octet 0x00) de chaque entrée. Si = 0 → supprimée :
File Entry 0x85→0x05 · Stream 0xC0→0x40 · FileName 0xC1→0x41.
Le FirstCluster dans le Stream (offset 0x14) est souvent encore valide → pointer directement sur les données.

Un disque a MBR type 0x07. Comment distinguer NTFS d'exFAT sans monter le volume ?Identification FS · Niveau : moyen
Lire les 8 octets à l'offset 0x03 du Boot Sector (VBR).
EXFAT (avec espaces) → exFAT.
NTFS (avec espaces) → NTFS.
NTFS a aussi la signature MFT (FILE) et l'offset $MFT dans le BPB.
Procédure X-Ways — Localiser un fichier exFAT
1
Clic droit sur le fichier → Navigate → Seek Directory Entry. Aller à l'entrée File Entry (0x85).
2
L'entrée suivante est le Stream Extension (0xC0). Se placer sur son premier octet "C".
3
Menu View → Template Manager → template "ExFAT Rcrd Type C0". Le détail affiche FirstCluster (offset 0x14) et DataLength (offset 0x18).
4
Calculer le nombre de clusters : DataLength ÷ TailleCluster (arrondi au supérieur). Ex : 53 910 / 4096 = 13.16 → 14 clusters.
5
Si NoFatChain = 1 : données contiguës depuis FirstCluster. Offset = ClusterHeapOffset × BPS + (N−2) × TailleCluster.
6
Si NoFatChain = 0 : Navigate → Seek FAT Entry → FirstCluster. Suivre le chaînage jusqu'à 0xFFFFFFFF (EOF).
7
Raccourci : clic droit → Navigate → List Clusters — voir immédiatement tous les clusters et la fragmentation.

📖 Exercice type — Bitmap exFAT : 28 clusters occupés ›

Si 28 clusters sont occupés à partir du cluster 2 (index 0) :

28 ÷ 8 = 3 octets complets (24 clusters) + 4 clusters restants
Bitmap : FF FF FF 0F 00 00 00 00...
0xFF = 0000 1111 → bits 0, 1, 2, 3 = clusters 26, 27, 28, 29 occupés

⚠ Les bits vont du poids faible au poids fort : bit 0 de l'octet 0 = cluster 2, bit 7 = cluster 9, bit 0 de l'octet 1 = cluster 10, etc.

ClusterHeapOffset = 384 secteurs, BPS = 512, TailleCluster = 4096. Quel est l'offset physique du cluster 8 ?exFAT offset · Niveau : difficile
Offset cluster 8 = ClusterHeapOffset × BPS + (FirstCluster − 2) × TailleCluster
= 384 × 512 + (8 − 2) × 4096
= 196 608 + 24 576 = 221 184 octets = 0x36000
Si NoFatChain = 1, les données commencent exactement à cet offset.
