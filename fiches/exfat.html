Bitmap d'allocation
Fonctionnement

La bitmap commence au cluster 2 (bit 0 de l'octet 0 = cluster 2). Chaque bit = 1 cluster. 1 octet = 8 clusters.

1 = occupé  ·  0 = libre

Lecture bit : poids faible à droite = cluster de plus petit numéro.

Formule pour cluster N

Offset octet = ⌊(N − 2) / 8⌋
Bit = (N − 2) mod 8 (depuis la droite)

Ex: cluster 21 → (21−2)/8 = 2 reste 3 → octet 2, bit 3

Valeur 7F = 0111 1111 → bit 7 = 0 (libre), bits 0–6 = 1 (occupés)

Exercice type : 28 clusters occupés

28 / 8 = 3 octets pleins + reste (4 clusters)
On part du cluster 2 (offset 0) → on décale de −1 :
FF FF FF 07 00 00 00 00

0x07 = 0000 0111 → clusters 26,27,28 occupés (bits 0,1,2)

Effacement d'un fichier

On met à 0 les bits des clusters concernés dans la bitmap.

La FAT n'est pas utilisée si NoFatChain = 1 (clusters contigus).

Bit 7 de l'EntryType → 0 : 0x85→0x05  ·  0xC0→0x40  ·  0xC1→0x41

FAT ou NoFatChain
NoFatChain = 1 (contigu)

Les clusters du fichier sont contigus. La FAT n'est pas utilisée pour ce fichier. Seul FirstCluster + DataLength suffisent pour trouver toutes les données.

Forensique : carving plus facile, récupération directe depuis FirstCluster.

NoFatChain = 0 (fragmenté)

Le fichier est fragmenté. La FAT contient le chaînage des clusters (comme FAT32). On la consulte depuis le FirstCluster.

Forensique : Navigation → Seek FAT entry → FirstCluster, puis chaînage normal.

Structure des entrées (RootDirectory)
Un fichier normal occupe 3 à 19 entrées de 32 octets chacune (vs 1024 octets/entrée en NTFS). Toutes les entrées d'un fichier sont contiguës.

Procédure X-Ways — Trouver un fichier
1
Clic droit sur le fichier → Navigate → Seek Directory Entry (Atteindre enreg. de fichier)
2
Localiser l'entrée 0x85 (File Entry) suivie de 0xC0 (Stream Extension). Se placer sur le "C" de C0.
3
Menu View → Template Manager → choisir le template "ExFAT Rcrd Type C0". Le détail affiche FirstCluster et DataLength.
4
Calculer le nombre de clusters : DataLength / TailleCluster (arrondi au supérieur). Ex: 53'910 / 4096 = 13.16 → 14 clusters.
5
Si fichier non contigu : Navigation → Seek FAT Entry → FirstCluster. Suivre le chaînage FAT normalement jusqu'à 0xFFFFFFFF.
6
Raccourci : clic droit sur le fichier → Navigate → List Clusters — voir immédiatement tous les clusters et la fragmentation.
Notions forensiques clés
Enregistrement

Le FS cherche d'abord le plus petit bloc pouvant contenir le fichier entier. Sinon, prend le plus grand trou → flag NoFatChain = 0 (fragmenté).

Copie réseau : taille inconnue au départ → copie dans un dossier temporaire puis déplacement. Cela peut créer de la fragmentation.

Timestamps

Résolution : 10 ms (vs 2 secondes en FAT32). Champ UtcOffset présent → timezone stockée explicitement.

Forensiquement supérieur à FAT32 pour la reconstruction de timeline.

Boot Signature

2 derniers octets du 1er secteur de la partition : toujours AA 55 (= 0xAA55 little-endian).

Flag VolumeDirty : indique si le volume est proprement démonté ou corrompu.

Récupération

Suppression : bit 7 des entrées mis à 0. Bitmap libérée. Contenu non effacé → récupération possible si clusters non réalloués.

SecondaryCount (offset 0x01 de l'entrée primaire) indique le nombre d'entrées secondaires qui suivent (0–255).

FICHIERS SYSTÈMES exFAT
$Bitmap
Table d'allocation des clusters. 1 bit = 1 cluster. Bit 1 = utilisé, bit 0 = libre. Stocké comme fichier ordinaire dans le répertoire racine. Cluster 2 par défaut.
$UpCase
Table de 128 Ko de conversion minuscules → majuscules Unicode. Utilisée pour la comparaison insensible à la casse des noms de fichiers. Cluster 3 habituellement.
Root Directory
Répertoire racine dynamique — commence à un cluster spécifié dans le boot sector (RootDirectoryCluster). Pas de limite fixe d'entrées contrairement à FAT16.
