🔷 Chrome = Google Ecosystem Forensics
Chrome stores comprehensive user data: history, cache, bookmarks, extensions, cookies, autofill, sync data. Multiple SQLite + JSON files.
Chrome Profile Location & Files
Windows:
C:\Users\[user]\AppData\Local\Google\Chrome\User Data\Default\

macOS:
~/Library/Application Support/Google/Chrome/Default/

Linux:
~/.config/google-chrome/Default/

Key Files Inside:
├─ History (SQLite) ← 🔴 Main artifact
├─ Bookmarks (JSON)
├─ Cookies (SQLite)
├─ Cache/ (binary files)
├─ Extensions/ (extension data)
├─ Local Storage/ (app-specific)
└─ Sync Data/ (if Google account)
Chrome History Forensics
Artifact Forensic Data How to Extract
urls table All visited URLs, titles, counts, timestamps sqlite3 History "SELECT * FROM urls;"
visits table Each visit individually (timeline) JOIN urls + visits on url_id
Bookmarks User's important URLs + folders Parse Bookmarks JSON file
Cache Downloaded pages, images, JS Carve from Cache/ directory
Extensions Malicious extensions (spyware) Check Extensions/ folder + manifest.json
Autofill Credit cards, addresses (encrypted) Web Data SQLite (encrypted by default)
🚨 Chrome Sync Data
If user logged in to Google account:
• History synced to Google servers
• Can recover from cloud account (with permission)
• Local sync cache = additional artifact
🦊 Firefox = Privacy-Focused Browser
Firefox stores data in profile folder. Key difference: Mozilla doesn't sync data by default. Local-only artifacts (unless Sync enabled).
Firefox Profile Location
Windows:
C:\Users\[user]\AppData\Roaming\Mozilla\Firefox\Profiles\[random].default-release\

macOS:
~/Library/Application Support/Firefox/Profiles/[random].default-release/

Linux:
~/.mozilla/firefox/[random].default-release/

Key Files:
├─ places.sqlite ← 🔴 History + Bookmarks
├─ cookies.sqlite
├─ prefs.js (user preferences)
├─ formhistory.sqlite (form data)
├─ cache2/ (disk cache)
└─ extensions.json (installed extensions)
Firefox vs Chrome: Key Differences
Aspect Chrome Firefox
Sync Default (Google account) Optional (Mozilla account)
Timestamp Format WebKit (1601) Unix microseconds
History DB History (3 tables) places.sqlite (10+ tables)
Encryption Autofill only (passwords vault) No encryption by default
Firefox prefs.js Analysis
User preferences stored in plaintext JavaScript:
user_pref("browser.startup.homepage", "about:blank");
user_pref("extensions.activeThemeID", "firefox-compact-dark");
user_pref("browser.search.defaultenginename", "Google");

→ Reveals user preferences, homepage, search engine
🧭 Safari = Apple Native Browser
Safari data in plist + SQLite. macOS and iOS versions have different storage. iCloud sync possible (if Apple account syncing enabled).
Safari Location & Files
Platform Location
macOS ~/Library/Safari/
iOS /var/mobile/Library/Safari/ (requires jailbreak)
Key macOS Safari Files:
History.db (SQLite) ← 🔴 Browsing history
Bookmarks.plist (binary plist) ← Bookmarks
TopSites.plist ← Frequently visited
History/ ← Older history files
Safari History.db Tables
  • history_items: URLs, titles, visit times
  • history_visits: Each visit individually (timeline)
  • safari_domain_expansion: Expanded URLs
📅 Multi-Browser Timeline = Complete User Activity
Combining history from Chrome, Firefox, Safari = comprehensive timeline of browsing behavior. Identify patterns, C2 communication, malicious sites.
Timeline Merging Strategy
Process:
  1. Extract history from each browser → sqlite3 queries
  2. Normalize timestamps → Unix epoch (important!)
  3. Deduplicate → Same URL visited in multiple browsers
  4. Sort chronologically → Single master timeline
  5. Correlate with other artifacts → Registry, logs, network
  6. Identify suspicious patterns → Malware downloads, C2
  7. Timeline visualization → Graph/chart for report
Timeline Builder Interactive
👆 Entrez visits pour fusionner timeline
⚠️ Timestamp Precision Issues
  • Chrome = 100-nanosecond (1601 epoch)
  • Firefox = microseconds (Unix epoch)
  • Safari = seconds (varies by version)
  • → Normalization critical for accurate timeline!
🔐 Extracting Credentials = High Value Evidence
Browsers store: passwords, credit cards, autofill data. Encryption varies (Chrome uses OS keychain, Firefox has master password). Extraction requires decryption or keychain access.
Credential Storage by Browser
Browser Storage File Encryption Extraction
Chrome Login Data (SQLite) OS keychain (DPAPI) Requires keychain key
Firefox logins.json + key4.db Master password (if set) Decrypt with master password
Safari Keychain (system-wide) OS Keychain encryption Live access only (locked)
⚠️ Forensic Limitations
  • Cannot extract Chrome passwords without keychain access
  • Firefox passwords encrypted (master password = blocker)
  • Safari locked to OS-level encryption
  • Solution: Live forensics (if possible) or known password
Autofill Data (Less Protected)
Autofill Extraction
Chrome Web Data (SQLite) stores:
  • Credit card numbers (partially encrypted)
  • Addresses (plaintext)
  • Names (plaintext)
  • Phone numbers (plaintext)
→ Often recoverable even if passwords not accessible

CLI Quick Commands
# Chrome: Extract all URLs with visit count
$ sqlite3 History "SELECT url, title, visit_count, last_visit_time FROM urls ORDER BY last_visit_time DESC;"

# Firefox: Timeline of all visits
$ sqlite3 places.sqlite "SELECT p.url, h.visit_date FROM moz_historyvisits h JOIN moz_places p ON h.place_id=p.id ORDER BY h.visit_date;"

# Safari: History (macOS)
$ sqlite3 History.db "SELECT url, visit_time FROM history_items ORDER BY visit_time DESC;"

# Extract bookmarks (Firefox)
$ sqlite3 places.sqlite "SELECT title, url FROM moz_bookmarks WHERE title IS NOT NULL;"

# Check Cache (Chrome)
$ ls -lah Cache/

# Timeline all browsers merged (bash)
$ (sqlite3 History "SELECT last_visit_time, url FROM urls"; sqlite3 places.sqlite "SELECT visit_date*1000000, url FROM moz_historyvisits JOIN moz_places ON place_id=id") | sort
✅ Workflow Complet Browser Forensique
  1. Locate browser profile folders (by OS)
  2. Extract History/places.sqlite/History.db
  3. Query each database (SQL commands above)
  4. Export to CSV for timeline
  5. Normalize timestamps (Unix epoch)
  6. Merge all browsers chronologically
  7. Correlate with network logs (DNS queries)
  8. Identify suspicious domains/downloads
  9. Check Cache/ for malware samples
  10. Report: timeline, suspicious sites, infected status
