📥 Memory Dump = Snapshot RAM (Volatile)
RAM contains ephemeral data: running processes, open connections, injected code, encryption keys. Dumps before shutdown = capture live artifacts (malware processes, network state).
Memory Dump Types & Methods
Method Tool Forensique
Live Dump FTK Imager, DumpIt, Volatility 🔴 Best (captures NOW state)
Hibernation File hiberfil.sys (Windows) Memory state at sleep time
Pagefile/Swap pagefile.sys, swapfile.sys Partial memory (disk), slower to recover
Crash Dump MINIDUMP, COMPLETE_DUMP Partial dump after BSOD
Live Dump Procedure
  1. Plug USB with forensic tools (read-only write blocker)
  2. Run FTK Imager or Volatility (minimal footprint)
  3. Dump entire RAM to USB/NAS (can take 30-60 min for 128GB)
  4. Verify hash (integrity)
  5. Never shutdown system until dump complete!
Memory Dump File Formats
Format Extension Tools
Raw Binary .raw, .mem, .bin Volatility, FTK
Windows Dump .dmp Volatility (needs profile)
🔧 Volatility = Memory Analysis Framework
Open-source framework for memory dump analysis. Supports Windows, Linux, macOS. Modular plugins for process listing, network connections, rootkit detection.
Volatility3 Architecture
Installation & Basic Usage:
# Install Volatility3
$ pip install volatility3

# Basic command
$ volatility3 -f memory.raw windows.pslist

# Syntax
volatility3 -f [DUMP] [OS].([PLUGIN])

Windows plugins: windows.pslist, windows.netscan, windows.malfind, windows.cmdline
Linux plugins: linux.pslist, linux.netstat
Critical Volatility Plugins
Plugin Fonction Forensique
pslist List running processes 🔴 Find malware processes
psscan Scan for hidden processes 🔴 Find rootkit processes
netscan Network connections (TCP/UDP) 🔴 C2 beaconing, backdoors
dlllist DLLs loaded in process Find injected DLLs
malfind Régions mémoire suspectes (RWX, code injecté) 🔴 Code injection, shellcode, packed malware
cmdline / handles Ligne de commande des processus / handles ouverts Arguments suspects, fichiers/clés ouverts par le malware
⚠️ Volatility 2 vs 3 : les plugins ssdt et apihooks existaient dans Volatility 2 mais ont été supprimés dans Volatility 3 (manque de mainteneurs et complexité de portage). Pour la détection de hooks SSDT, il faut soit utiliser Vol2 (déprécié), soit des outils kernel dédiés (PCHunter, GMER) sur système live.
🚨 Volatility Output Analysis
  • Suspicious process names (cmd.exe, powershell under svchost = unusual)
  • Unexpected parent-child relationships (explorer.exe → rundll32 = injected?)
  • Unknown DLLs (loaded from temp folder = malware)
  • Network connections to C2 IPs (known malicious, non-standard ports)
📋 Process Tree = Execution Hierarchy
Each process has parent (who launched it). Trees reveal anomalies: cmd.exe under svchost = injected, powershell under explorer = unusual.

💉 Code Injection = Malware Stealth Technique
Instead of running own process, malware injects code into legitimate process. Hides from task manager. Memory analysis reveals injection.
Common Injection Methods
Technique Mechanism Detection
DLL Injection LoadLibrary call → inject DLL Unexpected DLLs in dlllist
Process Hollowing Hollow process, replace code Mismatch disk exe vs memory
Shellcode Injection WriteProcessMemory → shellcode PAGE_EXECUTE_READWRITE regions
AppInit_DLLs Registry hook → load on startup Check registry + DLL verification
🔍 Detection Indicators
  • Executable memory without backing file (PAGE_EXECUTE_READWRITE with no .exe)
  • Inconsistent IAT (Import Address Table) (hooks/tampering)
  • Unusual section permissions (.text section writable = suspicious)
  • DLL from temp/AppData (not system32)
  • Memory pages with no matching file on disk

CLI Quick Commands
# List processes
$ volatility3 -f memory.raw windows.pslist

# Scan for hidden processes
$ volatility3 -f memory.raw windows.psscan

# Network connections
$ volatility3 -f memory.raw windows.netscan

# DLLs for specific process
$ volatility3 -f memory.raw windows.dlllist -pid 1024

# Code injection / shellcode
$ volatility3 -f memory.raw windows.malfind

# Dump process executable
$ volatility3 -f memory.raw windows.psxview

# Extract strings
$ strings memory.raw | grep "malware\|C2"
✅ Workflow Complet Memory Forensique
  1. Dump RAM (FTK Imager or Volatility live)
  2. List processes (pslist + psscan comparison)
  3. Analyze network connections (netscan → C2?)
  4. Inspect DLLs (find injected)
  5. Check for code injection (PAGE_EXECUTE regions)
  6. Scan SSDT/API hooks (rootkit detection)
  7. Extract suspicious executables (for analysis)
  8. Timeline: when processes started (process create time)
  9. Rapport: malware processes, C2 IPs, injection techniques
