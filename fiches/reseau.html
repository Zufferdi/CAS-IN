📡 Chapitre 25 · Manuel CAS-IN

Réseaux & Infrastructure

Modèle OSI, TCP/IP, adressage IPv4/IPv6, équipements réseau et techniques forensiques pour l'analyse du trafic et des incidents.

📡 Réseaux — Le squelette de toute investigation numérique
Comprendre les réseaux est fondamental en forensique : un attaquant qui se déplace dans une infrastructure laisse des traces à tous les niveaux — paquets sur le câble (PCAP), logs des équipements (firewall, switch, routeur), métadonnées sur les serveurs (DNS, SIEM), et artefacts sur les endpoints (Prefetch, Event Logs, registre). Pour reconstituer un incident, l'enquêteur doit naviguer entre ces couches. Le modèle OSI (7 couches) et son cousin pratique TCP/IP (4 couches) sont les cartes mentales qui permettent de structurer cette analyse : à quelle couche cette anomalie appartient-elle ? quel équipement la voit ? quel artefact la conserve ? Le réseau moderne combine plusieurs technologies : IPv4 (~4,3 milliards d'adresses, espace épuisé en 2011), IPv6 (déploiement progressif, 2¹²⁸ adresses), NAT (translation d'adresses, complique l'attribution car 1 IP publique = N hôtes derrière), VPN (anonymisation), VLAN (segmentation), SDN (réseau virtuel programmable). Côté infrastructure, le RAID (Redundant Array of Independent Disks) impacte directement la procédure d'acquisition forensique : il faut reconstituer la grappe avant l'analyse.

Adressage IP — IPv4 vs IPv6
L'épuisement des adresses IPv4 (2011) a accéléré le déploiement d'IPv6. En forensique, les deux coexistent et chacun a ses spécificités.
IPv4 — 32 bits
192.168.1.42
203.0.113.1
Format : 4 octets décimaux (0–255), séparés par des points.
Espace : 2³² = ~4,3 milliards d'adresses.
Notation CIDR : 192.168.0.0/24 = 256 adresses.

RFC 1918 Privées : 10.x, 172.16–31.x, 192.168.x
IPv6 — 128 bits
2001:0db8:85a3::8a2e:0370:7334
fe80::1 (link-local)
Format : 8 groupes de 4 chiffres hex, séparés par ':'.
Espace : 2¹²⁸ = 667 millions de milliards / mm² de surface terrestre.
Abréviation : groupes de zéros = :: (une fois max).

NAT — Network Address Translation

Le NAT traduit des adresses privées en adresses publiques. Problème forensique critique : une adresse IP publique peut masquer des centaines d'appareils derrière un même NAT.

⚠️ ATF 136 II 508 — Le Tribunal fédéral suisse a confirmé : une IP identifie l'abonné (le titulaire du contrat), pas nécessairement l'auteur de l'acte. Des éléments complémentaires (logs DHCP, MAC, session) sont requis pour l'attribution individuelle.

🔑 TCP vs UDP

  • TCP : connexion établie (3-way handshake SYN → SYN-ACK → ACK)
  • TCP : fiable, ordonné, contrôle de flux
  • UDP : sans connexion, rapide, non fiable
  • Forensique : un SYN sans SYN-ACK = port scan ou connexion refusée

📋 3-WAY HANDSHAKE TCP

  • Client → SYN → Serveur (initiation)
  • Serveur → SYN-ACK → Client (acceptation)
  • Client → ACK → Serveur (confirmation)
  • Forensique : SYN flood = DoS · SYN seul = scan (nmap -sS)

🔍 DNS ForensicsEXFILTRATION
Les requêtes DNS révèlent les domaines contactés même si le contenu est chiffré. Le DNS tunneling encode des données dans les sous-domaines : data.encoded.attacker.com
Requêtes DNS anormalement longues (> 60 car.), sous-domaines aléatoires à haute fréquence, TXT records inhabituels
📡 Beaconing C2MALWARE
Un malware "beacon" contacte son serveur C2 à intervalles réguliers (souvent avec du jitter). La régularité du trafic, même chiffré, est détectable statistiquement.
Connexions sortantes à intervalles réguliers (ex: toutes les 60s ±10s), volumes constants, même destination
🔄 ARP SpoofingMITM
L'attaquant empoisonne le cache ARP des victimes pour intercepter leur trafic. Il se place en "homme du milieu" et peut lire ou modifier le trafic non chiffré.
Plusieurs IP mappant la même adresse MAC, réponses ARP non sollicitées (gratuitous ARP), latence réseau accrue
🔍 Lateral MovementPOST-EXPLOIT
Après compromission initiale, l'attaquant se déplace latéralement via SMB, RDP, WMI, PsExec. Les logs réseau montrent des connexions inhabituelles entre postes internes.
SMB vers de nouvelles machines (Event 5140), RDP Type 10 entre postes (4624), comptes admin utilisés de façon atypique

🔍 SOURCES DE LOGS RÉSEAU

  • Firewall : toutes les connexions autorisées/refusées
  • Proxy : URLs visitées même en HTTPS (SNI/CONNECT)
  • DHCP server : IP ↔ MAC ↔ nom de machine
  • DNS serveur : tous les domaines résolus par machine
  • Windows : Event ID 5156 (connexion réseau autorisée)

🌐 TOOLS OSINT RÉSEAU

  • Shodan : moteur de recherche d'appareils connectés

  • Maltego : graphe de relations entre entités

⚠️ RAID ≠ Sauvegarde

Le RAID protège contre la défaillance hardware, pas contre la suppression accidentelle, le ransomware ou la corruption logique. Un ransomware chiffrant un volume RAID 5 chiffre les données sur tous les disques simultanément — aucune tolérance RAID ne peut aider.

🔧 FORENSIQUE RAID

  • Imager chaque disque individuellement avant toute reconstruction
  • Identifier : chunk size, ordre des disques, niveau RAID
  • Outils : ReclaiMe, RAID Reconstructor, mdadm (Linux)
  • RAID 5 dégradé = 1 disque manquant → recalcul par parité XOR
  • Ne jamais laisser le contrôleur RAID reconstruire sur l'original

📋 PARITÉ RAID 5

  • Parité = XOR de tous les blocs de données de la bande
  • Si D1 perdu : D1 = D2 XOR D3 XOR P (reconstruction)
  • Chunk size typique : 64 Ko, 128 Ko ou 256 Ko
  • Left-asymmetric = layout le plus courant
  • 2 disques perdus en RAID 5 → perte de données irrécupérable
🧠 Testez-vous
Une IP publique 185.234.X.X apparaît dans les logs comme source d'un acte délictueux. Pouvez-vous identifier l'auteur directement ?Attribution · Niveau : facile
Non. Selon l'ATF 136 II 508, l'adresse IP identifie l'abonné (titulaire du contrat), pas l'auteur de l'acte. Plusieurs raisons : (1) NAT — la majorité des connexions résidentielles partagent une IP publique entre tous les appareils du foyer (smartphone, ordinateur, tablette, IoT...), (2) WiFi ouvert ou compromis — un voisin ou passant peut utiliser le réseau, (3) VPN — IP de sortie ne reflète pas l'utilisateur réel, (4) Tor — IP du nœud de sortie totalement décorrélée, (5) VPS / proxy — IP appartenant à un hébergeur, l'utilisateur réel est ailleurs, (6) botnet — l'utilisateur est victime, pas auteur. Procédure CH : (a) requête LSCPT à l'opérateur pour identifier l'abonné (art. 14a LSCPT), (b) constat sur place / saisie pour identifier les appareils du foyer, (c) analyse forensique des appareils pour identifier l'utilisateur (compte session, biométrie, traces). Une IP seule = indice, jamais une preuve d'auteur.
Vous voyez dans un PCAP : 1 paquet SYN, 1 paquet SYN-ACK en retour, mais PAS de paquet ACK final. Que s'est-il passé ?TCP · Niveau : moyen
Connexion non établie — le 3-way handshake TCP n'a pas été complété. Plusieurs scénarios : (1) Scan SYN (half-open) — outil nmap -sS envoie SYN, reçoit SYN-ACK, ne renvoie pas ACK pour ne pas créer de connexion complète et éviter les logs applicatifs (mais le firewall et l'IDS le voient). Indicateur : nombreux SYN vers de nombreux ports depuis la même source. (2) SYN flood (DoS) — l'attaquant envoie des SYN en masse, ne complète jamais, sature les ressources serveur. (3) Filtrage / drop — un firewall sur le chemin du retour bloque l'ACK. (4) Crash client — le client a fermé brutalement avant d'envoyer ACK. Diagnostic : (a) compter les SYN sans ACK par source IP (filtre Wireshark : tcp.flags.syn==1 and tcp.flags.ack==0), (b) si volumétrie anormale + pattern de scan = SYN scan, (c) corréler avec logs IDS (Suricata, Snort détectent ce type de scan).
Quelle est la différence entre switch et routeur en termes forensiques ?Équipements · Niveau : facile
Switch (couche 2 OSI) : équipement de réseau local (LAN). Apprend les adresses MAC des appareils connectés à chaque port et stocke ce mapping dans sa CAM table (Content-Addressable Memory). Forensiquement : la CAM table indique quels appareils étaient présents sur quels ports physiques (utile pour identifier qui était branché où). Configurer un SPAN port (mirror port) sur un switch permet de capturer tout le trafic transitant par d'autres ports — base de la capture PCAP en entreprise. Logs limités. Routeur (couche 3 OSI) : équipement entre réseaux différents. Manipule les adresses IP, fait du routage et souvent du NAT. Forensiquement : (a) logs DHCP = qui a eu quelle IP, quand (essentiel pour attribution), (b) logs NAT = qui (IP privée + port) a généré quelle connexion sortante (IP publique + port), (c) tables de routage = topologie du réseau, (d) logs firewall intégré (sur les box modernes) = connexions autorisées/bloquées. Le routeur est la source forensique #1 dans une enquête réseau résidentielle ou PME.
Vous saisissez un NAS avec 4 disques en RAID 5. Comment procéder pour l'analyse forensique ?RAID · Niveau : difficile
RAID 5 = striping + parité distribuée sur tous les disques. Aucun disque seul ne contient de données utilisables — il faut reconstituer le RAID. Procédure : (1) Photographier l'ordre physique exact des disques avant retrait (le contrôleur a souvent un ordre logique différent — noter slot 1, 2, 3, 4). (2) Faire l'image bit-à-bit de chaque disque individuellement avec un write-blocker (dd ou ewfacquire), calculer SHA-256 de chacune. (3) Identifier les paramètres RAID : niveau (RAID 5), nombre de disques (4), stripe size (souvent 64KB ou 128KB), ordre des disques, parity rotation (left/right symmetric/asymmetric). Ces paramètres viennent : (a) du controller config (NAS web interface, RAID BIOS), (b) à défaut, par analyse heuristique (outils : R-Studio, ReclaiMe, RAID Reconstructor). (4) Reconstruire virtuellement avec un outil comme R-Studio, UFS Explorer, ou mdadm en mode read-only sur Linux : mdadm --assemble --readonly /dev/md0 /dev/loop0 /dev/loop1 /dev/loop2 /dev/loop3. (5) Une fois le RAID assemblé, monter le filesystem en read-only et procéder à l'analyse standard (Autopsy, X-Ways). Pièges : (a) NE JAMAIS reconstruire en write — peut détruire les données, (b) certains NAS (Synology, QNAP) utilisent des RAID propriétaires (SHR, etc.) — outils spécialisés requis, (c) si un disque est défaillant, RAID 5 supporte la perte d'1 disque sur 4 — reconstruction toujours possible.

Couches forensiques :

  • L7 : logs HTTP/DNS/email · proxy · EDR
