🔑 Principe — Le monde OT obéit à d'autres lois que l'IT
En IT classique, la priorité est la confidentialité, intégrité, disponibilité (CIA) — dans cet ordre. En OT (Operational Technology), la priorité est inversée : disponibilité, intégrité, confidentialité — et la sécurité humaine prime sur tout le reste. Couper un serveur web = quelques minutes d'indisponibilité. Couper un PLC qui contrôle une vanne = potentielle explosion, fuite chimique, victimes humaines. La forensique OT n'est pas la forensique IT avec un autre vocabulaire — c'est une discipline avec sa propre logique.
📐 1. Modèle Purdue — 6 niveaux d'abstraction

Le Purdue Enterprise Reference Architecture (PERA), publié en 1992 par l'Université Purdue (Indiana, USA), est devenu le standard mondial pour modéliser les architectures industrielles. Adopté par ISA-99 / IEC 62443, NIST SP 800-82, et toutes les normes de sécurité ICS.

⚠️ Le Level 3.5 — vulnérabilité critique #1 des PME industrielles CH
La DMZ industrielle est précisément ce qui SÉPARE le monde OT (Level 0-3, sécurité humaine) du monde IT (Level 4-5, productivité). Sans Level 3.5 : un attaquant qui pénètre par le mail corporate (Level 4) peut potentiellement atteindre une vanne carburant (Level 0). C'est exactement l'architecture défaillante observée à Tamoil Sierre (saga 4) — Veeder-Root TLS-350 directement exposé au routeur Sunrise sans DMZ.

Le constat amer : la majorité des protocoles industriels ont été conçus dans les années 1990-2000 pour des réseaux SÉRIE isolés (RS-232, RS-485). Quand ils ont été portés sur TCP/IP (sans modification de fond), ils ont hérité de l'absence native d'authentification et de chiffrement. L'exposition Internet de ces protocoles = open bar pour les attaquants.
🔬 3. Outils de forensique OT

Wireshark — avec dissectors industriels

Wireshark dispose nativement de dissectors pour la plupart des protocoles industriels. Filtres utiles :

modbus # Tout le trafic Modbus
modbus.func_code == 6 # Write Single Register (modification possible)
s7comm # Tout le trafic Siemens S7
s7comm.param.func == 0x05 # Write Var (modification possible)
bacapp # BACnet/IP
bacapp.confirmed_service == 15 # WriteProperty (modification)
tcp.port == 10001 # ATG Veeder-Root (pas de dissector officiel)
dnp3 # DNP3 (énergie)
iec104 # IEC 60870-5-104

Pour Veeder-Root ATG, pas de dissector officiel Wireshark — il existe des plugins communautaires (LUA scripts) pour décoder les commandes I-series (lecture) et S-series (écriture).

GRASSMARLIN — Mapping OT passif

GRASSMARLIN (développé par NSA puis open source) est un outil de découverte passive OT. Analyse les PCAP industriels pour :

  • Identifier les équipements (par fingerprint protocole)
  • Cartographier la topologie réseau OT
  • Détecter les protocoles utilisés et leurs versions
  • Produire des rapports compatibles Visio

Autres outils

  • Shodan / Censys / Onyphe : OSINT industriel (cf. attribution APT et saga 4 acte 4)
  • Nmap NSE scripts industriels : modbus-discover, s7-info, bacnet-info, enip-info
  • SCADAfence, Dragos, Claroty, Nozomi Networks : solutions commerciales SOC OT (détection comportementale, alertes)
  • Suricata + signatures ICS : IDS open source avec rules ICS
  • PLC Scout, PLC Hunter : outils de scan d'équipements industriels
⚡ 4. Acquisition forensique OT — spécificités
⚠️ DIFFÉRENCE CLÉ avec IT
En IT classique : on coupe le câble réseau → on image le disque → on analyse en lab. Le système est arrêté.
En OT : on NE PEUT PAS arrêter le processus physique. Un PLC qui contrôle un réacteur chimique ne se débranche pas comme un PC. L'acquisition forensique se fait en parallèle de l'opération continue.

Méthodologie d'acquisition OT

Phase 1 — Réunion préparatoire avec l'exploitant
→ Comprendre le processus (sécurité humaine en jeu ?)
→ Identifier ce qu'on peut sans risque vs ce qui demande coupure planifiée
→ Plan de continuité d'activité en cas de problème

Phase 2 — Capture passive (sans interférer)
→ Port mirror sur switch industriel (si disponible) — copie du trafic vers analyseur
→ TAP réseau passif (idéal) — boîtier hardware qui duplique le trafic sans le perturber
→ Capture PCAP via Wireshark / tcpdump / SPAN port
→ Logs équipements existants (PLC, HMI, historians)

Phase 3 — Extraction configuration
→ Exports config PLC via logiciel constructeur (TIA Portal Siemens, RSLogix Rockwell)
→ Snapshots historians (InfluxDB, OSIsoft PI System, AspenTech IP.21)
→ Backups SCADA (Wonderware, Iconics, Ignition)

Phase 4 — Analyse en lab
→ PCAP analysis avec dissectors
→ Reverse engineering protocole si nécessaire
→ Corrélation avec logs SIEM / Sysmon (côté IT)
→ Reconstitution chronologique

Phase 5 — Rapport et recommendations
→ Qualification juridique
→ Recommandations remédiation (DMZ Level 3.5, segmentation, monitoring)
→ Diffusion sectorielle si applicable
🛡️ 5. ISA-99 / IEC 62443 — Le standard de sécurité OT

L'ISA-99 / IEC 62443 est la norme internationale de référence pour la sécurité des systèmes d'automatisation et de contrôle industriels (IACS). Famille de documents :

  • IEC 62443-1 : Concepts et modèles généraux
  • IEC 62443-2 : Politiques et procédures de sécurité
  • IEC 62443-3 : Architecture de sécurité système
  • IEC 62443-4 : Sécurité des composants

Concepts clés introduits par 62443 :

  • Security Level (SL) : niveau de sécurité requis (SL1 à SL4 selon criticité)
  • Zones et conduits : segmentation logique du réseau industriel
  • Foundational Requirements (FR) : 7 exigences fondamentales (identification, contrôle d'accès, intégrité, confidentialité, restriction du flux de données, réponse aux événements, disponibilité des ressources)
🇨🇭 6. Le contexte suisse — LSI 2024 + OCyS 2025

Depuis le 1er janvier 2024, la LSI (Loi fédérale sur la sécurité de l'information) et son ordonnance OCyS structurent les obligations cybersécurité pour les infrastructures critiques en CH. Depuis le 1er avril 2025, obligation de signalement à l'OFCS sous 24h pour tout incident cyber sur infrastructure critique.

Sont concernés au sens LSI :

  • Énergie (production, transport, distribution électrique ; gaz ; carburant)
  • Santé (hôpitaux universitaires + cantonaux + grandes cliniques)
  • Eau potable et assainissement (municipal et cantonal)
  • Transports (CFF, aéroports, transports urbains majeurs)
  • Télécommunications (Swisscom, Salt, Sunrise et infrastructure)
  • Finance (banques systémiques, places de marché)
  • Administration publique

Les stations-service (cas saga 4) ne sont pas individuellement infrastructures critiques au sens LSI, mais les chaînes (Tamoil, AVIA, Migrol, BP, Shell, Coop Pronto) le sont. Donc obligation de signalement au niveau corporate, pas par site.
