Localisation des artefacts WSL
Système de fichiers Windows
  • Ubuntu : %LocalAppData%\Packages\CanonicalGroupLimited.Ubuntu...\LocalState\
  • Debian : %LocalAppData%\Packages\TheDebianProject...\LocalState\
  • WSL2 : fichier ext4.vhdx dans LocalState\
  • WSL1 : dossier rootfs\ avec arborescence Linux
Registre Windows
  • HKCU\Software\Microsoft\Windows\CurrentVersion\Lxss\
  • Une clé par distribution installée (GUID)
  • DefaultDistribution = distribution par défaut
  • BasePath = chemin vers les fichiers de la distro
Détection de l'usage WSL
Windows Event Logs
  • Event ID 4688 : processus wsl.exe lancé
  • Event ID 4688 : bash.exe, ubuntu.exe, debian.exe
  • Prefetch : WSL.EXE-*.pf, BASH.EXE-*.pf
  • Amcache : entrées pour wsl.exe et les distros
Contenu intéressant dans le VHD
  • /root/.bash_history — commandes exécutées
  • /home/user/.bash_history
  • /var/log/ — logs Linux
  • /tmp/, /root/ — fichiers temporaires
  • Outils réseau : nmap, curl, wget traces
Analyser le ext4.vhdx (WSL2)
1
Localiser le VHDX — chercher ext4.vhdx dans le profil utilisateur. Hash avant manipulation.
2
Convertir en RAW — qemu-img convert -f vhdx -O raw ext4.vhdx disk.raw
3
Analyser sur Linux — sudo mount -o ro,loop disk.raw /mnt/wsl puis accéder à /root/, /home/, /var/log/.
