Points forensiques clés par système
FAT12 / FAT16 / FAT32
  • 0xE5 en tête d'entrée SFN = fichier supprimé, données souvent récupérables
  • 0x00 = fin du répertoire (aucune entrée valide après)
  • Cluster de départ + taille encore présents après suppression
  • LFN : entrées 0x0F (R+H+S+V) précèdent le SFN, supprimer sans passer par l'OS efface seulement le SFN
  • Slack space : espace entre fin fichier et fin cluster = résidus d'anciens fichiers
  • FAT1 vs FAT2 : divergence = corruption ou manipulation
  • Root dir FAT16 plein (512 entrées) : erreur "Disk full" même avec espace libre
exFAT
  • $Bitmap : bit à 1 = cluster utilisé. Trouver le 1er 0 = 1er cluster libre
  • $UpCase : table de conversion majuscules/minuscules Unicode
  • Pas de Root Directory fixe = analyse plus complexe
  • Directory Entry Set : Stream Extension + File Name Extension
  • Cas d'usage : cartes SD > 64 Go (SDXC), appareils photo, drones
  • Pas de journalisation = récupération plus difficile après corruption
NTFS
  • MFT : chaque fichier = 1+ enregistrement de 1024 octets, signature "FILE"
  • Attribut résidant vs non-résidant : petits fichiers dans le MFT lui-même
  • $LogFile : journal circulaire des transactions récentes (LSN)
  • $UsnJrnl : journal des modifications ($J), persistant et précieux
  • ADS (Alternate Data Streams) : données cachées dans nom:stream
  • $I30 : index des répertoires, contient parfois des entrées fantômes
  • Timestomping : $STANDARD_INFO ≠ $FILE_NAME → manipulation
  • Runlist : data runs permettent la fragmentation, clé pour la récupération
EXT2/3/4
  • Inode : structure centrale (128 ou 256 octets) sans nom de fichier
  • Le nom est dans le répertoire (dir_entry_2) qui pointe vers l'inode
  • inode 2 = racine, inode 11 = lost+found
  • Suppression : inode libéré, blocs marqués libres, données persistantes
  • EXT3/4 journal : mode data=journal = métadonnées + données
  • Superbloc : magic = 0xEF53 (offset 56 dans le superbloc)
  • Block groups : superbloc copié dans certains groupes (flex_bg en EXT4)
  • Outils : TestDisk, Autopsy, The Sleuth Kit (istat, ifind, fls)
HFS+
  • Volume Header à l'offset 1024 (pas 0), copie à la fin du volume
  • Catalog B-tree : fichiers + répertoires indexés par CNID (Catalog Node ID)
  • Extents Overflow B-tree : fragments au-delà des 8 premiers extents
  • Forks : Data Fork (données) + Resource Fork (métadonnées Mac)
  • Big Endian ! Contrairement à tous les autres systèmes Windows/Linux
  • Epoch : 1er janvier 1904 ≠ Unix (1er janvier 1970)
  • HFS+ wrappers : ancien volume HFS encapsulant un HFS+ (PowerPC)
  • Journalisation : active par défaut depuis Mac OS X 10.2.2
🇨🇭 Contexte Suisse — CPP
  • Art. 248 CPP : scellés indépendants du système de fichiers
  • ISO/IEC 27037 : hash obligatoire quelle que soit la variante FS
  • NTFS = FS dominant sur les postes suspects Windows en Suisse
  • FAT32/exFAT = supports amovibles saisis (clés USB, cartes SD)
  • EXT = serveurs Linux, NAS, machines virtuelles
  • HFS+ = MacBook, iMac, anciens iPod — attention endianness Big Endian
  • TF 1B_602/2020 : intégrité des données indépendante du FS
Identifier un système de fichiers
Algorithme FAT12/16/32

1. Lire l'offset 0x36 (8 octets ASCII)
→ "FAT12 " → FAT12
→ "FAT16 " → FAT16
2. Si vide, lire 0x52
→ "FAT32 " → FAT32
3. Sinon : compter les clusters de données
→ < 4 087 → FAT12 · < 65 527 → FAT16 · reste → FAT32

Signatures & Magic Bytes

FAT/exFAT : EB ?? 90 + 55 AA offset 510
NTFS : EB 52 90 4E 54 46 53 ("NTFS")
EXT2/3/4 : 53 EF offset 56 dans superbloc
HFS+ : 48 2B ("H+") offset 1024
exFAT : OEM name 45 58 46 41 54 ("EXFAT")

EXT : magic 0xEF53 · inode 2 = racine · dir_entry_2 → inode
