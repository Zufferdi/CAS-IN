🔧 X.509 Certificate = Digital Identity
Certificates bind domain names to public keys. Issued by Certificate Authorities (CAs). Signed digitally. Publicly logged in Certificate Transparency (CT) logs since 2018 (required by Chrome/Firefox).
X.509 Certificate Structure (RFC 5280)
Field Content Forensique
Subject (CN) Common Name = domain 🔴 What domain is cert for?
Subject Alt Names (SAN) Alternative names (*.example.com) Wildcard = hides subdomains
Issuer Certificate Authority (CA) Which CA issued? (trust chain)
Valid From / To Validity period When cert issued/expires
Serial Number Unique ID from CA Uniquely identify cert
Signature Digital signature (CA's private key) Proves CA authorized
Certificate Extraction
# Extract from website
$ openssl s_client -connect example.com:443 -showcerts

# Extract from file
$ openssl x509 -in cert.pem -text -noout

# Check validity
$ openssl x509 -in cert.pem -noout -dates
📊 Certificate Transparency (RFC 6962)
All public CAs must log issued certificates to public CT logs. Chrome/Firefox require CT logs for trust. Enables tracking certificate issuance history.
CT Logs & Forensic Value
How CT Works:
  1. CA issues certificate for domain
  2. CA must submit to CT logs (publicly)
  3. CT log returns "SCT" (Signed Certificate Timestamp)
  4. Certificate becomes searchable in CT log
  5. Anyone can query CT log (crt.sh) to find certificates
Forensic Goldmine: crt.sh
Website: crt.sh → Search any domain
Returns: ALL certificates ever issued for that domain

Example query: crt.sh/?q=example.com
→ Shows every cert, issue date, expiry, issuer, SANs

✅ Perfect for:
  • Infrastructure timeline (when cert obtained)
  • Domain ownership changes (different CAs = different operators?)
  • Phishing domain tracking (typosquatting domains)
  • C2 infrastructure (multiple domains, same cert)

🌐 Domain History = Ownership & Operator Timeline
Combining CT logs + WHOIS = complete domain history. Reveals when domain registered, who owns it, when certificates obtained.
Domain Forensics Workflow
Step Tool Information
1. WHOIS lookup whois.com or CLI Registrant name, address, email
2. Registration date WHOIS field When domain first registered
3. CT logs (crt.sh) crt.sh or API When first cert issued (often right after registration)
4. Cert timeline crt.sh results How many certs, renewal frequency
5. IP history DNS history, passive DNS Where domain resolves (infrastructure)
🚨 Suspicious Patterns
  • Recently registered (< 1 week) = likely phishing
  • Registrant email = temp/throwaway = suspicious
  • Multiple domains, same registrant = infrastructure
  • Wildcard cert = tries to hide subdomains
  • Typosquatting variants (exxample.com for example.com)
🚨 Certificate Red Flags = Phishing & C2
Legitimate businesses use established CAs + long-term certs. Attackers often use free CAs + short-lived certs + bulk registrations.
Phishing Indicators
🚨 Free CA (Let's Encrypt)
Not inherently bad, but:
• Easy to obtain (automated)
• No vetting (instant issuance)
• Phishers use frequently
• Check age: < 1 week = suspicious
🚨 Typosquatting Domains
google.com vs
• gooogle.com (extra o)
• goo9le.com (9 instead of g)
• Check CT logs for variants
🚨 Wildcard Certificates
CN: *.example.com
• Hides subdomains
• Can serve malware on
• any.malicious.com
• Legitimate use exists, but suspicious with new domain
🚨 Bulk Registrations
Multiple domains registered:
• Same registrant
• Similar names (campaign)
• Quick succession
• Often phishing/spam network
C2 Certificate Patterns
C2 Infrastructure Tracking
Attackers often reuse certificates across multiple C2 domains:
  • Search CT logs for uncommon issuer + time period
  • Find all certs from that issuer in same window
  • Cluster by certificate serial (often copied)
  • Results = probable C2 network infrastructure

CLI Quick Commands
# Extract certificate from website
$ openssl s_client -connect example.com:443 -showcerts 2>/dev/null | openssl x509 -text

# Check certificate validity
$ openssl x509 -in cert.pem -noout -dates

# Get certificate info
$ openssl x509 -in cert.pem -noout -subject -issuer -serial

# WHOIS lookup
$ whois example.com

# CT log search (command line)
$ curl "https://crt.sh/?q=%.example.com&output=json"

# Find subdomains from CT logs
$ curl "https://crt.sh/?q=example.com&output=json" | jq '.[].name_value'
✅ Workflow Complet Certificate Forensique
  1. Extract certificate from target website (openssl)
  2. Parse certificate fields (subject, issuer, dates, SANs)
  3. Search CT logs (crt.sh) for domain + variants
  4. Timeline all certificates (when issued/expired)
  5. WHOIS lookup (domain registration, registrant)
  6. Check for typosquatting variants (CT search)
  7. Cluster infrastructure (same issuer/serial across domains)
  8. Check certificate reputation (SSL Labs, threat intel)
  9. Report: Timeline, ownership, suspicious patterns
