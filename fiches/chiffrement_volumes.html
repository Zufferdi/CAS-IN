🛡 Full Disk Encryption

Chiffrement de Volumes

BitLocker, FileVault, LUKS, VeraCrypt — fonctionnement, clés de récupération, attaques forensiques (cold boot, DMA, TPM sniffing) et méthodologie de saisie face au chiffrement.

⚡ RÈGLE D'OR TERRAIN
Ne jamais éteindre un ordinateur allumé sur scène de perquisition sans d'abord tenter une acquisition RAM. Une fois éteint, si le disque est chiffré (FDE) et que ni le mot de passe ni la clé de récupération ne sont obtenus, la preuve peut être perdue définitivement. AES-256 sans la clé = probabilité nulle de cassage par force brute.

🎯 Méthodologie forensique face au FDE
Arbre de décision selon l'état du device sur scène.
État device Objectif prioritaire Techniques
🟢 Allumé & session ouverte Acquérir la RAM avant toute chose WinPmem / Magnet RAM Capture / lime (Linux) / osxpmem (Mac). La clé FVEK/VMK est en mémoire tant que le volume est monté.
🟡 Allumé & verrouillé Garder en charge, Faraday, éviter extinction Attaques DMA via Thunderbolt (PCILeech), attaque cold boot possible mais destructrice. Nouvelle : cold-boot-ng fonctionne sur certains Lenovo.
🔴 Éteint Obtenir la clé de récupération par voie légale ou administrative BitLocker : requête Microsoft / Entra ID (si pro). LUKS : mot de passe de l'utilisateur. FileVault : iCloud escrow (peu documenté, entraide US).
🟠 Hiberné Préserver hiberfil.sys — contient la RAM + clé Extraction image bit-à-bit du disque, puis parse du hiberfil avec Volatility (windows.hibernation).
🪟 BitLocker — anatomie

🔗 Hiérarchie des clés

  • FVEK (Full Volume Encryption Key) — chiffre les données du disque (AES-XTS)
  • VMK (Volume Master Key) — chiffre la FVEK
  • Protectors chiffrent la VMK : TPM, PIN, USB key, Recovery Key (48 chiffres)
  • Lors du boot : protector → déchiffre VMK → déchiffre FVEK → mount
  • Outil : manage-bde -status C: puis -protectors -get C:

🔑 Récupération de la clé

  • Active Directory : attribut msFVE-RecoveryInformation (si BitLocker escrow activé)
  • Entra ID / Intune : blade BitLocker keys dans Azure
  • Compte Microsoft : account.microsoft.com/devices/recoverykey
  • USB recovery key : fichier .BEK (128 bits)
  • Printed key : 48 chiffres groupés par 6 → saisir en pré-boot
  • Suspension : manage-bde -protectors -disable C: — stocke la clé en clair sur le disque (backdoor temporaire, ne pas laisser)
TPM sniffing (attaque physique) : sur BitLocker avec TPM seul (sans PIN), la VMK transite en clair sur le bus LPC/SPI entre le TPM et le CPU au boot. Un analyseur logique à ~$10 permet de capturer la clé en quelques minutes. Attaque pratique, documentée (Dolos Group, 2021). Contremesure : activer un PIN.
🍎 FileVault — Apple Silicon

Sur les Mac Apple Silicon (M1/M2/M3), FileVault utilise la Secure Enclave :

  • Chaque Mac a une clé unique matérielle (UID) non-extractible
  • Le Secure Enclave Processor (SEP) dérive la clé de chiffrement à partir de l'UID + mot de passe utilisateur
  • Impossible de déplacer le disque sur un autre Mac (la clé UID est soudée dans l'AP)
  • Acquisition forensique : mac_apt (Yogesh Khatri) pour artefacts macOS — mais nécessite un Mac vivant
  • Mode DFU + Apple Configurator : utilisé par IC3D/Cellebrite pour passer en mode récupération (acquisition via GrayKey n'est pas disponible pour macOS)
  • Si mot de passe connu : boot sur Recovery (⌘+R) → Terminal → diskutil apfs unlockVolume
🐧 LUKS — Linux

🔓 Workflow d'analyse

  • Identifier : cryptsetup isLuks /dev/sdX
  • Dump du header : cryptsetup luksDump /dev/sdX → révèle algorithme, nombre de keyslots, UUID, itérations
  • Backup du header : cryptsetup luksHeaderBackup (à conserver pour bruteforce offline)
  • Unlock : cryptsetup open /dev/sdX chiffred_vol → /dev/mapper/chiffred_vol
  • Puis : mount /dev/mapper/chiffred_vol /mnt/...
  • Bruteforce : hashcat -m 14600 luks_header.img wordlist.txt (mode LUKS)
  • Coût LUKS2 + Argon2id : >100 ms par essai → force brute utile seulement si dico ciblé
❄️ Cold Boot Attack

Les clés de chiffrement d'un volume monté résident en RAM. Or la DRAM conserve son contenu quelques secondes à température ambiante — jusqu'à plusieurs minutes à basse température.

  • Procédure : pulvériser de l'azote liquide ou bombe air inversée sur les DRAM → −50°C
  • Arracher l'alimentation, éjecter les barrettes, les placer dans une autre machine bootée sur USB (memimage, bitunlocker)
  • Scanner la RAM pour les patterns de clés AES (entropie élevée + structure de schedule)
  • Outils : aeskeyfind, bitunlocker, rsakeyfind
  • Contre-mesures modernes : TRESOR (stocke la clé dans registres CPU AES-NI), ECC RAM avec scrubbing, CPUs Intel avec SME/MKTME
  • Succès : ~50 % sur hardware < 2015, ~10 % sur matériel récent

⚖️ Cadre suisse · Art. 90 al. 1 CPP

Le prévenu a le droit de se taire et ne peut être contraint à fournir un mot de passe de chiffrement. Le refus ne constitue pas une infraction en soi (contrairement au Royaume-Uni, RIPA 2000). Toutefois, le refus peut entraîner un indice de charge dans l'appréciation des preuves (art. 113 CPP).


Biométrie vs. mot de passe : la jurisprudence admet qu'un juge peut ordonner l'apposition d'une empreinte digitale ou du visage (Face ID) — acte non testimonial — mais pas la divulgation d'un mot de passe mental (nemo tenetur se ipsum accusare). Sur scène, éteindre le device après 5 min → Face ID se désactive et force le passcode.

Astuce acquisition : si l'ordinateur est allumé et déverrouillé, avant tout RAM dump, copiez le contenu des répertoires importants (Documents, Desktop, Downloads) vers un disque externe : c'est le seul moment où ces fichiers sont accessibles en clair. Le RAM dump peut échouer, mais cette copie préservera l'essentiel.
📋 Mémo — check FDE sur scène
  • Device allumé ? → NE PAS ÉTEINDRE. Ne pas brancher de souris (risque lock screen)
  • Session ouverte ? → acquisition RAM immédiate + copie fichiers en clair
  • Session verrouillée ? → Faraday + charge + test BitLocker unlock avec clés AD / Entra ID avant extinction
  • Éteint ? → imager le disque brut, documenter que le FDE est présent, tenter la récupération de la clé par voie légale
  • Mac ? → noter le modèle exact (T2 / M1 / M2) — change totalement la stratégie
  • VeraCrypt détecté ? → chercher les keyfiles (photos, MP3, n'importe quoi) dans l'environnement
  • Hibernate : fichier hiberfil.sys peut contenir les clés → toujours acquérir avant toute action
  • TPM+PIN sur un Lenovo/Dell ancien ? → envisager TPM sniffing en laboratoire
