🤝 Trois cibles très différentes
Slack, MS Teams et Discord sont souvent regroupés mais ils ont trois architectures distinctes. Slack = SaaS pur (workspace cloud + cache local Electron). Teams = SaaS profondément intégré à M365 (archives Exchange, OneDrive, Compliance Center). Discord = SaaS gaming-né, peu d'outils enterprise officiels mais beaucoup d'usage en SME tech. Connaître ces différences = savoir où chercher.
Slack — Architecture & sources de preuve
Slack desktop est une app Electron (Chromium + Node.js) avec cache LevelDB local. Les données canoniques sont chez Slack mais les artefacts locaux sont riches.
📁 Cache desktop Slack — Windows
  • %APPDATA%\Slack\ — racine
  • %APPDATA%\Slack\Cache\ — cache HTTP (images, files)
  • %APPDATA%\Slack\Local Storage\leveldb\ — état UI, drafts
  • %APPDATA%\Slack\storage\slack-downloads.json — fichiers téléchargés
  • %APPDATA%\Slack\logs\ — connexions, erreurs (textuels)
📁 Cache desktop Slack — macOS
  • ~/Library/Application Support/Slack/
  • ~/Library/Caches/com.tinyspeck.slackmacgap/
  • ~/Library/Logs/Slack/
  • App sandboxée → SIP peut bloquer accès direct
  • Préférer image disque + extraction offline
Slack Discovery API — Source canonique pour enquête
Pour les workspaces Enterprise Grid, Slack expose une API d'e-discovery qui donne accès à tous les messages, fichiers, channels (incluant DM et privés).
# 1. Obtenir un token Discovery (admin Enterprise Grid uniquement)
curl -X POST https://slack.com/api/discovery.enterprise.info -H "Authorization: Bearer xoxp-..."

# 2. Lister tous les utilisateurs (incluant désactivés)
curl "https://slack.com/api/discovery.users.list?token=xoxp-..."

# 3. Récupérer les messages d'un user (DM + channels publics + privés)
curl "https://slack.com/api/discovery.user.conversations?user=U12345&limit=200"

# 4. Export d'un canal complet avec historique
curl "https://slack.com/api/discovery.conversations.history?channel=C67890&oldest=1714521600"
⚖️ Discovery API requiert un plan Enterprise Grid + autorisation explicite de l'org. Pour Pro / Business+ : se rabattre sur Standard Export (admin → "Tools & settings" → "Workspace Export"), qui exclut les DM. Pour les DM sur ces plans, demande légale formelle à Slack via Trust & Safety.

⚠️ Limite : le cache local Slack n'est pas un historique complet. Slack desktop ne stocke localement que les conversations actives récentes pour l'expérience offline. Pour un historique complet, l'API Discovery ou Standard Export est obligatoire.
MS Teams — La source de vérité est dans M365 Compliance
Teams stocke peu localement. Les conversations 1:1 et de groupe sont en réalité des emails cachés dans la boîte aux lettres Exchange Online de chaque participant. Tout passe par M365.
🎯 Trois sources principales pour un enquêteur Teams
  • Compliance Center (Microsoft Purview) — recherche de contenu sur tous les channels
  • Exchange Online + Discovery Hold — chats 1:1 archivés comme emails dans dossier TeamsMessagesData
  • SharePoint / OneDrive — fichiers partagés en chat ou en channel
Microsoft Purview — Recherche de contenu Teams
# 1. Connect-IPPSSession (PowerShell, requis : compliance admin)
Connect-IPPSSession -UserPrincipalName admin@tenant.onmicrosoft.com

# 2. Créer une recherche sur l'utilisateur suspect
New-ComplianceSearch -Name "Case-2026-04-Suspect" -ExchangeLocation user@corp.ch -ContentMatchQuery 'kind:meetings OR kind:contacts OR kind:im'

# 3. Lancer + suivre le statut
Start-ComplianceSearch -Identity "Case-2026-04-Suspect"
Get-ComplianceSearch -Identity "Case-2026-04-Suspect"

# 4. Exporter les résultats (PST + métadonnées)
New-ComplianceSearchAction -SearchName "Case-2026-04-Suspect" -Export

# 5. Télécharger via eDiscovery Export Tool (Edge / IE seulement)
💡 Astuce Teams 1:1 : Les chats privés sont archivés dans le dossier TeamsMessagesData de la boîte de chaque user. Recherche : folderid:TeamsMessagesData dans Compliance.
Cache desktop Teams — En complément
📁 Teams Classic (Electron)
  • %APPDATA%\Microsoft\Teams\
  • ...\Cache\ — fichiers HTTP
  • ...\IndexedDB\https_teams.microsoft.com_0.indexeddb.leveldb\
  • ...\Logs\ — login, sync, erreurs
📁 Teams 2.0 (WebView2)
  • %LOCALAPPDATA%\Packages\MSTeams_8wekyb3d8bbwe\
  • ...\LocalCache\Microsoft\MSTeams\EBWebView\
  • Plus restreint que Teams Classic, app sandboxée
  • Outil : Magnet AXIOM, Cellebrite Inspector, KAPE module Teams
Discord — Pas d'API entreprise officielle, beaucoup d'artefacts locaux
Discord ne propose pas de Discovery API officielle. L'enquête repose sur les artefacts client locaux + requêtes formelles à Discord pour les DM serveur-side.
📁 Cache Discord Desktop — Windows
  • %APPDATA%\discord\ — racine
  • %APPDATA%\discord\Cache\ — fichiers HTTP, images, vidéos
  • %APPDATA%\discord\Local Storage\leveldb\ — état session, dernières conversations
  • %APPDATA%\discord\IndexedDB\https_discord.com_0.indexeddb.leveldb\ — messages cachés (limite ~50/canal)
🔍 Données extractibles localement
  • Token utilisateur (en clair dans LevelDB) → re-authentification en lecture
  • Liste des serveurs (Discord guilds) avec IDs
  • Avatars, fichiers récemment ouverts (cache)
  • Notifications désactivées / activées (preuve d'activité)
Workflow d'extraction Discord
# Étape 1 — Image disque, puis extraction offline (jamais sur live)
cd /case/extracted/AppData/Roaming/discord/Local\ Storage/leveldb/

# Étape 2 — Recherche du token utilisateur (commence par "mfa." pour MFA)
grep -Eor '[\w-]{24}\.[\w-]{6}\.[\w-]{27}|mfa\.[\w-]{84}' .

# Étape 3 — Exporter avec DiscordChatExporter (CLI, multiplateforme)
DiscordChatExporter.Cli.exe export -t "<token>" -c <channel_id> -f HtmlDark -o /case/discord/

# Étape 4 — Vérifier l'intégrité (hash de l'export + de la base raw)
sha256sum /case/discord/*.html /case/extracted/.../leveldb/*.ldb
⚖️ Précaution : utiliser le token pour lire les conversations en lieu et place du suspect a un statut juridique délicat (« perquisition électronique » sous mandat ? « interception »?). Préférer une réquisition formelle à Discord (legal@discord.com pour LE) qui fournit les logs côté serveur. Tor & Dark Web - mêmes considérations.
Webhook & Bot — Souvent oubliés
Discord est largement utilisé pour exfiltrer via webhooks. Reconnaître le pattern.
# Format d'un webhook Discord (à chercher dans le code malveillant ou le trafic)
https://discord.com/api/webhooks/{ID}/{TOKEN}

# Trafic réseau — Wireshark filter pour le détecter
tls.handshake.extensions_server_name == "discord.com"

# YARA rule pour détecter les webhooks dans des binaires/scripts
rule Discord_Webhook_URL { strings: $w = /https:\/\/discord\.com\/api\/webhooks\/\d+\/[A-Za-z0-9_-]+/ condition: $w }
Cadre légal CH — Messageries d'entreprise
⚖️ Surveillance de l'employé en Suisse

L'art. 26 OLT 3 et l'art. 328b CO encadrent la surveillance des communications professionnelles. Lecture systématique des messages d'un salarié = interdite sauf : règlement interne signé, motif justifié, principe de proportionnalité.

Pour une enquête pénale interne (suspicion fraude), aviser RH + juridique avant analyse, idéalement obtenir un mandat de l'autorité.

📜 Hébergement des données — Localité

Slack, Teams, Discord = serveurs aux US (avec régions UE). Réquisition au siège (Slack Technologies LLC, Microsoft Ireland, Discord Inc.) via :

  • Demande directe legal@
  • MLAT (CLOUD Act US, e-Evidence UE)
  • Délai 1 semaine à 6 mois selon urgence
🔐 Chiffrement & déchiffrement

Slack et Teams = TLS-in-transit + AES-256 at-rest, mais les opérateurs ont les clés (vs Signal/WhatsApp E2EE). Une réquisition légale fournit les contenus en clair côté serveur.

Discord : pas d'E2EE par défaut — accès admin = accès lecture sur tous les serveurs gérés.

🇨🇭 nLPD — Données de tiers

Conversations d'un suspect contiennent des données personnelles de tiers (collègues, clients). Acquisition complète = capture de ces données. Documenter la nécessité et proportionnalité dans le rapport (LPD art. 6).

🎓 Exam Tip — Messageries d'Entreprise

Slack Enterprise Grid → Discovery API (endpoint discovery.*) donne accès complet aux DM

Slack Pro/Business+ → Standard Export hors DM, requête formelle nécessaire pour DM

Teams chat 1:1 → archivé dans Exchange Online dossier TeamsMessagesData

Teams & Compliance Center → recherche unifiée Exchange + SharePoint + OneDrive + Teams via Purview

Discord → pas d'API enterprise, token user dans LevelDB, DiscordChatExporter pour lire

Webhook Discord → vecteur d'exfiltration courant, regex discord.com/api/webhooks/

Surveillance employé CH → règlement interne + proportionnalité (art. 328b CO, art. 26 OLT 3)

Une PME suisse soupçonne un cadre d'avoir partagé des données confidentielles via MS Teams. Le tenant est en plan E5. Comment procéder pour récupérer 6 mois de chats privés sans alerter le suspect ?Compliance · Niveau : moyen
Utiliser Microsoft Purview eDiscovery (Premium). Étapes : (1) Connect-IPPSSession en compliance admin, (2) New-ComplianceCase pour ouvrir un cas avec hold (verrouille la mailbox du suspect → empêche purge), (3) New-ComplianceSearch ciblé sur la mailbox + folderid:TeamsMessagesData, (4) Start-ComplianceSearch, (5) New-ComplianceSearchAction -Export qui crée un PST téléchargeable. Le suspect ne reçoit aucune notification (l'audit log lui est inaccessible). En Suisse : aviser RH + juridique avant lancement, documenter la proportionnalité (art. 328b CO).
Lors de l'analyse forensique d'un poste suspecté d'exfiltration, vous trouvez dans %APPDATA%\discord\Local Storage\leveldb\ une chaîne du type discord.com/api/webhooks/123456/abcdef-XYZ. Que faire ?Webhook · Niveau : moyen
Indicateur fort d'exfiltration via webhook. Discord webhook = endpoint d'écriture seule, souvent utilisé par malware/script pour envoyer des données vers un serveur Discord contrôlé par l'attaquant (anti-forensic, traffic légitime sortant). Étapes : (1) figer la preuve (hash du LevelDB), (2) NE PAS tester le webhook (réveille l'attaquant), (3) NE PAS envoyer de DELETE pour le « killer » sans accord juridique, (4) chercher dans %TEMP%, scripts PS et tâches planifiées la commande qui appelle l'URL, (5) requête formelle à Discord (legal@) avec l'ID du webhook pour identifier le serveur cible et son admin.
🎯 Essentiel terrain : Slack Enterprise = Discovery API (DM accessibles) · Slack Pro = Standard Export hors DM · Teams 1:1 = Exchange TeamsMessagesData via Purview · Discord = pas d'API enterprise + token dans LevelDB · Webhook Discord = exfiltration courante (URL en regex) · Surveillance employé CH (art. 328b CO + art. 26 OLT 3) = règlement + proportionnalité · MLAT pour réquisition cross-border (CLOUD Act, e-Evidence).
