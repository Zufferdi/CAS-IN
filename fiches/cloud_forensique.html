Défis spécifiques du cloud forensique
Problèmes fondamentaux
  • Juridiction multiple : les données peuvent être stockées dans n'importe quel pays
  • Accès limité : l'enquêteur n'a pas accès direct aux serveurs
  • Volatilité : logs supprimés après rétention (souvent 90 jours)
  • Multi-tenancy : isolation des données entre clients
  • Chiffrement : données chiffrées au repos et en transit
Leviers légaux disponibles
  • MLAT (Mutual Legal Assistance Treaty) : entraide judiciaire internationale
  • US CLOUD Act (2018) : accès direct aux données US stockées à l'étranger
  • Preservation Request : demander au provider de conserver les logs avant MLAT
  • Emergency Disclosure : pour danger imminent pour la vie
  • Content vs Metadata : les métadonnées sont plus facilement accessibles
Sources de logs par provider
🟦 Microsoft 365 / Azure
• Unified Audit Log — activité utilisateur 90 jours (E3) / 1 an (E5)
• Azure AD Sign-in logs — authentifications, IP, localisation
• Exchange Online — emails, métadonnées, traces de lecture
• SharePoint / OneDrive — accès fichiers, partages
• Teams — messages (via Compliance Center)
• Outil : Microsoft Compliance Center · Graph API · eDiscovery
🔴 Google Workspace
• Admin Reports — activité admin, connexions
• Gmail logs — envoi/réception, IP, appareil
• Drive Activity — accès, partage, suppression fichiers
• Meet — participation aux réunions
• Rétention : variable selon licence (180 j–6 mois)
• Outil : Vault (Google) · GAM (CLI) · Admin SDK API
🟠 Amazon AWS
• CloudTrail — toutes les actions API (qui a fait quoi, quand)
• VPC Flow Logs — trafic réseau entre ressources
• S3 Access Logs — accès aux buckets de stockage
• GuardDuty — détection d'anomalies
• Rétention : configurable (par défaut non permanents)
• Outil : AWS CLI · CloudWatch · Athena pour requêtes
🔵 Apple iCloud
• Données disponibles via Legal Process Guidelines d'Apple
• Contenu : contacts, calendriers, email, backups iOS
• iMessages : chiffrés E2E — Apple ne peut pas déchiffrer
• Backups non chiffrés si option activée par l'utilisateur
• Rétention : 25 jours pour les métadonnées de connexion
• Outil : Demande légale formelle uniquement
Processus de préservation
1
Preservation Request immédiate
Contacter le provider AVANT toute demande formelle pour demander la conservation des données. La plupart répondent en 24–48h pour les cas d'urgence. Sans ça, les logs disparaissent après rétention.
2
Identifier la juridiction
Où sont stockées les données ? (US, EU, etc.). Quel traité d'entraide applicable ? MLAT USA–Suisse, Entraide judiciaire EU–Suisse, etc. Le siège du provider ≠ localisation des données.
3
Demande légale formelle
Via MLAT (lent : 6–18 mois) ou accord bilatéral. En Suisse : passe par l'OFJ (Office fédéral de la justice). Distinguer métadonnées (plus facile) vs contenu (plus restrictif).
4
Analyse des logs reçus
Formater en timeline. Croiser avec les logs locaux. Les IP dans les logs cloud + corrélation avec DHCP local = attribution. Vérifier les User-Agents pour identifier l'appareil.
🇨🇭 Suisse et cloud : La LPD révisée (2023) impose des obligations aux entreprises suisses utilisant le cloud (art. 8 LPD : sécurité, art. 16 LPD : sous-traitants hors Suisse). Le PFPDT doit être notifié en cas de violation dans les 72h. Les données personnelles stockées dans le cloud US bénéficient du EU-US Data Privacy Framework (depuis juillet 2023).
