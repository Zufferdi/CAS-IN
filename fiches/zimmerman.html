① Philosophie — outils mono-objectifs

Chaque outil fait une chose — et la fait très bien.

🎯 Un outil, un artefact

Contrairement à des suites généralistes (X-Ways, Autopsy) qui parsent « tout » avec des heuristiques, les outils Zimmerman sont spécialisés par artefact. PECmd ne fait que du Prefetch. MFTECmd ne fait que la $MFT. Cette spécialisation garantit :

  • Exhaustivité — chaque champ du format est extrait et documenté
  • Fiabilité — code testé intensivement par la communauté DFIR
  • Reproductibilité — commandes CLI auditables, sorties CSV/JSON standardisées
  • Rapidité — pas de surcouche, traitement direct du format binaire
⚖️ Valeur judiciaire. En audience, dire « Analyse réalisée avec PECmd, outil reconnu de la communauté forensique internationale » est beaucoup plus solide que « Le logiciel a indiqué que… ». Les outils Zimmerman sont fréquemment cités dans les rapports d'expertise.
💡 X-Ways vs Zimmerman — complémentarité. X-Ways donne la vision globale, les outils Zimmerman apportent la précision chirurgicale sur chaque artefact Windows. Workflow type : X-Ways pour extraire les artefacts → outils Zimmerman pour les parser → Timeline Explorer pour corréler.

③ PECmd — analyse des fichiers Prefetch

L'outil de référence pour prouver une exécution de programme sur Windows.

⚡ PECmd — Prefetch Command

Spécialisé dans l'analyse des fichiers Prefetch .pf générés par Windows. Contrairement à un outil généraliste comme X-Ways qui identifie la présence d'un .pf, PECmd permet de comprendre précisément ce que Windows a enregistré sur l'exécution d'un programme.

🎯 Pourquoi utiliser PECmd ?

Les fichiers Prefetch sont une preuve d'exécution. Un .pf permet de démontrer :

  • qu'un programme a été exécuté sur le système
  • combien de fois il l'a été
  • à quelles dates approximatives (jusqu'à 8 timestamps)
  • quels fichiers et DLL ont été chargés au démarrage

Dans les enquêtes malware, intrusion, exécution de scripts, usage d'outils d'effacement, le Prefetch est un artefact clé.

④ Concept clé — le fichier Prefetch
💾 Qu'est-ce qu'un Prefetch ?

Windows crée un fichier .pf lors de l'exécution d'un programme, pour accélérer ses prochains lancements.

Localisation :

C:\Windows\Prefetch\

Nommage : NOM.EXE-HASH.pf (le hash dépend du chemin d'exécution).

📦 Ce que contient un Prefetch
  • Nom de l'exécutable
  • Nombre d'exécutions (compteur)
  • Jusqu'à 8 timestamps d'exécution
  • Liste complète des fichiers/DLL chargés
  • Chemin d'origine de l'exécutable
  • Version du format Prefetch (dépend de Windows)
⚖️ Valeur probante. La présence d'un Prefetch prouve une exécution, même si :
  • le programme a été supprimé
  • l'exécutable n'existe plus sur le disque
  • l'utilisateur nie l'avoir lancé
⚠️ Limite importante. L'absence d'un Prefetch ne prouve pas l'absence d'exécution. Le Prefetch peut être :
  • désactivé via EnablePrefetcher (Windows Server, certains SSD)
  • nettoyé volontairement par un outil anti-forensique
  • écrasé par rotation (limite ~1024 fichiers depuis Win8+, variable selon la version)
⑤ PECmd — commandes & sorties

Ligne de commande uniquement — traçabilité, reproductibilité, auditabilité.

📂 Analyse d'un dossier complet

Cas standard : analyser tout le dossier Prefetch d'un système.

PECmd.exe -d C:\Windows\Prefetch --csv C:\Export\prefetch.csv
-ddossier contenant les fichiers .pf
--csvexport des résultats au format CSV
🎯 Analyse d'un fichier unique

Cas ciblé : un exécutable suspect identifié en amont.

PECmd.exe -f NOTEPAD.EXE-3A4F2C1B.pf

Usage typique :

  • vérifier l'exécution d'un outil précis
  • analyser un .pf extrait d'un échantillon malware
  • confirmer ou infirmer une hypothèse d'usage
📊 Export JSON (usage avancé)
PECmd.exe -d C:\Windows\Prefetch --json C:\Export\

Utile pour l'intégration dans des pipelines automatisés, le traitement par scripts, ou l'import dans des plateformes SIEM / Splunk / Elastic.

📋 Informations extraites (colonnes CSV principales)
  • ExecutableName — nom de l'exécutable
  • RunCount — nombre d'exécutions enregistrées
  • SourceCreated / SourceModified — timestamps du .pf lui-même
  • LastRun + RunN (1..7) — jusqu'à 8 timestamps d'exécution
  • FilesLoaded — liste des fichiers et DLL chargés
  • VolumeName / VolumeSerialNumber — identification du volume source
  • Hashs internes du format Prefetch
  • Version du format Prefetch (indique la version Windows)

Ces données sont beaucoup plus complètes que celles affichées par un outil généraliste.

✅ Ce que PECmd permet d'affirmer. « Le programme X a été exécuté sur ce système » · « Il a été exécuté au moins N fois » · « La dernière exécution a eu lieu à une date compatible avec les faits ». Mais en forensique, on ne s'arrête jamais là. Les résultats PECmd se corrèlent avec UserAssist (registre), Jump Lists, ShellBags, journaux Windows, artefacts $MFT.
⑥ LECmd — parsing des fichiers LNK
🔗 LECmd — Lnk Explorer Command

Les fichiers .lnk sont créés automatiquement par Windows dès qu'un fichier est ouvert — ils contiennent le chemin absolu cible, le numéro de série du volume d'origine, les MAC times cibles, et même l'adresse MAC de la machine.

💻 Commande type
LECmd.exe -d "%AppData%\Microsoft\Windows\Recent" --csv C:\Export\

Emplacements clés à analyser :

  • %AppData%\Microsoft\Windows\Recent\ — fichiers récemment ouverts
  • %AppData%\Microsoft\Office\Recent\ — documents Office récents
  • Bureau et menu Démarrer
🎯 Preuves typiques extraites d'un .lnk
  • Chemin cible complet — même si le fichier a été supprimé ou volume absent
  • Volume d'origine — numéro de série, label, type (fixe/amovible)
  • Preuve d'utilisation d'une clé USB — via numéro de série du volume amovible
  • MAC times cibles — dates du fichier au moment de la création du raccourci
  • NetBIOS name + MAC address dans le TrackerDataBlock
⑦ MFTECmd — parsing de la $MFT NTFS
🗂 MFTECmd — Master File Table ECmd

Chaque fichier, chaque dossier, chaque attribut NTFS a une entrée dans la $MFT. MFTECmd parse cette table binaire (souvent plusieurs Go) et produit un CSV exploitable contenant tous les fichiers — existants ET supprimés, avec timestamps complets.

💻 Commandes clés
// Parser la $MFT principale
MFTECmd.exe -f C:\Extract\$MFT --csv C:\Export\

// Parser $UsnJrnl (journal NTFS des changements)
MFTECmd.exe -f C:\Extract\$J --csv C:\Export\

// Parser $Boot et $LogFile également
MFTECmd.exe -f C:\Extract\$Boot --csv C:\Export\

// Parser $SDS — Security Descriptor Stream (audit ACL)
MFTECmd.exe -f C:\Extract\$Secure:$SDS --csv C:\Export\

Compatible avec les fichiers .mft exportés par X-Ways — pipeline classique : X-Ways exporte → MFTECmd parse → Timeline Explorer corrèle.

📊 Ce que révèle le CSV
  • Tous les fichiers, avec leur chemin reconstitué
  • Les 4 timestamps de chaque attribut $STANDARD_INFORMATION et $FILE_NAME — détection de timestomping
  • Fichiers supprimés (entrée MFT encore présente, bit occupé à 0)
  • ADS (Alternate Data Streams) — données cachées derrière un fichier
  • Pistes de run list pour reconstruire les clusters
🔍 Détection de timestomping. Comparer les timestamps $SI (modifiables par l'utilisateur) avec $FN (modifiables uniquement par le kernel) révèle une manipulation. MFTECmd expose les deux colonnes — si $SI.Created est antérieure à $FN.Created, l'horodatage a été falsifié.
⑧ EvtxECmd — journaux d'événements Windows
📋 EvtxECmd — Windows Event Log ECmd

Les journaux .evtx (C:\Windows\System32\winevt\Logs\) contiennent des milliers d'événements XML imbriqués. EvtxECmd les parse en CSV linéaire, avec plus de 1000 « maps » qui enrichissent les Event IDs courants (logons, exécutions, services, PowerShell…).

💻 Commande type
EvtxECmd.exe -d C:\Windows\System32\winevt\Logs --csv C:\Export\

// Avec filtre sur une plage temporelle
EvtxECmd.exe -f Security.evtx --csv C:\Export\ --sd "2024-10-01" --ed "2024-10-07"
🎯 Event IDs clés à surveiller
Event IDSignification
4624Connexion réussie (Logon Type : 2=local, 3=réseau, 10=RDP)
4625Échec de connexion — bruteforce, mauvais MDP
4634Déconnexion d'une session — calculer la durée de session avec 4624
4648Logon avec credentials explicites — détection de mouvement latéral (runas, PsExec)
4672Privilèges spéciaux assignés au logon — détection d'élévation (admin, backup, debug)
4688Création de processus (si audit activé) — ligne de commande parfois incluse
4720Création de compte utilisateur
7045Installation d'un nouveau service (legacy)
4697Installation d'un nouveau service (moderne) — complément de 7045
1102Journal Security effacé (anti-forensique — très suspect)
⑨ ShellBags Explorer — dossiers visités
📁 ShellBags Explorer (SBE) — GUI

Windows enregistre dans le registre (NTUSER.DAT et USRCLASS.DAT) la liste des dossiers visités dans l'explorateur de fichiers — y compris ceux qui ont été supprimés, ceux sur des volumes amovibles absents, et les dossiers réseau.

🖥 Utilisation

Interface graphique (pas de CLI). Charger les ruches :

  1. File → Load hive
  2. Sélectionner NTUSER.DAT (généralement C:\Users\<user>\NTUSER.DAT)
  3. Ajouter USRCLASS.DAT (AppData\Local\Microsoft\Windows\UsrClass.dat)
  4. Explorer l'arborescence reconstituée dans le panneau principal
  5. Exporter : File → Export → All bags → CSV
🎯 Valeur probante
  • Prouve qu'un utilisateur a navigué dans un dossier donné
  • Reconstruit les chemins de clés USB explorées même une fois la clé débranchée
  • Révèle des dossiers supprimés depuis longtemps
  • Timestamps d'accès (first interacted, last interacted)
⑩ AmcacheParser — tous les exécutables connus
🧬 AmcacheParser — Amcache.hve

Amcache.hve est une ruche de registre Windows (Win8+) qui stocke des informations sur chaque exécutable ayant tourné sur la machine, y compris le SHA-1 complet du binaire. L'un des artefacts les plus précieux en réponse à incident.

💻 Commande type
AmcacheParser.exe -f C:\Windows\AppCompat\Programs\Amcache.hve --csv C:\Export\
🎯 Ce qu'on y trouve — bien plus que les exécutables

L'Amcache contient plusieurs tables distinctes, chacune avec ses propres preuves :

TableContenu forensique
InventoryApplicationFileExécutables : SHA-1, chemin, taille, éditeur, première exécution
InventoryApplicationProgrammes installés avec version, éditeur, langue, date d'installation
InventoryDriverBinaryPilotes chargés, SHA-1 — précieux pour détection rootkits
InventoryApplicationShortcutRaccourcis vers apps — utile pour le triage d'activité
InventoryDeviceContainerPériphériques connectés (y compris USB historiques)
InventoryDevicePnpMatériel Plug-and-Play énuméré

Usage typique : lister tous les exécutables → calculer les hashs → comparer à une baseline → isoler les binaires inconnus ou malveillants. Pour traquer un rootkit, se concentrer sur InventoryDriverBinary.

⑪ Autres outils de la suite — souvent oubliés

Trois outils complémentaires qui couvrent des artefacts spécifiques.

🗝 RECmd — Registry Explorer CLI

Pendant CLI du GUI Registry Explorer. Parse n'importe quelle ruche de registre avec des batches de requêtes — utile en pipeline automatisé.

RECmd.exe -d C:\Extract\Hives --bn BatchExamples\Kroll_Batch.reb --csv C:\Export\

Les batch files (.reb) définissent des extractions standard : USBSTOR, UserAssist, BAM/DAM, ShellBags, MRU, etc. Les plus utilisés : Kroll_Batch, RegistryASEPs.

📌 JLECmd — Jump Lists

Les Jump Lists (listes de fichiers récents par application, visibles en clic droit sur la barre des tâches) sont souvent plus riches que les .lnk.

JLECmd.exe -d "%AppData%\Microsoft\Windows\Recent\AutomaticDestinations" --csv C:\Export\

Extrait : chemins cibles, volumes, MAC times cibles, compteur d'utilisation par app — ex. VLC a joué cette vidéo 12 fois.

🛡 SDBExplorer — Shim Databases

Les fichiers .sdb (Shim Database) servent à ajuster la compatibilité des applications. Certains malwares s'en servent pour persister — par exemple en injectant une DLL dans un processus cible via le mécanisme de shim.

SDBExplorer.exe -f C:\Windows\AppPatch\sysmain.sdb

Emplacements classiques : C:\Windows\AppPatch\ (système) et C:\Windows\AppPatch\Custom\ (shims personnalisés — à surveiller).

⑫ Timeline Explorer — corrélation visuelle
⏱ Timeline Explorer — GUI

Tous les outils précédents produisent des CSV. Timeline Explorer est la visionneuse officielle pour les ouvrir, les filtrer, les trier, les empiler — tout en restant performant sur des fichiers de plusieurs millions de lignes.

🎛 Fonctions clés
  • Ouverture rapide de CSV massifs (millions de lignes)
  • Filtres colonnes type Excel, mais instantanés
  • Marquage/tagging de lignes pour le rapport
  • Export des lignes filtrées vers un nouveau CSV
  • Coloration conditionnelle pour faire ressortir les anomalies
  • Ouverture simultanée de plusieurs CSV dans des onglets
🔗 Corrélation multi-artefacts. Le vrai pouvoir de Timeline Explorer : charger simultanément la sortie de PECmd, MFTECmd, LECmd, EvtxECmd et observer une même fenêtre temporelle à travers tous les artefacts. Un processus lancé à 14:32:11 apparaîtra dans 4624 (logon), 4688 (création proc), Prefetch, $MFT — la corrélation élimine les faux positifs et consolide la chronologie.
⑬ Workflow forensique type

L'intervention des outils Zimmerman dans une enquête complète.

1
Analyse disque avec X-Ways. Vue globale, identification des artefacts pertinents selon l'hypothèse d'enquête.
2
Extraction des artefacts ciblés. Depuis X-Ways, extraire : dossier Prefetch\, $MFT, NTUSER.DAT, Amcache.hve, dossier winevt\Logs\, dossier Recent\.
3
Parsing avec les outils Zimmerman. PECmd sur Prefetch · MFTECmd sur $MFT · EvtxECmd sur les logs · AmcacheParser sur Amcache · LECmd sur Recent · SBE sur NTUSER/USRCLASS.
4
Export CSV standardisé. Tous les CSV dans un même dossier C:\Export\. Conserver ces CSV comme pièces annexes du rapport (reproductibilité).
5
Corrélation dans Timeline Explorer. Charger tous les CSV, filtrer autour de la fenêtre temporelle d'intérêt, marquer les lignes pertinentes.
6
Construction de la chronologie finale. Export des lignes taggées vers un timeline consolidé. Intégration dans le rapport avec la commande exacte et les hashs des fichiers analysés.
⑭ Bonnes pratiques forensiques
💾 Toujours sur copie

Ne jamais parser les ruches ou artefacts sur un système vivant — travailler sur une copie forensique (image E01/DD montée en lecture seule, ou extraction dans un dossier de travail).

📝 Documenter la commande exacte

Enregistrer dans le journal d'analyse la ligne de commande complète, y compris la version de l'outil (-v ou --version). Reproductibilité = validité judiciaire.

🔗 Toujours corréler

Un artefact isolé est faible en preuve. Un Prefetch + un 4688 + une entrée $MFT + un 4624 sur la même fenêtre temporelle = chronologie solide.

⚠️ Expliquer les limites

Prefetch désactivable · journaux écrasables · ruches verrouillées sur système vivant · timestomping possible sur $SI. L'analyste mentionne ces limites dans le rapport.

📦 Conserver les exports

Les CSV/JSON produits sont des pièces techniques du dossier. Ils doivent être conservés avec leur hash et accompagner le rapport final.

🎯 Ne pas sur-interpréter

PECmd prouve une exécution — il ne prouve pas l'intention. Corréler avec UserAssist, Jump Lists, logs, et le contexte factuel avant toute conclusion.

🎓 PECmd n'est pas un outil de découverte. C'est un outil de confirmation. Il permet à l'analyste de transformer une hypothèse en preuve, de démontrer une exécution passée, de renforcer une chronologie technique. La découverte se fait en amont (X-Ways, Autopsy, triage) — la confirmation par PECmd / LECmd / MFTECmd vient ensuite consolider le dossier.
