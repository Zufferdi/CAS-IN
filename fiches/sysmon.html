🔑 Sysmon — l'EDR gratuit de Microsoft
Sysmon (System Monitor) est un outil Sysinternals gratuit de Mark Russinovich, distribué par Microsoft. Installé comme service Windows + driver kernel, il enrichit les Event Logs natifs avec des événements riches : hash SHA-256 de chaque processus créé, GUID unique de processus, lignée parent complète, connexions réseau avec destination, modifications de registre, créations de fichiers, injection de code, requêtes DNS… Là où Security EID 4688 donne juste « powershell.exe a démarré », Sysmon EID 1 donne quelle ligne de commande, quel hash, quel parent, quel utilisateur, quel ProcessGuid pour corréler tout le reste. C'est le pilier du Threat Hunting Windows moderne, déployé par défaut chez la plupart des SOC matures.

Installation rapide
📥 Installation manuelle
# 1. Télécharger Sysmon
# https://learn.microsoft.com/sysinternals/downloads/sysmon

# 2. Télécharger une config (SwiftOnSecurity)
curl -O https://raw.githubusercontent.com/
  SwiftOnSecurity/sysmon-config/master/
  sysmonconfig-export.xml

# 3. Installer (admin)
sysmon64.exe -accepteula -i sysmonconfig-export.xml

# 4. Mettre à jour la config sans réinstaller
sysmon64.exe -c sysmonconfig-export.xml

# 5. Vérifier
sysmon64.exe -c        # afficher la config active
Get-Service Sysmon64   # service tournant
🏢 Déploiement de masse
  • GPO startup script avec sysmon64.exe -accepteula -i \\\\share\\config.xml conditionné sur l'absence du service
  • SCCM / Intune / Tanium : task séquence + détection par version Sysmon
  • WEF (Windows Event Forwarding) pour centraliser les logs vers un Event Collector → SIEM
  • Permissions WEF : wevtutil sl Microsoft-Windows-Sysmon/Operational /ca:O:BAG:SYD:(A;;0xf0005;;;SY)(A;;0x5;;;BA)(A;;0x1;;;S-1-5-32-573)
  • Mise à jour : nouvelle version → -u puis réinstall ; nouvelle config → -c
💡 Sysmon ≠ EDR commercial mais c'est le plus proche substitut gratuit. Ce qu'il n'a pas : pas de blocage actif (uniquement détection), pas de console centrale (il faut SIEM/WEF), pas de threat intel intégrée. Ce qu'il offre : visibilité endpoint au niveau d'un EDR de gamme moyenne, à coût zéro, totalement scriptable, avec une community config (SwiftOnSecurity, sysmon-modular) maintenue.
🎯 Les 27 Event IDs Sysmon — focus sur les 8 critiques
Sysmon génère 27 types d'événements (EID 1 à 27 dans les versions récentes). Tous ne se valent pas en valeur DFIR. Les 8 essentiels à mémoriser : 1, 3, 7, 8, 10, 11, 13, 22 — couvrant les phases Execution, C2, Code Injection, Persistence, Defense Evasion de MITRE ATT&CK.

🚨 Lecture forensique de cet event : WINWORD.EXE → powershell.exe encodé. C'est la chaîne « Office macro → PowerShell loader » classique des phishings (Emotet, Qakbot, IcedID, document attack 2024-2026). IntegrityLevel=Medium + ParentImage=WINWORD + CommandLine avec -Enc = 3 IOC suffisants pour escalader en P1. Le ProcessGuid permet ensuite de retrouver TOUS les EID 3 (réseau), 11 (fichiers créés), 13 (registre), 22 (DNS) liés à ce process.
⚙️ Le fichier de config — l'âme de Sysmon
Sysmon sans config est quasiment inutile (verbeux, sans filtrage). Toute la valeur vient du fichier XML qui définit pour chaque EID une chaîne de règles include / exclude avec des conditions sur les champs (contains, begin with, end with, is, image, etc.). Deux configurations communautaires dominent l'écosystème depuis 2017.
Les deux configs de référence
🐦 SwiftOnSecurity / sysmon-config

github.com/SwiftOnSecurity/sysmon-config

✅ Une grosse config monolithique, abondamment commentée (4000+ lignes). Maintenue par @SwiftOnSecurity (figure historique de l'OSINT cyber).

✅ Approche « exclude-list » : on logue beaucoup, on exclut le bruit légitime (Chrome update, OneDrive sync, Windows Update…).

✅ Excellente entrée pour un déploiement rapide « ça marche tout de suite ».

⚠️ Difficile à personnaliser (énorme fichier unique).

🧩 Olaf Hartong / sysmon-modular

github.com/olafhartong/sysmon-modular

✅ Configuration modulaire : un fichier XML par technique ATT&CK / par EID / par direction (include/exclude), assemblés via PowerShell Merge-AllSysmonXml.

✅ Chaque règle est mappée sur un identifiant ATT&CK (T1059.001, T1003.001…) — visible dans RuleName de l'event.

✅ Maintenable en CI/CD, fork facile par environnement.

⚠️ Plus exigeant — pour équipes SOC matures qui veulent un vrai pipeline de détection.

Squelette d'une config XML
<Sysmon schemaversion="4.90">
  <HashAlgorithms>SHA256,IMPHASH</HashAlgorithms>
  <CheckRevocation/>
  <DnsLookup>false</DnsLookup>        # désactiver lookup DNS sur IP

  <EventFiltering>

    <!-- ════════ EID 1 : Process Create ════════ -->
    <RuleGroup name="" groupRelation="or">
      <ProcessCreate onmatch="exclude">     # whitelist du bruit légitime
        <Image condition="is">C:\Windows\System32\svchost.exe</Image>
        <ParentImage condition="is">C:\Program Files\Google\Update\GoogleUpdate.exe</ParentImage>
      </ProcessCreate>
    </RuleGroup>

    <!-- ════════ EID 3 : Network Connection ════════ -->
    <RuleGroup name="" groupRelation="or">
      <NetworkConnect onmatch="include">    # on logue UNIQUEMENT ce qui matche
        <DestinationPort condition="is">4444</DestinationPort>       # Metasploit default
        <DestinationPort condition="is">1080</DestinationPort>       # SOCKS proxy
        <Image condition="end with">\powershell.exe</Image>
        <Image condition="end with">\cscript.exe</Image>
        <Image condition="end with">\wscript.exe</Image>
      </NetworkConnect>
    </RuleGroup>

    <!-- ════════ EID 10 : ProcessAccess (LSASS) ════════ -->
    <RuleGroup name="technique_id=T1003.001,technique_name=LSASS Memory" groupRelation="or">
      <ProcessAccess onmatch="include">
        <TargetImage condition="end with">\lsass.exe</TargetImage>
        <GrantedAccess condition="is">0x1010</GrantedAccess>     # Mimikatz
        <GrantedAccess condition="is">0x1410</GrantedAccess>
        <GrantedAccess condition="is">0x1438</GrantedAccess>
      </ProcessAccess>
    </RuleGroup>

  </EventFiltering>
</Sysmon>

⚠️ Limites importantes : Sysmon ne supporte ni les wildcards (*) ni les regex dans les conditions. Tout est string-match littéral. Pour les motifs complexes, il faut décomposer en plusieurs règles. La logique onmatch="include" + groupRelation="or" = OU logique entre toutes les conditions du groupe.
🔍 Threat Hunting avec Sysmon — patterns gagnants
Quelques chasses qui paient à coup sûr en environnement réel. À adapter selon votre baseline (IT internal, dev, etc.) — l'art du hunt est de connaître son normal pour repérer l'anormal.
Top 10 des hunts Sysmon
① Office → child process
EID 1 avec ParentImage = WINWORD/EXCEL/POWERPNT/OUTLOOK et Image ≠ {WINWORD, OUTLOOK protected view…}.
Détecte : macros malveillantes, exploits document.
ATT&CK : T1566.001 + T1204.002
② LSASS access avec GrantedAccess suspect
EID 10 avec TargetImage=lsass.exe et GrantedAccess ∈ {0x1010, 0x1410, 0x1438, 0x143A, 0x1FFFFF}.
Détecte : Mimikatz, ProcDump, comsvcs.dll, MiniDumpWriteDump.
ATT&CK : T1003.001
③ Run keys écrites par non-installer
EID 13 avec TargetObject contenant \CurrentVersion\Run et Image ≠ msiexec/Setup/installeurs connus.
Détecte : persistance utilisateur naïve.
ATT&CK : T1547.001
④ DNS queries vers domaines DGA
EID 22 avec QueryName matchant entropie élevée + TLD .top/.xyz/.icu, ou QueryStatus=0x9003 (NXDOMAIN) en rafale.
Détecte : C2 fallback DGA.
ATT&CK : T1071.004 + T1568.002
⑤ Pipe SMB Cobalt Strike
EID 17/18 avec PipeName matchant \\msagent_*, \\postex_*, \\status_*, \\MSSE-* (patterns Cobalt Strike beacon par défaut).
ATT&CK : T1071.001
⑥ Burst de FileCreate (ransomware)
EID 11 > 100 par seconde par même ProcessGuid, ou extensions cibles : .locked, .encrypted, .locky, .<random8>.
ATT&CK : T1486
⑦ Vulnerable Driver loaded
EID 6 avec ImageLoaded dans la liste BYOVD (loldrivers.io) : RTCore64.sys, gdrv.sys, iqvw64.sys…
ATT&CK : T1068
⑧ DLL load depuis user folder
EID 7 avec ImageLoaded commençant par C:\Users\ ou C:\Temp\ ou C:\ProgramData\ + signed=false.
ATT&CK : T1574 (DLL hijacking, side-loading)
⑨ WMI subscription persistence
EID 19/20/21 — toute occurrence est suspecte hors scénarios légitimes documentés (SCCM, GPO).
ATT&CK : T1546.003
⑩ Process Hollowing détecté
EID 25 (v13+) — Sysmon détecte directement le hollowing : Type="Image is replaced".
ATT&CK : T1055.012
Le ProcessGuid — colonne vertébrale de l'investigation
⭐ Le ProcessGuid est le champ Sysmon le plus puissant. C'est un GUID unique mondial créé pour chaque processus, présent dans tous les events Sysmon liés (1, 3, 7, 8, 10, 11, 13, 17, 18, 22…). Une seule requête WHERE ProcessGuid = '{4f8a72d1-...}' reconstruit instantanément tout ce qu'un processus a fait : ses fichiers créés, ses connexions, ses modifs registre, ses DNS — sans dépendre des PID (qui sont réutilisés). C'est l'équivalent du ProcessGuid qu'on retrouve aussi dans ParentProcessGuid → reconstruction de l'arbre généalogique complet.

Sysmon Tampering — comment l'attaquant attaque Sysmon
🚨 Sysmon est une cible de choix. Si l'attaquant le neutralise, l'EDR-like devient aveugle. Plusieurs techniques connues — chacune avec sa contre-mesure.
Technique Mécanisme Contre-mesure
Stop service net stop Sysmon64 avec privilège SYSTEM EID 4672 + EID 5 Sysmon → alerter sur arrêt service · forwarding WEF immédiat
Unload driver fltmc unload SysmonDrv Sysmon EID 6 sur lui-même · alerter sur driver unload
Rename binary Installer Sysmon avec un nom non-standard (-i custom.xml -name MyMonitor) → l'attaquant ne sait plus quoi tuer ✅ Bonne pratique défensive — masque la présence de Sysmon
Config swap Remplacer la config par une qui ne logue rien : sysmon -c minimal.xml EID 16 (config change) — alerter, comparer hash de config
Phantom DLL hijacking Injecter une DLL dans le processus Sysmon pour bypasser le filtrage WDAC + Code Integrity · monitoring intégrité du binaire
EDR-Sandblast / similar Patch des callbacks kernel (PsSetCreateProcessNotifyRoutineEx) Difficile — nécessite kernel-level monitoring · Defender for Endpoint, ELAM
⭐ Bonnes pratiques Sysmon en 2026 : (1) Forwarding WEF obligatoire vers un Event Collector externe — pas de log uniquement local, (2) renommer le service à l'install (-name X), (3) monitorer EID 16 Sysmon (config changes) et EID 4 Sysmon (state changes), (4) protéger le binaire sysmon par WDAC, (5) versionner la config en Git avec CI qui valide le XML avant déploiement.

Vous voyez un Sysmon EID 10 avec SourceImage=mimikatz.exe, TargetImage=lsass.exe, GrantedAccess=0x1010. À quoi correspond ce 0x1010 et que signifie-t-il forensiquement ?
Sysmon · Niveau : moyen
0x1010 est un masque d'accès Windows = PROCESS_VM_READ (0x0010) | PROCESS_QUERY_LIMITED_INFORMATION (0x1000). C'est le combo précis demandé par Mimikatz pour lire la mémoire de LSASS et en extraire les credentials (NTLM hashes, tickets Kerberos en cache, mots de passe en clair via WDigest si activé). Forensiquement, EID 10 + TargetImage=lsass.exe + GrantedAccess ∈ {0x1010, 0x1410, 0x1438, 0x143A, 0x1FFFFF} est la signature canonique du credential dumping (MITRE T1003.001). Variantes : procdump.exe -ma lsass.exe demandera 0x1FFFFF (PROCESS_ALL_ACCESS) — encore plus visible. Action SOC : isolation immédiate du host + capture RAM + révoquer tous les tickets Kerberos du domaine (Reset-ADAccountPassword sur krbtgt deux fois).
Pourquoi le ProcessGuid est-il préféré au ProcessId (PID) pour les corrélations forensiques ?
Sysmon · Niveau : facile
Les PIDs sont réutilisés par Windows. Sur un système qui tourne depuis longtemps, le PID 4328 a pu être powershell.exe à 09:00 puis chrome.exe à 14:00 puis cmd.exe à 18:00. Toute requête WHERE ProcessId=4328 mélange ces trois processus distincts. Le ProcessGuid est un GUID unique mondial créé par Sysmon à la naissance de chaque processus, jamais réutilisé. Il est présent dans tous les events Sysmon liés au même processus (EID 1, 3, 7, 8, 10, 11, 13, 17, 22…) et dans les events des processus enfants via ParentProcessGuid. Une seule requête WHERE ProcessGuid='{4f8a72d1-…}' reconstruit toute l'activité du processus + son arbre généalogique en remontant les GUIDs parent. C'est la pierre angulaire du Threat Hunting Sysmon.
