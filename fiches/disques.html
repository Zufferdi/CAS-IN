💾 Disques — Le substrat physique de toute donnée
Avant tout système de fichiers (NTFS, ext4, APFS), il y a la structure physique du disque : secteurs (plus petite unité physique, historiquement 512 octets, modernes 4096 = "Advanced Format"), partitions (zones logiques découpées par le schéma de partitionnement MBR ou GPT), et adressage (CHS hérité ou LBA moderne). Maîtriser cette couche est indispensable pour tout forensiste : un secteur mal compris = des offsets faussés ; un GPT non reconnu = des partitions invisibles ; une HPA/DCO ignorée = des données cachées non saisies. Deux problèmes contemporains majeurs : (1) SSD + TRIM — sur SSD, la commande TRIM efface physiquement les blocs marqués supprimés, fenêtre de récupération très courte (vs HDD où on peut récupérer des semaines après) ; (2) HPA / DCO — zones cachées en fin de disque où le firmware peut dissimuler des outils constructeur ou (volontairement) des données. Bonne pratique forensique : toujours vérifier la taille annoncée vs la taille maximale via hdparm, et documenter dans le rapport.

📜 MBR — Master Boot Record (secteur 0)
Premier secteur du disque · 512 octets · né en 1983 avec PC DOS 2.0.
OffsetTailleContenu
0x000440 octetsCode de démarrage (Bootstrap) — charge le bootloader OS
0x1B84 octetsSignature disque (Windows Disk Signature)
0x1BE64 octetsTable de partition — 4 × 16 octets (4 partitions primaires max)
0x1FE2 octetsSignature de boot : 55 AA — magic obligatoire
⚠️ Endianness : la valeur mathématique est 0xAA55 mais stockée en little-endian → 55 puis AA sur le disque. Si le BIOS ne trouve pas 55 AA aux offsets 510-511 → "No Bootable Device Found". Pour vérifier : xxd -s 510 -l 2 disk.img doit afficher 55aa.
📜 GPT — GUID Partition Table
Schéma moderne pour disques > 2.2 To · obligatoire UEFI · jusqu'à 128 partitions.
🧱 Structure GPT
  • LBA 0 : Protective MBR (code 0xEE — signale un disque GPT aux vieux systèmes)
  • LBA 1 : En-tête GPT primaire (CRC32 inclus)
  • LBA 2-33 : Table des partitions primaire (128 entrées × 128 octets)
  • … (zone données utilisateur) …
  • LBA -34 à -2 : Table des partitions secondaire
  • LBA -1 : En-tête GPT secondaire (sauvegarde)
  • Redondance primaire/secondaire = récupération si un en-tête corrompu
⚙️ Avantages vs MBR
  • MBR max : 2.2 To (adresses 32 bits)
  • GPT max : 8 Zettaoctets (adresses 64 bits LBA)
  • MBR : 4 partitions primaires
  • GPT : jusqu'à 128 partitions
  • UEFI obligatoire pour démarrer sur GPT
  • Le "Protective MBR" au LBA 0 signale aux vieux systèmes de ne pas toucher au disque GPT
  • Identifiants GUID uniques pour chaque partition (vs IDs réutilisés MBR)
🎯 Adressage — CHS vs LBA
📐 CHS — Cylinder/Head/Sector

Adressage physique hérité : Cylindre (0-N), Tête (0-M), Secteur (1-S). Forme : C/H/S.

Limites : la densité de pistes varie entre intérieur et extérieur du disque. Le CHS ne reflète plus la géométrie réelle depuis les disques > 504 Mo.

CHS 0/0/1 = LBA 0 = premier secteur du disque.

🔢 LBA — Logical Block Addressing

Numérotation séquentielle des secteurs de 0 à la fin du disque. Abstraction complète — le contrôleur du disque fait la traduction LBA → géométrie physique en interne.

Les outils forensiques modernes travaillent directement en LBA — accès direct à n'importe quel secteur indépendamment des structures logiques (partitions, systèmes de fichiers).

Format 28-bit : limite 137 Go · Format 48-bit (depuis 2002) : limite 144 Po.

📐 Secteurs et Clusters
🧱 Secteur — plus petite unité physique

Historiquement 512 octets. Disques modernes (depuis ~2010) : 4096 octets (Advanced Format / 4Kn).

Les outils forensiques lisent en secteurs — si un secteur n'est pas à 512, les calculs d'offset sont faussés.

Vérifier dans X-Ways : Options → Disque → Taille de secteur. Vérifier en CLI : fdisk -l /dev/sdX.

🧱 Cluster — unité d'allocation

Groupe de secteurs consécutifs. Le système de fichiers alloue toujours des clusters entiers — c'est l'unité minimale d'allocation logique.

FAT32 : taille variable (4 Ko à 32 Ko selon partition)

NTFS : 4096 octets par défaut (8 secteurs × 512)

Slack space : si un fichier de 7 octets occupe un cluster de 4096, il y a 4089 octets de slack space. Deux zones : le RAM Slack (fin du fichier → fin du dernier secteur, rempli de zéros sous Windows NT+) et le Drive Slack (secteurs entiers non utilisés jusqu'à la fin du cluster, contenant des résidus de l'ancien fichier) — artefact forensique précieux.

🚨 HPA et DCO — Zones cachées
⚠️ Bonne pratique forensique : toujours vérifier l'existence de zones HPA et DCO avant l'acquisition. Si non vérifié, le mentionner explicitement dans le rapport. Ces zones peuvent contenir des données dissimulées intentionnellement.
🔴 HPA — Host Protected Area

Zone à la fin du disque, hors adressage LBA normal. Invisible pour l'OS et les outils standards.

Utilisée par les fabricants pour stocker les outils de restauration. Peut être utilisée pour cacher des données.

Détection : comparer la taille annoncée (IDENTIFY DEVICE) avec la taille maximale (READ NATIVE MAX ADDRESS).

Commande : hdparm -N /dev/sdX

Si HPA présent : HPA is enabled + tailles différentes affichées.

🟣 DCO — Device Configuration Overlay

Couche de configuration qui peut masquer des fonctionnalités ou réduire la taille visible du disque.

Un fabricant peut "brider" un disque de 2 To pour le vendre comme 1 To via le DCO.

Forensiquement : zone potentiellement encore plus cachée que HPA — toujours vérifier.

Commande : hdparm --dco-identify /dev/sdX

Pour révéler complètement HPA + DCO et accéder à toute la NAND : hdparm --dco-restore (⚠️ irréversible, faire une image avant).

💿 SSD vs HDD — TRIM, le grand problème forensique
🟢 HDD — Récupération classique facile

Supprimer un fichier sur HDD ne supprime jamais les données physiquement. Le système de fichiers marque les clusters comme libres mais les octets restent intacts.

Le carving (reconstruction par signature) peut retrouver des données longtemps après la suppression — tant que les clusters n'ont pas été réécrits par d'autres fichiers.

Outils : foremost, scalpel, PhotoRec, Autopsy.

🔴 SSD — TRIM efface immédiatement

TRIM est une instruction envoyée au contrôleur SSD lors d'une suppression : « ces blocs ne contiennent plus rien d'utile, tu peux les effacer en arrière-plan ».

Le contrôleur efface physiquement lors de ses cycles de maintenance (parfois quelques minutes seulement après TRIM).

Conséquence forensique : la récupération après suppression sur SSD est très difficile et la fenêtre est très courte. Acquérir immédiatement avec write-blocker.

Désactiver TRIM avant analyse : fsutil behavior set DisableDeleteNotify 1 (Windows).

🧠 Testez-vous
Vous saisissez un SSD chez un suspect. Pourquoi le brancher avec un write-blocker même si vous voulez juste « regarder » ?SSD / TRIM · Niveau : facile
Sur SSD, brancher = potentiellement détruire des preuves. Sans write-blocker : (1) Le système peut monter automatiquement les partitions et écrire des metadata (last access time, journal NTFS, etc.). (2) Si TRIM est activé sur l'OS hôte et que le SSD est reconnu comme connu, certains OS envoient des commandes UNMAP en pre-emptive cleanup. (3) Le contrôleur SSD peut garbage-collecter en arrière-plan dès qu'il a du courant. (4) Wear leveling peut déplacer les blocs pour équilibrer l'usure. Write-blocker hardware (Tableau, WiebeTech) intercepte toutes les commandes d'écriture. Best practice forensique : (a) Hash SHA-256 du SSD avant tout, (b) acquérir une image dd/E01 immédiatement avec write-blocker, (c) travailler uniquement sur la copie. Bonus : sur certains SSD modernes, même avec write-blocker, il existe une dérive du hash mineure due aux opérations internes du contrôleur (housekeeping) — bien documenter dans le rapport.
Un disque de 4 To affiche seulement 2 To dans Windows et BIOS. Quelle hypothèse vérifier ?HPA / DCO · Niveau : moyen
Plusieurs hypothèses, dans l'ordre : (1) MBR au lieu de GPT — MBR limite à 2.2 To. Vérifier : parted /dev/sdX print. Si MBR sur disque > 2 To, le reste est inaccessible — pas malveillant mais le disque a été mal initialisé. (2) HPA / DCO actif — quelqu'un (ou le firmware) a brimé la taille visible. Vérifier : hdparm -N /dev/sdX compare HPA enabled · hdparm --dco-identify /dev/sdX compare DCO. Si différence entre IDENTIFY DEVICE et READ NATIVE MAX → HPA. (3) Disque de 4 To bridé hardware — certains disques sont vendus avec firmware limitant la capacité. (4) RAID / LVM — le disque est en RAID 1 (miroir) avec un autre, taille effective = 50%. (5) Encrypted volume non monté affichant taille du conteneur. Procédure forensique : (a) Documenter ce qu'affichent fdisk -l, hdparm -I, BIOS, Windows, (b) si HPA/DCO, faire une image complète AVANT de modifier (hdparm --dco-restore est irréversible), (c) toujours mentionner dans le rapport si HPA/DCO non vérifié.
Quel est le slack space dans un cluster NTFS ? Pourquoi est-il forensiquement intéressant ?Slack space · Niveau : moyen
NTFS alloue par cluster entier (typiquement 4096 octets). Un fichier de 100 octets occupe quand même 1 cluster complet. Les 3996 octets restants = slack space. Trois types à distinguer :

(1) RAM Slack (= Sector Slack) = espace entre la fin logique du fichier et la fin du dernier secteur utilisé. Sous Windows NT+ (NT4, XP, 7, 10, 11), le kernel remplit cette zone avec des zéros — contrairement à DOS/Windows 9x qui y écrivait le contenu du buffer RAM. Sur un système NT moderne, le RAM Slack contient donc des zéros et n'est forensiquement intéressant que comme marqueur de taille de fichier.

(2) Drive Slack = espace entre la fin du dernier secteur utilisé et la fin du dernier cluster alloué (secteurs entiers non utilisés). Cette zone n'est pas réinitialisée par l'OS lors de l'allocation — elle contient le contenu résiduel de l'ancien fichier qui occupait ces clusters. C'est ici que se trouvent les artefacts forensiques précieux : fragments de fichiers supprimés, anciens journaux, configurations.

Forensiquement : le Drive Slack est la zone intéressante. Outils : Autopsy (slack space module), X-Ways (afficher slack), icat (TSK), dd sur les bons offsets. Limite : les SSD avec TRIM effacent souvent ces résidus. Sur HDD, les résidus persistent quasi-éternellement. Anti-forensique : effacement sécurisé (DOD 7-pass, BCWipe) écrase aussi le slack.
Différence entre secteur, cluster, et bloc ?Vocabulaire · Niveau : facile
Secteur = plus petite unité d'écriture/lecture physique du disque. Décidé par le matériel (firmware contrôleur). Tailles : 512 octets (legacy, 1979-2010) ou 4096 octets (Advanced Format / 4Kn, depuis 2010+). Le secteur est indivisible du point de vue I/O. Cluster = unité d'allocation logique du système de fichiers. Toujours un multiple entier de secteurs (1, 2, 4, 8...). Décidé par le système de fichiers à la création. NTFS par défaut = 8 secteurs × 512 = 4096 octets. FAT32 = variable selon taille partition (4 Ko à 32 Ko). C'est l'unité minimale qu'un fichier peut occuper. Bloc = terme générique, ambigu selon le contexte : (a) bloc Linux ext4 = équivalent du cluster NTFS (1, 2 ou 4 Ko), (b) bloc système = parfois utilisé pour désigner un secteur de 512 octets (block device), (c) bloc SSD = unité d'effacement physique du contrôleur NAND (typiquement 256 KB à 4 MB), beaucoup plus grand qu'un cluster du FS — d'où la complexité du wear leveling. Forensiquement : secteur = niveau hardware (dd bs=512), cluster/bloc FS = niveau logique (carving).
🎓 Exam Tip — Technologie des Disques

MBR :

  • 1er secteur du disque (LBA 0) · 512 octets

  • Bootstrap 440 + Disk signature 4 + Partition Table 64 + 55AA

  • Signature 55 AA en little-endian aux offsets 510-511

  • Limite 2.2 To · 4 partitions primaires

GPT :

  • LBA 0 = Protective MBR (0xEE) · LBA 1 = GPT Header · LBA 2-33 = Table

  • Limite 8 ZB · 128 partitions · CRC32 · redondance fin de disque

  • Nécessite UEFI pour booter

Adressage : CHS (legacy C/H/S) vs LBA (séquentiel 0 → N)

Secteur = 512 octets legacy ou 4096 octets Advanced Format (4Kn)

Cluster = unité allocation FS · NTFS 4096 octets · multiple de secteur

Slack space = espace inutilisé dans un cluster · Drive Slack (secteurs non utilisés) contient résidus d'anciens fichiers = mine forensique · RAM Slack (fin du dernier secteur) = zéros sous Windows NT+

HPA (Host Protected Area) : zone cachée fin de disque · hdparm -N

DCO (Device Configuration Overlay) : peut masquer + brider · hdparm --dco-identify

HDD : suppression = clusters marqués libres, données restent → carving facile

SSD + TRIM : effacement physique des blocs supprimés → fenêtre récupération courte

Toujours utiliser un write-blocker avant connexion — y compris pour SSD

Codes types MBR : 0x07 (NTFS), 0x0C (FAT32 LBA), 0x83 (Linux), 0xEE (GPT), 0xEF (EFI)
