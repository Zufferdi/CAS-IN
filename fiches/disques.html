Technologie des disques — Structures physiques
MBR / GPTSecteur 0

HDD — Disque mécanique
  • Plateaux magnétiques + têtes de lecture
  • Rotation : 5400 ou 7200 tr/min
  • Adressage CHS (Cylinder/Head/Sector) → LBA
  • Secteur = 512 octets (standard) ou 4096 (Advanced Format)
SSD — Mémoire flash
  • Pas de partie mécanique — cellules NAND
  • TRIM : efface activement les blocs libérés → données irrécupérables
  • Wear leveling : répartit les écritures → données peuvent migrer // En forensique, une cellule NAND peut contenir des données "fantômes" de plusieurs cycles d'écriture antérieurs — technique de récupération avancée
  • Write blocker moins efficace si TRIM actif
MBR (Master Boot Record)
  • Secteur 0 — 512 octets
  • 440 octets bootstrap code + table partitions (4 primaires max)
  • Signature : 55 AA aux octets 510–511
  • Limite 2,2 To (adressage 32 bits)
GPT (GUID Partition Table)
  • Dépasse la limite 2,2 To du MBR
  • Protective MBR (type 0xEE) en secteur 0
  • Header GPT primary + backup (fin du disque)
  • 128 partitions max
HPA & DCO — Zones cachées
  • HPA (Host Protected Area) : SET MAX ADDRESS — réduit taille visible
  • DCO (Device Configuration Overlay) : masque des features
  • Vérifier systématiquement en forensique
  • Accès via commandes ATA directes
Cluster & Slack Space
  • Cluster = N secteurs (unité minimale d'allocation)
  • File slack : espace entre fin fichier et fin cluster → données résiduelles
  • RAM slack : remplissage jusqu'au prochain secteur
  • Espace non alloué : clusters jamais écrits ou libérés
Représentation des données
Bases numériques

Binaire (base 2) : 0/1. Nibble = 4 bits. Octet = 8 bits.
Hexadécimal (base 16) : 0–9, A–F. 1 octet = 2 digits hex.
Conversions clés : 0xFF=255 · 0xE5=229 · 0x4D5A=MZ (PE)

Endianness (boutisme)

Little Endian (Intel/Windows/FAT/NTFS) : octet poids faible en premier.
0x1234 stocké → 34 12
Big Endian (réseau/HFS+) : poids fort en premier.
PIÈGE : HFS+ = Big Endian ≠ Windows

Encodages texte

ASCII : 7 bits, 127 caractères. A=65=0x41, a=97=0x61
UTF-8 : 1–4 octets/char. Rétro-compatible ASCII.
UTF-16 : 2 octets/char. Utilisé dans LFN (FAT) et NTFS.
EBCDIC (IBM) : rare, héritage mainframe.

Entiers signés (complément à 2)

Bit 7 = bit de signe. 0xFF = −1 (signé) ou 255 (non signé).
Négatif hex → soustraction : 0xE2C8 : 0x10000 − 0xE2C8 = 0x1D38 = −7480
Règle : si MSB ≥ 0x80 → valeur négative

Nibble = 4 bits (1 digit hex). Octet = 8 bits = 2 nibbles = 1 byte.
WORD = 2 octets (16 bits) · DWORD = 4 octets (32 bits) · QWORD = 8 octets (64 bits)
Timestamps NTFS = 100 ns depuis 01.01.1601 · Timestamps Unix = secondes depuis 01.01.1970
💡 Tip forensique : Toujours noter l'endianness avant de lire une valeur. Sur Windows/x86 : tout est Little Endian (FAT, NTFS, exFAT). Sur les protocoles réseau IP/TCP : Big Endian. Sur HFS+ : Big Endian. La confusion endianness est l'erreur la plus fréquente en lecture manuelle d'un dump hexadécimal.
