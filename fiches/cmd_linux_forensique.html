CMD Linux — Live Response Forensique

Détection de compromission · Méthodologie inspirée du cheat sheet SANS Ed Skoudis
🎯 À quoi sert cette fiche ? Un système Linux semble compromis — comment l'auditer en live, sans tout casser, pour confirmer ou écarter l'hypothèse ? Cette fiche fournit la méthodologie en 8 sections (parallèle au cheat sheet Windows) et les commandes exactes à exécuter.
⚠️ Règle d'or : connaître le baseline de la machine (ce qui est normal). Sans baseline, ces commandes produisent du bruit. Sur les systèmes critiques, baseline en amont (Tripwire/AIDE) ; sinon, comparer avec une machine identique ou la doc d'admin.
Prérequis : 📖 Linux Forensique 📖 CMD Windows (parallèle)
Voir aussi : 🔗 Incident Response 🔗 Acquisition RAM 🔗 Logs Windows

⚙️ 1. Processus inhabituels

Énumération complète

# Tous les processus en mode arbre (parent/enfant) $ ps auxf # Vue plus moderne avec uptime + arborescence $ ps -ef --forest # Pour un processus suspect, lister TOUS ses fichiers ouverts $ lsof -p <PID> # Et l'inverse : qui ouvre ce fichier ? $ lsof /etc/passwd # Top live (touches : P=CPU, M=mémoire, k=kill) $ top -c # Plus moderne, interactif $ htop

Indices rouges : processus avec UID 0 (root) inattendus, processus avec un nom court ou aléatoire (x, ./a, kdevtmpfsi), processus parent init (PID 1) suspect (orphelin), CPU 100% inexpliqué (mineur de crypto).

🚨 Processus cachés ou avec fichiers supprimés

# Processus dont le binaire a été supprimé (signe classique de malware) # L'attaquant lance le binaire puis le rm pour effacer ses traces $ lsof +L1 # Output : "(deleted)" en fin de ligne pour les processus piégés # Comparer ps userland vs /proc kernel — un rootkit cache les processus $ ps -ef | wc -l $ ls /proc | grep -E '^[0-9]+$' | wc -l # Les 2 nombres doivent correspondre (à ±1 près pour les commandes elles-mêmes) # Lister les services systemd actifs $ systemctl list-units --type=service --state=running $ systemctl list-unit-files --state=enabled

📁 2. Fichiers inhabituels

Fichiers SUID root (très critiques)

# Tous les binaires SUID root — porte d'entrée vers privilege escalation $ find / -uid 0 -perm -4000 -type f -print 2>/dev/null # Idem mais en cherchant SUID + GUID + sticky $ find / -uid 0 -perm /6000 -type f -print 2>/dev/null

Une liste type sur Debian/Ubuntu : passwd, su, sudo, mount, umount, ping, chsh, chfn, gpasswd, newgrp, pkexec. Tout binaire SUID root en dehors de cette liste est suspect (vérifier avec stat et md5sum).

Fichiers dissimulés et orphelins

# Fichiers sans owner (compte attaquant supprimé après utilisation) $ find / -nouser -o -nogroup -print 2>/dev/null # Fichiers nommés avec espaces et points pour camouflage $ find / -name "..." -print 2>/dev/null $ find / -name ".. " -print 2>/dev/null # point-point-espace $ find / -name ". " -print 2>/dev/null # point-espace $ find / -name " " -print 2>/dev/null # 2 espaces # Gros fichiers (> 100 MB) cachés dans des dossiers temporaires $ find /tmp /var/tmp /dev/shm -type f -size +100M 2>/dev/null # Fichiers récemment modifiés (dernières 24h) $ find /etc /usr/bin /usr/sbin -type f -mtime -1 2>/dev/null # Vérifier intégrité des paquets (Debian/Ubuntu) $ debsums -c # compare hash actuel avec celui du paquet # Vérifier intégrité des paquets (RHEL/Fedora) $ rpm -Va | sort # Lettres-codes : S=size, M=mode, 5=md5, T=mtime, U=user, G=group

Sur RHEL/Fedora, prêter attention spéciale aux changements dans /sbin, /bin, /usr/sbin, /usr/bin — ces dossiers ne devraient JAMAIS être modifiés en dehors d'un yum update.

🌐 3. Réseau inhabituel

Connexions et ports en écoute

# Toutes les connexions actives + ports en écoute + PID + binaire $ ss -tulnp # nouvelle commande, remplace netstat $ netstat -tulnp # si ss indispo # Plus détaillé avec lsof : qui ouvre quoi sur le réseau $ lsof -i $ lsof -i :4444 # qui écoute sur le port 4444 ? $ lsof -i tcp -sTCP:ESTABLISHED # connexions actives uniquement # Connexions sortantes uniquement (exfiltration) $ ss -tn state established '( dport != :22 and dport != :443 )'

Mode promiscuous (sniffer en local)

# Détection sniffer/MITM — interfaces en mode promiscuous # Important : ifconfig n'est PAS fiable sur kernel 2.4+ (bug connu) $ ip link | grep -i PROMISC # Idem avec ip plus moderne $ ip -d link show | grep -i promisc

Note historique : sur les vieux kernels Linux 2.4, ifconfig pouvait reporter PROMISC à tort. Toujours préférer ip link pour la fiabilité.

Cache ARP et résolution

# Cache ARP — IPs ↔ MACs vues récemment $ arp -a $ ip neigh show # équivalent moderne # Spoofing détection : 2 IPs avec le même MAC, ou inverse $ arp -a | sort -k4 | uniq -d -f3

Sur un LAN spécialisé (DMZ, réseau industriel), toute IP non-attendue dans le cache ARP est suspecte.

⏰ 4. Tâches planifiées inhabituelles

Cron — utilisateur et système

# Cron de root (le plus critique) $ crontab -u root -l # Cron de tous les utilisateurs (UID = 0 ou comptes inhabituels) $ for u in $(cut -f1 -d: /etc/passwd); do echo "=== $u ==="; crontab -u $u -l 2>/dev/null; done # Cron systeme global $ cat /etc/crontab $ ls -la /etc/cron.{d,hourly,daily,weekly,monthly}/ # Tâches anacron (machines pas H24) $ cat /etc/anacrontab # Timers systemd (alternative moderne à cron) $ systemctl list-timers --all # At jobs (one-shot) $ atq $ at -c <jobnum> # voir le contenu d'un job

Persistance favorite des attaquants : /etc/cron.d/ avec un nom anodin, un timer systemd custom, ou @reboot dans un crontab utilisateur lambda.

👤 5. Comptes inhabituels

Audit /etc/passwd et /etc/shadow

# Comptes triés par UID (croissant) — cherche UID 0 multiples ou bas $ sort -nk3 -t: /etc/passwd | less # Comptes UID 0 (TOUS doivent être root sauf cas très particuliers) $ egrep ':0+:' /etc/passwd # Sur systèmes avec NSS (LDAP/SSSD), inclure les bases distantes $ getent passwd | egrep ':0+:' # Comptes avec shell de login mais qui ne devraient pas en avoir $ grep -E ':/bin/(bash|sh|zsh)$' /etc/passwd # Comptes avec mot de passe dans /etc/shadow (pas !! ou *) $ awk -F: '($2 != "*" && $2 != "!" && $2 != "!!") {print $1}' /etc/shadow # Dernières connexions (par compte) $ lastlog | grep -v "Never logged in" # Connexions actives $ w $ who -a # Historique tous comptes $ last -a -F | head -50 # Tentatives échouées (Debian/Ubuntu) $ lastb | head -30

Comptes système normaux (UID < 1000) : daemon, bin, sys, sync, www-data, sshd, systemd-*, _apt, nobody... Tout autre compte UID < 1000 mérite vérification. Normaux UID ≥ 1000 : ceux créés par useradd avec mot de passe et home.

Sudo et permissions élevées

# Qui a NOPASSWD (très dangereux si compromis) $ grep NOPASSWD /etc/sudoers /etc/sudoers.d/* # Membres du groupe wheel/sudo (admins) $ getent group sudo wheel admin # Configuration sudoers complète (lecture) $ sudo -l -U <username> # Logs des commandes sudo (qui a fait quoi) $ grep "COMMAND=" /var/log/auth.log | tail -30

📋 6. Logs inhabituels

journald (systemd) — moderne

# Logs depuis le dernier boot $ journalctl -b # Tous les logs avec priorité ≥ erreur depuis 24h $ journalctl -p err --since "24 hours ago" # Échecs sshd (brute force) $ journalctl -u ssh -p err # Logs d'un PID spécifique (si processus suspect identifié) $ journalctl _PID=<pid> # Suivre en temps réel $ journalctl -f

Logs classiques /var/log/

# Authentifications $ grep "Failed password" /var/log/auth.log | wc -l $ grep "Accepted password" /var/log/auth.log | tail -20 $ grep "session opened" /var/log/auth.log # Mode promiscuous logged (sniffer démarré) $ grep -i "promiscuous mode" /var/log/syslog /var/log/messages 2>/dev/null # Erreurs Apache (shellshock, exploits webapp...) $ grep -i "error" /var/log/apache2/error.log | tail -20 $ grep -E '(\.\./|wget|curl|/tmp/)' /var/log/apache2/access.log # Reboots inattendus $ last reboot | head -10 # Logs auditd (si configuré — recommandé pour systèmes critiques) $ ausearch -m EXECVE -ts recent $ ausearch -k authentication -ts recent

Indices à chercher dans les logs : "entered promiscuous mode", >20 caractères bizarres dans une ligne RPC, >100 échecs auth depuis une seule IP, redémarrages inexpliqués, services qui crashent.

📊 7. Performances et indices indirects

# Charge système (uptime + load average) $ uptime # Load > nb de cores = système saturé # Mémoire $ free -h # Si available proche de 0 sans raison apparente = leak ou crypto-miner # Disque (chute soudaine = exfiltration ou logs malveillants) $ df -h $ du -sh /var/log /tmp /var/tmp /home/* 2>/dev/null | sort -h # I/O par processus $ iotop -ao # nécessite root # Trafic réseau par processus $ nethogs eth0 # nécessite root

🎯 Workflow live response Linux (15 minutes)

1. Volatile FIRST
Acquisition RAM (LiME/AVML)
Liste connexions (ss -tulnp)
Snapshot processus (ps auxf)
2. Persistance
crontab -u root -l
systemctl list-units
/etc/cron.d/ inspection
3. Comptes
egrep ':0+:' /etc/passwd
last -a -F | head -50
grep NOPASSWD /etc/sudoers
4. Filesystem
find / -uid 0 -perm -4000
find / -nouser -print
lsof +L1 (deleted)
5. Réseau
ss -tn state established
ip link | grep PROMISC
arp -a (suspects)
6. Logs
journalctl -p err --since 24h
grep "Failed password" auth.log
grep promiscuous syslog
7. Diff baseline
debsums -c (Debian)
rpm -Va | sort (RHEL)
aide --check (si configuré)
🎓 Exam Tip — Méthodologie

DO NOT PANIC (rappel SANS) : si tu trouves un indice de compromission, ne pas couper la machine ni effacer quoi que ce soit. Documenter chaque commande exécutée + son output (timestamp, machine, user). Notifier le team Incident Response, qui décidera de la suite (containment vs investigation).

Volatile First (RFC 3227) : ordre de capture = RAM → connexions réseau → processus → état système → disque. Une fois la machine éteinte, la moitié de la preuve est perdue.

Baseline matters : sur tout système critique, déployer AIDE/Tripwire EN AVANCE pour avoir une référence. Détecter une compromission post-hoc sans baseline est 10× plus difficile.

💊 Auto-évaluation

1. Sur quel kernel ifconfig ne reporte-t-il pas fiablement le mode promiscuous ?

RéponseLinux 2.4+. Toujours préférer ip link | grep PROMISC.

2. Quelle commande liste les processus dont le binaire a été supprimé du disque ?

Réponselsof +L1 (link count = 0). Pattern classique de malware qui s'auto-efface.

3. Comment chercher tous les binaires SUID root ?

Réponsefind / -uid 0 -perm -4000 -type f -print 2>/dev/null

4. Comment détecter des comptes UID 0 multiples (autre que root) ?

Réponseegrep ':0+:' /etc/passwd ou avec NSS : getent passwd | egrep ':0+:'

5. Quel outil hashe les fichiers critiques pour détecter modifications ?

RéponseAIDE ou Tripwire. Doivent être déployés AVANT incident pour avoir une baseline.

6. Où trouver les tâches planifiées globales ?

Réponse/etc/crontab + /etc/cron.{d,hourly,daily,weekly,monthly}/ + timers systemd via systemctl list-timers.
