SQLite Forensique

ℹ️ SQLite est la base de données la plus répandue au monde. Chrome, Firefox, WhatsApp, Telegram, iOS, Android l'utilisent massivement. Un seul fichier = une base complète, portable, souvent récupérable même après suppression.
Bases SQLite forensiquement critiques
🌐 Google Chrome / Chromium
Windows: C:\Users\[user]\AppData\Local\Google\Chrome\User Data\Default\History macOS: ~/Library/Application Support/Google/Chrome/Default/History Linux: ~/.config/google-chrome/Default/History
Tables clés : urls (url, title, visit_count, last_visit_time), visits (timestamps précis), downloads (URL source, chemin local, état), keyword_search_terms (termes recherchés).
SELECT url, title, visit_count, datetime(last_visit_time/1000000-11644473600,'unixepoch') as last_visit FROM urls ORDER BY last_visit_time DESC LIMIT 50;
Historique Téléchargements Recherches Favoris
⚠️ Les timestamps Chrome utilisent l'epoch Windows (microsecondes depuis 01/01/1601). Formule : datetime(ts/1000000-11644473600,'unixepoch')
💬 WhatsApp (Android)
Android: /data/data/com.whatsapp/databases/msgstore.db Backup chiffré: /sdcard/WhatsApp/Databases/msgstore.db.crypt15
Tables clés : messages (key_remote_jid, data = texte du message, timestamp), media_refs (médias partagés), jid (contacts). Le fichier .crypt15 est chiffré avec la clé stockée dans /data/data/com.whatsapp/files/key (accessible root uniquement).
SELECT m.key_remote_jid, m.data, datetime(m.timestamp/1000,'unixepoch') as date, m.media_url FROM messages m WHERE m.data IS NOT NULL ORDER BY m.timestamp DESC LIMIT 100;
🔑 Déchiffrement crypt15 : Cellebrite UFED, WhatsApp Viewer (avec la clé exportée), ou extraction physique root.
🦊 Firefox
Windows: C:\Users\[user]\AppData\Roaming\Mozilla\Firefox\Profiles\[profil]\places.sqlite macOS: ~/Library/Application Support/Firefox/Profiles/[profil]/places.sqlite
Tables clés : moz_places (url, title, visit_count, last_visit_date), moz_historyvisits (timestamps précis + type de visite), moz_bookmarks. Attention : Firefox utilise des microsecondes depuis l'epoch UNIX standard.
SELECT p.url, p.title, datetime(v.visit_date/1000000,'unixepoch') as visited FROM moz_historyvisits v JOIN moz_places p ON v.place_id=p.id ORDER BY v.visit_date DESC LIMIT 50;
📱 iOS — Points d'intérêt
SMS: /var/mobile/Library/SMS/sms.db (table: message) Contacts: /var/mobile/Library/AddressBook/AddressBook.sqlitedb Appels: /var/mobile/Library/CallHistoryDB/CallHistory.storedata
Accessible via extraction logique (iTunes backup non chiffré) ou physique (Cellebrite, UFED). Les backups iTunes chiffrés contiennent plus de données mais nécessitent le mot de passe.
SELECT datetime(date+978307200,'unixepoch') as date_msg, text, is_from_me FROM message ORDER BY date DESC LIMIT 50;
⚠️ iOS utilise l'epoch Mac (01/01/2001 = 978307200 secondes UNIX). Formule : datetime(ts+978307200,'unixepoch')
✈️ Telegram (Desktop)
Windows: C:\Users\[user]\AppData\Roaming\Telegram Desktop\tdata\
Telegram Desktop utilise un format propriétaire (pas SQLite pur). Les messages sont dans des fichiers binaires du dossier tdata. Outils : TelegramDesktop-Dumper. Sur Android : SQLite accessible root, table messages.
Récupération de données supprimées
🔍 SQLite : pages non réallouées

SQLite marque les pages supprimées comme libres (freelist) mais ne les efface pas. Les données restent jusqu'à un VACUUM ou réallocation. Outils : sqlite3 avec PRAGMA freelist_count, ou SQLite Deleted Records Recoverer, ou Autopsy SQLite module.

-- Voir le nombre de pages libres (données supprimées potentielles) PRAGMA freelist_count; -- Forcer un VACUUM pour effacer (action à NE PAS faire en forensique) -- VACUUM;

Conversions d'epochs — Aide-mémoire
SQLITE
UNIX epoch (standard) : datetime(ts, 'unixepoch')
Chrome (µs depuis 1601) : datetime(ts/1000000 - 11644473600, 'unixepoch')
iOS/macOS (s depuis 2001): datetime(ts + 978307200, 'unixepoch')
Firefox (µs depuis 1970) : datetime(ts/1000000, 'unixepoch')
WhatsApp (ms depuis 1970): datetime(ts/1000, 'unixepoch')
