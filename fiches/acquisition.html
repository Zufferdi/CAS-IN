Acquisition et préservation
⚠ L'original ne doit JAMAIS être modifié. Write blocker physique obligatoire. Hash SHA-256 calculé sur l'original ET sur chaque copie. Toute divergence de hash = preuve inadmissible.
Ordre de volatilité (RFC 3227)
  1. RAM (registres, cache CPU)
  2. Connexions réseau actives
  3. Processus en cours
  4. Disque dur / SSD
  5. Logs distants
  6. Données archivées

Capturer du plus volatil au plus stable.

Live vs Dead Forensics

Dead Box : éteindre → acquisition statique. Pas d'altération. Perd RAM et clés de chiffrement.

Live Forensics : système allumé → capture RAM puis disque. Obligatoire si chiffrement actif (BitLocker/LUKS/FileVault).

Outils RAM : WinPmem, DumpIt (Windows) · LiME (Linux module)

Formats d'image forensique
  • DD/RAW : copie bit-à-bit brute. Simple, universelle. Pas de métadonnées.
  • E01/EWF (EnCase) : compression + métadonnées + hash intégré. Standard judiciaire.
  • AFF (Garfinkel) : format ouvert, segmentable (.aff/.afd/.afm). Supporté X-Ways nativement.
  • AFF4 : successeur moderne, meilleure compression.
Outils d'acquisition
  • dd (Linux) : dd if=/dev/sda of=img.dd bs=4M conv=noerror,sync
  • Guymager : GUI Linux, AFF/E01/DD avec hash automatique
  • FTK Imager : Windows GUI, E01, preview sans modifier
  • OSFClone : sans écran, copie de disque autonome
  • Write blockers : Tableau T35689iu, WiebeTech

Artefacts temporels et MAC times
Timestomping — Détection

NTFS maintient deux jeux de timestamps :

  • $STANDARD_INFORMATION : modifiable par les programmes (TimeStomp, Metasploit)
  • $FILE_NAME : modifiable uniquement par le noyau Windows

Divergence $SI vs $FN = timestomping probable.

MFTECmd exporte les deux colonnes. Comparer systématiquement.

Précisions par système de fichiers
  • NTFS : 100 nanosecondes depuis 01.01.1601. 4 timestamps MACE.
  • FAT : 2 secondes (dernière modif) / 10 ms (création, selon implémentation)
  • exFAT : 10 ms + UtcOffset (timezone explicite)
  • EXT : secondes Unix depuis 01.01.1970 (EXT4 : nanosecondes)
  • HFS+ : secondes depuis 01.01.1904 (Mac Epoch)
Copie Windows : met à jour Btime (création) mais PAS Mtime. Un fichier "créé" après sa "modification" = probablement copié.
Super-timeline : log2timeline/Plaso fusionne toutes les sources. Outil : log2timeline.py timeline.plaso image.E01
Méthodologie forensique (5 phases)
1
Identification : cartographier la scène numérique. Quels équipements, lesquels sont allumés, profil technique de la cible (chiffrement probable ?). Matériel prêt avant d'entrer.
2
Collecte : saisie physique selon procédures légales (mandat). Isolation réseau (Faraday bag pour téléphones). Documentation photographique. Début de la chain of custody.
3
Acquisition : write blocker + image forensique (E01/DD) + hash SHA-256 original ET copie. Dump RAM si chiffrement actif. Original mis sous scellés.
4
Analyse : examen des copies uniquement. Reconstruction timeline, fichiers supprimés, artefacts, corrélations. Outils : X-Ways, Autopsy, Volatility, Plaso.
5
Interprétation & Rapport : distinguer faits / interprétations / opinions. Rédaction avec niveau de certitude. L'expert ne prononce jamais la culpabilité.
