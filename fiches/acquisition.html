Image forensique vs Clone
Image forensique — Méthode standard

Copie de tout le contenu (secteurs, espaces vides, fichiers supprimés) dans un fichier conteneur sur un autre support. Inclut métadonnées, hash intégré, compression possible.

Ne peut pas démarrer — nécessite un outil forensique pour l'ouvrir. Immuable : l'analyste travaille sur des copies de l'image.

Formats : DD, E01, AFF, EWF2

Clone — Copie physique exacte

Copie bit-à-bit sur un disque physique de même capacité (ou supérieure). Peut démarrer comme l'original.

Problème : les disques "1 To" de marques différentes n'ont pas exactement le même nombre de secteurs. Travailler sur un clone risque de l'altérer.

Réservé aux cas où le démarrage du système est nécessaire.

Write Blocker — Outil n°1 de l'intervenant
Fonctionnement

Dispositif matériel interposé entre le disque suspect et l'ordinateur de l'analyste. Laisse passer tous les ordres de lecture, bloque physiquement tout ordre d'écriture.

Pourquoi matériel et pas logiciel ? Le write blocker logiciel peut être contourné par le système d'exploitation (ex. Windows qui met à jour une date d'accès).

Sans write blocker

Le système d'exploitation de l'analyste peut modifier les données du disque suspect :
• Mise à jour de la date d'accès
• Création de fichiers cachés
• Mise à jour d'un index
• Écriture dans le swap

Ces modifications invalident la preuve (art. 141 CPP).

Slicing FAT32 — Limite des 4 Go
Problème : FAT32 limite la taille d'un fichier à 4 Go − 1 byte. Une image disque d'un ordinateur moderne fait souvent plusieurs centaines de Go. Si le disque de destination est formaté en FAT32 → l'image doit être découpée.
