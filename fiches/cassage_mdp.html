🛠 Les deux outils de référence
Passware Kit Forensic (commercial, GUI) et Hashcat (open source, CLI) sont les deux outils de référence pour le cassage légal. Ils sont complémentaires : Passware excelle sur les conteneurs chiffrés (BitLocker, VeraCrypt, Office, archives), Hashcat sur les hashes extraits (NTLM, SHA, bcrypt, WPA). Une investigation sérieuse les utilise ensemble.

⚔️ Stratégie d'attaque par ordre de priorité
L'ordre des attaques n'est jamais aléatoire. On commence toujours par ce qui a le plus de chances de réussir rapidement : dictionnaire, puis on augmente la complexité (règles, masque, hybride) et seulement en dernier recours la force brute. Un mot de passe à 8 caractères ASCII complets demande ~100 000 ans à un GPU moderne en brute force — autant dire : à éviter.

⚡ Hashcat — modes & masque interactif
Hashcat utilise deux types de paramètres critiques : -a (mode d'attaque : dictionnaire, masque, hybride) et -m (type de hash : NTLM, SHA-512, bcrypt, BitLocker…). Maîtriser ces codes est essentiel car une mauvaise combinaison -m empêche le cassage même avec le bon dictionnaire.

Commandes Hashcat — exemples forensiques
# 1. Extraire les hashes NTLM depuis SAM + SYSTEM (impacket)
impacket-secretsdump -sam SAM -system SYSTEM LOCAL

# 2. Attaque dictionnaire sur hashes NTLM
hashcat -a 0 -m 1000 ntlm_hashes.txt rockyou.txt

# 3. Dictionnaire + règles (plus efficace)
hashcat -a 0 -m 1000 ntlm_hashes.txt rockyou.txt -r best64.rule

# 4. Masque ciblé — MDP type Mot123 (?u?l?l?d?d?d)
hashcat -a 3 -m 1000 hash.txt ?u?l?l?d?d?d

# 5. VeraCrypt AES — dictionnaire
hashcat -a 0 -m 13711 vc_header.bin rockyou.txt

# 6. Afficher progression + ETA
hashcat --status --status-timer 10 -a 0 -m 22600 bitlocker.hash words.txt

Fonctions clés de Passware
🧠 Analyse mémoire (RAM)

Fonctionnalité unique de Passware : analyser une image RAM pour en extraire directement la FVEK (Full Volume Encryption Key) de BitLocker ou VeraCrypt si le volume était monté.

Outils RAM compatibles : Volatility, WinPMem, Magnet RAM Capture.
Formats : .raw, .mem, .dmp, .vmem (VMware)

⚙️ Options d'attaque
  • Dictionnaire — listes intégrées + importation
  • Brute-force — charset et longueur configurables
  • Masque — pattern avec jokers
  • Xieve — intelligence artificielle de patterns
  • Previous passwords — réutilisation de MDP connus
  • GPU acceleration — CUDA (NVIDIA)
💡 Workflow Passware recommandé : (1) Extraction RAM si disponible → (2) Dictionnaire rockyou + dicts natifs → (3) Masque avec informations sur la cible → (4) Brute-force seulement si MDP court (≤ 6 car.)
BitLocker — processus de récupération
1
Chercher la clé de récupération — Compte Microsoft, Active Directory, Entra ID, fichier .BEK sur USB, fichier imprimé. Souvent la solution la plus rapide.
2
Analyser une image RAM — Si le système était actif lors de la saisie, la FVEK peut être en mémoire. Passware → Analyze Encrypted Disk → sélectionner le dump RAM.
3
Attaque sur le hash BitLocker — Extraire le header avec bitlocker2john ou Passware, puis attaquer avec Hashcat -m 22600.
4
TPM seul ? — Si le volume ne demande pas de MDP (TPM transparent), le déchiffrement peut être possible en montant le disque sur la machine d'origine, ou via TPM sniffing matériel (analyseur logique ~$10 sur bus LPC/SPI).
🎯 Stratégie globale d'investigation
Le cassage de mot de passe n'est pas une simple question technique : c'est une chaîne de décisions ordonnées, documentée pour recevabilité devant un tribunal. Chaque tentative infructueuse oriente la suivante. Et tout doit être fait dans le strict respect du CPP (Code de procédure pénale suisse).

Les 6 étapes méthodologiques
1
Inventaire des artefacts chiffrés
Identifier tous les fichiers/volumes chiffrés via X-Ways (attribut e!A), Axiom (section Chiffrement), entropie élevée (≥ 0.95). Lister les algorithmes détectés.
X-Ways → Rapport → Fichiers chiffrés confirmés
2
Chercher les indices de mot de passe
Fichiers texte, sticky notes, navigateur (MDP sauvegardés), boîte mail (compte Microsoft, clé de récupération), Active Directory, registre Windows (HKCU\Software).
X-Ways → Recherche texte « password » « mdp » « pass » « bitlocker »
3
Analyse de la mémoire RAM
Si disponible : analyser le dump RAM avec Passware (FVEK) ou Volatility. Priorité absolue si le système était en cours d'exécution lors de la saisie.
Passware → Memory Imager / Analyze RAM · Volatility bitlocker plugin
4
Attaque dictionnaire + règles
Lancer Hashcat avec rockyou.txt + best64.rule. Paralléliser avec Passware sur les fichiers Office/archives. Durée typique : 1–24h selon GPU.
hashcat -a 0 -m [type] hashes.txt rockyou.txt -r best64.rule
5
Profiler la cible pour masque ciblé
Analyser les autres MDP connus du suspect (SAM, navigateur), identifier des patterns (prénom+date, ville+chiffres). Construire un masque sur mesure.
hashcat -a 3 -m [type] hashes.txt ?u[prénom]?d?d?d?d
6
Documenter et rapporter
Chaque tentative doit être documentée (outil, version, durée, résultat). Le mot de passe trouvé est une preuve : noter les conditions exactes de récupération.
Rapport forensique : méthode + hash avant/après + timestamp

⚖️ Aspects juridiques — CPP & Droit suisse
Art. 265 CPP — Obligation de remise : le prévenu peut être contraint de remettre les mots de passe sur ordonnance du Ministère public. Refus = possible sanction.

Art. 113 CPP — Nemo tenetur : le prévenu n'est pas tenu de contribuer à sa propre incrimination. Le cassage forensique contourne ce principe légalement.

Art. 246–248 CPP — Perquisition informatique : le cassage de mot de passe est une mesure de contrainte nécessitant une autorisation judiciaire si hors flagrant délit.

LRens / LSCPT — Accès aux données chiffrées par les services de renseignement : procédure séparée du CPP.

Rapport forensique — Documenter : autorisation légale obtenue, méthode utilisée, temps écoulé, résultat, chaîne de possession du hash et du MDP trouvé.
🎓 Exam Tip — Cassage MDP

Ordre d'attaque : dictionnaire → règles → masque → hybride → brute-force (jamais 1er)

Jokers Hashcat : ?l=26 · ?u=26 · ?d=10 · ?s=32 · ?a=95

Modes -a : 0=dict · 3=masque · 6=hybride dict+masque · 7=hybride masque+dict

Modes -m clés : 1000=NTLM · 1800=SHA-512 · 13711=VeraCrypt · 22600=BitLocker · 13400=KeePass · 9400=Office 2007

Passware unique : extraction FVEK depuis dump RAM (BitLocker/VeraCrypt)

CPP : art. 265 obligation remise · art. 113 nemo tenetur · art. 246–248 perquisition

Un suspect a un volume VeraCrypt de 20 Go, entropie 0.998. Le PC a été saisi éteint. Quelle est la meilleure stratégie en premier ?Stratégie · Niveau : moyen
Chercher les indices de MDP dans l'environnement (poste du suspect, papiers, téléphone, autres fichiers non chiffrés du même suspect). Si le PC était éteint, pas de RAM dump possible → pas d'extraction de FVEK. Ordre : (1) indices MDP → (2) dictionnaire + règles → (3) masque ciblé si patterns connus. La force brute sur VeraCrypt AES avec PBKDF2 est pratiquement irréalisable (100K itérations → des années même avec GPU). Documenter chaque tentative pour le rapport.
Hashcat affiche -m 13711. Vous voulez casser un header BitLocker. Cela va-t-il fonctionner ?Modes Hashcat · Niveau : facile
Non. -m 13711 correspond à VeraCrypt AES, pas BitLocker. Pour BitLocker, utilisez -m 22600. Une mauvaise combinaison de -m empêche systématiquement le cassage même avec le bon dictionnaire et la bonne commande. Autres modes courants : -m 1000 NTLM · -m 1800 SHA-512 Linux · -m 9400 Office 2007 · -m 13400 KeePass.
