🔬 Autopsy — La plateforme forensique open source de référence
Autopsy, développé par Brian Carrier au sein de Sleuth Kit Labs (entité issue de Basis Technology depuis octobre 2023), est la plateforme forensique open source la plus utilisée au monde. Construit autour de The Sleuth Kit (TSK), Autopsy fournit une interface graphique unifiée pour analyser images disque (E01, AFF4, RAW), explorer systèmes de fichiers, extraire artefacts, faire de la timeline, du keyword search, et plus encore. Son architecture modulaire (Ingest Modules) permet d'enchaîner automatiquement des dizaines d'analyses : hash lookup, EXIF, registre Windows, navigateurs, emails, keyword search… 100% gratuit, multi-plateforme (Windows / macOS / Linux), supporte le mode multi-utilisateurs avec PostgreSQL pour les enquêtes en équipe. C'est l'alternative gratuite à FTK / EnCase / X-Ways.

Qu'est-ce qu'Autopsy ?
Autopsy — Interface graphique de TSK

Autopsy est la GUI officielle de The Sleuth Kit (TSK), le framework forensique open source maintenu par Sleuth Kit Labs (anciennement Basis Technology). Disponible sur Windows, macOS, Linux. Gratuit et open source (licences CPAL et Apache 2.0).


Analyse : images disque (E01, VMDK, RAW, AFF, L01), dossiers de fichiers, et disques physiques directement.


Version courante : Autopsy 4.x · Java-based · Plugin system

The Sleuth Kit (TSK) — Le moteur

TSK est la bibliothèque C sous-jacente qui fait le vrai travail. Autopsy ne fait qu'exposer TSK via une interface web locale.


TSK supporte : FAT12/16/32, exFAT, NTFS, EXT2/3/4, HFS+, APFS, ISO9660, UFS. Il expose des outils CLI indépendants (fls, icat, istat, blkcat…).


Cas d'usage typique CAS-IN : analyse de clés USB, disques Linux, images Android/iOS.

Architecture d'un cas Autopsy
1
Créer un cas (Case)
Chaque investigation = un cas distinct. Le cas contient les métadonnées de l'enquête (numéro, investigateur, organisation) et agrège toutes les sources de données. Un cas peut contenir plusieurs images disque.
Dossier de cas : C:\Cases\enquete_2025\ → contient le DB SQLite central (autopsy.db)
2
Ajouter une source de données (Data Source)
Ajouter l'image forensique (E01, DD, AFF) ou un dossier. Autopsy calcule le hash MD5 + SHA-256 automatiquement et les compare avec ceux du rapport d'acquisition.
Formats supportés : E01/Ex01, L01, AFF, VMDK, VHD, DD/RAW, ISO, dossier local
3
Sélectionner et lancer les modules d'ingest
Les modules s'exécutent en arrière-plan et peuplent la base SQLite. On peut continuer l'analyse manuelle pendant l'ingest. L'ordre d'exécution est géré automatiquement.
Durée : de 10 min (clé USB 16 Go) à plusieurs heures (disque 1 To avec tous les modules)
4
Analyse dans l'arborescence
Le panneau de gauche organise les résultats par catégorie (Images, Documents, Emails, Artefacts OS…). Chaque item peut être marqué, tagué, et ajouté au rapport.
Tags disponibles : Notable Item · Follow Up · TBD · ou custom
5
Générer le rapport
Rapport HTML, Excel, ou XML incluant automatiquement les items tagués, les hashs, les métadonnées du cas. Exportable pour le dossier judiciaire.
Generate Report → HTML Report → sélectionner les tags → inclure les artefacts
Structure interne — Base de données SQLite
Autopsy stocke tous ses résultats dans une base SQLite (autopsy.db). Chaque artifact = une ligne dans une table. Cela permet des requêtes SQL directes pour des analyses avancées que l'interface ne propose pas.
# Interroger la DB Autopsy directement
sqlite3 autopsy.db

# Lister tous les artefacts d'une image
SELECT artifact_type_name, COUNT(*) FROM blackboard_artifacts GROUP BY artifact_type_name;

# Récupérer les URLs visitées
SELECT value_text FROM blackboard_attributes WHERE attribute_type_id=1 LIMIT 100;

# Fichiers supprimés dans l'image
SELECT name, size, md5, parent_path FROM tsk_files WHERE dir_flags=2 ORDER BY crtime DESC;
Modules d'ingest — Référence complète
Hash Lookup
Compare chaque fichier avec des bases de hash connues : NSRL (fichiers OS légitimes), hashsets personnalisés. Filtre les fichiers système pour concentrer l'analyse sur les fichiers utilisateur. Peut aussi signaler des fichiers illicites connus (Project VIC, PhotoDNA).
→ Activer en premier. Élimine jusqu'à 70% des fichiers sur un disque Windows standard.
File Type Identification
Identifie les fichiers par leurs magic bytes (pas leur extension). Détecte les fichiers avec extension falsifiée (Type Mismatch) — équivalent du "Type Status" X-Ways.
→ Base : Apache Tika + bibliothèque de signatures TSK. Signale les incohérences extension/signature.
Embedded File Extractor
Extrait automatiquement le contenu des archives (ZIP, RAR, 7z), des emails (PST, MBOX), des documents Office et PDF. Analyse les contenus imbriqués récursivement.
→ Essentiel pour les emails forensiques. Extrait les pièces jointes et les intègre dans la timeline.
EXIF Parser
Extrait les métadonnées EXIF de toutes les images (JPEG, PNG, TIFF). Affiche les coordonnées GPS sur une carte interactive. Croise les timestamps photos avec la timeline.
→ GPS trouvé → vue carte intégrée. DateTimeOriginal vs timestamp FS = tentative de manipulation.
Keyword Search
Recherche plein texte indexée sur tout le contenu (fichiers, metadata, slack space). Supporte les expressions régulières, les listes de mots-clés prédéfinies (emails, IPs, numéros de carte, SSN…).
→ Lancer en dernier (long). Préconfigurer les listes : numéros suisses, IBAN CH, termes spécifiques.
Recent Activity
Extrait automatiquement : historique Chrome/Firefox/Edge/Safari, cookies, logins sauvegardés, téléchargements, applications récentes, documents récents, prefetch Windows.
→ Couvre les artefacts de navigation web et d'activité utilisateur en un seul module.
Windows Registry
Parse automatiquement les ruches Windows (SAM, SYSTEM, SOFTWARE, NTUSER.DAT, USRCLASS.DAT). Extrait : comptes, USB connectés (USBSTOR), programmes au démarrage, UserAssist, ShellBags, réseaux WiFi.
→ Équivalent de RegRipper intégré. Résultats dans OS Accounts + USB Devices + Data Artifacts.
Timeline Analysis
Construit une timeline chronologique de tous les événements FS (MAC times), artefacts OS et web. Visualisation graphique avec filtres par type d'événement et plage de dates.
→ Exporter en CSV pour import dans Excel ou Timesketch pour analyse collaborative.
Android Analyzer
Module spécialisé pour les images Android : contacts, SMS, MMS, appels, apps installées, comptes Google, données Snapchat/WhatsApp (si non chiffrées), fichiers multimédias.
→ Nécessite une image physique ou un backup Android complet (ADB avec root).
Interesting Files
Détecte des fichiers d'intérêt forensique prédéfinis : fichiers de configuration, bases de données connues (SQLite WhatsApp, Chrome), fichiers de cryptomonnais, wallets Bitcoin.
→ Configurable avec des règles personnalisées basées sur nom, chemin ou contenu.
Email Parser
Extrait et indexe les emails des formats PST (Outlook), MBOX (Thunderbird), EML, MSG. Crée une vue navigable par expéditeur/destinataire/date avec pièces jointes extraites.
→ Alternative légère à un outil dédié comme Aid4Mail pour les cas simples.
Encryption Detection
Calcule l'entropie de chaque fichier pour détecter le chiffrement ou la compression forte (entropie ≥ 0.95). Identifie aussi les conteneurs VeraCrypt et BitLocker par leurs signatures.
→ Entropie = 1.0 → chiffré. Faux positifs possibles sur les vidéos H.265 très compressées.
Workflow forensique Autopsy — Cas pratique
Configuration recommandée (CAS-IN)
  • Modules à activer en priorité : Hash Lookup + File Type + Recent Activity + Windows Registry + EXIF
  • Ajouter le NSRL (HashSet) pour filtrer les fichiers système
  • Keyword search : configurer avant l'ingest avec les listes adaptées
  • Ne pas activer PhotoRec carving si disque > 500 Go (très lent)
  • Travailler sur une copie de l'image — jamais sur l'original
Navigation efficace dans Autopsy
  • Panneau gauche → catégories : commencer par Results → Extracted Content
  • Vue Thumbnail pour parcourir rapidement les images
  • Filtre par type MIME pour isoler les vidéos, ZIP, etc.
  • Tag → "Notable Item" les éléments à inclure dans le rapport
  • Timeline : filtrer par plage de dates autour de l'incident suspecté
  • Communications : graphe des échanges email (visualisation réseau)

The Sleuth Kit — Commandes CLI essentielles
Commandes de navigation FS

Toutes les commandes TSK travaillent sur des images disque (DD, E01…) ou des devices physiques.

Identifier les partitions

mmls image.dd → liste les partitions et leurs offsets secteur. Nécessaire pour spécifier la partition cible avec -o [offset].

# Lister les partitions d'une image
mmls image.dd
# → Donne l'offset de chaque partition en secteurs

# Lister TOUS les fichiers (existants + supprimés) d'une partition
fls -r -o 2048 image.dd
# -r = récursif · -o 2048 = offset de la partition en secteurs
# Fichiers supprimés = ligne commençant par * (astérisque)

# Lister les fichiers supprimés uniquement
fls -d -r -o 2048 image.dd

# Voir les détails d'un inode
istat -o 2048 image.dd 42
# Affiche timestamps (atime/mtime/ctime/crtime), blocs, taille

# Extraire le contenu d'un inode vers stdout
icat -o 2048 image.dd 42 > fichier_récupéré.doc

# Afficher le contenu brut d'un bloc/cluster
blkcat -o 2048 image.dd 1024 | xxd | head -30

# Générer une timeline MAC times (format mactime)
fls -m "/" -r -o 2048 image.dd > fls_output.txt
mactime -b fls_output.txt -d -z UTC > timeline.csv

# Informations sur le système de fichiers (superbloc)
fsstat -o 2048 image.dd

# Carving PhotoRec (intégré dans testdisk)
photorec image.dd
Récupération de fichiers supprimés — Méthode TSK
EXT2 — Récupération directe

Pointeurs de blocs conservés après suppression. fls -d liste les inodes supprimés → icat extrait le contenu directement depuis les blocs.

EXT3/4 — Via journal

Block pointer zeroing → icat ne fonctionne plus. Utiliser ext4magic qui exploite le journal pour retrouver les anciens pointeurs avant suppression.

FAT32 — Via entrée SFN

Entrée 0xE5 → cluster de départ encore présent (offset 0x1A). icat utilise ce cluster pour extraire si les données n'ont pas été réallouées.

NTFS — Via MFT résiduelle

L'entrée MFT reste avec le bit occupé mis à 0 mais les attributs intacts. fls -d liste les fichiers supprimés encore dans la MFT.

Utiliser X-Ways quand…
  • Rapport judiciaire pour le tribunal fédéral ou cantonal
  • Analyse bas-niveau : runlist, slack space, HPA, DCO
  • Disques très fragmentés ou cas NTFS complexes
  • Haute performance requise (1 To+ en quelques heures)
  • La preuve sera contre-expertisée par un expert adverse
Utiliser Autopsy quand…
  • Budget limité ou formation initiale
  • Analyse Android / mobile forensics
  • Rapport automatique nécessaire rapidement
  • Analyse en équipe (cas multi-utilisateurs)
  • Analyse Linux/EXT ou macOS HFS+/APFS
  • Investigation préliminaire avant décision de saisie
🧠 Testez-vous
Vous lancez Autopsy sur une image de 500 GB. Tous les modules d'ingest sont activés. Combien de temps prévoir ?Performance · Niveau : facile
Plusieurs heures à plusieurs jours, selon la machine. Sur un PC moderne (i7, 16 Go RAM, SSD), comptez environ 4-8h pour 500 GB avec tous les modules. Phases bloquantes : (1) Hash Lookup sur tous les fichiers (NSRL = 200M+ hashes), (2) Keyword Search qui indexe TOUT le contenu via Solr (peut doubler le temps), (3) EXIF / Picture Analyzer sur des milliers d'images. Optimisation : lancer un premier ingest léger avec seulement Hash Lookup + File Type ID + Recent Activity (1-2h), regarder ce qui ressort, puis cibler des Keyword Search spécifiques sur la zone d'intérêt.
Vous voulez exporter tous les fichiers tagués "interesting" pour les soumettre à un autre expert. Comment ?Export · Niveau : facile
Dans Autopsy : (1) menu Tools → Generate Report, (2) sélectionner le format HTML (interactif) ou Excel (CSV pour traitement), (3) cocher Tagged Items pour ne reporter que les fichiers tagués, (4) le rapport contient les hash SHA-256 de chaque fichier, l'offset, le chemin source, et les tags. Pour exporter les fichiers eux-mêmes : clic-droit → Extract File(s) vers un dossier. Ne pas oublier de calculer un hash SHA-256 du dossier exporté (un fichier hashes.txt) avant transmission, et utiliser un support chiffré (LUKS / VeraCrypt).
Quelle est la différence entre Autopsy et The Sleuth Kit (TSK) ?Architecture · Niveau : moyen
The Sleuth Kit (TSK) est une collection d'outils en ligne de commande écrite par Brian Carrier : fls, istat, icat, mmls, fsstat, mactime, etc. Ces outils analysent les systèmes de fichiers à bas niveau. Autopsy est l'interface graphique unifiée qui orchestre TSK + d'autres modules (parsers de navigateurs, EXIF, hash lookup, keyword search Solr, etc.) dans un workflow cohérent. Analogie : TSK = moteur, Autopsy = voiture autour. Tu peux utiliser TSK sans Autopsy (scripts en CLI), et tu peux développer des Ingest Modules Python ou Java pour étendre Autopsy. Tous deux sont open source et maintenus par Basis Technology / Brian Carrier.
