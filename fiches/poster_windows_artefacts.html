Poster Windows Artefacts

Inspiré du poster officiel SANS FOR500 (Rob Lee) — organisé par question forensique

🎯 À quoi sert cette fiche ? Quand tu enquêtes sur un système Windows, tu te poses des questions précises (« quel programme a été exécuté ? » / « quel fichier a été supprimé ? » / « quel USB a été branché ? »). Cette fiche est ta grille d'entrée : pour chaque question, tu vois les artéfacts pertinents et tu cliques sur la fiche détaillée.
💡 Comment l'utiliser : (1) identifie ta question forensique, (2) repère la section correspondante ci-dessous, (3) examine chaque artéfact de cette section sur ta cible — un seul ne suffit jamais en forensique, on cumule pour avoir la timeline la plus précise possible.

⚡ 1. Program Execution — quel programme a été exécuté ?

Pour répondre à : « Tel exécutable a-t-il tourné sur cette machine ? Quand ? Combien de fois ? »
UserAssist
Programmes lancés depuis la GUI (Explorer, raccourcis bureau). Compte d'exécutions, dernière exécution. Encodé ROT-13.
NTUSER.DAT\Software\Microsoft\Windows\CurrentVersion\Explorer\UserAssist\{GUID}\Count
Shimcache (AppCompatCache)
Tracking compatibilité d'apps. Présence ≠ exécution garantie sur Win10 (assoupli). Win7: 1024 entrées max, dernière exécution = LastUpdateTime.
SYSTEM\CurrentControlSet\Control\Session Manager\AppCompatCache
Amcache.hve
Service ProgramDataUpdater. Chemin complet, SHA-1, taille, $StandardInfo Last Modification. Première exécution = Last Modification de la clé.
C:\Windows\AppCompat\Programs\Amcache.hve
BAM/DAM
Background Activity Moderator (Win10+). Chemin complet de l'exécutable + dernière exécution par SID utilisateur. Très fiable en forensique.
SYSTEM\CurrentControlSet\Services\bam\UserSettings\{SID}
SRUM
System Resource Usage Monitor. 30-60 jours d'historique. Apps lancées, comptes responsables, bytes envoyés/reçus par app par heure. Outil : srum_dump.exe.
C:\Windows\System32\SRU\SRUDB.dat
Jump Lists
Premier lancement = creation time du fichier AppID. Dernier lancement = modification time. Liste IDs : dfir.to/EZJumpList.
%USERPROFILE%\AppData\Roaming\Microsoft\Windows\Recent\AutomaticDestinations
Prefetch (.pf)
Win8/10 : 8 dernières exécutions embarquées. Win7 max 128 fichiers, Win8+ max 1024. Format (exename)-(hash).pf.
C:\Windows\Prefetch
Win10 Timeline
Apps + fichiers récents accessibles via WIN+TAB. Base SQLite. Focus count par app. Désactivé par défaut sur Win11.
%LOCALAPPDATA%\ConnectedDevicesPlatform\{folder}\ActivitiesCache.db
📖 Fiches détaillées : Amcache · Prefetch · Outils Zimmerman · Windows Forensique · Registre Windows

📂 2. File / Folder Opening — quel fichier ou dossier a été ouvert ?

Pour répondre à : « Tel fichier a-t-il été ouvert ? Quel programme l'a ouvert ? Depuis quel dossier ? »
Open/Save MRU
Fichiers ouverts/sauvegardés via la boîte de dialogue Windows. Subkey * = tous types, .??? = par extension.
NTUSER.DAT\...\Explorer\ComDlg32\OpenSavePIDlMRU
RecentDocs
150 derniers fichiers/dossiers ouverts (toutes apps). Organisé par extension. MRU list = ordre temporel.
NTUSER.DAT\...\Explorer\RecentDocs
LNK Files (.lnk)
Raccourcis auto-créés par Windows. Contient : MAC times du fichier cible, volume info (nom/type/serial), nom de la machine, share réseau.
%USERPROFILE%\AppData\Roaming\Microsoft\Windows\Recent\
Office Recent Files
Tracking par version Office. 14.0=2010, 15.0=365. Per-app : Word, Excel, PowerPoint, Access.
NTUSER.DAT\Software\Microsoft\Office\<Ver>\UserMRU\LiveID_*\FileMRU
ShellBags
Dossiers parcourus via Explorer. Persiste après suppression du dossier. Vue + tri + position fenêtre. Indispensable.
USRCLASS.DAT\...\Shell\Bags + BagMRU
Last-Visited MRU
Tracks le binaire (ex. notepad.exe) qui a ouvert chaque fichier de Open/Save MRU + dossier de dernier accès.
NTUSER.DAT\...\Explorer\ComDlg32\LastVisitedPidlMRU
Jump Lists
Aussi présent ici (vue par application des fichiers récents). Clic droit sur icône barre des tâches.
%USERPROFILE%\AppData\Roaming\Microsoft\Windows\Recent\AutomaticDestinations
IE/Edge file://
L'historique IE/Edge enregistre aussi les fichiers locaux ouverts. Format : file:///C:/path/file.ext.
%LOCALAPPDATA%\Microsoft\Windows\WebCache\WebCacheV*.dat
📖 Fiches détaillées : ShellBags · Windows Forensique · LECmd / JLECmd (Zimmerman)

🗑️ 3. Deleted Files & File Knowledge — quel fichier a été supprimé ou consulté ?

Pour répondre à : « Tel fichier a-t-il existé puis été supprimé ? Quand ? Par qui ? »
Recycle Bin Win7+
Sous-dossiers par SID utilisateur. Fichiers $I###### (PATH original + deletion time) + $R###### (data récupération).
C:\$Recycle.bin\<SID>\
Recycle Bin XP
Format historique : C:\RECYCLER\<SID>\INFO2. Mappe nom système (Dc1.ext) au nom + path original.
C:\RECYCLER\<SID>\INFO2
Search WordWheelQuery
Mots-clés recherchés dans le menu Démarrer. Unicode, ordre temporel via MRUlist.
NTUSER.DAT\...\Explorer\WordWheelQuery
Thumbcache
Vignettes en cache (32/96/256/1024 px). Persiste après suppression du fichier original. Excellent pour récupérer images effacées.
%LOCALAPPDATA%\Microsoft\Windows\Explorer\thumbcache_*.db
Thumbs.db (legacy)
Vignettes par dossier. Win7+ : créé sur partages réseau ou homegroup. XP : nom original + last modification stockés.
Caché dans chaque dossier d'images
Search ACMRU (XP)
Recherches via Search Assistant XP. Code 5001=Internet, 5603=fichier, 5604=texte, 5647=imprimante/personnes.
NTUSER.DAT\Software\Microsoft\Search Assistant\ACMru\####
$MFT (file knowledge)
Master File Table NTFS. Chaque entrée = 1024 octets. Trace même les fichiers récemment supprimés (record encore alloué).
$MFT (racine du volume NTFS)
UsnJrnl $J
USN Change Journal. Suit toutes les modifications (création, suppression, rename). Limité en taille (rotation circulaire), idéal pour tracer les opérations récentes.
$Extend\$UsnJrnl:$J
📖 Fiches détaillées : NTFS & $MFT · USN Journal · Windows Forensique · Data Carving

📥 4. File Download — d'où vient ce fichier ?

Pour répondre à : « Tel fichier a-t-il été téléchargé ? Depuis quel site ? Avec quel navigateur ? »
Browser History
Sites visités par date/heure, fréquence. IE/Edge : WebCacheV*.dat. Firefox : places.sqlite. Chrome : History (SQLite).
%LOCALAPPDATA%\<Browser>\...\History*
Downloads (browser)
Filename + size + type, URL source + referer, save location, app utilisée pour ouvrir, start/end times.
Firefox: places.sqlite (table moz_annos) · Chrome: History (downloads)
Email Attachments
Outlook : OST + PST. Aussi vérifier dossier OLK et Content.Outlook (varie selon version).
%LOCALAPPDATA%\Microsoft\Outlook\
Skype History
Logs chat + transferts de fichiers. Activé par défaut. Une entrée par message avec date/heure et username.
%APPDATA%\Skype\<skype-name>\
ADS Zone.Identifier
Alternate Data Stream NTFS depuis XP SP2. ZoneID=3 = Internet. 2=trusted, 4=untrusted. Détecte les fichiers téléchargés.
file.ext:Zone.Identifier (ADS)
Open/Save MRU
Tracks aussi les fichiers sauvegardés depuis le navigateur via Save As. Cumule avec download history.
NTUSER.DAT\...\Explorer\ComDlg32\OpenSavePIDlMRU
📖 Fiches détaillées : Navigateurs · Email Forensique

🔌 5. External Device / USB Usage — quel USB a été branché ?

Pour répondre à : « Quels USB ont été branchés ? Quand pour la première fois ? Par quel utilisateur ? »
USBSTOR / USB
Vendor + Product + Version + Serial unique. Caractère & en 2e position du serial = device sans serial unique (généré par Windows).
SYSTEM\CurrentControlSet\Enum\USBSTOR
setupapi.dev.log (Win7+)
Premier branchement (Plug and Play install). Recherche par device serial. Heures en local time du système.
C:\Windows\inf\setupapi.dev.log
USBSTOR Properties (Win7+)
0064 = First Install · 0066 = Last Connected (Win8+) · 0067 = Last Removal (Win8+).
SYSTEM\...\USBSTOR\Ven_Prod\Serial\Properties\{83da6326...}\####
MountPoints2 (par user)
GUID du device monté par cet utilisateur précis. Last write time = dernier branchement par cet user. Lien USB ↔ user.
NTUSER.DAT\...\Explorer\MountPoints2
MountedDevices (système)
Drive letter ↔ Volume Serial. Examine value data pour le serial number USB. Permet drive letter du dernier mount.
SYSTEM\MountedDevices
WPDBUSEnum (PnP)
Périphériques portables (smartphones MTP, appareils photo). Complète USBSTOR pour les devices non-mass-storage.
SYSTEM\CurrentControlSet\Enum\WpdBusEnumRoot
EmdMgmt (Volume Name)
Volume Serial Number du filesystem (≠ USB serial). Utile pour cross-référencer avec LNK et RecentDocs.
SOFTWARE\Microsoft\Windows NT\CurrentVersion\EMDMgmt
PnP Events (Event ID 20001)
Tentatives d'installation de driver Plug and Play. Status = 0 → succès. Couvre USB, Firewire, PCMCIA.
System.evtx (Event ID 20001)
📖 Fiches détaillées : USB Forensique · USB Removable Media

🌐 6. Browser Usage — quelle activité internet ?

Pour répondre à : « Quels sites visités ? Cookies ? Sessions ? Mots-clés recherchés ? »
History
Sites visités, dates, fréquence. Aussi accès fichiers locaux/réseau (file://). Per-user.
IE/Edge: WebCacheV*.dat · Firefox: places.sqlite · Chrome: History
Cookies
Sites visités, activités. Sessions authentifiées. Exfiltration éventuelle de cookies = take-over de session.
Browsers: cookies.sqlite / Cookies.binarycookies / etc.
Cache
"Snapshot in time" des pages visitées. Identifie les fichiers réellement vus (pas juste l'URL). Timestamps première sauvegarde + dernière vue.
Browsers: INetCache / Cache / etc.
Flash LSO (Super Cookies)
Local Stored Objects Flash. Pas d'expiration, pas de clear par browser. Tracking tenace. Largement obsolète depuis 2020 mais peut subsister.
%APPDATA%\Macromedia\FlashPlayer\#SharedObjects\
Session Restore
Récupération auto des onglets après crash. Onglets ouverts au moment du crash. Référents.
IE/FF/Chrome: Recovery / sessionstore.js / Current Session
Google Analytics __utma
Cookie unique-visitors. Domain hash + visitor ID + 1re visite + 2e-dernière + dernière + nombre total. Très riche en historique.
Cookies stores
Google Analytics __utmz
Cookie traffic-sources. Méthode d'accès (organic/referral/cpc/email/direct), keyword recherché (non-SSL), campagne AdWords.
Cookies stores
Browser Search Terms
Termes recherchés dans Google/DDG/etc., parsable depuis l'history. Aussi : autosuggestions stockées.
Browsers: places.sqlite (FF) · History (Chrome)
📖 Fiches détaillées : Navigateurs · SSL/TLS & HTTPS

👤 7. Account Usage — qui s'est connecté ?

Pour répondre à : « Quels comptes ont été utilisés ? Quand ? Comment ? Connexions réussies / échouées ? »
Last Login
Dernière connexion par compte local + dernier changement de password. Mais seulement la dernière, pas l'historique.
SAM\Domains\Account\Users
Logon Events 4624 / 4625
4624 = succès, 4625 = échec. Avec logon type qui qualifie la nature.
Security.evtx
Logon Types (4624 sub)
2=Console · 3=Network · 4=Batch · 5=Service · 7=Unlock · 8=NetworkCleartext · 9=NewCreds · 10=RDP · 11=CachedCreds.
Champ "Logon Type" dans 4624
RDP Events 4778 / 4779
4778 = session connectée/reconnectée, 4779 = déconnectée. Avec hostname + IP source. Souvent corrélé avec un 4624 type 10.
Security.evtx
Auth Events NTLM 4776
Authentification NTLM (compte local OU workgroup). Logged sur la machine qui authentifie. Distinguer succès vs échec.
Security.evtx (controleur ou local)
Auth Events Kerberos 4768/4769/4771
4768=TGT granted (login domaine) · 4769=service ticket · 4771=pre-auth failed. Loggé sur le DC.
Security.evtx (Domain Controller)
Services Events 7034-7045
7034=crash · 7035=start/stop control · 7036=started/stopped · 7040=start type changed · 7045=service installé. 4697 = service installé (Security log).
System.evtx + Security.evtx
4720 / 4672
4720=compte créé. 4672=connexion avec privilèges admin. Indicateur d'élévation de privilèges réussie.
Security.evtx

📡 8. Network Activity / Physical Location — où est cette machine ?

Pour répondre à : « À quels réseaux la machine s'est-elle connectée ? Avec quelle géolocalisation possible ? Quel timezone ? »
Timezone
⚠️ À vérifier en premier. Tous les timestamps internes en dépendent. Corrélation avec d'autres devices = nécessite un référentiel commun.
SYSTEM\CurrentControlSet\Control\TimeZoneInformation
Network History (NetworkList)
Réseaux Wi-Fi/filaire connus. Intranet name + SSID + MAC gateway. Géolocalisable via la MAC du gateway (BSSID).
SOFTWARE\...\NetworkList\Signatures\Managed + Unmanaged
WLAN Event Log
11000=association · 8001=connexion réussie · 8002=échec · 8003=disconnect. Avec SSID + BSSID (sauf Win8+ qui a retiré BSSID).
Microsoft-Windows-WLAN-AutoConfig%4Operational.evtx
SRUM Network
SRUM tracking aussi réseau par app : bytes envoyés/reçus par application par heure pendant 30-60 jours. Excellent pour exfiltration.
C:\Windows\System32\SRU\SRUDB.dat
BSSID Geolocation
Le MAC du gateway Wi-Fi (BSSID) peut être résolu en coordonnées GPS via WiGLE ou des bases publiques. Triangulation possible.
Use BSSID from Network History or WLAN Events
VPN / Network Profiles
Connexions VPN passées. Profils L2TP/PPTP/SSTP. Aussi visible dans RasMan et WLANSVC.
SOFTWARE\Microsoft\Rasman + NetworkList\Profiles

⏰ 9. Bonus — Time Rules MACB ($SI vs $FN)

🔑 Les attaques anti-forensiques modifient souvent les MAC times. Comparer $STANDARD_INFORMATION vs $FILE_NAME permet de détecter le timestomping : si $SI < $FN, c'est suspect (le fichier a été antidaté).

🎓 Exam Tip — Méthodologie d'enquête Windows

Règle d'or : un seul artéfact ne suffit JAMAIS. La forensique Windows est une enquête à plusieurs sources. Croiser au moins 2-3 artéfacts pour confirmer un fait.

Ordre standard : (1) Acquisition image disque + RAM, (2) Vérifier le timezone, (3) Établir la timeline globale (SI/FN/USN/RecentDocs), (4) Cibler la question forensique, (5) Croiser les artéfacts de cette section.

Outils recommandés : Suite Eric Zimmerman (PECmd, LECmd, MFTECmd, JLECmd, Amcache, Shimcache), KAPE pour la collection, Autopsy pour l'analyse globale, Velociraptor pour le live response à grande échelle.

Pièges classiques : timezone mal lu → corrélations fausses · Shimcache présence ≠ exécution sur Win10 · Recycle Bin vide ≠ pas de fichiers supprimés (carving disque) · MountPoints2 manquant ≠ device pas branché (effacé).

Indispensable : poster officiel SANS FOR500 (Rob Lee) dont cette fiche s'inspire — version PDF imprimable A1.
