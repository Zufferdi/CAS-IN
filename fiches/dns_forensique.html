DNS Forensique

Logs DNS · Exfiltration DNS · Beaconing · Passive DNS · Zeek

"DNS is the most important protocol you'll ever overlook. Every attack leaves DNS breadcrumbs — if you know where to look."
— SANS SEC503 · Network Forensics
💡 Pourquoi le DNS est sous-exploité : La plupart des enquêtes se concentrent sur HTTP/HTTPS. Pourtant, le DNS est souvent le seul protocole non filtré en sortie d'un réseau — raison pour laquelle les attaquants l'utilisent pour l'exfiltration de données et le command-and-control (C2).

🔴 DNS Exfiltration

🚨
Technique : Les données sont encodées en Base64 dans des sous-domaines DNS. L'attaquant contrôle le serveur DNS autoritaire pour les recevoir. Passe souvent inaperçu car le DNS est rarement bloqué en sortie.

Indicateurs d'exfiltration DNS

  • Sous-domaines anormalement longs (> 30 chars)
  • Caractères Base64 dans les sous-domaines (A-Z, 0-9, +/=)
  • Volume élevé de requêtes vers un seul domaine
  • Type de requête inhabituel : TXT, NULL, CNAME
  • Intervalles réguliers (beaconing)

Exemple concret

  • aGVsbG8=.attacker.com → "hello" en Base64
  • dGhpc2lzc2VjcmV0.attacker.com → données exfiltrées
  • Outils offensifs : iodine, dns2tcp, DNScat
  • Détection : analyser la longueur moyenne des sous-domaines
# Zeek : détecter les sous-domaines longs
cat dns.log | zeek-cut query | awk '{n=split($0,a,"."); if(length(a[1])>30) print}' | sort | uniq -c | sort -rn

🔄 DNS Beaconing — Indicateur C2

Le beaconing C2 via DNS est caractérisé par des requêtes périodiques régulières vers un même domaine :

IndicateurNormalBeaconing C2
IntervalleAléatoire, selon usageRégulier (30s, 60s, 5min…)
DomaineDivers, connusDGA ou domaine unique inconnu
RéponseIP stable (CDN)NXDOMAIN alternant / IP dynamique
VolumeQuelques requêtesCentaines/heure
TTL300–86400sTTL très bas (< 30s)
# Détecter beaconing avec Zeek + tshark
tshark -r capture.pcap -T fields -e dns.qry.name -Y "dns" | sort | uniq -c | sort -rn | head -20

🔍 Passive DNS — Investigation rétrospective

💡
Passive DNS : Bases de données mondiales qui enregistrent les résolutions DNS au fil du temps. Permettent de savoir quelle IP un domaine résolvait il y a 2 ans, ou quels autres domaines ont pointé vers la même IP.

Services Passive DNS

  • VirusTotal — Relations et résolutions historiques
  • DNSDB (Farsight) — Base la plus complète (payante)
  • RiskIQ / Microsoft Defender
  • SecurityTrails
  • Shodan — DNS inversé par IP

Cas d'usage forensique

  • Retrouver l'IP hébergeant un C2 qui a changé de DNS
  • Identifier d'autres domaines malveillants sur la même IP
  • Reconstruire l'infrastructure d'un attaquant
  • Confirmer la date de première utilisation d'un domaine

🛠️ Outils DNS forensiques

  • Zeek (Bro) : Analyse PCAP → dns.log structuré en TSV/JSON. Référence en IR réseau.
  • tshark : tshark -r cap.pcap -T fields -e dns.qry.name -Y dns
  • DNStwist : Détection de typosquatting — variantes orthographiques d'un domaine
  • Malicious Domain Checker : APIs VirusTotal, URLhaus, PhishTank
  • MassDNS : Résolution en masse pour les investigations OSINT
  • Dig / nslookup : Requêtes manuelles avec options (type, serveur spécifique)
# Extraire tous les domaines distincts d'un PCAP
tshark -r file.pcap -T fields -e dns.qry.name -Y "dns.flags.response == 0" | sort -u
