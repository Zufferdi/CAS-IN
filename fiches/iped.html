IPED — Indexador e Processador de Evidências Digitais

Outil DFIR open source développé par la Police fédérale brésilienne depuis 2012, publié sur GitHub en 2019. Java multithread, jusqu'à 400 GB/h et 135 millions d'items par cas. Alternative crédible à Autopsy, surtout pour les très gros volumes.

🎯 Pourquoi IPED ?

📜 Origine & contexte

  • Développé par Sepinf — Service de Perícias em Informática de la Police Fédérale brésilienne (PF/SEPINF)
  • Créé en 2012, sources publiées sur GitHub en 2019 sous LGPL-3.0
  • Utilisé en production sur les très grandes saisies (Operação Lava Jato, plusieurs millions de fichiers)
  • Equivalent fonctionnel d'Autopsy mais plus performant en multithread
  • Multi-plateforme : Windows et Linux, portable depuis une clé USB

⚡ Forces principales

  • Performance : jusqu'à 400 GB/h sur hardware moderne (SSD NVMe + multi-cœurs)
  • Scalabilité : 135M d'items dans un cas (multicas) testée
  • Carving efficient : moins de 10% du temps de processing pour 40+ formats
  • UFDR natif : ouvre les exports Cellebrite directement (rare en open source)
  • Portable cases : pas d'installation, exécution depuis le disque externe

💻 Workflow type
# 1. Lancer le processing en CLI (batch)
iped.bat -d "E:\Cases\Image001.E01" -o "F:\Output\Case01" -profile forensic

# 2. Traiter plusieurs sources d'un coup (multicas)
iped.bat -d "C:\Image1.E01" -d "C:\Image2.E01" -d "D:\PhoneExport.UFDR" -o "F:\Multicase"

# 3. Profil triage rapide pour décider quelle preuve approfondir
iped.bat -d "E:\Suspect.E01" -o "F:\Triage" -profile triage

# 4. Ouvrir le cas dans la GUI Java
iped-search-app.bat     # Windows
./iped-search-app.sh      # Linux

# 5. Construction depuis sources (dev)
git clone https://github.com/sepinf-inc/IPED.git
cd IPED
mvn clean install
# → target/release/ contient un build snapshot
💡 Pré-requis Linux : sur Linux il faut compiler manuellement Sleuthkit modifié + dépendances natives (libtsk_jni). Sur Windows, une release binaire pré-construite est disponible sur la page Releases GitHub.

⚖ Points de vigilance pour la pratique suisse

  • Open source = bon pour la transparence en procédure : code auditable, pas de "boîte noire". Argument utile face à un avocat de la défense.
  • Hashsets sensibles : ProjectVIC/CAID/Interpol ICSE sont réservés aux Law Enforcement. Pour les ENRC/expert privé en Suisse, contacter iped@pf.gov.br.
  • Traduction : interface disponible en EN/PT, partiellement FR (contributions communautaires).
  • Signature des binaires : Windows builds non signés Microsoft → potentiel SmartScreen. Vérifier les hash SHA-256 publiés sur la page Releases.
  • RGPD/nLPD : transcription cloud (Azure/Google) = données quittent l'UE. Préférer WhisperX local pour conformité.
🧪 Cas d'usage typiques

🔥 Très gros volumes

Saisie d'entreprise avec 50+ disques, > 10 TB total. IPED en multicas + profil forensic sur serveur Xeon 2× 32 cœurs / 256 GB RAM = ~30h de processing au lieu de plusieurs jours sous Autopsy.

📱 Téléphones via Cellebrite

Export UFDR ouvert directement, sans passer par UFED Reader. Permet de croiser téléphone + PC dans un même cas, avec timeline unifiée et graphe d'appels/messages.

🧾 Triage avant saisie

Profil triage en 30 minutes sur une clé USB suspecte → preview rapide pour décider en intervention si on emporte le matériel ou pas. Idéal pour premier intervenant.

👤 Recherche d'IOCs / regex

Index Lucene + regex pré-définies (CB, BTC, IBAN) → recherche d'un numéro de carte ou d'un wallet à travers tout un volume en quelques secondes. Très efficace en blanchiment/cyber-fraude.

⚠ Pièges et limites
  • RAM exigeante : pour 100M+ d'items, prévoir ≥ 64 GB. IPED indexe en mémoire avant de flusher sur disque. Sous-dimensionner → swapping intensif et écroulement performance.
  • Documentation limitée : le wiki GitHub est complet mais surtout en anglais et en portugais. Peu de tutoriels FR.
  • Build Linux complexe : compiler Sleuthkit modifié + JNI peut prendre 2h et exige des dev tools spécifiques (gcc, autoconf, libpng, libtiff).
  • PhotoDNA / hashsets sensibles : réservés aux Law Enforcement, pas accessibles à un expert privé.
  • Détection NSFW : modèles deep learning peuvent produire des faux positifs sur du contenu artistique/médical légitime — toujours vérifier visuellement.
  • SQLite recovery : utilise fqlite mais ne récupère pas tous les écrits journalisés (WAL pré-checkpoint). Croiser avec un outil dédié (sqlite_dissect) pour les cas critiques.
  • Pas de write-block intégré : utiliser un write-blocker hardware en amont, comme avec n'importe quel outil DFIR.
🧠 Testez-vous
Quel est l'avantage principal d'IPED face à Autopsy pour traiter une saisie de 5 TB sur 50 disques ?Performance · Niveau : facile
Performance multithread. IPED atteint jusqu'à 400 GB/h sur hardware moderne, soit ~4× plus rapide qu'Autopsy. Le mode multicas permet de traiter les 50 disques en parallèle dans un seul cas avec timeline et graphe unifiés. Sur 5 TB : 12–15h vs 50h+ avec Autopsy.
IPED utilise quelle bibliothèque pour le décodage des systèmes de fichiers ?Architecture · Niveau : moyen
The Sleuth Kit (TSK), la même bibliothèque qu'Autopsy. IPED supporte exactement les mêmes systèmes de fichiers (NTFS, FAT, exFAT, EXT, HFS+, APFS, ISO9660). La valeur ajoutée d'IPED est dans le pipeline de tasks, l'indexation Lucene et les parsers personnalisés (UFDR, WhatsApp, Telegram) — pas dans le décodage FS.
Vous trouvez un export cellebrite_dump.UFDR. Que pouvez-vous faire avec IPED que vous ne pouvez pas (facilement) avec Autopsy ?UFDR · Niveau : difficile
IPED ouvre nativement les fichiers UFDR, alors qu'Autopsy nécessite UFED Reader (Windows-only) ou conversion préalable. Avec IPED :
· charger l'UFDR comme source de données
· l'inclure dans un multicas aux côtés d'images PC pour timeline unifiée
· indexer son contenu dans le même Lucene
· faire un graphe de communications croisant téléphone et e-mails
Avantage opérationnel majeur pour les enquêtes mobile + PC.
🎓 À retenir pour la pratique — IPED

Origine : Police fédérale brésilienne (Sepinf — Setor de Perícias em Informática) · Java · open source LGPL-3.0 publié sur GitHub depuis 2019 (développé en interne depuis 2012).

Performances : jusqu'à 400 GB/h sur hardware moderne · capacité testée jusqu'à 135 millions d'items dans un seul cas · multithread très efficace (utilise toutes les cores disponibles).

Backend FS : utilise The Sleuth Kit (TSK) sous le capot → couverture FS identique à Autopsy (NTFS, FAT, exFAT, EXT, HFS+, APFS, ISO9660).

Différence clé vs Autopsy : multithread plus efficace · lecture native des fichiers UFDR Cellebrite · profils spécialisés (CSAM, triage) · graphes de communications.

Profils : forensic (standard exhaustif) · pedo (csam : focus sur images/vidéos + hashsets) · triage (preview rapide ~30 min) · fastmode (skip OCR/transcription) · blind (sans GUI, batch headless).

Cas portable : un cas IPED peut être exécuté depuis USB sans installation (réfrigérateur portable, idéal pour partage avec MP/magistrat).

Hashsets supportés : NSRL (public) · CAID · ProjectVIC · Interpol ICSE (les trois derniers réservés Law Enforcement).

Spécificités utiles en CH : parsers natifs WhatsApp / Telegram / Skype / Signal (souvent demandés en enquête) · OCR Tesseract intégré · transcription audio (WhisperX local pour conformité nLPD/RGPD).

Limites à connaître : exige ≥ 64 GB RAM pour 100M+ items · documentation limitée FR (wiki EN/PT) · pas de write-blocker intégré (utiliser hardware en amont) · binaires Windows non signés Microsoft → SmartScreen.

Repo officiel : github.com/sepinf-inc/IPED · contact dataset : iped@pf.gov.br.
