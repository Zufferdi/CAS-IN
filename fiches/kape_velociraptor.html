KAPE & Velociraptor — Collecte et triage DFIR

Kroll Artifact Parser · Velociraptor DFIR · Collecte rapide · Déploiement à grande échelle

"KAPE can collect 1500+ forensic artefacts from a live Windows system in under 5 minutes. Velociraptor can do the same across 10 000 endpoints simultaneously."
— Kroll Cyber Risk · Velociraptor DFIR Documentation
💡 Pourquoi ces outils sont devenus standards : Face à des incidents touchant des centaines de machines, les méthodes forensiques traditionnelles (image disque par machine) sont impossibles. KAPE et Velociraptor permettent un triage ciblé et rapide, sans bloquer l'activité de l'entreprise.

🎯 KAPE — Kroll Artifact Parser and Extractor

ℹ️
KAPE = Targets + Modules. Les Targets définissent ce qui est collecté (fichiers spécifiques). Les Modules définissent comment les traiter (parsing, conversion). Entièrement gratuit, développé par Eric Zimmerman.

Targets — Ce qu'on collecte

  • !BasicCollection — Artefacts essentiels (5 min)
  • !SANS_Triage — Recommandations SANS
  • Windows_EventLogs — Tous les EVTX
  • Prefetch — Fichiers prefetch
  • RegistryHives — Toutes les ruches
  • BrowserHistory — Chrome, Firefox, Edge
  • MFT — Master File Table

Modules — Ce qu'on parse

  • MFTECmd — Parse la MFT
  • EvtxECmd — Parse les Event Logs
  • PECmd — Parse le Prefetch
  • RegRipper — Extrait le Registre
  • Chainsaw — Détection sur EVTX
  • Hayabusa — Règles Sigma sur EVTX
# Collecte basique KAPE
kape.exe --tsource C: --tdest D:\KAPE_Output --target !BasicCollection
# Collecte + traitement (targets + modules)
kape.exe --tsource C: --tdest D:\out --target !SANS_Triage --module !EZParser --mdest D:\parsed

🦅 Velociraptor — DFIR à grande échelle

💡
Architecture : Serveur Velociraptor + agents légers (clients) déployés sur tous les endpoints. Le serveur envoie des VQL (Velociraptor Query Language) queries aux agents qui retournent les résultats en temps réel.

Capacités

  • Collecte d'artefacts sur 10 000+ machines simultanément
  • Interrogation en temps réel (processus, connexions, fichiers)
  • Chasse aux menaces (threat hunting) à l'échelle
  • Déploiement d'agents MSI / PowerShell
  • Intégration Sigma / YARA rules
  • Collecte planifiée ou à la demande

VQL — Exemples de queries

  • Lister processus actifs sur tous les endpoints
  • Chercher une IOC (hash, chemin, clé registre)
  • Collecter tous les prefetch / event logs
  • Détecter des IOC YARA sur les processus en mémoire
  • Timeline des connexions réseau par endpoint
-- VQL : lister processus avec hash sur tous les clients
SELECT Pid, Name, Exe, Hash.MD5 FROM pslist()
WHERE NOT Name IN ('svchost.exe', 'explorer.exe')
ORDER BY CreateTime DESC

🔄 Workflow KAPE typique en IR

1
Démarrer KAPE depuis une clé USB forensique
Ne jamais installer KAPE sur la machine suspecte. Lancer depuis support externe. KAPE lui-même ne modifie pas le système cible.
2
Sélectionner les Targets adaptés
Pour ransomware → !SANS_Triage + Windows_EventLogs. Pour APT → ajouter RegistryHives, AmCache, Prefetch. Pour compromission AD → ADInfo.
3
Parser avec les Modules (optionnel)
!EZParser exécute tous les outils Zimmerman sur les artefacts collectés. Résultat : CSV directement importables dans Timeline Explorer ou Excel.
4
Importer dans Timesketch / Timeline Explorer
Analyse de la timeline unifiée. Corrélation des événements. Pivot sur les IOC identifiés.
