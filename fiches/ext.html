Superbloc
  • Toujours à l'offset 1024 octets du début du volume
  • Contient : inode_count, block_count, s_inodes_per_group, s_blocks_per_group
  • Magic number : 0xEF53 (LE : 53 EF)
  • Copies de secours dans certains groupes (sparse_super)
  • s_last_mounted, s_mkfs_time, s_uuid → forensique
Groupes de blocs
  • Volume divisé en groupes de blocs de taille fixe
  • Chaque groupe : superbloc (copie), GDT, bitmap blocs/inodes, table inodes, données
  • Taille typique : 32 768 blocs × 4 Ko = 128 Mo / groupe
  • Formule groupe d'un inode :
(inode − 1) ÷ s_inodes_per_group

  • Mode (type + permissions Unix)
  • UID/GID propriétaire

  • 0644 : rw-r--r-- (standard fichier)

Suppression et récupération forensique
1
L'entrée de répertoire est invalidée (rec_len étendu pour "sauter" l'entrée). Le nom reste lisible dans les répertoires EXT2 — extraction avec fls -r.
2
i_links_count passe à 0. Sur EXT3/4 : les pointeurs de blocs dans l'inode sont effacés. Sur EXT2 : pointeurs conservés → récupération directe possible avec icat.
3
Les bits dans les bitmaps blocs et inodes sont remis à 0 (libres). Les données restent sur le disque jusqu'à réécriture — carving possible avec PhotoRec ou Scalpel.
4
EXT4 : Consulter le journal (ext4magic -R ou debugfs). La journalisation en mode data=journal offre les meilleures chances — data=writeback le moins.
// Formules d'offset inode :
Groupe     = (inode − 1) ÷ s_inodes_per_group // division entière
Index      = (inode − 1) mod s_inodes_per_group
Offset inode = Début_table_inodes + index × taille_inode
Exemple — Inode 150, 128 inodes/groupe, inode size = 256 octets
Groupe  = (150 − 1) ÷ 128 = 1
Index   = 149 mod 128 = 21
Offset  = début_table_groupe_1 + 21 × 256
Récupération EXT4 : Utiliser le journal (ext4magic), le carving sur l'espace non alloué (PhotoRec, Scalpel), ou analyser le journal avec debugfs. La journalisation EXT4 en data=writeback protège moins les données qu'en data=ordered ou data=journal.

Superbloc : offset 1024 octets · Magic 0xEF53 (LE : 53 EF)

Inode 2 = racine / · Inode 8 = journal EXT3/4 · Inodes normaux ≥ 11

EXT4 block pointer zeroing : pointeurs effacés → récupération via journal (ext4magic)

EXT2 : pointeurs conservés → récupération directe avec icat inode_num

Formule groupe : (inode − 1) ÷ s_inodes_per_group · Index = (inode − 1) mod s_inodes_per_group

Permissions Unix : 0644 = rw-r--r-- · 0755 = rwxr-xr-x · 0777 ⚠

Journalisation : data=journal > data=ordered > data=writeback (fiabilité forensique)

Pourquoi EXT4 rend la récupération plus difficile qu'EXT2 ?EXT forensique · Niveau : moyen
Block pointer zeroing : à la suppression, les pointeurs de blocs dans l'inode sont mis à 0. Sur EXT2 ils restaient → localisation directe avec icat. Sur EXT4 : passer par le journal (ext4magic) ou file carving sur l'espace libre.
Inode 150, 128 inodes/groupe. Quel groupe ? Quel index ?EXT calcul · Niveau : facile
Groupe = (150 − 1) ÷ 128 = 1 · Index = 149 mod 128 = 21 · Offset = début_table_inodes_groupe_1 + 21 × taille_inode
Un inode a i_links_count = 0. Que peut-on en déduire ?EXT Inodes · Niveau : moyen
Le fichier est supprimé — aucun hardlink ne pointe vers cet inode. Les données restent sur disque jusqu'à réallocation. Sur EXT2 : les pointeurs de blocs sont encore dans l'inode → récupération directe. Sur EXT3/4 : pointeurs effacés. Indice forensique : inode dans bitmap = libre mais données potentiellement récupérables.
Quel est le magic number du superbloc EXT et à quel offset le trouver ?EXT Superbloc · Niveau : facile
Magic number : 0xEF53 (en Little Endian : 53 EF). Il se trouve à l'offset 1024 + 56 = 1080 octets du début du volume (le superbloc commence à 1024, le magic est au champ offset 0x38 dans la structure superbloc). Vérifier ce magic est la première étape pour identifier un volume EXT.
