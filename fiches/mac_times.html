MACB — Les 4 timestamps NTFS
M Modified Contenu du fichier modifié (écriture)
A Accessed Dernier accès en lecture (souvent désactivé Win Vista+)
C Changed Métadonnées MFT modifiées (taille, perms, attr.)
B Born Date de création du fichier (création initiale)
Deux niveaux dans NTFS
  • $STANDARD_INFORMATION — accessible via API Windows (SetFileTime). C'est ce que l'Explorateur affiche. Modifiable par timestomping.
  • $FILE_NAME — mis à jour uniquement par le kernel NTFS. Résiste au timestomping classique. Clé de détection.
Règle d'or forensique
  • Si $SI.M < $FN.M → timestomping probable
  • Si date création > date modification → fichier copié (la copie crée une nouvelle date de création)
  • Précision NTFS : 100 nanosecondes. Les outils anti-forensiques arrondissent souvent à la seconde → détectable
  • X-Ways affiche les deux colonnes séparément
💡 Mnémo examen : MACB = "Ma Chère Alice Bouge" → Modified · Accessed · Changed · Born. Sur FAT, seuls M et B (+ A tronqué à la date) existent — pas de $FILE_NAME.

Détecter le timestomping
🔴 Indicateur #1 — $SI vs $FN

Date $STANDARD_INFORMATION antérieure à $FILE_NAME. Impossible naturellement — $FN est créé en même temps que le fichier et ne se met à jour que par le kernel.

🔴 Indicateur #2 — Précision suspecte

Timestamp NTFS se terminant par :00.0000000 (arrondi à la seconde). SetFileTime ne permet pas la précision sub-seconde → signature de timestomping via Metasploit, Timestomp, PowerShell.

🟡 Indicateur #3 — Chronologie incohérente

Fichier dans le Prefetch ou les Event Logs avant sa date de création affichée. Le Prefetch capte la première exécution — si elle précède la "naissance" du fichier, c'est une contradiction.

🔴 Indicateur #4 — USN Journal

Le journal $UsnJrnl ($Extend\$UsnJrnl) enregistre toutes les modifications de fichiers avec leur vrai timestamp kernel. Un fichier timestompé apparaît dans l'USN avec ses vraies dates.

🟡 Indicateur #5 — Création après modification

Date B (Born) postérieure à date M (Modified) → le fichier a été copié depuis une autre source. Windows met la date de création à "maintenant" lors d'une copie, mais préserve la date de modification.

🟡 Indicateur #6 — Shadow Copy

Comparer les timestamps dans un Volume Shadow Copy (VSS) avec ceux du système live. Si différents sans justification, manipulation possible.

Outils Eric Zimmerman — timestamps
MFTECmd Parse la $MFT entière → CSV avec $SI et $FN séparés. Détecte les anomalies temporelles automatiquement.
PECmd Parse les fichiers Prefetch → 8 dernières exécutions avec timestamps précis. Idéal pour prouver qu'un programme a tourné.
LECmd Parse les fichiers LNK (raccourcis) → timestamps de création/modif du LNK + du fichier cible + chemin réseau si applicable.
JLECmd Parse les Jump Lists → fichiers récents par application avec timestamps d'accès. Très utile pour les affaires de fuite de données.
SBECmd / SBE ShellBags Explorer → dossiers parcourus avec timestamps. Révèle même les dossiers supprimés et les clés USB connectées.
EvtxECmd Parse les Event Logs EVTX → CSV avec timestamps normalisés. Supporte les maps personnalisées (Chainsaw, Hayabusa).
DCode Convertit les timestamps de tous les formats (FILETIME, Epoch, Chrome, Mac Abs., etc.) → outil indispensable pour les analyses manuelles.
Horodatage certifié (TSA) — valeur probante
Autorité d'Horodatage (TSA)
  • Tiers de confiance (ex: SwissSign, GlobalSign) qui signe le hash d'un document avec son propre certificat
  • Résultat : preuve que le document existait avant T sous cette forme exacte
  • Standard : RFC 3161 (timestamp token = hash + heure + signature TSA)
  • Valeur probante : art. 177 CPC + ZertES (Suisse)
Pourquoi ça vaut plus qu'une date système
  • Date système = modifiable trivialement (SetFileTime, tzutil, VM snapshot)
  • TSA = signature cryptographique d'un tiers — impossible à falsifier rétroactivement
  • Le hash garantit l'intégrité : si le doc change, la signature TSA invalide
  • En Suisse : seule la signature électronique qualifiée (SEQ) sur une TSA accréditée a valeur légale pleine
# Horodatage RFC 3161 avec OpenSSL (TSA FreeTSA)
openssl ts -query -data rapport.pdf -sha256 -cert -out rapport.tsq
curl -H "Content-Type: application/timestamp-query" --data-binary @rapport.tsq https://freetsa.org/tsr -o rapport.tsr

# Vérification
openssl ts -verify -in rapport.tsr -data rapport.pdf -CAfile cacert.pem
Erreurs fréquentes à l'examen
❌ Confondre M et C — M (Modified) = contenu modifié. C (Changed) = métadonnées modifiées. Renommer un fichier ne touche pas M mais touche C.
❌ Croire que A est toujours actif — Windows Vista+ désactive NtfsDisableLastAccessUpdate par défaut. La date A peut être figée depuis des années.
❌ Ignorer $FILE_NAME — Beaucoup d'examens portent sur la différence $SI / $FN. Si vous ne citez que $STANDARD_INFORMATION, vous ratez la détection de timestomping.
❌ Confondre les époques Chrome et Firefox — Chrome part de 1601, Firefox de 1970. Dans une base de données de navigateur, une valeur de 13 chiffres ≠ une de 16 chiffres.
❌ Oublier la précision FAT — FAT32 stocke les timestamps avec une précision de 2 secondes. Des fichiers qui semblent avoir exactement le même timestamp peuvent ne pas l'avoir été créés simultanément.
✅ Règle de copie : lors d'une copie Windows, B devient "maintenant" mais M est préservé. Donc B > M → copie. B < M → fichier original ou timestompé.
