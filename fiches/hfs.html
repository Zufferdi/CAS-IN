🍎 Legacy Apple FS

HFS+ — Hierarchical File System Plus

B-Trees Catalog, CNID, endianness inversée, epoch 1904, resource forks, journal — le système Apple de 1998 à 2017 (et encore présent sur des millions de Macs antérieurs à macOS High Sierra).

⚠️ Big Endian ! HFS+ stocke toutes les valeurs multi-octets en Big Endian, à l'inverse de FAT/NTFS (Little Endian). En lecture hex manuelle : inverser l'ordre des octets pour chaque champ. X-Ways, Autopsy et mac_apt convertissent automatiquement.

🎯 Volume Header

  • Toujours à l'offset 1024, taille 512 octets
  • Signature : 0x482B = 'H+' (HFS+) · 0x4858 = 'HX' (HFSX, case-sensitive)
  • Contient : taille volume, nombre de blocs d'allocation, nextCatalogID (prochain CNID libre), timestamps volume
  • Pointeurs vers les 5 fichiers spéciaux (Catalog, Extents Overflow, Attributes, Startup, Allocation)
  • Attributs : journalé, bootable, corrompu au démontage (volumeInconsistent)
  • Alternate VH : copie à −1024 octets depuis la fin du volume (ancre de récupération)

🔢 CNID — Catalog Node ID

Identifiant unique 32 bits de chaque objet (fichier, dossier, thread). Équivalent de l'inode EXT. Persistant même après renommage ou déplacement — traçable dans les LNK macOS (Aliases).

  • 1 — parent fictif de la racine
  • 2 — répertoire racine du volume
  • 3 — Extents Overflow File
  • 4 — Catalog File
  • 5 — Bad Blocks File
  • 6 — Allocation File
  • 7 — Startup File
  • 8 — Attributes File
  • ≥ 16 — CNIDs utilisateurs normaux
🌳 Les 5 fichiers spéciaux B-Tree
HFS+ est entièrement construit sur des B-Trees. Chaque structure critique est un fichier invisible.
Fichier CNID Rôle forensique
Catalog File 4 Répertoire principal : nom, dates, taille, CNID, parent, fork pointers de chaque objet. Source primaire de métadonnées. Les nœuds B-Tree libérés mais non réécrits conservent des entrées résiduelles → récupération forensique.
Extents Overflow 3 Stocke les extents supplémentaires des fichiers très fragmentés (> 8 extents par fork). Clé = (forkType, CNID, startBlock) où forkType 0x00 = data, 0xFF = resource.
Attributes File 8 Attributs étendus (xattr) et ACL POSIX. Équivalent de $EA NTFS. Contient les Finder Info (icône, couleur label, position), quarantine (com.apple.quarantine), metadata Spotlight.
Allocation File 6 Bitmap d'allocation des Allocation Blocks — 1 bit par bloc. Équivalent $Bitmap NTFS.
Startup File 7 Données de boot pour systèmes non-Mac bootant en HFS+ (rare). Souvent vide sur macOS moderne.
📅 Timestamps HFS+ — Epoch 1904
HFS+ epoch 1er janvier 1904 00:00:00 UTC
Unix epoch 1er janvier 1970 00:00:00 UTC
Différence +2 082 844 800 secondes (66 ans)
Précision 1 seconde
Conversion unix_ts = hfs_ts − 2 082 844 800
En Python datetime(1904,1,1) + timedelta(seconds=hfs_ts)

🕐 Quatre timestamps par fichier

  • createDate — création du fichier (persistant même après modification)
  • contentModDate — dernière modification du contenu (équivalent mtime)
  • attributeModDate — dernière modif métadonnées (xattr, permissions)
  • accessDate — dernier accès en lecture (peut être désactivé pour perfs SSD)
  • backupDate — dernier backup Time Machine (si applicable)

Tous exprimés en secondes depuis epoch 1904, stockés en Big Endian 32 bits.

📎 Resource Forks — héritage Classic Mac OS

Chaque fichier HFS+ possède deux forks : le data fork (contenu principal) et le resource fork (icône custom, métadonnées d'application, code legacy).

  • Accès CLI : ls -l@ fichier (montre xattr), cat fichier/..namedfork/rsrc (lecture directe)
  • Taille du rsrc fork visible via xattr -l fichier ou Finder (Get Info)
  • En copie vers FAT/NTFS : macOS crée des fichiers AppleDouble préfixés ._nomfichier pour préserver le rsrc fork + xattr
  • Sur clé USB FAT : présence de ._ files = la clé a été utilisée sur Mac (empreinte forensique)
  • Dans archives .zip créées par Finder : dossier caché __MACOSX/ contient les AppleDouble
💡 Indice forensique : une clé USB qui contient des fichiers ._filename ou un dossier __MACOSX/ dans une archive ZIP a transité par un Mac. Permet d'établir qu'un fichier a été manipulé sur un appareil Apple avant d'arriver sur le système analysé.
📖 Journalisation HFS+

📝 Le journal HFS+

Introduit avec Mac OS X 10.2.2 (2002). Activable via diskutil enableJournal /dev/diskX. Signature VH = HX ou flag kHFSVolumeJournaledBit.

  • Fichier invisible .journal à la racine (CNID spécial)
  • Taille typique : 8–64 MB circulaire
  • Contient uniquement les métadonnées (pas le contenu utilisateur)
  • Structure : header + transactions séquentielles avec block list

🔬 Valeur forensique du journal

  • Historique récent des opérations sur métadonnées
  • Peut révéler des créations / suppressions / renommages non visibles dans le Catalog actuel
  • Anciens états de B-Tree nodes avant réécriture
  • Outils : hfsinspect, parsers custom Python (pyhfs)
  • Journal éphémère : bouclé rapidement sur système actif
🗑 Suppression et récupération

🔄 Ce qui se passe à la suppression

  1. 1. L'entrée est retirée du Catalog B-Tree. Le nœud B-Tree qui la contenait est marqué libre mais pas écrasé immédiatement tant que le nœud n'est pas réalloué.
  2. 2. Les blocs de données sont marqués libres dans l'Allocation File. Le contenu brut n'est pas effacé avant réallocation.
  3. 3. Si journalisation active : l'opération est enregistrée dans le .journal → fenêtre supplémentaire pour récupérer les métadonnées.
  4. 4. Les CNIDs ne sont pas réutilisés avant épuisement de l'espace 32 bits → un CNID supprimé reste unique historiquement.

🔨 Stratégies de récupération

  • Carving du Catalog : parser les nœuds B-Tree libérés pour extraire entrées résiduelles (outil : hfsinspect, Autopsy plugin HFS)
  • Extents orphelins : les extents dans Extents Overflow peuvent pointer sur des données toujours lisibles
  • Corbeille : ~/.Trash/ (volume système) + .Trashes/ (volumes externes) — souvent peu vidée
  • Time Machine : sauvegardes Time Machine historiques sur disque externe HFS+ → versions antérieures des fichiers
  • Spotlight metadata : .Spotlight-V100/ conserve des indices même après suppression
  • Journal : lecture séquentielle avec parser custom — fenêtre courte mais informative
💾 Time Machine sur HFS+

Time Machine de Mac OS X 10.5 (2007) à macOS 10.15 utilisait HFS+ avec hard links vers des répertoires — fonctionnalité non-standard exclusive Apple.

  • Stockage : /Volumes/<TM_Disk>/Backups.backupdb/<Mac>/
  • Un dossier par snapshot : YYYY-MM-DD-HHMMSS/
  • Hard links de répertoires → taille sur disque quasi-nulle pour snapshots incrémentaux
  • Lien symbolique Latest pointant sur la dernière sauvegarde
  • Valeur forensique majeure : accès aux versions antérieures de tous les fichiers, parfois sur plusieurs années
  • Sur macOS 11+ : Time Machine migre vers APFS snapshots (voir fiche APFS)
🔐 FileVault 1 (legacy, spécifique HFS+)

La première version de FileVault (Mac OS X 10.3 Panther → 10.6 Snow Leopard) ne chiffrait que le répertoire personnel, pas tout le volume :

  • Home directory stocké dans un sparsebundle chiffré AES-128 : /Users/.<user>/<user>.sparsebundle
  • Monté dynamiquement au login
  • Clé dérivée du mot de passe utilisateur + Master Password (optionnel)
  • Rest du volume HFS+ en clair → artefacts système accessibles sans la clé
  • FileVault 2 (10.7 Lion) = chiffrement complet du volume (CoreStorage / XTS-AES-128), voir fiche Chiffrement de Volumes

💻 Commandes essentielles
# Identifier le type de filesystem sur un disque
diskutil info /dev/disk2s1 | grep "File System"

# Monter une image HFS+ en lecture seule (Linux)
sudo mount -t hfsplus -o ro,loop,offset=1048576 image.dd /mnt/hfs

# Sleuth Kit — lister tous les fichiers
fls -r -p -f hfs image.dd

# Inspecter le Volume Header avec hfsinspect
hfsinspect -d /dev/disk2s1 -v

# Parcourir le Catalog B-Tree
hfsinspect -d image.dd --btree catalog

# Extraire attributs étendus (resource forks + xattr)
xattr -l fichier.ext
ls -l@ fichier.ext

# Convertir timestamp HFS+ (epoch 1904) en date lisible
python3 -c "from datetime import datetime, timedelta; \
  print(datetime(1904,1,1) + timedelta(seconds=3797928000))"
📚 Examen CAS-IN
  • Offset du Volume Header : 1024 (pas 0)
  • Signature : 0x482B ('H+') ou 0x4858 ('HX' journalisé / case-sensitive)
  • Endianness : Big Endian (inverser vs FAT/NTFS)
  • Epoch : 1er janvier 1904 (+2 082 844 800 secondes vs Unix)
  • Alternate VH : à −1024 octets depuis la fin du volume
  • CNID racine : 2
  • Catalog File : source primaire des métadonnées, B-Tree
  • Resource fork : forkType 0xFF · data fork : 0x00
  • AppleDouble (fichiers ._name) = traces macOS sur volumes non-HFS
