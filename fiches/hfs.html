Citation
"HFS+ volumes contain rich metadata structures including B-Tree catalogs that store full path history, creation events, and resource forks — often revealing more than the user intended to preserve."
— Apple Inc., Technical Note TN1150: HFS Plus Volume Format, 2004
🍎 Fun fact : HFS a été créé en 1985 pour le Mac 512K. Il ne supportait que 65536 fichiers par volume. En 2017, Apple a enfin migré vers APFS — 32 ans après. La forensique des vieux Macs reste donc pertinente sur une carrière entière d'enquêteur.

Volume Header (offset 1024)
  • Signature : 0x482B = 'H+' (HFS+)
  • Signature journalisé : 0x4858 = 'HX'
  • Taille : 512 octets
  • Contient : taille volume, nombre blocs, timestamps création/modification
  • Alternate VH : −512 octets depuis la fin du volume
CNID — Catalog Node ID
  • Identifiant unique de chaque objet (≈ inode EXT)
  • CNID 1 : parent fictif de la racine
  • CNID 2 : répertoire racine du volume
  • CNID 3 : Extents Overflow File
  • CNID 4 : Attributes File
  • CNID 5 : Startup File
  • CNIDs normaux ≥ 16. Persistant même si le fichier est renommé.

Suppression HFS+ et récupération
1
L'entrée du Catalog File B-Tree est supprimée. Mais les nœuds B-Tree non réalloués peuvent contenir des entrées résiduelles avec les métadonnées complètes.
2
Les blocs sont marqués libres dans l'Allocation File (bitmap). Données non effacées jusqu'à réallocation.
3
Si journalisation active : le journal peut contenir des versions antérieures des métadonnées. X-Ways 20.3+ supporte l'analyse directe des structures HFS+.
APFS — Apple File System (depuis 2017)
Nouveautés APFS vs HFS+
  • Snapshots : états du volume à un instant T (copy-on-write)
  • Clones : copies sans duplication immédiate des données
  • Chiffrement multi-clés natif (par fichier ou par volume)
  • Optimisé SSD/Flash : réduction de l'usure
  • Container partagé entre plusieurs volumes
Valeur forensique APFS
  • Snapshots Time Machine : versions antérieures de fichiers chiffrés
  • X-Ways 20.3+ : analyse B-Trees APFS, fichiers supprimés, snapshots
  • Chiffrement → impossible sans clé (iCloud peut contenir la clé)
  • Mactime précision nanoseconde
Extents Overflow : clé = (forkType + CNID + startBlock). forkType 0x00 = data fork, 0xFF = resource fork.
Resource Fork : données Mac classiques (icônes, ressources). Présence = ancien système ou application rosettified.
💡 Tip : Sur Mac saisi avec chiffrement FileVault actif, la clé est en RAM. La capturer avant extinction. Si macOS est verrouillé : mode DFU ou accès iCloud Recovery Key.
