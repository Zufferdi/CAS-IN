Microsoft 365 Forensique — Du Unified Audit Log au compromis BEC

80% des entreprises suisses utilisent Microsoft 365. Quand un compromis arrive (BEC, exfiltration, prise de contrôle), la forensique cloud remplace la forensique disque traditionnelle. Comprendre le Unified Audit Log, les sign-ins Azure AD, eDiscovery et MailItemsAccessed est devenu une compétence critique en DFIR moderne.
Prérequis : 📖 Cloud Forensics 📖 Email Forensics 📖 Réseau 📖 Droit pénal CH

🌐 Le paysage M365 — qu'est-ce qui produit des logs ?
Microsoft 365 n'est pas un produit unique mais une fédération de services, chacun avec ses logs propres. La forensique consiste à croiser ces sources pour reconstruire un fil d'événements.
ServiceLogs principauxRétention défaut
Azure AD / Entra ID Sign-in logs, Audit logs, Risk events, Provisioning logs 30 jours (free), 30j-2 ans (P1/P2)
Exchange Online Message Trace, Mailbox Audit, Transport logs 10 jours (Trace), 90 jours (Audit défaut)
SharePoint / OneDrive SharePoint Audit, OneDrive activity 180 jours (E3+), 1 an (E5)
Teams Teams Admin Center logs, Call records 30 jours (admin events), variable (messages)
Defender for Cloud Apps App connector logs, Anomaly detection 180 jours
Microsoft Purview Compliance audit, eDiscovery, DLP 180 jours-10 ans (selon plan)
Unified Audit Log ⭐ Agrégateur de TOUS les services ci-dessus 180 jours (E3), 1 an (E5), 10 ans (E5 add-on)

⭐ Unified Audit Log — la pierre angulaire

📋 Le Unified Audit Log (UAL)
Le UAL est la source n°1 en M365 forensics. Il agrège les événements d'Exchange, SharePoint, OneDrive, Teams, Azure AD, Power Platform, Defender, Purview, en un seul flux interrogeable.

Activation : obligatoire avant analyse ! Vérifier dans le portail Compliance / Purview ou via PowerShell : 
# Connexion à Exchange Online
Connect-ExchangeOnline -UserPrincipalName admin@tenant.onmicrosoft.com

# Vérifier si UAL est activé
Get-AdminAuditLogConfig | Format-List UnifiedAuditLogIngestionEnabled

# Si False, activer (rétroactivité = 0 ! les événements passés sont perdus)
Set-AdminAuditLogConfig -UnifiedAuditLogIngestionEnabled $true

# Recherche de base
Search-UnifiedAuditLog `
  -StartDate "2024-01-01 00:00" `
  -EndDate "2024-01-31 23:59" `
  -UserIds "victim@company.ch" `
  -ResultSize 5000

# Recherche par opération (BEC typique : règles de boîte)
Search-UnifiedAuditLog -StartDate "2024-01-01" -EndDate "2024-02-01" `
  -Operations "New-InboxRule","Set-InboxRule","UpdateInboxRules"

# Export vers CSV pour analyse
$results = Search-UnifiedAuditLog -StartDate "2024-01-01" -EndDate "2024-01-31" -ResultSize 5000
$results | Export-Csv -Path "ual_export.csv" -NoTypeInformation -Encoding UTF8
⚠️ Pièges du UAL :
  • Rétroactivité zéro : si UAL désactivé au moment des faits, événements perdus à jamais.
  • Latence d'ingestion : 30 minutes à 24 heures (rarement plus). Vérifier le timestamp CreationDate.
  • 5000 résultats max par requête : utiliser -SessionCommand ReturnLargeSet + -SessionId pour paginer.
  • Format JSON imbriqué dans la colonne AuditData : parser avec ConvertFrom-Json.
  • Rétention finie : 180 jours en E3, exporter rapidement après détection.

📧 MailItemsAccessed — l'événement clé BEC

🔍 Pourquoi MailItemsAccessed est crucial
Lors d'un compromis de boîte mail (Business Email Compromise), la question n°1 est : "qu'est-ce que l'attaquant a lu ?". Avant 2019, il était quasi impossible de répondre à cette question. Microsoft a introduit l'événement MailItemsAccessed pour résoudre ce problème.
  • Disponible avec licence E5 ou Microsoft Defender for Office 365 P2
  • Active Mailbox Auditing by default depuis janvier 2019
  • Enregistre chaque accès à un email — interface, MAPI, EWS, REST API, mobile
  • Capture le InternetMessageId = identifiant unique de l'email accédé
# Vérifier que Mailbox Audit est activé pour le user
Get-Mailbox -Identity victim@company.ch | Format-List Audit*

# Activer si nécessaire
Set-Mailbox -Identity victim@company.ch -AuditEnabled $true

# Recherche des MailItemsAccessed sur une période
Search-MailboxAuditLog -Identity victim@company.ch `
  -StartDate "2024-01-15" -EndDate "2024-01-20" `
  -Operations MailItemsAccessed -ResultSize 5000 -ShowDetails

# Filtrer par type d'accès (Sync = Outlook desktop, Bind = un par un)
Search-UnifiedAuditLog -StartDate "2024-01-15" -EndDate "2024-01-20" `
  -UserIds victim@company.ch -Operations MailItemsAccessed |
  Select CreationDate, UserIds, ClientIP, Operations, AuditData
🎯 Lecture des résultats :
  • OperationProperties.MailAccessType = Bind (lecture individuelle, app type Outlook/OWA) ou Sync (synchronisation client mobile/desktop)
  • Folders contient la liste des dossiers accédés avec FolderItems[].InternetMessageId
  • ClientIPAddress = IP de l'attaquant (souvent pivot vers VPN, Tor, ou hosting)
  • ClientInfoString = User-agent, peut révéler l'outil (ex: "Client=REST;ApiVersion=Beta..." pour scripts MS Graph)

🔐 Azure AD Sign-in Logs — qui s'est connecté ?

🚪 Les portes d'entrée tracées
Toute authentification réussie ou échouée est journalisée dans Azure AD. Critique pour détecter :
  • Compromis de credentials (login depuis nouveau pays/IP)
  • MFA bypass / fatigue MFA
  • Token theft / Pass-the-Cookie
  • Impersonation via tokens OAuth
Type de logContenuCas d'usage
Sign-in logs Authentifications interactives & non-interactives, MFA result, IP, location, device, app cible Détection de compromis, forensique BEC
Audit logs Modifications administrateur (création user, ajout d'app, changement de policy) Détection de persistence, escalade de privilèges
Risk events Détections heuristiques : impossible travel, anonymous IP, leaked credentials Triggers de Conditional Access, scoring
Provisioning logs Synchronisations vers/depuis SaaS tiers Détection d'apps OAuth malicieuses 
# Connexion via Microsoft Graph PowerShell
Connect-MgGraph -Scopes "AuditLog.Read.All","Directory.Read.All"

# Sign-ins dans une fenêtre temporelle
Get-MgAuditLogSignIn -Filter "createdDateTime ge 2024-01-15T00:00:00Z and createdDateTime le 2024-01-20T23:59:59Z and userPrincipalName eq 'victim@company.ch'" `
  -Top 1000

# Sign-ins échoués (potentiel password spray)
Get-MgAuditLogSignIn -Filter "status/errorCode ne 0" -Top 500 |
  Group-Object {$_.IpAddress} | Sort Count -Descending | Select -First 20

# Audit logs (changements admin)
Get-MgAuditLogDirectoryAudit -Filter "activityDateTime ge 2024-01-15" -Top 100

🔎 Microsoft Purview eDiscovery — collecte légale

⚖️ eDiscovery — la voie "officielle" de collecte
Microsoft Purview eDiscovery (anciennement Office 365 Compliance Center) est l'outil légalement préservant pour collecter du contenu (mails, fichiers, Teams, SharePoint) à des fins judiciaires ou réglementaires.
TierCapacitésQuand l'utiliser
Content Search Recherche cross-services, export PST/CSV/JSON Triage initial, recherche par mot-clé
eDiscovery (Standard) Cas, custodians, holds (legal hold) Inclus E3, suffisant pour la plupart des cas
eDiscovery (Premium) Workflow complet : custodian notice, OCR, ML relevance, redactions, review sets E5 add-on. Litiges complexes, GDPR DSAR à grande échelle
✅ Avantages forensiques d'eDiscovery :
  • Preservation Hold : empêche la suppression du contenu pendant l'enquête (durci la chaîne de custody)
  • Hash de l'export : SHA-256 fourni automatiquement par Microsoft
  • Manifest XML : décrit chaque item collecté (date, source, custodian)
  • Format PST directement importable dans Outlook ou un parser forensique
  • Légalement reconnu par les juridictions US, EU, CH

🚨 Attaques typiques M365 — playbook IR

📧 Business Email Compromise (BEC)
Scénario : phishing → vol de credentials → connexion attaquant → règle de redirection invisible → interception de facture → fraude au virement (souvent ~50-500k CHF en Suisse).

Indicateurs à chercher :
  • New-InboxRule ou Set-InboxRule avec critères (forward to external, delete, mark as read) — très suspect
  • Sign-ins depuis pays inhabituel sans MFA (souvent VPN résidentiel)
  • MailItemsAccessed sur des mails contenant des mots clés (factures, IBAN, CHF)
  • UserLoggedIn avec ApplicationId non standard (apps OAuth abusées)
  • Nouvelles authentifications MFA enregistrées (UserRegisteredSecurityInfo)
🎫 Token theft / Pass-the-Cookie
L'attaquant vole un cookie de session (via stealer malware ou AitM proxy comme Evilginx) et bypasse la MFA. La session est valide jusqu'à expiration (typiquement 60-90 minutes pour les tokens d'accès, 90 jours pour les refresh tokens).

Détection :
  • Sign-in logs : AuthenticationProtocol = "OAuth2" + UserAgent incohérent
  • Risk events : "Anomalous token", "Token issuer anomaly"
  • Multiple ClientIP pour la même session token (ID identique)
  • Vérifier UniqueTokenIdentifier dans les sign-ins
🔓 Apps OAuth malicieuses
L'utilisateur clique sur un lien "Login with Microsoft" qui demande des permissions excessives à une app tierce. Une fois consentie, l'app a accès à son mail/files/Teams sans MFA.

Détection :
  • Add-ServicePrincipal dans Audit Logs
  • Add OAuth2PermissionGrant avec scopes Mail.Read, Files.Read.All, offline_access
  • Dans Microsoft Defender : Cloud App Discovery
  • Liste des apps : Get-MgServicePrincipal -Filter "displayName eq 'app suspicious'"

🔌 Microsoft Graph API — collecte programmatique

🔧 Quand UAL ne suffit plus
Pour des cas complexes (volumes énormes, automation, intégration SIEM), Microsoft Graph permet l'accès programmatique à toutes les données. 
# Authentification app-only avec un certificat
Connect-MgGraph -ClientId "" `
  -TenantId "" `
  -CertificateThumbprint ""

# Lister les emails d'un user (nécessite Mail.Read)
Get-MgUserMessage -UserId victim@company.ch -Top 100 |
  Select Id, Subject, From, ReceivedDateTime, BodyPreview

# Récupérer une boîte mail complète (export EML par item)
$messages = Get-MgUserMessage -UserId victim@company.ch -All
$messages | ForEach-Object {
    Get-MgUserMessageContent -UserId victim@company.ch -MessageId $_.Id `
      -OutFile "exports\$($_.Id).eml"
}

# Lister les apps OAuth consenties par les users
Get-MgUserOauth2PermissionGrant -UserId victim@company.ch
🛡️ Permissions Graph à connaître : AuditLog.Read.All, Mail.Read ou Mail.ReadBasic.All, Files.Read.All, Directory.Read.All, SecurityEvents.Read.All. Toujours utiliser app-only avec accès limité (just-in-time si possible) et journaliser les requêtes.

🛡️ Microsoft Defender XDR & Sentinel

ProduitCouvreLogs disponibles
Defender for Office 365 Email (anti-phishing, anti-malware), liens cliqués UrlClickEvents, EmailEvents, EmailAttachmentInfo
Defender for Identity Active Directory (domain controllers on-prem) IdentityLogonEvents, IdentityDirectoryEvents
Defender for Endpoint Postes de travail Windows/Mac/Linux DeviceProcessEvents, DeviceFileEvents, DeviceNetworkEvents

🔍 Hunting via KQL : Defender XDR et Sentinel utilisent Kusto Query Language. Exemple de hunting BEC : 
// KQL : sign-ins depuis IP suspectes + création de règle inbox dans la même heure
let suspiciousLogins = SigninLogs
| where TimeGenerated > ago(7d)
| where ResultType == 0  // succès
| where IPAddress !startswith "192.168" and IPAddress !startswith "10."
| project TimeGenerated, UserPrincipalName, IPAddress, City=Location;
let inboxRules = CloudAppEvents
| where TimeGenerated > ago(7d)
| where ActionType in ("New-InboxRule","Set-InboxRule");
suspiciousLogins
| join kind=inner inboxRules on $left.UserPrincipalName == $right.AccountObjectId
| where abs(datetime_diff('minute', TimeGenerated, TimeGenerated1)) < 60
| project User=UserPrincipalName, LoginIP=IPAddress, City, RuleAction=ActionType, RuleTime=TimeGenerated1

⚠️ Limitations & pièges récurrents

Les 7 pièges classiques en M365 forensics :
  1. UAL non activé au moment du compromis → données perdues sans rétroactivité
  2. MailItemsAccessed nécessite licence E5 — si le client a E3, on ne saura pas ce que l'attaquant a lu
  3. Suppression rapide : un attaquant peut supprimer ses traces dans Inbox Rules avant ton arrivée. Vérifier l'historique des règles via UAL et non leur état actuel.
  4. Légère désync timestamps entre services (UAL vs Sign-in vs Mailbox Audit) — toujours noter la timezone (UTC) et arrondir à la minute
  5. 5000 résultats max par requête UAL : utiliser pagination ou exporter au plus tôt
  6. SDK PowerShell Connect-IPPSSession est en dépréciation — utiliser Connect-ExchangeOnline pour la nouvelle Compliance Center
  7. Identités hybrides (AD on-prem + AAD) : événements peuvent venir de l'on-prem (DC) sans apparaître dans Sign-in logs cloud. Croiser avec Event Logs Windows.

⚖️ Cadre juridique suisse

🇨🇭 Particularités M365 en Suisse
Microsoft a ouvert depuis 2019 des datacenters en Suisse (Genève + Zurich). Les clients M365 peuvent demander que leurs données au repos soient stockées en CH. Cela ne dispense PAS de la réquisition via réseau Microsoft Corp.
Article / RègleApplication M365
Art. 263 CPP Séquestre logique des comptes M365 (via réquisition Microsoft Suisse)
Art. 269 CPP Surveillance live = monitoring en temps réel des emails (très restreint)
Art. 273 CPP Données accessoires de communication = sign-in logs, headers email métadonnées
Art. 67 EIMP Si données chez Microsoft Corp (US), passer par MLAT US-CH
Art. 22 LPD Données de santé, croyance, opinions politiques dans les mails = catégories sensibles
nLPD art. 24 Notification d'incident dans les 72h en cas de compromis (BEC = compromis)
FINMA Circ. 2008/21 Banques : reporting des cyberincidents M365 dans les 24h
art. 248 CPP (scellés) Avocats, médecins, journalistes : leur boîte M365 peut être mise sous scellés
📌 Workflow Suisse typique en cas de BEC :
  1. Détection (souvent par la banque qui voit le virement)
  2. Plainte pénale (art. 146 CP escroquerie + art. 143 CP soustraction de données)
  3. Réquisition à l'entreprise (art. 265 CPP)
  4. L'entreprise mandate un expert privé (Compass, Quovadis, etc.) qui collecte UAL/Sign-ins via comptes admin avec PowerShell ou eDiscovery
  5. Hash + manifest + chaîne de custody
  6. Si suspect identifié à l'étranger : EIMP via OFJ Berne
  7. Procureur cantonal (Polcyber) coordonne
⚖️ Examen CAS-IN — points clés M365 :
  • Unified Audit Log (UAL) = source n°1, à activer AVANT incident (rétroactivité = 0)
  • Rétention UAL : 180j (E3), 1 an (E5), 10 ans (E5 + Audit add-on)
  • MailItemsAccessed : seul moyen de savoir ce qu'a lu un attaquant — nécessite E5
  • Bind = lecture individuelle (OWA), Sync = synchro mobile/desktop
  • InboxRules suspectes = signature BEC classique
  • Sign-in Logs Azure AD = qui s'est connecté, depuis où, avec quelle MFA
  • Token theft via AitM (Evilginx) = bypass MFA, détectable via UniqueTokenIdentifier
  • eDiscovery = collecte légalement préservante (PST + manifest + hash)
  • Microsoft Graph = collecte programmatique (Mail.Read, Files.Read.All)
  • nLPD art. 24 = notification dans les 72h en cas de compromis
