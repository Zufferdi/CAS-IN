🔢 Encodage — Le langage du forensiste
Au plus bas niveau, tout n'est qu'octets. Le caractère « A » que vous voyez à l'écran, votre photo de vacances, le mot de passe en cache — tout est une suite de bits dans un fichier ou en RAM. Le forensiste qui lit un disque bit-à-bit doit comprendre comment une même valeur peut être stockée différemment selon le contexte : (1) Bases de numération — binaire (010101), décimal (42), hexadécimal (0x2A) — la même chose, écriture différente. (2) Endianness (boutisme) — l'ordre des octets en mémoire diffère entre architectures Intel x86 (little-endian, octet poids faible d'abord) et SPARC/PowerPC (big-endian, poids fort d'abord). Une signature MBR 0x55AA apparaît comme AA 55 sur le disque. (3) Encodage de caractères — ASCII (7 bits, anglais), Latin-1 (8 bits, accents EU), UTF-8 (1-4 octets, universel — domine le web). (4) Complément à 2 — méthode universelle de représentation des nombres signés. (5) Encodages dérivés — Base64 (binaire → ASCII printable, +33% de taille), URL encoding, hexdump. Maîtriser ces fondations est indispensable avant de plonger dans les magic bytes, les structures NTFS, ou les protocoles réseau.

Encodages de caractères
ASCII — 1 byte par caractère

128 caractères (0–127). Lettres A–Z (41–5A), a–z (61–7A), 0–9 (30–39).
Mnémotechnique : A = 65 = 0x41 · a = 97 = 0x61 (diff = 32 = 0x20)

UTF-8 — 1 à 4 bytes

Compatible ASCII pour les 128 premiers. Europe occidentale = 2 bytes. Asiatiques = 3 bytes. Le plus utilisé sur le web et Linux. Encodage variable.

🧠 Testez-vous
Vous trouvez à l'offset 0x1FE d'un disque les octets 55 AA. Que signifie cette signature et pourquoi est-elle stockée dans cet ordre ?Endianness · Niveau : facile
Signature MBR (Master Boot Record) aux offsets 510-511 (=0x1FE-0x1FF). La valeur mathématique est 0xAA55 (43605 en décimal). Mais comme les disques PC sont en architecture Intel x86 = little-endian, l'octet de poids faible en premier : 0x55 (poids faible) puis 0xAA (poids fort) sur le disque. Cette signature est obligatoire — sans elle, le BIOS affiche « No bootable device found ». Forensiquement : (a) sa présence confirme un MBR valide, (b) son absence ou sa modification = corruption ou disque non bootable, (c) sur un disque GPT, le LBA 0 contient un « Protective MBR » qui conserve cette signature mais avec une seule entrée de partition de type 0xEE. Vérification : xxd -s 510 -l 2 disk.img doit afficher 55aa. Erreur classique : chercher aa55 et ne rien trouver — c'est 55aa sur le disque. Ne jamais oublier l'inversion little-endian quand on lit du hex brut.
Convertissez le caractère « é » dans son encodage UTF-8 et expliquez pourquoi il prend 2 octets.UTF-8 · Niveau : moyen
« é » en UTF-8 = 0xC3 0xA9 (193, 169 décimal). Pourquoi 2 octets ? UTF-8 est variable : (1) Les 128 premiers caractères ASCII (U+0000 à U+007F) tiennent dans 1 octet (compatibilité ASCII pure). (2) Caractères Unicode U+0080 à U+07FF (Latin étendu, grec, cyrillique, arabe, hébreu) prennent 2 octets avec préfixe 110xxxxx 10xxxxxx. (3) U+0800 à U+FFFF (chinois, japonais, coréen, etc.) = 3 octets. (4) U+10000 à U+10FFFF (emojis 🎉, alphabets rares) = 4 octets. « é » a le code Unicode U+00E9 (233 décimal). Étant entre 0x80 et 0x7FF, il est encodé sur 2 octets : binaire 233 = 11101001 → réparti en deux groupes : 00011 101001 → préfixés 110 et 10 → 11000011 10101001 = 0xC3 0xA9. Forensiquement : voir C3 A9 dans un dump = caractère « é » = probablement texte français/européen. Comparaison : Latin-1 stockait « é » sur 1 octet 0xE9, mais Latin-1 est limité à 256 caractères. UTF-8 est devenu standard depuis ~2010 et est utilisé par 98% des pages web aujourd'hui.
Vous trouvez la chaîne SGVsbG8sIFdvcmxkIQ== dans un email. Qu'est-ce et comment la décoder ?Base64 · Niveau : facile
C'est du Base64. Indices : (1) caractères dans l'alphabet [A-Za-z0-9+/] + padding =, (2) longueur multiple de 4, (3) terminaison == (padding indiquant que la longueur originale n'était pas multiple de 3 octets). Décodage : echo "SGVsbG8sIFdvcmxkIQ==" | base64 -d → Hello, World!. Comment fonctionne Base64 : (a) prend 3 octets binaires (24 bits), (b) les divise en 4 groupes de 6 bits, (c) chaque groupe de 6 bits (0-63) devient un caractère parmi A-Z a-z 0-9 + /. Conséquence : taille augmente de +33% (4 chars pour 3 octets). Pourquoi utilisé : transporter du binaire dans des protocoles texte (email SMTP, JSON, HTTP basic auth, attachments). Forensique : indice probable de : (1) fichier binaire encodé dans email, (2) image inline dans HTML (data:image/png;base64,...), (3) malware obfusqué (PowerShell -EncodedCommand), (4) tokens/JWT (3 parties séparées par .), (5) clés cryptographiques exportées. Variantes : Base64URL (utilise -_ au lieu de +/) pour URLs, Base32 (alphabet plus restreint), Base58 (Bitcoin, sans caractères ambigus 0/O).
Quelle valeur décimale a l'octet signé 0xFF en complément à 2 sur 8 bits ?Complément à 2 · Niveau : moyen
-1. Le complément à 2 est la méthode standard universelle pour représenter les nombres signés. Principe : sur 8 bits, le bit de poids fort est le « bit de signe » (0 = positif, 1 = négatif). Plage : -128 à +127 (vs 0-255 en non signé). Calcul pour 0xFF : (1) en binaire = 11111111, (2) bit de signe = 1 → négatif, (3) inverser tous les bits : 00000000, (4) ajouter 1 : 00000001 = 1, (5) appliquer le signe négatif → -1. Tableau utile : 0x7F = +127 (max positif) · 0x80 = -128 (min négatif) · 0xFF = -1 · 0xFE = -2. Pourquoi le complément à 2 ? Il permet d'utiliser le même circuit d'addition pour les nombres signés et non-signés : 0xFF + 0x01 = 0x00 avec retenue (= -1+1=0). C'est le système utilisé par tous les CPU modernes (x86, ARM, RISC-V…). Forensiquement : faire attention quand on lit des champs « valeur signée » dans des structures binaires — un offset de 0xFFFF FFFC en 32 bits signé = -4, pas un grand nombre positif.
🎓 Exam Tip — Encodage Bas Niveau

Bases de numération :

  • Binaire (base 2) — bits 0 et 1

  • Octal (base 8) — rare en forensique moderne

  • Décimal (base 10) — humain

  • Hexadécimal (base 16) — base de référence forensique · 1 octet = 2 hex digits

Tailles standards :

  • bit · octet (byte) = 8 bits · word = 16 bits · dword = 32 bits · qword = 64 bits

  • KB / MB / GB (puissances de 10) vs KiB / MiB / GiB (puissances de 2)

Endianness :

  • Little-endian = poids faible en premier (Intel x86/x64) · disques NTFS · FAT

  • Big-endian = poids fort en premier · réseau (network byte order) · SPARC · IBM

  • MBR signature 0xAA55 → stockée 55 AA sur disque (LE)

Encodages caractères :

  • ASCII 7 bits · 'A' = 0x41 = 65 · 128 caractères max

  • Latin-1 8 bits · 256 chars · accents EU

  • UTF-8 1-4 octets · universel · domine le web · 'é' = C3 A9

  • UTF-16 2 ou 4 octets · interne Windows · BOM FF FE (LE)

Encodages de transport :

  • Base64 : 3 octets → 4 chars · alphabet A-Z a-z 0-9 +/ · padding =

  • URL encoding : %xx hex (espace = %20)

  • Hex dump : représentation textuelle de binaire

Complément à 2 : nombres signés · 0xFF = -1 (8 bits) · plage [-128, +127]

XOR : opération réversible · A⊕A=0 · A⊕0=A · A⊕B⊕B=A (utilisé en crypto + obfuscation)

🎯 Essentiel terrain : Little-endian = octet de poids faible en premier (Intel) · Big-endian = poids fort d'abord (réseau, network byte order) · MBR signature 0xAA55 stockée 55 AA sur le disque · Base64 : 3 octets → 4 caractères · ASCII 'A' = 0x41 = 65 · UTF-8 'é' = C3 A9 · Complément à 2 : 0xFF = -1 sur 8 bits · XOR propriétés : A⊕A=0, A⊕0=A.
