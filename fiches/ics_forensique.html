⚙️ Industrial Control Systems

ICS/SCADA Forensique

⚠️ Différence fondamentale avec l'IT : un incident ICS peut entraîner des dégâts physiques, des risques pour la sécurité humaine et environnementale. La réponse sur incident est un effort joint entre cyber-analystes, ingénieurs procédés, opérateurs, et architectes réseau. La safety (sécurité physique) prime toujours sur la security (cybersécurité).

📡 Protocoles industriels clés

Modbus TCP port 502
tshark -Y "modbus" -r capture.pcap
Protocole le plus répandu (1979, Modicon). Aucune authentification, aucun chiffrement par défaut. Function Code 5 = Force Single Coil (déclencheur d'actionneur). Wireshark a un excellent dissector intégré. Dans un PCAP, identifier HMI ↔ PLC par les patterns request/response.
DNP3 port 20000
tshark -Y "dnp3" -r capture.pcap
Distributed Network Protocol — utilisé surtout dans l'énergie (smart grids, postes électriques). Supporte l'authentification Secure Authentication v5 (rare en pratique). Reconnaissable au pattern octet de start 0x05 0x64.
IEC 61850 multicast L2
tshark -Y "goose || sv" -r capture.pcap
Standard IEC pour postes électriques (Suisse : Swissgrid). GOOSE = trame multicast L2 ultra-rapide (< 4 ms) pour protection. SV = Sampled Values (échantillons de mesure 4 kHz). Pas de routage — confinés à un VLAN.
OPC-UA port 4840
tshark -Y "opcua" -r capture.pcap
Protocole moderne, sécurisé par design (TLS, signature, AES). Recommandé par BSI/IEC 62443. Coexiste avec Modbus en pratique sur les sites en transition. Détection de tunneling possible via l'analyse SecureChannel.
EtherNet/IP ports 44818 + 2222 UDP
tshark -Y "enip || cip" -r capture.pcap
Allen-Bradley/Rockwell — implicite, pas de lien avec Internet IP. CIP (Common Industrial Protocol) encapsulé. Souvent en environnements automobile, agro, fabrication US.
S7comm port 102
tshark -Y "s7comm" -r capture.pcap
Siemens propriétaire (S7-300/400/1200/1500). Pas d'authentification jusqu'à S7-1500 récents. Stuxnet (2010) ciblait spécifiquement S7-300/400 via injection de DB et OB. Ports 102 (TPKT/COTP) et 4840 (OPC-UA) coexistent souvent.

🔍 Network Security Monitoring ICS

Méthodes de capture passive

L'ICS NSM est strictement passif — toute action active risque de perturber le procédé. Deux options :

  • Network TAP (hardware) — duplique le trafic en hardware, fail-open obligatoire (si le TAP plante, le trafic passe encore). Installation : exige une fenêtre d'arrêt.
  • Port SPAN (mirror sur switch managé) — pas d'arrêt requis, mais peut perdre des paquets si CPU/RAM du switch saturés. Activer un VLAN à la fois.

Configuration SPAN typique (Cisco IOS)

# monitor session 1 source interface gi1/1 both # monitor session 1 destination interface gi1/2 # show monitor all

Capture bidirectionnelle de gi1/1 vers la sonde NSM connectée à gi1/2. Adapter aux conventions du fabricant (Hirschmann, Moxa, Stratix, etc.).

Niveau de capture : 5-tuple vs full packet

TypeContenuStockageCas d'usage
5-tuple IPFIXIP src/dst, port src/dst, protoFaible (~1 % du PCAP)Détection anomalies à long terme
Full Packet CaptureTout le payloadÉlevé (~10-100 GB/jour)Forensique post-incident, extraction fichiers

Stratégie pragmatique : IPFIX en continu sur tous les niveaux, full PCAP sur les chokepoints (frontière IT/OT, autour HMI critiques) avec rotation 7-30 jours.

🚨 Règles de détection ICS (Suricata/Snort pseudocode)

Communications interdites vers PLC

alert tcp !$Modbus_HMI any -> $Modbus_PLC any \ (msg:"COMMS DIRECTES VERS PLC NON-HMI"; sid:1000001;)

En production normale, seul le HMI doit communiquer avec le PLC. Toute autre source = scan, exfiltration, ou pivot d'attaquant.

Scan/usage Modbus sur réseau qui n'en a pas

alert tcp any any -> any 502 \ (msg:"SCAN OU USAGE MODBUS-TCP NON ATTENDU"; sid:1000002;)

Si ton inventaire ne liste aucun équipement Modbus, toute connexion port 502 est suspecte (recon).

Connexion vers C2 connu

alert tcp any any -> [evil_c2_ip] any \ (msg:"CONNEXION VERS C2 INDUSTROYER/PIPEDREAM"; sid:1000003;)

Compléter avec les IOC publiés par les CERT sectoriels (ICS-CERT, MELANI/NCSC en Suisse).

🎒 ICS IR Jump Bag

Le jump bag ICS est physique — souvent dans une mallette roulante stockée sur site. Il contient des outils utilisables même quand l'infrastructure est compromise (mode avion forcé).

🛠️ Outils techniques

  • Acquisition mémoire prioritaire (winpmem, FTK Imager Lite)
  • Laptops avec Security Onion, REMnux, SIFT Workstation
  • Outils malware : statique (PE Studio, CFF Explorer) + sandbox
  • Hashes de logiques/configs PLC de référence (signature avant incident)
  • Images baseline des assets critiques
  • Wireshark + dissectors ICS (Modbus, DNP3, IEC 61850, S7comm)

🎒 Matériel physique

  • Câbles de conversion (USB ↔ Serial, USB ↔ RS-485)
  • Radio handheld hors-bande (pas de réseau IP)
  • USB et disques forensiquement propres
  • EPI safety (casque, chaussures, gilet)
  • Certificats de formation safety du site
  • Caméra numérique sans métadonnées GPS

📞 Contacts & documentation

  • Contacts safety, ingénieurs procédé, intégrateurs
  • Schémas réseau imprimés (papier, pas PDF !)
  • Playbooks IR ICS imprimés
  • Numéros d'astreinte fournisseurs (Siemens, Schneider, ABB, etc.)
  • Coordonnées MELANI/NCSC Suisse en cas d'incident IIC

🇨🇭 Spécificités suisses

Cadre légal IIC (Infrastructures d'importance critique)

  • Loi sur la sécurité de l'information (LSI), art. 73-78 — devoir d'annonce des cyberincidents pour les exploitants d'IIC.
  • OFCS (Office fédéral de la cybersécurité) — successeur du NCSC depuis 2024 — est l'autorité de signalement.
  • Délai d'annonce : 24 heures à compter de la connaissance de l'incident (loi du 1er avril 2025).
  • Secteurs IIC : énergie (Swissgrid, BKW, Axpo), eau, transports (CFF), télécoms (Swisscom), santé, finance.

Coopération supra-cantonale

Pour des incidents touchant plusieurs cantons (par ex. cascade sur stations d'épuration), fedpol et le Ministère public de la Confédération (MPC) peuvent ouvrir une enquête. Voir aussi Autorités & compétences CH.

🎯 IR ICS — En pratique

Étape 1 — Triage
Compare hashes config/logique PLC vs baseline
Cherche IOC (IP, hash, comportement) dans logs
Acquisition mémoire en priorité (volatile !)
Étape 2 — Containment
Bascule en mode manuel si possible (opérateur prend le contrôle)
Bloque le C2 (firewall périmètre)
Désactive les accès distants vendeurs
Étape 3 — Eradication
⚠️ Uniquement quand opérations/safety le permettent
Re-flash PLC depuis baseline signée
Reconstruction HMI/SCADA depuis ISO certifié
Étape 4 — Lessons learned
Mise à jour ICS IR Plan
Tabletop trimestriel obligatoire
Gap analysis NSM & controls

⚠️ Pièges spécifiques ICS

  • Ne JAMAIS scanner activement un PLC en production — un nmap mal configuré peut faire crasher un PLC et arrêter une chaîne entière (cas documentés Allen-Bradley, Siemens).
  • Pas de mise à jour antivirus en plein procédé : un EDR mal calibré peut quarantainer un fichier de configuration et planter un HMI.
  • Legacy devices : nombreux PLC tournent depuis 15-20 ans avec des OS qui ne reçoivent plus de patches. La sécurité repose sur l'isolement réseau, pas sur le patching.
  • Vendor lock-in : Siemens, Rockwell, Schneider imposent souvent des outils propriétaires — la collaboration vendeur est vitale en IR.
  • Safety > Security : si une action de containment risque de provoquer un accident, on ne la fait pas. Documenter le compromis.

💊 Auto-évaluation

Tu interviens sur un incident sur un poste électrique. Le RSSI demande de "scanner toutes les IP du VLAN OT pour trouver le malware". Que réponds-tu ?ICS · Niveau : moyen
Refuser et expliquer. Un scan actif (même nmap -sT) peut crasher un PLC en production et provoquer un déclenchement non sollicité (perte de courant, accident). À la place : capturer passivement le trafic via SPAN/TAP, comparer hashes des configs PLC à la baseline, analyser logs HMI. Toujours préférer le passif au risque opérationnel.
Sur un capture PCAP en provenance d'une chaîne de production, tu identifies du trafic Modbus TCP entre 10.20.0.5 (HMI connu) et 10.20.0.42. Plus tard tu vois aussi du trafic Modbus depuis 10.20.0.99 (jamais vu) vers 10.20.0.42. Que conclus-tu ?ICS · Niveau : facile
Très probable compromission ou pivot d'attaquant. En ICS, le PLC ne devrait recevoir d'ordres que d'un HMI inventorié. Une nouvelle source qui parle Modbus = soit poste légitime non documenté (corriger l'inventaire), soit poste compromis utilisé pour reconnaissance ou injection. Action immédiate : isoler 10.20.0.99 via VLAN, capturer ses communications, analyser la machine.
Pourquoi est-il obligatoire qu'un Network TAP installé sur une ligne de communication ICS soit fail-open ?ICS · Niveau : facile
Si le TAP tombe en panne en mode fail-closed, il coupe la communication entre le HMI et le PLC, ce qui peut déclencher un arrêt d'urgence ou une perte de visibilité opérateur. En fail-open, la panne du TAP n'affecte pas le trafic légitime — la sonde NSM perd juste sa visibilité, ce qui est un compromis acceptable (safety > security).
🎓 Exam Tip — ICS Forensique

Modèle Purdue : 5 niveaux (5 = ERP, 0 = procédé physique). Frontière IT/OT entre N4 et N3 = chokepoint NSM critique.

Protocoles : Modbus (port 502, sans auth) · DNP3 (énergie) · IEC 61850 (postes électriques, GOOSE/SV) · OPC-UA (moderne, TLS) · S7comm (Siemens, port 102) · EtherNet/IP (Rockwell)

Attaques historiques : Stuxnet (2010, S7) · BlackEnergy (2015, Ukraine) · Industroyer (2016) · TRITON/Trisis (2017, Schneider Triconex SIS) · CrashOverride · PipeDream (2022, multi-vendeur)

Standards : IEC 62443 (cybersécurité ICS) · NERC CIP (énergie US) · NIS2 (UE) · ISO/IEC 27019 (énergie)

Suisse : OFCS (autorité), LSI art. 73-78 (annonce 24 h obligatoire), IIC = énergie/eau/transports/télécoms/santé/finance.

Règle d'or IR ICS : Safety > Security. Ne jamais containment au prix d'un accident physique.
