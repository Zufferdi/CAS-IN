NTFS
DFIR Filesystem
New Technology File System · Tout est fichier · Windows standard depuis 1993
Structure on-disk — « Tout est fichier »
$BootVBR secteur 0

Data AreaTous les fichiers + métafichiers

Contrairement à FAT, il n'y a pas de zone technique fixe (boot record, FAT1/2, root dir) — tout est dans la Data Area sous forme de fichiers accessibles par les mêmes mécanismes.

Master File Table ($MFT) — Le cœur de NTFS
Structure

Chaque fichier/dossier = 1 entrée de 1 KB (tuple). Entête de 42 bytes + séquence d'attributs. La MFT elle-même est un fichier ($MFT, entrée 0).

Si un fichier est petit (< 1 KB), ses données sont stockées directement dans le tuple (attribut résident).

Métafichiers système

$MFT (0) — La table elle-même
$MFTMirr (1) — Miroir des 4 premières entrées
$LogFile (2) — Journal des transactions
$Volume (3) — Nom et version du volume
. (5) — Répertoire racine
$Bitmap (6) — Table d'allocation clusters
$Boot (7) — Secteur de démarrage
$UsnJrnl — Journal USN (long terme)

Attribut résident

Données < 1 KB → stockées directement dans le tuple MFT. L'attribut $DATA contient le contenu du fichier. Accès immédiat sans aller chercher des clusters sur le disque.

Repérable dans X-Ways : flag R (Resident) allumé.

Attribut non-résident

Données > 1 KB → stockées dans des clusters pointés par une run list dans l'attribut. Le tuple MFT ne contient que la run list, pas les données elles-mêmes.

Le $DATA est presque toujours non-résident pour les fichiers utilisateur.

Run List — Décodage nibble par nibble
Exemple : 21 1C 7A 0A 00 — tiré de l'image 173088.jpg
21header
1Clongueur
7Aoffset lo
0Aoffset hi
00fin liste
① Octet header 21 — Nibble droit = 1 → lire 1 byte pour la longueur · Nibble gauche = 2 → lire 2 bytes pour l'offset LCN
② Longueur 1C → 1×16 + 12 = 28 clusters
③ Offset LCN 7A 0A → Little Endian → inverser → 0A 7A = 10×256 + 7×16 + 10 = LCN 2682
④ Résultat → 28 clusters consécutifs débutant au cluster 2682. Fin de liste : 00
Header nibbleSignificationExemple
Nibble droit (bits 0–3)Nombre de bytes pour la longueur du runx1 → 1 byte · x2 → 2 bytes
Nibble gauche (bits 4–7)Nombre de bytes pour l'offset LCN2x → 2 bytes · 3x → 3 bytes
00Fin de la run listToujours présent en dernier byte
Offsets négatifs (nombres signés) — L'offset de chaque run est relatif au run précédent (sauf le premier qui est absolu). Un bit de signe à 1 indique un déplacement vers l'arrière.

Exemple : FE 61 = 1111 1110 0110 0001 → signe = 1 → inverser + 1 → -415. Ce run commence 415 clusters avant le run précédent.
Timestamps NTFS — 1601 vs 1970
NTFS — Depuis le 1er janvier 1601
Résolution : 100 nanosecondes
Stockage : 8 bytes (QWORD) — Little Endian
Introduit en 1601 : début du calendrier grégorien

$STANDARD_INFORMATION — modifiable
$FILE_NAME — protégé par le noyau
UNIX — Depuis le 1er janvier 1970
Résolution : 1 seconde (ou ms selon impl.)
Stockage : 4 bytes (DWORD) pour Unix classique
EXT, HFS+, macOS utilisent cette époque

Outil de conversion : DC3dd, DCode, X-Ways Data Interpreter
Timestomping (anti-forensique) — Technique qui modifie $STANDARD_INFORMATION (facilement modifiable par les applications) sans toucher $FILE_NAME (protégé par le noyau). Indicateur : $SI.Created postérieur à $FN.Created → physiquement impossible → manipulation détectée.
B-Trees — Index et répertoires NTFS
Pourquoi des B-Trees ?

Un arbre binaire de 100 éléments a une hauteur de 7 (car 2⁷ = 128). Les B-Trees NTFS utilisent des nœuds larges (65 à 128 clés par nœud) → hauteur très faible → accès rapide même pour des millions de fichiers.

Les B-Trees sont en RAM pendant l'exécution, accès disque seulement pour les feuilles.

p>Chaque répertoire NTFS est un B-Tree d'entrées $INDEX. Les nœuds sont stockés dans des attributs $INDEX_ROOT et $INDEX_ALLOCATION.

Après suppression, les entrées restent parfois dans les nœuds B-Tree jusqu'à réorganisation — source de données récupérables.

Alternate Data Streams (ADS) & $Bitmap
Alternate Data Streams

Un fichier NTFS peut avoir plusieurs flux $DATA nommés.
Syntaxe : fichier.txt:caché.exe

L'Explorateur Windows affiche uniquement le flux principal. La taille visible ne reflète pas les ADS cachés. Outil : streams.exe (Sysinternals), X-Ways les détecte nativement.

$Bitmap — Table d'allocation

Le fichier $Bitmap (entrée 6 MFT) contient 1 bit par cluster : 0 = libre, 1 = occupé.

1 byte gère 8 clusters. Pour savoir si le cluster 42 est libre : byte 5 (42÷8), bit 2 (42%8).

≠ attribut $BITMAP utilisé par la MFT elle-même pour ses propres entrées.

Journal USN ($UsnJrnl) — Historique long terme
Ce qu'il enregistre

Toutes les modifications de fichiers : création, suppression, renommage, modification, avec horodatage précis. Taille configurable (par défaut ~32 Mo). Rétention : heures à semaines selon l'activité.

Valeur forensique

Même si le fichier supprimé est irrecupérable (clusters réalloués), le journal USN peut prouver qu'il a existé et quand il a disparu. Outil : MFTECmd.exe (Zimmerman) avec l'option --csv.
