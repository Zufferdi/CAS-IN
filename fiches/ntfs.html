NTFS
Forensique Filesystem Windows
New Technology File System — Windows NT 1993 → présent · Philosophie : Tout est fichier
⚠ NTFS commence au cluster 0 (contrairement à FAT qui commence à 2). Entrée MFT = 1024 octets (1 Ko). La $MFT n'est pas forcément au début du disque — consulter le boot sector offset 0x30.
Boot Sector — Point de départ
OffsetTailleChampNotes forensiques
0x03 8 octets OEM ID 4E 54 46 53 = NTFS en ASCII. Signature d'identification.
0x0B 2 octets BytesPerSector Généralement 0x0200 = 512 octets. Lire en Little Endian : "00 02" → 0x0200.
0x0D 1 octet SectorsPerCluster Valeur directe. Ex: 0x10 = 16 secteurs/cluster → cluster = 16 × 512 = 8192 octets.
0x28 8 octets TotalSectors Nombre total de secteurs du volume.
0x30 8 octets MFT LCN LCN (Logical Cluster Number) de la $MFT. Lire en Little Endian. Ex: "80 14 00 00" → 0x1480 = 5248. Offset $MFT = 5248 × 8192 = 42'991'616 octets.
0x38 8 octets MFTMirr LCN LCN de la copie de secours des 4 premiers records MFT.
0x40 4 octets ClustersPerMFT Négatif → exposant : ex −10 → 2¹⁰ = 1024 octets/record. Positif → nombre de clusters.
TailleCluster = BytesPerSector × SectorsPerCluster
Offset $MFT = MFT_LCN × TailleCluster
Offset cluster N = N × TailleCluster  (les clusters NTFS commencent à 0)

Structure d'un record MFT (1024 octets)
En-tête du record

Signature 46 49 4C 45 = "FILE" en ASCII (lecture gauche→droite).

Offset 0x14 (2 octets, WORD LE) = FirstAttributeOffset. Valeur typique : 0x38 = 56 décimal.

Structure : En-tête (≥42 bytes) · Série d'attributs · Espace libre · FIN à 0xFFFFFFFF

$BITMAP de la $MFT

Chaque bit = 1 record MFT. 1 = occupé, 0 = libre ou effacé.

1 octet gère 8 records. Chercher le record 42 : 42/8=5 reste 2 → octet 5, bit 2.

$Bitmap (record 6) = bitmap des clusters du volume. $MFT.$BITMAP = bitmap des records MFT.

En-tête commune à tous les attributs :
0x00 Type (4 bytes)
0x04 Longueur totale (4)
0x08 Résident ? (1) 0=oui / 1=non
0x0C Flags : Compressed=0x0001 · Encrypted=0x4000 · Sparse=0x8000
Attr. résident → offset 0x14 (2 octets) = offset interne vers le contenu.  |  Attr. non-résident → offset 0x20 (2 octets) = offset vers la RUNLIST.
Data Runlist — Décoder la fragmentation
Format du header de run

1 octet header : nibble gauche (poids fort) = nombre d'octets pour l'offset LCN. Nibble droit (poids faible) = nombre d'octets pour la longueur.

Ex: 22 → offset sur 2 octets, longueur sur 2 octets.

Ex: 31 → offset sur 3 octets, longueur sur 1 octet.

Offset positif ou négatif ?

L'offset LCN est un entier signé en complément à 2. Regarder le MSB (bit poids fort du dernier octet après LE).

Si dernier octet ≥ 0x80 → offset négatif.

Ex: "C8 E2" → 0xE2C8 → 0x10000 − 0xE2C8 = 0x1D38 = −7480.
Le run commence à LCN précédent − 7480.

Exemple : 22 7C 07 02 0C | 22 C7 07 B6 29 | 22 C0 03 C8 E2 | 00
22 7C 07 02 0C → longueur 0x077C=1916 clusters · LCN absolu 0x0C02=3074 · Début : cluster 3074
22 C7 07 B6 29 → longueur 0x07C7=1991 clusters · Offset +0x29B6=+10678 · Début : 3074+10678=13752
22 C0 03 C8 E2 → longueur 960 clusters · Offset 0xE2C8→négatif −7480 · Début : 13752−7480=6272
00 → Fin de la runlist. Ignorer tout ce qui suit.
Sauvegarde d'un fichier (ex: lioba.wav)
1
Chercher une entrée libre dans la $BITMAP de la $MFT → mettre le bit à 1. Naviguer à entrée × 1024 dans la $MFT.
2
Écrire l'entrée FILE avec tous ses attributs. Si fichier trop grand → $DATA non-résident avec runlist.
3
Chercher des clusters contigus libres dans $Bitmap (record 6). Marquer comme occupés.
4
Copier les données dans les clusters. Écrire l'action dans $LogFile. Vérifier quotas dans $Quota.
5
Journaliser dans $UsnJrnl. Mettre à jour le répertoire parent (ex: "Musique", record 57).
Effacement d'un fichier
1
Mettre à 0 le bit de l'entrée MFT dans $BITMAP de la $MFT. L'entrée FILE reste sur le disque jusqu'à réallocation.
2
Libérer les clusters dans $Bitmap (record 6) → bits à 0. Données non effacées.
3
Supprimer le nœud du répertoire parent ($I30). Des nœuds résiduels peuvent subsister → source forensique.
4
Journaliser dans $LogFile et $UsnJrnl — ces journaux conservent une trace de la suppression.
Points clés forensiques
Timestomping

Les outils (TimeStomp, Metasploit) modifient $STANDARD_INFORMATION mais oublient souvent $FILE_NAME.

Divergence $SI vs $FN = timestomping probable. MFTECmd exporte les deux colonnes.

Timestamps NTFS

Format : nombre de 100 nanosecondes depuis le 01.01.1601 (vs Unix : secondes depuis 01.01.1970).

4 timestamps MACE : Modified · Accessed · Changed (metadata) · (created) Born

$I30 résiduel

$INDEX_ALLOCATION d'un répertoire organise ses entrées en B-tree. Après suppression et réorganisation, des nœuds orphelins subsistent.

Dernière source quand $MFT écrasé + $UsnJrnl purgé.

Alternate Data Streams

Un fichier peut avoir plusieurs attributs $DATA nommés. Ex: fichier.txt:cache cache une autre donnée dans le flux alterné.

X-Ways les liste dans le Volume Snapshot. Non visible via l'Explorateur Windows standard.

$UsnJrnl (Change Journal)

Journal de toutes les modifications de fichiers. Taille configurable (typiquement 32–64 Mo). Tronqué régulièrement → fenêtre temporelle limitée.

Outil : MFTECmd ou fsutil usn readjournal. Survivance de preuves après effacement volontaire.

X-Ways — Raccourcis NTFS

Clic droit sur $MFT → Navigate → List Clusters → voir la fragmentation de la MFT.

Navigation → Seek FAT Entry / Seek MFT Record. En-tête "FILE" toujours cherché pour les enregistrements résiduels.
