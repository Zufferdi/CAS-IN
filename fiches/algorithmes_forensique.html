🏷️ Fonction de Hachage = Empreinte Numérique
Une fonction de hash H(data) transforme n'importe quel fichier (1 octet ou 100 GB) en une chaîne fixe (128, 160, ou 256 bits).

Propriétés essentielles :
  • 🔒 Déterministe : H(fichier) = même résultat toujours
  • ❌ Non-inversible : Impossible de recréer le fichier depuis le hash
  • 🎲 Effet avalanche : 1 bit changé → hash complètement différent
  • 💥 Collision difficile : Impossible de trouver deux fichiers avec même hash
Comparaison des Algorithmes de Hachage
Algo Bits Sécurité Vitesse Cas d'usage ⚠️ Notes
MD5 128 CASSÉ Rapide Checksums, non-crypto ⚠️ Ne plus utiliser en crypto
SHA-1 160 FAIBLE Rapide Chaîne de possession, Git Attaques SHAttered (2017)
SHA-256 256 ✓ BON Rapide Standard judiciaire Recommandé NIST

🔬 Fuzzy Hashing (SSDEEP)
Contrairement aux hashs cryptographiques (qui changent avec 1 bit), SSDEEP détecte les similarités.

Utile pour :
  • Détecter des variantes de malware (même code, compilé différemment)
  • Reconnaître des documents modifiés
  • Retrouver des images redimensionnées/compressées
ssdeep: 393216:8ypZ+cg1Eg3eXNbRKXdPN... vs 393216:8ypZ+cg1Eg3eXNbRKXdPN...
Correspondance : ~95% (image recadée)
🔍 Pattern Matching = Recherche de Signatures
Algorithme qui cherche une séquence d'octets (pattern) dans un flux de data, sans dépendre de la structure du filesystem.
Algorithmes de Recherche de Pattern
1. Brute Force (Naïf)
for i in range(len(data) - len(pattern)):
  if data[i:i+len(pattern)] == pattern:
    MATCH found at offset i Complexité : O(n × m) où n=data, m=pattern
Pros : Simple, peu de mémoire
Cons : Lent sur gros fichiers (disques entiers)
2. Boyer-Moore (Optimisé)
Pré-calculer table de saut basée sur dernier octet
Sauter jusqu'à m octets en avant si mismatch Complexité : O(n/m) en moyenne !
Pros : 2-10x plus rapide que brute force
Cons : Utilisé par Yara, Snort
3. Knuth-Morris-Pratt (KMP)
Pré-calculer table de chevauchement (failure table)
Éviter recomparaisons inutiles Complexité : O(n + m) — Garanti optimal
Pros : Prévisible, pas d'effet pire cas
Cons : Overhead de table (parfois lent sur petits patterns)
File Carving (Reconstruction de Fichiers)
📂 Carving = Récupérer Fichiers Supprimés
Principe : Chercher des magic bytes (en-têtes) et terminaisons (footers) pour reconstituer fichiers supprimés.

Étapes :
  1. Header Scanning : Chercher FF D8 FF (JPEG), 89 50 4E 47 (PNG), etc.
  2. Footer Detection : Fin du format (ex: FF D9 pour JPEG)
  3. Validation : Vérifier structure, taille plausible
  4. Assembly : Reconstruire le fichier entier
Outils : PhotoRec, Scalpel, Foremost
Algorithme de Carving
Algorithm: File Carving

Input: raw_disk, magic_bytes_dict
Output: recovered_files

offset ← 0
while offset < disk_size:
   if read_bytes(offset, 4) in magic_bytes:
      file_type ← identify(magic)
      footer ← magic_bytes_dict[file_type].footer
      end_offset ← find_next(footer, offset)
      if end_offset ← validate_structure(offset, end_offset):
         recovered_files.append(extract(offset, end_offset))
      offset ← end_offset
   else:
      offset ← offset + 1 (scan suivant)
⚠️ Pièges du Carving
  • Faux positifs : Magic bytes peuvent apparaître dans les données (ex: base64)
  • Fichiers fragmentés : Si le fichier est en plusieurs chunks non-contigus
  • Fichiers comprimés : Header + contenu comprimé → fin difficile à détecter
  • Containers : ZIP, TAR contiennent plusieurs fichiers (confusion possible)
🔤 Encoding ≠ Chiffrement
Encoding : Transformation réversible mais pas secrète (tout le monde connaît le format)
Chiffrement : Transformation secrète (clé requise)

En DFIR, chercher l'encoding = repérer tentatives d'obfuscation/anti-forensique.
Encodings Courants en Forensique
Base64
SGVsbG8gV29ybGQ=
• Encode 3 bytes → 4 caractères ASCII
• Usage : Emails, API, obfuscation légers
• Détection : Pattern [A-Za-z0-9+/=]{4,}$
Hexadécimal
48656c6c6f20576f726c64
• Encode 1 byte → 2 hex digits
• Usage : Dumps, shellcode, logs
• Détection : Pattern [0-9a-fA-F]{2,}
URL Encoding
Hello%20World
• Encode caractères spéciaux → %XX
• Usage : URLs, POST data
• Détection : Pattern %[0-9A-F]{2}
Unicode/UTF-8
U+0048 U+0065 ...
• Encode caractères multi-byte
• Usage : Contournement antivirus
• Détection : BOM, séquences multi-byte
Anti-Forensique : Détection
Technique : Analyse Entropie

L'entropie mesure le désordre / aléatoire des données.

H = -Σ(p_i × log₂(p_i)) pour chaque octet
Résultat : 0 (très ordonné) à 8 (totalement random) Interprétation :
  • H < 2 : Texte en clair (lettres ASCII répétitives)
  • 2 < H < 6 : Données structurées (JSON, XML, images)
  • H > 7.5 : Chiffré, comprimé, ou aléatoire (suspect !)
📦 Compression = Réduction Taille
Algorithme qui trouve des patterns répétitifs et les encode de façon plus courte, sans perte (lossless).

En DFIR : Comprendre les formats pour recovery et analyse de malware.
Algorithmes de Compression
Algo Type Ratio Vitesse Usage
DEFLATE LZ77 + Huffman Bon Rapide .zip, .gz
LZ4 Dictionnaire Moyen Très rapide Streaming, logs
BZIP2 Burrows-Wheeler Excellent Lent .bz2 archives
ZSTD Dictionnaire + BT Excellent Rapide Futur standard
⚠️ Impact Forensique
  • Recovery : Fichiers comprimés = impossible de simplement carver (les chunks sont invalides)
  • Analyse Malware : Malware comprimé → décompression nécessaire (UPX, WinRAR, etc.)
  • Evidence : Checksum change si on recomprime (besoin hash de l'original)
