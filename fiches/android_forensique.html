🤖 Mobile Android Acquisition SoC-specific

Android Forensique — Fragmentation, exploits, custom recoveries

Là où iOS est monolithique, Android est fragmenté : 1300+ constructeurs, 25 000+ modèles, 14 versions actives, des SoC Qualcomm/MediaTek/Exynos/Kirin/Tensor avec chacun leurs particularités. Cette diversité est à la fois une aubaine forensique (plus de surfaces d'attaque) et une complexité opérationnelle (chaque modèle peut nécessiter une approche différente).
Prérequis : 📖 Acquisition 📖 EXT4/F2FS 📖 Mobile Forensics 📖 Droit pénal CH

🔐 FBE vs FDE — comprendre le chiffrement Android
Android a évolué d'un chiffrement full-disk à un chiffrement par fichier. Cette distinction conditionne ce qu'on peut extraire en BFU.
SchémaVersionsMécanismeImpact forensique
FDE
Full-Disk Encryption		 Android 5-9 Tout le userdata chiffré avec une clé dérivée du PIN/passcode + KEK matériel Pas de données accessibles avant déverrouillage. Bruteforce possible si PIN faible.
FBE
File-Based Encryption		 Android 7+ (obligatoire 10+) 2 classes : CE (Credential Encrypted, après unlock) et DE (Device Encrypted, dès le boot) Avant unlock : seuls les fichiers DE accessibles (alarmes, accessibilité, certains logs). Après unlock : tout est lisible.
Metadata encryption Android 11+ Couche supplémentaire chiffrant les métadonnées (noms de fichiers, timestamps) Sans la clé, impossible de lister la structure du FS
📌 Conséquence pratique : Android 10+ avec FBE = quasi-équivalent au BFU iOS. Sans le passcode, on ne récupère que :
  • Le bootloader, recovery, certains logs DE (/data/system_de/)
  • Les apps avec mode "Direct Boot" (Alarmes, Accessibilité)
  • Aucune donnée utilisateur (Photos, Messages, contacts...)

📥 Méthodes d'acquisition — par niveau de profondeur

Niveau Méthode Couverture Prérequis
1. Manual Photos / vidéos de l'écran, navigation manuelle Visible à l'écran uniquement Device déverrouillé, pas de prérequis
2. Logical ADB backup (adb backup -all), MTP transfer Apps autorisant le backup, fichiers utilisateur (Photos, Downloads) Device déverrouillé, USB Debug activé, ou root
3. File System Custom recovery (TWRP), root + dd Tout le filesystem en clair (si déchiffré) Bootloader unlock + custom recovery, ou root

🎯 Exploits par SoC — la voie royale

🔓 EDL Mode (Qualcomm)
Emergency Download Mode : mode de récupération bas niveau présent sur tous les SoC Qualcomm. Activé par combinaison de touches ou court-circuit de pads de test (test points). Permet de flasher des images signées par le fabricant — et avec un programmer file (loader) fuité ou signé, on peut lire la NAND complète.
  • Outils : EDL.py (open source bkerler), QFIL (Qualcomm), Cellebrite Premium intègre la base de loaders
  • Limitation : la NAND lue est chiffrée si FDE/FBE actif → bruteforce nécessaire
  • Couvre : la majorité des Xiaomi, OnePlus, Samsung Snapdragon (US), Sony, Motorola, etc.
🔓 BROM Exploit (MediaTek)
Le Boot ROM de centaines de SoC MediaTek (MT67xx, MT68xx, MT81xx) souffre d'une vulnérabilité permanente (équivalent du checkm8 iOS). Permet de booter du code arbitraire avant le chargement de TrustZone. Exploit publié par bkerler en 2021.
  • Outils : mtkclient (open source), Cellebrite Premium MTK
  • Couvre : Oppo, Vivo, Realme, Xiaomi MTK, Tecno, Infinix (très répandus en Afrique/Asie)
  • Permet : Full File System extraction, bruteforce passcode hors device
🔓 Samsung Exynos — bootloader exploits
Plus complexe : Samsung utilise Knox, qui détecte les modifications du bootloader (Knox bit). Une fois "tripped", certaines features (Knox Container, Samsung Pay) sont irrécupérables. Cellebrite Premium a des méthodes propriétaires pour les Galaxy récents.
⚠️ Risque Knox Tripping : sur Samsung, certaines méthodes d'extraction physique déclenchent le Knox bit. Cela rend la chaîne de custody plus fragile devant un tribunal (le device est modifié à jamais). Documenter la décision dans le rapport et privilégier l'extraction logique si suffisant.

🔧 ADB — l'outil universel

📡 Android Debug Bridge
ADB est le pont de communication entre le PC d'analyse et le device. Il nécessite que le USB Debug soit activé sur le téléphone (Paramètres > Options développeur > Débogage USB). 
# Connexion et identification
adb devices                          # Liste les devices connectés
adb shell                            # Shell sur le device
adb shell getprop ro.build.version.release  # Version Android
adb shell getprop ro.product.model           # Modèle exact
adb shell getprop ro.serialno                # Numéro de série

# Backup logique (Android 4.0-11, déprécié ensuite)
adb backup -apk -shared -all -system -f backup.ab

# Convertir le backup en tar lisible
dd if=backup.ab bs=24 skip=1 | openssl zlib -d > backup.tar
# OU avec Android Backup Extractor (abe.jar)
java -jar abe.jar unpack backup.ab backup.tar

# Pull de fichiers spécifiques (si root)
adb shell su -c 'tar cf - /data/data' | tar xf -

# Logcat live
adb logcat -v time -d > logcat.txt

# Partition raw via dd (root requis)
adb shell su -c 'dd if=/dev/block/sda10 of=/sdcard/userdata.img'
adb pull /sdcard/userdata.img
💡 ADB authorisation : au premier branchement, le téléphone affiche une popup "Autoriser le débogage USB depuis cet ordinateur ?" avec une empreinte de la clé publique RSA. Cocher "Toujours autoriser" stocke la clé dans /data/misc/adb/adb_keys. Cette clé peut être récupérée d'un PC saisi et réinjectée pour autoriser un autre PC.

⭐ usagestats — le pattern of life Android
Depuis Android 5, le service UsageStatsManager enregistre toutes les interactions utilisateur dans /data/system/usagestats/0/. Les fichiers sont en format protobuf ou XML selon les versions.

Sous-dossiers :
  • daily/ — agrégats quotidiens (par jour Unix)
  • weekly/ — agrégats hebdomadaires
  • monthly/ — agrégats mensuels
  • yearly/ — agrégats annuels

Événements enregistrés (extrait) :
  • MOVE_TO_FOREGROUND / MOVE_TO_BACKGROUND — App au premier plan
  • SCREEN_INTERACTIVE — Écran allumé/éteint
  • KEYGUARD_HIDDEN / KEYGUARD_SHOWN — Lock/unlock
  • NOTIFICATION_INTERRUPTION — Notifications pertinentes
  • USER_INTERACTION — Activité utilisateur
Outils : ALEAPP (Android Logs Events And Protobuf Parser) avec module Usagestats, Magnet AXIOM (parsing intégré), Cellebrite Reader.

🛡️ Knox & Secure Folder (Samsung)

🔐 Knox Container
Knox est l'écosystème de sécurité Samsung. Il propose un Secure Folder (anciennement My Knox) qui crée un environnement utilisateur isolé avec apps cloisonnées, chiffrement séparé, déverrouillage différent.
  • Stockage : /data/user/150/ ou similaire (UID > 100)
  • Chiffrement : par-utilisateur, clé dérivée du mot de passe Secure Folder
  • Forensique : Cellebrite Premium peut extraire avec le mot de passe ou via méthodes propriétaires
  • Conséquence : Les apps dans Secure Folder sont invisibles en mode standard. Toujours vérifier la présence du folder !

🔧 Custom Recovery — TWRP & alternatives

🛠️ TWRP — la voie traditionnelle
Team Win Recovery Project est le custom recovery historique. Permet :
  • Backup partition par partition (boot, system, data, vendor)
  • Shell adb avec accès complet (root)
  • Mount de partitions, dd raw
Prérequis : bootloader unlock (déclenche reset factory + Knox tripping sur Samsung). Le bootloader unlock efface les données sur la plupart des modèles → impossible à utiliser pour acquisition forensique sauf si le device a déjà été unlocké (par le suspect, un revendeur, etc.).
✅ Cas particulier — devices "Engineering" ou "Test" : certains constructeurs (Xiaomi notamment) vendent des modèles dits "developer edition" avec bootloader pré-unlocké. Des prototypes ou devices de R&D sortent parfois en circulation. Vérifier en priorité !

🎯 Workflow Android — du "tu fais quoi avec ça" à l'extraction

1. Identification du device
  • Marque + modèle exact (sous le SIM tray, ou via *#06# pour IMEI)
  • SoC : Qualcomm, MediaTek, Exynos, Kirin, Tensor, Unisoc ?
  • Version Android (Paramètres > À propos > Version)
  • Bootloader status (Settings > About > Status, ou via fastboot oem device-info)
  • USB Debug actif ?
2. Choix de méthode
  • Device déverrouillé + USB Debug → ADB backup, puis tenter root → file system
  • Device verrouillé + Qualcomm → tentative EDL via points test
  • Device verrouillé + MediaTek vulnérable → BROM exploit (mtkclient)
  • Device verrouillé + Samsung récent → Cellebrite Premium ou rien
  • Last resort : chip-off (destructif, atelier requis)
3. Acquisition
  • Mode avion immédiat (ne pas tirer SIM, peut déclencher remote wipe)
  • Backup logique en parallèle d'extraction physique
  • Hash MD5/SHA-256 immédiat
  • Documenter le numéro de série du SoC, l'IMEI, l'empreinte avant/après
4. Analyse
  • Magnet AXIOM ou Cellebrite Reader pour parsing initial
  • ALEAPP modules : usagestats, accounts, location, etc.
  • SQLite tools pour les apps non parsed
  • Timeline globale via Plaso (l2t_csv import) ou Timesketch

⚖️ Examen CAS-IN — points clés Android :
  • FBE (Android 7+) = chiffrement par fichier, classes CE/DE
  • Avant unlock = quasi-équivalent BFU iOS sur Android 10+
  • EDL Mode = exploit Qualcomm via test points
  • BROM Exploit = vulnérabilité permanente MediaTek (mtkclient)
  • Knox tripping Samsung = irréversible, modification chaîne de custody
  • Bootloader unlock = data wipe sur la plupart des modèles
  • usagestats = pattern of life Android (équivalent knowledgeC.db)
  • Wi-Fi passwords stockés en clair dans WifiConfigStore.xml
  • WhatsApp backup chiffré sur /sdcard/ → clé dans /data/data/com.whatsapp/
  • Cellebrite Premium = best-in-class pour SoCs récents
