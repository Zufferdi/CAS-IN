🔢 File Signatures

Magic Bytes & Signatures Fichiers

🪄 Magic bytes (ou magic numbers, ou file signatures) : les premiers octets d'un fichier qui identifient son vrai format, indépendamment de l'extension. C'est la première chose à vérifier en forensique : un attaquant peut renommer malware.exe en image.jpg, mais les magic bytes ne mentent pas.

🛠️ Outils d'identification

file Linux/macOS
file inconnu.bin
Outil universel basé sur la base /usr/share/file/magic. Reconnaît > 1500 formats. Mode strict : file --mime-type. Recurse : find /path -type f -exec file {} \;.
xxd hexdump tool
xxd suspect.bin | head
Affiche les premiers octets en hex + ASCII. Beaucoup plus lisible que hexdump -C. Inverse : xxd -r reconstruit le binaire.
binwalk scan multi-magic
binwalk firmware.bin
Scanne TOUT le fichier et détecte les magic bytes imbriqués. Indispensable pour firmware, dump RAM, fichiers carving. Extraction : binwalk -e.
photorec data carving
photorec /dev/sdb
Carve les fichiers à partir des magic bytes sur un disque (même partition corrompue ou supprimée). Reconnaît > 480 formats. De TestDisk family.
trid détection profonde
trid -ce inconnu
Approche probabiliste avec base de patterns > 14 000 formats. Utile quand file donne "data" ou ne reconnaît pas.
PowerShell Windows natif
Get-Content suspect.bin -Encoding Byte -TotalCount 16 | ForEach-Object { '{0:X2}' -f $_ }
Lit les 16 premiers octets et les affiche en hex. Plus moderne : Format-Hex -Path suspect.bin.

🔎 Regex pour parser les outputs forensiques

Une fois qu'on a un dump (logs, mémoire, registres), on cherche des patterns : adresses IP, emails, hashes, base64, GUIDs. grep, egrep, awk, sed sont les outils universels.

🐧 CLI Linux pour forensique

grep / egrep — extraction de patterns

# Recherche simple grep "John" addressbook.txt # Insensible à la casse + lignes contexte avant/après grep -i -B 2 -A 2 "password" config.log # Plusieurs patterns (OR) egrep "error|fail|crit" /var/log/syslog grep "error\|fail\|crit" /var/log/syslog # Reverse (lignes qui NE matchent PAS) grep -v "^#" config.txt # supprime commentaires # Compter les hits grep -c "Failed login" auth.log # Recherche récursive dans dossier grep -rn "secret_key" /var/www/ # Mode Perl regex (lookahead, etc.) grep -P "^\d{4}-\d{2}-\d{2}" log.txt

awk — extraire des colonnes

# Top 10 IP les plus fréquentes dans access.log awk '{print $1}' access.log | sort | uniq -c | sort -rn | head # Séparateur custom (':') puis colonne 7 (shell de chaque user) awk -F: '{print $1 " → " $7}' /etc/passwd # Filtrer puis afficher (équivalent SQL WHERE) awk -F: '$3 >= 1000 {print $1}' /etc/passwd # users avec UID >= 1000 # Calculer une somme awk '{sum += $5} END {print "Total bytes:", sum}' transfer.log

sed — substitution

# Première occurrence par ligne echo "hallo" | sed 's/a/e/' # → hello # Globale (tout sur la ligne) sed 's/a/e/g' file > out # Anonymiser des IPs en masse sed -E 's/[0-9]+\.[0-9]+\.[0-9]+\.[0-9]+/X.X.X.X/g' log.txt # Supprimer les commentaires + lignes vides d'un fichier conf sed '/^#/d; /^$/d' nginx.conf # Modification in-place (avec backup .bak) sed -i.bak 's/old/new/g' fichier.txt

sort + uniq — déduplication et statistiques

# Trier puis dédupliquer sort access.log | uniq # Compter les occurrences (style histogram) sort | uniq -c | sort -rn # Lignes uniques (jamais dupliquées) — utile pour anomalies sort | uniq -u # Lignes en double (potentielles répétitions suspectes) sort | uniq -d # Ignorer les N premiers champs (par ex. timestamp variable) sort | uniq -f 2 -c

Combo classique : top user-agents suspects

awk -F'"' '{print $6}' access.log | \ sort | uniq -c | sort -rn | head -20

Extrait le 6e champ entre guillemets (= User-Agent en log Apache/Nginx), trie, dédoublonne avec compteur, retient les 20 plus fréquents. Idéal pour repérer un scanner (souvent UA bizarre type "Mozilla/5.0 (compatible; bot/1.0)").

🪟 Windows : findstr (équivalent grep)

# Recherche insensible à la casse, regex findstr /i /r "password" config.txt # Plusieurs patterns findstr "error fail crit" log.txt # OR par défaut # Lignes qui ne matchent PAS findstr /v "^#" config.txt # Mode regex étendu (équivalent grep -E partiel) findstr /r "^[0-9][0-9]*$" data.txt # lignes purement numériques # Recherche récursive findstr /s /i "secret" C:\Users\*.txt

⚠️ findstr est moins puissant que grep : pas de lookahead, pas de classes Unicode, regex limité. En PowerShell, préférer Select-String.

💊 Auto-évaluation

Tu as un fichier photo.jpg de 8 MB qui ne s'ouvre pas. xxd photo.jpg | head donne :
00000000: 504b 0304 1400 0000 0800 ...
Que conclus-tu ?Magic bytes · Niveau : facile
50 4B 03 04 = "PK\x03\x04" = ZIP. Le fichier n'est PAS un JPEG (qui commencerait par FF D8 FF). Suspect classique : extension renommée pour cacher un payload (ZIP contenant un script malveillant), ou simple confusion d'extension. Renomme en .zip, ouvre, examine le contenu. Si plusieurs fichiers à l'intérieur dont un .exe ou un .lnk, niveau de suspicion très élevé.
Pourquoi est-il impossible de distinguer de manière sûre un fichier VeraCrypt d'un fichier de pure aléa ?Crypto + magic · Niveau : moyen
Par design cryptographique. VeraCrypt (et TrueCrypt avant lui) chiffre TOUT le conteneur, header inclus. Aucun magic byte n'est laissé en clair, pour offrir une plausible deniability : "ce fichier de 5 GB n'est pas un conteneur, c'est juste du bruit". Détection en pratique : (1) entropie de Shannon ≈ 1.0 sur tout le fichier, (2) taille caractéristique (multiple de 512), (3) contexte (fichier mystérieux nommé backup.dat...). C'est aussi pourquoi la défense d'un suspect peut être "je ne me souviens pas du mot de passe" — on ne peut pas prouver qu'il y a quelque chose dedans.
Construis une commande qui extrait les 10 IP les plus fréquentes dans access.log Apache, avec leur nombre d'occurrences.Bash forensique · Niveau : moyen
awk '{print $1}' access.log | sort | uniq -c | sort -rn | head -10

Décomposition :
• awk '{print $1}' : extrait la 1re colonne (= IP en format Apache combined log)
• sort : trie alphabétiquement (prérequis pour uniq)
• uniq -c : déduplique en préfixant par le nombre d'occurrences
• sort -rn : trie numériquement en ordre décroissant (-n = numeric, -r = reverse)
• head -10 : garde les 10 premières lignes
🎓 Exam Tip — Magic Bytes & Regex

Top 10 magic à mémoriser : PNG (89 50 4E 47), JPEG (FF D8 FF), PDF (25 50 44 46), ZIP (50 4B 03 04), MZ/PE (4D 5A), ELF (7F 45 4C 46), GZIP (1F 8B), SQLite (SQLite format 3), MBR (55 AA à 0x1FE), GIF89a.

FS magic à offset : EXT4 = 53 EF @ 0x438 · NTFS = "NTFS " @ 0x03 · HFS+ = "H+" @ 0x400 (BE) · GPT = "EFI PART" @ 0x200.

Outils : file · xxd · binwalk (imbriqué) · photorec (carving) · trid (probabiliste).

Regex hashes : MD5 = [a-f0-9]{32} · SHA-1 = [a-f0-9]{40} · SHA-256 = [a-f0-9]{64}.

Combo bash : awk | sort | uniq -c | sort -rn | head = pattern incontournable pour stats top-N.

Piège VeraCrypt : pas de magic = entropie ≈ 1 = plausible deniability cryptographique.
