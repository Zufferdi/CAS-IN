ReFS — Resilient File System

Windows Server 2012+ · Storage Spaces · Intégrité · Différences forensiques vs NTFS

"ReFS was designed for large-scale storage infrastructure. Forensically, its lack of $MFT, different allocation tables, and sparse support by tools means investigators often miss critical artefacts."
— DFIR.training · ReFS Forensics 2023
💡 Quand le rencontrer : ReFS apparaît sur les serveurs Windows (Server 2012+), les espaces de stockage (Storage Spaces), les sauvegardes Windows Server Backup, et les volumes utilisés par Hyper-V pour stocker des VMs (recommandé par Microsoft).

🏗️ Structure interne ReFS

Composants clés

  • Object Table : Équivalent de la MFT NTFS (structure B+ Tree)
  • Schema Table : Types d'objets et attributs
  • Object ID Table : Association ID → fichier
  • Checksum : Chaque bloc de données a un checksum (SHA-256)
  • Superblock : À l'offset 0 du volume

Particularités forensiques

  • Pas de récupération native de fichiers supprimés
  • Les entrées de répertoire sont effacées immédiatement
  • Journalisation différente → moins d'artefacts résiduels
  • Volume Shadow Copy fonctionne sur ReFS (Windows Server)
  • $UsnJrnl présent et analysable

💡
Approche pragmatique : Monter le volume ReFS sur Windows Server et utiliser robocopy ou PowerShell pour l'extraction des fichiers accessibles. Pour les fichiers supprimés : Volume Shadow Copy ou sauvegardes.

🔄 Volume Shadow Copy sur ReFS

  • VSS fonctionne sur ReFS — Les snapshots VSS sont une source forensique précieuse
  • Commande : vssadmin list shadows /for=X:
  • Montage : mklink /D C:\shadow \?\GLOBALROOT\Device\HarddiskVolumeShadowCopyX\
  • Alternative : ShadowExplorer (GUI) pour accéder aux snapshots VSS
  • Hyper-V crée des snapshots VSS automatiquement lors des sauvegardes
