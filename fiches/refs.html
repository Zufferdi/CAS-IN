Structure interne ReFS
Composants clés
  • Object Table : équivalent de la MFT (B+ Tree)
  • Schema Table : types d'objets et attributs
  • Object ID Table : association ID → fichier
  • Superblock : à l'offset 0 du volume
  • Checksum SHA-256 sur chaque bloc de données
Limites forensiques
  • Pas de récupération native de fichiers supprimés
  • Entrées de répertoire effacées immédiatement
  • Journalisation différente → moins d'artefacts résiduels
  • MFTECmd (Zimmerman) ne s'applique pas à ReFS
  • Carving possible mais moins de repères
Outils & Volume Shadow Copy
Support outils
  • X-Ways Forensics : lecture OK, récupération limitée
  • Autopsy / TSK : expérimental
  • FTK Imager : montage OK
  • Windows natif : complet — PowerShell + robocopy
Volume Shadow Copy (VSS)
  • VSS fonctionne sur ReFS — source forensique principale
  • vssadmin list shadows /for=X:
  • Montage : mklink /D C:\shadow \?\GLOBALROOT\...\ShadowCopyX\
  • ShadowExplorer (GUI) pour accès facilité
🎓 Exam Tip — ReFS

ReFS = Resilient File System · Windows Server 2012+ · Storage Spaces · Hyper-V VMs

Pas de $MFT : Object Table B+ Tree → MFTECmd inutilisable sur ReFS

Suppression : entrées effacées immédiatement → récupération quasi impossible

Absent : ADS · Compression EFS · Noms 8.3 · Récupération native

Source principale : Volume Shadow Copy (VSS) — vssadmin list shadows /for=X:

Checksums SHA-256 intégrés par bloc de données · $UsnJrnl présent (structure différente)

Pourquoi ReFS rend-il la récupération de fichiers supprimés quasi impossible ?ReFS forensique · Niveau : moyen
ReFS efface les entrées de répertoire immédiatement. Pas de $MFT avec entrées orphelines (NTFS), pas de marquage 0xE5 (FAT). L'Object Table B+ Tree est mise à jour en place. Source principale : Volume Shadow Copy.
Quelles 3 fonctionnalités NTFS sont absentes de ReFS ?ReFS vs NTFS · Niveau : facile
ReFS ne supporte pas : ADS (Alternate Data Streams) · Compression EFS · Noms 8.3 courts. En contrepartie : checksums SHA-256 par bloc, conçu pour Storage Spaces.
