F2FS — Flash-Friendly File System

Android natif · Samsung · SSD modernes · Différences forensiques vs EXT4

"F2FS was created by Samsung in 2012 specifically for NAND flash storage. It's now the default filesystem on many Android devices — including every Samsung Galaxy since 2018."
— Linux Kernel Documentation · F2FS Design
💡 Prévalence forensique : De nombreux téléphones Android modernes (Samsung Galaxy, certains Xiaomi, Motorola) utilisent F2FS comme FS interne. Un enquêteur mobile qui ne connaît pas F2FS peut passer à côté d'artefacts importants ou mal interpréter des timestamps.

🏗️ Architecture F2FS

Zones du volume

  • Superblock : Métadonnées du FS (2 copies pour redondance)
  • Checkpoint : État cohérent du système (2 copies alternées)
  • Segment Info Table (SIT) : État de chaque segment
  • Node Address Table (NAT) : Localisation des blocs de noeuds
  • SSA (Segment Summary Area) : Résumé des segments actifs
  • Main Area : Données et noeuds entrelacés

Caractéristiques clés

  • Log-Structured : nouvelles données toujours écrites en position libre
  • Checkpoint toutes les 30s — état cohérent récupérable
  • Inline data : petits fichiers stockés dans le noeud même
  • Pas d'allocation fixe comme EXT4 → recovery difficile

📱 F2FS sur Android — Implications forensiques

⚠️
Récupération de données supprimées : Sur F2FS, les données supprimées sont rapidement réutilisées ou chiffrées par FBE. La probabilité de récupérer des fichiers supprimés est significativement plus faible que sur EXT4.
  • Samsung Galaxy S8+ / Note / A-series : F2FS sur la partition /data (userdata)
  • Full Disk Encryption (FDE) / File-Based Encryption (FBE) : Toujours combiné avec F2FS → données chiffrées même avec accès physique
  • UFED / Cellebrite : Support F2FS documenté — extraction logique préférable
  • Timestamps : Précision nanoseconde — fiable pour corrélation temporelle
  • Outils : f2fs-tools sur Linux — dump.f2fs pour analyse de structure
ℹ️
Identifier F2FS : Magic number = 0xF2F52010 au début du superblock. Visible dans un éditeur hex à l'offset 1024 du volume.

🔍 Analyse pratique

  • Extraction : Préférer l'extraction logique (UFED) ou le backup ADB plutôt que le chip-off si possible
  • Linux mount : mount -t f2fs /dev/sda /mnt (noyau Linux 3.8+)
  • Fsck : fsck.f2fs /dev/sda — vérification d'intégrité avant montage
  • Dump structure : dump.f2fs -d 1 /dev/sda
  • Sur Android rooted : accès via ADB shell + dd de la partition /data
