🔑 Pourquoi F2FS est incontournable en forensique mobile
F2FS a été créé par Samsung en 2012 spécifiquement pour le stockage NAND flash. C'est aujourd'hui le filesystem par défaut de nombreux appareils Android — dont tous les Samsung Galaxy depuis 2018. Un enquêteur mobile qui ne connaît pas F2FS passe à côté d'artefacts importants ou mal interprète des timestamps.

🏗 Architecture F2FS — Zones du volume
Contrairement à EXT4, F2FS organise le disque en segments et écrit toujours en positions libres (Log-Structured File System).
📦 Zones du volume F2FS
  • Superblock : métadonnées du FS — 2 copies pour redondance
  • Checkpoint : état cohérent du système — 2 copies alternées
  • Segment Info Table (SIT) : état de chaque segment
  • Node Address Table (NAT) : localisation des blocs de nœuds
  • SSA (Segment Summary Area) : résumé des segments actifs
  • Main Area : données et nœuds entrelacés
⚡ Caractéristiques clés
  • Log-Structured : nouvelles données toujours écrites en position libre
  • Checkpoint toutes les 30 s — état cohérent récupérable
  • Inline data : petits fichiers stockés dans le nœud même
  • Pas d'allocation fixe comme EXT4 → récupération difficile
  • Garbage Collection : compacte les segments partiellement valides
📱 F2FS sur Android — Implications forensiques
⚠ Récupération de données supprimées : sur F2FS, les données supprimées sont rapidement réutilisées par la Garbage Collection ou chiffrées par FBE. La probabilité de récupérer des fichiers supprimés est significativement plus faible que sur EXT4.
  • Samsung Galaxy S8+ / Note / A-series / S-series récents : F2FS sur la partition /data (userdata)
  • Full Disk Encryption (FDE) / File-Based Encryption (FBE) : toujours combiné avec F2FS → données chiffrées même avec accès physique
  • UFED / Cellebrite : support F2FS documenté — extraction logique préférable
  • Timestamps : précision nanoseconde — fiable pour corrélation temporelle
  • Outils : f2fs-tools sur Linux — dump.f2fs pour analyse de structure
  • Xiaomi, Motorola : certains modèles utilisent aussi F2FS (vérifier par device)
🔍 Identifier F2FS : Magic number = 0xF2F52010 au début du superblock. Visible dans un éditeur hex à l'offset 1024 du volume.
🔍 Analyse pratique
1
Extraction : préférer l'extraction logique (UFED) ou le backup ADB plutôt que le chip-off quand possible. Le chip-off donne du F2FS brut souvent chiffré.
2
Montage Linux : mount -t f2fs /dev/sda /mnt — nécessite un noyau Linux 3.8+ (dispos depuis 2013).
3
Vérification intégrité : fsck.f2fs /dev/sda avant montage read-only.
4
Dump structure : dump.f2fs -d 1 /dev/sda — révèle superblock, NAT, SIT, checkpoints.
5
Android rooté : accès via ADB shell + dd de la partition /data.

Pourquoi la récupération de fichiers supprimés sur F2FS est-elle considérablement plus difficile que sur EXT4 ?F2FS forensique · Niveau : moyen
F2FS est log-structured : toute modification crée un nouveau bloc en zone libre, et l'ancien bloc est marqué invalide mais réécrit rapidement par la Garbage Collection pour libérer des segments entiers. De plus, il n'existe pas de table d'inodes fixe (comme EXT4) — les inodes sont dans la NAT qui suit les écritures. Résultat : les pistes sont rapidement effacées, contrairement à EXT4 où les inodes restent souvent en place avec les pointeurs de blocs. Combiné à FBE (chiffrement par fichier), la récupération devient quasiment impossible sans les clés.
Un enquêteur saisit un Samsung Galaxy S22. Où se trouve le filesystem F2FS et comment l'identifier ?Android F2FS · Niveau : facile
Le F2FS est sur la partition /data (userdata) — la partition qui contient tous les fichiers utilisateur, apps et données applicatives. L'identifier : chercher le magic number 0xF2F52010 à l'offset 1024 du volume (avec un éditeur hex ou xxd -s 1024 -l 4). L'autre partition /system est généralement en EXT4 ou EROFS (read-only).
