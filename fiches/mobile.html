📱 Mobile Forensics — Le smartphone, mémoire externe du suspect
Un smartphone moderne contient typiquement plus de données personnelles que l'ordinateur de son propriétaire : conversations chiffrées, géolocalisation 24/7, photos et vidéos avec EXIF GPS, historique de paiements, contacts, calendrier, biométrie, applications bancaires, comptes professionnels. Pour le forensiste, c'est la cible principale dans la majorité des enquêtes pénales modernes. Cinq niveaux d'extraction existent, du moins au plus invasif : (1) Manual (photos d'écran, sans outil), (2) Logical (backup ADB / iTunes), (3) File System (jailbreak/root), (4) Physical (image bit-à-bit de la NAND), (5) Chip-off / JTAG (désoudage de la puce, dernier recours destructif). Difficulté majeure : iOS chiffre tout par défaut depuis iOS 8 (2014), Android depuis Marshmallow (2015). Sans le PIN/biométrie, les données sont illisibles — même avec accès physique à la NAND. Outils référence : Cellebrite UFED, Magnet AXIOM, MSAB XRY, Oxygen Forensic Detective, GrayKey (USA), ALEAPP/iLEAPP (open source). En Suisse : art. 246-248 CPP régit la saisie + cage de Faraday immédiate est protocolaire pour empêcher le wipe à distance via Find My iPhone / Find My Device.

🍎 iOS — Spécificités forensiques
🔐 Chiffrement iOS
  • Chiffrement AES-256 par défaut sur toute la NAND depuis iOS 8 (2014)
  • Clé dérivée du code PIN/passcode + UID matériel (gravé sur le SoC, jamais lisible)
  • Sans le PIN → données illisibles même avec accès physique à la NAND
  • Secure Enclave (depuis iPhone 5s, 2013) : brute-force PIN limité (10 essais max si configuré) + délais croissants
  • Boîtes : BFU (Before First Unlock = appareil pas déverrouillé depuis allumage) vs AFU (After First Unlock) — AFU plus facile à attaquer
  • GrayKey / Cellebrite Premium : exploits propriétaires (zero-days) pour brute-force PIN sur iPhones récents
💾 Backup iTunes
  • Localisation : %AppData%\Apple Computer\MobileSync\Backup\ (Windows) · ~/Library/Application Support/MobileSync/Backup/ (macOS)
  • Contient : SMS, iMessages, contacts, photos, apps, données santé, calendrier, mots de passe Keychain (si chiffré)
  • Format : fichiers nommés par hash SHA-1 du chemin original
  • Index : Manifest.db (SQLite) mappe hashes → chemins originaux
  • Outil d'analyse : iBackup Viewer, Autopsy, Cellebrite UFED, iLEAPP
  • Backup chiffré = Keychain inclus → si MDP connu, mine d'or. Sans MDP : Passware, Hashcat mode 14700
💡 Mode avion = priorité absolue lors de la saisie d'un iPhone. Find My iPhone peut être déclenché en quelques secondes pour effacer l'appareil à distance. Cage de Faraday obligatoire si le mode avion ne peut être confirmé. Référence : art. 248 CPP (saisie d'objets).
🤖 Android — Spécificités forensiques
🔧 ADB (Android Debug Bridge)
  • Backup si USB debugging activé : adb backup -all -apk -shared (déprécié Android 12+)
  • Nécessite confirmation sur l'appareil — si pas déverrouillé = problème
  • Shell : adb shell → accès système si root
  • Extraction directe SQLite si root : adb pull /data/data/com.whatsapp/databases/msgstore.db
  • Apps installées : adb shell pm list packages
  • Mode bootloader : adb reboot bootloader + fastboot pour OEM unlock (efface partition data)
🔐 Chiffrement Android
  • FDE (Full Disk Encryption, Android 5-6) : chiffrement de toute la partition userdata
  • FBE (File-Based Encryption, Android 7+, obligatoire Android 10+) : chiffrement par fichier avec deux classes : Credential Encrypted (CE) et Device Encrypted (DE)
  • Clé dérivée du PIN/MDP utilisateur + Trusted Execution Environment (TEE)
  • Root + extraction physique nécessaires pour accès complet hors backup
  • Samsung Knox : couche additionnelle, complique l'extraction sur Galaxy récents

🧠 Testez-vous
Vous saisissez un iPhone allumé et déverrouillé sur la scène d'une arrestation. Que faire en priorité ?Procédure terrain · Niveau : facile
Ordre opérationnel : (1) Cage de Faraday immédiate — sac/cage pour bloquer 4G/5G/Wi-Fi/Bluetooth. Find My iPhone peut être déclenché en quelques secondes par un complice pour wiper l'appareil. (2) NE PAS verrouiller — l'iPhone passe en BFU (Before First Unlock) et le chiffrement devient bien plus dur à casser. AFU (After First Unlock = état actuel déverrouillé) est beaucoup plus permissif. (3) Photographier l'écran allumé tel quel (preuve de contexte : apps ouvertes, conversations en cours, etc.). (4) Mode avion via le Centre de Contrôle (swipe depuis le coin supérieur droit, sans déverrouiller) — plus fiable que Faraday seul. (5) Désactiver Auto-Lock dans Settings → Display → Auto-Lock → Never (empêche le verrouillage auto). (6) Brancher au chargeur — éviter coupure batterie. (7) Transport en Faraday vers labo. (8) Au labo : extraction immédiate avec UFED ou GrayKey en mode AFU. Toujours documenter horodatages, témoin, et numéro IMEI.
Quelle est la différence entre extraction Logical et Physical ?Niveaux d'extraction · Niveau : moyen
Extraction Logical = utilise les API officielles du système (ADB backup pour Android, iTunes Backup pour iOS) pour récupérer les données accessibles via les mécanismes prévus. Avantages : non-invasif, supporté par tous les outils, pas besoin de jailbreak/root. Inconvénients : ne récupère que ce que le système expose — pas les données système, pas les pages allouées non utilisées, pas les enregistrements supprimés. Typiquement : contacts, SMS, agenda, photos, apps qui acceptent le backup. Extraction Physical = image bit-à-bit de la mémoire NAND, comme on ferait dd sur un disque dur. Avantages : capture tout y compris pages libres, slack space, données effacées récupérables, partitions cachées. Inconvénients : nécessite outils premium (UFED Physical Analyzer, GrayKey), souvent un exploit (jailbreak iOS, fastboot Android), et — limite majeure — si l'appareil est chiffré (iOS depuis iOS 8, Android depuis Marshmallow), l'image NAND est chiffrée et inutile sans le PIN. File System est intermédiaire : accès complet aux fichiers déchiffrés, mais pas aux espaces non alloués.
Vous trouvez un fichier knowledgeC.db dans une extraction iOS. Quelles informations contient-il ?Artefacts iOS · Niveau : difficile
Mine d'or forensique iOS. knowledgeC.db = base SQLite située dans /var/mobile/Library/CoreDuet/Knowledge/ contenant la timeline complète d'utilisation du device. Données : (1) Apps ouvertes/fermées avec timestamps précis (foreground/background), (2) Verrouillages/déverrouillages de l'appareil (qui prouve qu'il était entre les mains de l'utilisateur à un moment T), (3) Notifications reçues par app, (4) Activité Bluetooth : connexions à AirPods, voiture, etc., (5) État batterie et chargements, (6) Activité du capteur de mouvement (téléphone en main, en marche, en voiture), (7) Synchronisations Wi-Fi. Forensiquement : permet de reconstituer une journée typique du suspect — quelles apps utilisées, à quelles heures, où. Combiné avec les données GPS (Photos.sqlite, Maps cache), c'est une preuve de présence et d'activité très forte. Outils : APOLLO (Apple Pattern of Life Lazy Output 'er) parse knowledgeC.db automatiquement, ou iLEAPP, Mac4n6, ou requête SQL directe sur la base. Format timestamps : Mac/Cocoa epoch (s. depuis 2001) → datetime(ZSTARTDATE+978307200,'unixepoch').
Un suspect refuse de donner son PIN iPhone. Que faire pour accéder aux données ?Légal + technique · Niveau : difficile
Cas complexe — mélange juridique et technique. Volet juridique CH : (1) En Suisse, nul ne peut être contraint de témoigner contre soi-même (nemo tenetur, art. 113 CPP) — le suspect ne peut pas être forcé à divulguer son PIN. (2) Cependant, contraindre l'usage de la biométrie (Face ID, Touch ID) reste juridiquement débattu et controversé. (3) Le procureur peut ordonner saisie + analyse (art. 246-248 CPP). Volet technique : (1) iCloud backup — si le suspect utilise iCloud Backup et que c'est récent, demande légale Apple via MLAT peut donner accès aux données sauf si Advanced Data Protection activé (E2E sur tout iCloud, fin 2022). (2) iTunes backup — chercher sur les ordinateurs du suspect. Backup chiffré ? Tenter Passware/Hashcat. Non chiffré ? Mine d'or directe. (3) GrayKey / Cellebrite Premium — outils propriétaires (USA, Israël) qui exploitent des zero-days pour brute-force le PIN sur iPhones récents. Disponibles aux services d'enquête mais coûteux et accès limité. (4) Cloud iMessages — la victime/correspondants peuvent avoir leur propre copie. (5) Cloud apps (WhatsApp, Signal Desktop sur PC du suspect). (6) Métadonnées opérateur via LSCPT art. 273 CPP. (7) Patience : un futur exploit peut faire tomber le verrou. Conséquence pratique : ne JAMAIS verrouiller un iPhone saisi déverrouillé — c'est souvent la seule fenêtre.
🎓 Exam Tip — Mobile Forensics

5 niveaux d'extraction (du moins au plus invasif) :

  1. Manual — photos d'écran (témoin requis)

  2. Logical — backup ADB / iTunes (API officielles)

  3. File System — jailbreak iOS / root Android (FFS)

  4. Physical — image NAND bit-à-bit (UFED Premium, GrayKey)

  5. Chip-off / JTAG — désoudage (lab spécialisé, destructif)

Saisie : Cage de Faraday + Mode avion immédiat (anti-wipe à distance)

Ne JAMAIS verrouiller un appareil déverrouillé saisi (BFU vs AFU)

iOS :

  • Chiffré AES-256 par défaut depuis iOS 8 (2014)

  • Clé = PIN + UID matériel SoC (gravé)

  • Secure Enclave depuis iPhone 5s (2013)

  • BFU = Before First Unlock · AFU = After First Unlock

  • Backup iTunes : %AppData%\Apple Computer\MobileSync\Backup

Android :

  • ADB pour backup logique (USB debugging requis)

  • FBE = File-Based Encryption (Android 7+, obligatoire 10+)

  • Samsung Knox = couche additionnelle

Artefacts iOS clés : sms.db · AddressBook · CallHistory · knowledgeC.db (timeline activité)

Artefacts Android clés : mmssms.db · contacts2.db · usagestats · cache.wifi

Outils référence : Cellebrite UFED · Magnet AXIOM · MSAB XRY · GrayKey · ALEAPP/iLEAPP

Cadre légal CH : art. 246 (perquisition) · art. 248 (saisie objets) · art. 113 (nemo tenetur)
