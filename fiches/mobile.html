Niveaux d'extraction (du moins au plus complet)
1
Manual
Photographies de l'écran — aucun outil. Limité mais non-invasif.
2
Logical
Données synchronisées (contacts, SMS, calendrier). ADB backup (Android), iTunes backup (iOS).
3
File System
Accès complet au système de fichiers. Requiert jailbreak (iOS) ou root (Android).
4
Physical
Image bit-à-bit de la puce NAND — contient les données supprimées. Requiert équipement spécialisé (UFED, GrayKey).
5
Chip-off / JTAG
Désoudage de la puce mémoire ou accès JTAG. Dernier recours — risque de destruction.
iOS — Spécificités forensiques
Chiffrement iOS
  • Chiffrement AES-256 par défaut sur toute la puce NAND
  • Clé de chiffrement dérivée du code PIN + UID matériel (gravé sur SoC)
  • Sans le PIN → données illisibles même avec accès physique
  • Secure Enclave (depuis iPhone 5s) : brute force PIN limité + délais
  • GrayKey / Cellebrite Premium : exploits propriétaires pour extraire le PIN
Backup iTunes (non chiffré)
  • Localisation : %AppData%\Apple Computer\MobileSync\Backup\
  • Contient : SMS, iMessages, contacts, photos, apps, santé
  • Format : fichiers nommés par hash SHA-1 des chemins
  • Outil d'analyse : iBackup Viewer, Autopsy, UFED
  • Backup chiffré → Passware pour le MDP
💡 Mode avion = priorité absolue lors de la saisie d'un iPhone. L'effacement à distance (Find My iPhone) peut être déclenché en quelques secondes. Cage de Faraday obligatoire si le mode avion ne peut être confirmé (art. 248 CPP).
Android — Spécificités forensiques
ADB (Android Debug Bridge)
  • Backup si USB debugging activé : adb backup -all -apk -shared
  • Nécessite confirmation sur l'appareil (si pas déverrouillé = problème)
  • Shell : adb shell → accès système si root
  • Extraction DB SQLite directement si root
Chiffrement Android
  • FDE (Full Disk Encryption) : chiffrement de toute la partition userdata
  • FBE (File-Based Encryption, Android 7+) : chiffrement par fichier
  • Clé dérivée du PIN/MDP utilisateur
  • Root + extraction physique nécessaires pour accès complet
