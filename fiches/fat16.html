FAT16 vs FAT32 — Différences clés de structure
🔵 FAT16
Root Directory fixe — zone dédiée entre FAT2 et données (512 entrées × 32o = 16 Ko)
1 seul FAT volume — entrées 16 bits (0x0000 → 0xFFFF)
Secteurs réservés = 1 (juste le Boot Sector)
FS Type à l'offset 0x36 — "FAT16 "
Volume max : 4 Go
Cluster : 16 bits seulement (offset 0x1A)
Root Entry Count = 512 (offset 0x11)
🟢 FAT32
Root Dir dynamique — stocké en zone données comme répertoire normal (cluster 2 par défaut)
2 FAT volumes — entrées 32 bits (28 utilisés : 0x0FFFFFFF = EOF)
Secteurs réservés = 32 typique (FS Info sector inclus)
FS Type à l'offset 0x52 — "FAT32 "
Volume max : 8 To
Cluster : 32 bits (offset 0x1A + 0x14 hauts)
Root Entry Count = 0 (racine dynamique)

Formules de calcul — Offsets forensiques
Taille cluster = BytesPerSector × SectorsPerCluster // ex : 512 × 8 = 4096 octets
Début FAT 1 = ReservedSectors × BytesPerSector
Début Root Dir = Début FAT1 + (NumberOfFATs × FATsize) × BytesPerSector // FAT16 seulement
Début données = Début Root Dir + (RootEntryCount × 32) // +0 sur FAT32
Offset cluster N = Début données + (N − 2) × TailleCluster // clusters commencent à 2
Slack space = TailleCluster − (TailleFichier mod TailleCluster) // données résiduelles !

🔍 Indices forensiques Boot Sector

  • Signature 55 AA à l'offset 510 = secteur de boot valide
  • OEM ID "MSDOS5.0" ou "MSWIN4.1" → Windows natif
  • Number of FATs = 2 toujours — divergence = corruption ou manipulation
  • Root Entry Count = 0 → FAT32 (Root dans zone données)
  • FS Type string non fiable seul — recalculer le nombre de clusters

⚡ Identifier la variante FAT

  • Calculer nb clusters = (TailleVolume − SecteursDonnées) / SectorsPerCluster
  • < 4 087 → FAT12 · < 65 527 → FAT16 · plus → FAT32
  • Root Entry Count > 0 → FAT12 ou FAT16
  • FS Type à offset 0x36 pour FAT12/16, 0x52 pour FAT32
  • Cluster de départ FAT32 = 32 bits (combiner 0x1A + 0x14)

FAT12 — Encodage en 12 bits

FAT12 utilise des entrées de 12 bits — deux entrées partagent parfois un même octet. Pour lire l'entrée N :

Offset en octets = N × 12 / 8 = N × 3 / 2
Si N est pair : lire 12 bits bas des 2 octets → (octet1 | (octet2 << 8)) & 0x0FFF
Si N est impair : lire 12 bits hauts → (octet1 | (octet2 << 8)) >> 4

Exemple : octets 0xAB 0xCD 0xEF
Cluster 0 (pair) = 0xDAB (bits 0–11) · Cluster 1 (impair) = 0xEFC (bits 12–23 >> 0)

🗂 Cluster Slack

  • Un fichier d'1 octet occupe 1 cluster entier (ex : 4096 octets)
  • Slack = espace gaspillé entre fin fichier et fin cluster
  • Le slack contient des données résiduelles d'anciens fichiers
  • Formule : TailleCluster − (TailleFichier mod TailleCluster)

🔗 Fragmentation & Récupération

  • Fichier fragmenté = clusters éparpillés, tous chaînés dans la FAT
  • Suppression = clusters marqués libres, 1er octet = 0xE5
  • Récupération : cluster de départ encore dans l'entrée SFN
  • Données restent jusqu'à réallocation → carving possible

Identifier la variante FAT — 5 étapes
1
Lire Root Entry Count à l'offset 0x11. Si = 0 → FAT32. Si > 0 → FAT12 ou FAT16.
2
Calculer le nombre de clusters de données. < 4 087 → FAT12. < 65 527 → FAT16. Sinon → FAT32.
3
Lire la chaîne ASCII à l'offset 0x36 (FAT12/16) ou 0x52 (FAT32). Attention : cette valeur n'est pas toujours fiable seule !
4
FAT32 : vérifier Reserved Sectors (0x0E) = 32 typique. FAT16 = 1. Et Boot Signature = 0x55 0xAA à l'offset 510.
5
FAT32 : cluster de départ d'un fichier = 32 bits = (clus_hi 0x14 << 16) | clus_lo 0x1A. FAT16 : uniquement 0x1A (16 bits, 0x14 = 0).
🎓 Exam Tip — FAT12 / FAT16 / FAT32

0xE5 = fichier supprimé · 0x00 = fin du répertoire · données restent jusqu'à réallocation

Cluster départ SFN FAT32 : 0x1A–0x1B (16 bits bas) + 0x14–0x15 (16 bits hauts)

Root directory : FAT12 = 224 entrées · FAT16 = 512 · FAT32 = dynamique cluster 2

EOF : FAT12 = 0xFF8–FFF · FAT16 = 0xFFF8–FFFF · FAT32 = 0x0FFFFFF8–0FFFFFFF

FS Type : FAT12/16 → offset 0x36 · FAT32 → 0x52 · Boot signature 55 AA à l'offset 510

Attribut LFN = 0x0F (R+H+S+V) · Timestamps FAT = précision 2 secondes · Little Endian

Pourquoi l'attribut d'une entrée LFN vaut 0x0F ?FAT Attributs · Niveau : moyen
0x0F = R(0x01) + H(0x02) + S(0x04) + V(0x08). Cette combinaison est intentionnellement invalide pour un vrai fichier — les anciens systèmes FAT qui ne connaissent pas LFN l'ignorent automatiquement. Les entrées LFN précèdent l'entrée SFN correspondante dans le répertoire.
Comment localiser physiquement les données d'un fichier supprimé en FAT16 dont l'entrée SFN montre cluster départ = 0x0008 ?FAT16 forensique · Niveau : moyen
Le cluster de départ 8 est encore lisible à l'offset 0x1A–0x1B même après suppression (le premier octet du nom = 0xE5, mais le reste est intact). Offset physique = dataAreaStart + (8 − 2) × SectorsPerCluster × BytesPerSector. Les données restent intactes jusqu'à réallocation → carving direct possible depuis ce cluster.
Root Entry Count = 0 dans le BPB. Qu'est-ce que cela indique et où se trouve alors le répertoire racine ?FAT32 vs FAT16 · Niveau : facile
Root Entry Count = 0 → FAT32. Le répertoire racine n'a plus de zone fixe — il est stocké dans la zone de données comme un répertoire ordinaire, généralement au cluster 2 (spécifié dans le champ RootCluster du BPB étendu FAT32 à l'offset 0x2C). Il peut donc grandir dynamiquement sans limite fixe de 512 entrées.
