🔍 INDICES FORENSIQUES

  • Signature 0x55 0xAA à l'offset 510 = secteur de boot valide
  • OEM ID "MSDOS5.0" ou "MSWIN4.1" identifie Windows
  • Number of FATs = 2 toujours — comparer FAT1 et FAT2 pour détecter des corruptions
  • Root Entry Count = 0 → FAT32 (Root dans zone données)

⚡ CALCULS UTILES

  • Taille cluster = Bytes/Sector × Sectors/Cluster
  • 1er cluster données = secteur 0 + réservés + (FATs × taille FAT) + root
  • Offset fichier = (cluster − 2) × taille_cluster + début_données
  • Slack space = taille_cluster − (taille_fichier mod taille_cluster)

🔑 FICHIER SUPPRIMÉ

  • 1er octet du nom = 0xE5 → entrée marquée supprimée
  • Les clusters sont marqués libres dans la FAT
  • Mais les données restent jusqu'à réécrites = récupération possible
  • Taille et cluster de départ encore présents → reconstruction

⏱️ TIMESTAMPS FORENSIQUES

  • Date écriture (0x18) = seul timestamp modifié à chaque écriture
  • Date accès (0x12) souvent désactivée sous Windows (LastAccess = 0)
  • Précision : FAT = 2 secondes · NTFS = 100 nanosecondes
  • Endianness : Little Endian sur FAT

🗂️ CLUSTER SLACK

  • Un fichier de 1 octet occupe 1 cluster entier (ex: 4096 octets)
  • Le slack = espace gaspillé entre fin du fichier et fin du cluster
  • Le slack peut contenir des données résiduelles d'un ancien fichier
  • Forensiquement exploitable : rechercher des données dans le slack

🔗 FRAGMENTATION

  • Fragments non contigus = clusters éparpillés sur le disque
  • La FAT chaîne tous les fragments même s'ils ne sont pas adjacents
  • Récupération : suivre la chaîne FAT depuis l'entrée SFN
  • Fichier supprimé : chaîne brisée → carving nécessaire

Spécificités FAT12

FAT12 utilise des entrées de 12 bits — deux entrées partagent parfois un même octet. Pour lire l'entrée n°1 : lire 3 octets à partir de l'offset 1 × 12 / 8 = 1, puis extraire les 12 bits correspondants selon parité.

Byte 0 : 0xAB 0xCD 0xEF
Cluster 0 = 0xDAB (pair → 12 bits bas) | Cluster 1 = 0xEFC (impair → 12 bits haut)

🎯 IDENTIFIER LA VARIANTE

  • Compter les clusters de données
  • < 4087 → FAT12 · < 65527 → FAT16 · > → FAT32
  • Lire la chaîne ASCII à l'offset 0x36 (FAT12/16) ou 0x52 (FAT32)
  • Root Entry Count > 0 → FAT12 ou FAT16

📋 À RETENIR

  • Premier cluster utilisable = 2 (0 et 1 réservés)
  • FAT32 : Root Dir dans la zone données (cluster 2 par défaut)
  • FAT16 : Root Dir entre FAT2 et zone données (taille fixe)
  • exFAT ≠ FAT32 : structure radicalement différente
