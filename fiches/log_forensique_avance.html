📨 Syslog = Standard Log Format (RFC 5424)
Unix/Linux logging standard. Format: priority, facility, timestamp, hostname, program, message. Centralized logging on syslog servers. Plaintext (good for forensics).
Syslog Message Format
RFC 5424 Format:

<PRI>TIMESTAMP HOSTNAME TAG[PID]: MSG

Example:
<134>2024-03-20T14:32:15Z myhost sshd[1234]: Failed password for user admin

PRI breakdown:
• FACILITY (5 bits, valeurs 0–23) : type de service (auth=4, syslog=5, etc.)
• SEVERITY (3 bits, valeurs 0–7) : niveau (0=emergency, 7=debug)
• PRI = (FACILITY * 8) + SEVERITY

Example: 134
• 134 / 8 = 16 (facility)
• 134 % 8 = 6 (severity = INFO)
Syslog Facilities & Severities
Facility Code Forensique
auth (authentication) 4 🔴 Login attempts, access control
authpriv (private auth) 10 Sensitive auth events
syslog 5 System events
local0-local7 16-23 Application-specific
Syslog Forensic Value
  • Centralized = single source of truth
  • Chronological = precise timeline
  • Plaintext = easy parsing
  • Difficult to tamper (if on remote syslog server)
🪟 Windows Event Log (.evtx) = Binary Format
Windows stores events in binary evtx format. Security channel = authentication, privilege escalation, etc. System channel = driver loads, service starts.
Event Log Channels & Importance
Channel File Forensique Critique
Security Security.evtx 🔴 CRITICAL: All auth events
System System.evtx 🔴 CRITICAL: Driver loads, services
Application Application.evtx App errors, warnings
Critical Event IDs (Security Channel)
Event ID Description Forensique
4625 Failed logon attempt 🔴 Brute force attacks
4624 Successful logon 🔴 User access timeline
4688 Process creation 🔴 Malware execution
4698 Scheduled task created Persistence mechanism
4719 Audit log cleared 🚨 Evidence tampering!
📊 JSON Structured Logs = Modern Standard
Modern systems output structured logs (JSON). ECS (Elastic Common Schema) = standard field names. Machine-readable, perfect for log aggregation + correlation.
ECS (Elastic Common Schema) Fields
Example JSON Event (ECS):

{
  "timestamp": "2024-03-20T14:32:15.123Z",
  "event": {
    "category": "authentication",
    "action": "login",
    "outcome": "success"
  },
  "source": {"ip": "192.168.1.100"},
  "user": {"name": "admin"},
  "host": {"name": "server1"},
  "message": "User admin logged in from 192.168.1.100"
}

✅ Machine-parseable = easy correlation
ECS Advantages for Forensics
  • Standardized field names = easy parsing
  • Timestamps normalized (ISO 8601)
  • Source/destination IPs in standard fields
  • User/host/process info structured
  • Ideal for timeline aggregation
🚨 Log Tampering = Attacker Cover-Up
Attackers delete/modify logs to hide actions. Detection: sequence number gaps, timestamp jumps, impossible deltas, entry deletions. Proves obstruction.
Tampering Indicators
🚨 Sequence Gaps
Event IDs: 1000, 1001, 1003
(Missing 1002)
→ Indicates deletion
🚨 Timestamp Jumps
14:30:00 → 14:35:00 (5 min gap)
OR backward (14:35 → 14:32)
→ Deletion or clock reset
🚨 Event 4719 (Security)
"Audit log cleared"
Windows only
= Attacker cleared logs
🚨 Impossible Deltas
Log file size shrinks
(should only grow)
= Entries deleted
Tampering Detector Interactive
👆 Entrez Event IDs pour analyser
📅 Multi-Source Timeline = Complete Audit Trail
Combining Syslog + Windows evtx + JSON logs = comprehensive timeline. Identify patterns, correlate events across systems, detect lateral movement.
Timeline Aggregation Workflow
Process:
  1. Extract all log sources (evtx, syslog, JSON)
  2. Normalize timestamps (ISO 8601 / Unix epoch)
  3. Parse into standard fields (source IP, user, action)
  4. Deduplicate (same event logged multiple places)
  5. Sort chronologically (merge all timestamps)
  6. Correlate events (identify sequences)
  7. Detect patterns (brute force, lateral movement, data exfiltration)
Timeline Patterns
  • Brute force: Many failed logins (4625) from same IP
  • Privilege escalation: Logon (4624) → Privilege use (4672)
  • Lateral movement: Logon from unexpected IP → Process creation
  • Data exfiltration: Large network transfer logs correlate with file access

CLI Quick Commands
# Parse Windows evtx (Security channel)
$ evtx_dump Security.evtx | grep "4625\|4624\|4688"

# Parse JSON logs with jq
$ cat app.log | jq '.[] | select(.event.category=="authentication")'

# Extract failed logins
$ grep "Failed password" /var/log/auth.log | wc -l

# Timeline syslog (chronological)
$ sort -k1 -k2 /var/log/syslog | awk '{print $1, $2, $3, $4, $5, $NF}'

# Detect duplicate entries
$ cat combined.log | sort | uniq -d

# Convert timestamps
$ python3 -c "import datetime; print(datetime.datetime.utcfromtimestamp(1234567890))"

# Create super timeline (plaso)
$ log2timeline.py output.plaso image.dd
$ psort.py output.plaso
✅ Workflow Complet Log Forensique
  1. Collect all log sources (evtx, syslog, JSON, app logs)
  2. Parse each log type (evtx_dump, jq, grep)
  3. Normalize timestamps (ISO 8601 standard)
  4. Extract key fields (source IP, user, action, status)
  5. Merge into single timeline (sort by timestamp)
  6. Detect tampering (sequence gaps, timestamp jumps)
  7. Correlate events (identify sequences/patterns)
  8. Create super timeline (plaso or manual)
  9. Analyze for suspicious activity (brute force, lateral movement)
  10. Report: Timeline, suspicious events, evidence integrity
