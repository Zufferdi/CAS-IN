📁 ShellBags — La mémoire indélébile de l'explorateur Windows
Les ShellBags sont l'un des artefacts les plus puissants de la forensique Windows — et l'un des plus méconnus des suspects. Leur fonction officielle est banale : Windows mémorise pour chaque dossier que vous ouvrez dans l'Explorateur la position de la fenêtre, la taille des colonnes, le mode d'affichage (icônes, détails, miniatures), pour rétablir vos préférences à la prochaine visite. Effet de bord forensique : pour stocker ces préférences, Windows enregistre le chemin complet du dossier dans le registre — et ce chemin persiste indéfiniment, même si le dossier est ensuite supprimé, même si la clé USB qui le contenait est partie depuis 5 ans, même si le dossier était sur un partage réseau aujourd'hui démonté. Un ShellBag prouve trois choses simultanément : (1) le dossier a existé, (2) un utilisateur (identifié par SID) l'a ouvert visuellement dans l'Explorateur (donc accès intentionnel et conscient, pas juste un script qui passe), (3) quand approximativement il l'a fait. Ils sont stockés dans deux ruches utilisateur : USRCLASS.DAT (clé Local Settings\Software\Microsoft\Windows\Shell\BagMRU) — la principale, et NTUSER.DAT (clé Software\Microsoft\Windows\Shell\BagMRU) — secondaire. La structure est arborescente : la racine = Bureau, et chaque sous-clé = un sous-dossier visité, formant une cartographie complète des navigations. Outil incontournable : ShellBags Explorer (Eric Zimmerman). Anti-forensique : peu d'outils malveillants nettoient les ShellBags car peu d'attaquants savent qu'ils existent — ils sont donc extrêmement fiables en pratique.

① Concept — qu'est-ce qu'un ShellBag ?
🪟 Définition

Les ShellBags sont un ensemble de clés de registre que Windows utilise pour mémoriser les préférences d'affichage des dossiers dans l'Explorateur.

Concrètement, quand vous :

  • ouvrez un dossier,
  • redimensionnez sa fenêtre,
  • choisissez l'affichage Détails ou Grandes icônes,
  • triez par date ou par taille,

…Windows enregistre ces choix pour que, la prochaine fois, le dossier soit exactement comme vous l'avez laissé.

② Pourquoi c'est une mine d'or en forensique

La valeur des ShellBags réside dans leur persistance.

👁 Mémoire visuelle

Ils tracent la navigation de l'utilisateur via l'Explorateur Windows (GUI). Chaque dossier ouvert laisse une trace durable.

♾️ Survivance

Si un utilisateur crée C:\Documents\Projet_Secret, l'ouvre, puis le supprime, le ShellBag reste dans le registre.

🔌 Preuve d'existence

Ils prouvent qu'un dossier a existé, même si le disque dur externe ou la clé USB n'est plus connecté à l'ordinateur. Même si la clé a été détruite.

③ Architecture & localisation

Les ShellBags ne se trouvent pas dans un fichier unique, mais dans les ruches du registre utilisateur.

🗝 USRCLASS.DAT — le plus important (Windows 7/10/11)

Contient les ShellBags des dossiers locaux, des fichiers ZIP et des dossiers partagés.

// Chemin fichier
C:\Users\%User%\AppData\Local\Microsoft\Windows\UsrClass.dat

// Chemin registre
HKCU\Software\Classes\Local Settings\Software\Microsoft\Windows\Shell\BagMRU
🗝 NTUSER.DAT — legacy & cas spécifiques

Contient les ShellBags des dossiers réseaux (UNC paths), du Bureau et de certaines configurations système.

// Chemin fichier
C:\Users\%User%\NTUSER.DAT

// Chemin registre
HKCU\Software\Microsoft\Windows\Shell\BagMRU
HKCU\Software\Microsoft\Windows\ShellNoRoam
④ Structure — BagMRU vs Bags

Deux sections qui fonctionnent en tandem.

🗺 BagMRU — la Carte

Structure arborescente qui reproduit la hiérarchie des dossiers explorés.

  • Système de numérotation : 0, 1, 2, 3…
  • Ordre de visite + noms des dossiers
  • Chaque nœud peut avoir des sous-nœuds
⚙️ Bags — les Réglages

Contenu des préférences associées à chaque nœud BagMRU.

  • Coordonnées de la fenêtre (position, taille)
  • Mode de tri (par date, nom, taille)
  • Type de vue (détails, icônes, liste…)
  • Chaque numéro BagMRU renvoie à une clé Bags
🧩 Modèle mental : BagMRU = quels dossiers dans quel ordre. Bags = comment ils étaient affichés.

🔍 Preuve d'accès et de connaissance

Si un ShellBag existe pour D:\Recettes_Fraudes, cela prouve non seulement que le dossier a existé, mais que l'utilisateur a navigué dedans via l'Explorateur Windows.

Cela réfute l'argument : « Je ne savais pas que ce dossier était là, c'est un virus qui l'a créé ».

👉 Un virus n'utilise généralement pas l'interface graphique — il ne crée donc pas de ShellBags. La présence d'un ShellBag implique une action humaine consciente.

⑥ Périphériques externes (USB) — l'usage le plus puissant
🔌 Reconstruire une clé USB absente

Lorsqu'une clé USB est insérée, Windows ne crée pas seulement des artefacts USB (setupapi, USBSTOR) — il crée aussi des ShellBags dès que l'utilisateur explore la clé.

Vous pouvez voir l'arborescence complète d'une clé USB même si la clé est détruite :

E:\
├── Documents\
│   ├── Confidentiel\       ← dossier visité
│   │   └── Projet_X\       ← sous-dossier visité
│   └── Factures\
└── Photos\
    └── Vacances\

Toute cette structure est reconstituable depuis le seul USRCLASS.DAT du suspect.

🔗 Corréler pour identifier LA clé USB précisément. Un ShellBag sur E:\ prouve qu'un volume a été monté avec cette lettre, mais pas lequel. Pour identifier la clé USB précise, il faut croiser :
  • USBSTOR → numéro de série unique de la clé
  • MountedDevices → lettre attribuée à cette clé
  • ShellBags → dossiers explorés sur cette lettre
  • LNK files → fichiers ouverts depuis cette clé
Les 4 ensemble = attribution certaine.
⑦ Archives ZIP & RAR
📦 Windows traite les conteneurs comme des dossiers

Si l'utilisateur double-clique sur un ZIP pour voir son contenu sans le décompresser, un ShellBag est créé pour ce ZIP.

Conséquence forensique : on peut prouver que l'utilisateur a ouvert et exploré le contenu d'une archive, même s'il n'a jamais extrait les fichiers. Windows fait pareil pour :

  • ZIP — et navigation dans les sous-dossiers internes
  • RAR — si WinRAR associé à l'Explorer
  • .CAB — archives Microsoft
  • .ISO — images disque montées nativement (Windows 8+)
  • Sessions FTP ouvertes depuis l'Explorer
  • Chemins UNC — \\serveur\partage
⑧ L'horodatage — attention à l'interprétation
⏱ Last Write Time — ce qu'il signifie vraiment

Le Last Write Time de la clé de registre BagMRU indique la dernière fois que la clé a été écrite — ce qui correspond à :

  • l'ouverture du dossier,
  • la fermeture du dossier,
  • le changement de vue,
  • OU la création d'un sous-nœud (quand on ouvre un sous-dossier).

⚠️ Nuance importante : si l'utilisateur ouvre un sous-dossier de Dossier A, c'est la clé BagMRU de Dossier A qui est mise à jour — donnant l'illusion d'une interaction directe avec A. En audience, formuler : « il y a eu une activité liée à ce dossier à telle heure » plutôt que « l'utilisateur a ouvert ce dossier à telle heure ».

📅 First interacted vs Last interacted

ShellBags Explorer expose deux timestamps distincts par entrée :

  • First Interacted — timestamp figé à la première interaction avec ce dossier. Utile pour prouver une connaissance historique.
  • Last Interacted — timestamp qui évolue à chaque interaction ultérieure. Utile pour la dernière activité.

Ces deux dates permettent d'évaluer la durée de la connaissance d'un dossier par l'utilisateur — par exemple : dossier créé en janvier, première visite en février, dernière visite en octobre → connaissance de 8 mois.

⚠️ Attention : le Last Write Time ne donne PAS toutes les visites — seulement la dernière. Pour une chronologie complète, corréler avec les LNK files, Jump Lists et RecentDocs.
⑨ Les outils d'analyse

Ne jamais tenter regedit — les données sont en binaire hexadécimal illisible.

🗝 ShellBags Explorer (Eric Zimmerman) — l'outil de référence

Gratuit, dédié, open source. Standard de l'industrie.

  • Fonctionnement : charger USRCLASS.DAT et/ou NTUSER.DAT
  • Affichage : reconstruit l'arborescence comme si vous étiez dans l'explorateur
  • Colonnes clés : Absolute Path · First Interacted · Last Interacted · Last Write Time · Slot Key

Version CLI : sbecmd.exe — même logique en ligne de commande, utile pour les batchs et l'automation.

sbecmd.exe -d C:\Extract\HiveFolder --csv C:\Export\

Voir aussi : Suite Zimmerman

🔍 X-Ways Forensics

Trois approches possibles :

  • Viewer de registre interne — voit les clés brutes (difficile à interpréter)
  • X-Tensions (plugins) — scripts qui parsent les ShellBags dans le rapport
  • Méthode recommandée : extraire USRCLASS.DAT et NTUSER.DAT depuis X-Ways → ouvrir dans ShellBags Explorer
🏢 AXIOM / EnCase

Suites commerciales avec parsers automatiques intégrés. Les ShellBags apparaissent dans la catégorie « Artefacts OS » ou « Navigation Dossiers ».

⑩ Méthodologie d'analyse
1
Extraction. Récupérer NTUSER.DAT et USRCLASS.DAT pour chaque utilisateur suspect (via X-Ways ou montage lecture seule).
2
Parsing. Charger les fichiers dans ShellBags Explorer.
3
Filtrage par type. Chercher les entrées vers lettres de lecteurs amovibles (E:, F:, G:) et les chemins UNC (\\Serveur\Partage).
4
Recherche de mots-clés. Noms de dossiers suspects — « Factures », « Photos », « Hack », « Secret », etc.
5
Analyse chronologique. Trier par Last Write Time pour voir ce que l'utilisateur faisait à l'heure de l'incident.
6
Corrélation. Comparer avec les LNK files, Jump Lists et RecentDocs pour confirmer l'ouverture de fichiers spécifiques dans ces dossiers.
⑪ Limites & pièges

Crucial pour ne pas sur-interpréter en audience.

🚨 Dossiers ≠ fichiers. Les ShellBags prouvent l'ouverture d'un dossier, pas l'ouverture des fichiers à l'intérieur. Pour prouver qu'un PDF a été lu, il faut regarder les LNK files, Jump Lists ou RecentDocs.
⚠️ Accès ligne de commande — angle mort. Si l'utilisateur copie des fichiers via cmd.exe ou PowerShell (copy c:\source d:\dest), aucun ShellBag n'est créé. Les ShellBags sont exclusifs à l'interface graphique Explorer.
🧹 Nettoyage / anti-forensique. Des outils comme CCleaner ou BleachBit peuvent effacer les clés MRU, supprimant les ShellBags. Une absence totale de ShellBags sur un vieux système est suspecte — ce vide est en soi un indicateur d'activité anti-forensique.

🧠 Testez-vous
Vous trouvez un ShellBag mentionnant E:\exfil_secret\ mais aucune clé USB n'est branchée. Que pouvez-vous conclure ?Interprétation · Niveau : moyen
Plusieurs conclusions fortes peuvent être tirées : (1) Une clé USB a été branchée sur ce poste (à un moment donné, pas nécessairement présente actuellement), avec la lettre de lecteur E:. (2) L'utilisateur a ouvert ce dossier exfil_secret dans l'Explorateur Windows (interaction GUI, pas via script ou cmd). (3) Le dossier exfil_secret a réellement existé sur cette clé (les ShellBags sont créés uniquement quand le dossier est rendu par l'OS). (4) Le SID propriétaire de USRCLASS.DAT identifie l'utilisateur. Étapes complémentaires d'enquête : (a) Cross-check avec USBSTOR (registre SYSTEM) → identifier modèle + Serial de toutes les clés USB E: utilisées à cette époque, (b) MountedDevices + MountPoints2 (NTUSER.DAT) → confirmer mappage E: ↔ clé spécifique + utilisateur, (c) setupapi.dev.log → timestamp 1re connexion, (d) Recherche de fichiers .lnk Recent avec Volume Serial Number correspondant → fichiers ouverts depuis cette clé, (e) Examiner Last Write Time du ShellBag pour dater la dernière interaction. Force juridique : ce schéma de preuve est extrêmement solide en Suisse. Même si le suspect efface la clé ou la cache, les ShellBags restent — et il est extrêmement difficile pour la défense de contester que le dossier a été ouvert intentionnellement, car les ShellBags ne sont créés que lors d'une navigation GUI consciente.
Quelle est la différence forensique cruciale entre Last Write Time de la clé et First Interacted / Last Interacted ?Timestamps · Niveau : difficile
Confusion classique aux conséquences sérieuses en audience. Last Write Time (LWT) de la clé registre = horodatage Windows standard du registre = quand la clé elle-même a été modifiée. Mais il peut être mis à jour pour des raisons indirectes (ré-organisation par Windows, changement de préférence d'affichage par exemple) qui ne correspondent pas forcément à une interaction GUI directe avec ce dossier précis. First Interacted (extrait par ShellBags Explorer) = première fois que l'utilisateur a réellement ouvert le dossier visuellement — figé, ne change plus jamais. Last Interacted = dernière interaction GUI avec ce dossier — évolue à chaque visite. Implication forensique : ne JAMAIS rapporter le LWT comme « dernière fois que l'utilisateur a ouvert le dossier » — c'est incorrect. Toujours utiliser First/Last Interacted extraits par ShellBags Explorer (Eric Zimmerman) qui parse correctement les structures internes. Source des First/Last Interacted : ils proviennent des slots binaires dans la valeur NodeSlot de chaque clé BagMRU, pas du LWT du registre. Conséquence pratique : un ShellBag peut avoir LWT = 2024-12-15 mais Last Interacted = 2023-03-08 si l'utilisateur n'a plus visité le dossier depuis mars 2023 mais que le système a touché la clé pour d'autres raisons. En audience : être très précis sur cette nuance — la défense peut détecter et exploiter cette confusion. Best practice : toujours documenter les trois timestamps (LWT, First, Last) et expliquer leur signification.
Le suspect a copié des données via PowerShell Copy-Item. Pourquoi les ShellBags ne révèlent rien ?Limite · Niveau : facile
Les ShellBags sont exclusivement créés par l'interface graphique Explorer (explorer.exe) lors d'une navigation visuelle consciente de l'utilisateur. Ils ne sont JAMAIS créés par : (1) Commandes shell (cmd.exe, copy, xcopy, robocopy), (2) PowerShell (Copy-Item, Get-ChildItem, Move-Item), (3) Scripts batch ou WSH, (4) APIs Windows directes (CreateFile, FindFirstFile dans des programmes), (5) Outils tiers comme TotalCommander, FreeCommander, etc. (utilisent leurs propres caches), (6) Accès SMB/réseau via net use sans navigation Explorer. Conséquence forensique : un attaquant techniquement averti peut exfiltrer massivement des données via PowerShell sans laisser aucune trace ShellBag. Sources alternatives à examiner : (a) Logs PowerShell EID 4104 (ScriptBlock logging) — si activé, contient les commandes complètes y compris obfusquées, (b) Logs Sysmon Event 1 (ProcessCreate) avec hash + ligne de commande, (c) Prefetch de powershell.exe + cmd.exe avec dates et compteurs, (d) Amcache pour exécutables lancés, (e) EID 4688 (ProcessCreated, Security Log si audit activé) avec ligne de commande, (f) $LogFile NTFS ($MFT $LogFile) — peut révéler les opérations fichier en transaction, (g) USN Journal ($UsnJrnl) — chaque création/modification de fichier loggée. Conclusion : absence de ShellBags ≠ absence d'activité. Toujours croiser avec d'autres sources, surtout si le suspect a des compétences techniques.

━━ EMPLACEMENT ━━

• USRCLASS.DAT (principal, Windows 7+) :

  C:\Users\%User%\AppData\Local\Microsoft\Windows\UsrClass.dat

• NTUSER.DAT (secondaire, réseau + Bureau) :

━━ STRUCTURE ━━

• BagMRU = carte hiérarchique des dossiers visités (arborescence)

• Bags = réglages d'affichage associés (taille colonnes, mode, etc.)

• Chaque nœud = 1 dossier visité dans l'Explorateur

━━ CE QUI EST SOURCE D'ATTRIBUTION FORTE ━━

① Existence : le dossier a réellement existé

② Accès GUI : l'utilisateur l'a ouvert dans Explorer (intentionnel)

③ Attribution : SID utilisateur (depuis ruche)

④ Timing : First Interacted + Last Interacted

━━ TIMESTAMPS — ATTENTION ━━

• Last Write Time (LWT) = horodatage clé registre (≠ interaction directe)

• First Interacted = 1re ouverture GUI (figé)

• Last Interacted = dernière ouverture GUI (évolue)

• Toujours utiliser First/Last Interacted, pas LWT, pour les conclusions juridiques

━━ CAS PARTICULIERS ━━

• Traités comme dossiers : ZIP · RAR · CAB · ISO · FTP · UNC \\server\share

• Survit à : suppression dossier · USB déconnectée · partage démonté

━━ LIMITES ━━

• Aucune trace si copy/move via cmd · PowerShell · scripts

• Prouve l'ouverture du dossier, pas des fichiers à l'intérieur

• Effaçables par CCleaner/BleachBit (absence = signal anti-forensique)
