🛡 Full Disk Encryption — Le défi forensique majeur
Le chiffrement complet de disque (FDE) protège les données au repos contre l'accès physique. Pour l'enquêteur, c'est le défi forensique majeur : sans la clef ni le mot de passe, AES-256 est inviolable par force brute. La méthodologie change radicalement selon l'état du device sur scène (allumé, verrouillé, hiberné, éteint) — chaque état appelle une stratégie spécifique pour préserver la possibilité de déchiffrement.
⚡ RÈGLE D'OR TERRAIN
Ne jamais éteindre un ordinateur allumé sur scène de perquisition sans d'abord tenter une acquisition RAM. Une fois éteint, si le disque est chiffré (FDE) et que ni le mot de passe ni la clé de récupération ne sont obtenus, la preuve peut être perdue définitivement. AES-256 sans la clé = probabilité nulle de cassage par force brute.

🪟 BitLocker — Anatomie
🔗 Hiérarchie des clés
  • FVEK (Full Volume Encryption Key) — chiffre les données du disque (AES-XTS)
  • VMK (Volume Master Key) — chiffre la FVEK
  • Protectors chiffrent la VMK : TPM, PIN, USB key, Recovery Key (48 chiffres)
  • Boot : protector → VMK → FVEK → mount
  • Outil : manage-bde -status C: puis -protectors -get C:
🔑 Récupération de la clé
  • Active Directory — attribut msFVE-RecoveryInformation
  • Entra ID / Intune — blade BitLocker keys dans Azure
  • Compte Microsoft — account.microsoft.com/devices/recoverykey
  • USB recovery key — fichier .BEK (128 bits)
  • Printed key — 48 chiffres groupés par 6
  • Suspension — manage-bde -protectors -disable C: (backdoor temporaire)
TPM sniffing (attaque physique) : sur BitLocker avec TPM seul (sans PIN), la VMK transite en clair sur le bus LPC/SPI entre le TPM et le CPU au boot. Un analyseur logique à ~$10 permet de capturer la clé en quelques minutes. Attaque pratique, documentée (Dolos Group, 2021). Contremesure : activer un PIN.
🍎 FileVault — Apple Silicon
🔒 Secure Enclave Processor (SEP)

Sur les Mac Apple Silicon (M1/M2/M3), FileVault utilise la Secure Enclave :

  • Chaque Mac a une clé unique matérielle (UID) non-extractible
  • Le SEP dérive la clé de chiffrement à partir de l'UID + MDP utilisateur
  • Impossible de déplacer le disque sur un autre Mac (UID soudée dans l'AP)
  • Acquisition : mac_apt (Yogesh Khatri) — nécessite un Mac vivant
  • Mode DFU + Apple Configurator → mode récupération (GrayKey indisponible pour macOS)
  • Si MDP connu : Recovery (⌘+R) → Terminal → diskutil apfs unlockVolume
🐧 LUKS — Linux
🔓 Workflow d'analyse
  • Identifier : cryptsetup isLuks /dev/sdX
  • Dump du header : cryptsetup luksDump /dev/sdX → algorithme, keyslots, UUID, itérations
  • Backup du header : cryptsetup luksHeaderBackup (à conserver pour bruteforce offline)
  • Unlock : cryptsetup open /dev/sdX vol → /dev/mapper/vol
  • Mount : mount /dev/mapper/vol /mnt/...
  • Bruteforce : hashcat -m 14600 luks_header.img wordlist.txt
  • Coût LUKS2 + Argon2id : > 100 ms par essai → force brute utile uniquement avec dico ciblé
❄️ Cold Boot Attack
🧊 Récupération de clés via DRAM persistance

Les clés de chiffrement d'un volume monté résident en RAM. Or la DRAM conserve son contenu quelques secondes à température ambiante — jusqu'à plusieurs minutes à basse température.

  • Procédure : pulvériser azote liquide ou bombe air inversée sur les DRAM → −50 °C
  • Arracher l'alimentation, éjecter les barrettes, les placer dans une autre machine bootée sur USB
  • Scanner la RAM pour les patterns de clés AES (entropie élevée + structure de schedule)
  • Outils : aeskeyfind, bitunlocker, rsakeyfind
  • Contre-mesures modernes : TRESOR (clé dans registres CPU AES-NI), ECC RAM avec scrubbing, CPUs Intel SME/MKTME
  • Succès : ~50 % sur hardware < 2015, ~10 % sur matériel récent

⚖️ Cadre suisse — Art. 90 al. 1 CPP & Art. 113 CPP

Le prévenu a le droit de se taire et ne peut être contraint à fournir un mot de passe de chiffrement. Le refus ne constitue pas une infraction en soi (contrairement au Royaume-Uni, RIPA 2000). Toutefois, le refus peut entraîner un indice de charge dans l'appréciation des preuves (art. 113 CPP).


Biométrie vs. mot de passe : la jurisprudence admet qu'un juge peut ordonner l'apposition d'une empreinte digitale ou du visage (Face ID) — acte non testimonial — mais pas la divulgation d'un mot de passe mental (nemo tenetur se ipsum accusare). Sur scène, éteindre le device après 5 min → Face ID se désactive et force le passcode.

Astuce acquisition : si l'ordinateur est allumé et déverrouillé, avant tout RAM dump, copiez le contenu des répertoires importants (Documents, Desktop, Downloads) vers un disque externe — c'est le seul moment où ces fichiers sont accessibles en clair. Le RAM dump peut échouer, mais cette copie préservera l'essentiel.
📋 Mémo — Check FDE sur scène
  • Device allumé ? → NE PAS ÉTEINDRE. Ne pas brancher de souris (risque lock screen).
  • Session ouverte ? → acquisition RAM immédiate + copie fichiers en clair
  • Session verrouillée ? → Faraday + charge + test BitLocker unlock avec clés AD / Entra ID avant extinction
  • Éteint ? → imager le disque brut, documenter le FDE, tenter récupération de la clé par voie légale
  • Mac ? → noter le modèle exact (T2 / M1 / M2) — change la stratégie
  • VeraCrypt détecté ? → chercher les keyfiles (photos, MP3, n'importe quoi)
  • Hibernate : hiberfil.sys peut contenir les clés → toujours acquérir avant action
  • TPM+PIN sur Lenovo/Dell ancien ? → envisager TPM sniffing en laboratoire
Vous arrivez sur scène. PC Windows allumé, écran de session, BitLocker activé. Quelle action ABSOLUMENT à éviter ?Workflow terrain · Niveau : facile
NE PAS ÉTEINDRE. Tant que le PC est allumé avec le volume BitLocker monté, la FVEK est en mémoire RAM. Une acquisition RAM (WinPmem, Magnet RAM Capture) capture cette clé, ce qui permet ensuite de déchiffrer une image disque offline. Une fois éteint, la RAM est purgée et il ne reste que la voie légale (récupération clé via Microsoft/Entra ID/AD) pour accéder aux données. Ordre correct : (1) photographier l'écran, (2) ne pas toucher la souris (risque lock), (3) déconnecter du réseau, (4) acquisition RAM immédiate, (5) copie des dossiers utilisateur, (6) puis seulement extinction propre + image disque.
Un suspect refuse de donner son MDP BitLocker. La police peut-elle le forcer en Suisse ?Droit suisse · Niveau : moyen
Non — principe nemo tenetur (art. 113 CPP). Le prévenu a le droit de se taire et ne peut être contraint à fournir un mot de passe mental, sous peine de violer le principe de non-incrimination. Le refus peut toutefois constituer un indice de charge dans l'appréciation libre des preuves. Distinction importante : la biométrie (empreinte, Face ID) est un acte non testimonial et peut être ordonnée par un juge — d'où la pratique d'éteindre l'iPhone après 5 minutes pour forcer le passcode. Contrairement au Royaume-Uni (RIPA 2000), la Suisse ne sanctionne pas pénalement le refus de remettre le MDP. Voies légales alternatives : récupération via compte MS, AD, Entra ID, ou attaque technique.
🎓 Exam Tip — Chiffrement de Volumes

BitLocker : VMK (chiffrée par TPM/PIN/USB/Recovery) → FVEK → disk · Recovery 48 chiffres

FileVault Apple Silicon : Secure Enclave + UID matérielle non-extractible → disque non déplaçable

LUKS2 : Argon2id, > 100 ms/essai · header dump = cryptsetup luksDump

VeraCrypt : volumes cachés (déni plausible) légalement reconnus en Suisse

Cold boot : DRAM @ −50 °C → aeskeyfind · efficace surtout pré-2015

TPM sniffing : analyseur logique sur bus LPC/SPI · contremesure = TPM+PIN

RÈGLE D'OR : ne jamais éteindre un PC allumé sans acquisition RAM préalable

Art. 113 CPP : nemo tenetur · biométrie ordonnable, MDP non
